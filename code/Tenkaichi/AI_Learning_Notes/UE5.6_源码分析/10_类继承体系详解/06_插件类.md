# 06 - 第 5 层：插件类 — GAS 等

> **特点**：需要手动启用插件才能用，Build.cs 里要加依赖。
> 
> 这一层是**第三方/官方插件**提供的基类。

---

## 一、GAS 相关的类

| 基类 | 用途 | 最终继承谁 |
|------|------|-----------|
| `UAttributeSet` | 属性集（存数值） | `UObject` |
| `UGameplayAbility` | 技能 GA（可执行动作） | `UObject` |
| `UAbilitySystemComponent` | ASC（管理器） | `UActorComponent` |
| `UGameplayEffect` | GE（修改数值的手段） | `UObject` |

---

## 二、它们的继承链

```
UObject
    ├── UAttributeSet（GAS 属性集）
    ├── UGameplayAbility（GAS 技能）
    └── UGameplayEffect（GAS 效果）

UActorComponent
    └── UAbilitySystemComponent（GAS 管理器）
```

**注意**：GAS 的类都是**直接继承 UObject 或其子类**，没有绕很深的继承链。

---

## 三、其他常见插件类

| 插件 | 基类 | 用途 |
|------|------|------|
| Niagara | `UNiagaraSystem` | 粒子特效 |
| Metasound | `UMetasoundSource` | 音频系统 |
| CommonUI | `UCommonUserWidget` | 跨平台 UI |
| EnhancedInput | `UInputAction` | 增强输入 |
| ModularGameplay | `UModularPawn` | 模块化角色 |

## 四、如何判断一个类是插件的？

### 方法 1：看 Build.cs 依赖

```csharp
// 如果 Build.cs 里有这个依赖，说明用了插件的东西
PublicDependencyModuleNames.Add("GameplayAbilities");  // ← GAS 插件
PublicDependencyModuleNames.Add("Niagara");            // ← Niagara 插件
```

### 方法 2：IDE 跳转看路径

- `Engine\Source\Runtime\...` → 引擎核心
- `Engine\Plugins\...` → 插件

### 方法 3：Ctrl+点击类名跳转

跳转到定义后，看文件路径就能判断。

## 五、GAS 类的特殊之处

### 为什么 GAS 要单独设计这些类？

因为 GAS 需要**反射系统**来动态操作属性和技能：

```cpp
// GE（GameplayEffect）要修改血量
// 但 GE 不知道你的属性叫什么名字、在哪里
// 
// 有了反射，GAS 可以：
// 1. 通过 FGameplayAttribute 找到属性
// 2. 读取它的当前值
// 3. 修改它
// 4. 通知 UI 更新
```

### 继承关系总结

| 类 | 继承 | 原因 |
|----|------|------|
| `UAttributeSet` | `UObject` | 需要反射来访问属性 |
| `UGameplayAbility` | `UObject` | 需要反射来序列化配置 |
| `UAbilitySystemComponent` | `UActorComponent` | 需要挂载到 Actor 上 |

---

## 六、一句话总结

> **插件类 = 房子的"加装设备"**
> 
> - GAS 提供技能/属性系统
> - Niagara 提供粒子特效
> - Metasound 提供音频系统
> 
> 它们都基于 UObject 体系，只是增加了特定领域的功能。
