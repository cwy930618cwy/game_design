# 4.2 TeamDisplayAsset —— 依赖断点说明（必须先读）

## 一、一句话结论

**`TeamDisplayAsset` 不能独立编译。** 它的 `.cpp` 在 `#if WITH_EDITOR` 的 `PostEditChangeProperty` 里
硬调用 `ULyraTeamSubsystem::NotifyTeamDisplayAssetModified`，链接期硬依赖 `TeamSubsystem`；
而 `TeamSubsystem` 是 **GAS 断点类**（依赖 `AbilitySystemGlobals` + `PlayerState` + `TeamInfo` 系列 + `TeamCheats`），
其中 `AbilitySystemGlobals` 属于阶段五 GAS，尚未教。

**这推翻了阶段四总 md 里"4.2 独立可教"的判断。** 按铁律 31，依赖没就位时绝不跳过，必须先停下让用户决定。

## 二、真实依赖链（铁律 30，自下而上，被依赖在下）

```
4.2 TeamDisplayAsset(.cpp)                    ← 想教的目标
      │ 硬调用 NotifyTeamDisplayAssetModified（WITH_EDITOR 内，编译+链接期硬依赖）
      ▼
TeamSubsystem                                   ← 断点节点（GAS）
      ├── AbilitySystemGlobals（GAS，阶段五）      ← 叶子·断点（未教）
      ├── PlayerState（阶段四后半段）              ← 未教
      ├── TeamInfoBase / PrivateInfo / PublicInfo  ← 未教
      ├── TeamCheats                              ← 未教
      └── TeamAgentInterface（4.1，已教 ✅）
```

- `.h` 依赖：`Engine/DataAsset` + 一堆前向声明 → **`.h` 独立可教**。
- `.cpp` 依赖：`MeshComponent`/`NiagaraComponent`/`MaterialInstanceDynamic`/`Engine/Texture`（全引擎类 ✅）
  **+ `Teams/LyraTeamSubsystem.h`（断点 ✗）**。
- 断点处：`PostEditChangeProperty`（`#if WITH_EDITOR`）→ `TeamSubsystem::NotifyTeamDisplayAssetModified`。

> 注意：即使 `#if WITH_EDITOR` 只在编辑器下编译，它也属于**编译期必须能解析**的代码（编辑器构建会编到）。
> 所以是硬依赖，不是可省略项。铁律 31 不允许"先省略/以后补"。

## 三、为什么不能按"先教 .h 跳过 .cpp 那段"处理

- `.cpp` 的 `PostEditChangeProperty` 是 Lyra 真实代码，铁律 23/25 要求**一比一完整还原、一字不砍**。
- 省略 = 违规；把逻辑后讲可以，但**代码不能后补**（铁律 25）。
- 而补这段代码就必须先有 `TeamSubsystem` → 又拖出整个 GAS 体系。
