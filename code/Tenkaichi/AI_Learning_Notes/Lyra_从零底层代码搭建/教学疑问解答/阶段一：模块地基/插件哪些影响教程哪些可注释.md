# 答疑：`.uproject` 的 81 个插件，哪些影响当前教程、哪些可先注释

> **触发**：用户把 `Tenkaichi.uproject` 完整对齐 Lyra（81 个插件 + `EpicSampleNameHash`）后，问：这 81 个插件里，哪些会影响到 L1 教程（编译/跑起来），哪些可以先注释掉（`Enabled: false`）减少心智负担。
> **结论先行**：**一个都不用注释**。你现在的 `.uproject` 和 `TenkaichiGame.Build.cs` 是「配套」的——Build.cs 依赖了哪些模块，`.uproject` 就必须启用提供这些模块的插件，缺一个就编译报错。所以当前教程阶段，**保持 81 个全启用**最省事、最正确。

---

## 一、判断标准（一句话）

**一个插件「能不能注释」，唯一标准 = 它提供的模块，是不是被 `TenkaichiGame.Build.cs`（或本阶段要教的 `TenkaichiGame.cpp`）依赖了。**

- 被依赖 → **不能注释**（注释了编译直接报「找不到模块」）。
- 没被依赖 → **可以注释**（但现在注释它，纯粹是给自己找事，因为后面 L2~L7 迟早要启用回来）。

---

> - `GameplayAbilities` 插件提供 `GameplayAbilities` + `GameplayTasks` 两个模块。

### B 类：引擎核心模块，【不需要插件，Build.cs 依赖但和插件无关】

这些模块是引擎自带的，`Build.cs` 里也依赖了，但**不归任何 `.uproject` 插件管**，所以跟「注释插件」没关系：

`Core`、`CoreOnline`、`CoreUObject`、`ApplicationCore`、`Engine`、`PhysicsCore`、`GameplayTags`、`AIModule`、`Hotfix`、`Niagara`、`PropertyPath`、`InputCore`、`Slate`、`SlateCore`、`RenderCore`、`DeveloperSettings`、`NetCore`、`RHI`、`Projects`、`UMG`、`AudioMixer`、`NetworkReplayStreaming`、`ClientPilot`、`EngineSettings`、`Json`、`ExternalRpcRegistry`、`HTTPServer`

> `Gauntlet` 是引擎插件 `Experimental\Gauntlet`，Build.cs 私有依赖里也有它，但它同时也在 `.uproject` 里列了（`Enabled: true`），所以也保持启用即可。

### C 类：Build.cs 没依赖，【当前可注释，但不建议】

这些插件当前 L1 教程**用不到**（Build.cs 没依赖它们的模块），理论上可以先 `Enabled: false`。但**强烈不建议现在注释**——因为：

1. 它们大多在 L2~L7 会被用到，到时又要改回来，来回折腾。
2. 注释了也没省下任何编译时间（插件没启用本来就不参与编译）。
3. 保持「一比一还原」是铁律 23 的总纲，自己动手注释反而偏离 Lyra。

属于 C 类的（举例，不全）：

- **VR/AR 平台插件（本来就是 `false`）**：`MagicLeap` 系列、`OpenXR` 系列、`SteamVR`、`GearVR`、`LuminPlatformFeatures`、`MLSDK` —— 这些 Lyra 本来就没启用，你照抄成 `false` 就已经是「注释」状态了。
- **`ResonanceAudio`、`RuntimePhysXCooking`**：Lyra 也是 `false`，照抄即可。
- **示例内容插件**：`ShooterCore`、`ShooterMaps`、`TopDownArena`、`ShooterExplorer`、`ShooterTests`、`FunctionalTestingEditor` —— 方案 A 已确认全搬，保持 `true`。
- **在线服务**：`OnlineSubsystemEOS`、`OnlineServicesEOS`、`OnlineSubsystemSteam`、`SocketSubsystemSteamIP`、`SteamSockets`、`PlayFabParty`、`EOSReservedHooks`、`OnlineFramework` 等 —— L5/L7 联机会用到，保持 `true`。

## 三、结论与建议

1. **当前 L1 教程：保持 `.uproject` 现状（81 个全按 Lyra 原样），一个都别注释。**
   - 理由：Build.cs 已经写全了 20 个「插件模块」依赖，注释任何一个都会编译失败。
   - 真正「已经注释」的（`Enabled: false`）就是 Lyra 里本来就是 `false` 的那 12 个 VR/AR/ResonanceAudio/RuntimePhysXCooking，你照抄成 `false` 就是对的，不用再额外动手。

2. **什么时候才需要「注释」**：如果后续某个阶段（比如 L5 GAS）之前想先跑起来、又担心某个插件依赖太多，才考虑临时 `false`。但按铁律 23「一比一完整还原」，我们不这么做——Lyra 怎么写的就怎么启用。

3. **一句话记住**：`.uproject` 的插件和 `Build.cs` 的模块依赖是「一套」，谁动谁编译崩。当前阶段，**照抄、别注释、别删**。
