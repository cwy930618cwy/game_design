## 一、为什么有这一层（解决什么问题）

回到总纲依赖层次：

```
L1 模块地基：Game 模块（.uproject/Build.cs/模块入口/日志/Tag）  ← 已完成
L2 底层插件：ModularGameplayActors / GameplayMessageRouter      ← 已完成（已还原）
L3 系统基础地基 + GAS 叶子                                      ← 本阶段
L4 角色体系：Team / Pawn / Character / PlayerController ...
L5 GAS 核心 + System 收口：GameplayAbility / ASC / AssetManager / GameInstance
...
```

L2 给了两个"底座"（Actor 可扩展 + 对象可传话）。但再往上盖之前，**必须先铺两层底**：

1. **CommonGame/CommonUser 插件**：Lyra 的玩家/会话地基，`GameInstance` 和 `PlayerController` 都继承它——**不装它，阶段四/五整个卡死**。
2. **一批"能力叶子"**（GAS 里能自包含的小类）和**两个真独立的 System 类**（GameEngine、GameplayCueManager）：它们是角色体系和 GAS 核心的底层依赖，**必须先有**。

> 一句话：**阶段三先铺"地基 + 叶子"，把后续所有层都要用到的底打好。** 真正重头的 `AssetManager`/`GameData`/`GameInstance` 是"收口类"，要等角色+GAS 就位才能教（放到阶段五）。

## 二、⚠️ 先说清：为什么阶段三不再包含 AssetManager / GameData / GameInstance

> 旧版总 md 把阶段三当成"整个 System 目录"，并分"线 A（独立）/ 线 B（带依赖）"。**这是错的，2026-10-08 已推翻**（见复盘）。

真实依赖查证（铁律 30/31）显示：

| System 类 | 真实依赖 | 结论 |
|----------|---------|------|
| `TenkaichiGameEngine` | `UGameEngine`（引擎） | ✅ 真独立，本阶段教 |
| `TenkaichiGameplayCueManager` | `UGameplayCueManager`（引擎 GAS） | ✅ 真独立，本阶段教 |
| `TenkaichiGameData` | `.cpp` 的 `Get()` 硬调用 `AssetManager` | ❌ 收口类，阶段五教 |
| `TenkaichiAssetManager` | 依赖 GameData + PawnData + GameplayCueManager | ❌ 收口类，阶段五教 |
| `TenkaichiGameInstance` | 继承 `UCommonGameInstance` + 依赖 Player | ❌ 依赖角色，阶段五教 |

> **关键**：`GameData` 不是"软引用不影响编译"——它的 `Get()` 是**运行时硬调用** `AssetManager`，`AssetManager` 又无底依赖角色+GAS。所以 `GameData`/`AssetManager`/`GameInstance` 都是**收口类**，必须放到阶段五（GAS 核心 + 收口）一起教。
>
> 本阶段只教**真独立**的部分 + **能力叶子**。
