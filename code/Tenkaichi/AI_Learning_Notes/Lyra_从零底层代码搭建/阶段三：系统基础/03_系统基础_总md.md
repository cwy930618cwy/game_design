## 一、为什么有这一层（解决什么问题）

回到总纲依赖层次：

```
L1 模块地基：Game 模块（.uproject/Build.cs/模块入口/日志/Tag）  ← 已完成
L2 底层插件：ModularGameplayActors / GameplayMessageRouter      ← 已完成（已还原）
L3 系统基础：GameInstance / AssetManager / GameEngine / 消息    ← 本阶段
L4 角色与玩家：Character / Player / GameMode / Experience
L5 Gameplay 系统：AbilitySystem / Input / Camera / Inventory / Teams
...
```

L2 给了两个"底座"（Actor 可扩展 + 对象可传话）。但一个游戏要跑起来，还缺**几个"全局大脑"**——它们负责：
- **GameInstance**：整个游戏的"会话级"单例（跨关卡存活，管 InitState 注册、用户登录、会话）。
- **AssetManager**：整个游戏**资源的"大管家"**（谁加载、何时加载、加载进度）。
- **GameEngine**：引擎初始化钩子（在引擎起来时做自定义）。
- **GameData / GameSession / GameplayTagStack**：全局数据资产、会话规则、可复制的 Tag 栈。

> 一句话：**L3 给了游戏几个"全局单例 + 全局数据"，让上层（角色/玩家/体验）有地方安放"全局状态"。**

## 三、⚠️ 关键问题：阶段三的依赖（必须先跟你说清）

**这是 Lyra 的真实结构，不是 Bug**——`System/` 目录**并不完全独立**，它引用了一些阶段四/五才建的类：

| 本阶段文件 | 依赖的"未来类" | 属于 |
|-----------|---------------|------|
| `UTenkaichiGameInstance` | `UTenkaichiPlayerController`、`UTenkaichiLocalPlayer` | 阶段四 |
| `UTenkaichiAssetManager` | `UTenkaichiPawnData` | 阶段五 |
| `UTenkaichiGameData` | `UGameplayEffect`（GAS 属性） | 阶段五 |

**还有一个更前置的问题**：`UTenkaichiGameInstance` 继承 **`UCommonGameInstance`**（来自 Lyra 的 `CommonGame` 插件），但**你工程 `Plugins\` 里还没有 `CommonGame` 插件**（`.uproject` 声明了它，但插件本体没装）。

> 所以阶段三**不是完全独立的**。要做 `TenkaichiGameInstance`，得先有 `CommonGame` 插件；做 `AssetManager`/`GameData` 又引用了阶段四五的类。
