# 3.4.2 AbilityTagRelationshipMapping —— 教 .cpp

## 一、本文件要解决什么

`.h` 里声明了 3 个查询函数，这里把它们的**实现**写出来。

三个函数干的事本质一样：**遍历关系数组 `AbilityTagRelationships`，找出"匹配上当前技能标签"的那条关系，把它配置的「要阻断/要取消/要要求/要禁止」的标签收集出来。**

实现很朴素——就是 `for` 循环 + `AppendTags`（把标签并进结果容器），没有任何花哨逻辑。

#include "AbilitySystem/TenkaichiAbilityTagRelationshipMapping.h"

// 给一组技能标签，解析出「要阻断/取消的标签」
void UTenkaichiAbilityTagRelationshipMapping::GetAbilityTagsToBlockAndCancel(const FGameplayTagContainer& AbilityTags, FGameplayTagContainer* OutTagsToBlock, FGameplayTagContainer* OutTagsToCancel) const
{
	// 暂时用简单的遍历
	for (int32 i = 0; i < AbilityTagRelationships.Num(); i++)
	{
		const FTenkaichiAbilityTagRelationship& Tags = AbilityTagRelationships[i];
		if (AbilityTags.HasTag(Tags.AbilityTag))
		{
			if (OutTagsToBlock)
			{
				OutTagsToBlock->AppendTags(Tags.AbilityTagsToBlock);
			}
			if (OutTagsToCancel)
			{
				OutTagsToCancel->AppendTags(Tags.AbilityTagsToCancel);
			}
		}
	}
}

// 给一组技能标签，解析出「激活时额外要求/禁止的标签」
void UTenkaichiAbilityTagRelationshipMapping::GetRequiredAndBlockedActivationTags(const FGameplayTagContainer& AbilityTags, FGameplayTagContainer* OutActivationRequired, FGameplayTagContainer* OutActivationBlocked) const
{
	// 暂时用简单的遍历
	for (int32 i = 0; i < AbilityTagRelationships.Num(); i++)
	{
		const FTenkaichiAbilityTagRelationship& Tags = AbilityTagRelationships[i];
		if (AbilityTags.HasTag(Tags.AbilityTag))
		{
			if (OutActivationRequired)
			{
				OutActivationRequired->AppendTags(Tags.ActivationRequiredTags);
			}
			if (OutActivationBlocked)
			{
				OutActivationBlocked->AppendTags(Tags.ActivationBlockedTags);
			}
		}
	}
}

// 判断「这组技能标签」是否被「传入的动作标签」取消
bool UTenkaichiAbilityTagRelationshipMapping::IsAbilityCancelledByTag(const FGameplayTagContainer& AbilityTags, const FGameplayTag& ActionTag) const
{
	// 暂时用简单的遍历
	for (int32 i = 0; i < AbilityTagRelationships.Num(); i++)
	{
		const FTenkaichiAbilityTagRelationship& Tags = AbilityTagRelationships[i];

		if (Tags.AbilityTag == ActionTag && Tags.AbilityTagsToCancel.HasAny(AbilityTags))
		{
			return true;
		}
	}

	return false;
}

## 四、逐段讲解

### 1. 头文件

```cpp
#include "AbilitySystem/TenkaichiAbilityTagRelationshipMapping.h"
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiAbilityTagRelationshipMapping)
```

- 第一行：包含自己的 `.h`（声明所在文件）。
- 第二行：`UE_INLINE_GENERATED_CPP_BY_NAME(...)`——UE5 的**内联生成代码宏**，替代老版本在 `.cpp` 里手动 `#include "...generated.h"` 的做法，自动把 UHT 生成的实现内联进来。**名字必须和类名一致**（`TenkaichiAbilityTagRelationshipMapping`）。

### 2. 第一个函数：`GetAbilityTagsToBlockAndCancel`

```cpp
void UTenkaichiAbilityTagRelationshipMapping::GetAbilityTagsToBlockAndCancel(const FGameplayTagContainer& AbilityTags, FGameplayTagContainer* OutTagsToBlock, FGameplayTagContainer* OutTagsToCancel) const
{
	for (int32 i = 0; i < AbilityTagRelationships.Num(); i++)
	{
		const FTenkaichiAbilityTagRelationship& Tags = AbilityTagRelationships[i];
		if (AbilityTags.HasTag(Tags.AbilityTag))
		{
			if (OutTagsToBlock)      // 出参可能为空，先判空再写
			{
				OutTagsToBlock->AppendTags(Tags.AbilityTagsToBlock);
			}
			if (OutTagsToCancel)
			{
				OutTagsToCancel->AppendTags(Tags.AbilityTagsToCancel);
			}
		}
	}
}
```

逻辑拆解：

1. `AbilityTagRelationships.Num()` —— 关系数组的长度。
2. `AbilityTags.HasTag(Tags.AbilityTag)` —— 判断"传入的技能标签"里**是否包含**这条关系的 `AbilityTag`。
   - 包含 → 这条关系生效，把它的"要阻断/要取消"标签收集进结果。
   - 不包含 → 跳过这条。
3. `if (OutTagsToBlock)` —— **判空**。因为出参是裸指针，调用方可能传 `nullptr`（表示"我不关心这个结果"），必须先判断再解引用，否则崩。
4. `OutTagsToBlock->AppendTags(...)` —— 把这条关系里的标签**追加**进结果容器（`AppendTags` = 把参数里的所有标签合并进来）。

### 3. 第二个函数：`GetRequiredAndBlockedActivationTags`

结构和第一个**一模一样**，只是收集的字段不同：

```cpp
OutActivationRequired->AppendTags(Tags.ActivationRequiredTags);  // 收集「激活要求」标签
OutActivationBlocked->AppendTags(Tags.ActivationBlockedTags);     // 收集「激活禁止」标签
```

匹配条件同样是 `AbilityTags.HasTag(Tags.AbilityTag)`。

### 4. 第三个函数：`IsAbilityCancelledByTag`（返回 bool）

```cpp
if (Tags.AbilityTag == ActionTag && Tags.AbilityTagsToCancel.HasAny(AbilityTags))
{
	return true;
}
return false;
```

和前两个**不同**的地方：

- 前两个是"**技能标签匹配**关系里的 `AbilityTag`"（`HasTag`，看包含）；
- 这个是"**动作标签 == 关系里的 AbilityTag**"（`==`，精确相等）。

完整语义：**如果"传入的动作标签"正好等于某条关系的关键标签，并且这条关系配置的"要取消"标签里，含有"当前这组技能标签"中的任意一个，就认为该技能被取消了。**

- `Tags.AbilityTagsToCancel.HasAny(AbilityTags)` —— `HasAny` = 两组标签**有任意交集**就返回 true。
- 遍历完没匹配到 → 返回 `false`。

## 五、三个函数的对比

| 函数 | 返回值 | 匹配方式 | 干什么 |
|------|--------|---------|--------|
| `GetAbilityTagsToBlockAndCancel` | `void`（出参） | `HasTag`（技能标签包含关系标签） | 收集「要阻断/要取消」标签 |
| `GetRequiredAndBlockedActivationTags` | `void`（出参） | `HasTag`（技能标签包含关系标签） | 收集「激活要求/禁止」标签 |
| `IsAbilityCancelledByTag` | `bool` | `==`（动作标签精确相等） | 判断技能是否被取消 |

## 六、几个要记住的点

1. **出参用裸指针 + 判空**：`Out*` 可能为 `nullptr`，必须先 `if` 判断再解引用。
2. **`AppendTags`**：把一组标签合并进另一组（取并集）。
3. **`HasTag` vs `HasAny`**：`HasTag` 判断"单个标签是否在容器里"；`HasAny` 判断"两组容器是否有交集"。
4. **`==` vs `HasTag`**：前两个函数用 `HasTag`（技能标签"包含"关系标签）；第三个用 `==`（动作标签"精确等于"关系标签）——因为动作标签是单一标签，要精确匹配。
5. **`UE_INLINE_GENERATED_CPP_BY_NAME`**：名字必须和类名一致。
