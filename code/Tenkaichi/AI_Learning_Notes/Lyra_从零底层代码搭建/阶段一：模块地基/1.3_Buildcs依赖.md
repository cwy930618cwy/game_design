## 一、`Build.cs` 是什么（先讲为什么）

`Build.cs` 是一个模块的"依赖清单"。它告诉 UE 编译系统（UnrealBuildTool）：

- 这个模块**用到了引擎里的哪些模块**（`Core`、`Engine`、`GameplayTags`…），编译时要把这些模块的头文件路径、链接库准备好。
- 这些依赖里，哪些是**公开的**（引用本模块的人也能用）、哪些是**私有的**（只有本模块自己用）。

如果 `Build.cs` 少挂了一个依赖，后面阶段（L2~L7）写代码时一 include 那个模块的头文件，编译就会报"找不到 XXX.h"。所以地基这一步，必须把 Lyra 的依赖**一个不漏**地还原。

## 四、代码大概干嘛的（先给概念，详细后置）

- **`PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;`**：告诉编译系统用"显式或共享的预编译头"模式，加快编译。
- **`PublicIncludePaths`**：把 `TenkaichiGame` 目录加进公开头文件搜索路径，这样本模块（以及引用本模块的人）能直接 `#include "TenkaichiGame/xxx.h"`。
- **`PrivateIncludePaths`**：私有头文件搜索路径，当前为空。
- **`PublicDependencyModuleNames`（22 个公开依赖）**：不仅本模块能用，引用本模块的其他模块也能"看到"。比如后面 Character 代码要用 GAS（`GameplayAbilities`），就得是公开依赖。
- **`PrivateDependencyModuleNames`（26 个私有依赖）**：只本模块内部用，不暴露给引用者（比如 `UMG` / `Slate` 这些 UI 实现细节）。
- **`DynamicallyLoadedModuleNames`**：动态加载的模块，当前为空。
- **`PublicDefinitions.Add("SHIPPING_DRAW_DEBUG_ERROR=1")`**：Shipping/Test 构建时，让 `DrawDebug` 函数直接报编译错误（防止上线版本残留调试画线）。
- **`ExternalRpcRegistry` + `HTTPServer`**：两个后补私有依赖，用于外部 RPC 框架；Shipping 下用 `WITH_RPC_REGISTRY=0` / `WITH_HTTPSERVER_LISTENERS=0` 宏把相关功能剥离，去掉漏洞。
- **`SetupGameplayDebuggerSupport(Target)` / `SetupIrisSupport(Target)`**：两个方法调用，分别启用 Gameplay 调试器和 Iris 网络复制支持。

> 以上每个依赖"它具体是什么、为什么 Lyra 要挂它"，会在后面阶段**遇到它真正派上用场的那一步**再逐个展开讲。本步先**一比一写全**，不删不跳（铁律 23/25/27）。
