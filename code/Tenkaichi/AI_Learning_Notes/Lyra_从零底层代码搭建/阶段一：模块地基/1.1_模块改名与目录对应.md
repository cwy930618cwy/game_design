## 一、为什么模块要叫 TenkaichiGame，而不是 Tenkaichi（先讲为什么）

回顾铁律 24（前缀替换规则）：**把 Lyra 里的 `Lyra` 换成 `Tenkaichi`，其余一个字不砍**。

Lyra 的模块名叫 `LyraGame`（见 `LyraStarterGame.uproject` 第 8 行 `"Name": "LyraGame"`）：

```json
"Modules": [
    {
        "Name": "LyraGame",
        "Type": "Runtime",
        "LoadingPhase": "Default",
        ...
    },
```

所以 `LyraGame` → `TenkaichiGame`，**`Game` 这个字必须保留**。你现在工程里叫 `Tenkaichi`（丢了 `Game`），不符合一比一还原，所以要改。

> 一句话：不是"叫 Tenkaichi 也能跑"，而是"Lyra 叫 LyraGame，所以你必须叫 TenkaichiGame"。这就是铁律 17「命名一比一对应」的一部分。

## 二、改名涉及哪些地方（全景，先看清要动什么）

模块名一改，凡是"写死了 `Tenkaichi` 这个名字"的地方都要跟着改，否则编译时 UE 会报"找不到模块 TenkaichiGame"。一共 **4 处**：

| # | 位置 | 现在 | 改成 |
|---|------|------|------|
| 1 | 目录名 `Source/Tenkaichi/` | `Tenkaichi` | `TenkaichiGame` |
| 2 | `Tenkaichi.uproject` 第 8 行 | `"Name": "Tenkaichi"` | `"Name": "TenkaichiGame"`（并补 `TenkaichiEditor` 模块） |
| 3 | `Source/Tenkaichi.Target.cs` 第 13 行 | `ExtraModuleNames.Add("Tenkaichi")` | `ExtraModuleNames.Add("TenkaichiGame")` |
| 4 | `Source/TenkaichiEditor.Target.cs` 第 13 行 | `ExtraModuleNames.Add("Tenkaichi")` | `ExtraModuleNames.Add("TenkaichiGame")` |

> 注意目录里的 3 个文件（`Tenkaichi.Build.cs` / `Tenkaichi.cpp` / `Tenkaichi.h`）的名字和内容，会在后续小步里处理（`Build.cs` 下一步、`Tenkaichi.cpp`→`TenkaichiGameModule.cpp` 再下一步、`Tenkaichi.h` 删除）。**本小步先只做「目录改名 + 3 处引用对齐」**。

## 三、逐个讲

### 3.1 目录名 `Source/Tenkaichi/` → `Source/TenkaichiGame/`

UE 约定：一个模块的代码放在 `Source/模块名/` 目录下，目录名必须和模块名一致。Lyra 的模块 `LyraGame` 代码就在 `Source/LyraGame/`。

所以你把 `Source/Tenkaichi/` 重命名为 `Source/TenkaichiGame/` 即可（铁律 09 目录对应）。

> 操作：在 IDE 或资源管理器里把 `Source/Tenkaichi` 文件夹重命名为 `Source/TenkaichiGame`。里面的文件先不动，后面小步再逐个改。

### 3.2 `.uproject` 里的模块名

你现在的 `Tenkaichi.uproject`：

```json
{
	"FileVersion": 3,
	"EngineAssociation": "5.6",
	"Category": "",
	"Description": "",
	"Modules": [
		{
			"Name": "Tenkaichi",        ← 这里要改
			"Type": "Runtime",
			"LoadingPhase": "Default"
		}
	],
	...
}
```

改成 `"Name": "TenkaichiGame"`，并且**补上第二个模块 `TenkaichiEditor`**（对应 Lyra 的 `LyraEditor`，铁律 23 完整还原，不能只建 Game 漏掉 Editor）：

```json
	"Modules": [
		{
			"Name": "TenkaichiGame",
			"Type": "Runtime",
			"LoadingPhase": "Default",
			"AdditionalDependencies": [
				"DeveloperSettings",
				"Engine"
			]
		},
		{
			"Name": "TenkaichiEditor",
			"Type": "Editor",
			"LoadingPhase": "Default"
		}
	],
```

> 对照 Lyra：`LyraStarterGame.uproject` 里是 `"Name": "LyraGame"`（`Type: "Runtime"`、`LoadingPhase: "Default"`）+ `"Name": "LyraEditor"`（`Type: "Editor"`），而且 **`LyraGame` 这个模块还带了 `AdditionalDependencies`（`DeveloperSettings`、`Engine`）**。
>
> ⚠️ **铁律 23 + 25：这个 `AdditionalDependencies` 必须一比一完整还原，当场写上，不能「后面阶段再加」**。Lyra 的 `.uproject` 里就是这么写的（第 11~14 行），所以 `TenkaichiGame` 也必须一模一样带上 `DeveloperSettings` + `Engine` 两个额外依赖。
>
> **大概干嘛的（先有个概念，后面遇到再细讲）**：
> - `AdditionalDependencies` 是在 `Build.cs` 声明的依赖之外，**再额外给这个模块补依赖**的字段。
> - `Engine`：让 `TenkaichiGame` 模块能直接用引擎最核心那套头文件/接口（几乎每个游戏模块都依赖它）。
> - `DeveloperSettings`：让模块能用 UE 的「开发者设置」系统（`UDeveloperSettings`），Lyra 用它做编辑器里的各种可配置项。
>
> 这两个依赖各自管哪些具体功能、在哪个阶段派上用场，**等后面遇到（比如建开发者设置、音频设置时）再详细讲**。现在只要记住：Lyra 这么写，`TenkaichiGame` 就照写，一个不能少。

### 3.3 两个 `Target.cs` 里的 `ExtraModuleNames`

`Target.cs` 是"这个编译目标要包含哪些模块"的清单。你现在两个文件都写了 `ExtraModuleNames.Add("Tenkaichi")`：

- `Source/Tenkaichi.Target.cs`（第 13 行）：游戏目标（`TargetType.Game`）
- `Source/TenkaichiEditor.Target.cs`（第 13 行）：编辑器目标（`TargetType.Editor`）

这两行的 `"Tenkaichi"` 都要改成 `"TenkaichiGame"`。

> 对照 Lyra：`LyraGame.Target.cs` 第 17 行是 `ExtraModuleNames.AddRange(new string[] { "LyraGame" });`，`LyraEditor.Target.cs` 第 12 行是 `ExtraModuleNames.AddRange(new string[] { "LyraGame", "LyraEditor" });`。
>
> **⚠️ 完整还原要求（铁律 23 + 25）**：Lyra 的 `Target.cs` 比你的复杂得多——它有 **10 个 Target 文件**（`LyraGame`、`LyraEditor`、`LyraClient`、`LyraServer`，以及 `LyraGameEOS`/`LyraGameSteam`/`LyraGameSteamEOS`/`LyraServerEOS`/`LyraServerSteam`/`LyraServerSteamEOS` 六种 EOS/Steam 组合），而且 `LyraGame.Target.cs` 里还有一大段 `ApplySharedLyraTargetSettings`（约 280 行，做证书校验、GameFeature 插件扫描、Shipping 配置等）+ `ConfigureGameFeaturePlugins`。**这些都要一比一完整还原，一个字不能少。**
>
> 但**代码完整 ≠ 逻辑一次讲透**（铁律 25）：Target.cs 涉及 10 个文件 + 280 行设置，内容多，所以拆成几个小 md 逐个写全。本小步先聚焦「模块改名」这个最小闭环——**但注意：这里不是"只写一行、其余以后补"，而是"先写哪个文件、后面小步接着把其余文件完整写全"**。Target.cs 的完整还原（10 个文件 + `ApplySharedLyraTargetSettings` + `ConfigureGameFeaturePlugins` 全量）会紧接着在后续小 md 里一比一教完，不会漏。
