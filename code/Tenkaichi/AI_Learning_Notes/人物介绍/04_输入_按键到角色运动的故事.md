# 输入：按键 → 角色运动 的故事

> **定位**：前面 [08 开火大戏](./08_故事版总结_一场开火大戏.md) 讲了"技能"怎么演。但开火之前，得先能**移动、转视角、蹲下**——这些是"输入"。本文用故事讲清：**你按下 WASD / 鼠标，角色为什么会动？**
>
> **一句话**：按键 → **翻译官**把"物理按键"翻译成"游戏指令标签" → **操作台**收到指令，转交给**身法替身**（移动）和**镜头**（转视角）。开火这类"技能"则走另一条道，交给**技能总管**。

---

## 一、先认识 4 个角色（延续剧院世界观）

| 角色 | 技术对应 | 一句话职责 |
|------|---------|-----------|
| 🎮 **观众的手** | 键盘/鼠标/手柄 | 真人按下按键（源头）。 |
| 📨 **传令兵** | Enhanced Input 系统 + `InputAction` | 接收"哪个键被按了"，但它不懂游戏，只报"鼠标左键按了"这种原始消息。 |
| 🗂️ **翻译官** | `ULyraInputConfig` | 把"物理按键"翻译成"游戏指令标签"（如"移动""转视角""开火"）。 |
| 🎛️ **操作台** | `ULyraHeroComponent` | 收到翻译后的指令，**分派**给对应的人：移动给身法替身，转视角给镜头，开火给技能总管。 |
| 🏃 **身法替身** | `ULyraCharacterMovementComponent` | 真正让角色"跑起来"的物理引擎。 |

> **核心认知**：传令兵只懂"几号键按了"，不懂"移动"。翻译官把它变成游戏能懂的"移动指令"，操作台再执行。**这就是"输入映射"的意义——把硬件语言翻译成游戏语言。**

## 二、故事：你按下"W"键，角色往前走

```
🎮 你按下键盘 "W"
        │
        ▼
① 📨 传令兵："有人按了 IA_Move 这个动作！"
   （Enhanced Input 系统检测到，发出 InputAction 消息）
        │
        ▼
② 🗂️ 翻译官查字典：
   "IA_Move" 对应的游戏指令标签 = InputTag.Move
   （查的是 InputConfig 这张映射表）
        │
        ▼
③ 🎛️ 操作台收到："InputTag.Move 触发了！"
   调用 Input_Move( 方向值 )
        │
        ▼
④ 🎛️ 操作台算方向：
   "玩家现在面向哪？" → 取镜头的朝向（Yaw）
   把"前后左右"换算成"世界里的前进方向"
        │
        ▼
⑤ 🏃 操作台对身法替身喊："往这个方向加个移动力！"
   调用 Pawn->AddMovementInput(方向, 力度)
        │
        ▼
⑥ 🏃 身法替身（移动物理）：收到，角色开始往前走
```

**就这么简单！** 移动 = **按键 → 翻译 → 操作台算方向 → 身法替身执行**。

## 三、故事：你移动鼠标，镜头转过去

```
🎮 你移动鼠标
        │
        ▼
① 📨 传令兵："IA_Look_Mouse 动作触发了！"
        │
        ▼
② 🗂️ 翻译官：IA_Look_Mouse → InputTag.Look_Mouse
        │
        ▼
③ 🎛️ 操作台收到，调用 Input_LookMouse( X, Y )
        │
        ├─ X（左右）→ Pawn->AddControllerYawInput(X)    转头（水平）
        └─ Y（上下）→ Pawn->AddControllerPitchInput(Y)  抬头/低头（垂直）
        │
        ▼
④ 🎥 镜头跟着转，画面随之改变
```

> **注意**：移动用的是"镜头朝向"（`GetControlRotation().Yaw`），所以**你先转视角，再按 W，角色就朝新方向走**——这就是"镜头相对移动"。

## 四、关键分岔：移动 vs 开火，走的是两条路

这是整篇**最重要**的一点。操作台（HeroComponent）在绑定输入时，把指令分成**两类**：

```
🎛️ 操作台绑定输入时，分两条路：

┌─ 路线 A：NativeInputActions（固定功能，手动绑）──────┐
│  • InputTag.Move      → Input_Move      （移动）     │
│  • InputTag.Look_Mouse→ Input_LookMouse （转视角）   │
│  • InputTag.Crouch    → Input_Crouch    （蹲下）     │
│  • InputTag.AutoRun   → Input_AutoRun   （自动跑）   │
│  这些是"角色本来就有的固定动作"，直接调函数执行        │
└──────────────────────────────────────────────────────┘

┌─ 路线 B：AbilityInputActions（技能，自动绑）─────────┐
│  • InputTag.Weapon.Fire → 转交给"技能总管"(ASC)      │
│  • InputTag.Jump        → 转交给 ASC                 │
│  这些是"技能"，操作台不自己处理，甩给 ASC 去激活技能   │
└──────────────────────────────────────────────────────┘
```

**两条路的代码证据**（`InitializePlayerInput` 里）：

```cpp
// 路线 A：移动/镜头/蹲下 —— 手动绑定到固定函数
LyraIC->BindNativeAction(InputConfig, InputTag_Move, ..., this, &Input_Move, ...);
LyraIC->BindNativeAction(InputConfig, InputTag_Look_Mouse, ..., this, &Input_LookMouse, ...);

// 路线 B：技能 —— 绑定到"转交 ASC"的函数
LyraIC->BindAbilityActions(InputConfig, this, &Input_AbilityInputTagPressed, &Input_AbilityInputTagReleased, ...);
```

> **路线 B 的转交**：`Input_AbilityInputTagPressed` 里其实就一句——`LyraASC->AbilityInputTagPressed(InputTag)`，把"开火键被按了"这件事**转告技能总管**，剩下的交给 [08 开火大戏](./08_故事版总结_一场开火大戏.md) 那套流程。

## 六、几个"啊哈"点（把困惑一次说清）

| 你可能困惑的 | 真相 |
|-------------|------|
| "按键怎么就变成移动了？" | 中间有个**翻译官（InputConfig）**，把"物理键"翻译成"游戏指令标签"。 |
| "移动和开火为什么不一样？" | 移动是**角色固定功能**（操作台直接执行）；开火是**技能**（转交技能总管 ASC）。 |
| "为什么先转视角再按 W 会朝新方向走？" | 移动方向取的是**镜头朝向**（`ControlRotation.Yaw`），镜头相对移动。 |
| "蹲下/自动跑归谁管？" | 和移动一样是**固定功能**，走路线 A，操作台直接调 `ToggleCrouch()` 等。 |
| "这套绑定什么时候发生？" | 角色初始化到一定阶段（`bReadyToBindInputs`）时，操作台的 `InitializePlayerInput` 统一绑定。 |

---

## 七、记住这 3 句话就够了

1. **按键先过"翻译官"（InputConfig）变成游戏指令标签，再交给"操作台"（HeroComponent）分派。**
2. **移动/镜头/蹲下 = 固定功能**，操作台直接执行；**开火/跳跃 = 技能**，转交技能总管（ASC）。
3. **移动方向取镜头朝向**，所以"镜头相对移动"——转视角决定你往哪走。
