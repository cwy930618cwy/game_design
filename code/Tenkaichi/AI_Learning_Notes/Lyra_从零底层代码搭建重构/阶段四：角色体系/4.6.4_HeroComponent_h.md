## 一、`.h` 全景（这段代码是什么结构）

`UTenkaichiHeroComponent` 继承 **`UPawnComponent`**（可挂在 Pawn 上的组件）+ **`IGameFrameworkInitStateInterface`**（初始化状态机接口）。

它管三件事：**相机（CameraMode）、输入（InputMappings）、初始化状态机（InitState）**。方法分成几组：

1. **查找/静态** —— `FindHeroComponent()`、特性名字 `NAME_ActorFeatureName`/`NAME_BindInputsNow`
2. **相机** —— `SetAbilityCameraMode()`/`ClearAbilityCameraMode()`/`DetermineCameraMode()`
3. **输入配置** —— `AddAdditionalInputConfig()`/`RemoveAdditionalInputConfig()`/`IsReadyToBindInputs()`
4. **初始化状态机** —— `CanChangeInitState()`/`HandleChangeInitState()`/`OnActorInitStateChanged()`/`CheckDefaultInitialization()`
5. **生命周期** —— `OnRegister()`/`BeginPlay()`/`EndPlay()`
6. **输入处理函数** —— `Input_Move()`/`Input_LookMouse()`/`Input_LookStick()`/`Input_Crouch()`/`Input_AutoRun()`/`Input_AbilityInputTagPressed()`/`Input_AbilityInputTagReleased()`

## 三、逐段讲解

### 1. 头文件包含（第 5~9 行）

```cpp
#include "Components/GameFrameworkInitStateInterface.h"  // 初始化状态机接口
#include "Components/PawnComponent.h"                    // Pawn 组件基类
#include "GameFeatures/GameFeatureAction_AddInputContextMapping.h"  // ⚠️ 定义了 FInputMappingContextAndPriority（L7，未教）
#include "GameplayAbilitySpecHandle.h"                   // ⚠️ GAS 的能力 Spec 句柄（断点）
#include "TenkaichiHeroComponent.generated.h"            // UHT 生成头
```

前两个是已教的（L2），后两个是**硬 include**（不是前置声明）——这正是 `.h` 要挂起的原因。

### 2. API 宏（第 11 行）

```cpp
#define UE_API TENKAICHIGAME_API
```

`UE_API` 是本模块的导出宏，保证方法能被蓝图/其他模块调用。`TenkaichiHeroComponent` 类标了 `MinimalAPI`（只导出最少的），所以每个要导出的方法前都要手动加 `UE_API`。

### 3. 前置声明（第 13~24 行）

```cpp
namespace EEndPlayReason { enum Type : int; }
struct FLoadedMappableConfigPair;
struct FMappableConfigPair;

class UGameFrameworkComponentManager;
class UInputComponent;
class UTenkaichiCameraMode;      // L5 Camera（未教）
class UTenkaichiInputConfig;     // L5 Input（未教）
class UObject;
struct FActorInitStateChangedParams;
struct FFrame;
struct FGameplayTag;
struct FInputActionValue;
```

这些**前置声明**（`class X;`/`struct X;`）不阻塞编译——它们只在头文件里作为**指针/引用参数**出现，编译器不需要完整定义。

### 4. 类声明 + 构造函数 + 静态查找（第 32~42 行）

```cpp
UCLASS(MinimalAPI, Blueprintable, Meta=(BlueprintSpawnableComponent))
class UTenkaichiHeroComponent : public UPawnComponent, public IGameFrameworkInitStateInterface
```

- `Blueprintable` —— 允许蓝图继承
- `BlueprintSpawnableComponent` —— 允许在蓝图里作为组件添加（这正是它的用法：加到 Pawn 蓝图组件面板）

```cpp
static UTenkaichiHeroComponent* FindHeroComponent(const AActor* Actor)
{ return (Actor ? Actor->FindComponentByClass<UTenkaichiHeroComponent>() : nullptr); }
```

静态查找函数——在指定 Actor 上找 Hero 组件。`FindComponentByClass` 是引擎方法，按类型找组件。

### 5. 相机覆盖接口（第 45~48 行）

```cpp
void SetAbilityCameraMode(TSubclassOf<UTenkaichiCameraMode> CameraMode, const FGameplayAbilitySpecHandle& OwningSpecHandle);
void ClearAbilityCameraMode(const FGameplayAbilitySpecHandle& OwningSpecHandle);
```

- `TSubclassOf<UTenkaichiCameraMode>` —— 相机模式的类（软引用，不实例化）
- 技能可以**临时覆盖**默认相机（比如开镜技能），结束时用 `ClearAbilityCameraMode` 恢复
- `OwningSpecHandle` 用来标识"是谁设的覆盖"——只有同一个技能才能清除自己的覆盖

### 6. 输入配置接口（第 51~57 行）

```cpp
void AddAdditionalInputConfig(const UTenkaichiInputConfig* InputConfig);
void RemoveAdditionalInputConfig(const UTenkaichiInputConfig* InputConfig);
bool IsReadyToBindInputs() const;
static const FName NAME_BindInputsNow;   // "能力输入已可绑定"事件名
static const FName NAME_ActorFeatureName; // 本特性名字 "Hero"
```

- 一个英雄可以有**额外输入配置**（比如"开镜模式"追加一套按键绑定），用 `Add`/`Remove` 动态增删
- `IsReadyToBindInputs()` —— 输入是否已绑定好（非玩家永远 false）
- `NAME_BindInputsNow` —— 初始化到一定阶段，通过 `GameFrameworkComponentManager` 广播"现在可以绑输入了"的事件名

### 7. 初始化状态机接口（第 65~71 行）

```cpp
virtual FName GetFeatureName() const override { return NAME_ActorFeatureName; }
bool CanChangeInitState(...) const;     // 能否进入下一状态
void HandleChangeInitState(...);        // 状态改变时：初始化相机/输入/能力系统
void OnActorInitStateChanged(...);      // 别的特性（PawnExtension）状态改变时触发
void CheckDefaultInitialization();      // 推进初始化链
```

这套和 4.7 PawnExtension 完全一样——Hero 也是初始化状态机的一个"特性"（Feature）。它**监听 PawnExtension 的状态**（4.7 教过），PawnExtension 到 `DataInitialized` 后，Hero 才去初始化相机/输入。

### 8. 生命周期回调（第 75~80 行）

```cpp
virtual void OnRegister() override;     // 注册时：校验挂在 Pawn 上，注册到状态机
virtual void BeginPlay() override;      // 开始：监听 PawnExtension 状态
virtual void EndPlay(...) override;     // 结束：注销状态机
```

### 9. 输入处理函数（第 82~92 行）

```cpp
void InitializePlayerInput(UInputComponent* PlayerInputComponent);  // 把输入动作绑定到具体处理函数
void Input_AbilityInputTagPressed(FGameplayTag InputTag);  // 能力输入：按下
void Input_AbilityInputTagReleased(FGameplayTag InputTag);  // 能力输入：松开
void Input_Move(const FInputActionValue& InputActionValue);  // 移动
void Input_LookMouse(const FInputActionValue& InputActionValue);  // 鼠标视角
void Input_LookStick(const FInputActionValue& InputActionValue);  // 摇杆视角
void Input_Crouch(const FInputActionValue& InputActionValue);  // 蹲伏
void Input_AutoRun(const FInputActionValue& InputActionValue);  // 自动奔跑
```

- `FInputActionValue` —— EnhancedInput 的动作值（可以是 bool/float/Vector2D 等）
- `FGameplayTag InputTag` —— 能力输入是按"输入标签"绑定的（`InputTag_Move` 等，1.8 教过）
- 这些是**绑定到输入动作的回调**，在 `.cpp` 里实现（4.8.2 教）

### 10. 相机模式决定（第 94 行）

```cpp
TSubclassOf<UTenkaichiCameraMode> DetermineCameraMode() const;
```

决定当前用哪个相机模式——**优先用能力覆盖的，否则用 PawnData 里的默认相机**。

### 11. 成员变量（第 98~109 行）

```cpp
UPROPERTY(EditAnywhere)
TArray<FInputMappingContextAndPriority> DefaultInputMappings;  // 默认输入映射列表

UPROPERTY()
TSubclassOf<UTenkaichiCameraMode> AbilityCameraMode;  // 能力设置的相机模式

FGameplayAbilitySpecHandle AbilityCameraModeOwningSpecHandle;  // 设覆盖的技能的句柄

bool bReadyToBindInputs;  // 输入是否已绑定好
```

- `DefaultInputMappings` —— **可编辑的默认输入映射**（`FInputMappingContextAndPriority` 是 L7 GameFeatures 定义的结构体，含"哪个输入映射 + 优先级 + 是否注册到设置"）
- `AbilityCameraMode` —— 能力临时设置的相机模式（`TSubclassOf` 软引用，不 `UPROPERTY` 复制）
- `bReadyToBindInputs` —— 标记输入是否已绑定，非玩家永远 false

## 四、挂起原因回顾

`.h` 因第 5~9 行 **2 个硬 include** 整体 `#if 0`：
- `GameFeatureAction_AddInputContextMapping.h`（L7 GameFeatures，用户工程无此文件）→ 定义 `FInputMappingContextAndPriority`
- `GameplayAbilitySpecHandle.h`（GAS）→ 定义 `FGameplayAbilitySpecHandle`

**这不是我们漏代码**——是这两个文件本身没教/没建。代码一比一完整写上，挂起登记备忘录，等 GameFeatures/GAS 就位后放开。
