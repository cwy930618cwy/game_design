## 一、这步要干嘛（一句话）

把 `Tenkaichi.uproject` 整个文件，**一比一还原成 Lyra 的 `LyraStarterGame.uproject`**——只做两处替换：`LyraGame` → `TenkaichiGame`、`LyraEditor` → `TenkaichiEditor`，其余一字不砍。

> 你现在这个文件「缺胳膊少腿」：`Plugins` 数组只有 1 个插件，Lyra 有 81 个；还漏了末尾的 `EpicSampleNameHash` 字段。这步就是把缺的全补回来，让它和 Lyra 长得一模一样。

## 二、为什么非得补全（先讲为什么）

`.uproject` 是「这个工程由哪些模块、启用哪些插件」的清单，UE 加载工程时就靠它。它有几个关键部分，缺一个都可能出问题：

| 字段 | 作用 | 你现在的状态 |
|------|------|-------------|
| `Modules` | 声明工程自己的模块（对应 `Source/` 下的 `.Build.cs`） | ✅ 已改好 |
| `Plugins` | 声明启用哪些插件（插件=外部代码包，很多模块靠它提供） | ❌ 只有 1 个，Lyra 有 81 个 |
| `EpicSampleNameHash` | 官方样例工程的哈希标识（Lyra 作为样例项目带的） | ❌ 漏了 |

**为什么 `Plugins` 缺了会致命**：你 `TenkaichiGame.Build.cs` 的依赖里写了 `GameplayAbilities`、`GameFeatures`、`ModularGameplay`、`ModularGameplayActors`、`DataRegistry`、`ReplicationGraph`、`SignificanceManager`、`CommonLoadingScreen`……这些模块**不是引擎自带、也不是你工程自己的**，它们分别来自 `GameplayAbilities`、`GameFeatures`、`ModularGameplay` 等插件。`.uproject` 不启用这些插件，模块就「不存在」，一编译就报「找不到模块」。

## 四、这段代码是干嘛的（讲个大概，详细后置）

### 1. `Modules`（工程自己的模块清单）

| 字段 | 值 | 说明 |
|------|-----|------|
| `TenkaichiGame` | Runtime / Default | 主游戏模块，对应 `Source/TenkaichiGame/` 下的 `TenkaichiGame.Build.cs` |
| `AdditionalDependencies` | `DeveloperSettings` + `Engine` | 在 `Build.cs` 之外**额外补的依赖**：`Engine` 让模块能用引擎核心接口，`DeveloperSettings` 让模块能用「开发者设置」系统 |
| `TenkaichiEditor` | Editor / Default | 编辑器扩展模块，只在编辑器里加载，对应 `Source/TenkaichiEditor/` |

### 2. `Plugins`（启用哪些插件）

81 个插件，按用途大致几类：

| 类别 | 代表插件 | 说明 |
|------|---------|------|
| **玩法系统** | `GameplayAbilities`、`GameFeatures`、`ModularGameplay`、`ModularGameplayActors` | GAS 技能、玩法模块化 |
| **UI/框架** | `CommonUI`、`CommonGame`、`CommonUser`、`CommonLoadingScreen`、`UIExtension` | Lyra 的 UI 与框架层 |
| **输入** | `EnhancedInput` | 增强输入 |
| **数据/网络** | `DataRegistry`、`ReplicationGraph`、`SignificanceManager`、`GameplayMessageRouter` | 数据注册、网络优化、消息路由 |
| **示例内容** | `ShooterCore`、`ShooterMaps`、`TopDownArena`、`ShooterExplorer`、`ShooterTests` | Lyra 自带的射击示例 |
| **在线服务** | `OnlineSubsystemEOS`、`OnlineServicesEOS`、`OnlineSubsystemSteam` 等 | EOS/Steam 联机 |
| **音频/动画/渲染** | `AudioModulation`、`AnimationWarping`、`Niagara`、`Water` 等 | 各类表现能力 |
| **平台/VR（禁用）** | `MagicLeap` 系列、`OpenXR` 系列、`SteamVR`、`GearVR`、`MLSDK` | `Enabled: false`，不启用但照抄 |

### 3. `EpicSampleNameHash`（结尾那个哈希）

`"451731683"` 是 Epic 官方样例工程的标识哈希，Lyra 作为官方样例项目带着它。一比一还原就照抄这个值。

## 五、照抄时最容易踩的坑（重点）

1. **插件名一个字不改**：`ActorPalette`、`GameplayAbilities`、`AnimationLocomotionLibrary`……这些是引擎/第三方插件名，**不是项目命名，不做 `Lyra`→`Tenkaichi` 替换**。
2. **`Enabled: false` 也要照抄**：`MagicLeap` 系列（3 个）、`OpenXR` 系列（3 个）、`SteamVR`、`GearVR`、`LuminPlatformFeatures`、`MLSDK`、`ResonanceAudio`、`RuntimePhysXCooking` 共 **12 个是 `false`**，别图省事删掉——禁用也是还原的一部分。
3. **字段一个不落**：`Enabled` / `Optional` / `TargetAllowList` / `PlatformAllowList` / `SupportedTargetPlatforms`，Lyra 有哪个字段你就写哪个字段，值也别改（比如 `PlayFabParty` 有 `PlatformAllowList` + `SupportedTargetPlatforms` 两个字段）。
4. **`ModelingToolsEditorMode` 是裸的**：Lyra 里它只有 `{ "Name": "...", "Enabled": true }`，**不带** `TargetAllowList`。你现在的文件里它多带了个 `TargetAllowList: ["Editor"]`，要删掉，和 Lyra 对齐。
5. **结尾别漏 `EpicSampleNameHash`**：Lyra 最后一行是 `"EpicSampleNameHash": "451731683"`，照抄。
6. **`Category` 是 `"Samples"`**：Lyra 里不是空字符串，是 `"Samples"`，照抄。
7. **示例插件照抄**（方案 A 已确认）：`ShooterCore`、`ShooterMaps`、`TopDownArena`、`ShooterExplorer`、`ShooterTests` 一比一全搬，不排除。
