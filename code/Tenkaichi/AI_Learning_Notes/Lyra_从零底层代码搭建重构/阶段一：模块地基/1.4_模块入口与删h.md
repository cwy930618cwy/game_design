## 一、模块入口是干嘛的（先讲为什么）

每个 UE 模块都需要一个"入口文件"，负责在模块加载/卸载时触发初始化和清理。

Lyra 的 `LyraGame` 模块入口文件叫 `LyraGameModule.cpp`，全文只有 20 行，非常短。它做了三件事：

1. **定义自己的模块类** `FLyraGameModule`，继承引擎的 `FDefaultGameModuleImpl`（默认游戏模块实现）。
2. **重写两个生命周期回调**：`StartupModule()`（模块加载时触发）和 `ShutdownModule()`（模块卸载时触发）。现在都是空的，等后面阶段要往里加初始化逻辑。
3. **用 `IMPLEMENT_PRIMARY_GAME_MODULE` 宏注册**：告诉 UE「这是主游戏模块」，三个参数分别是「模块类名、模块名、模块名字符串」。

> 你现在的 `Tenkaichi.cpp` 直接用引擎默认的 `FDefaultGameModuleImpl`（没自己的模块类），不是 Lyra 的样子。所以这一步要改成定义自己的 `FTenkaichiGameModule` 类。

## 四、逐个讲这 20 行（先给概念，详细后置）

1. **`#include "Modules/ModuleManager.h"`**：引入模块管理器的头文件，`IMPLEMENT_PRIMARY_GAME_MODULE` 宏和 `FDefaultGameModuleImpl` 都在这里定义。
2. **`class FTenkaichiGameModule : public FDefaultGameModuleImpl`**：定义自己的模块类，继承默认游戏模块实现。
3. **`virtual void StartupModule() override {}`**：模块加载时调用，现在为空。
4. **`virtual void ShutdownModule() override {}`**：模块卸载时调用，现在为空。
5. **`IMPLEMENT_PRIMARY_GAME_MODULE(FTenkaichiGameModule, TenkaichiGame, "TenkaichiGame")`**：注册主游戏模块。三个参数：
   - `FTenkaichiGameModule`：模块类名
   - `TenkaichiGame`：模块名（要和 `.uproject` / `Build.cs` 里的名字一致）
   - `"TenkaichiGame"`：模块名字符串

> `StartupModule` / `ShutdownModule` 里为什么现在都是空的、后面会往里面加什么，等后面阶段（比如初始化日志、注册消息）遇到时再展开。本步先一比一写全（铁律 27）。
