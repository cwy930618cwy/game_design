# 3.3 TenkaichiGameplayCueManager —— .h 讲解

> **归属**：阶段三 3.3，接总 md。本文件只讲 `.h`。
> **源码依据**：`LyraGameplayCueManager.h`（一比一还原，`Lyra` → `Tenkaichi`）。

## 一、先讲为什么（解决什么问题）

回到总 md 的核心：我们要做一个"**用到才加载**"的 GameplayCue 管理器。`.h` 要解决的是——

**声明这个类"长什么样"**：它继承谁、重写父类哪几个钩子、自己有哪些方法、内部要维护哪些缓存数据。

`.h` 本身不干活（干活在 `.cpp`），它只是**画好蓝图**：告诉编译器"我要做这么个类，有这些能力和这些数据"。

## 二、头文件 include 与前置声明

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

// 引擎类头文件：提供 UGameplayCueManager 基类
#include "GameplayCueManager.h"

// 生成头文件（UHT 用，放最后）
#include "TenkaichiGameplayCueManager.generated.h"

class FString;
class UClass;
class UObject;
class UWorld;
struct FObjectKey;
```

**逐段讲**：

- `#include "GameplayCueManager.h"`：我们要继承的父类 `UGameplayCueManager` 就定义在这个引擎头文件里。
- `#include "TenkaichiGameplayCueManager.generated.h"`：UHT（Unreal 头文件工具）自动生成的，**必须放最后一行 include**，它负责把 `UCLASS()`/`GENERATED_BODY()` 等宏展开。
- 下面 5 个 `class`/`struct` 是**前置声明**（forward declaration）：只告诉编译器"有这么个类型"，不用完整 include。因为 `.h` 里这些类型**只出现在指针/引用/参数里**，不需要知道内部结构。

> 为什么前置声明而不是 include？减少编译依赖、加快编译。类型只用指针时，前置声明就够了。

## 三、类声明

```cpp
UCLASS()
class UTenkaichiGameplayCueManager : public UGameplayCueManager
{
	GENERATED_BODY()

public:
	UTenkaichiGameplayCueManager(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	static UTenkaichiGameplayCueManager* Get();

	//~UGameplayCueManager 接口（以下是重写父类的方法）
	virtual void OnCreated() override;
	virtual bool ShouldAsyncLoadRuntimeObjectLibraries() const override;
	virtual bool ShouldSyncLoadMissingGameplayCues() const override;
	virtual bool ShouldAsyncLoadMissingGameplayCues() const override;
	//~End of UGameplayCueManager 接口

	static void DumpGameplayCues(const TArray<FString>& Args);

	// 当使用「延迟加载」模式时，本方法负责加载那些「无论如何都要常驻」的 cue
	void LoadAlwaysLoadedCues();

	// 刷新「单个 GameplayCue 主资产」所对应的 bundle（打包时把 cue 归组）
	void RefreshGameplayCuePrimaryAsset();
```

**逐段讲**：

- `UCLASS()`：告诉 UHT 这是个反射类（可被引擎反射系统管理）。
- `class UTenkaichiGameplayCueManager : public UGameplayCueManager`：继承引擎的 `UGameplayCueManager`。注意类名前缀 `U`（UObject 派生）。
- `GENERATED_BODY()`：UHT 宏，展开出一堆反射基础设施（`StaticClass()` 等），**每个 UCLASS 必须要有**。
- **构造函数**：`const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get()`——这是 UE 标准构造函数签名，`FObjectInitializer` 是"对象初始化器"，构造 UObject 时传给它（通常直接转给父类）。
- **`Get()`**：静态方法，返回全局唯一实例。这是"单例访问入口"，别处要拿这个管理器就调 `UTenkaichiGameplayCueManager::Get()`。
- **4 个 `virtual ... override`**：重写父类 `UGameplayCueManager` 的钩子。`//~UGameplayCueManager 接口` 和 `//~End of UGameplayCueManager 接口` 是 Lyra 源码的**分组注释**（标识"下面是重写父类的接口"），按铁律 21 翻成中文。
  - `OnCreated()`：管理器被创建时。
  - `ShouldAsyncLoadRuntimeObjectLibraries()`：运行时对象库要不要异步加载。
  - `ShouldSyncLoadMissingGameplayCues()`：缺的 cue 要不要同步加载。
  - `ShouldAsyncLoadMissingGameplayCues()`：缺的 cue 要不要异步加载。
- **`DumpGameplayCues`**：静态方法，接受命令行参数（`TArray<FString>`），打印当前加载的所有 cue，给调试用。
- **`LoadAlwaysLoadedCues()`**：加载"无论如何都要常驻"的 cue。
- **`RefreshGameplayCuePrimaryAsset()`**：刷新 cue 的主资产（把当前所有 cue 打进一个 asset bundle）。

> 上面 `// When delay loading cues...`、`// Updates the bundles...` 是 Lyra 源码里的**英文注释**，按铁律 21 要翻成中文，代码本体（方法名/签名）一字不动。

## 四、私有方法（内部干活用的）

```cpp
private:
	void OnGameplayTagLoaded(const FGameplayTag& Tag);
	void HandlePostGarbageCollect();
	void ProcessLoadedTags();
	void ProcessTagToPreload(const FGameplayTag& Tag, UObject* OwningObject);
	void OnPreloadCueComplete(FSoftObjectPath Path, TWeakObjectPtr<UObject> OwningObject, bool bAlwaysLoadedCue);
	void RegisterPreloadedCue(UClass* LoadedGameplayCueClass, UObject* OwningObject);
	void HandlePostLoadMap(UWorld* NewWorld);
	void UpdateDelayLoadDelegateListeners();
	bool ShouldDelayLoadGameplayCues() const;
```

**这些是"内部流水线"的各个环节**（`private`，外部看不到，只给 `.cpp` 自己调）：

- `OnGameplayTagLoaded`：监听"某个 GameplayTag 被加载"的回调。
- `HandlePostGarbageCollect`：垃圾回收（GC）结束后的回调。
- `ProcessLoadedTags`：批量处理已加载的 tag。
- `ProcessTagToPreload`：处理"某个 tag 要预加载对应的 cue"。
- `OnPreloadCueComplete`：预加载一个 cue 完成的回调。
- `RegisterPreloadedCue`：把一个加载好的 cue 类登记进缓存。
- `HandlePostLoadMap`：地图加载完成后的回调（清理失效的 cue 引用）。
- `UpdateDelayLoadDelegateListeners`：根据加载模式，重新挂/卸这些委托监听。
- `ShouldDelayLoadGameplayCues`：判断当前是否应该"延迟加载 cue"（专用服务器不延迟）。

> 每个方法具体干嘛，到 `.cpp` 那一步再展开。现在 `.h` 只认个名。

## 五、私有成员（内部缓存数据）

```cpp
private:
	struct FLoadedGameplayTagToProcessData
	{
		FGameplayTag Tag;
		TWeakObjectPtr<UObject> WeakOwner;

		FLoadedGameplayTagToProcessData() {}
		FLoadedGameplayTagToProcessData(const FGameplayTag& InTag, const TWeakObjectPtr<UObject>& InWeakOwner) : Tag(InTag), WeakOwner(InWeakOwner) {}
	};

private:
	// 客户端上因「被内容引用」而预加载的 cue（能力表现类）
	UPROPERTY(transient)
	TSet<TObjectPtr<UClass>> PreloadedCues;
	TMap<FObjectKey, TSet<FObjectKey>> PreloadedCueReferencers;

	// 客户端上预加载后「永远保持加载」的 cue（被代码引用，或显式要求常驻）
	UPROPERTY(transient)
	TSet<TObjectPtr<UClass>> AlwaysLoadedCues;

	TArray<FLoadedGameplayTagToProcessData> LoadedGameplayTagsToProcess;
	FCriticalSection LoadedGameplayTagsToProcessCS;
	bool bProcessLoadedTagsAfterGC = false;
};
```

**逐段讲**：

- **`FLoadedGameplayTagToProcessData`**：一个内部小结构体，装"一个待处理的 tag + 它归属的对象"（`WeakOwner`）。有两个构造函数：空构造 + 带参构造（初始化列表 `: Tag(InTag), WeakOwner(InWeakOwner)`）。
  - `TWeakObjectPtr<UObject>`：**弱指针**，指向对象但不阻止它被 GC 回收（避免循环引用/悬空）。
- **`PreloadedCues`**：`TSet<TObjectPtr<UClass>>`——客户端因"内容引用"而预加载的 cue 类集合。`UPROPERTY(transient)` 表示不序列化（运行时临时数据）。
- **`PreloadedCueReferencers`**：`TMap<FObjectKey, TSet<FObjectKey>>`——记录"哪个 cue 被谁引用"，用于清理时判断"这个 cue 还有没有人用"。
- **`AlwaysLoadedCues`**：`TSet<TObjectPtr<UClass>>`——永远常驻的 cue 集合（代码引用或显式要求常驻）。
- **`LoadedGameplayTagsToProcess`**：`TArray<...>`——待处理 tag 的队列。
- **`LoadedGameplayTagsToProcessCS`**：`FCriticalSection`——**临界区锁**，多线程读写上面的队列时加锁保护。
- **`bProcessLoadedTagsAfterGC`**：布尔标记，GC 后需要补处理。

> 注释（`// 客户端上因「被内容引用」而预加载...`）已按铁律 21 翻成中文。
