## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "Engine/DataAsset.h"
#include "GameplayTagContainer.h"

#include "TenkaichiInputConfig.generated.h"

class UInputAction;
class UObject;
struct FFrame;

/** 一条「输入动作 ↔ 技能标签」的映射 */
USTRUCT(BlueprintType)
struct FTenkaichiInputAction
{
	GENERATED_BODY()

public:

	/** 输入动作（例如 IA_Fire），用只读指针存，避免误改 */
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)
	TObjectPtr<const UInputAction> InputAction = nullptr;

	/** 这个输入动作对应的技能标签（例如 InputTag.MouseButton.Left） */
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Meta = (Categories = "InputTag"))
	FGameplayTag InputTag;
};

/** 存放「输入配置」的数据资产：把输入动作和技能标签绑定起来 */
UCLASS(BlueprintType, Const)
class UTenkaichiInputConfig : public UDataAsset
{
	GENERATED_BODY()

public:

	UTenkaichiInputConfig(const FObjectInitializer& ObjectInitializer);

	// 根据标签，在「原生输入」里找出对应的输入动作（找不到可打印错误日志）
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Pawn")
	const UInputAction* FindNativeInputActionForTag(const FGameplayTag& InputTag, bool bLogNotFound = true) const;

	// 根据标签，在「技能输入」里找出对应的输入动作（找不到可打印错误日志）
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Pawn")
	const UInputAction* FindAbilityInputActionForTag(const FGameplayTag& InputTag, bool bLogNotFound = true) const;

public:
	// 拥有者使用的「原生输入」列表。这些输入动作绑定到游戏标签，需要手动绑定
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Meta = (TitleProperty = "InputAction"))
	TArray<FTenkaichiInputAction> NativeInputActions;

	// 拥有者使用的「技能输入」列表。这些输入动作绑定到游戏标签，会自动绑定到带匹配标签的技能上
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Meta = (TitleProperty = "InputAction"))
	TArray<FTenkaichiInputAction> AbilityInputActions;
};
```

## 四、逐段讲解

### 1. 头文件

```cpp
#include "Engine/DataAsset.h"
#include "GameplayTagContainer.h"
#include "TenkaichiInputConfig.generated.h"

class UInputAction;
class UObject;
struct FFrame;
```

- `Engine/DataAsset.h`：提供 `UDataAsset` 基类。
- `GameplayTagContainer.h`：提供 `FGameplayTag`。
- `generated.h`：UHT 生成，放最后。
- `class UInputAction;` —— **前置声明**。`.h` 里只用了 `UInputAction` 的**指针**，不需要完整定义，前置声明就够，能加快编译。真正的定义在 `.cpp` 里包含的 EnhancedInput 头文件里。
- `class UObject;` / `struct FFrame;` —— 同样只是给 UHT 用的前置声明。

### 2. 结构体 `FTenkaichiInputAction`

```cpp
USTRUCT(BlueprintType)
struct FTenkaichiInputAction
{
	GENERATED_BODY()

	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)
	TObjectPtr<const UInputAction> InputAction = nullptr;

	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Meta = (Categories = "InputTag"))
	FGameplayTag InputTag;
};
```

- `USTRUCT(BlueprintType)`：反射结构体，且**能在蓝图里作为类型使用**（`BlueprintType`）。
- 两个字段都是 `EditDefaultsOnly`（只在"默认值"里编辑，即这个资产本身）+ `BlueprintReadOnly`（蓝图只读）。

**字段逐个讲**：

| 字段 | 类型 | 含义 |
|------|------|------|
| `InputAction` | `TObjectPtr<const UInputAction>` | 输入动作。注意 `const` + 只读指针——这个资产只是**引用**别人定义好的输入动作，不拥有、不修改。`= nullptr` 是初始化默认值 |
| `InputTag` | `FGameplayTag` | 该输入动作对应的技能标签。`meta = (Categories = "InputTag")` 让编辑器下拉只显示 `InputTag` 分类下的标签 |

> `TObjectPtr` 是 UE5 推荐的"智能指针"包装，比裸指针 `UInputAction*` 更安全，自动处理对象失效。它和裸指针用起来几乎一样（支持 `->`、`==`）。

### 3. 数据资产类 `UTenkaichiInputConfig`

```cpp
UCLASS(BlueprintType, Const)
class UTenkaichiInputConfig : public UDataAsset
{
	GENERATED_BODY()
	...
};
```

- `UCLASS(BlueprintType, Const)`：能在蓝图里使用 + **`Const`**（声明"这是个不可变资产"——里面的数据在运行时不会改，UE 会据此做优化/校验）。
- 继承 `UDataAsset`：数据资产，编辑器里创建、配置。

### 4. 构造函数

```cpp
UTenkaichiInputConfig(const FObjectInitializer& ObjectInitializer);
```

- UE 反射类的构造函数标准写法：带 `FObjectInitializer` 参数。实现通常空着（`.cpp` 里就是 `{}`），因为没什么要初始化的，但需要声明以符合 UE 构造约定。

### 5. 两个查询函数（BlueprintCallable）

```cpp
UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Pawn")
const UInputAction* FindNativeInputActionForTag(const FGameplayTag& InputTag, bool bLogNotFound = true) const;

UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Pawn")
const UInputAction* FindAbilityInputActionForTag(const FGameplayTag& InputTag, bool bLogNotFound = true) const;
```

- `UFUNCTION(BlueprintCallable, ...)`：**可在蓝图里调用**，`Category = "Tenkaichi|Pawn"` 是蓝图面板里的分组名。
- 返回 `const UInputAction*`：找到的输入动作（指针）。
- 参数 `bool bLogNotFound = true`：**默认参数**——找不到时是否打印错误日志。调用方可省略（默认 true），或传 `false` 静默查找。
- 两个函数都是 `const`（纯查询，不改数据）。

### 6. 两个 public 数组

```cpp
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Meta = (TitleProperty = "InputAction"))
TArray<FTenkaichiInputAction> NativeInputActions;   // 原生输入

UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Meta = (TitleProperty = "InputAction"))
TArray<FTenkaichiInputAction> AbilityInputActions;  // 技能输入
```

- 两个数组，装的都是 `FTenkaichiInputAction`。
- `Meta = (TitleProperty = "InputAction")`：编辑器里每个数组元素，用它的 `InputAction` 字段作为显示标题（而不是默认"0 号元素"）。
- `EditDefaultsOnly`：只能在资产默认值里编辑；`BlueprintReadOnly`：蓝图只读。

## 五、几个要记住的点

1. **`UDataAsset`**：数据资产基类，编辑器里配置。
2. **`TObjectPtr<const UInputAction>`**：UE5 智能指针 + `const`，只引用不拥有。
3. **前置声明 `class UInputAction;`**：`.h` 只用到指针，不用 include 完整头文件，加快编译。
4. **`UCLASS(BlueprintType, Const)`**：蓝图可用 + 不可变资产。
5. **`UFUNCTION(BlueprintCallable, ...)`**：蓝图可调用的函数。
6. **`EditDefaultsOnly` + `BlueprintReadOnly`**：只在默认值编辑 + 蓝图只读。
