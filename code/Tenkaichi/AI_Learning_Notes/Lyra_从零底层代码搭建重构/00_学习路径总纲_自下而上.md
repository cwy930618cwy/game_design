## 【重要】死结怎么处理（本重构版的核心变化）

旧版路线在**阶段四（角色）↔ 阶段五（GAS 核心）**处撞上死结：`GameplayAbility` 依赖 `Character/PlayerController/HeroComponent`，而 `Character/PC/Hero` 又依赖 `GameplayAbility`——**互相依赖**，无法按"谁先被依赖谁先教"的线性顺序解开。

**重构版处理原则：死结没关系，直接绕过去。**

| 情况 | 处理方式 |
|------|---------|
| 类 `.h` 只 `#include` 引擎类 + 前置声明（class X;） | **独立可编译**，正常教，不挂起 |
| 类 `.cpp` 硬调用尚未就位的类 | 代码一比一完整写上，**用 `//` 或 `#if 0` 注释挂起**（铁律 33），登记注释备忘录（铁律 34） |
| 互相依赖的类 | **按层推进，不因死结停下**。先教 A（B 部分挂起），再教 B（A 部分挂起），最后统一解开 |

> 一句话：**每个类都按 Lyra 一比一完整教，能编译的直接编译，依赖没就位的注释挂起，到阶段统一解开。永远不因"依赖缠绕"跳过任何类。**

## 六、推进节奏（铁律 20/29）

1. **每层先建总 md**（概念+全景），停，等用户"懂了/下一步"。
2. **每个类按 `.h` → `.cpp` 分开教、分开建 md**（命名带 `_h`/`_cpp` 后缀）。
3. **每讲完一小步，同一轮立刻建对应小 md**（铁律 07）。
4. **每到一个新阶段开头，先翻注释备忘录**，把依赖已就位的条目提醒用户解开（铁律 34）。
