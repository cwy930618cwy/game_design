# Q13 — 第 02 课第 4 步：self-contained 挂法下，属性集怎么"自动进"ASC 的？

> **对应源码**（都实际打开核对过）：
> - `UAbilitySystemComponent::InitializeComponent()` → `Engine/Plugins/Runtime/GameplayAbilities/Source/GameplayAbilities/Private/AbilitySystemComponent_Abilities.cpp` 第 58-88 行
> - `AddAttributeSetSubobject` 注释 → `AbilitySystemComponent.h` 第 147-156 行
> - Lyra 第 19 行注释 → `Source/LyraGame/Character/LyraCharacterWithAbilities.cpp` 第 19-20 行
>
> **一句话**：self-contained 挂法下，属性集在构造函数里 `CreateDefaultSubobject` 造在角色身上后，**不需要手动授予**——ASC 的 `InitializeComponent` 会用 `GetObjectsWithOuter(Owner)` 自动扫描 Owner 身上所有 AttributeSet 并加入 `SpawnedAttributes`。这就是 Lyra 第 19 行注释"detected by InitializeComponent"的真实机制。

## 一、问题是什么

第 4 步（`02_4_3`）我们在角色构造函数里把 HealthSet 造在角色 `this` 上：

```cpp
HealthSet = CreateDefaultSubobject<UTenkaichiHealthSet>(TEXT("HealthSet"));
```

疑问：**这个 HealthSet 造在"角色"身上，ASC 又没主动去拿它，它到底怎么"进"ASC 的？为什么 `GetHealth()` 能读出值？**

> 4-3 的注释写了"会被 ASC 的 InitializeComponent 自动检测"——当时是照抄 Lyra 第 19 行注释，没核实到具体源码。本文件就是补上这个源码依据。

---

## 二、真实机制：ASC 的 `InitializeComponent` 自动扫描 Owner

```58:88:Engine/Plugins/Runtime/GameplayAbilities/Source/GameplayAbilities/Private/AbilitySystemComponent_Abilities.cpp
void UAbilitySystemComponent::InitializeComponent()
{
	Super::InitializeComponent();

	// Look for DSO AttributeSets (note we are currently requiring all attribute sets to be subobjects of the same owner. ...
	AActor *Owner = GetOwner();
	InitAbilityActorInfo(Owner, Owner);	// Default init to our outer owner

	// cleanup any bad data that may have gotten into SpawnedAttributes
	for (int32 Idx = SpawnedAttributes.Num()-1; Idx >= 0; --Idx)
	{
		if (SpawnedAttributes[Idx] == nullptr)
		{
			SpawnedAttributes.RemoveAt(Idx);
		}
	}

	TArray<UObject*> ChildObjects;
	GetObjectsWithOuter(Owner, ChildObjects, false, RF_NoFlags, EInternalObjectFlags::Garbage);

	for (UObject* Obj : ChildObjects)
	{
		UAttributeSet* Set = Cast<UAttributeSet>(Obj);
		if (Set)  
		{
			SpawnedAttributes.AddUnique(Set);
		}
	}

	SetSpawnedAttributesListDirty();
}
```

**逐句拆解**：
1. `AActor *Owner = GetOwner();`——拿到 ASC 的宿主（就是我们那个角色）。
2. `GetObjectsWithOuter(Owner, ChildObjects, ...)`——**扫描"以 Owner 为外部对象的所有 UObject"**。因为 HealthSet 是 `CreateDefaultSubobject` 造在角色 this 上的，它的 Outer 就是这个角色，所以会被扫到。
3. `Cast<UAttributeSet>(Obj)`——扫到的对象里，凡是 `UAttributeSet` 派生类（我们的 HealthSet 正是），就挑出来。
4. `SpawnedAttributes.AddUnique(Set)`——加入 ASC 的 `SpawnedAttributes` 列表。**至此 HealthSet 正式"归"ASC 管**，`GetHealth()` 才能通过 ASC 读到值。

> 这就是"自动检测"的真相：**不是 ASC 主动去角色身上找，而是 HealthSet 造在角色上（Outer=角色），ASC 初始化时按 Outer 反向扫描，把它收编。**

## 三、为什么必须是 `InitializeComponent` 这个时机

配合 Q11（`PostInitializeComponents` 干嘛）：

```
构造函数（HealthSet 造在角色上，Outer=角色）
  → 组件 RegisterComponent
  → ASC 的 InitializeComponent（★ 这里扫描 Owner，把 HealthSet 收编进 SpawnedAttributes）
  → 角色的 PostInitializeComponents（我们调 InitAbilityActorInfo）
  → BeginPlay
```

- HealthSet 在**构造函数**造好，但那时 ASC 还没初始化，还没收编它。
- ASC 的 **`InitializeComponent`** 才是"收编"发生的时刻（扫描 Owner 的 subobjects）。
- 所以 `InitAbilityActorInfo` 放在角色的 `PostInitializeComponents`（在组件 `InitializeComponent` 之后）才安全——那时 ASC 已经把 HealthSet 收编完了。

> `AddAttributeSetSubobject` 的注释（`AbilitySystemComponent.h` 第 149 行）也印证了这点："All subobjects of this component are automatically added during initialization."

## 四、那 Lyra 的"手动授予"（`GiveToAbilitySystem`）是怎么回事？

Lyra 里确实有一套"手动授予属性集/技能"的代码：`ULyraAbilitySet::GiveToAbilitySystem`（`LyraAbilitySet.cpp` 第 94-95 行 `AddAttributeSetSubobject`）。但它是**另一条路**用的：

- **self-contained 挂法（我们这条）**：属性集造在角色身上，ASC 自动扫描收编——**不需要手动授予**。`LyraCharacterWithAbilities` 就是这种。
- **PlayerState / GameFeature 挂法（玩家主角那条）**：ASC 挂在 PlayerState 上，属性集不是角色构造时造的，而是运行时由 `GameFeatureAction_AddAbilities` 动态授予（`GameFeatureAction_AddAbilities.cpp` 第 221 行调 `GiveToAbilitySystem`）——**这条才需要手动授予**。

> 所以"授予属性集"不是第 02 课 self-contained 骨架要做的事。我们只要在构造函数里造好、让 ASC 自动收编即可。手动授予是后面走 PlayerState 那条路（第 05 课组件化、第 12 课 GameFeature）才会涉及。

---

## 五、我们这版 vs Lyra

**机制完全一致**：
- Lyra `LyraCharacterWithAbilities` 构造函数造 `HealthSet`/`CombatSet` 在角色上 → ASC `InitializeComponent` 自动收编。
- 我们 `TenkaichiCharacterWithAbilities` 构造函数造 `HealthSet` 在角色上 → 同一个 ASC `InitializeComponent` 自动收编。

**唯一差异**：Lyra 造了 HealthSet + CombatSet 两个，我们只造 HealthSet（减法：CombatSet 战斗阶段才用，将来补）。机制本身一比一还原。

---

## 六、一句话结论

**self-contained 挂法下，属性集在构造函数造在角色身上（Outer=角色），ASC 的 `InitializeComponent` 用 `GetObjectsWithOuter(Owner)` 反向扫描、把它是 `UAttributeSet` 的 subobject 自动收编进 `SpawnedAttributes`——所以不需要手动授予。Lyra 的"手动授予"（`GiveToAbilitySystem`）是 PlayerState/GameFeature 那条路才用的，不是我们这条。**
