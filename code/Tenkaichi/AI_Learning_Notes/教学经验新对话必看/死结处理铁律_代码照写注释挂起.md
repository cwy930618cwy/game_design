# 死结处理铁律 —— 遇到死结/后期内容，直接注释挂起，不许纠结

> **定位**：本文件是"死结/后期内容"处理方式的**最高优先级总开关**。
> 33 号是详细版，本文件是**一句话钉死版**——每次遇到死结就照此执行，不许再反复纠结"依赖会不会缠绕、该不该提前教"。
> 用户原话（2026-10-12，重复多次）：**"死结没关系""遇到后期内容注释就行"**。

---

## 一、一句话铁律

> **遇到死结（互相依赖 / 依赖未就位）：代码照样一比一完整写上，一个字不少；然后把依赖没就位的部分用 `//` 或 `#if 0` 注释挂起，登记到注释备忘录，到依赖就位那一步再提醒解开。**
>
> **绝不允许：因为死结/依赖缠绕就停下来反复纠结，也不允许跳过、省略、简化、说"以后补"。**

---

## 二、执行步骤（遇到死结/后期内容时，一口气做完）

1. **代码一比一完整写上**（铁律 23/25），一个字不少——死结不删代码。
2. **用 `//` 或 `#if 0 ... #endif` 注释挂起**依赖未就位的部分，并加醒目提示：
   ```markdown
   > ⚠️ 【注释挂起】以下代码依赖阶段 X（`具体类名`），当前依赖未就位，请先注释掉。
   > 代码已一比一还原 Lyra，等阶段 X 就位后放开注释即可。（已登记注释备忘录）
   ```
3. **登记到 `教学经验新对话必看\注释备忘录.md`**（内容/为什么挂起/依赖哪阶段/解开时机）。
4. **继续往下推进，不停下、不纠结**。到依赖就位那一步，翻注释备忘录提醒解开。

---

## 三、什么叫"死结"（本文件管什么）

| 场景 | 是不是死结 | 怎么处理 |
|------|-----------|---------|
| 两个类互相依赖（A→B 且 B→A） | ✅ 死结 | 直接注释挂起，按层推进，不因死结停下 |
| 依赖还没教到的后期内容（GAS 核心等） | ✅ 后期内容 | 代码写全，注释挂起 |
| 类 `.h` 只前置声明 + 引擎 include（独立可编译） | ❌ 不是死结 | 正常教，不挂起 |
| 依赖已就位 | ❌ 不是死结 | 正常教，正常解开注释 |

> 关键：**只有 `.cpp` 的运行时硬调用才决定编译/链接**。`.h` 里 `class X;` 前置声明不阻塞编译（铁律 30）。所以很多"看着像死结"的，`.h` 其实能独立编译，只有 `.cpp` 需要挂起。

## 四、禁止清单（遇到死结时绝对不许做）

- ❌ 不因死结**停下来反复纠结**（用户明确反感："你有病啊""尼玛的不要管死结了"）
- ❌ 不跳过 / 不省略 / 不简化 / 不说"以后补"（铁律 31）
- ❌ 不把死结当成"教学顺序卡点"无限期挂起
- ❌ 不自己发明"绕开依赖的替代写法"（铁律 16 禁止加法）
