# 33 — 遇到后期内容：代码一比一完整写上，但提示可"注释挂起"

> **定位**：本文件是新增铁律 33。解决"教学推进到 GAS 断点"时的处理方式。

## 一、这条铁律怎么来的（真实场景，2026-10-12）

阶段四教到断点类（`TeamSubsystem`、`PawnExtensionComponent`、`HeroComponent`、`Character`、`PlayerController`、`PlayerState`、`TeamDisplayAsset`）时，
这些类直接/间接依赖**阶段五的 GAS 核心**（`AbilitySystemComponent`、`GameplayAbility`、`AbilitySet`），依赖没就位，编译不过（铁律 31）。

用户提出方案：**"回到阶段三，把 GAS 相关代码先注释挂起"**，并明确：

> **"遇到后期内容，也要一比一还原，但是提示我注释了就行"**

即：**代码照 Lyra 一比一完整写上，一个字不少（铁律 23/25）；但因为依赖未就位，提示用户把这段先注释掉，等依赖就位再放开。**

## 二、核心规则（做什么 / 不做什么）

| 场景 | ✅ 做 | ❌ 不做 |
|------|------|--------|
| 遇到依赖未就位的后期内容（如 GAS） | 代码**一比一完整写上**（铁律 23/25） | 不省略、不简化、不"以后补" |
| 写完代码后 | **明确提示"这段可以注释挂起"**，说明为什么（依赖未就位） | 不假装能编译、不跳过 |
| 被注释挂起的代码 | 保留完整还原内容，只是用 `//` 或 `#if 0` 包起来 | 不删掉、不改写 |
| 依赖就位后 | 提醒用户**放开注释**，代码就是 Lyra 原样 | 不留注释残留 |

## 三、为什么这样设计（对照铁律）

- **铁律 23/25**：代码必须一比一完整还原，一个字不少；"逻辑后讲"可以，但"代码后补"= 省略 = 违规。
- **铁律 31**：依赖没就位就不能硬编译——要么补依赖，要么停下。
- **33 号统一收口**：**"代码写全但注释挂起"** = 既满足"一比一完整还原"，又满足"依赖没就位不硬编译"。两头兼顾。

> 一句话：**代码照抄 Lyra 全写上，但告诉用户"这段先注释掉"，等 GAS 就位再放开。**

## 四、挂起的具体写法（给用户的提示）

在 md 里，对被注释挂起的代码段，加上醒目提示，例如：

```markdown
> ⚠️ 【注释挂起】以下代码依赖阶段五 GAS（`AbilitySystemComponent`/`GameplayAbility`），
> 当前依赖未就位，请先注释掉（用 `//` 或 `#if 0 ... #endif` 包裹）。
> 代码本身已一比一还原 Lyra，等 GAS 阶段就位后放开注释即可。
```

## 五、适用范围

- 阶段四的 GAS 断点类：`TeamSubsystem`、`PawnExtensionComponent`、`HeroComponent`、`Character`、`PlayerController`、`PlayerState`、`TeamDisplayAsset`。
- 任何"依赖未就位但代码要一比一还原"的场景。
