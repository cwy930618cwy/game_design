# 32 — 教学铁律：每次教方法，方法上面都要加一行中文注释（其余与 Lyra 一模一样）

> **定位**：本文件是 [21_教学代码注释一律写成中文](./21_教学代码注释一律写成中文.md) 和 [28_还原大段真实源码时注释也要中文化](./28_还原大段真实源码时注释也要中文化.md) 的**进一步强化**。新对话开始教学前，除 00~31 外，**必须读本文件**。
>
> **一句话**：**以后每次教方法（函数），方法上面都要加一行 `// 中文注释`，讲清这个方法干嘛的；注释之外的部分（方法签名、参数、返回值、实现逻辑）保持和 Lyra 一模一样，一字不改。**

---

## 一、这条铁律怎么来的（真实需求，2026-10-10）

阶段三 3.3 `GameplayCueManager` 教学收尾时，用户发现 `.h` 里 9 个 private 方法（内部流水线环节）**没有注释**，要求：

> "能不能以后方法前面都加个注释，比如 `// 监听『某个 GameplayTag 被加载』的回调`。其他的一比一还原 Lyra 就行，注释不影响。"

随后用户又要求 `.cpp` 里同样这 9 个方法的**实现**前面也加上对应的中文注释，并明确：

> "以后每次教方法，上面都要加上注释 `// xxxx`，其他的保留跟 Lyra 一模一样。"

**根因复盘**：
- Lyra 源码里这 9 个 private 方法**原本就没有注释**（源码原样），所以之前一比一还原时，方法上面是空的。
- 但用户是中文学习者，一堆没有注释的方法等于"只有名字，不知道干嘛"，增加理解负担。
- 注释是给人看的说明文字，**加注释不破坏「一比一还原」**——还原的是代码逻辑，注释是额外给人看的说明。

---

## 二、核心规则

**教每个方法（函数）时，方法签名上面加一行 `// 中文注释`，讲清这个方法干嘛的；其余部分（签名、参数、返回值、函数体）一比一还原 Lyra，一字不改。**

| 部分 | 处理 | 说明 |
|------|------|------|
| **方法上面的 `//` 注释** | **必须加**（中文） | 讲清方法干嘛的，说人话 |
| **方法签名**（返回类型、函数名、参数列表） | 原样不动 | 一比一对应 Lyra（前缀替换除外） |
| **函数体**（实现逻辑） | 原样不动 | 一比一还原 Lyra |
| **方法内部已有的注释** | 中文化（见 21/28） | 翻译成人话 |

> 判断标准：**用户看到任何一个方法，一眼就知道它干嘛的，不用去猜函数名。**

---

## 三、注释写什么、怎么写

1. **写在方法签名正上方一行**，格式 `// xxxx`（行注释）。
2. **说人话**：讲清"这个方法干嘛的"，不是机械翻译函数名。
3. **一行就够**：简单方法一句话；复杂方法也先一句话概括，细节留给方法体内的注释或讲解。
4. **`.h` 和 `.cpp` 都要加**：
   - `.h` 里：方法**声明**上面加注释（讲"干嘛"）。
   - `.cpp` 里：方法**实现**上面加同样的注释（保持一致）。
5. **注释内容 `.h` 和 `.cpp` 对应一致**：同一个方法，两处注释意思相同。

### 示例

```cpp
// 监听「某个 GameplayTag 被加载」的回调
void OnGameplayTagLoaded(const FGameplayTag& Tag);
```

```cpp
// 监听「某个 GameplayTag 被加载」的回调
void UTenkaichiGameplayCueManager::OnGameplayTagLoaded(const FGameplayTag& Tag)
{
    ...
}
```

## 五、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 教一个方法 | 方法上面加一行 `// 中文注释` | 方法上面空着、只有函数名 |
| 加注释 | 说人话，讲清"干嘛" | 机械翻译函数名 / 写英文 |
| 方法本体（签名+函数体） | 一比一还原 Lyra | 因加注释而改动代码逻辑 |
| `.h` 和 `.cpp` | 两处都加、注释一致 | 只加一边 / 两处注释不一致 |

## 六、执行要求（每次教方法时自检）

1. **这个方法上面有中文注释吗**？没有就加一行。
2. **注释说人话了吗**？一眼能懂"这个方法干嘛的"。
3. **代码本体动了吗**？签名、参数、函数体必须一比一还原 Lyra（前缀替换除外）。
4. **`.h` 和 `.cpp` 都加了吗**？两处注释意思一致。

## 七、一句话结论

**以后每次教方法，方法上面都要加一行 `// 中文注释`（说人话，讲清干嘛）；`.h` 声明和 `.cpp` 实现都要加、注释一致；注释之外的部分（签名、参数、函数体）保持和 Lyra 一模一样，一字不改。**
