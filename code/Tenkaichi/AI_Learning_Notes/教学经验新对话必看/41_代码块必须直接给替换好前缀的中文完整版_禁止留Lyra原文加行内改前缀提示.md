# 41 — 教学铁律：贴给用户的「代码块」必须直接给「已替换好前缀 + 中文注释」的完整版本，禁止在代码块里留 Lyra 原文 + 行内"改前缀"提示注释

> **定位**：本文件是 [24](./24_前缀替换规则_lyra对应Tenkaichi其余一模一样.md)、[39](./39_代码块注释要直接写中文_别只写说明不实际改.md)、[40](./40_教同类内容先套已被确认的正确范本_禁自创三段式.md) 的**执行层补强**，教训来自 2026-10-21 P02.2 `UTenkaichiActorUtilities`。新对话开始教学前，除 00~40 外，**必须读本文件**。
>
> **一句话**：贴给用户照着写的**代码块必须是最终可编译版本**——前缀已替换成 `Tenkaichi`、注释已中文化。**禁止**在代码块里给 Lyra 原文 + 行内 `// ← 改成 TenkaichiXXX` 这种提示注释让用户自己去改。用户照抄时会把提示注释一起抄进去、却忘了替换，工程里残留 Lyra 前缀，编译不过。

## 一、这条铁律怎么来的（真实教训，2026-10-21）

教 P02.2 `UTenkaichiActorUtilities` 的 `.h` 时，AI 在"完整代码"和"逐段拆解"的代码块里写了 **Lyra 原文**，再在行尾加提示注释让用户自己替换前缀：

```cpp
// 生成头文件（UHT 用，放最后）
#include "LyraActorUtilities.generated.h"  // ← 改成 TenkaichiActorUtilities.generated.h

class UObject;
struct FFrame;
...
UCLASS()
class ULyraActorUtilities : public UBlueprintFunctionLibrary  // ← 改 UTenkaichiActorUtilities
{
```

用户照着抄进 `Source\TenkaichiGame\System\TenkaichiActorUtilities.h`，**结果**：
1. 两处前缀没替换——工程里残留 `ULyraActorUtilities` / `LyraActorUtilities.generated.h`；
2. 行内 `// ← 改成...` 提示注释被**原样抄进了工程代码**，污染交付物；
3. 因为 `.h` 文件名是 `TenkaichiActorUtilities.h` 而类名却是 `ULyraActorUtilities`、generated.h 也是 `LyraActorUtilities.generated.h`，**编译直接不过**。

用户当场怒斥：**"谁让你这么教的？？？"**

**根因复盘**：
1. **违反 24 号前缀替换的执行要求**：24 号说"机械替换 `Lyra`→`Tenkaichi`"，但 AI 把"替换"做成了"告诉用户自己替换"——**该给的没给，把'替换'写成了'提示'**。
2. **违反 40 号范本**：正确范本（P01.1 `_h.md`）第一节的代码块直接就是 `FTenkaichiVerbMessage` / `TENKAICHIGAME_API` / `TenkaichiVerbMessage.generated.h`——**已替换好**。AI 这次却退化回"贴 Lyra 原文 + 行内提示"，等于把 40 号"直接给替换版"做成了"给原文让用户改"。
3. **违反 39 号的判断标准**：39 号说"扫代码块，不扫表格"。这次更要扫**代码块里的行内提示注释**——`// ← 改...` 就是"没实际替换、只写了说明"的典型，和 39 号"代码块留英文、表格说中文化"是同一个病根：**该改的没改，把'改'写成了'说'**。
4. **行内提示注释是坑**：即使前缀替换了，行内 `// ← 改成...` 这种教学提示若留在代码块里，用户照抄时会连提示一起抄进工程。**代码块必须是干净的最终版本，零教学噪声**。

## 二、核心规则（硬动作）

**贴给用户照着写的每个代码块，必须是「已替换好前缀 + 已中文化注释」的干净最终版本：**

- **前缀已替换**：`ULyraActorUtilities`→`UTenkaichiActorUtilities`、`LyraActorUtilities.generated.h`→`TenkaichiActorUtilities.generated.h`、`Category="Lyra"`→`Category="Tenkaichi"`……**代码块里不允许出现任何残留的 `Lyra` 前缀**（除非这个标识符本身在 Lyra 里就无前缀，如 `EBlueprintExposedNetMode`）。
- **注释已中文**：所有 `//` / `/* */` 直接写中文（配合 39 号）。
- **零教学噪声**：代码块里**不允许出现** `// ← 改成XXX` / `// 注意改成` / `// TODO 换成` 这类"让用户自己改"的提示注释——**代码块是交付物，用户照抄必须直接得到正确代码**。
- **前缀替换说明放在代码块外**：需要告诉用户"这处前缀换过了"，放在 md 正文/表格/引用块里（如 `> 与 Lyra 原文件只差前缀：...`），**绝不放进代码块**。

## 三、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 代码块里写类名 | 直接写 `class UTenkaichiActorUtilities` | 写 `class ULyraActorUtilities  // ← 改 UTenkaichiActorUtilities` |
| 代码块里写 generated.h | 直接写 `#include "TenkaichiActorUtilities.generated.h"` | 写 `#include "LyraActorUtilities.generated.h"  // ← 改成 Tenkaichi...` |
| 代码块里写 Category | 直接写 `Category="Tenkaichi"` | 写 `Category="Lyra"` 再在别处说"应改 Tenkaichi" |
| 想提示用户"前缀换过了" | 在 md 正文/表格/引用块写"只差前缀"说明 | 在代码块行尾加 `// ← 改...` |
| 交付代码块 | 干净、可直接编译、零教学注释 | 带行内提示/残留 Lyra 前缀/英文注释 |

## 四、为什么必须这样（讲清原因）

- **代码块 = 交付物**：用户是照着代码块一个字符一个字符敲进工程的。代码块里是 `ULyraActorUtilities`，敲进工程就是 `ULyraActorUtilities`；代码块里带了 `// ← 改...`，敲进工程就污染了工程代码。**代码块是什么，工程就是什么**。
- **前缀替换是 AI 的职责，不是用户的任务**：24 号明确"把 `Lyra` 换成 `Tenkaichi`"是唯一机械规则，应该由 AI 在给代码时就换好。让用户自己替换，就是把"该 AI 做的机械工作"甩给用户，而且用户一忘就编译不过。
- **行内提示注释无法靠"抄完删掉"**：用户专注抄代码时，很容易把行内注释也当成代码抄进去，且没有任何机制保证他会记得删。**从源头消灭：代码块里根本不放这种注释**。
- **39 号堵"表格说中文"，本号堵"行内说改前缀"**：都是同一个病——"该在代码块里落实的，写成了代码块外的说明"。39 号管注释中文化，本号管前缀替换 + 零教学噪声，执行层面同源。

## 五、执行要求（贴任何代码块前自检）

1. **扫代码块**：每个代码块里有没有残留 `Lyra` 前缀？（`EBlueprintExposedNetMode` 这类无前缀标识符除外）
2. **扫行内提示**：有没有 `// ← 改` / `// 改成` / `// TODO` / `// 注意换成` 这种"让用户自己改"的注释？有 → 直接改成正确内容，删掉提示。
3. **扫注释语言**：所有 `//` / `/* */` 是否已中文？（配合 39 号）
4. **假想用户照抄**：用户把整个代码块一字不差抄进工程，能不能直接编译？不能 → 代码块不合格，重写。
5. **前缀说明外移**：如果确实要告诉用户"这处换过前缀"，写进代码块**外**的正文/表格/引用块，不污染代码块。

## 七、一句话结论

**贴给用户照着写的每个代码块，必须是「已替换好前缀（`Tenkaichi`）+ 已中文化注释 + 零行内提示注释」的干净最终版本——用户照抄一字不差就能直接编译。禁止在代码块里给 Lyra 原文 + `// ← 改成XXX` 行内提示让用户自己去改，也禁止 `Category="Lyra"` 这类残留前缀。前缀替换说明只能写在代码块外的正文/表格里，绝不进代码块。检查时就扫代码块：有残留 `Lyra` 前缀、有 `// ← 改` 提示、有英文注释，任何一个存在就是违规，当场改成干净的可编译版本。**
