# 29 — 教学铁律：新内容必须「先总 md → 教 h → 教 cpp」，别凭进度表乱猜下一步

> **定位**：本文件是对 [20](./20_每次新内容先建总md等确认再逐个小步建md禁止一次全建.md) 和 [08](./08_教学md开头要先讲为什么再给代码.md) 的**落地强化版**，教训来自 2026-10-08 阶段一第 1 步收尾时。
>
> **一句话**：进入一个新的「教学内容」（一个文件/一类文件）时，节奏永远是 **先建一个总 md（讲为什么+全景）→ 停 → 用户说下一步 → 教 `.h`（建 `.h` md）→ 停 → 用户说下一步 → 教 `.cpp`（建 `.cpp` md）**。判断「下一步教什么」不能凭 MEMORY 里的进度表拍脑袋，要回到**总 md 的全景清单**逐项核对。

---

## 一、这条铁律怎么来的（真实教训，2026-10-08）

阶段一第 1 步（建模块 + Build.cs）快收尾时，用户问「下一步教啥」。AI 做了两件错事：

1. **凭进度表猜下一步**：AI 看 MEMORY.md 里写「教学目录已建到 1.6」，就直接推「下一步是 1.7 日志通道」，但**没有回到总 md 的全景清单**确认「日志通道」这个内容到底该按什么结构教。
2. **忘了铁律 20 的节奏**：AI 上来就准备「直接拆小 md 教日志通道」，把「日志通道」当成「已经在教的 Build.cs/Target 那种零散文件」，而不是当成一个**全新的教学内容**——应该「先建总 md → 教 h → 教 cpp」三步走。

用户当场纠正，甩出 P02 三份 md（P02-1 总 / P02-2 教 h / P02-4 教 cpp），并说「先建一个总的 然后教 h 然后教 cpp」「经验没写进去？新建一个 md 再巩固下」。

**根因复盘**：
- AI 把「自下而上还原」里的每个文件，都当成了「可以一口气拆一堆小 md」的对象，忘了**铁律 20 的串行节奏**对「一个独立教学内容（一个文件）」同样适用。
- AI 判断「下一步」靠 MEMORY 进度表，而不是回总 md 的**全景清单**逐项核对，导致漏掉了「日志通道 / GameplayTags 还没教、且要按三步走」这个事实。

### 第二次翻车（同一天，2026-10-08，教 h 时）

用户说「下一步」后，AI 把 1.7-h 的讲义**只打在聊天里**，**没有落成 md 文件**。用户连发两轮怒斥：「？？？？你不新建md吗？？？？？」「更新经验 都要新建md 啊」。

**根因复盘**：
- AI 把「教 h」理解成「在聊天里讲 h」，却忘了**铁律 07（每教一小步就立刻建 md，不等提醒）** 和铁律 20 的「教 h = 建 `.h` md」——「教」和「建 md」是**同一动作**，不是「先聊完再决定要不要落盘」。
- 换句话说：**每一个教学步骤（总 / h / cpp），它的「讲义」都必须同时是一个 md 文件**。讲义只能出现在 md 里，不能只存在于聊天记录中。

## 二、核心规则（硬动作）

### 规则 1：判断「下一步教什么」= 回总 md 全景清单，不靠进度表猜

总 md（如 `01_建TenkaichiGame模块与Buildcs_总md.md`）里有一个「这一步要动的文件/内容全景清单」。判断下一步，就是**对着这个清单，看哪一项还没教**，而不是看 MEMORY 里「建到 1.x」的数字。

- 阶段一第 1 步全景清单里，除了 Build.cs / 模块入口 / 10 个 Target / .uproject，还明确列了 **`LyraLogChannels.h/.cpp`（日志通道）** 和 **`LyraGameplayTags.h/.cpp`（GameplayTags）** 这两组「模块地基」文件。
- 这两组**不是** Build.cs 那种「零散依赖清单」，而是**独立的教学内容**，必须各按「总 → h → cpp」三步走。

### 规则 2：每一个「独立教学内容」都要「先总 md → 教 h → 教 cpp」

- 内容 = 一个文件（如 `TenkaichiLogChannels.h/.cpp`）或一类文件。
- 节奏串行：总 md（为什么 + 全景，不贴代码）→ 停 → 教 `.h` → 停 → 教 `.cpp`。
- 禁止「一次把总 + h + cpp 全建完」，也禁止「跳过总 md 直接教 h」。

### 规则 4：**教 = 建 md，讲义必须落成文件（不能只打在聊天里）**

- 每教一步（总 / h / cpp），**同一个动作里**就要建好对应的 md 文件（铁律 07）。
- 「讲义只发在聊天、没落成 md」= 违规，等于没教。讲义只能存在于 md 里，聊天只是通知用户「md 建好了」。
- 命名对应：总 md 用 `x.x_主题_总md`，`.h` 用 `x.x-h_..._h.md`，`.cpp` 用 `x.x-cpp_..._cpp.md`（铁律 15/20）。

### 规则 3：日志通道这类「新内容」的下一步判断

- 日志通道 `LyraLogChannels.h/.cpp` = 一个独立教学内容 → 先建「总 md」讲「日志分类是什么、为什么放模块地基、4 个日志通道全景」，然后停，等确认再教 h、再教 cpp。

### 规则 5：用户说「下一步」时，先检查用户是否真的写完了当前步骤

- 用户说「下一步」**不等于**「我已写完当前步骤的代码」。可能是「我要看下一课」、也可能只是「继续讲」。
- 收到「下一步」时，**先读用户工程的真实代码文件**（如 `Source/TenkaichiGame/TenkaichiLogChannels.cpp`），确认当前步骤的代码**真的已经写完、内容对得上**，再进下一步。
- 如果发现代码还没写 / 没写全 / 和讲义对不上，要**停下来提醒用户先写完**，而不是自顾自往下教。
- 这一条和铁律 01「只教不写代码」一致：代码是用户写的，AI 必须靠「读代码」确认用户落地了，不能靠「用户说了下一步」就假设落地了。

> 今天（2026-10-08）第三次翻车：用户说「下一步」，AI 默认用户已写完 `.cpp`，直接教了 1.7-cpp，没有先读用户工程里的 `TenkaichiLogChannels.cpp` 确认是否真的写完了。

## 五、执行要求（每次教学自检）

1. **问「下一步教啥」时**：先打开对应总 md，读它的「全景清单」，逐项核对，而不是看进度数字。
2. **遇到新内容**：先建**一个**总 md（为什么 + 全景），停。
3. **等反馈**：总 md 确认后教 `.h`，`.h` 确认后教 `.cpp`，串行推进。
4. **教 = 建 md**：每教一步（总/h/cpp），同一个动作里就把对应 md 文件建好，讲义绝不能只发聊天不落盘。
5. **收到「下一步」先读代码确认**：先读用户工程里的真实代码文件，确认当前步骤真的写完了、内容对得上，再进下一步；没写完就停下来提醒。
6. **自检**：这一轮有没有「没确认写完就推进」？有没有「没得到确认就提前建了下一个 md」？有没有「跳过了总 md 直接教 h」？有没有「教了却没建 md」？有就是违规。

## 六、一句话结论

**判断下一步 = 回总 md 全景清单逐项核对（不是看进度数字）；每遇到一个独立教学内容（日志通道、GameplayTags 等）都要「先总 md → 教 h → 教 cpp」三步串行走，一步一反馈；且「教 = 建 md」——每一步的讲义必须同时落成 md 文件，绝不能只发在聊天里；收到「下一步」先读用户工程代码确认当前步骤真写完了再推进。禁止跳过总 md、禁止一次全建完、禁止只聊不建 md、禁止不检查就当用户写完了。**
