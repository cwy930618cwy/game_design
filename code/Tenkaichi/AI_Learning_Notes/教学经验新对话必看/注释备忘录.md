# 注释备忘录 —— 记录"注释挂起"的后期内容

> **定位**：本文件是**注释挂起台账**（铁律 33 的落地工具）。
> 每次教学遇到"依赖未就位但代码要一比一还原"的后期内容，就：
> 1. **先跟用户说"这段先注释掉"**；
> 2. **把条目登记到本备忘录**（含：内容、为什么挂起、依赖哪个阶段、解开时机）；
> 3. 到对应阶段（依赖就位）时，**提醒用户解开注释**，然后从本表勾掉。

---

## 一、为什么要有这个备忘录

铁律 33 规定：依赖未就位的代码**也要一比一完整写上**，但用 `//` 或 `#if 0 ... #endif` 挂起。
问题来了：挂起的内容散落在各个阶段，时间一长会**忘记哪段挂起了、该在哪个阶段解开**。

这个备忘录就是专门记这件事的：**谁被挂起 → 为什么 → 该在哪解开**。推进到对应阶段时照着它提醒用户解开，避免注释残留或漏解。

## 二、登记/解开流程

| 时机 | 动作 |
|------|------|
| **遇到后期内容** | ① 跟用户说"这段可以注释挂起"；② 在本表新增一行；③ 在对应教学 md 里加 ⚠️ 挂起提示 |
| **到对应阶段** | ① 翻本表看有哪些该解的；② 提醒用户放开注释；③ 确认解开后，把该行状态改成 ✅ 已解 |
| **依赖始终没到** | 该行保持挂起状态，直到依赖就位 |

## 四、写教学 md 时的挂起提示模板

对被挂起的代码段，在 md 里加上醒目提示：

```markdown
> ⚠️ 【注释挂起】以下代码依赖阶段 X（`具体类名`），当前依赖未就位，请先注释掉
> （用 `//` 或 `#if 0 ... #endif` 包裹）。代码已一比一还原 Lyra，等阶段 X 就位后放开注释即可。
> （已登记到 `教学经验新对话必看\注释备忘录.md`）
```
