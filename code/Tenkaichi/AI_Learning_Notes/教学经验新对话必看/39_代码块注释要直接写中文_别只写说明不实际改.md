# 39 — 教学铁律：贴给用户的「代码块」注释必须当场直接写中文，禁止"只在旁边表格里写『中文化』说明、代码块却留英文原文"

> **定位**：本文件是 [21](./21_教学代码注释一律写成中文.md)、[28](./28_还原大段真实源码时注释也要中文化_别拿源码原文当借口.md)、[36](./36_注释中文化是无条件全量的_接口分界标记也要中文.md) 的**执行层补强**，教训来自 2026-10-20 P01.1 `FLyraVerbMessage`。新对话开始教学前，除 00~38 外，**必须读本文件**。
>
> **一句话**：用户要照抄的是**代码块**，不是讲解表格。所以**代码块里的 `//` 注释必须当场直接写成中文**；禁止"代码块留英文原文、只在旁边的表格里写一句『中文化：应写成……』"——表格里的说明是"讲给用户听的解说"，**不能替代代码块本身的中文化**。

---

## 一、这条铁律怎么来的（真实教训，2026-10-20）

教 P01.1 `FLyraVerbMessage` 的 `.h` 声明层时，AI 建的 `P01.1_TenkaichiVerbMessage_h.md` 里有两个代码块注释留了英文原文，却在**旁边的讲解表格**里写了"中文化"说明：

```cpp
// Represents a generic message of the form Instigator Verb Target (in Context, with Magnitude)   ← 代码块里英文
USTRUCT(BlueprintType)
struct FLyraVerbMessage
{
	GENERATED_BODY()
```

表格里 AI 却写：

> `| 顶部 // 注释 | **中文化**（铁律 21/28/36）："表示形如『发起者 动词 目标（带上下文与数值）』的通用消息" |`

用户当场连打感叹号怒斥：**"为什么又不翻译注释啊！！！！！！"**

**根因复盘**：
1. AI 犯了一个"自欺"的错误——**把『要照抄的代码块』和『讲给用户听的表格说明』搞混了**。它以为在表格里写一句"这个注释应该中文化成 XXX"，就等于"注释中文化了"。**错**——用户照着代码块抄，抄到的还是英文。
2. 表格里的"中文化：应写成……"只是**解说**（告诉用户"这个注释的意思"），它**不改变代码块本身的内容**。要用户抄到中文注释，就必须**把代码块里的 `//` 直接改成中文**，而不是在别处说明"应该改成中文"。
3. 这是对 21/28/36 的**执行层面**违反：那些铁律规定"注释要中文"，但 AI 把"要中文"做成了"说一句该中文"——**该改的没改，把"改"写成了"说"**。

---

## 二、核心规则（硬动作）

**贴给用户照着写的每个代码块里，所有 `//` / `/* */` 注释一律当场直接写成中文，一个字都不留英文。**

- **代码块 = 用户要照抄的代码**：它是"交付物"，里面的注释必须已经是中文，用户抄过去就是中文。
- **讲解表格 = 讲给用户听的解说**：它只是解释"为什么/什么意思"，**永远不能替代代码块本身的中文化**。
- **判断标准**：扫一遍你贴的**代码块**（不是表格），里面有没有 `//` 开头是英文的？有 → 就是违规，当场改成中文。

---

## 三、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 代码块里 `// Represents a generic message...` | 代码块里直接写 `// 表示形如「发起者 动词 目标」的通用消息` | 代码块留英文，表格里写"应中文化成XXX" |
| 代码块里 `// Returns a debug string...` | 代码块里直接写 `// 返回这个消息的调试字符串表示` | 代码块留英文，表格里写"这是中文化版本" |
| 想讲解某个注释的意思 | 表格里照常讲意思，**但代码块本身必须已是中文** | 用表格里的"中文化说明"当"我已经改了"的证据 |
| 检查注释中文化 | 只检查**代码块**里的 `//` | 只检查表格/正文，忽略代码块 |

---

## 四、为什么必须这样（讲清原因）

- **用户抄代码，抄的是代码块**：表格是给人读的解说，用户真要写进工程时，是照着**代码块**一个字符一个字符敲的。代码块里是英文，敲进工程的就是英文注释——这就违反了 21/28/36 的初衷。
- **"说改"≠"改了"**：在表格里写"这个注释应中文化成 XXX"，只是**告诉用户应该怎么做**，不是**已经把代码块改成中文**。要用户拿到中文，必须**实际改代码块**。
- **讲解表格可以有，但不能替代**：表格可以继续解释"这个注释是什么意思、为什么这么写"，但前提是代码块本身已经是中文。两者不冲突，且**代码块中文化是前提**。

---

## 五、执行要求（贴任何代码块前自检）

1. **扫代码块，不扫表格**：这段要贴的代码里，**每一个代码块**内的 `//` 和 `/* */` 都检查了吗？有没有英文？
2. **当场直接改**：发现英文注释，**就在代码块里直接改成中文**，不要想着"在表格里说明一下就行"。
3. **代码原样**：翻译注释时，类名/方法/宏/关键字/接口名（`FLyraVerbMessage`/`LYRAGAME_API`/`GENERATED_BODY()` 这些标识符）**不能动**，它们属于代码。
4. **别等提醒**：主动做，不等用户喊"你怎么又不翻译注释"。

## 六、和 21/28/36 的关系（本号是它们的执行收口）

- **21 号**：教学代码注释一律中文（管 `.h`/`.cpp`）。
- **28 号**：还原大段真实源码注释也中文，别拿"源码原文"当借口。
- **36 号**：连 `//~AActor interface` 接口分界标记也中文，别拿"结构标记"当借口。
- **39 号（本号）**：**代码块里的注释要当场直接写中文，禁止"只在表格里写中文化说明、代码块留英文"**——堵住"该改代码块却写成解说"的执行漏洞。

> 21/28/36 规定"注释必须中文"（**是什么**）；39 号规定"中文化要落在代码块里，不能只落在解说里"（**怎么做**）。

## 七、一句话结论

**贴给用户照着写的每个代码块，里面的 `//` / `/* */` 注释必须当场直接写成中文——代码块就是交付物，用户照它抄，抄到的必须是中文。禁止"代码块留英文原文、只在旁边表格里写一句『中文化：应写成……』"——表格里的说明是讲给用户听的解说，永远不能替代代码块本身的中文化。检查时就扫代码块，不扫表格。**
