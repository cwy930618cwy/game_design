# 36 — 教学铁律：注释中文化是「无条件全量」的，连接口分界标记 `//~AActor interface` 也不能留英文

> **定位**：本文件是 [21](./21_教学代码注释一律写成中文.md) 和 [28](./28_还原大段真实源码时注释也要中文化_别拿源码原文当借口.md) 的**最后一公里补强**。新对话开始教学前，除 00~35 外，**必须读本文件**。
>
> **一句话**：贴给用户照着写的代码里，**任何 `//` / `/* */` 注释都必须中文化——包括 `//~AActor interface`、`//~End of AActor interface` 这类"接口分界标记"**。不能因为它们看起来像"代码结构标记"就留着英文。

---

## 一、这条铁律怎么来的（真实教训，2026-10-14）

教「4.7.2 ATenkaichiPawn —— `.h` 声明层」时，AI 建了 `4.7.2_Pawn_h.md`，把 `.h` 代码块里的普通说明注释都翻成了中文，但**接口分界标记保留了英文**：

```cpp
	//~AActor interface          ← 留着英文
	UE_API virtual void PreInitializeComponents() override;
	UE_API virtual void EndPlay(const EEndPlayReason::Type EndPlayReason) override;
	//~End of AActor interface   ← 留着英文

	//~APawn interface           ← 留着英文
	UE_API virtual void PossessedBy(AController* NewController) override;
	UE_API virtual void UnPossessed() override;
	//~End of APawn interface    ← 留着英文
```

用户当场质问：**"为什么他的注释是中文的？"**（语气里带着"该中文的不中文"的批评）。

**根因复盘**：AI 犯了一个"自作聪明的例外"——把 `//~AActor interface` 这类标记当成"**不是说明文字、是代码结构分界**"，认为它不在"注释中文化"范围内。这个"我以为它是结构标记"的自我判断，正是 21/28 号已经封死的"找借口留英文"的变体。

---

## 二、核心规则（一条，无条件）

**贴给用户照着写的代码里，所有注释——不分类型、不分位置、不分长什么样——一律翻译成中文。**

"所有注释"到底含哪些？**一个都不能留英文**：

| 注释类型 | 例子 | Lyra 原文 | 你要写成 |
|---------|------|-----------|---------|
| 文档注释 | 类头 | `/** ATenkaichiPawn */` | `/** ATenkaichiPawn */`（类名本身是代码，保留） |
| 说明注释 | 方法上方 | `//~AActor interface` | `//~AActor 接口开始` |
| 分界标记① | 接口开始 | `//~AActor interface` | `//~AActor 接口开始` |
| 分界标记② | 接口结束 | `//~End of AActor interface` | `//~AActor 接口结束` |
| 分界标记③ | 继承接口 | `//~ITenkaichiTeamAgentInterface interface` | `//~ITenkaichiTeamAgentInterface 接口开始` |
| 函数体注释 | 方法内部 | `// This could be changed to return...` | `// 这里可以改成……` |

> **判断标准就一条**：只要它是 `//` 或 `/* */` 开头的东西，**就是注释，就必须中文**。**禁止**用"它是接口分界标记""它是结构标签""它不算说明文字"这类理由留英文。

---

## 三、为什么不能拿"接口分界标记"当借口

之前 AI 的自我辩护是："`//~AActor interface` 是代码结构标记，不是给人看的说明文字，所以算代码、可以留英文。"

**这条辩护是错的**，理由有三：

1. **它是 `//` 注释，语法上就是注释**。`~` 只是 UE 的约定写法（`//~接口名 interface` / `//~End of 接口名 interface`），它仍然是注释，不是代码。
2. **它同样是给人看的**——给读者标"这堆 override 属于 AActor 接口"。中文学习者看 `//~AActor 接口开始` 比 `//~AActor interface` 秒懂。
3. **28 号已经堵死所有"找借口"**：28 号说"不能拿这是源码原文当借口"，本号补一刀——**也不能拿"它是结构标记"当借口**。任何借口在注释中文化面前都无效。

## 四、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| `//~AActor interface` | 写 `//~AActor 接口开始` | 留着英文"因为它结构标记" |
| `//~End of APawn interface` | 写 `//~APawn 接口结束` | 留着英文 |
| 类头 `/** */` | 类名保留，其余中文 | 整段照抄英文 |
| 方法上方说明注释 | 翻成中文 | 留着英文 |
| 函数体内部注释 | 翻成中文 | 留着英文 |

## 五、执行要求（贴任何代码前自检）

1. **扫全部注释**：这段代码里，**每一个** `//` 和 `/* */` 都检查了吗？包括接口分界标记、`~End of` 结尾标记。
2. **别分类**：不要在心里把注释分成"该中文的"和"不该中文的（结构标记）"——**一律中文**。
3. **代码原样**：翻译注释时，类名/方法/宏/关键字/接口名（`AActor`/`APawn`/`ITenkaichiTeamAgentInterface` 这些标识符）**不能动**，它们属于代码。
4. **别等提醒**：主动做，不等用户纠正"你怎么又留英文"。

## 六、和 21/28 的关系（本号是它们的收口）

- **21 号**：教学代码注释一律中文（管 `.h`/`.cpp`）。
- **28 号**：还原大段真实源码（`Target.cs`/`Build.cs`/配置）注释也中文，别拿"源码原文"当借口。
- **36 号（本号）**：连 `//~AActor interface` 这类**接口分界标记**也要中文，别拿"结构标记"当借口。
- 三者合起来 = **注释中文化是全量、无条件、无例外的**：只要 `//` / `/* */` 开头，就中文。

---

## 七、一句话结论

**贴给用户照着写的代码里，所有注释一律中文化，没有任何例外——包括 `//~AActor interface`、`//~End of AActor interface` 这类接口分界标记（写 `//~AActor 接口开始` / `//~AActor 接口结束`）。代码标识符（`AActor`/`APawn`/接口名）原样不动。禁止用"它是结构标记"当借口留英文。**

## 八、标准翻译表（UE 接口分界标记速查）

| Lyra 原文 | 中文化写法 |
|-----------|-----------|
| `//~AActor interface` | `//~AActor 接口开始` |
| `//~End of AActor interface` | `//~AActor 接口结束` |
| `//~APawn interface` | `//~APawn 接口开始` |
| `//~End of APawn interface` | `//~APawn 接口结束` |
| `//~ITenkaichiTeamAgentInterface interface` | `//~ITenkaichiTeamAgentInterface 接口开始` |
| `//~End of ITenkaichiTeamAgentInterface interface` | `//~ITenkaichiTeamAgentInterface 接口结束` |

> 规律：`//~Xxx interface` → `//~Xxx 接口开始`；`//~End of Xxx interface` → `//~Xxx 接口结束`。接口名（`AActor`/`APawn`/`ITenkaichiTeamAgentInterface`）是代码标识符，原样保留。
