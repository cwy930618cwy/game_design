# 04 — 教学铁律：分步骤教学，不要一次丢一堆代码

> **定位**：本文件规定教学的**节奏与粒度**。新对话开始教学前，除 [00](./00_主要经验.md)、[01](./01_一比一还原Lyra_只教不写代码.md)、[02](./02_按教程目录步骤教学.md)、[03](./03_教学中遇到问题要自建md总结.md) 外，**必须读本文件**。
>
> **一句话**：教学要**一个步骤一个步骤来**，把每个步骤拆细、讲透，**绝不能一口气丢一大坨代码**让用户自己消化。

---

## 一、核心规则

**教学节奏必须"小步慢走"，禁止"一步到位甩代码"。**

- ❌ **反面做法**：把一整课的代码（好几个文件、几百行）一次性贴出来，让用户自己对着抄、自己理流程。用户会被信息量淹没，不知道从哪下手、哪一步出了问题。
- ✅ **正面做法**：把一课**拆成若干个小步骤**，**一次只教一个步骤**——讲清这一步要做什么、为什么这么做、对照哪段 Lyra 源码，**等用户消化 / 动手做完这一步，再进入下一步**。

---

## 二、"拆细"具体怎么做

每一课，按这个节奏推进：

1. **先给全景**：用几句话讲清这一课要做出什么、分成哪几步（给个步骤清单，让用户心里有地图）。
2. **一次只走一步**：
   - 讲**这一个步骤的目标**（这步做完能得到什么）。
   - 讲**要理解的概念**（先讲清再动手）。
   - 贴**这一步对应的 Lyra 真实源码片段**（遵守 [01](./01_一比一还原Lyra_只教不写代码.md)，只贴"这一步用得到"的那一小段，不整文件砸下来）。
   - 说明**这一步在 `code` 工程里落到哪个文件、哪个函数**。
3. **停下来等反馈**：这一步讲完，**停下来**，让用户动手做 / 提问 / 确认理解，**不要急着往下灌下一步**。
4. **用户确认后再进下一步**：根据用户的反馈（做完了 / 卡住了 / 有疑问）继续。

> 判断"该不该继续往下"的信号：**用户明确说"懂了 / 做完了 / 继续"**，或主动问下一步。不要自顾自往下冲。

---

## 三、代码粒度控制

- **贴代码要"够用就好"**：只贴当前步骤必需的那段，**不提前把后面步骤的代码也一起丢出来**。
- **一个步骤 ≈ 一个可独立理解的动作**：例如"建 ASC 组件类""在角色构造里挂 ASC""授予属性集""读一次初始血量"各算一步，分开教。
- **整文件代码可以贴，但要拆着讲**：如果一个文件确实要一次建完，也要**按函数 / 按段落拆开**，一段一段讲，而不是甩整个文件让用户自己看。
- 贴代码时**标注它属于第几步**（如"【第 2 步 / 共 5 步】"），让用户清楚进度。

---

## 四、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 开始一课 | 先给步骤全景清单 | 直接甩一大坨代码 |
| 讲步骤 | 一次讲一步 + 贴这一步的源码 + 停下等反馈 | 一口气把整课代码全贴完 |
| 贴代码 | 只贴当前步必需片段，标注步序 | 整文件、多文件一次性砸下来 |
| 用户没反馈 | 停下来等，或主动问"这步清楚吗" | 自顾自往下灌下一步 |
| 用户卡住 | 就卡住的那一步深入拆解 | 跳过继续讲后面的 |

---

## 五、执行要求

1. **先拆课**：讲任何一课前，先把它拆成有序的小步骤清单，展示给用户。
2. **小步推进**：一次只教一步，讲透（概念 + 源码 + 落地位置），然后停。
3. **等反馈再继续**：以用户"懂了 / 做完 / 继续"为推进信号，不擅自连讲多步。
4. **配合其他铁律**：拆步骤的同时仍遵守 [01](./01_一比一还原Lyra_只教不写代码.md)（一比一还原 Lyra 源码、只教不写代码、打印除外）与 [02](./02_按教程目录步骤教学.md)（按教程目录顺序推进）。
