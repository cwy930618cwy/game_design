# 40 — 教学铁律：教同类内容必须先套「已被确认的正确范本」，禁止自创一套"原文→拆解→替换版"的三段式

> **定位**：本文件是 37（md 文件命名照抄既有）、39（代码块注释直接中文）的**内容结构层补强**，教训来自 2026-10-20 P01.1 `FLyraVerbMessage`。新对话开始教学前，除 00~39 外，**必须读本文件**。
>
> **一句话**：教一个新的 `.h`/`.cpp` 时，**先去看同一个目录里已经建过、且用户认可过的同类 md（如重构1阶段五 `3.4.3_InputConfig_h.md`），直接套用它的"章节结构"**，再把内容填进去。**禁止**自己另起炉灶发明一套"先整段展示 Lyra 原文 → 再逐段拆解原文 → 最后才给替换版"的三段式结构——那既绕又容易在"拆解原文"环节犯 39 号的错。

---

## 一、这条铁律怎么来的（真实教训，2026-10-20）

教 P01.1 `FLyraVerbMessage` 的 `.h` 声明层时，AI **没有照抄重构1阶段五 `3.4.3_InputConfig_h.md` 已经被用户认可的正确范本**，而是自创了一套"三段式"结构：

```
第一节：先看 Lyra 真实 .h（一字不差）   ← 整段贴 Lyra 英文原文
第二节：逐段拆解（先讲清为什么，再给代码） ← 代码块注释留英文 + 表格写"中文化"说明
第三节：你要写的代码                     ← 才给替换版
```

结果**两个地方都出问题**：

1. **自创结构、绕远路**：重构1阶段五的正确范本是"**一、本文件要解决什么 → 二、对应 Lyra 源码（只给路径 + 前缀替换说明，不整段贴原文）→ 三、完整代码（直接给替换版+中文注释）→ 四、逐段讲解**"。AI 却多造了一个"整段展示 Lyra 原文"的环节，把一个简单的 `.h`（39 行）拆成 3 个代码块（原文/拆解/替换版），既冗余又增加出错面。
2. **在"逐段拆解"环节犯了 39 号的错**：拆解部分的代码块注释留了英文（`// Represents a generic message...`），旁边表格却写"中文注释（铁律 21/28/36）：'表示形如……'"——**代码块英文、表格说中文，真眼说瞎话**。用户当场怒斥：**"真眼说瞎话？？？？""为什么瞎搞啊"**。

**根因复盘**：
1. **明明有正确范本，却不主动套用**。重构1阶段五的 `3.4.3_InputConfig_h.md` 就是同类（`.h` 教学）已被用户认可的正确结构。AI 教 P01.1 时没去翻它、没照它的章节结构写，而是凭当天心情自创了"原文→拆解→替换版"三段式——**同类内容不用既有范本，等于每个新文件都要重新发明一次结构**，必然出错。
2. **"展示 Lyra 原文"这个多余环节制造了坑**：一旦引入"整段贴 Lyra 英文原文"，后面的"拆解原文"代码块就天然带着英文注释，很容易顺手就留下英文、只在表格里补一句"中文化"——这正是 39 号禁止的。**正确范本压根没有"贴原文"这一节**，直接给替换版，从源头堵死这个坑。

---

## 二、核心规则（硬动作）

**教任何新的 `.h`/`.cpp`（或其他教学单元）前，先做两件事：**

1. **找范本**：在重构1阶段五 / 重构2 目录里，找一个**同类、且已教过、用户没挑过毛病的 md**（`.h` 就找 `.h` 范本，`.cpp` 就找 `.cpp` 范本）。
2. **套结构**：**直接复制它的"章节结构"**（标题层级、每节放什么），只换成本次的内容。结构**照抄，不自创**。

正确范本（重构1阶段五 `3.4.3_InputConfig_h.md`）的章节结构是：

```
# xxx —— 教 .h
## 一、本文件要解决什么
## 二、对应 Lyra 源码        ← 只给路径 + 前缀替换说明，不整段贴 Lyra 原文
## 三、完整代码（注释已中文化） ← 直接给替换好前缀 + 中文注释的完整代码块
## 四、逐段讲解               ← 用替换版代码块，注释已是中文
```

---

## 三、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 教一个新的 `.h`/`.cpp` | 先翻同目录/重构1阶段五找同类范本，**照抄它的章节结构** | 凭感觉自创一套新结构 |
| 展示 Lyra 源码 | 在"对应 Lyra 源码"节**只给路径 + 前缀替换说明** | 整段贴 Lyra 英文原文，再造"拆解原文"环节 |
| 交付代码 | 第一节就给**替换版 + 中文注释**的完整代码块 | 先贴原文、再拆解、最后才给替换版 |
| 逐段讲解 | 用替换版代码块（注释已是中文） | 拆解用的代码块留英文注释、表格里补"中文化" |
| 结构拿不准 | 去翻已认可范本，照它来 | 自己新发明一个"更全/更细"的结构 |

## 四、为什么必须这样（讲清原因）

- **范本就是"已被用户验收"的正确答案**：重构1阶段五的 md 是用户一路确认过来的，它的结构就是用户认可的交付格式。新内容套它的结构 = 大概率一次过；自创结构 = 大概率被抓错。
- **"贴 Lyra 原文"环节是坑源**：一旦引入整段英文原文，后续代码块就容易顺手留英文、只在表格写"中文化"——39 号堵的就是这个。正确范本没有这节，**直接给替换版，从源头消灭坑**。
- **结构稳定 = 心智负担低**：每个新文件结构都一样，用户不用适应新排版，AI 也不用每次重新想结构，出错面最小。这与 37 号（命名照抄）是同一个原则——**命名照既有，结构也照既有**。

---

## 五、执行要求（新建教学 md 前自检）

1. **先找范本**：这个新文件在**重构1阶段五**或**重构2**里有没有同类已教过的 md？有 → 先读它的章节结构。
2. **照抄结构**：标题层级、每节放什么，**原样套用**，只换内容。
3. **删掉多余环节**：如果想到要"先展示 Lyra 原文整段"——**停**，正确范本没有这节，直接给替换版。
4. **代码块即交付**：所有代码块必须是替换版 + 中文注释（配合 39 号），不许代码块英文、表格说中文。
5. **别等提醒**：主动套范本，不等用户喊"你怎么又瞎搞"。

---

## 六、和 37/39 的关系（本号是它们的内容结构版）

- **37 号**：md **文件命名**照抄既有格式，不自创。
- **39 号**：**代码块注释**直接中文，禁止只在表格写"中文化"。
- **40 号（本号）**：**md 的章节结构**也要照抄既有范本，禁止自创"原文→拆解→替换版"三段式——它是 37 的"结构版"，又能在源头避免 39 号的坑。

> 37 管"文件叫什么"、39 管"代码块里写什么"、40 管"md 怎么排章节"。三者合起来：**命名、内容、结构，全部照既有范本，不自创**。

---

## 七、一句话结论

**教任何新的 `.h`/`.cpp` 前，先到重构1阶段五 / 重构2 里找一个同类、已被用户认可的 md，直接照抄它的章节结构，只换内容。禁止自创"先整段展示 Lyra 原文 → 逐段拆解 → 最后给替换版"的三段式——正确范本只给"路径 + 前缀替换说明"，第一节直接交付替换版 + 中文注释的完整代码块。结构照抄既有的，绝不重新发明，否则必然在"拆解原文"环节犯 39 号"代码块英文、表格说中文"的错。**
