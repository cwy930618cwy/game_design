# 00A — 第一步：插件校验（`.uproject` 的 `Plugins` 段）

> 这是 S00 动手前**第一步**要做的事。
> 目标：**让 `.uproject` 里写的插件，一个都不会让引擎报错。**
> 依据：本机 `D:\ue5\Epic Games\UE_5.4` 实查（620 个 `.uplugin`）+ 你工程实查（2026-11-23）

---

## 第 0 步：先建立 3 个认知（1 分钟）

### 认知 1：插件的 `.uplugin` 只有两个地方有

```
引擎插件  → D:\ue5\Epic Games\UE_5.4\Engine\Plugins\**\XXX.uplugin
工程插件  → E:\ue5\game_design\code\Tenkaichi\Plugins\XXX\XXX.uplugin
```

`.uproject` 里写 `"Name": "XXX"`，引擎就去这两处找 `XXX.uplugin`。**找不到就报错。**

### 认知 2：插件有 4 种状态，只有 1 种会报错

| 你写的 | 引擎怎么做 | 找不到 `.uplugin` 时 |
|---|---|---|
| `"Enabled": true` | 去找并加载 | ❌ **报错** |
| `"Enabled": false` | **压根不找** | ✅ 无声忽略 |
| `"Enabled": true` + `"Optional": true` | 去找，找不到就算 | ✅ 无声忽略 |
| `"Enabled": true` + `"PlatformAllowList"` 不含当前平台 | 判断平台后就跳过 | ✅ 无声忽略 |

🔑 **一句话**：**只有「启用 + 无豁免」的插件，存在性才是硬要求。**

### 认知 3：报错原文长这样（记住它，一看就懂）

```
X plugin is referenced by target but not found
```

`X` 就是那个插件的名字。

## 第 1 步：跑一条命令，看你缺不缺（2 分钟）

把下面整段复制到 PowerShell 里回车：

```powershell
$proj = "E:\ue5\game_design\code\Tenkaichi\Tenkaichi.uproject"
$json = Get-Content $proj -Raw | ConvertFrom-Json

# 引擎里所有插件名
$engineNames = Get-ChildItem "D:\ue5\Epic Games\UE_5.4\Engine\Plugins" -Recurse -Filter *.uplugin -File -EA SilentlyContinue | ForEach-Object { $_.BaseName }
# 工程里所有插件名
$projNames   = Get-ChildItem "E:\ue5\game_design\code\Tenkaichi\Plugins" -Recurse -Filter *.uplugin -File -EA SilentlyContinue | ForEach-Object { $_.BaseName }

Write-Output ("插件总数: " + $json.Plugins.Count)
Write-Output "==== 会报错的（启用 + 找不到 + 无 Optional + 无平台白名单）===="
$json.Plugins | Where-Object {
    $_.Enabled -eq $true -and
    $engineNames -notcontains $_.Name -and
    $projNames   -notcontains $_.Name -and
    -not ($_.PSObject.Properties.Name -contains 'Optional') -and
    -not ($_.PSObject.Properties.Name -contains 'PlatformAllowList')
} | ForEach-Object { "  ERROR: " + $_.Name }

Write-Output "==== 本机没有但安全的（豁免）===="
$json.Plugins | Where-Object {
    $engineNames -notcontains $_.Name -and $projNames -notcontains $_.Name
} | ForEach-Object {
    $why = ""
    if (-not $_.Enabled) { $why = "Enabled=false" }
    elseif ($_.PSObject.Properties.Name -contains 'Optional') { $why = "Optional=true" }
    elseif ($_.PSObject.Properties.Name -contains 'PlatformAllowList') { $why = "平台白名单=[" + ($_.PlatformAllowList -join ",") + "]" }
    "  OK: {0,-30} 原因: {1}" -f $_.Name, $why
}
```

## 第 2 步：搞清楚「本机没有」的那 11 个是什么（3 分钟）

你可能会想：Lyra 明明写了，为什么我这没有？

| 插件 | 本机为什么没有 | 要不要删 |
|---|---|---|
| `MagicLeap` | MagicLeap AR 平台，UE5.4 起从引擎移除 | ❌ 不删（Lyra 原样） |
| `MagicLeapMedia` | 同上（媒体播放部分） | ❌ 不删 |
| `MagicLeapPassableWorld` | 同上（可通行世界部分） | ❌ 不删 |
| `OpenXRHMD` | UE5.4 已并入 `OpenXR` 主插件 | ❌ 不删 |
| `SteamVR` | 5.4 改为可选分发（Launcher 版不带） | ❌ 不删 |
| `GearVR` | 三星 GearVR 已废弃 | ❌ 不删 |
| `LuminPlatformFeatures` | MagicLeap Lumin 平台已废弃 | ❌ 不删 |
| `MLSDK` | MagicLeap SDK，已移除 | ❌ 不删 |
| `RuntimePhysXCooking` | UE5 默认用 Chaos 物理，PhysX 相关已移除 | ❌ 不删 |
| `D3DExternalGPUStatistics` | 外接显卡统计，需单独装 | ❌ 不删（有 `Optional`） |
| `PlayFabParty` | 主机语音，只在 XB1/XSX 启用 | ❌ 不删（有白名单） |

**为什么一个都不删**：

```
① 一比一    → Lyra 原文就这么写的，删了偏离源
② 无害      → 全是 Enabled:false / Optional / 白名单，引擎不查
③ 换引擎时  → 以后要是用源码版 UE5.4，这些插件就有了，不用再改回来
```

> 📌 **你用的是 Epic Launcher 装的 UE 5.4（功能完整版，但不是「引擎源码全量插件版」）**。
> Lyra 官方是在引擎源码环境下做的，所以敢写这些已废弃插件。

## 第 3 步：记住「什么时候会突然报错」（1 分钟）

**只有一种情况**：你把某个 `"Enabled": false` 改成了 `true`。

```jsonc
// ❌ 这样改 → 立刻报错
{ "Name": "MagicLeap", "Enabled": true }        → MagicLeap plugin is referenced by target but not found
{ "Name": "RuntimePhysXCooking", "Enabled": true } → RuntimePhysXCooking plugin is referenced by target but not found

// ✅ 保持原样 → 永远不报错
{ "Name": "MagicLeap", "Enabled": false }
```

## 第 4 步：真报错了怎么办（对症下药）

| 报错里的插件名 | 是什么 | 怎么做 |
|---|---|---|
| 9 个已废弃插件之一（`MagicLeap` / `SteamVR` / `GearVR` / `MLSDK` / `OpenXRHMD` / `RuntimePhysXCooking` …） | 你误改成了 `true` | **改回 `false`** |
| 9 个工程插件之一（`AsyncMixin` / `CommonGame` / `ModularGameplayActors` …） | `Plugins\` 下没有对应目录 | 把插件的 `.uplugin` 放进 `Tenkaichi\Plugins\XXX\`（S01~S05 建） |
| `PocketWorlds` / `ShooterCore` / `ShooterMaps` / `TopDownArena` / `ShooterExplorer` / `ShooterTests` | 这几个是 Lyra 的示例玩法插件，**我们 S00 故意没写** | **不要加进 `.uproject`**，S05 / S23 才加 |
| 别的引擎插件 | 拼错名字 / 引擎版本不对 | 检查拼写；确认 `EngineAssociation` 是 `5.4` |

## 第 5 步：一条铁律（贴墙上）

```
先建目录（含 .uplugin）  →  再往 .uproject 加清单
```

反过来的后果：

```
.uproject 先写了 XXX  →  Plugins\XXX\XXX.uplugin 还不存在  →  引擎报错  →  编辑器打不开
```

这就是为什么我们 S00 只写 **70 项**，不写 Lyra 的 76 项 —— 差的 6 项（`PocketWorlds` + 5 个示例玩法）源码还没建。
