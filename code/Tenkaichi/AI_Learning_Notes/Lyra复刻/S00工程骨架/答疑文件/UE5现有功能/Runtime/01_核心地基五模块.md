# ① — `Core` / `CoreUObject` / `Engine` / `ApplicationCore` / `Launch` 详解

> 位置：`Engine\Source\Runtime\` 下的 5 个模块
> 来源：引擎源码（`D:\ue5\Epic Games\UE_5.4`，**只读不改**）
> 分类：Runtime · 核心地基
> 规模：Runtime 177 个模块里最底层的 5 个，其他 172 个基本都直接间接依赖它们

---

## 一、一句话

★ 这 5 个是 UE5 的「**地基五件套**」：Core 管基础类型，CoreUObject 管反射和对象，Engine 管游戏对象，ApplicationCore 管应用外壳，Launch 管程序入口。

---

## 二、5 个模块各自干嘛

### `Core` —— 最底层的 C++ 工具箱

不依赖任何引擎模块，提供基础类型、容器、字符串、数学、内存、日志、委托、异步。

- `Public\CoreMinimal.h` —— 几乎所有 `.h` 文件的第一行 include，把常用头一次性拉进来
- `Public\CoreTypes.h` —— 基础类型别名（`int32` / `uint8` / `FString` 的前置声明等）
- `Public\Containers\` —— `TArray` / `TMap` / `TSet` / `FString`
- `Public\Math\` —— `FVector` / `FRotator` / `FMath`
- `Public\Delegates\` —— `DECLARE_DELEGATE` 系列

### `CoreUObject` —— 反射系统 + 垃圾回收

UE 之所以是 UE 的核心：UCLASS / UPROPERTY / UFUNCTION 的元数据、对象的创建与销毁、序列化都在这。

- `Public\UObject\UObjectGlobals.h` —— `NewObject<>` / `LoadObject<>` / `StaticFindObject`
- `Public\UObject\Class.h` —— `UClass` 本体，反射数据的载体
- `Public\UObject\Object.h` —— `UObject` 基类，所有反射对象的根
- `Public\Serialization\` —— 存档 / 网络序列化

### `Engine` —— 游戏运行时主体

你平时写的 `AActor` / `APawn` / `APlayerController` / `UWorld` / `UActorComponent` 全在这。

- `Classes\Engine\Engine.h` —— `UEngine`，游戏引擎主对象（另有一个 `Public\Engine.h` 是轻量头）
- `Classes\GameFramework\Actor.h` —— `AActor`，场景里一切物体的基类
- `Classes\GameFramework\PlayerController.h` —— `APlayerController`
- `Classes\Components\` —— `UStaticMeshComponent` / `USkeletalMeshComponent` 等组件

### `ApplicationCore` —— 应用外壳

管「这是一个应用程序」级别的事：命令行参数、平台抽象、应用生命周期、Slate 启动前的初始化。不直接提供游戏类。

### `Launch` —— 程序入口

整个引擎和编辑器的 `main` 所在地，`GuardedMain` / `LaunchEngineLoop` 负责启动到关闭的完整循环。你基本不会直接 include 它。

- `Public\LaunchEngineLoop.h` —— 引擎主循环类

## 三、有它 vs 没它

| 模块 | 没它会怎样 |
|---|---|
| `Core` | 连 `int32` 和 `TArray` 都没有，什么都编译不了 |
| `CoreUObject` | 没有 UCLASS / UPROPERTY / GC，退化成纯 C++，UE 的编辑器/蓝图全没了 |
| `Engine` | 没有 Actor / World / Component，写不了游戏逻辑 |
| `ApplicationCore` | 起不来应用程序，平台层和 Slate 无法初始化 |
| `Launch` | 没有可执行入口，引擎无法启动 |

---

## 四、Lyra 怎么用它（大概）

- **Core**：Lyra 每个 `.h` 几乎都 include `CoreMinimal.h`；`TArray` / `TMap` / `FGameplayTag` 的底层容器都来自 Core。
- **CoreUObject**：`ULyraHeroComponent` / `ULyraHealthComponent` 继承了 UObject 体系；`ULyraGameplayAbility` 的反射、引擎的 `NewObject<>` 全靠它。
- **Engine**：`ALyraCharacter : ACharacter`、`ULyraGameInstance : UCommonGameInstance`（再往上就是 `UGameInstance`）、`ULyraCameraComponent` 都活在 Engine 层。
- **ApplicationCore / Launch**：Lyra 不直接写它们，但每个可执行文件都是经 Launch 启动、经 ApplicationCore 初始化的。

---

## 五、本复刻线什么时候碰它

| 模块 | 什么时候查 |
|---|---|
| `Core` | 写任何 `.h` 时；查容器 / 字符串 / 委托用法 |
| `CoreUObject` | 理解 `UPROPERTY` 为什么能反射、对象什么时候被 GC |
| `Engine` | 查 `AActor` / `APawn` / `UGameInstance` 的基类方法签名（**最常查**） |
| `ApplicationCore` | 基本不碰 |
| `Launch` | 基本不碰 |

---

## 六、注意

- 这 5 个模块**不是插件**，是引擎自带模块。你的 `.uproject` 里不需要写它们，但 `Build.cs` 里几乎一定会依赖 `Core` / `CoreUObject` / `Engine`。
- Engine 模块的头文件分散在 `Public\` 和 `Classes\` 两个目录，找 `Actor.h` 要去 `Classes\GameFramework\`，别只搜 `Public\`。
- 复刻时**只读不改**引擎源码；这 5 个模块里的代码你照抄的机会很少，主要是查签名。
