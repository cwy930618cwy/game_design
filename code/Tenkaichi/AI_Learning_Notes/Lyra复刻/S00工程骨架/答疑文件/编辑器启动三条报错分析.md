# 答疑 — 编辑器启动三条报错分析（S00 阶段）

> 触发：敲完 S00 前 5 个文件后启动编辑器，`Output Log` 里出现 3 条 `Error`，其中 2 条还弹了 `是否将条目添加到 DefaultEngine.ini？` 对话框。
> 结论：**都是 `Config\` 缺条目导致的，跟 S00 已敲的代码无关；改 ini 即可，不改任何 `.h/.cpp`。**
> 依据：`D:\ue5\Epic Games\UE_5.4`（引擎源码实查）+ `E:\ue5\LyraStarterGame\Config`（Lyra 原配置实查）

---

## 一、三条报错 → 两个根因

| # | 报错原文 | 根因 | 修复文件 |
|---|---|---|---|
| 1 | `LogGameFeatures: Error: Asset manager settings do not include a rule for assets of type GameFeatureData` | `Config\DefaultGame.ini` 里**没有** `[/Script/Engine.AssetManagerSettings]` 段 | `Config\DefaultGame.ini` |
| 2 | `LoadErrors: Error: 资产管理器设置不包含类型为GameFeatureData的资产的条目…` | 同 #1（这是 #1 的中文弹窗版，**同一条**） | 同上 |
| 3 | `LoadErrors: Error: 碰撞描述文件设置不包括水体碰撞描述文件的条目…` | `Config\DefaultEngine.ini` 里**没有** `WaterBodyCollision` 碰撞配置 | `Config\DefaultEngine.ini` |

> 所以真正只有 **2 个根因**；#1 和 #2 是一条报错的两次输出（`LogGameFeatures` 打日志 + `LoadErrors` 弹窗）。

## 二、为什么 S00 阶段必然触发

```
S00 当前拥有的东西              缺少的东西                   报错
├─ Tenkaichi.uproject           Config\DefaultGame.ini 空 →  [1][2]
│  └─ 启用了 GameFeatures / Water 插件    没有任何 PrimaryAssetTypesToScan
├─ Source\LyraGame\             Config\DefaultEngine.ini 无 →  [3]
│  └─ LyraGameModule.cpp（空模块）          [/Script/Engine.CollisionProfile] 段
└─ Config\DefaultEngine.ini
   └─ 只有渲染 / 音频 / 平台设置
```

两处检查都是「**只要工程里有内容就报错**」的硬检查：

| 报错 | 引擎检查代码 | 判断条件 |
|---|---|---|
| [1][2] | `Engine\Plugins\Runtime\GameFeatures\Source\GameFeatures\Private\GameFeaturesSubsystem.cpp:494` | `FApp::HasProjectName() && GetPrimaryAssetRules(GameFeatureData).IsDefault()` |
| [3] | `Engine\Plugins\Experimental\Water\Source\Editor\Private\WaterEditorModule.cpp:347` | `FApp::HasProjectName() && !GetProfileTemplate("WaterBodyCollision")` |

两处都写着 `Only error when we have a UE project loaded` —— **打开的是模板工程不报，打开你自己的工程就报**。所以这是「正常工程没配好」的信号，不是代码写错。

## 三、报错 [1][2]：GameFeatureData 资产规则

### 3.1 它到底在说什么

`GameFeatures` 插件（我们在 `.uproject` 里启用了）启动时要确认：**资产管理器知不知道「GameFeatureData 这种资产」怎么扫、怎么打包**。
它去 `UAssetManager` 查规则，查不到默认值 → 报错。

### 3.2 Lyra 怎么写的

`E:\ue5\LyraStarterGame\Config\DefaultGame.ini:44`

```ini
+PrimaryAssetTypesToScan=(PrimaryAssetType="GameFeatureData",AssetBaseClass="/Script/GameFeatures.GameFeatureData",bHasBlueprintClasses=False,bIsEditorOnly=False,Directories=((Path="/Game/Unused")),SpecificAssets=,Rules=(Priority=-1,ChunkId=-1,bApplyRecursively=True,CookRule=AlwaysCook))
```

### 3.3 S00 阶段的最小改法（只加这 1 行）

在 `E:\ue5\game_design\code\Tenkaichi\Config\DefaultGame.ini` 末尾追加：

```ini
[/Script/Engine.AssetManagerSettings]
+PrimaryAssetTypesToScan=(PrimaryAssetType="GameFeatureData",AssetBaseClass="/Script/GameFeatures.GameFeatureData",bHasBlueprintClasses=False,bIsEditorOnly=False,Directories=((Path="/Game/Unused")),SpecificAssets=,Rules=(Priority=-1,ChunkId=-1,bApplyRecursively=True,CookRule=AlwaysCook))
```

> ⚠️ **只加这一行**，不要现在就把 Lyra 的 `LyraExperienceDefinition` / `LyraGameData` / `LyraLobbyBackground` 等 6 条一起抄进来 —— 那些类的 `AssetBaseClass` 指向 `/Script/LyraGame.XXX`，而 S00 阶段 `LyraGame` 模块还是空的，**类不存在会再触发一批新警告**。
>
> 📌 **收敛时机**：S07 建完 `ULyraAssetManager` 后，把 Lyra `DefaultGame.ini:38-54` 整段（8 条规则 + 5 个 `bShouldXXX` 开关）一次性照抄过来，与本行合并为完整版。

## 四、报错 [3]：WaterBodyCollision 碰撞配置

### 4.1 它到底在说什么

`.uproject` 启用了 `Water` 插件（Lyra 原样启用）。Water 插件的编辑器模块启动时检查：**碰撞配置里有没有 `WaterBodyCollision` 这个 Profile**，没有就报错 + 弹窗问你要不要自动加。

### 4.2 Lyra 怎么写的

`E:\ue5\LyraStarterGame\Config\DefaultEngine.ini:175`

```ini
+Profiles=(Name="WaterBodyCollision",CollisionEnabled=QueryOnly,bCanModify=False,ObjectTypeName="",CustomResponses=((Channel="WorldDynamic",Response=ECR_Overlap),(Channel="Pawn",Response=ECR_Overlap),(Channel="Visibility",Response=ECR_Ignore),(Channel="Camera",Response=ECR_Ignore),(Channel="PhysicsBody",Response=ECR_Overlap),(Channel="Vehicle",Response=ECR_Overlap),(Channel="Destructible",Response=ECR_Overlap)),HelpMessage="Default Water Collision Profile (Created by Water Plugin)")
```

### 4.3 S00 阶段的最小改法（只加这 1 行 + 段头）

在 `E:\ue5\game_design\code\Tenkaichi\Config\DefaultEngine.ini` 末尾追加：

```ini
[/Script/Engine.CollisionProfile]
+Profiles=(Name="WaterBodyCollision",CollisionEnabled=QueryOnly,bCanModify=False,ObjectTypeName="",CustomResponses=((Channel="WorldDynamic",Response=ECR_Overlap),(Channel="Pawn",Response=ECR_Overlap),(Channel="Visibility",Response=ECR_Ignore),(Channel="Camera",Response=ECR_Ignore),(Channel="PhysicsBody",Response=ECR_Overlap),(Channel="Vehicle",Response=ECR_Overlap),(Channel="Destructible",Response=ECR_Overlap)),HelpMessage="Default Water Collision Profile (Created by Water Plugin)")
```

### 4.4 顺带一句：点弹窗的「是」会怎样

点「是」等于调 `WaterEditorModule.cpp:357 AddWaterCollisionProfile()`，它会自动往 `DefaultEngine.ini` 写**几乎一样的一行**（差异只有 `ObjectTypeName` 会被填成 `WorldStatic`、`bCanModify` 也是 false）。能消错，但**跟 Lyra 原文不完全一致**（Lyra 的 `ObjectTypeName` 是空串）。所以推荐手动抄 Lyra 这一行，别点弹窗。

> ⚠️ **不建议为了消错去关 `Water` 插件** —— Lyra 原样启用它，关掉违反「一比一」；而且后面关卡里但凡有水体都会挂。

## 五、改完怎么验证

1. 关掉编辑器（改 ini 必须重启才生效）。
2. 重新双击 `Tenkaichi.uproject`。
3. `Output Log` 里搜 `Error`：上面 3 条应该**全部消失**。
4. 若还有别的 `Error`，先确认是不是这两个根因的变体，再往下查。

> 📌 预期仍会保留的**无害**提示（不要当成错误去修）：
> - `LogWindows: Failed to load 'aqProf.dll' / 'VtuneApi.dll'` —— 没装 GPU/CPU 分析工具，正常
> - `LogWindows: Failed to load 'WinPixGpuCapturer.dll'` —— 没装 PIX，正常
> - `LogCore: Warning: UTS: Unable to launch the Unreal Trace Server ... 拒绝访问` —— 权限问题，不影响编辑
> - `LogAudio: No default SoundConcurrencyObject specified` —— 引擎默认，忽略

## 六、这两行属于哪一轮讲义

| ini 改动 | 属于 | 说明 |
|---|---|---|
| `[/Script/Engine.AssetManagerSettings]` 全段 | **S07**（`ULyraAssetManager` 讲义） | S07 会一次性给完整 8 条规则；本次只是先加 1 条消错 |
| `[/Script/Engine.CollisionProfile]` 里 `WaterBodyCollision` | **S06**（`LyraCollisionChannels.h` 讲义） | S06 会顺带把 Lyra 的完整碰撞段（含 `LyraPawnMesh` / `LyraPawnCapsule` 等 4 个自定义 Profile）照抄进来 |

> 也就是说：**现在这两行是「临时止血」，S06 / S07 会被完整版覆盖**。这样既不阻塞今天启动编辑器，也不影响后面一比一。

---

## 七、一句话总结

**两条报错都是 `Config\` 少了条目：`DefaultGame.ini` 缺 `GameFeatureData` 的资产扫描规则，`DefaultEngine.ini` 缺 `WaterBodyCollision` 碰撞配置。各加 1 行 Lyra 原文即可，代码一行不动；完整版分别在 S07（AssetManager）和 S06（碰撞段）收敛。**
