# 技能配置长啥样？—— 用"突击步枪开火"举例

> **定位**：前面 [03_运行时链路](./03_动起来后_运行时链路人物谱.md) 讲了"按键→技能→伤害"的**运行时流程**。本文回答一个具体问题：**这些技能的"配置"到底长啥样？** 用一个完整例子——突击步枪开火——把配置面板还原出来。
>
> **一句话**：Lyra 的技能配置**不在代码里，而是一堆数据资产（`.uasset`）**。你在编辑器里打开它们，像填表一样配置"这个技能耗多少蓝、按哪个键触发、打多远、扣多少血"。本文用 C++ 结构体反推出这些"表格"的真实样子。

---

## 一、先破一个误区：配置 ≠ 代码

```
❌ 你以为的：技能写在 .cpp 里，if(按开火键) 开火()
✅ 实际的：  技能是一堆 .uasset 数据资产，代码只写"逻辑"，"数值/参数"全在资产里填
```

> **关键认知**：Lyra 是**数据驱动**。程序员写"技能怎么执行"（C++），策划/设计师在编辑器里填"技能的具体数值"（`.uasset`）。**同一套代码，填不同配置 = 不同的枪/不同的技能**。

这些配置资产长什么样？——**它们就是 C++ 结构体的可视化**。每个 `UPROPERTY(EditAnywhere, Category="xxx")` = 编辑器面板上的一个格子。本文就带你"反推"这些面板。

---

## 二、配置的"五层套娃"（以突击步枪为例）

一个"开火"技能，配置分散在 5 个数据资产里，层层引用：

```
① 📋 角色设计稿(PawnData)     "这个英雄有哪些技能、用什么操作"
        │ 引用
        ▼
② 🎁 技能套装(AbilitySet)     "给这个英雄发：开火技能 + 跳跃技能 + 血量属性"
        │ 引用
        ▼
③ ⚡ 技能本身(GameplayAbility) "开火技能：按什么键、耗什么、怎么激活"
        │ 引用
        ▼
④ 🎯 武器实例(WeaponInstance)  "这把枪：射程、伤害、后坐力曲线、弹容量"
        │ 施加
        ▼
⑤ 💥 伤害效果(GameplayEffect)  "命中后扣多少血"
```

> 下面逐层打开配置面板。

```
│  └────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────┐ │

```

**它在说什么**：这个英雄"用 Shooter 身体 + 发两套技能 + 用这套操作 + 这个镜头"。**它是角色的总配置入口**。

**它在说什么**："给这个英雄发：跳跃/蹲/冲刺/死亡 4 个技能 + 初始化属性的效果 + 血量/战斗两张属性表"。

## 五、第③层：技能本身 `GA_Jump`（打开一个具体技能）

**对应 C++**：`ULyraGameplayAbility`（[LyraGameplayAbility.h](../../LyraStarterGame5.6/LyraStarterGame/Source/LyraGame/AbilitySystem/Abilities/LyraGameplayAbility.h)）

双击某个技能资产，面板长这样：

```
┌─ GA_Jump ─────────────────────────────────────────┐
│                                                   │
│  Lyra | Ability Activation                        │
│  ┌──────────────────────────────────────────────┐ │
│  │ Activation Policy:  On Input Triggered  ▼    │ │  ← 按键触发一次
│  │ Activation Group:   Independent  ▼           │ │  ← 独立，不顶替别人
│  └──────────────────────────────────────────────┘ │
│                                                   │
│  Costs                                              │
│  ┌──────────────────────────────────────────────┐ │
│  │ Additional Costs:  (空 = 跳跃不耗资源)       │ │  ← 放技能代价
│  └──────────────────────────────────────────────┘ │
│                                                   │
│  Advanced                                           │
│  ┌──────────────────────────────────────────────┐ │
│  │ Failure Tag To User Facing Messages:         │ │  ← 放不出来时的提示
│  │   (空)                                       │ │
│  └──────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────┘
```

**关键字段解释**（都是 C++ 里的 `UPROPERTY`）：

| 面板字段 | C++ 字段 | 含义 |
|---------|---------|------|
| Activation Policy | `ActivationPolicy` | `OnInputTriggered`（按一次）/`WhileInputActive`（按住持续）/`OnSpawn`（出生自动） |
| Activation Group | `ActivationGroup` | `Independent`（独立）/`Exclusive_Replaceable`（互相顶替）/`Exclusive_Blocking`（占着不让别人放） |
| Additional Costs | `AdditionalCosts` | 放技能的代价（蓝量/弹药/充能），见下面"代价" |

### 代价 `ULyraAbilityCost`（[LyraAbilityCost.h](../../LyraStarterGame5.6/LyraStarterGame/Source/LyraGame/AbilitySystem/Abilities/LyraAbilityCost.h)）

"开火耗弹药"这种代价，是一个个可插入的子对象：

```
┌─ GA_FireRifle 的 Costs ───────────────────────────┐
│  Additional Costs:                                │
│  ┌──────────────────────────────────────────────┐ │
│  │ ☑ Only Apply Cost On Hit:  true              │ │  ← 打中才扣弹药
│  │   (命中成功才扣，打空不扣)                    │ │
│  └──────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────┘
```

> `bOnlyApplyCostOnHit` = 打中才扣弹药（避免打空也浪费子弹）。这是"开火技能"和"跳跃技能"配置的关键区别。

## 六、第④层：按键怎么映射到技能？`DA_InputConfig_Hero`

**对应 C++**：`ULyraInputConfig`（[LyraInputConfig.h](../../LyraStarterGame5.6/LyraStarterGame/Source/LyraGame/Input/LyraInputConfig.h)）

"按跳跃键 → 触发 GA_Jump"这步，靠输入配置。面板长这样（结构体 `FLyraInputAction`）：

```
┌─ DA_InputConfig_Hero ─────────────────────────────┐
│                                                   │
│  Ability Input Actions:  (技能用的按键)           │
│  ┌──────────────────────────────────────────────┐ │
│  │ Input Action       │ Input Tag               │ │
│  ├──────────────────────────────────────────────┤ │
│  │ IA_Fire            │ InputTag.Weapon.Firing  │ │  ← 开火键 → 开火技能
│  │ IA_Jump            │ InputTag.Jump           │ │  ← 跳跃键 → 跳跃技能
│  │ IA_Aim             │ InputTag.Weapon.Aiming  │ │
│  └──────────────────────────────────────────────┘ │
│                                                   │
│  Native Input Actions:  (非技能的按键，如移动)    │
│  ┌──────────────────────────────────────────────┐ │
│  │ IA_Move            │ InputTag.Move           │ │
│  │ IA_Look            │ InputTag.Look           │ │
│  └──────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────┘
```

**它怎么串起来**：

```
你按"开火键"
  → IA_Fire（输入动作）
  → 查表得到 InputTag.Weapon.Firing
  → 技能总管(ASC)找"哪个技能的 InputTag 是 Firing"
  → 找到 GA_FireRifle → 激活它
```

> **关键**：按键和技能**不直接绑定**，中间隔了一个 **GameplayTag（输入标签）**。这样"换按键"只改输入配置，"换技能"只改技能套装，互不影响。

## 八、第⑤层：伤害效果 `GE_DealDamage`

**对应 C++**：`GameplayEffect`（引擎）+ `ULyraDamageExecution`（[LyraDamageExecution.h](../../LyraStarterGame5.6/LyraStarterGame/Source/LyraGame/AbilitySystem/Executions/LyraDamageExecution.h)）

"命中扣多少血"。伤害 GE 通常用 **SetByCaller**（调用者指定数值）：

```
┌─ GE_DealDamage ───────────────────────────────────┐
│                                                   │
│  Modifiers                                          │
│  ┌──────────────────────────────────────────────┐ │
│  │ Attribute:  Health (血量)                    │ │
│  │ Modifier Op: Add                             │ │
│  │ Magnitude:   Set By Caller Tag               │ │  ← 由开火方动态传入
│  │   = GameplayEffect.SetByCaller.Damage        │ │     (不是写死的数字)
│  └──────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────┘
```

**它怎么工作**：
- GE 不写死"扣40血"，而是说"扣血量 = 调用者传进来的 `Damage` 值"。
- 开火技能命中时，从**武器实例**读基础伤害 → 乘**距离衰减** → 乘**材质倍数**（爆头2x）→ 算出最终值 → 作为 `Damage` 传给 GE。
- GE 把这个值**扣到目标的 Health 属性上**（呼应 [03](./03_动起来后_运行时链路人物谱.md) 的"📉血量属性"）。

> **呼应最早那篇**：`LyraGameData` 里存的就是这个伤害 GE 的软引用——**一个 GE 复用多种数值场景**（枪伤、爆炸伤、毒伤都用它，只是传不同 Damage 值）。

## 九、完整配置链：从"按开火键"到"扣血"

把五层串起来，看配置如何环环相扣：

```
【你按开火键】
   ↓
④ DA_InputConfig_Hero：IA_Fire → InputTag.Weapon.Firing
   ↓
① DA_Hero_PawnData：这个英雄挂了 DA_WeaponAbilities 技能套装
   ↓
② DA_WeaponAbilities：里面有个技能 InputTag = Firing → GA_FireRifle
   ↓
③ GA_FireRifle（技能）：
   - ActivationPolicy = OnInputTriggered（按键触发）
   - Cost = 打中才扣弹药(bOnlyApplyCostOnHit)
   - 引用武器 → DA_Rifle_Weapon
   ↓
④ DA_Rifle_Weapon（武器实例）：
   - 射线检测(WeaponTrace)打中敌人
   - 基础伤害 × 距离衰减 × 材质倍数(爆头2x) = 最终伤害
   ↓
⑤ GE_DealDamage（伤害效果）：
   - 把最终伤害值(SetByCaller)扣到目标 Health
   ↓
【目标血量 -40，血量归0则触发死亡】
```

## 十一、三个关键认知

### ① 配置 = 数据资产，不是代码
技能的"数值/参数"全在 `.uasset` 里，代码只写"逻辑"。**改配置不用重新编译**——编辑器里改数字，立即生效。这就是"数据驱动"。

### ② GameplayTag 是"万能插头"
按键和技能不直接绑，中间隔 `InputTag`；技能之间用 `AbilityTag` 管互斥。**Tag 让各配置解耦**——换按键、换技能、改互斥都互不影响。

### ③ SetByCaller 让一个 GE 复用
伤害 GE 不写死数值，用 SetByCaller 由调用方传入。**枪伤/爆炸/毒伤共用一个 GE**，只传不同 Damage 值——这就是最早 `LyraGameData` 只存 3 个 GE 的原因。

### 真实版"步枪开火"配置链（照着这个路径在编辑器里点开）

把前面讲的"五层套娃"换成**真实文件**：

```
【第①层·角色设计稿】
  Content/Characters/Heroes/SimplePawnData/SimplePawnData.uasset
  （或射击模式：ShooterCore/.../HeroData_ShooterGame.uasset）
        │ 引用 AbilitySet
        ▼
【第②层·技能套装】
  ShooterCore/Content/Game/AbilitySet_ShooterHero.uasset     ← 英雄通用技能(跳/蹲/死)
  ShooterCore/Content/Weapons/Rifle/AbilitySet_ShooterRifle.uasset  ← 步枪技能(开火/换弹)
        │ 里面挂着 GA
        ▼
【第③层·技能本身】
  Content/Weapons/GA_Weapon_Fire.uasset   ← 开火技能(激活策略/代价)
        │ 引用武器
        ▼
【第④层·武器实例】
  ShooterCore/Content/Weapons/Rifle/WID_Rifle.uasset   ← 步枪(射程/散布/伤害曲线)
        │ 命中后施加 GE
        ▼
【第⑤层·伤害效果】
  ShooterCore/Content/Weapons/Rifle/GE_Damage_RifleAuto.uasset
  （或通用：Content/GameplayEffects/Damage/GE_Damage_Basic_SetByCaller.uasset）
```

**互斥规则**（开火时不能换弹之类）在：
```
ShooterCore/Content/Game/TagRelationships_ShooterHero.uasset
```

**表现特效**（枪口火光、子弹命中火花）在：
```
ShooterCore/Content/Weapons/Rifle/GCN_Weapon_Rifle_Fire.uasset
```

### 一个关键发现：技能套装"分家"了

注意真实项目里，技能套装**拆成了两份**：

```
AbilitySet_ShooterHero   →  英雄"身上"的技能（跳/蹲/冲刺/死亡/治疗）
AbilitySet_ShooterRifle  →  武器"附带"的技能（开火/换弹）
```

> 这正好呼应 [02 开演后](./02_开演后_玩家与角色人物谱.md) 讲的：角色设计稿（PawnData）里的 `AbilitySets` 是个**数组**——可以挂多份技能套装。英雄一份、每把武器一份，**换枪 = 换一份武器技能套装**，设计非常清爽。

### 怎么在编辑器里验证

1. 打开 `LyraStarterGame.uproject`（编辑器）。
2. 内容浏览器（Content Browser）里导航到 `Content/Weapons/`，找到 `GA_Weapon_Fire`，**双击打开**。
3. 右侧 Details 面板就能看到本文第三节讲的"Activation Policy / Activation Group / Costs"那些格子——**和本文画的一模一样**。
4. 顺着引用往下点：`GA_Weapon_Fire` 里引用的武器 → `WID_Rifle`；`AbilitySet_ShooterRifle` 里挂的 `GA_Weapon_Fire`……整条链就串起来了。

> 提示：这些是二进制 `.uasset`，用文本编辑器打开是乱码，**必须在 UE 编辑器里打开**。
