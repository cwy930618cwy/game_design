# 05 — UI 资源详解（Content/UI 里有什么）

> **定位**：讲 Lyra Content 里的 `UI/` 目录——存放所有**界面资源**（血条、准星、菜单、背包界面等）。重点回答"Lyra 的 UI 长什么样、用什么技术、怎么组织"。
>
> **关联**：
> - [UE5.6_深入理解/.../02_CommonUI详解](../../UE5.6_深入理解/03_UI模块/02_CommonUI详解.md) — CommonUI 框架原理
> - [UE5.6_深入理解/.../04_UMG控件大全详解](../../UE5.6_深入理解/03_UI模块/04_UMG控件大全详解.md) — UMG 控件基础
>
> **一句话**：Lyra 的 UI 全部基于 **CommonUI + UMG**，`UI/` 目录里是各种 **Widget 蓝图（W_ 开头）**——从准星血条到主菜单设置，都是可视化界面资产。

---

## 一、Lyra UI 用什么技术

先明确：Lyra 的 UI **不是用 Slate 硬写**，而是：

```
UMG（基础控件库）
   ↑ 增强
CommonUI（高级框架：手柄导航/输入切换/弹窗栈）
   ↑ 使用
Lyra UI（Content/UI 里的 Widget 蓝图）
```

| 技术 | 角色 |
|------|------|
| **UMG** | 基础控件（按钮、文本、图片、血条） |
| **CommonUI** | 高级能力（手柄焦点、输入切换、可激活窗口栈） |
| **Widget 蓝图** | 具体的界面资产（`W_xxx` / `UI_xxx`） |

> ⚠️ Lyra 的 UI 几乎全是**蓝图**（不是 C++），程序员写好基类（C++），策划/技术在蓝图里搭界面。

---

## 二、UI/ 目录里有什么（典型分类）

虽然不同 Lyra 版本子目录命名有差异，但**界面类型一致**。大致分这几类：

```
UI/
├── HUD/                    ← 游戏内抬头显示（战斗中常驻）
│     ├── W_ShooterHUD      ← 射击模式 HUD 总容器
│     ├── W_HealthBar       ← 血条
│     ├── W_AmmoCount       ← 弹药数
│     ├── W_Crosshair       ← 准星
│     └── W_ExperienceBadge ← 当前玩法标识
│
├── Menu/ 或 Menus/         ← 各种菜单界面
│     ├── W_MainMenu        ← 主菜单
│     ├── W_PauseMenu       ← 暂停菜单
│     ├── W_SettingsMenu    ← 设置界面
│     └── W_GameMenu        ← 游戏内菜单（Tab 键那种）
│
├── Common/                 ← 通用控件（可复用）
│     ├── W_LyraButton      ← Lyra 风格按钮
│     ├── W_LyraTabList     ← 标签页列表
│     ├── W_InputPrompt     ← 按键提示图标
│     └── W_ListEntry       ← 列表项模板
│
├── Widgets/                ← 其他零散控件
└── ...（材质/贴图/字体等 UI 相关资源）
```

> ⚠️ 命名规律：`W_` 开头 = Widget 蓝图；`UI_` 开头的多是数据/配置类。实际以工程为准。

## 三、几类核心 UI 逐个说

### 3.1 HUD（抬头显示）—— 战斗中常驻

**是什么**：玩游戏时一直显示在屏幕上的信息（血条、弹药、准星）。

| 控件 | 显示什么 |
|------|---------|
| `W_HealthBar` | 当前血量（监听 GAS 属性变化刷新） |
| `W_AmmoCount` | 当前弹夹/备弹数 |
| `W_Crosshair` | 准星（射击时居中） |
| `W_ShooterHUD` | 把上面这些组合起来的总容器 |

> **特点**：HUD 是"被动显示"——它不主动操作，只是**监听游戏数据变化 → 刷新显示**。比如血量变了，血条自动更新。

### 3.2 菜单（Menu）—— 按需弹出

**是什么**：玩家按 ESC/Tab 弹出的界面，能暂停或半暂停游戏。

| 界面 | 作用 |
|------|------|
| `W_MainMenu` | 进游戏前的主菜单（开始/设置/退出） |
| `W_PauseMenu` | 暂停菜单（继续/设置/返回主菜单） |
| `W_SettingsMenu` | 设置（画质/音量/按键） |
| `W_GameMenu` | 游戏内的功能菜单（Tab 打开） |

> **特点**：菜单靠 CommonUI 的 **Activatable Widget（可激活窗口）** 管理——打开时压栈、关闭时出栈，支持逐层返回。详见下方"弹窗栈"。

### 3.3 通用控件（Common）—— 可复用积木

**是什么**：多个界面共用的"零件"，如按钮、列表项、按键提示。

| 控件 | 用途 |
|------|------|
| `W_LyraButton` | Lyra 统一风格的按钮（带手柄焦点、音效） |
| `W_InputPrompt` | "按 X 跳跃""按 E 拾取"这种**按键图标提示** |
| `W_ListEntry` | 列表里的一行（设置项、队伍列表项） |
| `W_TabList` | 标签页切换栏 |

> **设计思想**：把常用零件做成通用控件，改一处全局生效，不用每个界面单独做按钮。

## 四、关键机制：CommonUI 给 Lyra UI 加了什么

单纯 UMG 做不了现代游戏 UI，CommonUI 补了三个关键能力（这就是 Lyra 用它的原因）：

### 4.1 输入切换（键盘/鼠标 ↔ 手柄）

```
玩家插上手柄 → UI 自动把手提示图标换成手柄按键图标
玩家用键盘   → 自动切回键盘图标
```

`W_InputPrompt` 就是干这个的——同一个提示，根据当前输入设备显示不同图标。

### 4.2 手柄焦点导航

```
CommonUI 按钮（CommonButtonBase）
  ├─ 手柄方向键 → 焦点在按钮间移动
  └─ 按确认键   → 激活该按钮
```

不用鼠标，也能用手柄玩菜单。

### 4.3 可激活窗口栈（Activatable Widget Stack）★

这是 Lyra 菜单的核心机制：

```
按 ESC → 推入 W_PauseMenu（暂停游戏）
   └─ 点"设置" → 推入 W_SettingsMenu（叠在上面）
        └─ 按返回 → 弹出 W_SettingsMenu（回到暂停菜单）
             └─ 再按返回 → 弹出 W_PauseMenu
                  └─ 再按返回 → 继续游戏
```

像"栈"一样管理界面：**后进先出**，每层界面只管自己的开关，互不干扰。

## 五、UI 和游戏逻辑怎么连接

Lyra 的 UI **不直接写死逻辑**，而是通过两种方式获取数据：

### 5.1 监听 GameplayMessage（消息）

```cpp
// UI 订阅消息，游戏发数据过来就刷新
// 比如血量变化消息 → 血条 UI 收到后更新显示
MessageSystem->ListenForMessages(MSGKEY("HealthChanged"), ...);
```

### 5.2 读取 GAS 属性 / PlayerState

```cpp
// 血条直接绑定 ASC 的生命值属性
AbilitySystemComponent->GetNumericAttribute(ULyraHealthSet::GetHealthAttribute());
```

> **原则**：UI 只负责"显示"，不负责"计算"。数据从 GAS/消息/PlayerState 来，UI 被动刷新。

## 六、策划/技术在哪改

| 想改什么 | 去哪 |
|---------|------|
| 改血条样式 | `UI/HUD/W_HealthBar` |
| 改主菜单布局 | `UI/Menu/W_MainMenu` |
| 加一个设置项 | `W_SettingsMenu` 里加控件 |
| 改按钮外观 | `UI/Common/W_LyraButton`（全局生效） |
| 改按键提示图标 | `W_InputPrompt` |

> ⚠️ UI 多是蓝图，改布局不用编译 C++。但如果涉及新的事件/数据绑定，可能要程序加 C++ 支持。

## 七、常见误区

| 误区 | 正确理解 |
|------|---------|
| "Lyra UI 用 Slate 写的" | 主要用 **UMG + CommonUI 蓝图**，Slate 只在极少数底层 |
| "UI 里写游戏逻辑" | UI 只负责显示，逻辑在 GAS/组件里，UI 被动刷新 |
| "每个界面独立" | 靠 **Activatable Widget 栈** 管理层级和返回 |
| "W_ 开头是数据" | `W_` 开头是 **Widget 蓝图**（界面） |
| "改 UI 要重编代码" | 纯布局调整不用编译；新数据绑定才可能要 C++ |

## 八、总结速查

```
Content/UI/ = 所有界面资源（Widget 蓝图）

技术栈：UMG（基础）+ CommonUI（高级）+ 蓝图

三类界面：
  HUD（战斗中常驻）   → 血条/弹药/准星（被动显示）
  Menu（按需弹出）    → 主菜单/暂停/设置（Activatable 栈管理）
  Common（通用控件）  → 按钮/列表项/按键提示（可复用）

CommonUI 三大能力：
  ├─ 输入切换（键盘 ↔ 手柄图标自动换）
  ├─ 手柄焦点导航（方向键选按钮）
  └─ 可激活窗口栈（后进先出，逐层返回）★

连接方式：UI 被动监听 GameplayMessage / GAS 属性刷新
```

**一句话**：`UI/` 里全是 **CommonUI + UMG 做的 Widget 蓝图**——分 HUD（常驻显示）、Menu（弹窗栈管理）、Common（可复用零件）三类。Lyra 用 CommonUI 解决了**手柄导航、输入切换、界面层级**三大现代游戏 UI 痛点，UI 本身只被动显示、不写游戏逻辑。
