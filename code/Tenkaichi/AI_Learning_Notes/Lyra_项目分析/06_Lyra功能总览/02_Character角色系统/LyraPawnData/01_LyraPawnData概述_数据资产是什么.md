# 01 — `LyraPawnData` 概述：什么是"数据资产（DataAsset）"

> **定位**：`LyraPawnData` 系列的第一篇。先搞清楚它是什么、跟 `ALyraPawn` 有什么本质区别、为什么 Lyra 要用它。后续再逐篇拆解每个字段。
>
> **不讲代码**，只讲概念和"它在整个 Lyra 里扮演什么角色"。

---

## 一、一句话看懂 `ULyraPawnData`

> **`ULyraPawnData` = 一份"Pawn 的配置蓝图"。** 它不是一种 Pawn，而是"**描述一个 Pawn 该怎么造**"的数据。

注意它的类名前面是 **`U`**（不是 `A`）：

| 类型 | 是什么 | 例子 |
|------|--------|------|
| `A` 开头（如 `ALyraPawn`） | 一个**活的对象 / Actor**，能放进关卡、有生命周期 | 游戏里的角色身体 |
| `U` 开头（如 `ULyraPawnData`） | 一份**数据 / 资产**，不能放进关卡，只是"配置表" | 角色的设计图纸 |

> **类比**：
> - `ALyraPawn` = **一辆造好的车**（能开上路）。
> - `ULyraPawnData` = **这张车的配置单**（写着"用什么引擎、什么轮胎、什么摄像头"）。
> - 配置单本身不能开，但**照着它能造出一辆车**。

---

## 二、它是从哪来的？——`UPrimaryDataAsset`

看它的定义：

```
class ULyraPawnData : public UPrimaryDataAsset
```

- `UObject` → `UDataAsset` → `UPrimaryDataAsset` → `ULyraPawnData`
- **`DataAsset`（数据资产）** 是 UE 提供的一种"专门存数据的 UObject"，特点是：
  - **不可变（Const）**：运行时不该被修改，纯只读配置。
  - **可序列化**：能保存成资产文件（`.uasset`），策划能在编辑器里配。
  - **轻量**：不像 Actor 那样重，只是一坨数据。

> **关键标签**（看 UCLASS 那行）：
> - `BlueprintType` → 蓝图里能用。
> - `Const` → 运行时不可改（只读配置）。
> - `DisplayName = "Lyra Pawn Data"` → 编辑器里显示的名字。

---

## 三、它里面装了什么？（五大配置）

`ULyraPawnData` 就几个变量，但个个都是"造 Pawn 的关键参数"：

| 字段 | 类别 | 干嘛的 |
|------|------|--------|
| `PawnClass` | Pawn | **用哪个 Pawn 类来造**（比如 `ALyraCharacter`） |
| `AbilitySets` | Abilities | **给这个 Pawn 的能力集合**（GAS，一堆技能/属性） |
| `TagRelationshipMapping` | Abilities | **能力标签之间的关系映射**（比如"眩晕时不能攻击"） |
| `InputConfig` | Input | **输入配置**（按键绑定哪些动作） |
| `DefaultCameraMode` | Camera | **默认摄像机模式**（第几人称、跟随方式等） |

> **一句话**：这份资产把"**一个角色长什么样、会什么、怎么操作、镜头怎么跟**"全部**数据化**了。

---

## 四、它和 `ALyraPawn` 的关系（关键！）

这是理解 Lyra 架构的核心：

```
ULyraPawnData（配置单）          ALyraPawn（造出来的车）
   • PawnClass ─────────────►  具体造哪个 Pawn 类
   • AbilitySets ───────────►  给它装上这些能力
   • InputConfig ───────────►  给它配上输入
   • DefaultCameraMode ─────►  给它设上镜头
                                 
   数据（死的）                    对象（活的）
   编辑器里配                      运行时存在
```

**流程**：

```
① 策划在编辑器里创建一份 LyraPawnData 资产
      填入：PawnClass=某个Character、AbilitySets=[技能A,技能B]...
        ↓
② 游戏运行时，某个系统（GameMode/Spawner）读取这份资产
        ↓
③ 照着 PawnClass 造出真正的 Pawn（ALyraPawn 或其子类）
        ↓
④ 把 AbilitySets / InputConfig / CameraMode 一一应用上去
        ↓
⑤ 一个"活的、配置完整的"角色就诞生了
```

> **核心思想**：**把"造什么"和"怎么造"分离**。`LyraPawnData` 管"配置"，`ALyraPawn` 管"执行"。换一份资产，就能造出完全不同的角色（战士、法师、小兵……），而**不用改任何代码**。

---

## 五、为什么 Lyra 要这么设计？（数据驱动）

这就是游戏开发里非常重要的一个理念：**数据驱动（Data-Driven）**。

| 没有 DataAsset（老式做法） | 有 DataAsset（Lyra 做法） |
|---|---|
| 每做一个新角色，得写一个新 C++ 类 | 复制一份资产，改改数值即可 |
| 策划改个技能得找程序员 | 策划自己在编辑器里配 |
| 代码和数据耦合，难维护 | 代码只管"读数据并应用"，职责清晰 |
| 加 10 个角色 = 写 10 个类 | 加 10 个角色 = 建 10 份资产 |

> **好处**：
> 1. **策划能直接参与配置**，不用碰代码。
> 2. **扩展性极强**，加新角色零代码。
> 3. **便于平衡调整**，改数值不用重新编译。
> 4. **模块化**，同一套 Pawn 代码 + 不同资产 = 无数种角色。

## 六、`.h` vs `.cpp` 各干嘛的

### `.h`（头文件）——"配置项清单"

- 声明 `ULyraPawnData` 继承自 `UPrimaryDataAsset`。
- 列出五大配置字段（`PawnClass`、`AbilitySets` 等），每个带 `UPROPERTY` 标注（让编辑器能显示、能配）。
- 前向声明用到的类型（`APawn`、`UObject`、各种 `ULyra*`）。

### `.cpp`（源文件）——"初始化默认值"

- 只有一个构造函数，把几个指针/类字段**初始化为空（nullptr）**。
- 非常简短，因为**大部分数据是策划在编辑器里填的**，代码只需要"把变量清零，准备接收配置"。

> **对比 `ALyraPawn`**：那个 `.cpp` 很重（队伍逻辑、网络同步、回调一大堆）；而 `LyraPawnData.cpp` **几乎空的**——因为它只是个"数据容器"，不需要复杂逻辑。

---

## 七、学完这一篇，你应该记住

1. **`ULyraPawnData` 是一份"Pawn 配置蓝图"**，是数据资产（DataAsset），不是活的 Actor。
2. **`U` 开头是数据，`A` 开头是对象**——配置单 vs 造出来的车。
3. **它装五大配置**：PawnClass、AbilitySets、TagRelationshipMapping、InputConfig、DefaultCameraMode。
4. **它体现"数据驱动"思想**：造什么（数据）和执行（代码）分离，加新角色零代码。
5. **`.cpp` 几乎为空**——因为它只是数据容器，逻辑在别处（读取并应用它的系统）。


### 关键联系点

| 联系 | 说明 |
|------|------|
| **PawnClass** | 这是最直接的纽带——资产里写着"造哪个 Pawn 类"，运行时就照它 new 出真对象 |
| **其余字段** | 造出 Pawn 后，再把能力/输入/镜头从资产搬 onto 这个实例 |
| **分离原则** | 资产管"配什么"，Pawn 管"怎么执行"；换资产不换代码 |
| **多对一** | 一份资产 → 一个实例；同一套 Pawn 代码 ← 可对应无数份资产 |

### 类比

```
LyraPawnData = 菜谱（写着：用鸡胸肉、加这些调料、火候多大）
ALyraPawn    = 厨师（会做菜的这套手艺/锅铲）
运行时的成品  = 按菜谱、用厨师手艺做出的一道菜

• 换菜谱（换资产）→ 做出不同的菜（不同的角色）
• 厨师（Pawn 代码）还是那套，不用换
```
