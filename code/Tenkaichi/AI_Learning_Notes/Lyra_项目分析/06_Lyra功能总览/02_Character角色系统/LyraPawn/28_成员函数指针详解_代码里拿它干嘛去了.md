# 成员函数指针详解：`&ThisClass::OnControllerChangedTeam` 到底拿它干嘛去了？

> **定位**：回答一个具体问题——"`AddDynamic(this, &ThisClass::OnControllerChangedTeam)` 里后面那个 `&ThisClass::OnControllerChangedTeam` 是啥？代码拿它去干什么了？"。不讲虚的，就讲它在真实代码里的用途。
>
> **关联**：
> - [24_委托绑定详解_GetTeamChangedDelegateChecked与AddDynamic](./24_委托绑定详解_GetTeamChangedDelegateChecked与AddDynamic.md) — 委托绑定整体流程
> - [25_GetTeamChangedDelegateChecked与AddDynamic底层源码剖析](./25_GetTeamChangedDelegateChecked与AddDynamic底层源码剖析.md) — AddDynamic 是个宏
> - [23_Cast为什么返回指针_指针基础详解](./23_Cast为什么返回指针_指针基础详解.md) — 指针的基础概念
>
> **一句话**：`&ThisClass::OnControllerChangedTeam` 是一个"**成员函数指针**"——它不是调用函数，而是"**把那个函数的地址（门牌号）取出来交给别人保管**"，等将来某个时刻由别人回头来调用它。

---

## 一、先看它在真实代码里的位置

```cpp
// LyraPawn.cpp 第 47 行
ControllerAsTeamProvider->GetTeamChangedDelegateChecked()
    .AddDynamic(this, &ThisClass::OnControllerChangedTeam);
```

整行的意思：**"告诉系统——以后队伍变了，请回调我这个 Pawn 的 `OnControllerChangedTeam` 函数。"**

拆开两段看：

| 片段 | 作用 |
|------|------|
| `ControllerAsTeamProvider->GetTeamChangedDelegateChecked()` | ① 拿到那个"队伍变化通知器"（委托） |
| `.AddDynamic(this, &ThisClass::OnControllerChangedTeam)` | ② 往里面登记：以后有事就叫我这个对象的这个函数 |

本篇重点讲后半段的第二个参数：`&ThisClass::OnControllerChangedTeam`。

---

## 二、`&ThisClass::OnControllerChangedTeam` 是什么？——成员函数指针

它叫 **成员函数指针**（pointer to member function）。逐部分翻译：

```cpp
&ThisClass::OnControllerChangedTeam
 //    ↑            ↑
 //  哪个类      类里的哪个函数
```

| 片段 | 含义 |
|------|------|
| `OnControllerChangedTeam` | 一个**成员函数**的名字（`ALyraPawn` 里定义的那个回调函数） |
| `ThisClass::` | 指明"这个函数属于 `ThisClass` 这个类"（`ThisClass` 是 UE 给的别名，代表"当前这个类"，这里就是 `ALyraPawn`） |
| `&` | 取地址——"**把这个函数的地址拿出来**" |

### 合起来的意思

> **`&ThisClass::OnControllerChangedTeam` = "我（ALyraPawn）那个 `OnControllerChangedTeam` 函数的门牌号"**

**关键**：它**不是"调用"这个函数**（没有括号、不执行），而是**把这个函数的地址交给别人保管**。

---

## 三、代码拿它干嘛去了？——理解委托的本质

普通调用函数是这样（立刻执行）：

```cpp
OnControllerChangedTeam(a, b, c);   // ← 加括号，现在就调用，马上执行
```

但委托要的是：**"先别执行，先把'该调谁'记下来，等将来某个时刻再执行。"**

所以不能直接传"调用的结果"，得传"**指向那个函数的指针**"——这就是 `&` 的作用：

```cpp
// 不是"现在就调用它"，而是"把这个函数的地址交给你保管"
AddDynamic(this, &ThisClass::OnControllerChangedTeam);
```

**它拿这个函数指针去干的事**：把它存进委托内部的"联系人名单"里。等将来队伍真的变了，委托会拿着这个地址，回头来调用 `OnControllerChangedTeam`。

> **类比**：
> 你把一张写着"火灾时打这个电话"的号码条（函数指针）塞进消防箱（委托）。
> 平时它躺在那不动（不执行），**只有火灾发生（事件触发）时**，消防箱才拿出这张号码条来拨打（调用）。

---

## 四、`this` 又是干嘛的？（配合着一起看才完整）

```cpp
AddDynamic(this, &ThisClass::OnControllerChangedTeam);
//         ↑                    ↑
//     哪个对象           那个对象的哪个函数
```

- `&ThisClass::OnControllerChangedTeam` = 函数的门牌号（什么活）
- `this` = **具体是哪个实例**（哪个 Pawn，谁来干）

因为 `OnControllerChangedTeam` 是**成员函数**，它必须依附于某个具体对象才能调用。光有函数地址不够，还得知道"这是谁的函数"。

> **类比**：
> - `&ThisClass::OnControllerChangedTeam` = "某个工作岗位的职责说明"（什么活）
> - `this` = "具体是哪个员工"（谁来干）
> - 两者合起来 = "安排**这个员工**去干**这份活**"

## 五、宏展开后你就全懂了（串起上一篇）

还记得第 27 篇讲的吗？`AddDynamic` 是个宏。它把你写的两个参数，自动补上第三个隐藏参数（函数名字符串），展开后大致是：

```cpp
// 你写的：
AddDynamic(this, &ThisClass::OnControllerChangedTeam);

// 宏展开后 ≈ ：
__Internal_AddDynamic(
    this,                                              // ① 对象（哪个员工）
    &ThisClass::OnControllerChangedTeam,               // ② 函数地址（干什么活）
    STATIC_FUNCTION_FNAME(TEXT("OnControllerChangedTeam"))  // ③ 函数名字符串（调试/反射用）
);
```

**第三个隐藏参数**是宏帮你自动补的"函数名字符串"——用于 UE 的反射和调试（比如蓝图里能看到函数名、报错时能定位）。这也解释了为什么 UE 要用宏包一层：省你打字，还顺带塞进名字字符串。


## 七、常见误区

| 误区 | 正确理解 |
|------|---------|
| "`&xxx` 就是调用 xxx 函数" | ❌ 加 `&` 是取地址、**不执行**；调用要去掉 `&` 并加括号 |
| "只要函数地址就够了，不用传 this" | ❌ 成员函数必须依附对象，`this` 指明"谁的函数" |
| "函数指针和普通指针一样" | ⚠️ 类似，但它指向的是"某个类的成员函数"，比普通指针更特殊 |
| "AddDynamic 会立刻触发回调" | ❌ 只是**登记**，等事件发生才回调 |

## 八、总结

```
Q：&ThisClass::OnControllerChangedTeam 拿它干嘛去了？

A：它是一个"成员函数指针"= 那个函数的门牌号。
   代码拿它去做的事：
     → 把它（连同 this）存进委托的"联系人名单"
     → 等将来队伍变化事件发生时，委托拿着这个地址回头调用它

三个关键点：
  1. & 开头 = 取函数地址，不执行（区别于调用）
  2. ThisClass:: 指明是哪个类的成员函数
  3. 必须配 this 一起用：函数指针=干什么活，this=谁来干

宏 AddDynamic 还会自动补第三个参数（函数名字符串）用于反射/调试。
```

**一句话**：`&ThisClass::OnControllerChangedTeam` 就是"**我这个 Pawn 的 `OnControllerChangedTeam` 函数的门牌号**"，代码拿它去"**登记到委托的联系人名单里，等队伍变化时按这个门牌号上门回调**"——它不是调用，而是"预约一次将来的调用"。
