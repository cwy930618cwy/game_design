# 10 — 接口继承接口详解

> **定位**：解释"**接口继承接口**"——`ILyraTeamAgentInterface : public IGenericTeamAgentInterface` 这种写法，以及继承后有什么效果。
>
> **一句话**：**接口也能继承接口**，子接口**自动拥有父接口的所有方法**（就像类继承类）。子接口只需新增自己的方法，父接口的方法直接继承来用。

---

## 一、先看真实的三层继承链

```cpp
// 第 1 层：引擎提供的通用队伍接口（Plugins/Runtime/GenericTeam）
class IGenericTeamAgentInterface {
    // ★ 注意：这些方法【有默认实现】（大括号里有内容）
    virtual void SetGenericTeamId(FGenericTeamId NewTeamID) {
        // 引擎写好的默认逻辑
    }
    virtual FGenericTeamId GetGenericTeamId() const {
        return FGenericTeamId::NoTeam;   // 默认返回"无队伍"
    }
};

// 第 2 层：Lyra 的接口，继承引擎的
class ILyraTeamAgentInterface : public IGenericTeamAgentInterface {
    // Lyra 新增的一个方法（引擎没有的）
    virtual FOnLyraTeamIndexChangedDelegate* GetOnTeamIndexChangedDelegate() {
        return nullptr;   // 默认返回空
    }
};
```

**这就是"接口继承接口"**：`ILyraTeamAgentInterface` **继承了** `IGenericTeamAgentInterface`。

---

## 二、关键观察：`ILyraTeamAgentInterface` **没有重新声明**父接口的方法

看清楚——`ILyraTeamAgentInterface` 里**只新增了** `GetOnTeamIndexChangedDelegate`，**根本没提** `SetGenericTeamId` / `GetGenericTeamId`。

那这两个方法从哪来？**从父接口 `IGenericTeamAgentInterface` 自动继承来的！**

```
IGenericTeamAgentInterface（父）
    ├─ SetGenericTeamId()    ← 有默认实现
    └─ GetGenericTeamId()    ← 有默认实现
         │
         │  继承（儿子自动拥有父亲的一切）
         ▼
ILyraTeamAgentInterface（子）
    ├─ SetGenericTeamId()    ← 从父亲那继承来的，没改，直接用
    ├─ GetGenericTeamId()    ← 从父亲那继承来的，没改，直接用
    └─ GetOnTeamIndexChangedDelegate()  ← 自己新增的
```

> **类比**：爸爸会做饭和修车，儿子天生就会这两样（遗传）。儿子又额外学了烘焙。你要儿子做饭——他直接做（用爸爸教的），不用重新发明。

---

## 三、接口继承接口 = "能力叠加"

**接口继承接口的本质**：子接口 = 父接口的能力 + 自己新增的能力。

```
IGenericTeamAgentInterface（父）
  └─ 能力：SetGenericTeamId / GetGenericTeamId（队伍基础能力）

ILyraTeamAgentInterface（子）继承父
  └─ 拥有父的全部：SetGenericTeamId / GetGenericTeamId（自动继承）
  └─ 新增自己的：GetOnTeamIndexChangedDelegate（Lyra 加的能力）
```

**最终效果**：`ILyraTeamAgentInterface` 拥有了**三个方法**（2 个继承 + 1 个新增）。

---

## 四、为什么接口要继承接口？（配场景）

**场景：Lyra 想扩展引擎的队伍接口**

引擎有个 `IGenericTeamAgentInterface`（通用队伍能力）：
```cpp
class IGenericTeamAgentInterface {
    virtual void SetGenericTeamId(...) {...}   // 设置队伍
    virtual FGenericTeamId GetGenericTeamId() {...}  // 获取队伍
};
```

Lyra 想加一个"队伍变化时通知"的功能，但**不想改引擎的接口**。怎么办？

**答案：继承它，新增一个方法**：
```cpp
class ILyraTeamAgentInterface : public IGenericTeamAgentInterface {
    virtual FOnLyraTeamIndexChangedDelegate* GetOnTeamIndexChangedDelegate() { ... }
    // ↑ 新增的队伍通知能力
};
```

**好处**：
1. **不改引擎**（继承不是修改）
2. **复用父能力**（队伍基础能力自动继承）
3. **扩展新能力**（新增自己的方法）

---

## 五、接口继承接口 vs 类继承类（对比）

其实**完全一样**——接口也是类，继承规则相同：

| | 类继承类 | 接口继承接口 |
|---|---|---|
| 语法 | `class A : public B` | `class IA : public IB` |
| 效果 | 子类拥有父类成员 | 子接口拥有父接口方法 |
| 复用 | 继承父代码 | 继承父方法声明 |

```cpp
// 类继承类：Dog 继承 Animal，拥有 Animal 的方法
class Animal { void eat() {} };
class Dog : public Animal { };   // Dog 会自动 eat()

// 接口继承接口：ILyra 继承 IGeneric，拥有其方法
class IGenericTeamAgentInterface { void GetGenericTeamId() {} };
class ILyraTeamAgentInterface : public IGenericTeamAgentInterface { };
// ILyra 会自动 GetGenericTeamId()
```

## 六、多层接口继承（可以一直往上继承）

接口可以**多层继承**，能力一层层累加：

```
IGenericTeamAgentInterface（最底层：队伍基础）
  └─ ILyraTeamAgentInterface（加：队伍通知）
       └─ 实际的角色类（如 ALyraCharacter）
            └─ 实现了所有队伍能力
```

**实际类只要实现最底层，就拥有所有层的能力**（或继承中间层的默认实现）。

---

## 七、总结速查

```
接口继承接口：
  class ILyra : public IGeneric {}
  → ILyra 自动拥有 IGeneric 的所有方法

效果：
  子接口 = 父接口能力 + 自己新增能力
  ILyra = SetGenericTeamId（继承）+ GetGenericTeamId（继承）+ GetOnTeamIndexChangedDelegate（新增）

为什么用：
  不改引擎（继承不是修改）
  复用父能力（自动继承）
  扩展新能力（新增方法）

和类继承一样：
  接口也是类，继承规则相同
```

**一句话**：**接口继承接口 = 子接口自动拥有父接口的所有方法**，子接口只新增自己的方法。`ILyraTeamAgentInterface` 继承 `IGenericTeamAgentInterface`，所以它拥有"队伍基础能力"（继承）+ "队伍通知能力"（新增）。**这样 Lyra 能扩展引擎接口，又不改引擎。**
