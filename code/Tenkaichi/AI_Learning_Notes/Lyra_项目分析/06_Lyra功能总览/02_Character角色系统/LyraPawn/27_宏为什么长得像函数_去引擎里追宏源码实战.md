# 宏为什么长得像函数？+ 去引擎里追宏源码的实战方法

> **定位**：回答两个具体问题——① **"宏怎么看像方法/函数？"** ② **"它的源码在哪，怎么知道它怎么展开？"**。上一篇（第 26 篇）讲了"宏是什么"，这一篇教你"宏看着像函数时别被骗，以及怎么亲手扒开它"。
>
> **关联**：
> - [26_宏Macro详解_从define到UE委托宏](./26_宏Macro详解_从define到UE委托宏.md) — 宏的根本定义
> - [25_GetTeamChangedDelegateChecked与AddDynamic底层源码剖析](./25_GetTeamChangedDelegateChecked与AddDynamic底层源码剖析.md) — 那个委托宏从哪来
>
> **一句话**：宏看着像函数，是因为 UE 故意用"函数调用"的写法让你传参；但它不是函数——**函数算出一个值，宏变出一段代码**。想看它到底变了什么，就去引擎头文件里找 `#define`，或用 IDE 的"展开宏"功能。

## 一、你的感觉没错：委托宏确实长得像函数

看这一段（就是第 26 篇里你看不懂的那行）：

```cpp
DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(   // ← 像个函数名
    FOnLyraTeamIndexChangedDelegate,               // ← 像参数
    UObject*, ObjectChangingTeam,
    int32, OldTeamID,
    int32, NewTeamID);                             // ← 结尾分号也像函数调用
```

**它和函数调用的"外壳"几乎一模一样**：名字 + 括号 + 逗号分隔的参数 + 分号。所以你觉得"这不像宏，倒像函数"——这个直觉是对的。

### 但它和函数有本质区别

| | 函数调用 `Foo(a, b)` | 宏调用 `DECLARE_...(a, b)` |
|---|---|---|
| 谁处理它 | **编译器**在运行时执行 | **预处理器**在编译前替换文字 |
| 有没有返回值 | 有返回类型 | ❌ 没有，它"变出代码"而非"算出结果" |
| 参数会被算几次 | 算一次 | 可能被替换**多次**（坑！） |
| 展开后变成什么 | 还是那行调用 | **变成一大堆完全不同的代码** |
| 有没有类型检查 | ✅ 有 | ❌ 纯文字替换，不检查类型 |

> **记忆口诀**：**函数是"算出一个值"，宏是"变出一段代码"**。
> 委托宏看着像函数调用，是因为 UE 故意用"函数式"的写法让你传参数；但它背后干的是"生成一个类"的事，跟"计算"毫无关系。

### 怎么一眼分辨"这是宏还是函数"？

**看命名**——几乎可以肯定是宏的名字特征：
- **全大写下划线开头**：`DECLARE_XXX`、`UCLASS`、`UPROPERTY`、`GENERATED_BODY`、`check()`、`ensure()`……
- 普通函数不会这么命名（C++ 惯例函数名小写开头）。

> 看到 `全大写_下划线(` 这种组合，先默认它是宏，就不会被"像函数"的外表骗到。

## 二、宏的源码到底在哪？（真实位置）

先给结论：

> **委托宏的"源码"分两层。**
> 1. **宏本身的定义**（那一行 `#define DECLARE_... `）——**真的存在于引擎头文件里，能直接找到**。
> 2. **宏展开后生成的那个类**——**不存在于任何源文件里**！它是预处理器**临时拼出来的**，编译完就没了。所以你永远搜不到"那个类的 .cpp"。

### 真实文件位置

```
C:\Program Files\Epic Games\UE_5.6\Engine\Source\Runtime\Core\Public\Delegates\
├── DelegateCombinations.h   ← DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams 在这（第 71 行）
└── Delegate.h               ← FUNC_DECLARE_DYNAMIC_MULTICAST_DELEGATE 在这（第 296 行）
```

## 三、手把手追宏：它是"套娃"的，要追两层

宏很少一层到位，往往是"宏调用宏"。我们一层层追。

### 第一层（`DelegateCombinations.h` 第 71 行，真实源码）

```cpp
#define DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(
    DelegateName, Param1Type, Param1Name, Param2Type, Param2Name, Param3Type, Param3Name)
    BODY_MACRO_COMBINE(CURRENT_FILE_ID,_,__LINE__,_DELEGATE)
    FUNC_DECLARE_DYNAMIC_MULTICAST_DELEGATE(
        DelegateName,
        DelegateName##_DelegateWrapper,                                   // 用 ## 拼出一个 wrapper 函数名
        FUNC_CONCAT(Param1Type InParam1, Param2Type InParam2, Param3Type InParam3),   // 拼参数列表
        FUNC_CONCAT(*this, InParam1, InParam2, InParam3),                              // 拼调用实参
        void, Param1Type, Param2Type, Param3Type)
```

注意这里又出现了新宏：`FUNC_DECLARE_DYNAMIC_MULTICAST_DELEGATE`、`BODY_MACRO_COMBINE`、`FUNC_CONCAT`、`##`。别慌，继续追第二层。

### 第二层（`Delegate.h` 第 296~316 行，真实源码）—— 这才是真正"变出类"的地方

```cpp
/** Declare user's dynamic multi-cast delegate, with wrapper proxy method for executing the delegate */
#define FUNC_DECLARE_DYNAMIC_MULTICAST_DELEGATE(DynamicMulticastDelegateClassName, ExecFunction, FuncParamList, FuncParamPassThru, ...) \
class DynamicMulticastDelegateClassName : public TBaseDynamicMulticastDelegate<FNotThreadSafeDelegateMode, __VA_ARGS__> \
	{ \
	public: \
		/** Default constructor */ \
		DynamicMulticastDelegateClassName() \
		{ \
		} \
		\
		/** Construction from an FMulticastScriptDelegate must be explicit. */ \
		explicit DynamicMulticastDelegateClassName( const TMulticastScriptDelegate<>& InMulticastScriptDelegate ) \
			: TBaseDynamicMulticastDelegate<FNotThreadSafeDelegateMode, __VA_ARGS__>( InMulticastScriptDelegate ) \
		{ \
		} \
		\
		/** Broadcasts this delegate to all bound objects */ \
		void Broadcast( FuncParamList ) const \
		{ \
			ExecFunction( FuncParamPassThru ); \
		} \
	};
```

**去掉换行符 `\` 和注释后，它的骨架其实极简**：

```cpp
#define FUNC_DECLARE_DYNAMIC_MULTICAST_DELEGATE(ClassName, ExecFunction, FuncParamList, FuncParamPassThru, ...) \
class ClassName : public TBaseDynamicMulticastDelegate<..., __VA_ARGS__> {   \
public:                                                                     \
    ClassName() {}                                                          \
    void Broadcast( FuncParamList ) const { ExecFunction( FuncParamPassThru ); } \
};
```

### 把两层合起来 = 你写的那一行最终变成了什么

```cpp
// 你写的（看起来像函数调用）：
DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(FOnLyraTeamIndexChangedDelegate, UObject*, X, int32, Y, int32, Z)

// 展开后 ≈ 一个货真价实的类：
class FOnLyraTeamIndexChangedDelegate
    : public TBaseDynamicMulticastDelegate<FNotThreadSafeDelegateMode, void, UObject*, int32, int32>
{
public:
    FOnLyraTeamIndexChangedDelegate() {}
    explicit FOnLyraTeamIndexChangedDelegate(const TMulticastScriptDelegate<>& In)
        : TBaseDynamicMulticastDelegate<...>(In) {}
    void Broadcast(UObject* InParam1, int32 InParam2, int32 InParam3) const {
        FOnLyraTeamIndexChangedDelegate_DelegateWrapper(*this, InParam1, InParam2, InParam3);
    }
};
```

**看到了吗？** 那个"像方法"的宏调用，展开后就是一个**货真价实的 class**——有基类、有构造函数、有 `Broadcast` 方法。这就是为什么说"它看着像函数，其实是变出一个类"。

## 四、几个帮你看懂宏的"零件"（第一次见很正常）

追宏时会反复遇到这几个东西，认识它们就顺畅了：

| 零件 | 是什么 | 例子 |
|------|--------|------|
| `\`（行尾反斜杠） | 宏的"换行续行符"，表示下一行还是同一句宏 | `#define A x \` 然后换行 `y` → A = x y |
| `##` | **拼接符**，把两边粘成一个词 | `DelegateName##_Wrapper` → `FOnLyra..._Wrapper` |
| `__VA_ARGS__` | "可变参数占位符"，把剩下的参数全塞进来 | `...` 收多少传多少 |
| `FUNC_CONCAT(...)` | 再套一层宏做拼接（UE 为了兼容某些编译器） | 本质还是拼接 |

> **记忆**：`\` = 换行不断句；`##` = 粘词；`__VA_ARGS__` = 剩余参数打包。

## 五、三种"查宏怎么展开"的方法（实战，推荐程度排序）

| 方法 | 怎么做 | 适合场景 | 推荐度 |
|------|--------|---------|--------|
| **① 全局搜宏名** | 在引擎源码里搜 `#define 宏名` | 想知道宏的定义本身长啥样 | ★★★ |
| **② IDE 展开宏** | VS/Rider 里右键该宏 → "展开宏 / Expand Macro" | 想直接看完整展开结果（**最直观**） | ★★★★★ |
| **③ 编译预处理输出** | MSVC 加 `/E`，或 Clang 加 `-E`，导出预处理后的 `.i` 文件 | 终极手段，能看到整个文件所有宏展开后的纯 C++ | ★★★★ |

### 重点推荐方法②：IDE 一键展开

日常读源码用这个最快——
- **Rider**：选中 `DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(...)` 那行 → 右键 → **Expand Macros**（或快捷键）。
- **Visual Studio**：菜单 **View → Visual Assist → Expand Macro(s)**（需装 VAssistX），或直接看预处理输出。

它会直接把"那一行神秘宏"渲染成展开后的完整类，**一目了然，不用你手动追套娃**。

## 六、常见误区

| 误区 | 正确理解 |
|------|---------|
| "宏看着像函数，它就是函数" | ❌ 函数算值、有类型检查；宏是编译前的文字替换，无类型 |
| "宏展开后的类 somewhere 有个 .cpp" | ❌ 那个类是**临时拼出来的**，不存在独立源文件 |
| "宏太复杂看不懂，别学了" | ⚠️ UE 重度依赖宏；掌握"追宏三步法"后，唬人的宏都能拆 |
| "展开宏会破坏代码" | ❌ 只是展示，不改动你的源码 |

## 七、总结

```
Q1：宏为什么长得像函数？
    → 委托宏故意写成"函数调用"的样子让你传参（名字+括号+逗号+分号）
    → 但本质不同：函数 = 算出一个值；宏 = 变出一段代码
    → 辨别口诀：全大写下划线开头（DECLARE_ / UCLASS / check）≈ 宏

Q2：源码在哪？怎么知道怎么展开？
    → 宏定义真实位置：
        Engine/.../Delegates/DelegateCombinations.h（第 71 行）
        Engine/.../Delegates/Delegate.h（第 296 行）
    → 宏是"套娃"：DECLARE_... → FUNC_DECLARE_... → 拼出一个 class
    → 展开后就是真实的 class（有基类、构造、Broadcast 方法）

    三种查法：
      ① 全局搜 #define 宏名
      ② IDE 右键"展开宏"（最直观，强烈推荐）
      ③ 编译器 /E 输出预处理文件（终极手段）

记住：宏的"图纸"藏在引擎头文件的 #define 里；
      用 IDE 的"展开宏"功能，能直接看到它拼出来的真身。
```

**一句话**：宏看着像函数是因为 UE 用"函数式写法"传参，但它背后是**文本拼接出一个类**；这个类的"图纸"就藏在引擎那两个头文件的 `#define` 里——**追宏就像追套娃，一层层 `#define` 下去，终点一定是一个普通的 class**。
