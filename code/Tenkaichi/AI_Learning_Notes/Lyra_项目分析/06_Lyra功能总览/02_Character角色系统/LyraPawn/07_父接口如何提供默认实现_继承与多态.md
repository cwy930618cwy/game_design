# 父接口如何"帮"子接口实现？—— 彻底搞懂继承与多态

> **定位**：解答一个高频困惑——"为什么说父接口能提供默认实现，子接口只需要写自己新增的方法？这背后的机制是什么？" 本文用 Lyra 队伍接口的真实继承链讲透。
>
> **关联**：
> - [06_接口Interface与类Class的区别](./06_接口Interface与类Class的区别.md) — 接口 vs 类基础
> - [05_LyraTeamAgentInterface 队伍接口详解](./05_LyraTeamAgentInterface队伍接口详解.md) — 本例的真实源码
>
> **一句话**：不是"父接口帮忙子接口实现"，而是 **C++ 继承机制——儿子天然拥有父亲的一切方法**。儿子可以**直接用**父亲的方法，也可以**重写覆盖**它。这就是多态。

---

## 一、先看真实的三层继承链

```cpp
// 第 1 层：引擎提供的通用队伍接口（Plugins/Runtime/GenericTeam）
class IGenericTeamAgentInterface {
    // ★ 注意：这些方法【有默认实现】（大括号里有内容）
    virtual void SetGenericTeamId(FGenericTeamId NewTeamID) {
        // 引擎写好的默认逻辑
    }
    virtual FGenericTeamId GetGenericTeamId() const {
        return FGenericTeamId::NoTeam;   // 默认返回"无队伍"
    }
};

// 第 2 层：Lyra 的接口，继承引擎的
class ILyraTeamAgentInterface : public IGenericTeamAgentInterface {
    // Lyra 新增的一个方法（引擎没有的）
    virtual FOnLyraTeamIndexChangedDelegate* GetOnTeamIndexChangedDelegate() {
        return nullptr;   // 默认返回空
    }
};
```

### 关键观察：`ILyraTeamAgentInterface` **没有重新声明** `SetGenericTeamId`

看清楚——它**只新增了 `GetOnTeamIndexChangedDelegate`**，**根本没提** `SetGenericTeamId` / `GetGenericTeamId`。

那这两个方法从哪来？**从父接口 `IGenericTeamAgentInterface` 自动继承来的！**

```
IGenericTeamAgentInterface（父）
    ├─ SetGenericTeamId()    ← 有默认实现
    └─ GetGenericTeamId()    ← 有默认实现
         │
         │  继承（儿子自动拥有父亲的一切）
         ▼
ILyraTeamAgentInterface（子）
    ├─ SetGenericTeamId()    ← 从父亲那继承来的，没改，直接用
    ├─ GetGenericTeamId()    ← 从父亲那继承来的，没改，直接用
    └─ GetOnTeamIndexChangedDelegate()  ← 自己新增的
```

> **类比**：爸爸会做饭和修车，儿子天生就会这两样（遗传）。儿子又额外学了烘焙。你要儿子做饭——他直接做（用爸爸教的），不用重新发明。

## 二、那 LyraPawn 为什么要重写 SetGenericTeamId？

虽然 LyraPawn **可以**直接用引擎的默认实现，但 Lyra 团队**选择重写它**，因为**需要定制行为**。

看 `LyraPawn.cpp` 的真实实现：

```cpp
void ALyraPawn::SetGenericTeamId(const FGenericTeamId& NewTeamID)
{
    if (GetController() == nullptr) {
        if (HasAuthority()) {
            MyTeamID = NewTeamID;              // ← Lyra 自己的逻辑：网络权威检查
            ConditionalBroadcastTeamChanged(...);
        }
    }
    // ... 引擎的默认实现可没法做这些安全检查
}
```

**引擎的默认实现是"通用的"，但 Lyra 需要"特殊的"**（比如网络权威检查、广播变化）——所以它重写了。

## 三、正确理解："父接口帮子接口实现"这个说法错在哪

| 错误理解 | 正确理解 |
|---------|---------|
| "父接口帮子接口实现" | ❌ 不是"帮忙"，是**继承机制**——儿子天然拥有父亲的方法 |
| "子接口偷懒不写" | ❌ 子接口**根本没声明**这个方法，是**从父接口继承来的** |
| "父子是同一个东西" | ❌ 子接口**可以重写覆盖**父亲的实现，只是 Lyra 在这个例子里选择了重写 `SetGenericTeamId` |

### 核心机制：C++ 继承 + 虚函数重写

```cpp
// 父亲：有默认实现
class Father {
    virtual void Foo() { /* 默认 */ }
};

// 儿子：继承 Father
class Son : public Father {
    // Foo() 从父亲继承而来，Son 可以直接用
    // 也可以重写：
    // virtual void Foo() override { /* 自定义 */ }
};

// 用 Son 的对象调用 Foo()
Son s;
s.Foo();  // → 如果 Son 没重写，就调 Father 的；重写了就调 Son 的
```

这就是**多态（Polymorphism）**——同一个函数名，不同对象调用可能走不同的实现。

## 四、一张图看懂整个调用链

```
调用 s.Foo()
      │
      ▼
Son 有没有重写 Foo()？
      │
      ├─ 没重写 → 自动用 Father 的实现（继承来的）
      │
      └─ 重写了 → 用 Son 自己的实现
```

套到 Lyra：

```
调用 pawn->SetGenericTeamId(x)
      │
      ▼
ALyraPawn 重写了 SetGenericTeamId 吗？
      │
      ├─ 是（Lyra 的选择）→ 用 Lyra 的网络权威检查版本
      │
      └─ 如果 Lyra 没重写 → 会用引擎 IGenericTeamAgentInterface 的默认版本
```

## 五、"能用父亲的就一定要用吗？" —— 不一定

这是另一个常见疑问。答案是：**不必须，儿子可以选择重写覆盖。**

| 场景 | 做法 |
|------|------|
| 父亲的行为完全满足需求 | 直接用，不重写（省事） |
| 父亲的行为不够，需要定制 | 重写覆盖（`override`） |
| 父亲的行为完全不对 | 重写覆盖，彻底替换 |

> Lyra 的 `SetGenericTeamId` 就是第三种的典型：引擎默认版本没有网络权威检查，Lyra 需要这个检查，于是**重写覆盖**了它。

## 六、纯虚函数 vs 有默认实现的虚函数

这里还有个容易混的点，一并讲清：

| 类型 | 写法 | 含义 | 子类要写吗 |
|------|------|------|-----------|
| **纯虚函数** | `virtual void Foo() = 0;` | 只有声明，没实现 | **必须写**，否则编译报错 |
| **有默认实现的虚函数** | `virtual void Foo() { ... }` | 有声明也有默认实现 | **可选**：直接用，或重写覆盖 |

- `ILyraTeamAgentInterface::GetOnTeamIndexChangedDelegate` 返回 `nullptr` —— 是有默认实现的虚函数，子类可重写。
- 真正"逼你必须写"的是那些 `= 0` 的纯虚函数。

## 七、常见误区

| 误区 | 正确理解 |
|------|---------|
| "父接口替子接口干活" | ❌ 是继承让儿子天然拥有父亲的方法 |
| "子接口必须重写父亲的方法" | ❌ 想用就用，想覆盖才重写 |
| "重写后父亲的方法就没了" | ❌ 还在，只是被"遮盖"了，仍可用 `Super::Foo()` 调回父亲版本 |
| "多态就是多个形态" | 本质是"同一函数名，按对象实际类型走不同实现" |

---

## 八、总结速查

```
继承 = 儿子自动拥有父亲的一切方法

父亲的方法有默认实现时：
  ├─ 儿子可以直接用（不重写）
  └─ 儿子也可以重写覆盖（想要不同行为时）

调用时走哪个版本？
  └─ 看对象的"实际类型"有没有重写（多态）

纯虚函数 (= 0) vs 有默认实现的虚函数：
  ├─ = 0：必须写，否则编译报错
  └─ 有默认：可选，直接用或重写

Lyra 例子：
  IGenericTeamAgentInterface（引擎）→ SetGenericTeamId 有默认实现
  ILyraTeamAgentInterface（Lyra）→ 没重写它，直接继承
  ALyraPawn（具体类）→ 重写了 SetGenericTeamId，加网络权威检查
```

**一句话**：**继承 = 儿子自动拥有父亲的一切**。父亲的方法有默认实现，儿子可以**直接用**（不重写），也可以**重写覆盖**（想要不同行为时）。Lyra 的 `SetGenericTeamId` 就是"儿子重写了父亲的方法来做网络权威检查"的典型例子——这不是"帮忙"，而是 C++ 继承与多态的自然结果。
