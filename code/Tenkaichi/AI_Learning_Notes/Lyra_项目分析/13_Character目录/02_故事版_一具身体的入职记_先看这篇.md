## 出场人物（先认脸，别记细节）

故事里有四个角色，它们**住在同一具身体里**：

| 故事里的名字 | 真实类名 | 它是什么 |
|---|---|---|
| **统筹** | `ULyraPawnExtensionComponent` | 一个组件。管流程、管资料、管钥匙 |
| **经纪人** | `ULyraHeroComponent` | 一个组件。给身体配"手"和"眼睛" |
| **心脏** | `ULyraHealthComponent` | 一个组件。管血、管死 |
| **身体** | `ALyraCharacter` | 一个 Actor。就是这一整套东西的容器 |

还有两个"身体之外的"：

| 名字 | 真实类名 | 说明 |
|---|---|---|
| **老板** | `ALyraPlayerState` | 玩家的**能力系统（ASC）住在老板身上**，不住在身体上 |
| **简易身体** | `ALyraPawn` | 另一种更简陋的身体，和"身体"是兄弟 |

---

## 第一章：世界上有两种身体

游戏世界里有很多"能被操控的东西"。Lyra 先把它们分成两类：

- **简易身体**（`ALyraPawn`）：给的很少。它会走路、知道自己属于哪个队（红队/蓝队），就这些。
- **正式身体**（`ALyraCharacter`）：给的多一套。除了队伍，它还有**心脏（血量）**、**相机位**、而且**能借用能力系统**。

**最容易搞错的一点**：

> 正式身体**不是**简易身体的升级版。
> 它们俩是**兄弟**——各自从不同的地方继承（`AModularPawn` / `AModularCharacter`），只是都学会了一样本事："报出自己的队伍"。

所以你会看到两个文件里有**几乎一样的队伍代码**。那不是抄袭，是两个人各自学了一遍同样的技能。

> **这一章记住一句话**：身体分两种，是兄弟，不是父子。

---

## 第二章：正式身体的自述

一个正式身体被造出来（构造函数）的时候，它能给自己**缝三个器官**：

1. **统筹**（`PawnExtensionComponent`）
2. **心脏**（`HealthComponent`）
3. **相机位**（`CameraComponent`）

然后它看了看自己，发现一件事：

> **它没有手。**

也就是说：它**收不到玩家的按键**。玩家按 W、按空格、按鼠标，它一概不知道。

更让它"躺平"的是，它的代码里写着这么一句话（源码注释）：

> **"我的职责是把事件转发给身上的组件。新功能请尽量做成组件。"**

所以它不着急——反正有人会来管。

> **这一章记住一句话**：身体是个容器，自己不干活。

---

## 第三章：经纪人是从外面来的

那"手"是谁给的？是**经纪人**（`ULyraHeroComponent`）。

关键点来了：

> **经纪人不在这三个器官的名单里。**
> 它不是 C++ 身体自带的，而是在**具体角色蓝图里被手动加上去的**。

为什么这么设计？

因为"要不要有人操控"这件事，得看**具体这只角色是谁**：

- 玩家角色 → 加经纪人 → 有手有眼睛
- NPC 小兵 → 不加 → 不需要手（AI 自己驱动）

而且经纪人身上标了"我可以被放进蓝图"，所以策划/程序在蓝图里 Add 一下就有了。

经纪人负责两件事，而且只有两件：

| 它管 | 具体是 |
|---|---|
| **手** | 玩家的按键 → 送到对的人手里 |
| **眼睛** | 决定"现在该用哪个相机" |

> **这一章记住一句话**：经纪人不是身体自带的，是蓝图里选装的；它只管手和眼睛。

---

## 第四章：统筹说"都别急，排队"

身体出生后，几个组件都想干活。但**顺序不能乱**，否则会出问题（比如血量组件想连能力系统，但能力系统还没接上）。

于是**统筹**定了一套流程，四个阶段：

```
1. 我刚出生（Spawned）
2. 资料齐了（DataAvailable）
3. 资料挂载好了（DataInitialized）
4. 可以玩了（GameplayReady）
```

每个组件都得**一级一级往上爬**，还得**等别人**。

经纪人在这件事上特别"乖"——它走到第 3 级之前，必须先确认：

> **"统筹，你到 `DataInitialized` 了吗？你没到，我不敢动。"**

这是整个关系里最硬的一条规矩：

```134:134:Source/LyraGame/Character/LyraHeroComponent.cpp
		return LyraPS && Manager->HasFeatureReachedInitState(Pawn, ULyraPawnExtensionComponent::NAME_ActorFeatureName, LyraGameplayTags::InitState_DataInitialized);
```

**经纪人等着，一直等到统筹有动静**；统筹一动，经纪人立刻再试一次。

> **这一章记住一句话**：经纪人自己说了不算，它在等统筹。

---

## 第五章：开关被按下的那一刻 ★

终于，统筹走到了 `DataInitialized`。

经纪人大步走上前，一口气干了**三件事**（这是全故事最关键的一段）：

| 顺序 | 干了什么 | 用人话讲 |
|---|---|---|
| ① | 找统筹拿资料 | 拿到 `PawnData`（里面有"该绑哪些按键""默认用哪个相机"） |
| ② | **挂钥匙** | 调 `InitializeAbilitySystem(...)`，把**老板身上的能力系统**接到这具身体上 |
| ③ | **装手** | 调 `InitializePlayerInput(...)`，把按键和函数绑起来 |
| ④ | **交眼睛** | 把"我决定用哪个相机"这个能力，交给相机组件 |

**注意第 ② 步有多反直觉**：

> **"给身体接上能力系统"这件事，是经纪人做的，不是身体自己做的。**

而且这件事一做完，会有连锁反应：

```
经纪人接上能力系统
   → 统筹广播："钥匙挂好了！"
      → 身体收到消息 → 顺手把心脏也叫醒（心脏要连上能力系统才能算血）
```

与此同时身体也没闲着。它从来不主动找经纪人，它只做一件事：

> **把外界的变化（换控制器了、PlayerState 好了、输入组件来了）告诉统筹。**

至于谁关心这些变化——它不管。

> **这一章记住一句话**：经纪人按下开关，一按下去，钥匙、手、眼睛同时通；身体只负责把消息递给统筹。

---

## 第六章：玩家按键之后

现在经纪人有手了。玩家一按键，按键会走三条路：

| 玩家按了 | 走哪条路 |
|---|---|
| **能力键**（开火、开镜、冲刺…） | 经纪人**只认标签**，把标签交给能力系统 → 由能力系统决定放哪个技能 |
| **移动/视角/自动跑** | 经纪人**薄薄转发一层**：算一下方向、转给控制器，自己不判断 |
| **蹲伏键** | 经纪人只喊一声"你要不要蹲一下"，**真正判断的是身体** |

蹲伏这条特别值得看，因为能看到"分工"：

1. 经纪人：`Character->ToggleCrouch()`（我只喊一声）
2. 身体：判断"我是站着还是蹲着？**而且必须站在地上才能蹲**"
3. 身体的移动组件：调整胶囊高度
4. 引擎回调身体：`OnStartCrouch()` —— "身高改完了，依赖身高的东西自己调整"
5. 身体顺手做一件事：**给能力系统打一个标签 `Status.Crouching`**

**为什么要打标签？**

因为打上标签后，整个项目的其他部分就能用**同一句话**问"我现在在蹲吗"：

- 技能：这个技能要求"必须蹲着才能放"
- UI：蹲下时自动隐藏某块界面
- 蓝图：播蹲行动画

> **这一章记住一句话**：经纪人只转发，具体玩法在身体；身体把"状态"翻译成标签，方便所有人查询。

---

## 第七章：老板为什么这么重要

回到那个反直觉的设定：**能力系统（ASC）住在老板（`ALyraPlayerState`）身上，不在身体上。**

为什么？

因为**换个身体，能力不该丢**：

```
玩家活着 → 身体 A（身体上有心脏、相机、手）
玩家死了 → 身体 A 被销毁
玩家复活 → 新的身体 B
```

如果能力系统住在身体上，那每次死亡复活，技能、等级、装备全丢了。
住在老板身上，**身体只是临时借用**——换几具身体都无所谓。

源码注释把这句写得很直白：

```162:164:Source/LyraGame/Character/LyraHeroComponent.cpp
			// The player state holds the persistent data for this player (state that persists across deaths and multiple pawns).
			// The ability system component and attribute sets live on the player state.
```

> **这一章记住一句话**：能力跟人不跟身体，所以钥匙在老板手里。

## 第八章：简易身体的一生

那**简易身体**（`ALyraPawn`）呢？

它就像一个"精简版容器"：

- ✅ 会走路
- ✅ 知道自己是红队还是蓝队
- ❌ 没有心脏
- ❌ 没有相机
- ❌ 不借能力系统

它可以被当成"通用底子"，用在不需要完整角色能力的地方（比如载具、炮台、观战化身之类）。

而经纪人其实**不认身体的具体型号**——它只要求三件事：是个真 Pawn、有老板（PlayerState）、有统筹。

只有一处例外：**蹲伏**这条路上，经纪人会明确"只认正式身体"：

```453:453:Source/LyraGame/Character/LyraHeroComponent.cpp
	if (ALyraCharacter* Character = GetPawn<ALyraCharacter>())
```

因为"蹲"这种玩法，只有正式身体才具备。

> **这一章记住一句话**：经纪人核心逻辑通用，遇到具体玩法（如蹲）才挑身体型号。

## 三句话总结（真正的重点）

1. **身体是容器，不干活**：`ALyraCharacter` 只把事件转给统筹，功能都在组件里。
2. **经纪人是选装外设，还要排队**：它是蓝图里加的，而且必须等统筹走到某一步才敢动手——动手时它会**一次性接通能力系统、输入和相机**。
3. **能力跟人不跟身体**：所以钥匙在老板（`PlayerState`）手里，身体只是借用。
