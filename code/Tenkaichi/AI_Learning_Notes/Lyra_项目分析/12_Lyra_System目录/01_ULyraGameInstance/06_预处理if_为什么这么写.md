# 为什么这么写 `#if`？—— C++ 预处理指令详解

> **定位**：解释 `LyraGameInstance.cpp` 第 32 行 `#if UE_WITH_DTLS` 这种写法，跟 JS 的 `if` 有什么区别。
>
> **原代码**（`LyraGameInstance.cpp` 第 32-33 行）：
> ```cpp
> #if UE_WITH_DTLS
>     static bool bUseDTLSEncryption = false;
> #endif
> ```
>
> **一句话**：这个 `#if` **不是运行时的 if**，而是**编译前的"文字删减"**——编译前就把不需要的代码**物理删除**，跟 JS 的 `if`（运行时判断）根本不是一回事。

---

## 一、先破一个误解：`#if` ≠ JS 的 `if`

你写 JS 的 `if`，是这样的：

```js
if (bUseDTLSEncryption) {        // 程序【运行时】判断
    doSomething();
}
```

- 这个 `if` 在**程序跑起来之后**才判断。
- 代码**始终都在**，只是"跑不跑"由条件决定。

但 C++ 的 `#if` 完全不同：

```cpp
#if UE_WITH_DTLS                 // 这是【编译前】判断
    static bool bUseDTLSEncryption = false;
#endif
```

- 这个 `#if` 在**程序还没开始跑、还在编译阶段**就判断了。
- 条件不成立时，里面的代码**直接被删掉**（就像从没写过一样）。

> **核心区别**：
> | | JS 的 `if` | C++ 的 `#if` |
> |---|---|---|
> | 什么时候判断 | **运行时**（程序跑的时候） | **编译前**（程序还没生成） |
> | 条件不成立时 | 代码还在，只是不执行 | 代码**被物理删除**，根本不存在 |
> | 属于什么 | 程序逻辑 | **预处理**（文本处理） |

---

## 二、`#if` 到底是什么？—— 预处理指令

C++ 编译分两大步：

```
① 预处理（Preprocessing）  ← #if 在这一步！
   处理所有 # 开头的指令（#include、#if、#define...）
   本质是"文本替换/删除"
        ↓
② 编译（Compilation）
   把处理后的代码翻译成机器码
```

**`#if` 就是第 ① 步的指令**。它的工作方式：

> 编译器在编译前，先看 `#if` 后面的条件：
> - 条件为真 → **保留** `#if` 和 `#endif` 之间的代码
> - 条件为假 → **删掉** `#if` 和 `#endif` 之间的代码（当它不存在）

**关键**：这一步发生在**编译前**，是纯粹的"文本删减"，跟程序运行无关。

---

## 三、用类比彻底讲透

### 类比：考试前的"划重点"

想象你要带一本书进考场，但老师规定"有些章节不考，可以撕掉"：

- **`#if`（编译前撕页）**：考试前，你把不考的章节**直接撕掉**，带进考场的书是"精简版"。考场上根本看不到那些页。
- **JS 的 `if`（考场上决定看不看）**：书完整带进去，考场上你**看到**某题决定"这章我不看"。

> `#if` 是"**考前撕书**"——不考的内容压根不带进去。
> JS `if` 是"**考场上翻书**"——内容都在，只是临时决定读不读。

### 类比：装修时"预留线路"

- `#if`：装修时决定"这面墙要不要预埋电线"——**墙砌好前**决定，不埋就永远没有。
- JS `if`：装修好后，决定"这个灯开不开"——**灯在，随时能开**。

## 四、回到原代码：为什么 DTLS 要这么写？

```cpp
#if UE_WITH_DTLS                          // 如果引擎编译时启用了 DTLS
    static bool bUseDTLSEncryption = false;   // 才定义这个变量
    ...（一堆 DTLS 相关代码）...
#endif
```

**`UE_WITH_DTLS` 是什么？**

它是一个**宏**（macro），在引擎编译配置里定义：
- 如果你的引擎**编译时开启了 DTLS 支持** → `UE_WITH_DTLS` 有值（为真）→ DTLS 代码**保留**。
- 如果**没开启** → `UE_WITH_DTLS` 未定义（视为假）→ DTLS 代码**被删掉**。

**为什么要把 DTLS 代码包起来？**

因为 **DTLS 是可选功能**，不是所有游戏都需要。如果不用 `#if` 包起来会怎样：

```cpp
// 假设不用 #if，直接写：
#include "DTLSCertStore.h"      // ← 如果引擎没编 DTLS，这个头文件根本不存在！
static bool bUseDTLSEncryption = false;
```

- 问题：没启用 DTLS 的引擎里，`DTLSCertStore.h` 这个文件**压根不存在**。
- 结果：**编译报错**（找不到头文件）。

**用 `#if` 包起来后**：
- 没启用 DTLS → 这些代码被删掉 → 编译器根本看不到 `#include "DTLSCertStore.h"` → 不报错。
- 启用 DTLS → 代码保留 → 正常编译。

> **所以 `#if` 的核心价值**：让**同一份源码**能根据"编译配置"编译出**不同版本**——有 DTLS 的版本、没 DTLS 的版本，都从这份代码来。

## 五、C++ 预处理 `#if` 家族

`#if` 是一整套指令，常见的有：

| 指令 | 作用 | 例子 |
|------|------|------|
| `#if` | 条件为真才保留 | `#if UE_WITH_DTLS` |
| `#ifdef` | "如果定义了某宏"才保留 | `#ifdef DEBUG` |
| `#ifndef` | "如果没定义某宏"才保留 | `#ifndef HEADER_H`（防止重复包含） |
| `#elif` | 否则如果（else if） | `#elif PLATFORM_WINDOWS` |
| `#else` | 否则 | `#else ... #endif` |
| `#endif` | 结束条件块 | 必须和 `#if` 配对 |
| `#define` | 定义宏 | `#define MAX 100` |
| `#include` | 引入头文件 | `#include "Foo.h"` |

> 这些全以 `#` 开头，都叫**预处理指令**，都在编译前做"文本处理"。

## 六、对比：同一个逻辑用两种方式写

假设要写"只在调试时打印日志"：

### 用 JS 的 `if`（运行时）
```js
function log(msg) {
    if (isDebug) {              // 运行时判断
        console.log(msg);
    }
}
// log() 始终存在，isDebug 决定打不打
```

### 用 C++ 的 `#if`（编译前）
```cpp
void Log(const FString& Msg)
{
#if UE_BUILD_DEVELOPMENT       // 编译前判断
    UE_LOG(LogTemp, Log, TEXT("%s"), *Msg);
#endif
}
// 发行版编译时，UE_LOG 那行被删掉，函数体直接变空
```

**区别**：
- JS 版：`console.log` 代码**一直在**，`isDebug` 控制打不打。
- C++ 版：发行版里 `UE_LOG` 那行**根本不存在**（被删了），连"判断"这个动作都没有——省掉运行时开销。

> **为什么 C++ 要这么搞？** 因为 C++ 是编译型语言，很多优化在**编译期**做掉更高效。调试代码在发行版里"物理消失"，零运行时成本。

## 七、常见疑问速答

| 疑问 | 答案 |
|------|------|
| `#if` 和 `if` 一样吗？ | **不一样**。`#if` 是编译前删代码，`if` 是运行时判断 |
| `#if` 后面跟的是变量吗？ | 不是，是**宏**（如 `UE_WITH_DTLS`），值在编译配置里定 |
| 为什么 JS 没有这个？ | JS 是解释型、运行时动态，没有"编译前"这个阶段 |
| `#if` 删代码后程序会报错吗？ | 不会，删掉后就像从没写过，编译器看不到 |
| `#if` 和 `#ifdef` 区别？ | `#if` 判断宏的**值**；`#ifdef` 只判断宏**有没有定义** |
| 运行时代码里能看到 `#if` 吗？ | 看不到，它在编译前就处理完了，运行时早已不存在 |
| `#endif` 必须写吗？ | 必须，和 `#if` 配对，否则编译报错 |

## 八、总结

```
# 开头的 = 预处理指令，在【编译前】做文本处理，不是运行时逻辑

#if UE_WITH_DTLS 的含义：
  编译前检查 UE_WITH_DTLS 这个宏
   ├─ 为真 → 保留 #if 和 #endif 之间的代码
   └─ 为假 → 把之间的代码【物理删除】（当没写过）

和 JS if 的本质区别：
  JS if   → 运行时判断，代码一直在，只是跑不跑
  C++ #if → 编译前删减，条件假时代码根本不存在

为什么 DTLS 用 #if：
  DTLS 是可选功能，不是所有引擎都编了它。
  用 #if 包起来，同一份代码能编出"有DTLS"和"没DTLS"两个版本，
  没编 DTLS 时相关代码被删掉，不会因为找不到头文件而报错。
```

**一句话**：`#if UE_WITH_DTLS` 不是运行时的 `if`，而是**编译前的"代码删减"指令**——编译时如果没启用 DTLS，`#if` 和 `#endif` 之间的代码会被**物理删除**（当没写过），这样同一份源码能根据编译配置产出不同版本，不会因为引用不存在的 DTLS 头文件而报错。JS 没有这个概念，因为它是运行时解释、没有"编译前"阶段。
