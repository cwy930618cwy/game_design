# 一篇讲明白：P04-3 和 P04-4 到底在干嘛

> **解决什么问题**：你看 P04-3 和 P04-4 时"晕"，是因为那两篇堆了大量"Lyra 有什么、我们砍什么"的对照表，把一条简单的链淹没在细节里了。
>
> **这一篇反着来**：不讲减法、不讲 Lyra 源码对照，只用**一个故事 + 一张全景图**，把整条链捋成一条直线。看懂了这一篇，再回去看 P04-3/P04-4 就清楚了。

---

## 一、先记住一个事实：P04 所有步骤，都在搭同一条链

从你按下一个键，到角色动起来，中间要经过**四段**。P04 的 1、2、3、4 步，就是在**一段一段地把这条链搭起来**。

一句话记住这条链：

```
按下一个键  →  ① 找到对应的"动作"  →  ② 把"动作"接到"处理函数"  →  ③ 处理函数让角色动
```

对应到 UE 的名词：

```
按键(W/鼠标)  →  InputAction(动作)  →  回调函数(Input_Move)  →  AddMovementInput(真动)
```

---

## 二、用一个故事串起整条链

### 故事：一家快递公司

想象你在运营一家快递公司，顾客（玩家）下单后，包裹要经过四个岗位才送到：

| 岗位 | 干的事 | 对应 UE 里的东西 |
|------|--------|-----------------|
| **① 前台** | 顾客说"我要寄到北京"，前台把它翻译成一张**标准运单** | `InputMappingContext`（IMC）：按键 → InputAction |
| **② 调度** | 拿到运单，按"目的地"分类，决定交给哪个司机 | `InputConfig`（字典）：Tag → InputAction |
| **③ 接线员** | 打电话通知对应司机"你有一单" | `TenkaichiInputComponent`：绑定回调 |
| **④ 司机** | 真正开车送货 | 回调函数 + `AddMovementInput`：真正移动 |

**关键点：顾客按一个键，这个"信号"要依次穿过 ①②③④ 四个岗位，包裹（移动指令）才真正送到。**

P04 的四步，就是**一个岗位一个岗位地把这条流水线建起来**：

| 步骤 | 建的是哪个岗位 | 对应哪个文件/类 |
|------|---------------|----------------|
| P04-1 | ② 调度（字典） | `TenkaichiInputConfig` |
| P04-2 | ③ 接线员 | `TenkaichiInputComponent` |
| P04-3 | ④ 司机（处理函数 + 移动） | 角色类的 `Input_Move` 等 |
| P04-4 | ① 前台（把按键接到动作） | 注册 IMC 的代码 |

> **看到这你可能已经明白了：晕的原因，是这四步在文件里是「倒着」出现的——先教②③④，最后才教①（前台）。所以你在 P04-3、P04-4 之间绕来绕去，搞不清顺序。**

```

     │

     │     （P04-4 要写的：注册 IMC，让这张表生效）
     ▼
  InputAction：IA_Move（一个叫「移动」的动作）
     │
     │  ② 调度：字典说「InputTag.Move → IA_Move」
     │     （P04-1 建的：TenkaichiInputConfig 字典）
     ▼
  FGameplayTag：InputTag.Move（一个"标签"）
     │
     │  ③ 接线员：BindNativeAction 说「这个 Tag 触发时，调用 Input_Move」
     │     （P04-2 建的：TenkaichiInputComponent + P04-3 调用它）
     ▼
  回调函数：Input_Move
     │
     │  ④ 司机：AddMovementInput 让角色往前走
     │     （P04-3 写的：Input_Move 函数体）
     ▼

```

**记住读图顺序：从上往下 = 从"按键"到"角色动"的先后顺序。**

## 四、那 P04-3 和 P04-4 分别负责图里哪一段？

### P04-3 = 图的**下半段**（③④）

它写的是：**信号已经变成"Input_Move 这个动作"之后，该怎么办。**

具体两件事：
1. **接线（③）**：在 `SetupPlayerInputComponent` 里调用 `BindNativeAction`，把 `InputTag.Move` 绑到 `Input_Move` 函数上。
2. **开车（④）**：写 `Input_Move` 函数体，里面调 `AddMovementInput` 让角色动。

> P04-3 做完，链的**后半段通了**：只要有 `IA_Move` 信号进来，角色就能动。但问题是——**还没有任何东西能把"按键"变成"IA_Move 信号"**。所以角色还是不会动。

### P04-4 = 图的**最上面一段（①）**

它写的是：**怎么让"按 W 键"这个物理动作，变成"IA_Move 信号"。**

具体一件事：
1. **注册 IMC（①）**：在 `SetupPlayerInputComponent` 里，把 `DefaultInputMappingContext` 注册进输入子系统（`ClearAllMappings` + `AddMappingContext`），这样引擎才知道「W 键对应 IA_Move」。

> P04-4 做完，链的**第一段通了**：按键终于能变成动作信号。整条链就完整了。

## 五、用一句话彻底记住

> **P04-3 让"动作"能变成"移动"；P04-4 让"按键"能变成"动作"。**
>
> 一个管**链尾**（动作→移动），一个管**链头**（按键→动作）。两个合起来，按键才能真正驱动角色动。

---

## 六、为什么 P04-4 的代码写在同一个函数里？

你可能注意到，P04-3 和 P04-4 的代码**都写在 `SetupPlayerInputComponent` 这一个函数里**，所以会搞混。

其实它俩在这个函数里是**一前一后两段，各干各的**：

```cpp
void SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
    Super::SetupPlayerInputComponent(PlayerInputComponent);

    // ===== 上半段：P04-4 干的事（① 前台，让按键→动作生效）=====
    // 拿输入子系统 → ClearAllMappings → AddMappingContext(DefaultInputMappingContext, 0)

    // ===== 下半段：P04-3 干的事（③④ 接线 + 开车）=====
    // BindNativeAction(InputTag.Move, ..., &Input_Move)   ← 接线
    // BindNativeAction(InputTag.Look.Mouse, ..., &Input_LookMouse)
}
// Input_Move 函数体（④ 开车）在函数外面，P04-3 写的
```

**记住：`SetupPlayerInputComponent` 是"开机时一次性跑一遍"的地方。** 游戏启动、角色被玩家接管时，引擎自动调它一次，把整条链从头到尾装好。所以 P04-3（装链尾）和 P04-4（装链头）都在这里。

## 七、小结（一张表带走）

| 你要问 | 答案 |
|--------|------|
| P04-3 在干嘛 | 让「动作信号」能驱动「角色移动」（链尾） |
| P04-4 在干嘛 | 让「按键」能产生「动作信号」（链头） |
| 为什么角色之前不动 | 链头（按键→动作）还没接通，只有链尾 |
| 两段代码在哪 | 都写在 `SetupPlayerInputComponent`，一前一后 |
| 读完这篇回头看 | P04-3 是图下半段，P04-4 是图最上面那段 |
