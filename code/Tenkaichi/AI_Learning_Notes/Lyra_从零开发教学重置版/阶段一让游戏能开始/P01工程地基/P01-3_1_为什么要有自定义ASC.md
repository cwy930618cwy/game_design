## 二、先搞懂：为什么 Lyra 要包这一层

打开 Lyra 真实源码（`Source/LyraGame/AbilitySystem/LyraAbilitySystemComponent.h`），第 22-34 行：

```27:34:Source/LyraGame/AbilitySystem/LyraAbilitySystemComponent.h
UCLASS(MinimalAPI)
class ULyraAbilitySystemComponent : public UAbilitySystemComponent
{
	GENERATED_BODY()

public:

	UE_API ULyraAbilitySystemComponent(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

它比引擎基类多出来的东西，可以归成**四类项目规矩**：

| 类别 | Lyra 加了什么（真实函数） | 解决什么问题 |
|------|--------------------------|--------------|
| **生命周期接管** | `EndPlay`（第 37 行）、`InitAbilityActorInfo`（第 40 行） | 自己接手"角色上线/下线"的时机，顺便做 Lyra 自己的登记、通知技能"你换新身体了" |
| **激活组并发控制** | `IsActivationGroupBlocked`、`AddAbilityToActivationGroup`、`CancelActivationGroupAbilities`（第 53-56 行） | 防止两个互斥技能同时开（引擎基类不管这件事） |
| **输入 → 技能** | `AbilityInputTagPressed/Released`、`ProcessAbilityInput`、`ClearAbilityInput`（第 47-51 行） | Lyra 是 **Tag 驱动输入**，按键 → GameplayTag → 技能，这层转换写在 ASC 里 |
| **标签互斥表** | `SetTagRelationshipMapping`、`GetAdditionalActivationTagRequirements`（第 68-71 行） | 用一张数据表配"哪些技能互相打断/互相屏蔽"，数据驱动而非硬编码 |

> 类比：引擎的 `UAbilitySystemComponent` 是"**电力局的总电箱**"，只管通电；Lyra 的 `ULyraAbilitySystemComponent` 是自己装的"**总配电箱**"——加了空气开关（激活组）、贴了标签（Tag 映射）、接了智能面板（输入处理）。**我们不改电箱内部，只是在外面加自己的配电箱。**

> 一句话：**包一层的本质 = 给项目的规矩一个统一的家**，而不是把规矩散落在角色、技能、蓝图各处。

## 五、一句话结论

**引擎的 `UAbilitySystemComponent` 只管"通电"，项目的规矩（生命周期接管、激活组互斥、Tag 驱动输入、互斥表）需要一个自己的子类来装——Lyra 叫 `ULyraAbilitySystemComponent`，我们叫 `UTenkaichiAbilitySystemComponent`；而且你的 `TenkaichiAttributeSet.cpp` 已经在 include 它了，这一步不做，工程编译不过。**
