## 一、这一步要解决什么问题（先讲为什么）

上一步定好了路线 B：把「绑定 + 移动」放进角色类 `ATenkaichiCharacterWithAbilities`。

要在 `.h` 里新增三样东西，先回答「为什么」：

1. **为什么加一个 `InputConfig` 成员？**
   因为 `BindNativeAction` 需要一本字典去查「Tag → InputAction」。Lyra 里这本字典存在 `PawnData` 资产里（我们砍掉了），所以退而求其次，在角色类上直接放一个 `InputConfig` 引用，让它在编辑器里指到我们的 `DA_TenkaichiInputConfig` 资产。

2. **为什么要重写 `SetupPlayerInputComponent`？**
   这是引擎 `APawn` 的虚函数，**角色被玩家 Possess（接管）时引擎会自动调用它**。这是「接输入」的标准入口。我们在这个入口里调用 `BindNativeAction`，把回调绑上。不重写它，引擎就不知道该给你绑输入。

3. **为什么 `Input_Move` / `Input_LookMouse` 是 `protected` 成员函数，签名是 `const FInputActionValue&`？**
   因为它们是被「绑定」的回调，由 Enhanced Input 在按键触发时调用，传进来一个 `FInputActionValue`（这次输入的值，比如「W 按下的力度」或「鼠标移动的二维量」）。`protected` 是 Lyra 的习惯——只给绑定内部用，不暴露给外界。

> 类比：`SetupPlayerInputComponent` 是「开机后自动接线的那个插座」，`InputConfig` 是「插在插座上的电话本」，`Input_Move`/`Input_LookMouse` 是「电话响了之后去接电话的人」。

```cpp
// ===== 1. 顶部新增前向声明（class 声明区） =====
class UTenkaichiInputConfig;
struct FInputActionValue;

// ===== 2. public 区新增：重写输入入口 =====
public:
	// 角色被玩家接管时，引擎会自动调用，在这里把输入绑上（对应 LyraCharacter.h:162）
	virtual void SetupPlayerInputComponent(UInputComponent* PlayerInputComponent) override;

// ===== 3. protected 区新增：两个输入回调（对应 LyraHeroComponent.h:84-85） =====
protected:
	// 移动输入回调（WASD 前后左右）
	void Input_Move(const FInputActionValue& InputActionValue);

	// 鼠标转视角回调
	void Input_LookMouse(const FInputActionValue& InputActionValue);

// ===== 4. 新增成员：输入配置资产引用（路线B用编辑器直指，替代 Lyra 的 PawnData） =====
	UPROPERTY(EditDefaultsOnly, Category = "Tenkaichi|Input")
	TObjectPtr<const UTenkaichiInputConfig> InputConfig;
```

> 说明：`InputConfig` 这个成员我们放在哪（private / protected / public）？Lyra 里 PawnData 是 PawnExtension 的配置，我们简化后，把它当成「可编辑的配置」用 `EditDefaultsOnly`（只在默认值里编辑、运行时只读），跟第 1 步字典里的 `NativeInputActions` 一个待遇。

## 五、逐段回扣「为什么这么写」

| 代码 | 为什么 |
|------|--------|
| `class UTenkaichiInputConfig;` | 前向声明，`.h` 里只用指针，不必 include 完整定义（加快编译） |
| `struct FInputActionValue;` | 同上，回调参数用引用，前向声明即可 |
| `virtual void SetupPlayerInputComponent(UInputComponent* PlayerInputComponent) override;` | 重写引擎 `APawn` 的虚函数；`override` 表示「覆盖基类」，编译器会帮你检查签名对不对 |
| `void Input_Move(const FInputActionValue& InputActionValue);` | 回调签名一比一照抄 Lyra；`const &` 避免拷贝输入值 |
| `void Input_LookMouse(const FInputActionValue& InputActionValue);` | 同上 |
| `UPROPERTY(EditDefaultsOnly, Category = "Tenkaichi\|Input")` | 让 `InputConfig` 能在编辑器蓝图默认值里指到 `DA_TenkaichiInputConfig` 资产 |
| `TObjectPtr<const UTenkaichiInputConfig> InputConfig;` | UE5 智能指针 + `const`（只读配置） |

## 六、这一步没教过的新方法（先扫一遍）

- **`SetupPlayerInputComponent(UInputComponent*)`**：引擎 `APawn` 的虚函数，角色被 Possess 时自动调用，是「接输入」的标准入口。**重点新方法**。
- **`FInputActionValue`**：Enhanced Input 的「输入值」类型，按键触发时把值传给回调。`.Get<FVector2D>()` 能取出二维向量（移动的 XY、鼠标的 XY）。
- **`override`**：C++ 关键字，表示「覆盖基类虚函数」，写错签名编译器会报错（比裸 `virtual` 更安全）。

> 其余（`TObjectPtr`、前向声明 `class Xxx;`）都在 P04-1b / P04-2c 讲过了。
