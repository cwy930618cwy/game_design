# 09 — 通用复刻流程：给一个项目路径就能开工

> **定位**：把 `00`~`08` 九份经验**去项目化**，提炼成一套「**给源路径 → 一比一复刻 → 建 md**」的通用流程。
> **适用**：任何「照着权威源码，在另一个目录里一比一还原同名文件」的任务（引擎 / 框架 / SDK / 大型开源库）。
> **不适用**：从零写新代码、重构、改 bug —— 那是另一套流程。
> **一句话**：**只读权威源，只换根不改名，代码零差异，注释全中文，一轮两件套，推进前先验收。**

---

## 一、开工前必须问清的 4 个路径（缺一不可）

| 代号 | 含义 | 举例（当前实例） |
|---|---|---|
| `<源根>` | **唯一权威来源**，只读不改 | `D:\ue5\Epic Games\UE_5.4` |
| `<还原根>` | 还原代码落点，**只放代码，不放 md** | `E:\ue5\game_design\code\Tenkaichi`（本项目） |
| `<讲义根>` | 教学 md 落点，**只放 md，不放代码** | `E:\ue5\game_design\code\Tenkaichi\AI_Learning_Notes` |
| `<经验根>` | 经验 / 铁律 md 落点（与讲义根同目录，经验 md 直接放根下） | `E:\ue5\game_design\code\Tenkaichi\AI_Learning_Notes` |

**映射规则（唯一一条）**：

```
<源根>\<相对路径>  →  <还原根>\<相对路径>
```

**只换根，其余层级、目录名、文件名、大小写、下划线，一字不动。**

> ⚠️ 三个目录**绝不交叉**：还原根里出现 `.md` = 放错了；讲义根里出现源码 = 放错了。

## 二、五条铁律（违反任何一条 = 返工）

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **零改名** | 类名 / 文件名 / 目录名 / 宏 / API 全部保持源项目原名。不做前缀替换、不砍后缀、不改大小写 |
| 2 | **一比一** | 目录树、文件归属、代码逻辑、字段与值全部一致。不删不跳、不简化、不自己加代码、不发明源项目没有的东西 |
| 3 | **唯一例外 = 注释** | 注释全量译成中文；每个方法 / 成员变量**正上方**补中文注释；交付前逐行扫描（构造函数最容易漏） |
| 4 | **代码块 = 交付物** | 干净可照抄：零英文注释、零 `// ← 改成XXX` 行内提示、零空注释占位、零教学噪声 |
| 5 | **先查后教** | 只认 `<源根>` 的真实文件，每个符号都能指出 `文件:行号`；找不到就说「未找到源码依据」，**绝不编** |

**必须原样保留的源项目细节**（不许「修正」）：

| 项 | 例子 |
|---|---|
| 源项目错字 | `plVatform` / `VisibileForDll` / `CreateModulRules` |
| 特殊空白 | Tab 空行、空格缩进的 `{`、行尾多余空格 |
| 重复项 | 同一 include / 同一宏重复出现，**不许去重** |
| 被注释掉的代码 | `// Target.Platform != ...` 原样保留 |
| 字符串字面量 | `TEXT("...")` / `[Obsolete("...")]` / `UE_LOG` 消息 —— **不翻译**（运行时输出 / API 契约） |

## 三、推进顺序：按源项目真实目录自上而下

```
① 建总纲 md（全景清单：哪些目录、多少文件、按什么顺序）
② 逐层建「层总 md」（Engine\ → Engine\Source\ → Runtime\Core\ → Public\ …）
③ 进到叶子目录后，按文件名排序逐个文件做「两件套」
```

**不按依赖链、不按重要性、不跳「不影响编译」的文件。** 读一个建一个。

---

## 四、每个文件 = 一轮两件套（★ AI 只教不写）

收到「下一步 / 继续 / 教 `<文件名>`」时，**同一轮内**依次产出：

| # | 产物 | 路径 | 规模参考 |
|---|---|---|---|
| ① | **总 md** | `<讲义根>\<阶段>\NN_<文件名>_总md.md` | 3~5KB / 85 行内 |
| ② | **复制文件 md** | `<讲义根>\<阶段>\NN_<文件名>复制文件.md` | 完整代码 + 每行上方中文注释 |

**没有第三件。代码由用户自己敲，AI 绝不往 `<还原根>` 写任何代码文件。**

> ⚠️ **AI 代写代码 = 最严重违规**。用户原话：「教学只教 我来写」「怎么又帮我写啊！！！！！！！！！！我要疯了」。
> ⚠️ 建完总 md 就停 = 违规。总 md 只是两件套第一件，不是交付点。
> ⚠️ **不建 `答疑文件\` 子目录**，两件套全部平铺在阶段目录下。
> ⚠️ **注释必须独占一行、写在代码正上方**，严禁行尾注释。

## 五、总 md 骨架（4 段，不许加）

```markdown
# NN — `<相对路径>/<文件名>` —— 总 md

> 依据：`<源根>\<相对路径>\<文件名>`（**N 行**）
> 你新建文件：`<还原根>\<相对路径>\<文件名>`
> **✅ 本节可独立编译** / **⚠️ 本节不能独立编译**——依赖 xxx

---

## 一、这个文件解决什么问题（为什么）
   —— 场景故事 + 核心设计 ①②③ + 🔑 一句话比喻

## 二、内部结构全景
   —— 树形图（├─ └─），把成员/方法全列出来 + 行号区间

## 三、依赖分析
   —— 表格：文件 | 依赖工程内类？ | 能否独立编译 | 需挂起？
   —— 关键依赖表：文件 | 作用

## 四、怎么教（推进节奏）
   —— 本轮两件套说明

---

**下一步**：按文件名顺序，下一个是 xxx（N 字节）
```

**禁止**：总 md 里塞逐行大表格；总 md 用 mermaid（用树形图）。

## 六、复制文件 md 骨架（★ 注释写在代码上方）

```markdown
# NN — `<文件名>` 复制文件

> 依据：`<源根>\...`（**N 行**）
> 你新建文件：`<还原根>\...`
> **用法**：照着下面代码逐行敲。**注释在每行上方，敲的时候整行 `//` 注释都不要抄**。

```<语言>
// 中文注释（独占一行，在被注释代码正上方）
<代码行>
// 中文注释
<代码行>
```

## 敲完自查
| 检查项 | 通过标准 |

## 源码依据
```

**注释密度**：每行代码上方都有注释，讲清 4 件事 —— 干什么 / 类型从哪来 / 为什么这么写 / 真实文件在哪。

**注释位置（★ 血泪）**：

```cpp
// ✅ 正确：注释独占一行，写在代码正上方
// 模块名；引擎据此去 Source\LyraGame\ 找 LyraGame.Build.cs
"Name": "LyraGame",

// ❌ 错误：注释写在行尾（一律返工）
"Name": "LyraGame",                 // 模块名
```

**就地教**：每段代码后**立刻**列「本段新元素」，**不许攒到末尾统一列**；一行一个；只列首次出现的；禁止四行表格。

## 七、验收：推进前必做（最高优先级）

收到「下一步」→ **第一件事是验收上一份**，不是直接开工。

### 7.1 硬动作

1. 定位当前这一步对应的源文件 + 用户写的还原文件
2. **同时读两份**（不许凭记忆、不许拿自己的讲义当基准）
3. 逐行比对 6 项
4. 回复里明确报结论
5. **全对才推进**；不通过 → 列差异让用户改，本轮不推进

### 7.2 判定表（6 项）

| 检查项 | 通过标准 |
|---|---|
| 路径 / 名字 | 与源项目同名同层级，零改名、零后缀变化 |
| 代码行 | 与源项目**逐字一致**（含缩进、空格、括号位置）；不删不跳、不多不少 |
| 注释中文化 | 原注释译中文；类/方法/成员变量正上方补中文注释；**零英文注释** |
| **注释位置** | **全部独占一行、写在代码正上方**；**零行尾注释** |
| 零教学噪声 | 无 `// ← 改成XXX`、无行内提示、无空注释占位 |
| 完整性 | 一比一贴全，不能只写一半、不能留 `TODO 以后补` |

> ⚠️ 注释中文化允许**行数变多**，别拿「行数不同」误判写错。**只比代码行。**
> ⚠️ 用户还没写文件时，报「未找到还原文件，等待用户敲完」，**不许自己代写**。

### 7.3 结论怎么写

- **通过**：`✅ 已核对 <文件>：路径/名字 ✓、代码行逐字一致 ✓（codeOurs=N / codeEngine=N / diff=0）、注释全中文 ✓、零教学噪声 ✓、完整性 ✓ → 准推进`
- **不通过**：`❌ 未通过：第 N 行 …（源原文 … / 还原文件 …）→ 先改正，本轮不推进`

## 八、验收脚本（必须按文件类型剔注释）

**核心**：比对「非注释非空代码行」，`codeOurs == codeEngine` 且 `diff == 0` 才算通过。

| 文件类型 | 剔除规则 |
|---|---|
| `.h` / `.cpp` / `.hpp` / `.cc` | `//` + `/* */` |
| `.xml` | `<!-- -->` |
| `.cs` / `.java` / `.ts` / `.js` | `//` + `/* */` |
| `.py` | `#` + `"""` |
| `.json` | 无注释（直接比） |

**硬规则**：

| # | 规则 |
|---|---|
| 1 | 必须按文件类型剔注释，**只剔 `//` 会把块注释当代码行 → 假报警** |
| 2 | 比对前统一 `Trim()` |
| 3 | **`diff > 0` 先怀疑脚本**，打印前 8 条差异确认是真差异再报「未通过」 |
| 4 | 报结论必须带代码行数（`codeOurs/codeEngine`），让用户能复核 |

> 踩坑记录：只剔 `//` 时 `CoreMinimal.h` 报 `diff=173`、`Core.h` 报 `300`、`Core_APL.xml` 报 `116` —— **全是假报警**，实际全 0。

## 九、属性 / 新元素台账（只算「教还原源码」）

| 场景 | 算不算教学 | 要不要登记 |
|---|---|---|
| 教还原源码时讲到的属性 / 新元素 | ✅ 算 | ✅ 要登记 |
| 用户主动提问 → 我建答疑 md | ❌ 不算 | ❌ 不登记 |
| 用户问「还有什么类似属性」→ 建清单 md | ❌ 不算 | ❌ 不登记 |

**硬动作**：

1. 写讲义前先查台账 → 已登记只写「见台账 #N」，未登记标记「本课必讲」
2. 讲义里**就地教**（每段代码后立刻列）
3. 同一轮把新讲的**追加进台账**，更新「已登记 N 项」
4. 回复里报「本轮新登记 N 项」

**台账格式**（一行一个）：

```markdown
| N | `类名.属性名` | `文件:行号` | 一句话干什么 | 首次教学讲义文件名 |
```

## 十、踩坑清单（血泪，务必避开）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | **AI 代写代码文件**（★ 最严重，2026-11-20 血泪） | 用户说「教学只教 我来写」，代写 = 剥夺练习机会，用户暴怒 | **只产出 md 讲义，绝不往还原根写代码** |
| 2 | **Python 批量覆写 md**：`[io.open(f,'w').write(...) for f in fs]` | 列表推导先 `open(f,'w')` 截断为 0 字节，再读 → **文件被清空** | 先全部读入内存 → 再逐个写；优先用 `replace_in_file` |
| 3 | **宏续行内插注释** | `#define X(a) \` 后面插 `// 注释` → **宏定义被截断，编译失败** | 生成后跑脚本检测「以 `\` 结尾的行」，删除其 `pre` 注释 |
| 4 | **块注释逐行替换** | `/** ... */` 每行都替换 → 行数错位、`*/` 被误处理成 `/` | **整块压成一行 `//` 中文注释**，块内所有行映射到同一行 |
| 5 | **字符串字面量被翻译** | `TEXT("Unspecified allocator")` 译成中文 → 运行时行为改变 | `TEXT()` / `[Obsolete]` / `UE_LOG` 消息**一律不翻译** |
| 6 | **`pre` 与 `rep` 重复** | 同一行既加注释又替换 → 输出两行 | 生成前 `for k in pre: if k in rep: pre.pop(k)` |
| 7 | **只剔 `//` 的验收脚本** | 块注释当代码行 → 假报警 | 按文件类型剔注释（见第八节） |
| 8 | **拿行数不同误判写错** | 注释中文化必然增加行数 | 只比**代码行**，不比总行数 |
| 9 | **还原根 / 讲义根混放** | 代码目录里出现 md，讲义目录里出现源码 | 两个目录严格分离 |
| 10 | **注释写在代码行尾**（2026-11-20 血泪） | 用户看不懂、复制后要手工挪 | **注释独占一行，写在代码正上方** |
| 11 | **一次连发多份讲义**（2026-11-20 血泪） | 用户没法逐个敲，节奏全乱 | 一轮只做一个文件，发完就停 |
| 12 | **代码切片分段**（2026-11-20 血泪） | 用户没法整块复制 | 复制文件里必须是**完整代码**，不许省略 |
| 13 | **建 `答疑文件\` 子目录**（2026-11-20 血泪） | 用户找不到文件 | 两件套**平铺**在阶段目录下 |
| 14 | **JSON 里写 `//` 注释**（2026-11-20 血泪） | 引擎解析失败 | 复制文件用 `jsonc` 代码块，并注明「敲的时候删掉注释」 |
| 15 | **英文注释没译完**（2026-11-20 血泪） | 违反「英文注释一律改中文」 | 交付前扫一遍，`//` 后无中文的行逐条处理（被注释掉的代码除外） |

## 十二、一句话总结

**给一个源路径，问清 4 个路径 → 只换根不改名 → 按目录自上而下 → 每个文件一轮两件套（总 md + 复制文件 md）→ 用户自己敲代码 → 下次「下一步」先验收再推进。AI 只教不写，代码零差异，注释全中文且写在代码上方，字符串不翻译，宏续行不插注释，一轮只做一个文件。**
