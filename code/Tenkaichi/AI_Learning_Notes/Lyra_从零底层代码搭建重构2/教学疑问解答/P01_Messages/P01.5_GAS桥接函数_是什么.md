# P01.5 疑问解答 —— VerbMessageToCueParameters / CueParametersToVerbMessage 到底在干嘛

> 来源：P01.5 `TenkaichiVerbMessageHelpers.cpp` 里两个 `#if 0` 挂起的 GAS 桥接函数。
> 读者觉得没看懂"消息 → GAS 参数""GAS 参数 → 消息"是什么意思，这里用类比 + 逐字段对照讲透。

---

## 一、一句话结论

**这两个函数是"翻译器"**：把 **VerbMessage（P01.1 的消息体）** 和 **GameplayCue 参数（GAS 的 `FGameplayCueParameters`）** 之间**互相转译**。

它们俩长得几乎一模一样（字段高度对应），但属于**两套不同的系统**：
- **VerbMessage** 是 Lyra 自己的"玩法事件消息"（谁打了谁、什么动词、数值多少）
- **FGameplayCueParameters** 是 GAS 里 **GameplayCue（游戏玩法提示/特效）** 用的参数字典

有时候 A 系统发的是 VerbMessage，但 B 系统想吃 GameplayCue 参数——就得**翻译**过去；反过来也一样。

---

## 二、类比：同一份简历，两种格式

> 想象一个"**招聘事件**"。同一份候选人信息，在两个系统里格式不同：
>
> | 系统 | 格式 | 例子 |
> |------|------|------|
> | **Lyra 消息系统** | VerbMessage | "候选人张三，应聘『程序员』岗，来自北京，目标上海，期望 3 万" |
> | **GAS GameplayCue** | FGameplayCueParameters | 一份简历表格：姓名=张三，岗位=程序员，来源地=北京，目标地=上海，薪资=3万 |
>
> **`VerbMessageToCueParameters`** = 把"一句话"整理成"简历表格"（翻译过去）。
> **`CueParametersToVerbMessage`** = 把"简历表格"重新说成"一句话"（翻译回来）。

一个系统只发"一句话"，另一个系统只认"简历表格"，中间就得有个人帮忙**来回翻译**——这两个函数就是那个翻译。

## 三、逐字段对照（看它们字段几乎一一对应）

### 翻译方向 1：消息 → GAS 参数

```cpp
FGameplayCueParameters UTenkaichiVerbMessageHelpers::VerbMessageToCueParameters(const FTenkaichiVerbMessage& Message)
{
	FGameplayCueParameters Result;

	Result.OriginalTag        = Message.Verb;            // 动词标签 → 原始标签
	Result.Instigator         = Cast<AActor>(Message.Instigator);   // 发起者
	Result.EffectCauser       = Cast<AActor>(Message.Target);      // 目标（变成"效果施加者"）
	Result.AggregatedSourceTags = Message.InstigatorTags;          // 发起者标签集合
	Result.AggregatedTargetTags  = Message.TargetTags;              // 目标标签集合
	//@TODO: = Message.ContextTags;
	Result.RawMagnitude       = Message.Magnitude;        // 数值

	return Result;
}
```

### 翻译方向 2：GAS 参数 → 消息（方向相反，字段一样）

```cpp
FTenkaichiVerbMessage UTenkaichiVerbMessageHelpers::CueParametersToVerbMessage(const FGameplayCueParameters& Params)
{
	FTenkaichiVerbMessage Result;
	
	Result.Verb           = Params.OriginalTag;            // 原始标签 → 动词标签
	Result.Instigator     = Params.Instigator.Get();       // 发起者（弱指针取出来）
	Result.Target         = Params.EffectCauser.Get();     // 目标（从"效果施加者"取）
	Result.InstigatorTags = Params.AggregatedSourceTags;   // 发起者标签集合
	Result.TargetTags     = Params.AggregatedTargetTags;   // 目标标签集合
	//@TODO: Result.ContextTags = ???;
	Result.Magnitude      = Params.RawMagnitude;           // 数值

	return Result;
}
```

### 字段对照表

| VerbMessage 消息体字段 | FGameplayCueParameters 字段 | 含义 |
|------------------------|----------------------------|------|
| `Verb`（动词标签，如"击杀"） | `OriginalTag`（原始标签） | 事件"是什么" |
| `Instigator`（发起者） | `Instigator`（发起者） | 谁干的 |
| `Target`（目标） | `EffectCauser`（效果施加者） | 作用在谁身上 |
| `InstigatorTags`（发起者标签组） | `AggregatedSourceTags`（来源标签组） | 发起者身上的标签 |
| `TargetTags`（目标标签组） | `AggregatedTargetTags`（目标标签组） | 目标身上的标签 |
| `Magnitude`（数值，如伤害量） | `RawMagnitude`（原始数值） | 带多少数值 |

> 注意几个小差异（翻译时顺便做了转换）：
> - `Instigator` 在消息里是 `TWeakObjectPtr`（弱指针），转成 GAS 参数要 `Cast<AActor>`；转回来要 `.Get()` 取出来
> - `Verb`（FGameplayTag）→ `OriginalTag`（FGameplayTag），同一个东西不同叫法
> - 消息里没有 GAS 参数的 `ContextTags`（`@TODO` 注释 = 这段 Lyra 也没填，留空）

## 四、为什么要"翻译"（实际价值）

1. **两边系统都能发同一件事**：比如"击杀"事件——用 Lyra 消息发（VerbMessage），也要给 GAS 的 GameplayCue 发（方便挂特效/音效）。翻译器让一份信息能同时喂给两套系统。
2. **代码复用**：不用手写两遍字段拷贝，一个函数搞定。
3. **保持数据一致**：字段一一对应，翻译过去再翻译回来，信息不丢。

> 但为什么**挂起**？——因为 `FGameplayCueParameters` 是 **GAS 模块**（`GameplayEffectTypes.h`）里的类型，当前 `Build.cs` 还没加 GameplayAbilities 依赖（GAS 核心 P05 才教）。**代码已一比一写全、`#if 0` 挂起**，等 P05 GAS 就位，解开就能用，一个字不用改（已登记注释备忘录第 13 项）。

---

## 五、小结

| 函数 | 干嘛 | 方向 |
|------|------|------|
| `VerbMessageToCueParameters` | 把一条 Lyra 消息"翻译"成 GAS 的 GameplayCue 参数 | 消息 → GAS |
| `CueParametersToVerbMessage` | 把 GAS 的 GameplayCue 参数"翻译"回一条 Lyra 消息 | GAS → 消息 |

两个函数就是**同一份信息在"Lyra 消息"和"GAS GameplayCue"两种格式之间的双向翻译器**，字段一一对应，翻译时顺便做指针/类型的小转换。

---

**P01.5 其余部分**（`ToString()` + 两个反查函数）与 GAS 无关，可正常编译；只有这两个 GAS 桥接函数挂起，等 P05 就位解开。
