## 一、这是什么？解决什么问题？

**一句话**：一个挂在角色身上的调试组件，**监听"谁打了我、打了几下、每次打多少"**，然后按时间窗口汇总打印出来。

武器调好子弹轨迹后，你还需要知道**伤害数值对不对**。这个组件就是干这个的：

- **它是个 `UActorComponent`**，挂在角色身上。
- **它监听 `TAG_Lyra_Damage_Message`** 这个 GameplayTag 频道上的消息（P05 定义过）。
- 收到"受伤消息"（`FLyraVerbMessage`）后，判断 `Payload.Target == GetOwner()`（是不是打在我身上），是就记录：**这一帧被打了几次、总共多少伤害、第一次被打的时间**。
- 每次**Tick**检查：如果距离上次被打已经超过 `SecondsBetweenDamageBeforeLogging` 秒（默认1秒），就把这段时间积累的伤害记录汇总，用 `UE_LOG` 打印出来。

**一句话**：**"受击记录仪"** —— 谁在多少帧里打了我多少次、总伤害多少、DPS 多少，全打印出来。

## 二、为什么这么写？

### 核心数据结构：`FFrameDamageEntry`

```cpp
struct FFrameDamageEntry
{
	int32 NumImpacts = 0;      // 这一帧被打了几次
	double SumDamage = 0.0;    // 这一帧累计伤害
	double TimeOfFirstHit = 0.0; // 这一帧第一次被打的时间点
};
```

**为什么按"帧"分组？**
- 一次连招可能同一帧打出多段伤害（比如霰弹枪一次散射命中 5 发）。
- 按"帧"分组后，打印结果能看出**每帧的伤害密度**（一发 vs 多段）。

### 两个容器

| 成员 | 类型 | 作用 |
|------|------|------|
| `ListenerHandle` | `FGameplayMessageListenerHandle` | 消息监听的句柄，反注册时用 |
| `LastDamageEntryTime` | `double` | 上次被打的时间点（判断是否超时汇总） |
| `DamageLog` | `TMap<int64, FFrameDamageEntry>` | key = `GFrameCounter`（引擎全局帧计数器），value = 该帧的伤害记录 |

**为什么用 `TMap<int64, FFrameDamageEntry>`？**
- key 是引擎全局帧号 `GFrameCounter`，同一个"帧号"自动合并（同帧多段伤害累加）。
- `FindOrAdd(GFrameCounter)` —— 找不到就新建一帧记录，找到了就在原记录上累加。

### Tick 里的汇总逻辑

每隔 `SecondsBetweenDamageBetweenLogging`（默认 1 秒）没被打，就把 `DamageLog` 里的所有记录：
1. 按"第一次被打时间"排序。
2. 统计：总帧数、总次数、总伤害。
3. 计算：**Min/Max/Avg 帧间隔（毫秒）+ DPS**。
4. `UE_LOG(LogTenkaichi, Warning, ...)` 打印，清空 `DamageLog`。

**为什么用 `Warning` 级别？**
- 调试信息，用 `Warning` 在默认日志里就能看到（`Verbose` 级别默认不开）。

### OnDamageMessage 回调

```cpp
if (Payload.Target == GetOwner())
```
- 只统计打**自己**的伤害。`FLyraVerbMessage`（P01）里有 `Target` 字段，指向受伤对象。
- `SumDamage += -Payload.Magnitude`：伤害用**负值**存（Lyra 约定伤害为负），取负变正累加。
