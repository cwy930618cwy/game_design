## 一、这是什么？解决什么问题？

**一句话**：给"远程武器"指定"用什么准星 UI"的配置片段。

前面 P11.5 教了开枪技能（射线追踪 + 命中）。但玩家**怎么瞄准**？需要一个**准星（Reticle）**——就是屏幕中央那个小十字/圆点。

- 不同武器要用**不同的准星**（狙击镜 vs 冲锋枪红点）。
- `UInventoryFragment_ReticleConfig` 就是一个**配置卡**：当这把武器被装备到角色身上时，告诉 UI"该用哪几个准星控件"。

它是 **Inventory（P08）的"片段（Fragment）"机制**的一个具体实现：
- P08 里装备的定义是 `UTenkaichiInventoryItemDefinition`，它由一堆"片段"（Fragment）组成。
- 每个片段给物品加一种能力/数据。比如：
  - `ULyraInventoryFragment_SetStats` → 加属性
  - `ULyraInventoryFragment_EquippableItem` → 可装备
  - **`UInventoryFragment_ReticleConfig` → 指定准星**（本类）

## 二、为什么这么写？

这是 P11 里**最小**的一个类，只有 **20 行**，核心就一个属性：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Reticle)
TArray<TSubclassOf<ULyraReticleWidgetBase>> ReticleWidgets;
```

拆解：

| 部分 | 含义 |
|------|------|
| `UPROPERTY(EditAnywhere, BlueprintReadOnly)` | 在蓝图/资产里可编辑，运行时只读 |
| `TArray<...>` | 一个数组（可以用多个准星，比如"普通准星 + 开镜准星"） |
| `TSubclassOf<ULyraReticleWidgetBase>` | 指定**准星控件类**（不是实例，是类——UI 拿到类名后自己创建实例） |
| `ULyraReticleWidgetBase` | P16 UI 的准星控件基类（**本项目还没做，依赖 P16**） |

**为什么是 `TSubclassOf` 而不是直接 `ULyraReticleWidgetBase*`？**
- `TSubclassOf<T>` 是"类的类型引用"，运行时可以 `NewObject` 创建它。
- 配置里只存"要用哪种准星"（类），不存"某个具体准星实例"（实例）。这样同一个准星类可以复用到多把武器上。
