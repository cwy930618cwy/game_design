## 二、逐行讲解

### 1. 头文件

```cpp
#include "TenkaichiWeaponDebugSettings.h"
#include "Misc/App.h"
```

| 头文件 | 提供什么 |
|--------|---------|
| `TenkaichiWeaponDebugSettings.h` | 本类声明（含基类 `UDevelopmentSettingsBackedByCVars`） |
| `Misc/App.h` | `FApp::GetProjectName()`（获取当前项目名） |

### 2. UHT 宏

```cpp
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiWeaponDebugSettings)
```

- 每个 `.cpp` 都要 include 这个宏（参数 = 类名），它把 UHT 生成的内联实现塞进来。
- 这是 UE5 的**内联生成**机制，替代老版 `.generated.cpp` 的 include 方式。

### 3. 构造函数

```cpp
UTenkaichiWeaponDebugSettings::UTenkaichiWeaponDebugSettings()
{
}
```

- 空实现。构造函数在这里没做任何初始化——因为 3 个 float 属性由**配置系统**（`.ini`）驱动，不需要写默认值。
- 缺省值为 0（不画调试）。

### 4. 获取配置分组名

```cpp
FName UTenkaichiWeaponDebugSettings::GetCategoryName() const
{
	return FApp::GetProjectName();
}
```

- `FApp::GetProjectName()` 返回**当前项目名**（本工程就是 `TenkaichiGame`）。
- 这样该配置会显示在**"项目设置 → TenkaichiGame"**分组下（而不是默认的"General"）。
- 用项目名而不是写死字符串的好处：**换项目名时自动跟随**，不用改代码。
