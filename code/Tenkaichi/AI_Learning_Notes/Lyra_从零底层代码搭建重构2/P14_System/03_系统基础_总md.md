## 一、为什么有这一层（解决什么问题）

回到总纲的依赖层次图：

```
L1 模块地基：Game 模块（.uproject/Build.cs/模块入口/日志/Tag）  ← 已完成
L2 底层插件：ModularGameplayActors / GameplayMessageRouter      ← 已完成
L3 系统基础：CommonGame / CommonUser / GameEngine               ← 本阶段
L4 角色与玩家：Character / Player / GameMode / Experience
L5 Gameplay 系统：AbilitySystem / Input / Camera / Teams / Inventory
...
```

L1 我们把 `TenkaichiGame` 模块建起来了，L2 装了"模块化 Actor + 消息路由"两个底座。但一个游戏要真正跑起来，还缺三样"系统级"的东西：

1. **玩家/会话的地基（CommonGame）**——Lyra 的 `GameInstance`、`PlayerController`、`LocalPlayer` 全都继承自它。不装它，阶段四、阶段五直接编译不过。
2. **用户身份 + 在线会话（CommonUser）**——负责"这个玩家是谁、游戏怎么连起来"。它是 CommonGame 的搭档。
3. **游戏自己的引擎类（GameEngine）**——UE 启动时创建"引擎对象"，游戏想在这时机插自定义逻辑，就继承 `UGameEngine` 建一个自己的引擎类。

> 一句话：**L3 给了"玩家级"的系统地基——CommonGame 管玩家/会话对象框架，CommonUser 管身份/在线流程，GameEngine 管引擎启动的钩子。** 这三样都是"别人都要站在上面的底座"。

## 三、关键概念（先建立认知，再拆小步）

### 概念 1：什么是 CommonGame？为什么 Lyra 不直接继承引擎的 `UGameInstance`？

引擎原生 `UGameInstance` / `APlayerController` / `ULocalPlayer` 是"最通用"的类，啥都不带。但 Lyra 需要统一的**玩家会话、UI 布局管理**，所以 Epic 在 CommonGame 里给它们各自包了一层"加强版"。

Lyra 的对应类**直接继承 CommonGame**（而不是引擎原生类）：
```
UGameInstance              ← UCommonGameInstance          ←（阶段五）TenkaichiGameInstance
AModularPlayerController   ← ACommonPlayerController      ←（阶段四）TenkaichiPlayerController
ULocalPlayer               ← UCommonLocalPlayer           ←（阶段四）TenkaichiLocalPlayer
```
> 类比：CommonGame = 一台"预装系统"的电脑，Lyra 直接买它来用，不用从裸机开始。

### 概念 2：CommonUser 是干嘛的？和 CommonGame 什么关系？

- **CommonGame** 管"玩家/会话的对象框架"（对象怎么组织）。
- **CommonUser** 管"玩家身份 + 在线会话的具体流程"（登录、权限、建房/搜房/加入）。

两个核心子系统（都是 `UGameInstanceSubsystem`）：
- `UCommonUserSubsystem`：用户登录、身份、权限（能不能联机/聊天）。
- `UCommonSessionSubsystem`：创建/搜索/加入在线会话（开房、匹配、邀请）。

> 一句话：**CommonGame 是骨架，CommonUser 是血肉**——CommonGame 定义"谁"，CommonUser 定义"怎么连起来"。

### 概念 3：什么是自定义引擎类（GameEngine）？为什么建了还要配置？

UE 启动时创建"引擎对象"，默认是引擎自带的 `UGameEngine`。游戏想**在引擎启动时插自定义逻辑**，就继承它、重写 `Init()`。

但**光建类没用**——必须在 `Config/DefaultEngine.ini` 的 `[/Script/Engine.Engine]` section 下写 `GameEngine=/Script/TenkaichiGame.TenkaichiGameEngine`，告诉 UE"用这个类当引擎"。这是"能编译 ≠ 会生效"的典型例子。

> 类比：GameEngine 类是"新引擎的钥匙"，`GameEngine=` 配置是"把钥匙插进锁孔"——两者缺一不可。

### 概念 4：这些是"插件 + 独立类"，不是项目 Source 一比一还原的重点

注意区分三类东西：
- **CommonGame/CommonUser**：**插件**，拷贝进来，**只装不拆**（里面的类用到时再讲）。
- **TenkaichiGameEngine**：**我们自己在 `TenkaichiGame` 模块里写的类**，要一比一还原 `.h`/`.cpp`。
- **GameplayCueManager + GAS 叶子**：本来也在旧阶段三，但按真实依赖**已归到 L5**（见重构总纲），本阶段不教。
