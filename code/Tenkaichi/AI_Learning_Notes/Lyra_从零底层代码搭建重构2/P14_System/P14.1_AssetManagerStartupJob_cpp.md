## 〇、这个 `.cpp` 在解决什么

`.h` 声明了任务单的骨架，`.cpp` 实现唯一的核心方法 `DoJob()`：执行加载函数 → 拿到流式句柄 → 绑进度委托 → 阻塞等待完成 → 打印耗时。

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiAssetManagerStartupJob.h"

#include "TenkaichiLogChannels.h"

// 执行真正的加载，如果创建了句柄就返回它。
TSharedPtr<FStreamableHandle> FTenkaichiAssetManagerStartupJob::DoJob() const
{
	const double JobStartTime = FPlatformTime::Seconds();

	TSharedPtr<FStreamableHandle> Handle;
	UE_LOG(LogTenkaichi, Display, TEXT("Startup job \"%s\" starting"), *JobName);
	JobFunc(*this, Handle);

	if (Handle.IsValid())
	{
		Handle->BindUpdateDelegate(FStreamableUpdateDelegate::CreateRaw(this, &FTenkaichiAssetManagerStartupJob::UpdateSubstepProgressFromStreamable));
		Handle->WaitUntilComplete(0.0f, false);
		Handle->BindUpdateDelegate(FStreamableUpdateDelegate());
	}

	UE_LOG(LogTenkaichi, Display, TEXT("Startup job \"%s\" took %.2f seconds to complete"), *JobName, FPlatformTime::Seconds() - JobStartTime);

	return Handle;
}
```

## 二、关键点讲解

### 1. `DoJob()` 的整体流程

```
记开始时间 → 打日志"starting" → 执行 JobFunc（真正加载）→
如果有句柄：绑进度委托 → 阻塞等待完成 → 解绑进度委托 →
打日志"took X seconds" → 返回句柄
```

### 2. `JobFunc(*this, Handle)`——执行加载函数

```cpp
JobFunc(*this, Handle);
```

调用构造时传入的 `JobFunc`，第一个参数是任务自己（`*this`，让加载函数能访问 `SubstepProgressDelegate` 上报进度），第二个参数 `Handle` 是**引用传出**——加载函数在里面 `Handle = ...` 创建流式句柄，执行完外面就能拿到。

### 3. `BindUpdateDelegate`——绑定进度更新委托

```cpp
Handle->BindUpdateDelegate(FStreamableUpdateDelegate::CreateRaw(this, &FTenkaichiAssetManagerStartupJob::UpdateSubstepProgressFromStreamable));
```

`FStreamableHandle` 有一个"更新委托"（加载过程中周期触发）。这里把 `UpdateSubstepProgressFromStreamable` 绑上去，加载时就会周期上报进度（带节流，`.h` 里讲过）。

- `CreateRaw(this, ...)`：绑定**原始 C++ 成员函数**（对比 `CreateUObject` 绑 UObject、`CreateLambda` 绑 lambda）。因为 `FTenkaichiAssetManagerStartupJob` 是纯结构体（不是 UObject），只能用 `CreateRaw`。

### 4. `WaitUntilComplete(0.0f, false)`——阻塞等待

```cpp
Handle->WaitUntilComplete(0.0f, false);
```

阻塞当前线程，直到加载完成：
- 第一个参数 `0.0f`：超时时间，`0` 表示**不超时**（一直等到完成）。
- 第二个参数 `false`：`bStartStalled`（是否"失速启动"，暂不加载）。`false` = 正常加载。

> 这是"同步等待异步加载"的关键：启动时 AssetManager 要等这些资产真正加载完才能继续，所以用 `WaitUntilComplete` 卡住。

### 5. 解绑进度委托

```cpp
Handle->BindUpdateDelegate(FStreamableUpdateDelegate());
```

加载完成后，绑一个**空的委托**（`FStreamableUpdateDelegate()` 默认构造 = 空委托）来解绑，避免后续再触发上报。

### 6. `UE_LOG(..., Display, ...)` 日志级别

- `Display`：显示级别（比 `Log` 更显眼，启动任务这种"里程碑"用 Display）。
- 打印任务名 + 耗时，方便排查启动性能。
