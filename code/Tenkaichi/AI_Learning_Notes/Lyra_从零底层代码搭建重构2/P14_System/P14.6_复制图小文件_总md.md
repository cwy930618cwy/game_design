## 一、这三个类解决什么问题（先讲为什么）

**复制图（ReplicationGraph）** 是 UE 的一种网络优化机制：决定"哪些 Actor 要复制给哪些客户端"，避免把整个世界的所有 Actor 都复制给每个玩家（浪费带宽）。P14.7 会教 Lyra 自定义的复制图，而这三个小文件是它的**配套**：

| 类 | 作用 |
|----|------|
| `ULyraSignificanceManager` | **重要性管理器**（空壳）——引擎 `USignificanceManager` 的占位继承，将来按"重要性"决定复制优先级 |
| `ELyraRepGraphActorClassSettings`（Types） | **枚举 + 结构体**——定义 Actor 类怎么路由到复制节点 |
| `ULyraReplicationGraphSettings` | **复制图配置**——用控制台变量（CVar）暴露复制图的各种参数 |

> **类比**：复制图是"对讲机调度员"（决定谁听谁说），这三个小文件是调度员的"花名册（Types 枚举）、配置表（Settings）、重要性评估员（SignificanceManager）"。

## 二、内部结构全景

### 1. `SignificanceManager`（16 + 6 行，极简空壳）

```cpp
UCLASS()
class ULyraSignificanceManager : public USignificanceManager
{
	GENERATED_BODY()

```

空壳：只继承，什么都不加。将来要自定义"重要性"逻辑时再加。

### 2. `ReplicationGraphTypes`（76 行，纯头文件）

- `EClassRepNodeMapping` 枚举：4 个值（`NotRouted`/`RelevantAllConnections`/`Spatialize_Static`/`Spatialize_Dynamic`/`Spatialize_Dormancy`），定义 Actor 类路由到哪个复制节点。
- `FRepGraphActorClassSettings` 结构体：Actor 类的复制配置（`ActorClass`/`ClassNodeMapping`/`bAddClassRepInfoToMap` 等）。

### 3. `ReplicationGraphSettings`（65 + 11 行）

- 继承 `UDeveloperSettingsBackedByCVars`（开发者设置 + CVar 支持）。
- 一堆 `UPROPERTY`，每个都带 `ConsoleVariable` meta（对应一个控制台变量）。
- `ClassSettings` 数组（`TArray<FRepGraphActorClassSettings>`）——每类 Actor 的复制配置。
