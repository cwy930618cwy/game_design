## 一、这个类解决什么问题（先讲为什么）

UE 引擎的 `UGameInstance` 是**整个游戏进程的生命周期管理者**——游戏启动时创建，退出时销毁，全局唯一。Lyra 继承它（实际继承 `UCommonGameInstance`，CommonGame 插件的版本）做了 `ULyraGameInstance`：

1. **注册 InitState 状态机**：启动时注册 4 个初始化状态 tag（Spawned → DataAvailable → DataInitialized → GameplayReady），这是 ModularGameplay 的"初始化状态机"基础。
2. **主玩家控制器**：`GetPrimaryPlayerController()` 返回 `ALyraPlayerController`（强类型）。
3. **登录回调**：`HandlerUserInitialized` 登录成功后让 LocalPlayer 加载设置。
4. **加密演示**：一套硬编码密钥的流量加密演示代码（DTLS，仅演示用，注释里明确"不安全"）。

> **类比**：`GameInstance` 是"整个游戏进程的管家"——从开机到关机的总负责人。GameMode/GameState 是"一场戏"的导演/记分板（每次进图新建），GameInstance 是"整个剧组"的制片人（整个进程只有一份，从头管到尾）。
