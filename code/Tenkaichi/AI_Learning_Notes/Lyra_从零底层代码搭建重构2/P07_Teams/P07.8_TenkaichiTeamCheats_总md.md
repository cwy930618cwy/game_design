## 一、为什么要有 TeamCheats

P07.1~P07.7 已经把队伍系统搭好了：有接口、有外观、有信息实体、有管理子系统。
但有个很实际的问题——**开发时怎么调试队伍？**

想象你在测一张对战图：

- 想看看"A 队颜色对不对" → 得手动改数据资产、重启 PIE，再拖两个玩家进去分队伍
- 想测"友军伤害关没关" → 得先让两个人进不同队，再开枪
- 想知道"现在场上到底有几队、都谁在" → 只能打断点看 `TeamMap`

Lyra 的解法：**给队伍系统配一组控制台作弊指令**（Cheat）。运行时敲一行命令就能换队、查队。

| 命令（控制台里敲） | 作用 |
|-------------------|------|
| `CycleTeam` | 把当前玩家换到下一队（到末尾绕回第一队） |
| `SetTeam 3` | 把当前玩家换到 3 队 |
| `ListTeams` | 打印当前所有队伍 ID |

> 类比：`TeamCheats` = 队伍系统的**遥控器**。平时游戏逻辑不碰它，但开发者拿着它可以随时换台。

### 它为什么是关键（不只是一个小工具类）

打开 `TenkaichiTeamSubsystem.cpp` 第 85~91 行（当前被 `#if 0` 包着）：

## 四、关键理解点

### 概念 1：`UCheatManagerExtension` 是什么

- 引擎的**作弊管理器扩展**：`UCheatManagerExtension : public UObject`（`CheatManager.h:71`）
- 一个 CheatManager 可以挂多个 Extension，每个 Extension 贡献一批 `Exec` 命令
- 比"直接往 `UCheatManager` 加函数"更模块化——Lyra 的 `PlayerController` 里就挂了好几个 Extension

> 教学分级：这是**引擎底层接口（① 只讲不拆）**——引擎自带，我们不用新建，懂它干嘛就行。

### 概念 2：`UFUNCTION(Exec)` 的三档标记差异

| 函数 | 标记 | 差异说明 |
|------|------|---------|
| `CycleTeam` / `SetTeam` | `Exec, BlueprintAuthorityOnly` | **只能服务器执行**（换队是权威操作） |
| `ListTeams` | `Exec` | 客户端也能敲（只是打印，不改状态） |

> `BlueprintAuthorityOnly` = 蓝图调用时也只在权威端生效，防止客户端乱换队。

### 概念 3：`UWorld::GetSubsystem` 静态方法 vs `World->GetSubsystem`

```cpp
// TeamCheats 这么写（静态版本，World 可为 null）
UWorld::GetSubsystem<UTenkaichiTeamSubsystem>(GetWorld())

// TeamSubsystem 内部 / TeamStatics 这么写（成员版本）
World->GetSubsystem<UTenkaichiTeamSubsystem>()
```

两者等价，Lyra 在这里用的是**静态版本**（`LyraTeamCheats.cpp:17/42/55`）。照抄即可，不要"顺手统一"。

### 概念 4：`LogConsoleResponse` 日志分类

- 引擎内置分类（`HAL/IConsoleManager.h`），专门给"控制台命令的回显"用
- 敲 `CycleTeam` 后控制台会打印 `Changed to team 3 (from team 1)` —— 就是这个分类输出的
- 与 Lyra 自定义的 `LogTenkaichiTeams` 不同：前者是"回显给用户"，后者是"开发日志"

## 六、要记住的点

1. **`TeamCheats` 是"小类卡大类"的钥匙**——31 行 `.h` 卡着 449 行 `TeamSubsystem.cpp` 和整条 Teams 链。
2. **`UFUNCTION(Exec)`** = 这个函数可以在控制台里当命令敲（函数名即命令名，下划线风格）。
3. **`BlueprintAuthorityOnly`** 用在会改状态的函数上（`CycleTeam` / `SetTeam`），纯查询的 `ListTeams` 不加。
4. **每个函数第一步都是 `if (UTeamSubsystem* ... )` 判空**——子系统可能还没创建，Lyra 统一用这个 pattern 兜底。
5. **`GetPlayerController()` 来自 `UCheatManagerExtension` 基类**，不用自己存指针。
