> 你新建文件：`Source/TenkaichiGame/Teams/TenkaichiTeamDisplayAsset.h`

## 一、完整代码（一比一还原，注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "Engine/DataAsset.h"
#include "TenkaichiTeamDisplayAsset.generated.h"

struct FPropertyChangedEvent;

class UMaterialInstanceDynamic;
class UMeshComponent;
class UNiagaraComponent;
class AActor;
class UTexture;

// 队伍的显示信息（颜色、显示名、贴图等）
UCLASS(BlueprintType)
class UTenkaichiTeamDisplayAsset : public UDataAsset
{
	GENERATED_BODY()
	
public:
	// 标量参数表：名字 → 数值（如自发光强度、透明度）
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TMap<FName, float> ScalarParameters;

	// 颜色参数表：名字 → 颜色（如阵营主色、描边色）
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TMap<FName, FLinearColor> ColorParameters;

	// 贴图参数表：名字 → 贴图（如阵营图标、纹理）
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TMap<FName, TObjectPtr<UTexture>> TextureParameters;

	// 队伍短名（UI 显示用，如 "RED"）
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	FText TeamShortName;

public:
	// 把这份队伍的标量/颜色/贴图参数，全部刷到一个动态材质上
	UFUNCTION(BlueprintCallable, Category=Teams)
	void ApplyToMaterial(UMaterialInstanceDynamic* Material);

	// 把这份队伍的标量/颜色/贴图参数，刷到网格组件的所有材质上
	UFUNCTION(BlueprintCallable, Category=Teams)
	void ApplyToMeshComponent(UMeshComponent* MeshComponent);

	// 把这份队伍的标量/颜色/贴图参数，刷到一个 Niagara 粒子组件上
	UFUNCTION(BlueprintCallable, Category=Teams)
	void ApplyToNiagaraComponent(UNiagaraComponent* NiagaraComponent);

	// 遍历目标 Actor 的所有组件，把队伍外观刷到每个可用的组件上（可含子组件）
	UFUNCTION(BlueprintCallable, Category=Teams, meta=(DefaultToSelf="TargetActor"))
	void ApplyToActor(AActor* TargetActor, bool bIncludeChildActors = true);

public:

	//~UObject interface
#if WITH_EDITOR
	// 编辑器里改了属性时调用：通知队伍子系统刷新（依赖 TeamSubsystem，阶段五解挂）
	virtual void PostEditChangeProperty(FPropertyChangedEvent& PropertyChangedEvent) override;
#endif
	//~End of UObject interface
};
```

## 二、逐段讲解（先讲"为什么"再讲"是什么"）

### 1. 继承 `UDataAsset`，而不是 `UPrimaryDataAsset`

- 这里用的是 **`UDataAsset`**（普通数据资产），不是 `PawnData` 那种 `UPrimaryDataAsset`。
- 区别：`UDataAsset` 只是"可在编辑器里创建实例的数据容器"；`UPrimaryDataAsset` 多了"全局唯一标识、可被 AssetManager 全局查找加载"。
- `TeamDisplayAsset` 不需要被 AssetManager 全局加载（它是被 TeamInfo/TeamSubsystem 引用），所以用 `UDataAsset` 就够。

### 2. 四个 UPROPERTY 字段 —— 用 `TMap<FName, T>` 而不是固定成员

- 为什么用 `TMap`：材质参数的名字是不固定的（不同材质有不同参数名）。用 `名字 → 值` 的映射表，才能灵活适配任意材质。
- `EditAnywhere`：可在编辑器里改（资产详情面板）。
- `BlueprintReadOnly`：蓝图只能读，不能写（保护数据一致性）。

### 3. 四个 `ApplyToXxx` 方法 —— 为什么都标 `BlueprintCallable`

- `TeamDisplayAsset` 是数据资产，最终要**在蓝图/游戏里用**。标 `BlueprintCallable`，蓝图就能直接调用这些方法把外观刷到对象上。
- `Category=Teams`：在蓝图面板里归到 "Teams" 分类，方便查找。
- `ApplyToActor` 带 `meta=(DefaultToSelf="TargetActor")`：蓝图里调用时，`TargetActor` 默认指向调用者自己（省得手动拖）。

### 4. `PostEditChangeProperty` —— 编辑器专属 + 断点

- `#if WITH_EDITOR`：这段只在**编辑器构建**下编译（打包后没有）。
- 作用：在编辑器里改了队伍外观属性时，自动通知 `TeamSubsystem` 刷新所有用到这份外观的对象（即时预览）。
- **断点（铁律 35）**：它硬调用 `ULyraTeamSubsystem::NotifyTeamDisplayAssetModified`，而 `TeamSubsystem` 是 GAS 断点类。这段在 `.cpp` 里**注释挂起**（`.h` 里声明保留，因为声明本身不依赖 TeamSubsystem）。

### 5. 前向声明（`class X;`）为什么够用

- `.h` 顶部只有 `struct FPropertyChangedEvent;` 和一堆 `class UMaterialInstanceDynamic;` 等**前向声明**。
- 因为 `.h` 里这些类型只出现在**指针/引用参数**和 `TMap` 容器里，不需要它们的完整定义——所以 `.h` 能独立编译。

## 三、依赖核对（铁律 30/31）

- `.h` 依赖：引擎 `Engine/DataAsset.h` + 一堆前向声明 → **全部引擎类，自包含**。
- 无 `TeamSubsystem` 硬依赖（`.h` 不 include 它）→ **`.h` 可独立编译**。

**结论：`.h` 可独立编译，无未教依赖。**
