# 4.4.1 TeamInfoBase —— `.h` 声明

> 依据：`LyraTeamInfoBase.h`（Lyra 原样，前缀 `Lyra`→`Tenkaichi`，一字不砍）
> 你新建文件：`Source/TenkaichiGame/Teams/TenkaichiTeamInfoBase.h`

## 一、完整代码（一比一还原，注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "GameFramework/Info.h"
#include "System/GameplayTagStack.h"

#include "TenkaichiTeamInfoBase.generated.h"

namespace EEndPlayReason { enum Type : int; }

class UTenkaichiTeamCreationComponent;
class UTenkaichiTeamSubsystem;
class UObject;
struct FFrame;

// 队伍信息的基类：记录队号 + 队伍标签栈，并负责与队伍子系统注册
UCLASS(Abstract)
class ATenkaichiTeamInfoBase : public AInfo
{
	GENERATED_BODY()

public:
	ATenkaichiTeamInfoBase(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	// 获取这支队伍的队号
	int32 GetTeamId() const { return TeamId; }

	//~AActor interface
	// 游戏开始时，尝试把自己的队伍信息注册到队伍子系统
	virtual void BeginPlay() override;
	// 结束时，若已注册则从队伍子系统注销
	virtual void EndPlay(const EEndPlayReason::Type EndPlayReason) override;
	//~End of AActor interface

protected:
	// 把"这支队伍"注册到指定的队伍子系统（由派生类可覆写的行为）
	virtual void RegisterWithTeamSubsystem(UTenkaichiTeamSubsystem* Subsystem);
	// 若已有队号，则尝试注册到世界里的队伍子系统
	void TryRegisterWithTeamSubsystem();

private:
	// 设置队号（服务器端；队号只能设置一次）
	void SetTeamId(int32 NewTeamId);

	// 客户端收到队号复制时触发，重新尝试注册
	UFUNCTION()
	void OnRep_TeamId();

public:
	// 允许"队伍创建组件"访问私有成员（建队时需要设队号/标签）
	friend UTenkaichiTeamCreationComponent;

	// 队伍的标签栈（复制到所有客户端）
	UPROPERTY(Replicated)
	FGameplayTagStackContainer TeamTags;

private:
	// 队号（只复制一次，客户端收到后触发 OnRep_TeamId）
	UPROPERTY(ReplicatedUsing=OnRep_TeamId)
	int32 TeamId;
};
```

## 二、逐段讲解（先讲"为什么"再讲"是什么"）

### 1. 继承 `AInfo`，不是 `AActor`

- `AInfo` 是引擎的"无碰撞 Actor"，适合纯逻辑实体（如比赛状态、规则）。
- 它不处理移动/碰撞/渲染。`TeamInfoBase` 是队伍数据的载体，不需要可见物体，所以继承 `AInfo`。

### 2. 两个复制字段

| 字段 | 类型 | 复制方式 | 含义 |
|------|------|---------|------|
| `TeamTags` | `FGameplayTagStackContainer` | `Replicated` | 队伍的标签栈（✅ L1 已教），持续同步 |
| `TeamId` | `int32` | `ReplicatedUsing=OnRep_TeamId` | 队号，只复制一次，客户端收到触发回调 |

- `friend UTenkaichiTeamCreationComponent`：友元类——建队组件需要直接设队号/标签，故授权它访问私有成员。

### 3. 方法一览

| 方法 | 类型 | 干嘛的 |
|------|------|--------|
| `GetTeamId()` | 内联 | 返回队号 |
| `BeginPlay()` | 覆写 `AActor` | 开始播放时尝试注册到队伍子系统 |
| `EndPlay(...)` | 覆写 `AActor` | 结束时若已注册则注销 |
| `RegisterWithTeamSubsystem(...)` | protected 虚 | 把队伍注册到指定子系统（可覆写） |
| `TryRegisterWithTeamSubsystem()` | protected | 有队号才尝试注册 |
| `SetTeamId(...)` | private | 服务器端设队号（只能设一次） |
| `OnRep_TeamId()` | UFUNCTION | 客户端收到队号复制时重新尝试注册 |

> **为什么 `SetTeamId` 是 private + `friend`**：队号由建队组件统一分配，不能随意改——所以私有，只有 `TeamCreationComponent`（友元）能设。保证"队号一次分配、不可篡改"。

## 三、依赖核对（铁律 30/31）

- `.h` 依赖：`GameFramework/Info.h`（引擎）+ `System/GameplayTagStack.h`（✅ L1 已教）+ 一堆前向声明。
- `UTenkaichiTeamSubsystem` / `UTenkaichiTeamCreationComponent` 在 `.h` 里只是**前向声明**（`class X;`），
  不阻塞编译（铁律 30：`.h` 前置声明不影响编译）。
- `TeamSubsystem` 硬依赖在 **`.cpp`** 里（铁律 30：`.cpp` 运行时硬调用才决定编译/链接）。

**结论：`.h` 可独立编译，无阻塞依赖。** 断点只在 `.cpp`。
