# 4.5 TeamSubsystem / TeamStatics —— 总 md

> 定位：4.5 是队伍系统的**核心枢纽**——前面 4.1~4.4 教的"队伍接口、外观、队伍信息三件套"，
> 全都要靠 **`TeamSubsystem`** 统一管理、查询、切换。它是解开关联 4.4 两个挂起的关键类。
> `TeamStatics` 是一组**蓝图静态辅助函数**，方便蓝图侧调用队伍信息。

## 一、为什么要有 TeamSubsystem

前面教了"队伍是谁""队伍长啥样""队伍信息的实体"——但**谁来统一管这些队伍？**

- 谁维护"队伍ID → 队伍信息"的映射？
- 谁回答"这个 Actor 属于哪队？""这两个 Actor 是否同队？"
- 谁处理"队伍外观改变后通知所有人刷新"？

Lyra 用**一个 WorldSubsystem（世界子系统）**来干这件事：`TeamSubsystem`。
它随 World 创建/销毁，全局唯一，负责**登记队伍、查询队伍、比较队伍、管理队伍标签与外观**。

> 类比：TeamSubsystem = 队伍"总人事处"——所有人（Actor）来报到，它登记；别人问"他是哪队的"，它查档案回答。

## 二、本文件里有什么（全景）

### 1. `TeamSubsystem`（`UWorldSubsystem`，核心）

**辅助结构**：
- `FLyraTeamTrackingInfo`：单个队伍的"追踪信息"（PublicInfo + PrivateInfo + DisplayAsset + 变更委托）。
- `ELyraTeamComparison`：两队比较结果枚举（同队/异队/无效）。

**核心成员**：
- `TeamMap`（`TMap<int32, FLyraTeamTrackingInfo>`）：队号 → 队伍追踪信息。

**方法分组**：

| 分组 | 方法 |
|------|------|
| 生命周期 | `Initialize` / `Deinitialize` |
| 登记/注销 | `RegisterTeamInfo` / `UnregisterTeamInfo` |
| 查询归属 | `FindTeamFromObject` / `FindTeamFromActor` / `FindPlayerStateFromActor` |
| 比较 | `CompareTeams`（两个重载）/ `CanCauseDamage` |
| 改队 | `ChangeTeamForActor` |
| 标签栈 | `AddTeamTagStack` / `RemoveTeamTagStack` / `GetTeamTagStackCount` / `TeamHasTag` |
| 存在性 | `DoesTeamExist` |
| 外观 | `GetTeamDisplayAsset` / `GetEffectiveTeamDisplayAsset` / `NotifyTeamDisplayAssetModified` / `GetTeamDisplayAssetChangedDelegate` |
| 枚举 | `GetTeamIDs` |

### 2. `TeamStatics`（`UBlueprintFunctionLibrary`，辅助）

一组**静态**蓝图函数，包装 `TeamSubsystem` 查询：
`FindTeamFromObject` / `GetTeamDisplayAsset` / `GetTeamScalarWithFallback` / `GetTeamColorWithFallback` / `GetTeamTextureWithFallback`。

## 四、关键理解点

### 概念 1：什么是 WorldSubsystem？

- `UWorldSubsystem` 是 UE 的**世界子系统**：每个 World 一个实例，随 World 创建/销毁。
- 适合存"每局游戏的全局状态"——队伍就是每局动态生成的，所以放 WorldSubsystem 合适。

### 概念 2：`TeamMap` 怎么组织？

- `TMap<int32, FLyraTeamTrackingInfo>`：队号(int32) → 该队的追踪信息(Public/Private/DisplayAsset/委托)。
- 所有查询（某 Actor 哪队、某队外观）都查这个 Map。

### 概念 3：为什么用 `MinimalAPI`？

- `UCLASS(MinimalAPI)`：类的导出符号**最小化**——只导出公共 API，减少编译依赖。
- 方法前都有 `UE_API` 宏标记要导出的。这是 Lyra 对"被多模块引用"类的优化。

### 概念 4：`ELyraTeamComparison` 三态

- `OnSameTeam`（同队）/ `DifferentTeams`（异队）/ `InvalidArgument`（无效）——比较结果清晰三态。
