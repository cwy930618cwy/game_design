## 一、为什么还要有 ObserveTeamColors

P07.9 的 `AsyncAction_ObserveTeam` 解决了"**蓝图监听队伍变化**"：

```
[Observe Team] ──► OnTeamChanged (bTeamSet, TeamId)
```

但 UI 拿到 `TeamId = 1` 之后，**还得自己去查"1 队长什么样"**——
要再调一次 `TeamStatics::GetTeamDisplayAsset` 拿外观资产，再从里面 `GetTeamColorWithFallback` 取颜色。

> 更麻烦的是：**队伍没换，但队伍的颜色换了**（策划在编辑器里改了 `TeamDisplayAsset` 的参数），
> P07.9 的节点**完全不会通知你**——因为它只监听"队伍号"。

### 问题场景

想象 UI 上的队友血条：

| 时刻 | 发生什么 | P07.9 节点 | 我们想要 |
|------|---------|-----------|---------|
| T0 | 玩家开局是 1 队 | ✅ 广播 `(true, 1)` | 血条变蓝 |
| T1 | 被 `CycleTeam` 换到 2 队 | ✅ 广播 `(true, 2)` | 血条变红 |
| T2 | 策划**改了 2 队的颜色**（队伍没变） | ❌ **静默** | **血条要跟着变色** |

P07.9 在 T2 完全失职。这就是 P07.10 存在的理由。

### Lyra 的解法：多一路监听 + 多一个输出

`AsyncAction_ObserveTeamColors` = P07.9 的**升级版**，三个变化：

```
[Observe Team Colors] ──► OnTeamChanged (bTeamSet, TeamId, DisplayAsset)
                                                              ▲
                                                        多输出的第 3 个参数
```

| 变化 | 说明 |
|------|------|
| ① **委托多一个参数** | 从 2 参 `FTeamObservedAsyncDelegate` → 3 参 `FTeamColorObservedAsyncDelegate`，**直接带上 `DisplayAsset`** |
| ② **多一路监听** | 除"对象换队"外，再监听"**这个队伍的外观资产变了**"（`TeamSubsystem::GetTeamDisplayAssetChangedDelegate`） |
| ③ **多一个成员** | `LastBroadcastTeamId` 记住上次播的队伍，用于**换队时把旧队伍的监听解绑** |

> 类比：P07.9 是"**只订报纸**"（队伍变了送一份）；
> P07.10 是"**订报纸 + 订阅该报社的改版通知**"（队伍变了送，报纸改版也送），
> 而且**送的时候直接把报纸塞你手里**（`DisplayAsset`），你不用自己再去报亭买。

## 四、关键理解点

### 概念 1：为什么要存**两个**弱引用（本类最反直觉的地方 ★）

```cpp
TWeakInterfacePtr<ITenkaichiTeamAgentInterface> TeamInterfacePtr;  // 接口视图
TWeakObjectPtr<UObject> TeamInterfaceObj;                          // 裸对象视图
```

**同一个对象，存了两份。** 为什么？因为它们**用途不同**：

| 成员 | 用来干什么 | 为什么必须单独存 |
|------|-----------|----------------|
| `TeamInterfacePtr` | 调 `GetGenericTeamId()` / 绑"换队"委托 | 需要**接口类型**才能调接口方法 |
| `TeamInterfaceObj` | 传给 `GetWorldFromContextObject()` / `GetTeamDisplayAsset(WorldContextObject, ...)` | 那些函数收的是 **`const UObject*`**，不是接口 |

> 💡 你可能想问：**`TeamInterfacePtr.Get()` 拿到的不就是对象吗？**
> 不完全——`TWeakInterfacePtr::Get()` 返回的是**接口指针 `ITenkaichiTeamAgentInterface*`**，
> 它虽然能 `Cast` 回 `UObject`，但 Lyra 选择**再存一份裸的**，省掉每次转换。
> **照抄 Lyra，别"顺手优化掉一个"**（铁律 16：禁止加法 = 也禁止擅自做减法）。

### 概念 2：`BroadcastChange` —— 搬家的广播员（本类核心 ★）

这是本类**唯一新增的实质逻辑**，P07.9 完全没有对应物。

```cpp
// 解绑旧队伍的外观监听
if (TeamSubsystem && bTeamChanged && (LastBroadcastTeamId != INDEX_NONE))
    TeamSubsystem->GetTeamDisplayAssetChangedDelegate(LastBroadcastTeamId).RemoveAll(this);

// 广播
LastBroadcastTeamId = NewTeam;
OnTeamChanged.Broadcast(NewTeam != INDEX_NONE, NewTeam, DisplayAsset);

// 绑定新队伍的外观监听
if (TeamSubsystem && bTeamChanged && (NewTeam != INDEX_NONE))
    TeamSubsystem->GetTeamDisplayAssetChangedDelegate(NewTeam).AddDynamic(this, &ThisClass::OnDisplayAssetChanged);
```

**为什么"外观监听"要跟着队伍搬？**

`TeamSubsystem` 的委托是**按队伍 ID 分桶**的（`TeamMap.FindOrAdd(TeamId).OnTeamDisplayAssetChanged`）。
你监听的是"1 队的外观"，但对象换到 2 队了 → **你必须退订 1 队、改订 2 队**，
否则：还在收 1 队的改版通知（**错的**），2 队改版了反而收不到（**漏的**）。

> 类比：你从 1 号楼搬到 2 号楼，**订阅的牛奶得改送到新地址**。
> `BroadcastChange` 就是那个"**广播 + 顺便改牛奶地址**"的管家。
>
> 📌 **顺序很讲究**：先解绑旧的 → 再广播 → 最后绑新的。
> 这样广播时蓝图拿到的 `DisplayAsset` 是新的，监听也已经切换到新队伍了。

### 概念 3：`bTeamChanged` 守卫（避免无意义的解绑/重绑）

```cpp
const bool bTeamChanged = (LastBroadcastTeamId != NewTeam);
```

如果 `OnDisplayAssetChanged` 触发（队伍没变，只是外观变了），
`LastBroadcastTeamId == NewTeam` → `bTeamChanged == false` → **跳过解绑和重绑**，只广播。

> 💡 这就是 **T2 场景**（策划改颜色）走的路径：只广播，不搬家。

### 概念 4：委托从 2 参变 3 参

| 类 | 委托 | 参数 |
|----|------|------|
| P07.9 | `FTeamObservedAsyncDelegate` | `(bool bTeamSet, int32 TeamId)` |
| **P07.10** | `FTeamColorObservedAsyncDelegate` | `(bool bTeamSet, int32 TeamId, const UTenkaichiTeamDisplayAsset* DisplayAsset)` |

宏也从 `TwoParams` 变 **`ThreeParams`**。蓝图侧多一个 `DisplayAsset` 引脚，
UI 拿到就能直接 `GetTeamColorWithFallback`，**不用再查一次**。

> ⚠️ 注意第 3 个参数是 **`const UTenkaichiTeamDisplayAsset*`（裸指针，且带 const）**——
> 这是 `DECLARE_DYNAMIC_MULTICAST_DELEGATE` 支持 UObject 派生类指针的写法。Lyra 原样。

### 概念 5：`Activate()` 里多了 World 这一层

P07.9 的 `Activate()` 直接 `TeamInterfacePtr.Get()` 就开干；本类**多套了一层**：

```cpp
if (ITenkaichiTeamAgentInterface* TeamInterface = TeamInterfacePtr.Get())
{
    if (UWorld* World = GEngine->GetWorldFromContextObject(TeamInterfaceObj.Get(), EGetWorldErrorMode::LogAndReturnNull))
    {
        CurrentTeamIndex = GenericTeamIdToInteger(TeamInterface->GetGenericTeamId());
        CurrentDisplayAsset = UTenkaichiTeamStatics::GetTeamDisplayAsset(World, CurrentTeamIndex);
        ...
    }
}
```

因为**取外观资产必须先有 World**（`GetTeamDisplayAsset` 第一个参数是 `WorldContextObject`，内部要找 `TeamSubsystem`）。
拿不到 World（对象不在任何世界里）→ `bCouldSucceed` 保持 `false` → 最后自毁。

> 📌 `EGetWorldErrorMode::LogAndReturnNull` = 拿不到就**打日志并返回 `nullptr`**，不崩溃。
> 这是引擎 3 档错误模式之一（`Assert` / `LogAndReturnNull` / `ReturnNull`）。

### 概念 6：和 P07.9 的结构对照（一张表看懂差异）

| 维度 | P07.9 `ObserveTeam` | **P07.10 `ObserveTeamColors`** |
|------|--------------------|-------------------------------|
| 委托参数 | 2 参（无外观） | **3 参（带 `DisplayAsset`）** |
| 工厂是否转发 | 是（转发给 `InternalObserveTeamChanges`） | **否（自己直接 `NewObject`）** |
| 监听路数 | 1 路（对象换队） | **2 路（换队 + 队伍外观变）** |
| 弱引用成员 | 1 个（接口） | **2 个（接口 + 裸对象）** |
| 额外状态 | 无 | **`LastBroadcastTeamId`** |
| 核心方法 | 无 | **`BroadcastChange`（统一广播 + 搬监听）** |
| include 数 | 2 | **6** |
| 规模 | `.h` 51 / `.cpp` 72 | **`.h` 55 / `.cpp` 109** |
| 挂起 | 零 | **零** |

> 💡 **为什么 P07.10 不转发了？**
> P07.9 的 `ObserveTeam(UObject*)` 需要把裸指针**隐式转**成 `TScriptInterface`，所以拆了个私有静态做类型转换。
> P07.10 全程只用裸 `UObject*` 和 `TWeakInterfacePtr`（用 `TWeakInterfacePtr<...>(TeamAgent)` 显式构造），
> **不需要那层转换** → Lyra 就直接在工厂里干完了。
> 这是"**为什么两个同族类结构不同**"的真实答案：**依赖的类型不同，拆法就不同**。
