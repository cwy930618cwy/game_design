## 一、为什么要有 AsyncAction_ObserveTeam

P07.1~P07.8 把队伍系统搭全了：接口、外观、信息实体、管理子系统、作弊遥控器。
但还差一个"**最后一公里**"的问题——

> **蓝图里怎么"监听某个对象的队伍变化"？**

### 问题场景

想象你要做 UI 上的"队友血条"：

- 玩家 A 开局是 1 队 → 血条显示蓝色
- 中途被 `CycleTeam` 换到 2 队 → 血条要**立刻**变红

在 C++ 里这很容易：`TeamInterface->GetTeamChangedDelegateChecked().AddDynamic(...)` 一行搞定。
**但蓝图里没法拿到那个委托**——因为：

1. `ITenkaichiTeamAgentInterface` 标了 `meta=(CannotImplementInterfaceInBlueprint)`（P07.1 `.h:31`），蓝图拿不到它
2. 委托 `FOnTenkaichiTeamIndexChangedDelegate` 是 C++ 类型，蓝图不能直接 `Bind`

### Lyra 的解法：异步蓝图节点（Async Action）

Lyra 把"监听队伍变化"包装成一个**蓝图里的异步节点**（就是蓝图那类带 `OnTeamChanged` 输出引脚的节点）：

```
[Observe Team] ──► OnTeamChanged (bTeamSet, TeamId)
```

蓝图里拖一个节点、连个事件，队伍一变就自动回调。而且：

- **立刻广播一次**当前队伍（`Activate()` 里第一次 Broadcast）→ 蓝图不用额外再查一次
- 之后每次换队都广播
- 对象销毁 / 手动 Cancel → 自动解绑（`SetReadyToDestroy()`）

> 类比：`TeamSubsystem` 是**管家**，`TeamStatics`（P07.7）是给蓝图的**电话簿**（同步查询），
> 而 `AsyncAction_ObserveTeam` 是给蓝图的**订阅推送服务**（异步监听）——
> 你不用反复打电话问，留个地址，变了它主动通知你。

### 它为什么独立且零挂起

它**只依赖 P07.1 的纯接口**（`ITenkaichiTeamAgentInterface`），**完全不碰 TeamSubsystem**。
所以它是 P07 里第二个"零挂起可独立编译"的类（第一个是 P07.1）。

## 四、关键理解点

### 概念 1：`UCancellableAsyncAction` vs `UBlueprintAsyncActionBase`（引擎 ①，只讲不拆）

| 类 | 来源 | 特点 |
|----|------|------|
| `UBlueprintAsyncActionBase` | `Kismet/BlueprintAsyncActionBase.h:19` | 最基础：**只提供一次性异步节点**（激活→广播→结束） |
| `UCancellableAsyncAction` | `CancellableAsyncAction.h:15` | **可取消** + **长期存活**：注册到 GameInstance，直到你显式 `SetReadyToDestroy()` / `Cancel()` |

Lyra 选 `UCancellableAsyncAction` 的原因很直接：**"监听队伍变化"是长期订阅，不是一次性操作**。
如果只继承 `UBlueprintAsyncActionBase`，节点激活一次就完了，后续换队收不到。

> 教学分级：引擎底层接口 **① 只讲不拆**——引擎自带，我们不用新建，懂它干嘛就行。

### 概念 2：`GENERATED_UCLASS_BODY()`（本文件的特殊点）

P07.1~P07.8 里我们见过两种 UHT 宏：

| 宏 | 用在哪 | 含义 |
|----|--------|------|
| `GENERATED_BODY()` | P07.8 TeamCheats（普通类） | 不带构造函数，**类里没有声明构造函数** |
| `GENERATED_UINTERFACE_BODY()` / `GENERATED_IINTERFACE_BODY()` | P07.1 接口 | 接口专用，成对出现 |
| **`GENERATED_UCLASS_BODY()`** | **本文件 P07.9** | **需要自定义构造函数**：`.cpp` 里必须有 `UAsyncAction_ObserveTeam::UAsyncAction_ObserveTeam(const FObjectInitializer& ObjectInitializer)` |

> ⚠️ **`GENERATED_UCLASS_BODY()` 和 `.cpp` 里的构造函数是绑定的一对**——
> 少了构造函数会链接报错（`undefined reference to ...::...()`）。
> Lyra 本文件的构造函数只有 `Super(ObjectInitializer)` 一行，但**不能省**。

### 概念 3：弱引用 `TWeakInterfacePtr` + `TScriptInterface`

```cpp
TWeakInterfacePtr<ITenkaichiTeamAgentInterface> TeamInterfacePtr;   // 成员：弱引用
static UAsyncAction_ObserveTeam* InternalObserveTeamChanges(TScriptInterface<ITenkaichiTeamAgentInterface> TeamActor);  // 参数：脚本接口
```

| 类型 | 为什么用它 |
|------|-----------|
| `TScriptInterface<T>` | 蓝图/C++ 通用的"接口指针"包装，能跨 UObject 边界传给蓝图 |
| `TWeakInterfacePtr<T>` | **弱引用**——被监听的 Actor 销毁后，`Get()` 自动返回 `nullptr`，**不会悬空崩溃** |

> 💡 为什么必须弱引用？这个 AsyncAction 注册在 GameInstance 上，**可能比被监听的 Actor 活得久**。
> 用强引用会把 Actor 钉在内存里 → 内存泄漏 + 逻辑错误。Lyra 统一用 `TWeakInterfacePtr` 兜底。

### 概念 4：`Activate()` 里"先广播一次"的设计（本类最精妙的地方）

```cpp
// 广播一次，让调用者立刻拿到当前状态
OnTeamChanged.Broadcast(CurrentTeamIndex != INDEX_NONE, CurrentTeamIndex);
```

为什么？蓝图用法是这样的：

```
BeginPlay → Observe Team → OnTeamChanged 事件里刷新 UI
```

如果**不**首次广播，蓝图就得再额外调一次 `TeamStatics::FindTeamFromObject` 拿初始队伍——**两处逻辑**。
Lyra 让它**一激活就播一次当前值**，蓝图只写一个事件处理就够了。

> 📌 第一个参数 `bTeamSet` = `CurrentTeamIndex != INDEX_NONE`，即"这个对象现在有没有队伍"。
> 没队伍时传 `false` + `INDEX_NONE(-1)`，蓝图可以据此显示"无队伍"状态。

### 概念 5：`RegisterWithGameInstance` —— 让对象活下来

```cpp
Action->RegisterWithGameInstance(TeamActor.GetObject());
```

`UCancellableAsyncAction` 自己**不注册**的话，会被 GC 回收（因为它只是个 `UObject`，没人引用）。
`RegisterWithGameInstance` 把它挂到 GameInstance 上保活，直到 `SetReadyToDestroy()` 才释放。

### 概念 6：`UObject*` → `TScriptInterface` 的隐式转换

```cpp
UAsyncAction_ObserveTeam* UAsyncAction_ObserveTeam::ObserveTeam(UObject* TeamAgent)
{
	return InternalObserveTeamChanges(TeamAgent);   // ← UObject* 直接传进去
}
```

`ObserveTeam` 收的是裸 `UObject*`，却直接传给形参是 `TScriptInterface<ITenkaichiTeamAgentInterface>` 的
`InternalObserveTeamChanges` —— 这是 `TScriptInterface` 的隐式构造函数在起作用。

> ⚠️ 隐患：**传进来的 `UObject*` 可能根本没实现这个接口**。
> Lyra 在这里**不做检查**，而是在 `InternalObserveTeamChanges` 里用 `TeamActor != nullptr` 兜底
> （`TScriptInterface` 的 `operator!=` 比较的是内部 `UObject*` 是否为空）。
> 真正的接口有效性靠 `Activate()` 里 `TeamInterfacePtr.Get()` 再判一次。
> **照抄 Lyra，不要"顺手加个 Cast"。**
