## 一、完整代码（一比一还原，注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "GenericTeamAgentInterface.h"
#include "UObject/Object.h"

#include "UObject/WeakObjectPtr.h"
#include "TenkaichiTeamAgentInterface.generated.h"

#define UE_API TENKAICHIGAME_API

template <typename InterfaceType> class TScriptInterface;

// 队伍变更通知委托：当某个对象换了队伍时，通过它广播（旧队伍→新队伍）
DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(FOnTenkaichiTeamIndexChangedDelegate, UObject*, ObjectChangingTeam, int32, OldTeamID, int32, NewTeamID);

// 把引擎的队伍ID（FGenericTeamId）转成普通整数；没队伍返回 INDEX_NONE（-1）
inline int32 GenericTeamIdToInteger(FGenericTeamId ID)
{
	return (ID == FGenericTeamId::NoTeam) ? INDEX_NONE : (int32)ID;
}

// 把普通整数转回引擎的队伍ID；INDEX_NONE 表示没有队伍
inline FGenericTeamId IntegerToGenericTeamId(int32 ID)
{
	return (ID == INDEX_NONE) ? FGenericTeamId::NoTeam : FGenericTeamId((uint8)ID);
}

/** 供能被划入某个队伍的对象实现的接口 */
UINTERFACE(MinimalAPI, meta=(CannotImplementInterfaceInBlueprint))
class UTenkaichiTeamAgentInterface : public UGenericTeamAgentInterface
{
	GENERATED_UINTERFACE_BODY()
};

class ITenkaichiTeamAgentInterface : public IGenericTeamAgentInterface
{
	GENERATED_IINTERFACE_BODY()

	// 返回"队伍变更委托"的指针（实现类覆写；默认无，返回空）
	virtual FOnTenkaichiTeamIndexChangedDelegate* GetOnTeamIndexChangedDelegate() { return nullptr; }

	// 静态工具：判断队伍确实变了，才广播"队伍变更"给监听者
	static UE_API void ConditionalBroadcastTeamChanged(TScriptInterface<ITenkaichiTeamAgentInterface> This, FGenericTeamId OldTeamID, FGenericTeamId NewTeamID);
	
	// 获取"队伍变更委托"并断言其非空（实现类必须已覆写，否则崩溃）
	FOnTenkaichiTeamIndexChangedDelegate& GetTeamChangedDelegateChecked()
	{
		FOnTenkaichiTeamIndexChangedDelegate* Result = GetOnTeamIndexChangedDelegate();
		check(Result);
		return *Result;
	}
};

#undef UE_API
```

## 二、逐段讲解（先讲"为什么"再讲"是什么"）

### 1. `#define UE_API TENKAICHIGAME_API` 与 `#undef UE_API`

- **解决什么问题**：`ConditionalBroadcastTeamChanged` 是一个静态函数，需要在别的模块也能调用。
  函数前面要带本模块的 DLL 导出宏（`TENKAICHIGAME_API`）才能在链接时被其他模块看到。
- **为什么局部重定义**：把 `UE_API` 临时顶替成 `TENKAICHIGAME_API`，用完后 `#undef` 还原。
  这样写一行 `UE_API` 就等价于 `TENKAICHIGAME_API`，简洁，且不污染全局。

### 2. 委托 `FOnTenkaichiTeamIndexChangedDelegate`

- `DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams`：声明一个"三个参数、可多播、可序列化到蓝图"的委托。
- 三个参数：`ObjectChangingTeam`（谁换了队伍）、`OldTeamID`（旧队伍）、`NewTeamID`（新队伍）。
- 用途：UI 或系统监听它，得知"某人从红队切到蓝队"，从而刷新阵营颜色/规则。

### 3. 两个转换工具函数（内联）

- `GenericTeamIdToInteger`：引擎的 `FGenericTeamId` 本质是个 `uint8`。没队伍（`NoTeam`）转成 `INDEX_NONE`（即 -1）。
- `IntegerToGenericTeamId`：反过来，`INDEX_NONE` 转回 `NoTeam`，否则转成对应 `FGenericTeamId`。
- 为什么要转：委托参数用的是 `int32`，而引擎队伍类型是 `FGenericTeamId`，两者之间需要互转桥接。

### 4. 接口类本身

- `UINTERFACE(MinimalAPI, meta=(CannotImplementInterfaceInBlueprint))`：
  - `MinimalAPI`：接口函数不强制导出（只导出类型本身）。
  - `CannotImplementInterfaceInBlueprint`：禁止在蓝图里实现这个接口（保持纯 C++ 逻辑）。
- `class UTenkaichiTeamAgentInterface : public UGenericTeamAgentInterface`：**U 类（反射壳）继承引擎的队伍接口 U 壳**。
- `class ITenkaichiTeamAgentInterface : public IGenericTeamAgentInterface`：**I 类（实际逻辑）继承引擎的队伍接口 I 类**。
  → 因此自动拥有引擎的 `SetGenericTeamId` / `GetGenericTeamId` 等队伍查询能力。

### 5. 三个方法

| 方法 | 类型 | 干嘛的 |
|------|------|--------|
| `GetOnTeamIndexChangedDelegate()` | 虚函数 | 返回"队伍变更委托"指针，默认 `nullptr`，由实现类覆写 |
| `ConditionalBroadcastTeamChanged(...)` | **静态** | 判断新旧队伍不同，才广播委托；相同就跳过 |
| `GetTeamChangedDelegateChecked()` | 非虚 | 取委托并 `check` 断言非空（实现类没覆写会崩，用于兜底） |

> 注意 `ConditionalBroadcastTeamChanged` 是**静态成员函数**（带 `static` 语义，靠 `This` 参数访问对象），
> 它不属于某个具体实例，而是"给定任意实现对象，判断并广播"。实现写在 `.cpp` 里（下一步教）。
