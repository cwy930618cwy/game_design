# P07.9 `AsyncAction_ObserveTeam` —— `.h` 声明层

## 一、本文件要解决什么

把类总 md 里"给蓝图的订阅推送服务"落成真实的 `.h` 文件。
`AsyncAction_ObserveTeam.h` 定义 `UAsyncAction_ObserveTeam` 类，继承**引擎**的 `UCancellableAsyncAction`。

**这个 `.h` 只有 1 个委托 + 1 个类（5 个成员）**，但它是蓝图节点的"对外合同"：

| 成员 | 分类 | 对蓝图意味着什么 |
|------|------|-----------------|
| `FTeamObservedAsyncDelegate OnTeamChanged` | 委托属性 | 蓝图节点右侧那个 **红色输出引脚** |
| `static ObserveTeam(UObject*)` | 静态工厂 | 蓝图节点本体（拖出来的那个方块） |
| `Activate()` / `SetReadyToDestroy()` | 引擎虚函数覆写 | 控制"什么时候开始订阅 / 什么时候解绑" |
| `InternalObserveTeamChanges` | 私有静态 | 真正 `NewObject` 的地方 |
| `OnWatchedAgentChangedTeam` | 私有回调 | 收到换队通知 → 转成蓝图广播 |
| `TeamInterfacePtr` | 私有字段 | 记住"我在监听谁" |

**它和 P07 其他类的三点不同（重点）**：

| 对比项 | P07.6 TeamSubsystem | P07.8 TeamCheats | **P07.9 AsyncAction_ObserveTeam** |
|--------|--------------------|------------------|-------------------------------|
| 类名前缀 | `UTenkaichiTeamSubsystem` | `UTenkaichiTeamCheats` | **`UAsyncAction_ObserveTeam`（无前缀，保持原样）** |
| 基类 | `UWorldSubsystem` | `UCheatManagerExtension` | **`UCancellableAsyncAction`（引擎）** |
| UHT 构造宏 | `GENERATED_BODY()` | `GENERATED_BODY()` | **`GENERATED_UCLASS_BODY()`（需自写构造函数）** |
| 导出宏 | `#define UE_API` + 逐个方法带 | 无 | **无 `UE_API`，无 `#define UE_API`** |
| 服务对象 | C++ 逻辑层 | 开发者控制台 | **蓝图** |

> **为什么类名不加 `Tenkaichi`？**
> 铁律 24 是"把 `Lyra` 换成 `Tenkaichi`，其余一字不砍"——Lyra 这个类**本来就没有 `Lyra` 前缀**
> （`E:\ue5\LyraStarterGame5.6\...\Teams\AsyncAction_ObserveTeam.h:20`），所以替换后**保持原样**。
> 新建文件就叫 `AsyncAction_ObserveTeam.h`，**不要**画蛇添足写成 `TenkaichiAsyncAction_ObserveTeam.h`。

> **为什么是 `GENERATED_UCLASS_BODY()` 而不是 `GENERATED_BODY()`？**
> 本类**要自定义构造函数**（`.cpp` 里有 `UAsyncAction_ObserveTeam::UAsyncAction_ObserveTeam(const FObjectInitializer&)`），
> 所以用 `GENERATED_UCLASS_BODY()`。**这是两者唯一的区别**，照抄 Lyra 不要互换。

> 依赖：3 个引擎头文件 + 2 个前置声明（其中 `ITenkaichiTeamAgentInterface` 是 P07.1 ✅ 已落盘），**零挂起可独立编译**。

## 三、完整代码（注释已中文化）

你新建文件：`Source/TenkaichiGame/Teams/AsyncAction_ObserveTeam.h`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "Engine/CancellableAsyncAction.h"
#include "UObject/ScriptInterface.h"
#include "UObject/WeakInterfacePtr.h"

#include "AsyncAction_ObserveTeam.generated.h"

class ITenkaichiTeamAgentInterface;
struct FFrame;

DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FTeamObservedAsyncDelegate, bool, bTeamSet, int32, TeamId);

/**
 * 监听指定对象上的队伍变化
 */
UCLASS()
class UAsyncAction_ObserveTeam : public UCancellableAsyncAction
{
	GENERATED_UCLASS_BODY()

public:
	// 监听指定队伍代理（TeamAgent）上的队伍变化
	//  - 它会立刻触发一次，给出当前的队伍归属
	//  - 对于任何可能属于某个队伍的对象（实现了 ITenkaichiTeamAgentInterface 的），
	//    它之后还会持续监听队伍归属的变化
	UFUNCTION(BlueprintCallable, meta=(BlueprintInternalUseOnly="true", Keywords="Watch"))
	static UAsyncAction_ObserveTeam* ObserveTeam(UObject* TeamAgent);

	//~UBlueprintAsyncActionBase 接口开始
	// 节点被激活时调用：订阅队伍变化委托，并立刻广播一次当前的队伍归属
	virtual void Activate() override;
	// 节点即将销毁或被取消时调用：解除委托订阅，避免对象销毁后仍被回调
	virtual void SetReadyToDestroy() override;
	//~UBlueprintAsyncActionBase 接口结束

public:
	// 当队伍被设置或改变时调用
	UPROPERTY(BlueprintAssignable)
	FTeamObservedAsyncDelegate OnTeamChanged;

private:
	// 监听指定队伍 Actor 上的队伍变化
	static UAsyncAction_ObserveTeam* InternalObserveTeamChanges(TScriptInterface<ITenkaichiTeamAgentInterface> TeamActor);

private:
	// 被监听对象换队时的回调：把新队伍号转成蓝图委托再广播一次
	UFUNCTION()
	void OnWatchedAgentChangedTeam(UObject* TeamAgent, int32 OldTeam, int32 NewTeam);

	// 记住"我在监听谁"，用弱引用保存，避免延长被监听对象的生命周期
	TWeakInterfacePtr<ITenkaichiTeamAgentInterface> TeamInterfacePtr;
};
```

## 四、逐段讲解

### 4.1 文件头 + 三个 include（第 1~9 行）

```cpp
#pragma once

#include "Engine/CancellableAsyncAction.h"
#include "UObject/ScriptInterface.h"
#include "UObject/WeakInterfacePtr.h"

#include "AsyncAction_ObserveTeam.generated.h"
```

| 行 | 干什么 |
|----|--------|
| `#pragma once` | 防重复包含（所有 `.h` 标配） |
| `Engine/CancellableAsyncAction.h` | ★ **基类来源**，提供 `UCancellableAsyncAction`。引擎文件，不挂起 |
| `UObject/ScriptInterface.h` | 提供 `TScriptInterface<T>` —— 第 44 行 `InternalObserveTeamChanges` 的形参类型 |
| `UObject/WeakInterfacePtr.h` | 提供 `TWeakInterfacePtr<T>` —— 第 50 行成员类型 |
| `AsyncAction_ObserveTeam.generated.h` | UHT 生成头，**文件名必须与本文件同名** |

> 📌 **`generated.h` 必须放最后**：UHT 要求它是最后一个 include，否则报 `expected an include at the end`。
> 📌 **后两个 include 不是可选的**——本文件在**类型定义里直接用到** `TScriptInterface` / `TWeakInterfacePtr`，
> 光靠前置声明不够（成员/形参需要完整类型），必须 include。
> 对比 P07.8 只前置声明 `UObject`/`FFrame`（那两个只出现在指针/生成的 thunk 里）。

### 4.2 两个前置声明（第 11~12 行）

```cpp
class ITenkaichiTeamAgentInterface;
struct FFrame;
```

| 声明 | 为什么需要 |
|------|-----------|
| `class ITenkaichiTeamAgentInterface;` | ⚠️ 注意是 **`I` 开头**（接口实现类），不是 `UTenkaichiTeamAgentInterface`。本文件只在指针/模板参数里用它 → 前置声明即可，**不需要 include**（这样 `.h` 才零依赖） |
| `struct FFrame;` | UHT 生成的蓝图 thunk 函数（`execXxx`）参数里用到，是 UHT 的固定套路 |

> 💡 **为什么不 include `Teams/TenkaichiTeamAgentInterface.h`？**
> 因为 `.h` 里只把它当**模板参数**（`TScriptInterface<T>` / `TWeakInterfacePtr<T>`），不访问它任何成员。
> 前置声明就够 → `.h` 保持"零项目内依赖"，编译更快、也更不容易被引擎外的改动波及。
> **真正的 include 放到 `.cpp` 里**（那里才调 `GetTeamChangedDelegateChecked()`）。
> 这是 C++ 的标准做法：**能前置声明就不 include**。

### 4.3 委托声明（第 14 行）

```cpp
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FTeamObservedAsyncDelegate, bool, bTeamSet, int32, TeamId);
```

| 元素 | 说明 |
|------|------|
| `DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams` | UHT 宏：声明一个**蓝图可绑定的多播委托**，带 2 个参数 |
| 第 1 个参数 `FTeamObservedAsyncDelegate` | 委托类型名（**无 `Lyra` 前缀，保留原样**） |
| 第 2~3 个 `bool, bTeamSet` | "有没有队伍"：`true` = 有队，`false` = 无队（`INDEX_NONE`） |
| 第 4~5 个 `int32, TeamId` | 队伍号。无队时是 `INDEX_NONE`（即 `-1`） |

> 📌 **`DYNAMIC` 是关键**：只有 `DECLARE_DYNAMIC_*` 系列的委托才能被 `UPROPERTY(BlueprintAssignable)` 标记、
> 才能在蓝图里拉线绑定。普通 `DECLARE_MULTICAST_DELEGATE` 只能 C++ 用。
>
> 📌 **为什么两个参数要一起给？** 因为"没队伍"也是一个合法状态。
> 如果只传 `TeamId = -1`，蓝图还得额外判断；Lyra 直接把"有没有"单独做成 `bool`，蓝图一眼看懂。

### 4.4 类声明（第 16~23 行）

```cpp
/**
 * 监听指定对象上的队伍变化
 */
UCLASS()
class UAsyncAction_ObserveTeam : public UCancellableAsyncAction
{
	GENERATED_UCLASS_BODY()
```

| 元素 | 说明 |
|------|------|
| `UCLASS()` | **空标记**——没有 `MinimalAPI`、没有 `BlueprintType`、没有 `Abstract`。Lyra 原样 |
| `UCancellableAsyncAction` | 引擎基类（`CancellableAsyncAction.h:15`），教学分级 **① 只讲不拆** |
| `GENERATED_UCLASS_BODY()` | ⚠️ **本文件特殊点**——带 `UCLASS` 后缀的版本，**要求 `.cpp` 里必须写构造函数** |

> **为什么本类要用 `GENERATED_UCLASS_BODY()`？**
> 因为它**必须自定义构造函数**（`.cpp` 第 9~12 行），而 `GENERATED_BODY()` 生成的是"不接受 `FObjectInitializer` 参数"的版本。
> 两者不能混用：**写了 `GENERATED_UCLASS_BODY()` 却在 `.cpp` 里不写构造函数 → 链接报错**（符号找不到）。
>
> **为什么这里要自定义构造函数？**
> Lyra 原样如此，构造函数体只有 `Super(ObjectInitializer)` 一行。看起来"多余"，但 Lyra 就是这么写的——
> 它给下游留了一个"想在构造时多干点事"的钩子。**照抄，不要自作主张删掉换成 `GENERATED_BODY()`。**

### 4.5 静态工厂 `ObserveTeam`（第 25~30 行）

```cpp
	// 监听指定队伍代理（TeamAgent）上的队伍变化
	//  - 它会立刻触发一次，给出当前的队伍归属
	//  - 对于任何可能属于某个队伍的对象（实现了 ITenkaichiTeamAgentInterface 的），
	//    它之后还会持续监听队伍归属的变化
	UFUNCTION(BlueprintCallable, meta=(BlueprintInternalUseOnly="true", Keywords="Watch"))
	static UAsyncAction_ObserveTeam* ObserveTeam(UObject* TeamAgent);
```

#### `UFUNCTION` 三件套

| 标记 | 含义 |
|------|------|
| `BlueprintCallable` | 蓝图里能调 |
| `static` | **静态函数** → 蓝图里表现为一个"工厂节点"（不需要先有对象实例） |
| `meta=(BlueprintInternalUseOnly="true")` | ★ **不直接暴露给用户**：这个函数存在的唯一目的是让 UHT 生成那个异步节点，蓝图右键菜单里**搜不到**它本身 |
| `meta=(Keywords="Watch")` | 蓝图搜索关键词——搜 "Watch" 也能找到这个节点 |

> 💡 **`BlueprintInternalUseOnly` 是什么体验？**
> 蓝图里你拖出来的是 `[Observe Team]` 这个**异步节点**（带 `OnTeamChanged` 输出引脚），
> 而不是一个叫 "Observe Team" 的普通函数调用节点。
> 这个"节点"是 UHT 根据 `BlueprintCallable + static + 返回 UBlueprintAsyncActionBase 子类` 自动生成的
> （`UK2Node_AsyncAction`）。`BlueprintInternalUseOnly` 只是把底层的原始函数**藏起来**，避免重复。

#### 参数为什么是裸 `UObject*` 而不是 `TScriptInterface`？

```cpp
static UAsyncAction_ObserveTeam* ObserveTeam(UObject* TeamAgent);
```

因为**蓝图侧传进来的就是一个对象引用**（Actor / Component / 什么都行）。
Lyra 在这里不做类型限制，交给下一层 `InternalObserveTeamChanges` 的 `TScriptInterface` 隐式转换去处理。

> ⚠️ **隐患（Lyra 明知故犯）**：传进来的对象可能压根没实现队伍接口。
> Lyra 的处理是**层层判空**（`InternalObserveTeamChanges` 判 `TeamActor != nullptr`，
> `Activate()` 再判 `TeamInterfacePtr.Get()`），而不是在这里 `Cast` 拦截。
> **照抄，别"顺手加个 Cast"。**

#### 注释里那两句话很重要

Lyra 原文的注释直接告诉了调用者**这个节点的行为契约**：

1. **"会立刻触发一次"** → 你不用额外再查一次当前队伍
2. **"之后持续监听"** → 换队会再触发

这正好对应 `.cpp` 里 `Activate()` 的实现（下一步教）。

### 4.6 两个引擎虚函数覆写（第 32~35 行）

```cpp
	//~UBlueprintAsyncActionBase 接口开始
	// 节点被激活时调用：订阅队伍变化委托，并立刻广播一次当前的队伍归属
	virtual void Activate() override;
	// 节点即将销毁或被取消时调用：解除委托订阅，避免对象销毁后仍被回调
	virtual void SetReadyToDestroy() override;
	//~UBlueprintAsyncActionBase 接口结束
```

| 函数 | 谁在什么时候调它 | 本类的实现要干什么（见 `.cpp`） |
|------|-----------------|-------------------------------|
| `Activate()` | **引擎自动调**——蓝图节点被激活、委托已绑定好之后 | 取当前队伍 → `AddDynamic` 绑定 → **首次广播** → 失败则 `SetReadyToDestroy()` |
| `SetReadyToDestroy()` | 你（或引擎 `Cancel()`）显式调 | `Super` 之后 `RemoveAll(this)` **解绑委托** |

> ⚠️ **注释写的是 `UBlueprintAsyncActionBase`，但基类是 `UCancellableAsyncAction`**——
> 这是 **Lyra 原样**（源码第 32/35 行就是这么写的）。
> 因为这两个虚函数实际定义在祖父类 `UBlueprintAsyncActionBase` 里（`BlueprintAsyncActionBase.h:28/37`），
> `UCancellableAsyncAction` 只是继承没改。
> **按铁律 14/24：一字不砍，照抄这个注释**（只做中文化，见铁律 36）。

> 📌 **`Activate()` 和 `SetReadyToDestroy()` 必须成对**：
> 一个负责"订阅"，一个负责"退订"。漏了退订 → 对象销毁后委托还指向它 → **野指针崩溃**。
> 这是异步节点最常见的坑，Lyra 用 `SetReadyToDestroy` 统一兜底。

#### `InternalObserveTeamChanges`（第 44 行）


- **私有静态**——蓝图看不见（没有 `UFUNCTION`），只有 `ObserveTeam` 会调它

#### `OnWatchedAgentChangedTeam`（第 47~48 行）

```cpp
	UFUNCTION()
	void OnWatchedAgentChangedTeam(UObject* TeamAgent, int32 OldTeam, int32 NewTeam);
```

| 点 | 说明 |
|----|------|
| `UFUNCTION()` | **空标记但必须有**——`AddDynamic` 绑定的函数必须是 `UFUNCTION`，否则 UHT 不生成反射信息，绑定失败 |

| 命名 | `OnWatchedAgentChangedTeam` = "被监视的代理换了队时" |

> 📌 **参数个数/类型必须与委托严格一致**：`AddDynamic` 是运行时按名字绑定的，

#### `TWeakInterfacePtr`（第 50 行）

```cpp
	TWeakInterfacePtr<ITenkaichiTeamAgentInterface> TeamInterfacePtr;
```

| 对比 | 强引用（裸指针 / `TObjectPtr`） | **`TWeakInterfacePtr`（本类）** |
|------|------------------------------|-------------------------------|
| Actor 销毁后 | 指针悬空 → 访问崩溃 | `Get()` 自动返 `nullptr`，**安全** |
| 是否延长对象生命 | 是 → 可能内存泄漏 | 否 |
| 用法 | `Ptr->Method()` | `if (auto* P = Ptr.Get()) { P->Method(); }` |

> 💡 **为什么本类必须用弱引用？**
> 这个 AsyncAction 通过 `RegisterWithGameInstance` 挂在 GameInstance 上，**生命周期可能比被监听的 Actor 还长**。
> 用强引用会把 Actor 钉在内存里不放 → 泄漏 +  resurrect 后的逻辑错误。
> Lyra 统一用 `TWeakInterfacePtr` 兜底，判空即可。
