# 4.4.3 TeamPublicInfo —— 总 md

> 定位：TeamPublicInfo 是 4.4 队伍信息**三件套**（TeamInfoBase / PublicInfo / PrivateInfo）里的**第二件**。
> 三件套总览已在 `4.4_TeamInfoBase_总md.md` 讲过；本总 md 单独聚焦 **TeamPublicInfo 这一个类**的"为什么 + 全景"。

## 一、为什么要有 TeamPublicInfo

4.4.1/4.4.2 教了队伍**基类** `TeamInfoBase`（队号 + 标签栈 + 注册逻辑）。
但一支队伍除了"编号和标签"，还有**对外展示的样子**——队旗、配色、材质参数。这些所有玩家都要看得到。

Lyra 单独用一个类来装这份"公开外观"：**`TeamPublicInfo`**。它继承基类，只**新增一块"外观数据"**，其它全部复用。

> 类比：TeamInfoBase = 队伍档案，TeamPublicInfo = 队旗（对外展示）。

## 二、TeamPublicInfo 里有什么（全景）

继承 `ATenkaichiTeamInfoBase`，新增：

| 成员 | 类型 | 说明 |
|------|------|------|
| `TeamDisplayAsset` | `TObjectPtr<UTenkaichiTeamDisplayAsset>`（`ReplicatedUsing=OnRep_TeamDisplayAsset`） | 队伍外观数据（✅ 4.2 已教），只复制一次 |
| `GetTeamDisplayAsset()` | 内联 | 返回外观数据 |
| `SetTeamDisplayAsset(...)` | private | 服务器端设外观（只能设一次），给 `TeamCreationComponent` 用 |
| `OnRep_TeamDisplayAsset()` | UFUNCTION | 客户端收到外观复制时触发 |

**继承链带来的复制字段**：基类已有 `TeamTags` + `TeamId`，本类追加 `TeamDisplayAsset`。

## 四、关键理解点

### 概念 1：为什么公开外观要单独一个类？

- 队伍数据有**可见性差异**：外观/队名所有人看（Public），战术数据只有本队看（Private）。
- 拆成三个类，将来各自挂不同复制/可见策略。Public 类只放"所有客户端都要同步"的外观。

### 概念 2：`TObjectPtr` 是什么？

- UE5 的智能指针封装，用于 UPROPERTY 引用资产，配 GC 更安全。Lyra 用它，一比一保留。

### 概念 3：外观数据什么时候会被复制？

- `TeamId` / `TeamDisplayAsset` 都用 `COND_InitialOnly`——建队时一次性确定，之后基本不变，只复制一次。
- `TeamTags` 用 `Replicated`——标签可动态增减，持续同步。
