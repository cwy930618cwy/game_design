# 4.4 TeamInfoBase / TeamPublicInfo / TeamPrivateInfo —— 总 md

## 一、为什么要有这一节

阶段四 4.1 教了"队伍接口"（谁是哪队的），4.2 教了"队伍外观数据"（队伍长啥样）。现在教**"队伍本身"**——
一支队伍在游戏里是一个**实体 Actor**，它要记录"队号、队伍标签、队伍外观"，并在所有客户端同步。

Lyra 用**三个继承关系的 Actor 类**来表现一支队伍：

| 类 | 继承 | 干什么 |
|----|------|--------|
| `ALyraTeamInfoBase` | `AInfo` | 队伍**基类**：存队号 + 队伍标签栈，负责和 `TeamSubsystem` 注册 |
| `ALyraTeamPublicInfo` | `ALyraTeamInfoBase` | **公开**队伍信息：存"队伍外观数据"（`TeamDisplayAsset`），所有玩家都看得到 |
| `ALyraTeamPrivateInfo` | `ALyraTeamInfoBase` | **私有**队伍信息：占位，将来放"只有本队能看"的私有数据（当前空） |

> 类比：Base = 队伍档案，Public = 队旗（对外展示），Private = 队内机密（只有自己人能看）。

## 二、本文件里有什么（全景）

### 1. `TeamInfoBase`（基类，最关键）

- 继承 `AInfo`（引擎的"无碰撞 Actor"，适合做纯逻辑实体）。
- 两个 UPROPERTY 复制字段：
  - `TeamTags`（`FGameplayTagStackContainer`，`Replicated`）——队伍的标签栈（✅ L1 已教）。
  - `TeamId`（`int32`，`ReplicatedUsing=OnRep_TeamId`）——队号。
- 方法：`GetTeamId` / `SetTeamId` / `BeginPlay` / `EndPlay` / `RegisterWithTeamSubsystem` / `TryRegisterWithTeamSubsystem` / `OnRep_TeamId` / `GetLifetimeReplicatedProps`。

### 2. `TeamPublicInfo`（公开信息）

- 继承 `TeamInfoBase`，加一个 `TeamDisplayAsset`（队伍外观，`ReplicatedUsing=OnRep_TeamDisplayAsset`）。
- 方法：`GetTeamDisplayAsset` / `SetTeamDisplayAsset` / `OnRep_TeamDisplayAsset`。

### 3. `TeamPrivateInfo`（私有信息）

- 继承 `TeamInfoBase`，只有构造函数（空实现），占位。

## 四、关键理解点

### 概念 1：`AInfo` 是什么？

- `AInfo` 是引擎的"无碰撞 Actor"，通常用于纯逻辑实体（如比赛状态、规则）。
- 它默认不复制移动、不需要场景位置。`TeamInfoBase` 继承它，因为它本质是"一个数据/状态的载体"，不是可见物体。

### 概念 2：复制（Replication）怎么配？

- `TeamId` 用 `ReplicatedUsing=OnRep_TeamId`：服务器改了队号 → 同步到客户端 → 触发 `OnRep_TeamId` 回调。
- `COND_InitialOnly`：只在**初次复制**时同步（队号建好后基本不变）。
- `TeamTags` 用 `Replicated`：服务器 → 客户端持续同步。
- `GetLifetimeReplicatedProps` 里用 `DOREPLIFETIME` / `DOREPLIFETIME_CONDITION` 声明。

### 概念 3：为什么用"基类 + 公开 + 私有"三层？

- 不同队伍数据有不同的可见性：公开的（外观/队名）所有人看；私有的（队内战术数据）只有本队看。
- 拆开三个类，将来各自挂不同的复制/可见策略，互不干扰。
