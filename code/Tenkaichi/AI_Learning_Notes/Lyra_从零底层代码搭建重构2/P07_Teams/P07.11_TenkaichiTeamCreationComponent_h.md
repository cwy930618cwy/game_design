# P07.11 `TenkaichiTeamCreationComponent` —— `.h` 声明层

## 一、本文件要解决什么

把类总 md 里"开局装配工"落成真实的 `.h` 文件。
`TenkaichiTeamCreationComponent.h` 定义 `UTenkaichiTeamCreationComponent`，继承**引擎 ModularGameplay 插件**的 `UGameStateComponent`。

本文件 **64 行 / 1 个类（12 个成员）**，被 **3 个宏切成 4 段**——这是 P07 里结构最特殊的一个 `.h`：

```
public:     构造函数 + IsDataValid(#if WITH_EDITOR) + BeginPlay
private:    OnExperienceLoaded
protected:  3 个配置 UPROPERTY（蓝图子类填的"输入"）
#if WITH_SERVER_CODE
protected:  3 个服务器虚函数
private:    3 个服务器私有方法
#endif
```

### 三个宏分区一眼看懂

| 宏 | 包住什么 | 为什么 |
|----|---------|--------|
| `#if WITH_EDITOR` | `IsDataValid` | 只在编辑器里编译（数据校验是编辑器功能） |
| `#if WITH_SERVER_CODE` | 6 个 `Server*` 方法 + `OnPlayerInitialized` + `GetLeastPopulatedTeamID` | 只在**含服务器逻辑**的构建里编译（纯客户端包不需要） |
| （无宏） | 构造函数 / `BeginPlay` / `OnExperienceLoaded` / 3 个配置属性 | 所有构建都要 |

### 十二个成员的角色

| 成员 | 分区 | 一句话 |
|------|------|--------|
| 构造函数 | public | 设 2 个 Info 类的默认值 |
| `IsDataValid` | public（EDITOR） | 编辑器数据校验（Lyra 里是空壳 TODO） |
| `BeginPlay` | public | 等 Experience 加载完 → 注册回调 |
| `OnExperienceLoaded` | private | 加载完的回调：有权限就建队 + 分队 |
| `TeamsToCreate` | protected | ★ **队伍配置表**：队号 → 外观资产 |
| `PublicTeamInfoClass` | protected | 要 Spawn 的公开信息类 |
| `PrivateTeamInfoClass` | protected | 要 Spawn 的私有信息类 |
| `ServerCreateTeams` | protected（SERVER） | 遍历配置表建队 |
| `ServerAssignPlayersToTeams` | protected（SERVER） | 给已在线玩家分队 + 监听新玩家 |
| `ServerChooseTeamForPlayer` | protected（SERVER） | ★ 单个玩家的分队决策（观众剥队） |
| `OnPlayerInitialized` | private（SERVER） | 新玩家登录回调 |
| `ServerCreateTeam` | private（SERVER） | ★ 真的 Spawn 一对 Info Actor |
| `GetLeastPopulatedTeamID` | private（SERVER） | ★ 找人最少的队（含平局规则） |

#pragma once

#include "Components/GameStateComponent.h"

#include "TenkaichiTeamCreationComponent.generated.h"

class UTenkaichiExperienceDefinition;
class ATenkaichiTeamPublicInfo;
class ATenkaichiTeamPrivateInfo;
class ATenkaichiPlayerState;
class AGameModeBase;
class APlayerController;
class UTenkaichiTeamDisplayAsset;

UCLASS(Blueprintable)
class UTenkaichiTeamCreationComponent : public UGameStateComponent
{
	GENERATED_BODY()

public:
	// 构造函数：给两个队伍信息类填上默认类型
	UTenkaichiTeamCreationComponent(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	//~UObject 接口开始

	// 编辑器里校验数据是否合法（当前只调用父类，具体校验待补）

	//~UObject 接口结束

	//~UActorComponent 接口开始
	// 组件开始运行时调用：等待体验（Experience）加载完成后再开始建队
	virtual void BeginPlay() override;
	//~UActorComponent 接口结束

private:
	// 体验加载完成的回调：在服务器端创建所有队伍并给已有玩家分配队伍
	void OnExperienceLoaded(const UTenkaichiExperienceDefinition* Experience);

protected:
	// 要创建的队伍列表（队号 → 外观资产的映射，外观资产可以留空）
	UPROPERTY(EditDefaultsOnly, Category = Teams)
	TMap<uint8, TObjectPtr<UTenkaichiTeamDisplayAsset>> TeamsToCreate;

	// 生成"公开队伍信息"Actor 所用的类
	UPROPERTY(EditDefaultsOnly, Category=Teams)
	TSubclassOf<ATenkaichiTeamPublicInfo> PublicTeamInfoClass;

	// 生成"私有队伍信息"Actor 所用的类
	UPROPERTY(EditDefaultsOnly, Category=Teams)
	TSubclassOf<ATenkaichiTeamPrivateInfo> PrivateTeamInfoClass;

#if WITH_SERVER_CODE
protected:
	// 服务器端：按配置表逐个创建队伍
	virtual void ServerCreateTeams();
	// 服务器端：给当前已存在的玩家分配队伍，并监听之后新登录的玩家
	virtual void ServerAssignPlayersToTeams();

	/** 为给定的 PlayerState 设置队伍 ID。仅观战的 PlayerState 会被解除所有队伍关联。 */
	virtual void ServerChooseTeamForPlayer(ATenkaichiPlayerState* PS);

private:
	// 新玩家初始化完成的回调：为其分配队伍
	void OnPlayerInitialized(AGameModeBase* GameMode, AController* NewPlayer);
	// 服务器端：为指定队号生成一对队伍信息 Actor（公开 + 私有）并设置外观
	void ServerCreateTeam(int32 TeamId, UTenkaichiTeamDisplayAsset* DisplayAsset);

	/** 返回当前人数最少的队伍 ID，若没有任何有效队伍则返回 INDEX_NONE */
	int32 GetLeastPopulatedTeamID() const;
#endif
};

### 4.3 类声明 + `UCLASS(Blueprintable)`（第 17~23 行）

```cpp
UCLASS(Blueprintable)
class UTenkaichiTeamCreationComponent : public UGameStateComponent
{
	GENERATED_BODY()

public:
	// 构造函数：给两个队伍信息类填上默认类型
	UTenkaichiTeamCreationComponent(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

| 元素 | 说明 |
|------|------|
| **`UCLASS(Blueprintable)`** | ★ **本类特殊点**——P07 其他类都是空 `UCLASS()`。允许**蓝图继承本类** |
| `UGameStateComponent` | 引擎 ModularGameplay 插件（`GameStateComponent.h:16`），教学分级 ① |
| `GENERATED_BODY()` | 普通版本（对比 P07.9/10 的 `GENERATED_UCLASS_BODY()`） |
| 构造函数**带默认参数** | `= FObjectInitializer::Get()` —— 不传就用全局默认初始化器 |

#### 为什么本类必须 `Blueprintable`

因为 `TeamsToCreate`（队伍配置表）是 **`EditDefaultsOnly`**——
只能在**蓝图默认值**里配。要配就得有蓝图子类：

```
B_TeamCreation_5v5（蓝图继承自本类）
   └─ TeamsToCreate = { 0 → DA_BlueTeam, 1 → DA_RedTeam }

B_TeamCreation_FFA
   └─ TeamsToCreate = { 0 → DA_P0, 1 → DA_P1, ... }
```

> 💡 **类比**：C++ 类是"**模板**"，蓝图子类是"**填好的表单**"。
> 没有 `Blueprintable`，你就只能靠改 C++ 代码换队伍配置——那太蠢了。

#### 为什么这里用 `GENERATED_BODY()` 而 P07.9/10 用 `GENERATED_UCLASS_BODY()`

因为**构造函数带默认参数**：

```cpp
UTenkaichiTeamCreationComponent(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

有默认参数 → 在 `.h` 里**声明**即可（`.cpp` 里再给出实现，但**不需要** `GENERATED_UCLASS_BODY()` 那套）。
对比 P07.9/10 的构造函数**没有默认参数**且在 `.h` 里**不声明** → 必须用 `GENERATED_UCLASS_BODY()`。

> ⚠️ 三个 `AsyncAction` / 本组件的宏选择**都是 Lyra 原样**，别互换。
> 判断口诀：**`.h` 里有没有声明构造函数？有 → `GENERATED_BODY()`；没有 → `GENERATED_UCLASS_BODY()`**。

#### `TeamsToCreate`

| 元素 | 说明 |
|------|------|
| `TMap<uint8, ...>` | **队号 → 外观资产**。键是 `uint8`，对应引擎 `FGenericTeamId` 的内部类型（`GenericTeamAgentInterface.h`） |
| `TObjectPtr<UTenkaichiTeamDisplayAsset>` | UE5 的对象指针包装（支持 UHT 反射 + GC 追踪） |
| `EditDefaultsOnly` | **只能在蓝图默认值里配**，运行时改不了 |
| `Category = Teams` | 细节面板里归到 "Teams" 分类 |

> 📌 **外观资产可以留空** —— Lyra 注释原话："the display asset can be left unset if desired"。
> 留空 = 这个队没有特殊外观，走默认。

#### 两个 `TSubclassOf<...>`

| 元素 | 说明 |
|------|------|
| `TSubclassOf<ATenkaichiTeamPublicInfo>` | **"要 Spawn 哪个类"** 的类型安全包装。蓝图里表现为一个**类选择器下拉框** |
| 默认值 | `.cpp` 构造函数里设成 `ATenkaichiTeamPublicInfo::StaticClass()` |
| 为什么要可配 | 允许蓝图子类**换成自己的派生类**（比如加了额外队伍数据的 `B_MyTeamInfo`） |

> 💡 **为什么不直接 Spawn `ATenkaichiTeamPublicInfo`？**
> 因为 Lyra 想留扩展点：游戏可以在蓝图里派生一个带额外数据的队伍信息类，
> 然后在 `TeamCreationComponent` 的蓝图子类里把它选上——**全程不用改 C++**。

> ⚠️ **为什么是 `protected` 而不是 `private`？**
> 因为**蓝图子类要能读写**它们。`private` 蓝图访问不到。

### 4.8 `#if WITH_SERVER_CODE` 段（第 49~63 行）

```cpp
#if WITH_SERVER_CODE
protected:
	// 服务器端：按配置表逐个创建队伍
	virtual void ServerCreateTeams();
	// 服务器端：给当前已存在的玩家分配队伍，并监听之后新登录的玩家
	virtual void ServerAssignPlayersToTeams();

	/** 为给定的 PlayerState 设置队伍 ID。仅观战的 PlayerState 会被解除所有队伍关联。 */
	virtual void ServerChooseTeamForPlayer(ATenkaichiPlayerState* PS);

private:
	// 新玩家初始化完成的回调：为其分配队伍
	void OnPlayerInitialized(AGameModeBase* GameMode, AController* NewPlayer);
	// 服务器端：为指定队号生成一对队伍信息 Actor（公开 + 私有）并设置外观
	void ServerCreateTeam(int32 TeamId, UTenkaichiTeamDisplayAsset* DisplayAsset);

	/** 返回当前人数最少的队伍 ID，若没有任何有效队伍则返回 INDEX_NONE */
	int32 GetLeastPopulatedTeamID() const;
#endif
};
```

#### `WITH_SERVER_CODE` 是什么

| 宏 | 含义 |
|----|------|
| `WITH_SERVER_CODE` | 引擎宏：**当前构建是否含服务器逻辑** |
| 纯客户端包（`Client`） | `0` → 这 6 个方法**根本不编译进去** |
| 服务器 / 独立 / 编辑器 | `1` → 正常编译 |

> 💡 **两个好处**：
> ① **减小客户端包体**——建队/分队逻辑客户端用不到
> ② **防作弊**——客户端连代码都没有，无从篡改

#### 三个 `virtual`（可扩展点）

| 方法 | 为什么是 `virtual` |
|------|------------------|
| `ServerCreateTeams()` | 允许子类改"建队流程"（比如加个"随机打乱队号"） |
| `ServerAssignPlayersToTeams()` | 允许子类改"分队流程"（比如按段位分队而不是按人数） |
| `ServerChooseTeamForPlayer(PS)` | ★ 允许子类改"**单个玩家怎么分队**"（最常见的扩展点） |

> 📌 **这就是"框架类"的设计**：Lyra 给默认实现（按人数均衡），
> 你想改成"按段位/按好友关系/随机" → **派生一个子类覆写这一个函数**即可。

对比三个 `private` 非虚函数（`OnPlayerInitialized` / `ServerCreateTeam` / `GetLeastPopulatedTeamID`）——
它们是**内部实现细节**，Lyra 不打算让你改。

#### 注意两段注释风格不同

```cpp
	// 服务器端：按配置表逐个创建队伍                              ← 我们用 //
	/** 为给定的 PlayerState 设置队伍 ID。... */                   ← Lyra 原本用 /** */
```

- Lyra **原本有** `/** */` 文档注释的两处（`ServerChooseTeamForPlayer` / `GetLeastPopulatedTeamID`）→ **保留 `/** */` 格式 + 中文化**（铁律 21）
- Lyra **原本没有**注释的 → **补 `//`**（铁律 32）

> ⚠️ **别统一成一种**——Lyra 原样是 `/** */` 就保持 `/** */`，只把里面英文翻译成中文。

#### `OnPlayerInitialized` 的两个形参

```cpp
void OnPlayerInitialized(AGameModeBase* GameMode, AController* NewPlayer);
```

| 形参 | 说明 |
|------|------|
| `AGameModeBase* GameMode` | 触发事件的 GameMode（**引擎基类**，不是 `ATenkaichiGameMode`——Lyra 刻意用基类减少耦合） |
| `AController* NewPlayer` | 新登录的玩家控制器（引擎类） |

> 💡 签名必须匹配 P13 `ATenkaichiGameMode::OnGameModePlayerInitialized` 委托的签名。
> 那个委托不存在时，本声明**依然能编译**（只是指针参数）。
