#include "LyraLogChannels.h"
#include "GameFramework/Actor.h"

DEFINE_LOG_CATEGORY(LogLyra);
DEFINE_LOG_CATEGORY(LogLyraExperience);
DEFINE_LOG_CATEGORY(LogLyraAbilitySystem);
DEFINE_LOG_CATEGORY(LogLyraTeams);

FString GetClientServerContextString(UObject* ContextObject)
{
	ENetRole Role = ROLE_None;

	if (AActor* Actor = Cast<AActor>(ContextObject))
	{
		Role = Actor->GetLocalRole();
	}
	else if (UActorComponent* Component = Cast<UActorComponent>(ContextObject))
	{
		Role = Component->GetOwnerRole();
	}

	if (Role != ROLE_None)
	{
		return (Role == ROLE_Authority) ? TEXT("Server") : TEXT("Client");
	}
	else
	{
#if WITH_EDITOR

		{
			extern ENGINE_API FString GPlayInEditorContextString;
			return GPlayInEditorContextString;
		}
#endif
	}

	return TEXT("[]");
}

## 三、逐段拆解（先讲清为什么，再给代码）

### 段 1：include（第 3-4 行）

```cpp
#include "LyraLogChannels.h"
#include "GameFramework/Actor.h"
```

- `#include "LyraLogChannels.h"`：要用 `.h` 里声明的 `LogLyra` 等符号和函数声明，得先引进来。
- `#include "GameFramework/Actor.h"`：因为下面要 `Cast<AActor>` 和 `Cast<UActorComponent>`，需要 `AActor` / `UActorComponent` 的完整定义（不只是前置声明），所以 include 这个头文件。

### 段 2：定义 4 个日志通道（第 6-9 行）

```cpp
DEFINE_LOG_CATEGORY(LogLyra);
DEFINE_LOG_CATEGORY(LogLyraExperience);
DEFINE_LOG_CATEGORY(LogLyraAbilitySystem);
DEFINE_LOG_CATEGORY(LogLyraTeams);
```

这就是「定义」——和 `.h` 里的「声明」成对（总 md 概念 ① 讲过：`DECLARE` 在 `.h`，`DEFINE` 在 `.cpp`）。`DEFINE_LOG_CATEGORY(名字)` 真正分配这个日志分类的存储。**必须 4 个都定义，漏一个就链接报错。**

### 段 3：工具函数 `GetClientServerContextString`（第 11-40 行）

这是本步的重点，逐行讲：

#### 第 13 行：`ENetRole Role = ROLE_None;`

`ENetRole` 是 UE 网络里表示「角色权限」的枚举，有三种值：`ROLE_None`（未定）、`ROLE_Authority`（权威端，即 Server）、`ROLE_SimulatedProxy` / `ROLE_AutonomousProxy`（模拟/自主代理，即 Client 端）。这里先初始化为 `ROLE_None`。

#### 第 15-22 行：根据传入对象，取出它的「角色权限」

```cpp
if (AActor* Actor = Cast<AActor>(ContextObject))
{
	Role = Actor->GetLocalRole();
}
else if (UActorComponent* Component = Cast<UActorComponent>(ContextObject))
{
	Role = Component->GetOwnerRole();
}
```

- 传进来的 `ContextObject` 可能是 `AActor`，也可能是挂在 Actor 上的 `UActorComponent`（组件）。这里用 `Cast` 判断它到底是哪种。
- 是 `AActor` → 调 `GetLocalRole()` 拿它自己的角色权限。
- 是 `UActorComponent` → 调 `GetOwnerRole()` 拿它**所属 Actor** 的角色权限（组件自己没有独立权限，跟随宿主 Actor）。

> 这就是为什么函数参数是 `UObject*`——它足够宽，能同时接收 Actor 和 Component，内部再用 `Cast` 精确判断。

#### 第 24-27 行：有权限 → 拼出 Server / Client

```cpp
if (Role != ROLE_None)
{
	return (Role == ROLE_Authority) ? TEXT("Server") : TEXT("Client");
}
```

- 如果取到了权限（不是 `ROLE_None`）：
  - `ROLE_Authority` → 返回 `"Server"`；
  - 其它（各种 Proxy）→ 返回 `"Client"`。
- 三目运算符 `? :` 就是「如果...否则...」的简写。

#### 第 28-37 行：编辑器 PIE 场景的特判

```cpp
else
{
#if WITH_EDITOR
	if (GIsEditor)
	{
		extern ENGINE_API FString GPlayInEditorContextString;
		return GPlayInEditorContextString;
	}
#endif
}
```

- 如果 `Role == ROLE_None`（比如传入 `nullptr`，或对象不属于网络世界），再判断：**是不是在编辑器里 PIE 运行**。
- `#if WITH_EDITOR` 是预处理宏：**只有编译编辑器版本时才包含这段代码**（打包发布版时这段直接不编译进去）。
- `GIsEditor` = 运行时判断「当前是不是编辑器环境」。
- 如果两者都满足，返回引擎的 `GPlayInEditorContextString`——这是引擎在 PIE 时维护的一个字符串，记录了「当前是哪个 PIE 实例 / 第几个客户端」（如 `"Client 1"`）。用 `extern ENGINE_API` 声明引用引擎的这个全局变量（它在 `UnrealEngine.h` 里，已在源码核实）。

#### 第 39 行：兜底返回 `"[]"`

```cpp
return TEXT("[]");
```

- 如果都不是（非编辑器、也没权限），返回 `"[]"`——一个「空」的占位，表示「不知道是哪端」。以后打日志拼字符串时，这个 `[]` 就代表「无上下文」。

---

## 四、关键点：为什么返回的字符串这么有用（用途预告）

这个函数最终返回三种可能的字符串之一：`"Server"` / `"Client"` / `"[]"`（或 PIE 下的 `"Client 1"` 等）。

**用途**：联机调试时，把这段塞进日志开头，比如：

```
UE_LOG(LogTenkaichiAbilitySystem, Log, TEXT("%s 某技能触发了"), *GetClientServerContextString(GetOwner()));
```

这样 Server 和 Client 各打各的日志时，你一眼就能分清「这条是 Server 打来的，还是 Client 打来的」，不用对着乱糟糟的日志猜。**这是 Lyra 联机调试的一个基础设施**。

> 现在先知道「它干嘛的、返回什么」即可。真正在 `UE_LOG` 里用它，是后面 L4/L5 业务层打日志时的事（详细原理到时再展开，铁律 27）。

## 六、逐段回扣「为什么」

| 代码 | 为什么这么写 |
|------|-------------|
| `#include "TenkaichiLogChannels.h"` | 引用 `.h` 里声明的 4 个通道 + 函数声明 |
| `#include "GameFramework/Actor.h"` | 要 `Cast<AActor>`/`Cast<UActorComponent>`，需要完整类定义 |
| `DEFINE_LOG_CATEGORY(LogTenkaichi);` ×4 | 定义 `.h` 里声明的 4 个通道，成对（`DECLARE` ↔ `DEFINE`） |
| `ENetRole Role = ROLE_None;` | 用 UE 网络权限枚举，先初始化「未定」 |

| `Role == ROLE_Authority ? "Server" : "Client"` | 权威端=Server，代理端=Client |
| `#if WITH_EDITOR` + `GIsEditor` | 只在编辑器 PIE 下编译/运行这段，返回 PIE 实例字符串 |
| `extern ENGINE_API FString GPlayInEditorContextString;` | 引用引擎维护的 PIE 上下文全局变量 |
| `return TEXT("[]");` | 兜底：无上下文时返回空占位 |
