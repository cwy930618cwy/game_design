## 一、这个类解决什么问题（先讲为什么）

CommonGame 插件定义 `UCommonMessagingSubsystem`——一个**统一的消息接口**，提供 `ShowConfirmation`（确认框）和 `ShowError`（错误框）两个纯虚函数。项目的其他地方（登录失败、网络错误等）都通过这个接口弹窗，**不用关心具体怎么弹**。

Lyra 继承它实现：把对话框（`UCommonGameDialog`）推到 `UI.Layer.Modal` 层。

> **类比**：`UCommonMessagingSubsystem` 是"弹窗服务台的标准接口"（谁都能来申请弹窗），`ULyraUIMessaging` 是"具体接线员"——它知道用哪个对话框类、推到哪个 UI 层。

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "Messaging/CommonMessagingSubsystem.h"
#include "Templates/SubclassOf.h"
#include "UObject/SoftObjectPtr.h"

#include "TenkaichiUIMessaging.generated.h"

class FSubsystemCollectionBase;
class UCommonGameDialog;
class UCommonGameDialogDescriptor;
class UObject;

/**
 * UI 消息子系统：实现确认框和错误框的弹出。
 */
UCLASS()
class UTenkaichiUIMessaging : public UCommonMessagingSubsystem
{
	GENERATED_BODY()

public:
	// 构造函数：空实现。
	UTenkaichiUIMessaging() { }

	// 初始化：同步加载对话框类。
	virtual void Initialize(FSubsystemCollectionBase& Collection) override;

	// 显示确认框。
	virtual void ShowConfirmation(UCommonGameDialogDescriptor* DialogDescriptor, FCommonMessagingResultDelegate ResultCallback = FCommonMessagingResultDelegate()) override;
	// 显示错误框。
	virtual void ShowError(UCommonGameDialogDescriptor* DialogDescriptor, FCommonMessagingResultDelegate ResultCallback = FCommonMessagingResultDelegate()) override;

private:
	// 确认框类（运行时缓存，硬引用）。
	UPROPERTY()
	TSubclassOf<UCommonGameDialog> ConfirmationDialogClassPtr;

	// 错误框类（运行时缓存，硬引用）。
	UPROPERTY()
	TSubclassOf<UCommonGameDialog> ErrorDialogClassPtr;

	// 确认框类（配置文件指定，软引用）。
	UPROPERTY(config)
	TSoftClassPtr<UCommonGameDialog> ConfirmationDialogClass;

	// 错误框类（配置文件指定，软引用）。
	UPROPERTY(config)
	TSoftClassPtr<UCommonGameDialog> ErrorDialogClass;
};
```

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiUIMessaging.h"

#include "Messaging/CommonGameDialog.h"
#include "NativeGameplayTags.h"
#include "CommonLocalPlayer.h"
#include "PrimaryGameLayout.h"
#include "Widgets/CommonActivatableWidgetContainer.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiUIMessaging)

class FSubsystemCollectionBase;

// 定义弹窗层 tag。
UE_DEFINE_GAMEPLAY_TAG_STATIC(TAG_UI_LAYER_MODAL, "UI.Layer.Modal");

// 初始化：同步加载对话框类（从 config 软引用 → 运行时硬引用）。
void UTenkaichiUIMessaging::Initialize(FSubsystemCollectionBase& Collection)
{
	Super::Initialize(Collection);

	ConfirmationDialogClassPtr = ConfirmationDialogClass.LoadSynchronous();
	ErrorDialogClassPtr = ErrorDialogClass.LoadSynchronous();
}

// 显示确认框：推到 UI.Layer.Modal 层。
void UTenkaichiUIMessaging::ShowConfirmation(UCommonGameDialogDescriptor* DialogDescriptor, FCommonMessagingResultDelegate ResultCallback)
{
	if (UCommonLocalPlayer* LocalPlayer = GetLocalPlayer<UCommonLocalPlayer>())
	{
		if (UPrimaryGameLayout* RootLayout = LocalPlayer->GetRootUILayout())
		{
			RootLayout->PushWidgetToLayerStack<UCommonGameDialog>(TAG_UI_LAYER_MODAL, ConfirmationDialogClassPtr, [DialogDescriptor, ResultCallback](UCommonGameDialog& Dialog) {
				Dialog.SetupDialog(DialogDescriptor, ResultCallback);
			});
		}
	}
}

// 显示错误框：推到 UI.Layer.Modal 层。
void UTenkaichiUIMessaging::ShowError(UCommonGameDialogDescriptor* DialogDescriptor, FCommonMessagingResultDelegate ResultCallback)
{
	if (UCommonLocalPlayer* LocalPlayer = GetLocalPlayer<UCommonLocalPlayer>())
	{
		if (UPrimaryGameLayout* RootLayout = LocalPlayer->GetRootUILayout())
		{
			RootLayout->PushWidgetToLayerStack<UCommonGameDialog>(TAG_UI_LAYER_MODAL, ErrorDialogClassPtr, [DialogDescriptor, ResultCallback](UCommonGameDialog& Dialog) {
				Dialog.SetupDialog(DialogDescriptor, ResultCallback);
			});
		}
	}
}
```

## 三、关键点讲解

### 1. 四个成员：软/硬两套

```cpp
UPROPERTY()          TSubclassOf<UCommonGameDialog> ConfirmationDialogClassPtr;   // 运行时缓存（硬）
UPROPERTY()          TSubclassOf<UCommonGameDialog> ErrorDialogClassPtr;          // 运行时缓存（硬）
UPROPERTY(config)    TSoftClassPtr<UCommonGameDialog> ConfirmationDialogClass;    // 配置（软）
UPROPERTY(config)    TSoftClassPtr<UCommonGameDialog> ErrorDialogClass;           // 配置（软）
```

**为什么要两套？**
- `config` 软引用：从 `DefaultGame.ini` 配置（策划/开发者配"用哪个对话框蓝图"），不占启动内存。
- 运行时硬引用 `...Ptr`：`Initialize` 里 `LoadSynchronous()` 一次性同步加载成硬引用，后续弹窗直接用（不用每次加载）。

> 这是"配置用软引用 + 运行时转硬引用"的经典模式。

### 2. `UPROPERTY(config)`——从 ini 读

```cpp
UPROPERTY(config)
TSoftClassPtr<UCommonGameDialog> ConfirmationDialogClass;
```

`config` 说明符：这个属性从 ini 配置文件读（`[/Script/TenkaichiGame.TenkaichiUIMessaging]` 段）。

### 3. `Initialize` 里同步加载

```cpp
ConfirmationDialogClassPtr = ConfirmationDialogClass.LoadSynchronous();
ErrorDialogClassPtr = ErrorDialogClass.LoadSynchronous();
```

`LoadSynchronous()`：同步加载软引用指向的类。返回 `UClass*`，赋值给 `TSubclassOf`。

> 子系统初始化阶段同步加载是可接受的（不像游戏运行中卡顿）。

### 4. `GetLocalPlayer<UCommonLocalPlayer>()`——模板取本地玩家

```cpp
if (UCommonLocalPlayer* LocalPlayer = GetLocalPlayer<UCommonLocalPlayer>())
```

`GetLocalPlayer<T>()`：`UCommonMessagingSubsystem` 提供的模板方法，拿到"关联的本地玩家"（转成 `T`）。

### 5. `PushWidgetToLayerStack<T>`——推到 UI 层的栈

```cpp
RootLayout->PushWidgetToLayerStack<UCommonGameDialog>(TAG_UI_LAYER_MODAL, ConfirmationDialogClassPtr, [DialogDescriptor, ResultCallback](UCommonGameDialog& Dialog) {
	Dialog.SetupDialog(DialogDescriptor, ResultCallback);
});
```

`PushWidgetToLayerStack<WidgetT>(层tag, 控件类, 初始化lambda)`：
- 往 `UI.Layer.Modal` 层推一个 `UCommonGameDialog` 控件。
- 推完后调 lambda，参数是**控件实例的引用**——在 lambda 里做初始化（`SetupDialog`）。

> 这个"推完再初始化"的模式很常见：控件创建 → 通过 lambda 传配置进去。

### 6. lambda 捕获的两个东西

```cpp
[DialogDescriptor, ResultCallback](UCommonGameDialog& Dialog)
{
	Dialog.SetupDialog(DialogDescriptor, ResultCallback);
}
```

- `DialogDescriptor`：对话框内容描述（标题/正文/按钮文本）。
- `ResultCallback`：用户点击后的回调（确定/取消走哪个分支）。

`SetupDialog(描述, 回调)`：把这两样交给对话框实例。

### 7. 两个方法的唯一差别

`ShowConfirmation` 用 `ConfirmationDialogClassPtr`，`ShowError` 用 `ErrorDialogClassPtr`。逻辑完全一样——因为"确认框"和"错误框"只是**用不同的对话框蓝图类**。
