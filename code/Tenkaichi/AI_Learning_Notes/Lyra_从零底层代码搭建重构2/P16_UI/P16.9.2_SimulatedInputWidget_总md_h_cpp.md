## 一、这个类解决什么问题（先讲为什么）

移动端没有物理摇杆/按键，需要**虚拟控件**（屏幕上的摇杆、按钮）来产生输入。但"虚拟控件"不能直接改游戏逻辑——它必须**伪装成真实输入**（让 EnhancedInput 以为玩家真的推了摇杆）。

`ULyraSimulatedInputWidget` 就是"模拟输入"的基类：
- 配一个 `AssociatedAction`（要模拟的输入动作）。
- 调 `InputKeyValue(向量)` → 通过 `InjectInputVectorForAction` **注入输入**。
- 如果没配动作，就退化成"模拟按键"（`InputKey` + `FallbackBindingKey`）。

> **类比**：这是"假肢"——虚拟摇杆是"假肢的外形"，这个类是"假肢的神经接口"（把动作翻译成引擎能懂的输入信号）。

	FKey KeyToSimulate;

## 三、`.h` 关键点

### 1. `SetConsumePointerInput(true)`（在 `.cpp` 构造里）

```cpp
ULyraSimulatedInputWidget::ULyraSimulatedInputWidget(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)

	SetConsumePointerInput(true);
}
```

`SetConsumePointerInput(true)`：**消费指针输入**——触摸/点击这个控件时，事件不再传给下层控件。

> 因为虚拟摇杆要"吃掉"触摸事件（否则下面的 UI 也会响应）。

### 2. `GetPaletteCategory()`——编辑器调色板分类

```cpp

const FText ULyraSimulatedInputWidget::GetPaletteCategory()

#endif
```

`GetPaletteCategory()`：UMG 编辑器左侧"控件面板"里的分类。这里归到 **"Input"** 分类。

> 注意 `LOCTEXT` 的 key 拼写是 `"PalleteCategory"`（Lyra 的拼写错误，少了个 `t`）——按铁律 23 照抄。

### 3. `CommonVisibilityBorder`（`BindWidget`）

```cpp
UPROPERTY(BlueprintReadWrite, meta = (BindWidget))
TObjectPtr<UCommonHardwareVisibilityBorder> CommonVisibilityBorder = nullptr;
```

`UCommonHardwareVisibilityBorder`：CommonUI 的"按硬件类型显示/隐藏"边框（比如只在移动端显示）。

> 注意是 `BindWidget`（**必需**）——蓝图里必须有同名控件。但 Lyra 给了默认值 `nullptr`（矛盾？实际上 `BindWidget` 要求蓝图有，C++ 默认值只是初始化）。

### 4. `FallbackBindingKey = EKeys::Gamepad_Right2D`

```cpp
UPROPERTY(BlueprintReadOnly, EditAnywhere)
FKey FallbackBindingKey = EKeys::Gamepad_Right2D;
```

默认备用键是**手柄右摇杆 2D**（`Gamepad_Right2D`）——因为虚拟摇杆最常模拟的就是右摇杆。

## 四、完整代码：`.cpp`（170 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiSimulatedInputWidget.h"
#include "EnhancedInputSubsystems.h"
#include "GenericPlatform/GenericPlatformInputDeviceMapper.h"
#include "TenkaichiLogChannels.h"
#include "InputKeyEventArgs.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiSimulatedInputWidget)

#define LOCTEXT_NAMESPACE "TenkaichiSimulatedInputWidget"

// 构造函数：开启"消费指针输入"。
UTenkaichiSimulatedInputWidget::UTenkaichiSimulatedInputWidget(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	SetConsumePointerInput(true);
}

#if WITH_EDITOR
// 编辑器调色板分类。
const FText UTenkaichiSimulatedInputWidget::GetPaletteCategory()
{
	return LOCTEXT("PalleteCategory", "Input");
}
#endif // WITH_EDITOR

// 控件构造完成（查初始键 + 监听控制映射变化）。
void UTenkaichiSimulatedInputWidget::NativeConstruct()
{
	// 找初始键，然后监听控制映射的任何变化
	QueryKeyToSimulate();

	if (UEnhancedInputLocalPlayerSubsystem* System = GetEnhancedInputSubsystem())
	{
		System->ControlMappingsRebuiltDelegate.AddUniqueDynamic(this, &UTenkaichiSimulatedInputWidget::OnControlMappingsRebuilt);
	}
	
	Super::NativeConstruct();
}

// 控件销毁（解绑控制映射变化）。
void UTenkaichiSimulatedInputWidget::NativeDestruct()
{
	if (UEnhancedInputLocalPlayerSubsystem* System = GetEnhancedInputSubsystem())
	{
		System->ControlMappingsRebuiltDelegate.RemoveAll(this);
	}

	Super::NativeDestruct();
}

// 触摸结束（清空模拟输入）。
FReply UTenkaichiSimulatedInputWidget::NativeOnTouchEnded(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent)
{
	FlushSimulatedInput();
	
	return Super::NativeOnTouchEnded(InGeometry, InGestureEvent);
}

// 基于本控件的拥有本地玩家取增强输入子系统。
UEnhancedInputLocalPlayerSubsystem* UTenkaichiSimulatedInputWidget::GetEnhancedInputSubsystem() const
{
	if (APlayerController* PC = GetOwningPlayer())
	{
		if (ULocalPlayer* LP = GetOwningLocalPlayer())
		{
			return LP->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>();
		}
	}
	return nullptr;
}

// 从当前输入子系统取玩家输入。
UEnhancedPlayerInput* UTenkaichiSimulatedInputWidget::GetPlayerInput() const
{
	if (UEnhancedInputLocalPlayerSubsystem* System = GetEnhancedInputSubsystem())
	{
		return System->GetPlayerInput();
	}
	return nullptr;
}

// 把给定的向量作为输入注入到当前模拟键。
void UTenkaichiSimulatedInputWidget::InputKeyValue(const FVector& Value)
{
	const APlayerController* PC = GetOwningPlayer();
	const FPlatformUserId UserId = PC ? PC->GetPlatformUserId() : PLATFORMUSERID_NONE;
	// 如果有配关联输入动作，就用它
	if (AssociatedAction)
	{
		if (UEnhancedInputLocalPlayerSubsystem* System = GetEnhancedInputSubsystem())
		{
			// 我们不想给这个动作应用任何修饰器或触发器，但函数签名要求传
			TArray<UInputModifier*> Modifiers;
			TArray<UInputTrigger*> Triggers;
			System->InjectInputVectorForAction(AssociatedAction, Value, Modifiers, Triggers);
		}
	}
	// 没有关联动作，就尝试在备用键上模拟输入
	else if (UEnhancedPlayerInput* Input = GetPlayerInput())
	{
		const FInputDeviceId DeviceToSimulate = IPlatformInputDeviceMapper::Get().GetPrimaryInputDeviceForUser(UserId);
		if(KeyToSimulate.IsValid())
		{
			const float DeltaTime = GetWorld()->GetDeltaSeconds();
			auto SimulateKeyPress = [Input, DeltaTime, DeviceToSimulate](const FKey& KeyToSim, const float Value, const EInputEvent Event)
			{
				FInputKeyEventArgs Args = FInputKeyEventArgs::CreateSimulated(
					KeyToSim,
					Event,
					Value,
					KeyToSim.IsAnalog() ? 1 : 0,
					DeviceToSimulate);

				Args.DeltaTime = DeltaTime;
			
				Input->InputKey(Args);
			};
			
			// 对于"键对"的根键（比如 Mouse2D 由 MouseX 和 MouseY 组成），
			// 我们应该对键对里的每个键调 InputKey，而不是对配对键本身。
			// 这样事件才能在 UPlayerInput 的键状态表里正确累积。
			// 来自消息处理器和视口客户端的所有输入事件都是这样工作的，
			// 所以我们模拟键输入时也应该这样做。
			if (const EKeys::FPairedKeyDetails* PairDetails = EKeys::GetPairedKeyDetails(KeyToSimulate))
			{
				SimulateKeyPress(PairDetails->XKeyDetails->GetKey(), Value.X, IE_Axis);
				SimulateKeyPress(PairDetails->YKeyDetails->GetKey(), Value.Y, IE_Axis);
			}
			else
			{
				SimulateKeyPress(KeyToSimulate, Value.X, IE_Pressed);
			}
		}
	}
	else
	{
		UE_LOG(LogTenkaichi, Error, TEXT("'%s' is attempting to simulate input but has no player input!"), *GetNameSafe(this));
	}
}

// 把给定的二维向量作为输入注入到当前模拟键。
void UTenkaichiSimulatedInputWidget::InputKeyValue2D(const FVector2D& Value)
{
	InputKeyValue(FVector(Value.X, Value.Y, 0.0));
}

// 清空所有模拟输入（松开所有键）。
void UTenkaichiSimulatedInputWidget::FlushSimulatedInput()
{
	if (UEnhancedPlayerInput* Input = GetPlayerInput())
	{
		Input->FlushPressedKeys();
	}
}

// 根据增强输入查询"关联动作绑了哪些键"来设置 KeyToSimulate。
void UTenkaichiSimulatedInputWidget::QueryKeyToSimulate()
{
	if (UEnhancedInputLocalPlayerSubsystem* System = GetEnhancedInputSubsystem())
	{
		TArray<FKey> Keys = System->QueryKeysMappedToAction(AssociatedAction);
		if(!Keys.IsEmpty() && Keys[0].IsValid())
		{
			KeyToSimulate = Keys[0];
		}
		else
		{
			KeyToSimulate = FallbackBindingKey;
		}
	}
}

// 控制映射变化时调用，让我们有机会适配自己的键。
void UTenkaichiSimulatedInputWidget::OnControlMappingsRebuilt()
{
	QueryKeyToSimulate();
}

#undef LOCTEXT_NAMESPACE
```

## 五、`.cpp` 关键点讲解

### 1. `InputKeyValue` 的两条路径（核心）

```cpp
if (AssociatedAction)          // ① 有输入动作 → 注入向量
{
	System->InjectInputVectorForAction(AssociatedAction, Value, Modifiers, Triggers);
}
else if (UEnhancedPlayerInput* Input = GetPlayerInput())   // ② 没动作 → 模拟按键
{
	... Input->InputKey(Args);
}
```

**路径 ①（推荐）**：`InjectInputVectorForAction(动作, 向量, 修饰器, 触发器)` —— 直接把向量注入到输入动作（EnhancedInput 原生支持）。

**路径 ②（退化）**：模拟按键（`InputKey`）—— 老式输入路径。

> 注释说"我们不想给这个动作应用任何修饰器或触发器，但函数签名要求传"——所以传空数组。

### 2. `FInputKeyEventArgs::CreateSimulated(...)`——创建模拟按键事件

```cpp
FInputKeyEventArgs Args = FInputKeyEventArgs::CreateSimulated(
	KeyToSim,
	Event,
	Value,
	KeyToSim.IsAnalog() ? 1 : 0,     // 模拟量给 1，数字量给 0
	DeviceToSimulate);
```

`CreateSimulated(键, 事件类型, 值, 模拟量, 设备ID)`：创建一个"模拟"的按键事件（标记为 simulated，不是真实硬件输入）。

### 3. 键对处理（`GetPairedKeyDetails`）——最精妙的部分

```cpp
if (const EKeys::FPairedKeyDetails* PairDetails = EKeys::GetPairedKeyDetails(KeyToSimulate))
{
	SimulateKeyPress(PairDetails->XKeyDetails->GetKey(), Value.X, IE_Axis);
	SimulateKeyPress(PairDetails->YKeyDetails->GetKey(), Value.Y, IE_Axis);
}
else
{
	SimulateKeyPress(KeyToSimulate, Value.X, IE_Pressed);
}
```

**问题**：`Gamepad_Right2D` 是"2D 键"（由 `Gamepad_RightX` + `Gamepad_RightY` 组成）。如果直接对 `Gamepad_Right2D` 调 `InputKey`，**引擎的键状态表不会正确累积**。

**解决**：用 `GetPairedKeyDetails` 拿到"X 键 + Y 键"，**分别**对它们调 `InputKey`（`IE_Axis` 事件）。

> 注释详细解释了原因："来自消息处理器和视口客户端的所有输入事件都是这样工作的，所以我们模拟键输入时也应该这样做。"

### 4. `QueryKeyToSimulate`——查动作绑了哪些键

```cpp
TArray<FKey> Keys = System->QueryKeysMappedToAction(AssociatedAction);
if(!Keys.IsEmpty() && Keys[0].IsValid())
{
	KeyToSimulate = Keys[0];      // 用第一个绑定的键
}
else
{
	KeyToSimulate = FallbackBindingKey;   // 没绑定就用备用键
}
```

和 P16.3.3 的 `UTenkaichiActionWidget::GetIcon` 用的是同一个方法（`QueryKeysMappedToAction`）。

### 5. `ControlMappingsRebuiltDelegate`——监听重绑

```cpp
// NativeConstruct
System->ControlMappingsRebuiltDelegate.AddUniqueDynamic(this, &UTenkaichiSimulatedInputWidget::OnControlMappingsRebuilt);

// NativeDestruct
System->ControlMappingsRebuiltDelegate.RemoveAll(this);
```

玩家重绑按键时，`KeyToSimulate` 要跟着更新（否则模拟的还是旧键）。

`AddUniqueDynamic`：动态委托 + 去重（不会重复绑）。

### 6. `FlushSimulatedInput`——松开所有键

```cpp
void UTenkaichiSimulatedInputWidget::FlushSimulatedInput()
{
	if (UEnhancedPlayerInput* Input = GetPlayerInput())
	{
		Input->FlushPressedKeys();
	}
}
```

`FlushPressedKeys()`：清空所有"按下的键"状态。

**为什么需要？** 因为模拟输入是"持续注入"的（每帧 `InputKeyValue`）。触摸结束时如果不 flush，引擎会以为键还按着（角色一直移动）。

> `NativeOnTouchEnded` 里调它——触摸结束就松开。

### 7. `GetEnhancedInputSubsystem` 的双重检查

```cpp
if (APlayerController* PC = GetOwningPlayer())
{
	if (ULocalPlayer* LP = GetOwningLocalPlayer())
	{
		return LP->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>();
	}
}
return nullptr;
```

**注意**：`PC` 检查了但**没用**（只是确认"有控制器"）。实际用的是 `GetOwningLocalPlayer()`。

> 这是 Lyra 的冗余写法（`PC` 变量未使用）。按铁律 23 照抄。
