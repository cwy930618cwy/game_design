## 一、这个类解决什么问题（先讲为什么）

`UCommonButtonBase` 是 CommonUI 的按钮基类——它支持"显示输入动作提示"（比如按钮旁边显示 `[A] 确认` / `[左键] 确认`，随输入方式变化）。

但它有个问题：**按钮文字和输入动作提示的优先级处理**要自己写。Lyra 做了 `ULyraButtonBase` 来统一处理：

- 如果按钮文字**没设置**（或显式要求覆盖）→ 用**输入动作的显示文字**（比如 `确认`）。
- 如果按钮文字设置了 → 用手动设置的文字。
- 输入方式变化（键鼠 ↔ 手柄）→ 刷新按钮样式。

> **类比**：`UCommonButtonBase` 是"通用按钮"，`ULyraButtonBase` 是"智能按钮"——它会自动决定"该显示什么字"（手动文字 or 输入动作提示）。

## 二、完整代码（可直接照抄）

### `TenkaichiButtonBase.h`（45 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "CommonButtonBase.h"

#include "TenkaichiButtonBase.generated.h"

class UObject;
struct FFrame;

// 按钮基类：自动处理"按钮文字 vs 输入动作提示"的优先级。
UCLASS(Abstract, BlueprintType, Blueprintable)
class UTenkaichiButtonBase : public UCommonButtonBase
{
	GENERATED_BODY()

public:
	// 设置按钮文字（蓝图可调）。
	UFUNCTION(BlueprintCallable)
	void SetButtonText(const FText& InText);
	
protected:
	// UUserWidget 接口开始
	// 蓝图预构造时（编辑器里预览 + 运行时构造）刷新样式和文字。
	virtual void NativePreConstruct() override;
	// UUserWidget 接口结束

	// UCommonButtonBase 接口开始
	// 输入动作控件更新时（刷新样式和文字）。
	virtual void UpdateInputActionWidget() override;
	// 输入方式变化时（刷新样式）。
	virtual void OnInputMethodChanged(ECommonInputType CurrentInputType) override;
	// UCommonButtonBase 接口结束

	// 刷新按钮文字（决定用输入动作文字还是手动文字）。
	void RefreshButtonText();
	
	// 蓝图可实现的更新按钮文字事件。
	UFUNCTION(BlueprintImplementableEvent)
	void UpdateButtonText(const FText& InText);

	// 蓝图可实现的更新按钮样式事件。
	UFUNCTION(BlueprintImplementableEvent)
	void UpdateButtonStyle();
	
private:
	// 是否覆盖按钮文字（内联编辑开关）。
	UPROPERTY(EditAnywhere, Category="Button", meta=(InlineEditConditionToggle))
	uint8 bOverride_ButtonText : 1;
	
	// 按钮文字（勾选覆盖时使用）。
	UPROPERTY(EditAnywhere, Category="Button", meta=( editcondition="bOverride_ButtonText" ))
	FText ButtonText;
};
```

### `TenkaichiButtonBase.cpp`（54 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiButtonBase.h"
#include "CommonActionWidget.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiButtonBase)

// 蓝图预构造时（编辑器里预览 + 运行时构造）刷新样式和文字。
void UTenkaichiButtonBase::NativePreConstruct()
{
	Super::NativePreConstruct();

	UpdateButtonStyle();
	RefreshButtonText();
}

// 输入动作控件更新时（刷新样式和文字）。
void UTenkaichiButtonBase::UpdateInputActionWidget()
{
	Super::UpdateInputActionWidget();

	UpdateButtonStyle();
	RefreshButtonText();
}

// 设置按钮文字（蓝图可调）。
void UTenkaichiButtonBase::SetButtonText(const FText& InText)
{
	// 传空字符串 = 取消覆盖（改回用输入动作提示）
	bOverride_ButtonText = InText.IsEmpty();
	ButtonText = InText;
	RefreshButtonText();
}

// 刷新按钮文字（决定用输入动作文字还是手动文字）。
void UTenkaichiButtonBase::RefreshButtonText()
{
	// 如果要覆盖，或手动文字是空的，就优先用输入动作的显示文字
	if (bOverride_ButtonText || ButtonText.IsEmpty())
	{
		if (InputActionWidget)
		{
			const FText ActionDisplayText = InputActionWidget->GetDisplayText();	
			if (!ActionDisplayText.IsEmpty())
			{
				UpdateButtonText(ActionDisplayText);
				return;
			}
		}
	}
	
	UpdateButtonText(ButtonText);	
}

// 输入方式变化时（刷新样式）。
void UTenkaichiButtonBase::OnInputMethodChanged(ECommonInputType CurrentInputType)
{
	Super::OnInputMethodChanged(CurrentInputType);

	UpdateButtonStyle();
}
```

## 三、关键点讲解

### 1. `bOverride_ButtonText` 的位域写法

```cpp
UPROPERTY(EditAnywhere, Category="Button", meta=(InlineEditConditionToggle))
uint8 bOverride_ButtonText : 1;
```

`uint8 bOverride_ButtonText : 1`：**位域**（1 个 bool 只占 1 bit）。UE 里 bool 类型的 UPROPERTY 常用这种写法（省内存 + UHT 支持）。

`meta=(InlineEditConditionToggle)`：这个 bool 是"开关"，控制下一个属性的可编辑性。

### 2. `meta=(editcondition="bOverride_ButtonText")`

```cpp
UPROPERTY(EditAnywhere, Category="Button", meta=( editcondition="bOverride_ButtonText" ))
FText ButtonText;
```

只有 `bOverride_ButtonText` 为 true 时，`ButtonText` 才可编辑（P14.6-2 也讲过 `EditCondition`）。

> 注意这里是小写 `editcondition`（UE 的 meta 名不区分大小写，Lyra 原文小写）。

### 3. `SetButtonText` 的反直觉逻辑

```cpp
void UTenkaichiButtonBase::SetButtonText(const FText& InText)
{
	bOverride_ButtonText = InText.IsEmpty();   // ← 注意！
	ButtonText = InText;
	RefreshButtonText();
}
```

**注意**：`bOverride_ButtonText = InText.IsEmpty()` —— 传**空字符串**时 `bOverride_ButtonText = true`？

等等，这看起来反了。看 `RefreshButtonText` 就明白了：

```cpp
if (bOverride_ButtonText || ButtonText.IsEmpty())
{
	if (InputActionWidget)
	{
		const FText ActionDisplayText = InputActionWidget->GetDisplayText();	
		if (!ActionDisplayText.IsEmpty())
		{
			UpdateButtonText(ActionDisplayText);   // 用输入动作文字
			return;
		}
	}
}
UpdateButtonText(ButtonText);   // 用手动文字
```

- `bOverride_ButtonText == true` → **优先用输入动作文字**（"覆盖"是指"输入动作覆盖手动文字"）。
- `bOverride_ButtonText == false` → 用手动文字（但如果手动文字为空，也回退到输入动作）。

所以 `SetButtonText(TEXT(""))` → `bOverride_ButtonText = true` + `ButtonText` 空 → `RefreshButtonText` 走 `if` 分支 → 用输入动作文字。

**命名有点绕**：`bOverride_ButtonText` 实际意思是"**让输入动作提示覆盖按钮文字**"。按铁律 23 照抄，不改名。

### 4. `BlueprintImplementableEvent`——纯蓝图实现

```cpp
UFUNCTION(BlueprintImplementableEvent)
void UpdateButtonText(const FText& InText);
```

`BlueprintImplementableEvent`：**C++ 只声明，实现完全在蓝图里**（C++ 调用它，蓝图负责实现）。

对比 P16.1.3 的 `BlueprintNativeEvent`（C++ 有默认实现 `_Implementation` + 蓝图可覆写）。

| 宏 | C++ 实现 | 蓝图实现 |
|----|---------|---------|
| `BlueprintImplementableEvent` | ❌ 无 | ✅ 必须有 |
| `BlueprintNativeEvent` | ✅ `_Implementation` | ✅ 可覆写 |

> 这里用 `BlueprintImplementableEvent`——因为"怎么更新文字"完全取决于蓝图控件结构（C++ 不知道你的文本控件叫啥），只能蓝图实现。

### 5. `InputActionWidget`——基类成员

```cpp
if (InputActionWidget)
{
	const FText ActionDisplayText = InputActionWidget->GetDisplayText();	
```

`InputActionWidget` 是 `UCommonButtonBase` 的成员（`UCommonActionWidget*`），负责显示输入动作图标/文字。`GetDisplayText()` 返回"这个动作在当前输入方式下的显示文字"（如"确认"/"Confirm"）。

### 6. 三个刷新时机

| 时机 | 方法 | 场景 |
|------|------|------|
| 蓝图预构造 | `NativePreConstruct` | 编辑器预览 + 运行时创建 |
| 输入动作控件更新 | `UpdateInputActionWidget` | 绑定的动作变了 |
| 输入方式变化 | `OnInputMethodChanged` | 键鼠 ↔ 手柄切换 |

前两个都调 `UpdateButtonStyle()` + `RefreshButtonText()`，第三个只调 `UpdateButtonStyle()`（因为输入方式变了主要是图标样式变）。
