## 一、这个类解决什么问题（先讲为什么）

P16.4.5 的 `UTenkaichiTabListWidgetBase::HandleTabCreation_Implementation` 里有一句：

```cpp
ITenkaichiTabButtonInterface::Execute_SetTabLabelInfo(TabButton, *TabInfoPtr);
```

它要求标签按钮**实现这个接口**，才能接收"标题文字 + 图标"。`ULyraTabButtonBase` 就是**标准实现**——它同时继承：
- `ULyraButtonBase`（P16.3.2，带按钮文字/动作提示能力）。
- `ILyraTabButtonInterface`（P16.4.5，能接收标签描述）。

所以这个类是"标签页按钮"的基类：既是一个标准按钮，又能显示标签图标。

> **类比**：`ULyraTabListWidgetBase` 是"标签页系统"，`ULyraTabButtonBase` 是"标准标签页按钮"——系统建标签时通过接口把标题图标塞给它。

## 二、完整代码（可直接照抄）

### `TenkaichiTabButtonBase.h`（38 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "TenkaichiTabListWidgetBase.h"
#include "UI/Foundation/TenkaichiButtonBase.h"

#include "TenkaichiTabButtonBase.generated.h"

#define UE_API TENKAICHIGAME_API

class UCommonLazyImage;
class UObject;
struct FFrame;
struct FSlateBrush;

// 标签按钮基类：既是按钮，又能显示标签图标。
UCLASS(MinimalAPI, Abstract, Blueprintable, meta = (DisableNativeTick))
class UTenkaichiTabButtonBase : public UTenkaichiButtonBase, public ITenkaichiTabButtonInterface
{
	GENERATED_BODY()

public:
	// 从懒加载对象设置图标（软引用，按需加载）。
	UE_API void SetIconFromLazyObject(TSoftObjectPtr<UObject> LazyObject);
	// 直接设置图标画刷。
	UE_API void SetIconBrush(const FSlateBrush& Brush);

protected:
	// 实现接口：接收标签描述（填文字 + 图标）。
	UFUNCTION()
	UE_API virtual void SetTabLabelInfo_Implementation(const FTenkaichiTabDescriptor& TabLabelInfo) override;

private:
	// 图标（懒加载图片控件，可选绑定）。
	UPROPERTY(meta = (BindWidgetOptional))
	TObjectPtr<UCommonLazyImage> LazyImage_Icon;
};

#undef UE_API
```

## 三、关键点讲解

### 1. 多继承：`ULyraButtonBase` + `ILyraTabButtonInterface`

```cpp
class UTenkaichiTabButtonBase : public UTenkaichiButtonBase, public ITenkaichiTabButtonInterface
```

- 第一个基类是 **UObject 体系**（`UTenkaichiButtonBase`）——必须放第一。
- 第二个是 **UE 接口**（`ITenkaichiTabButtonInterface`）——放后面。

> UE 多继承规则：UObject 类必须在最左，接口跟在后面。这是硬性要求。

### 2. `SetTabLabelInfo_Implementation`——实现接口的 BlueprintNativeEvent

```cpp
UFUNCTION()
UE_API virtual void SetTabLabelInfo_Implementation(const FTenkaichiTabDescriptor& TabLabelInfo) override;
```

P16.4.5 里接口声明的是：
```cpp
UFUNCTION(BlueprintNativeEvent, Category = "Tab Button")
void SetTabLabelInfo(const FTenkaichiTabDescriptor& TabDescriptor);
```

实现时函数名加 `_Implementation` 后缀（`BlueprintNativeEvent` 的规则，P15.x 讲过）。

> 注意 `.h` 里实现处标了 `UFUNCTION()`（没有参数）——因为接口的 UFUNCTION 已经在接口声明里写过，实现处只需 `UFUNCTION()` 占位（让 UHT 识别）。

### 3. `meta = (BindWidgetOptional)`——可选绑定

```cpp
UPROPERTY(meta = (BindWidgetOptional))
TObjectPtr<UCommonLazyImage> LazyImage_Icon;
```

对比 P16.3.1 的 `BindWidget`（必需）：
- `BindWidget`：蓝图**必须**有同名控件，否则编译报错。
- `BindWidgetOptional`：蓝图**可以有**（没有就是空指针，不报错）。

**为什么这里可选？** 因为不是所有标签按钮都要图标（纯文字标签）。所以声明为可选，代码里也都有 `if (LazyImage_Icon)` 保护。

### 4. `SetIconFromLazyObject` vs `SetIconBrush`

```cpp
void SetIconFromLazyObject(TSoftObjectPtr<UObject> LazyObject)   // 软引用，按需加载
{
	if (LazyImage_Icon)
	{
		LazyImage_Icon->SetBrushFromLazyDisplayAsset(LazyObject);
	}
}

void SetIconBrush(const FSlateBrush& Brush)                       // 直接给画刷（已加载）
{
	if (LazyImage_Icon)
	{
		LazyImage_Icon->SetBrush(Brush);
	}
}
```

两个入口：
- `SetIconFromLazyObject`：给**软引用**（`TSoftObjectPtr`），控件负责按需加载（`CommonLazyImage` 的能力）。
- `SetIconBrush`：给**已构造的 `FSlateBrush`**（直接设置）。

### 5. `UCommonLazyImage`——CommonUI 的懒加载图片

`UCommonLazyImage` 是 CommonUI 的图片控件，支持：
- `SetBrushFromLazyDisplayAsset(软引用)`：异步加载后再显示（不阻塞）。
- `SetBrush(画刷)`：直接设置（同步）。

> 对比普通 `UImage`：`UCommonLazyImage` 更适合"可能很大的图标/缩略图"。

### 6. `SetTabLabelInfo_Implementation` 只做两件事

```cpp
void UTenkaichiTabButtonBase::SetTabLabelInfo_Implementation(const FTenkaichiTabDescriptor& TabLabelInfo)
{
	SetButtonText(TabLabelInfo.TabText);        // ① 按钮文字（P16.3.2 的方法）
	SetIconBrush(TabLabelInfo.IconBrush);       // ② 图标
}
```

`SetButtonText` 是 P16.3.2 `UTenkaichiButtonBase` 的方法——这里直接复用（继承来的）。

> 注意它**没有**调 `Super::SetTabLabelInfo_Implementation(...)`——因为父类链里没有其他实现（`UTenkaichiButtonBase` 不实现这个接口）。按铁律 23 照抄。
