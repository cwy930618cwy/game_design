## 一、这个类解决什么问题（先讲为什么）

武器 UI（准星、弹药数、武器名）都要**知道当前拿的是什么武器**。武器在 GAS 的装备系统里（P09），要拿到"当前武器的 `ULyraWeaponInstance`"得绕一圈：

```
玩家 Pawn → 找 ULyraEquipmentManagerComponent → GetFirstInstanceOfType<ULyraWeaponInstance>()
```

`ULyraWeaponUserInterface` 把这个"找当前武器"的流程封装起来，并**在武器切换时通知蓝图**（`OnWeaponChanged`）。

> **类比**：这是"武器 UI 的探子"——每帧盯着玩家手上的武器，一换就喊一声（`OnWeaponChanged`），让子类去更新显示。

// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "CommonUserWidget.h"

#include "TenkaichiWeaponUserInterface.generated.h"

class UTenkaichiWeaponInstance;
class UObject;
struct FGeometry;

// 武器 UI 基类：每帧检测当前武器，切换时通知蓝图。
UCLASS()
class UTenkaichiWeaponUserInterface : public UCommonUserWidget
{
	GENERATED_BODY()

public:
	// 构造函数：空实现。
	UTenkaichiWeaponUserInterface(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	// 控件构造完成。

	// 控件销毁。

	// 每帧 Tick（检测武器变化）。
	virtual void NativeTick(const FGeometry& MyGeometry, float InDeltaTime) override;

	// 武器变化时的蓝图事件（子类实现）。
	UFUNCTION(BlueprintImplementableEvent)
	void OnWeaponChanged(UTenkaichiWeaponInstance* OldWeapon, UTenkaichiWeaponInstance* NewWeapon);

private:
	// 按新武器重建控件（基类留空，子类可覆写）。

private:

	TObjectPtr<UTenkaichiWeaponInstance> CurrentInstance;

void UTenkaichiWeaponUserInterface::NativeTick(const FGeometry& MyGeometry, float InDeltaTime)
{
	Super::NativeTick(MyGeometry, InDeltaTime);

	if (APawn* Pawn = GetOwningPlayerPawn())
	{
		if (UTenkaichiEquipmentManagerComponent* EquipmentManager = Pawn->FindComponentByClass<UTenkaichiEquipmentManagerComponent>())
		{
			if (UTenkaichiWeaponInstance* NewInstance = EquipmentManager->GetFirstInstanceOfType<UTenkaichiWeaponInstance>())
			{
				// 换武器了（且新武器有 owner/instigator，说明已完全初始化）

					CurrentInstance = NewInstance;
					RebuildWidgetFromWeapon();
					OnWeaponChanged(OldWeapon, CurrentInstance);
				}
			}
		}
	}
}

## 三、关键点讲解

### 1. `NativeTick` 里每帧"轮询"武器

```cpp
if (APawn* Pawn = GetOwningPlayerPawn())
{
	if (UTenkaichiEquipmentManagerComponent* EquipmentManager = Pawn->FindComponentByClass<UTenkaichiEquipmentManagerComponent>())
	{
		if (UTenkaichiWeaponInstance* NewInstance = EquipmentManager->GetFirstInstanceOfType<UTenkaichiWeaponInstance>())
```

三级链：**Pawn → 装备管理器组件 → 第一个武器实例**。

> 为什么用"每帧轮询"而不是"事件监听"？因为 Lyra 没有给"武器切换"提供广播事件，轮询是最简单的做法。对 UI 来说每帧三次查找开销可接受。

### 2. `NewInstance != CurrentInstance`——只在变化时处理

```cpp
if (NewInstance != CurrentInstance && NewInstance->GetInstigator() != nullptr)
```

两个条件：
1. **确实是新武器**（指针不同）。
2. **新武器已完全初始化**（`GetInstigator() != nullptr`）。

**为什么需要条件 2？** 因为武器实例可能在"正在生成"的过程中就被 `GetFirstInstanceOfType` 拿到，但当时还没设置 Instigator（Owner）。等它完全初始化后再触发 `OnWeaponChanged`，避免 UI 读到半成品数据。

### 3. `OldWeapon` / `NewWeapon` 双参数事件

```cpp
UTenkaichiWeaponInstance* OldWeapon = CurrentInstance;
CurrentInstance = NewInstance;
RebuildWidgetFromWeapon();
OnWeaponChanged(OldWeapon, CurrentInstance);
```

**先存旧值 → 再更新成员 → 再通知**。这样 `OnWeaponChanged` 能同时拿到"从什么变成什么"（比如做切换动画、比较类型）。

### 4. `BlueprintImplementableEvent`——子类必须实现

```cpp
UFUNCTION(BlueprintImplementableEvent)
void OnWeaponChanged(UTenkaichiWeaponInstance* OldWeapon, UTenkaichiWeaponInstance* NewWeapon);
```

P16.3.2 讲过：`BlueprintImplementableEvent` = C++ 只声明，实现全在蓝图。子类（具体武器 UI）在蓝图里实现它，去更新显示。

### 5. `RebuildWidgetFromWeapon()` 空实现

```cpp
void UTenkaichiWeaponUserInterface::RebuildWidgetFromWeapon()
{
	
}
```

Lyra 留了个**空函数**（private，非虚）——目前没用，可能后续会用到。按铁律 23 照抄保留（含函数体里的空行）。

### 6. `NativeConstruct` / `NativeDestruct` 只调 Super

```cpp
void UTenkaichiWeaponUserInterface::NativeConstruct()
{
	Super::NativeConstruct();
}
```

这两个覆写**没有额外逻辑**（只调 Super）。Lyra 保留它们作为"将来扩展的钩子"。

> 按铁律 23 照抄——不要因为"没用"就删掉。

### 7. 为什么 `NativeTick` 能生效？（需要开启 Tick）

`UUserWidget::NativeTick` 只有在**控件 Tick 被启用**时才调用。默认 UMG 控件是开启 Tick 的（除非加了 `DisableNativeTick` meta）。本类**没有** `DisableNativeTick`，所以 Tick 生效。

> 对比 P16.4.4 `UTenkaichiBoundActionButton` 加了 `DisableNativeTick`（按钮不需要 Tick）。
