## 一、这个类解决什么问题（先讲为什么）

设置界面（Settings）需要：
- **多个标签页**（画面/音频/操作/游戏性）。
- **返回/应用/取消**三个操作（用输入动作触发，支持手柄）。
- **脏状态管理**：改了设置才显示"应用/取消"按钮。

`ULyraSettingScreen` 继承 CommonUI 的 `UGameSettingScreen`（它已经做了"设置项列表 + 导航"），只加：
1. **顶部标签页**（`TopSettingsTabs`，用 P16.4.5 的 `UTenkaichiTabListWidgetBase`）。
2. **三个输入动作绑定**（返回/应用/取消）。
3. **脏状态联动**（改了才加"应用/取消"绑定）。

> **类比**：`UGameSettingScreen` 是"设置面板骨架"，`ULyraSettingScreen` 是"加了标签页和快捷键的面板"。

## 三、关键点讲解

### 1. 基类 `UGameSettingScreen`（CommonUI 插件）

```cpp
class UTenkaichiSettingScreen : public UGameSettingScreen
```

`UGameSettingScreen`（`Widgets/GameSettingScreen.h`）：CommonUI 的"设置屏"基类，提供：
- `CreateRegistry()`（虚函数，子类实现"用哪个设置注册表"）。
- `ApplyChanges()` / `CancelChanges()`（应用/撤销）。
- `AttemptToPopNavigation()`（返回上一级）。
- `OnSettingsDirtyStateChanged`（脏状态回调）。
- `RegisterUIActionBinding` / `AddActionBinding` / `RemoveActionBinding`（输入动作绑定管理）。

> 这是"引擎/插件底层接口"——按 MEMORY 的教学分级，**只讲不拆**（不逐行教 `UGameSettingScreen` 本身）。

### 2. `UCLASS(Abstract, meta = (Category = "Settings", DisableNativeTick))`

```cpp
UCLASS(Abstract, meta = (Category = "Settings", DisableNativeTick))
```

- `Abstract`：抽象类（必须蓝图子类）。
- `Category = "Settings"`：UMG 编辑器控件面板里的分类。
- `DisableNativeTick`：禁用原生 Tick（设置屏不需要每帧逻辑）。

### 3. `meta = (BindWidget, OptionalWidget = true, AllowPrivateAccess = true)`

```cpp
UPROPERTY(BlueprintReadOnly, Category = Input, meta = (BindWidget, OptionalWidget = true, AllowPrivateAccess = true))
TObjectPtr<UTenkaichiTabListWidgetBase> TopSettingsTabs;
```

三个 meta：
| meta | 作用 |
|------|------|
| `BindWidget` | 蓝图里找同名控件自动绑定 |
| `OptionalWidget = true` | **可选**（蓝图没有也不报错） |
| `AllowPrivateAccess = true` | 私有成员也允许蓝图访问 |

> 注意 `OptionalWidget` 是**另一种写法**（对比 P16.3.1 的 `BindWidgetOptional`）——两者效果相同，Lyra 这里用了 `BindWidget + OptionalWidget`。

### 4. `RegisterUIActionBinding(FBindUIActionArgs(数据表行, true, 委托))`

```cpp
BackHandle = RegisterUIActionBinding(FBindUIActionArgs(BackInputActionData, true, FSimpleDelegate::CreateUObject(this, &ThisClass::HandleBackAction)));
```

对比 P16.1.3 的 `RegisterUIActionBinding(FBindUIActionArgs(FUIActionTag::ConvertChecked(TAG), false, 委托))`：

| 参数 | P16.1.3（HUDLayout） | P16.9.5（SettingScreen） |
|------|---------------------|------------------------|
| 动作来源 | `FUIActionTag`（GameplayTag） | **`FDataTableRowHandle`**（数据表行） |
| `bConsumeInput` | `false` | **`true`**（吃掉输入） |

**为什么用数据表行？** 因为设置屏的快捷键要**可配置**（策划在数据表里配"返回用哪个键"），而 HUDLayout 的 Esc 是硬编码 tag。

**`bConsumeInput = true`**：吃掉输入（防止 Esc 同时触发"关闭设置"和"关闭游戏"）。

### 6. `HandleBackAction`——三级返回逻辑

```cpp
void UTenkaichiSettingScreen::HandleBackAction()
{
	if (AttemptToPopNavigation())   // ① 有子页面 → 返回上一级
	{
		return;
	}

	ApplyChanges();                  // ② 没有子页面 → 应用改动
	DeactivateWidget();              // ③ 关闭设置屏
}
```

**三级**：
1. 在子页面（比如"画面设置"里）→ 返回标签页。
2. 在标签页 → 应用改动。
3. 然后关闭。

### 7. `OnSettingsDirtyStateChanged_Implementation`——脏状态联动

```cpp
if (bSettingsDirty)
{
	if (!GetActionBindings().Contains(ApplyHandle)) { AddActionBinding(ApplyHandle); }
	if (!GetActionBindings().Contains(CancelChangesHandle)) { AddActionBinding(CancelChangesHandle); }
}
else
{
	RemoveActionBinding(ApplyHandle);
	RemoveActionBinding(CancelChangesHandle);
}
```

**逻辑**：
- **有改动**（`bSettingsDirty`）→ **加**"应用/取消"绑定（玩家能按快捷键）。
- **没改动** → **移除**绑定（按了也没意义）。

`Contains(...)` 检查：避免重复添加。

> 这是"按需启用快捷键"的设计——没改动时按"应用"什么都不做，不如直接禁用。

### 8. `FUIActionBindingHandle`——绑定句柄

```cpp
FUIActionBindingHandle BackHandle;
FUIActionBindingHandle ApplyHandle;
FUIActionBindingHandle CancelChangesHandle;
```

`RegisterUIActionBinding` 返回的句柄——用于后续 `AddActionBinding` / `RemoveActionBinding`（动态启停）。

> 注意 `BackHandle` **从不被移除**（返回键一直有效），只有 `ApplyHandle` / `CancelChangesHandle` 会动态增删。
