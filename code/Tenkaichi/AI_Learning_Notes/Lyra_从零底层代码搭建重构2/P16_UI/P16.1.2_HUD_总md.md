## 一、这个类解决什么问题（先讲为什么）

引擎的 `AHUD` 是"抬头显示" Actor——每个玩家控制器有一个，负责画 HUD。Lyra 继承它做了 `ALyraHUD`，但 Lyra 源码注释明确说：

> "Note that you typically do not need to extend or modify this class, instead you would use an 'Add Widget' action in your experience to add a HUD layout and widgets to it. This class exists primarily for debug rendering."

也就是说：**这个类不需要你改，UI 是通过 P15.7 `AddWidgets` 加的**。它主要干两件事：

1. **作为 ModularGameplay 的"组件接收者"**：`AddGameFrameworkComponentReceiver`——这样 `UGameFrameworkComponentManager` 能给它发扩展事件（P15.7 `AddExtensionHandler` 的接收方）。
2. **广播 `NAME_GameActorReady`**：`BeginPlay` 时发"游戏 Actor 就绪"事件——**P15.7 `AddWidgets` 就是监听这个事件来加 UI 的**。
3. **调试渲染**：`GetDebugActorList` 把所有带 ASC 的 Actor 加进调试列表（引擎调试视图用）。

> **类比**：HUD 是"舞台上的告示牌架子"——架子本身不画内容，但它是"挂告示（Widget）"的地方。架子立好时会喊一声"我准备好了"（`NAME_GameActorReady`），挂告示的人（P15.7）听见就来挂。
