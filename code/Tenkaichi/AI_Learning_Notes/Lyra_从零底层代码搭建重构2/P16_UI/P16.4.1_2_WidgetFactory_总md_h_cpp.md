## 一、这两个类解决什么问题（先讲为什么）

列表控件（`UListView`/`UTileView`）需要"**给每条数据配一个控件**"（比如玩家列表里，每个玩家显示一个玩家条目控件）。

默认方式是"所有数据用同一个控件类"。但有时**不同类型的数据要用不同的控件**（比如"好友"显示绿色条目、"敌人"显示红色条目）。

`ULyraWidgetFactory` 就是抽象这个逻辑的**接口**：
- `ULyraWidgetFactory`（抽象基类）：声明 `FindWidgetClassForData(Data)` → 返回"这条数据该用哪个控件类"。
- `ULyraWidgetFactory_Class`（实现）：配置一个"类 → 控件类"的映射表，然后**沿继承链往上找**匹配的规则。

> **类比**：
> - `WidgetFactory` = "控件选型规则"的抽象标准（谁来都得回答"这条数据配哪个控件"）。
> - `WidgetFactory_Class` = "按类查表"的具体规则——你配"玩家类→玩家条目控件"，它就能查出来；如果数据是"玩家类的子类"，它会**往上找父类规则**。

### P16.4.2 `TenkaichiWidgetFactory_Class.h`（31 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "TenkaichiWidgetFactory.h"
#include "Templates/SubclassOf.h"
#include "UObject/SoftObjectPtr.h"

#include "TenkaichiWidgetFactory_Class.generated.h"

#define UE_API TENKAICHIGAME_API

class UObject;
class UUserWidget;

// 控件工厂实现：按"数据类 → 控件类"映射表找。
UCLASS(MinimalAPI)
class UTenkaichiWidgetFactory_Class : public UTenkaichiWidgetFactory
{
	GENERATED_BODY()

public:
	// 构造函数：空实现。
	UTenkaichiWidgetFactory_Class() { }

	// 找控件类（沿继承链往上查映射表）。
	UE_API virtual TSubclassOf<UUserWidget> FindWidgetClassForData_Implementation(const UObject* Data) const override;
	
protected:
	// 数据类 → 控件类 的映射表。
	UPROPERTY(EditAnywhere, Category = ListEntries, meta = (AllowAbstract))
	TMap<TSoftClassPtr<UObject>, TSubclassOf<UUserWidget>> EntryWidgetForClass;
};

#undef UE_API
```

### P16.4.2 `TenkaichiWidgetFactory_Class.cpp`（22 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiWidgetFactory_Class.h"

#include "Blueprint/UserWidget.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiWidgetFactory_Class)

// 找控件类（沿继承链往上查映射表）。
TSubclassOf<UUserWidget> UTenkaichiWidgetFactory_Class::FindWidgetClassForData_Implementation(const UObject* Data) const
{
	// 从当前类开始，一路往父类找，看有没有这个类的构造规则。
	for (UClass* Class = Data->GetClass(); Class; Class = Class->GetSuperClass())
	{
		TSoftClassPtr<UObject> ClassPtr(Class);
		if (const TSubclassOf<UUserWidget> EntryWidgetClassPtr = EntryWidgetForClass.FindRef(ClassPtr))
		{
			return EntryWidgetClassPtr;
		}
	}

	return TSubclassOf<UUserWidget>();
}
```

## 三、关键点讲解

### 1. `UCLASS(MinimalAPI, Abstract, Blueprintable, BlueprintType, EditInlineNew)`

五个修饰符：

| 修饰符 | 作用 |
|--------|------|
| `MinimalAPI` | 精简导出（成员手动标 `UE_API`） |
| `Abstract` | 抽象类（不能直接实例化） |
| `Blueprintable` | 蓝图可继承 |
| `BlueprintType` | 蓝图可作变量类型 |
| **`EditInlineNew`** | **可以在编辑器里"内联新建"实例**（作为属性值时直接 new，不用先建资产） |

`EditInlineNew` 很关键：这样在别的类的属性里（比如 `ListView` 的 `EntryWidgetFactory`），可以直接展开配置工厂实例，不用单独创建一个 `UObject` 资产。

### 2. `BlueprintNativeEvent` + `_Implementation`

```cpp
UFUNCTION(BlueprintNativeEvent)
TSubclassOf<UUserWidget> FindWidgetClassForData(const UObject* Data) const;

// .cpp 里：
TSubclassOf<UUserWidget> UTenkaichiWidgetFactory::FindWidgetClassForData_Implementation(const UObject* Data) const
{
	return TSubclassOf<UUserWidget>();
}
```

`BlueprintNativeEvent` 要求 C++ 提供 `_Implementation`。基类实现返回空（表示"我找不到"），子类覆写。

### 3. `template <class TClass> class TSubclassOf;`——模板前置声明

```cpp
template <class TClass> class TSubclassOf;
```

前置声明一个**模板类**（不是普通类）。这样 `.h` 里用 `TSubclassOf<UUserWidget>` 不用 include `Templates/SubclassOf.h`。

> 注意 `.cpp` 里才真正 include `Templates/SubclassOf.h`（用到了完整定义）。

### 4. `TMap<TSoftClassPtr<UObject>, TSubclassOf<UUserWidget>>`

```cpp
UPROPERTY(EditAnywhere, Category = ListEntries, meta = (AllowAbstract))
TMap<TSoftClassPtr<UObject>, TSubclassOf<UUserWidget>> EntryWidgetForClass;
```

映射表：
- Key：`TSoftClassPtr<UObject>`（数据类，软引用——不强制加载）。
- Value：`TSubclassOf<UUserWidget>`（对应的控件类，硬引用）。

`meta = (AllowAbstract)`：编辑器里**允许选抽象类**作为 Key（方便配"所有 Pawn 子类都用某个控件"这种规则）。

### 5. 沿继承链往上找（核心逻辑）

```cpp
for (UClass* Class = Data->GetClass(); Class; Class = Class->GetSuperClass())
{
	TSoftClassPtr<UObject> ClassPtr(Class);
	if (const TSubclassOf<UUserWidget> EntryWidgetClassPtr = EntryWidgetForClass.FindRef(ClassPtr))
	{
		return EntryWidgetClassPtr;
	}
}
```

**核心技巧**：从数据的实际类开始，**一路往父类找**。

举例：映射表配了 `APawn → 通用Pawn条目`。数据是 `ATenkaichiCharacter`（`APawn` 的子类）：
1. 查 `ATenkaichiCharacter` → 没有。
2. 查 `ACharacter`（父类）→ 没有。
3. 查 `APawn`（祖父类）→ **有！返回 `通用Pawn条目`**。

这样只配一条父类规则，所有子类都能用——**支持"规则继承"**。

### 6. `FindRef` vs `Find`

```cpp
if (const TSubclassOf<UUserWidget> EntryWidgetClassPtr = EntryWidgetForClass.FindRef(ClassPtr))
```

`TMap::FindRef(Key)`：按 Key 找 Value 的**拷贝**（不是指针）。找不到返回默认构造值（空 `TSubclassOf`）。

对比 `Find()` 返回指针（找到才非空）。

### 7. 为什么两个类用 `MinimalAPI` + `#define UE_API`

两个类都跨模块使用（ListView 的属性里会引用 `ULyraWidgetFactory`），所以用 `MinimalAPI` + 手动标 `UE_API`。

> 注意 `UTenkaichiWidgetFactory_Class` 覆写的 `_Implementation` 也标了 `UE_API`（因为它要跨模块被调用）。
