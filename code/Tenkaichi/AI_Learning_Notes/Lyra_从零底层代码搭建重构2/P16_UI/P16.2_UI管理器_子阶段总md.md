## 〇、为什么先建这个子阶段总 md

P16.2 的 2 个类都是"UI 全局管理"——一个管 UI 栈的可见性，一个管弹窗消息。它们建立在 CommonGame 插件的 UI 体系上。

---

## 一、这两个类解决什么问题（先讲为什么）

**1. `UTenkaichiUIManagerSubsystem`（UI 管理器）**

CommonGame 插件提供 `UGameUIManagerSubsystem`——管理"每个本地玩家的 UI 布局根（RootLayout）"。Lyra 继承它，只加了一件事：**每帧同步"UI 可见性"到 HUD 的 `bShowHUD`**。

具体：按 `~` 键开关 HUD（引擎调试功能）时，`AHUD::bShowHUD` 变化。Lyra 希望"关 HUD 时整个 UI 也隐藏"。所以每帧检查所有本地玩家，把 `bShowHUD` 映射成 RootLayout 的可见性。

**2. `UTenkaichiUIMessaging`（UI 消息）**

CommonGame 插件提供 `UCommonMessagingSubsystem`——统一的消息接口（显示确认框、错误框）。Lyra 继承它，实现"把对话框推到 `UI.Layer.Modal` 层"。

> **类比**：
> - UIManagerSubsystem = "UI 总闸"——控制所有 UI 是显示还是隐藏。
> - UIMessaging = "弹窗服务台"——统一弹确认框/错误框。
