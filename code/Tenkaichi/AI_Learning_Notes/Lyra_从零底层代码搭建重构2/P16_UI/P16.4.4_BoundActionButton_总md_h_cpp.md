## 一、这个类解决什么问题（先讲为什么）

`UCommonBoundActionButton` 是 CommonUI 的"绑定动作按钮"——它会在按钮上显示"触发这个按钮的输入动作"（比如手柄的 `A`、键鼠的 `左键`），并且**输入动作会随输入方式自动切换图标**。

但图标换对了，**按钮的整体外观**（背景色、边框、字体）也该跟着换——手柄时用"手柄风格的按钮皮肤"，键鼠时用"键鼠风格"。

`ULyraBoundActionButton` 做的就是这件事：配 3 套样式（键盘/手柄/触摸），**输入方式变化时自动切**。

> **类比**：`UCommonBoundActionButton` 是"会换图标键位的按钮"，`ULyraBoundActionButton` 是"连皮肤也换的按钮"。

## 二、完整代码（可直接照抄）

### `TenkaichiBoundActionButton.h`（38 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "Input/CommonBoundActionButton.h"

#include "TenkaichiBoundActionButton.generated.h"

#define UE_API TENKAICHIGAME_API

class UCommonButtonStyle;
class UObject;

// 绑定动作按钮：按输入方式（键鼠/手柄/触摸）自动切换按钮样式。
UCLASS(MinimalAPI, Abstract, meta = (DisableNativeTick))
class UTenkaichiBoundActionButton : public UCommonBoundActionButton
{
	GENERATED_BODY()
	
protected:
	// 控件构造完成（绑输入方式变化事件 + 立刻应用一次样式）。
	UE_API virtual void NativeConstruct() override;

private:
	// 输入方式变化回调（切换样式）。
	void HandleInputMethodChanged(ECommonInputType NewInputMethod);

	// 键鼠样式。
	UPROPERTY(EditAnywhere, Category = "Styles")
	TSubclassOf<UCommonButtonStyle> KeyboardStyle;

	// 手柄样式。
	UPROPERTY(EditAnywhere, Category = "Styles")
	TSubclassOf<UCommonButtonStyle> GamepadStyle;

	// 触摸样式。
	UPROPERTY(EditAnywhere, Category = "Styles")
	TSubclassOf<UCommonButtonStyle> TouchStyle;
};

#undef UE_API
```

### `TenkaichiBoundActionButton.cpp`（45 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiBoundActionButton.h"

#include "CommonInputSubsystem.h"
#include "CommonInputTypeEnum.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiBoundActionButton)

class UCommonButtonStyle;

// 控件构造完成（绑输入方式变化事件 + 立刻应用一次样式）。
void UTenkaichiBoundActionButton::NativeConstruct()
{
	Super::NativeConstruct();

	if (UCommonInputSubsystem* InputSubsystem = GetInputSubsystem())
	{
		// 绑"输入方式变化"事件
		InputSubsystem->OnInputMethodChangedNative.AddUObject(this, &ThisClass::HandleInputMethodChanged);
		// 立刻按当前输入方式应用一次（否则首次显示样式不对）
		HandleInputMethodChanged(InputSubsystem->GetCurrentInputType());
	}
}

// 输入方式变化回调（切换样式）。
void UTenkaichiBoundActionButton::HandleInputMethodChanged(ECommonInputType NewInputMethod)
{
	TSubclassOf<UCommonButtonStyle> NewStyle = nullptr;

	if (NewInputMethod == ECommonInputType::Gamepad)
	{
		NewStyle = GamepadStyle;
	}
	else if (NewInputMethod == ECommonInputType::Touch)
	{
		NewStyle = TouchStyle;
	}
	else
	{
		NewStyle = KeyboardStyle;
	}

	// 只有配了样式才设置（没配就保留当前）
	if (NewStyle)
	{
		SetStyle(NewStyle);
	}
}
```

## 三、关键点讲解

### 1. 基类 `UCommonBoundActionButton`（不是 `UCommonButtonBase`）

```cpp
class UTenkaichiBoundActionButton : public UCommonBoundActionButton
```

继承链：`UCommonBoundActionButton` → `UCommonButtonBase`。它比普通按钮多了"**绑定输入动作**"的能力（自动显示触发键图标 + 响应该键）。

> 对比 P16.3.2 的 `UTenkaichiButtonBase` 继承 `UCommonButtonBase`（无动作绑定）。

### 2. `NativeConstruct`——构造完成时（UUserWidget 生命周期）

```cpp
virtual void NativeConstruct() override;
```

`NativeConstruct`：控件**构造完成**时调用（每次加入视口都会调，可能多次）。

> 对比：
> - `NativeOnInitialized`：只调一次（控件初始化）。
> - `NativeConstruct`：每次构造都调（重建时也会）。
> - `NativeOnActivated`：每次激活都调（CommonUI 特有）。

### 3. 绑事件 + 立刻应用一次（关键模式）

```cpp
InputSubsystem->OnInputMethodChangedNative.AddUObject(this, &ThisClass::HandleInputMethodChanged);
HandleInputMethodChanged(InputSubsystem->GetCurrentInputType());
```

**两件事缺一不可**：
1. `AddUObject`：绑"输入方式变化"事件（将来变化时切）。
2. 立刻调一次：**用当前输入方式应用样式**。

**为什么必须立刻调？** 因为 `OnInputMethodChangedNative` 只在**变化时**触发。控件刚创建时输入方式没"变化"，不调的话首次显示的样式就是错的（比如手柄玩家看到键鼠样式）。

> 这是"注册监听 + 初始同步"的经典模式（P16.1.3 的 HUDLayout 也类似）。

### 4. `OnInputMethodChangedNative` 带 `Native` 后缀

```cpp
InputSubsystem->OnInputMethodChangedNative.AddUObject(...)
```

`OnInputMethodChangedNative`：**C++ 原生版**委托（不是动态委托，不能蓝图绑，但更快）。

对比常见还有 `OnInputMethodChanged`（动态版，蓝图可绑）。这里用 Native 版因为纯 C++ 处理。

### 5. 三选一 + `else` 兜底键鼠

```cpp
if (NewInputMethod == ECommonInputType::Gamepad)
	NewStyle = GamepadStyle;
else if (NewInputMethod == ECommonInputType::Touch)
	NewStyle = TouchStyle;
else
	NewStyle = KeyboardStyle;   // 兜底：鼠标键盘 + 其他所有
```

`ECommonInputType` 有 `MouseAndKeyboard`/`Gamepad`/`Touch` 等值。这里用 `else` 兜底——所有非手柄非触摸的都当键鼠。

### 6. `if (NewStyle)`——没配就保留当前样式

```cpp
if (NewStyle)
{
	SetStyle(NewStyle);
}
```

如果某个输入方式的样式没配（空 `TSubclassOf`），**不设置**（保留当前样式），避免把样式清空。

### 7. `UCLASS(MinimalAPI, Abstract, meta = (DisableNativeTick))`

- `Abstract`：抽象类（蓝图里必须有子类才能用）。
- `DisableNativeTick`：禁用原生 Tick（按钮不需要每帧逻辑）。
