## 一、这个类解决什么问题（先讲为什么）

CommonUI 的 `UCommonActionWidget` 负责显示"输入动作的按键图标"（比如显示一个 `A` 键图标）。

但它默认从**数据表**读"动作 → 图标"的映射。问题是：**玩家如果重绑了按键**，数据表里的映射就过时了（数据表里写 `A` 是跳跃，玩家改成了 `空格`，图标还显示 `A`）。

Lyra 做了 `ULyraActionWidget`：如果配了 `AssociatedInputAction`（增强输入的输入动作），就**实时查"这个动作现在绑了哪些键"**，用那个键的图标——这样重绑后图标会跟着变。

> **类比**：`UCommonActionWidget` 是"查字典显示按键图标"，`ULyraActionWidget` 是"实时查你现在的键位设置"——重绑了也能显示对。

### `TenkaichiActionWidget.cpp`（41 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiActionWidget.h"

#include "CommonInputBaseTypes.h"
#include "CommonInputSubsystem.h"
#include "Engine/LocalPlayer.h"
#include "EnhancedInputSubsystems.h"

// 返回图标（按增强输入的实际键位查）。
FSlateBrush UTenkaichiActionWidget::GetIcon() const
{
	// 如果有增强输入动作关联到这个控件，就搜索绑定到该动作的键，
	// 用那些键的图标代替默认数据表设置。这覆盖了玩家重绑按键的情况。
	if (AssociatedInputAction)
	{
		if (const UEnhancedInputLocalPlayerSubsystem* EnhancedInputSubsystem = GetEnhancedInputSubsystem())
		{
			// 查询这个动作绑定了哪些键
			TArray<FKey> BoundKeys = EnhancedInputSubsystem->QueryKeysMappedToAction(AssociatedInputAction);
			FSlateBrush SlateBrush;

			const UCommonInputSubsystem* CommonInputSubsystem = GetInputSubsystem();
			// 用第一个绑定键的图标
			if (!BoundKeys.IsEmpty() && CommonInputSubsystem && UCommonInputPlatformSettings::Get()->TryGetInputBrush(SlateBrush, BoundKeys[0], CommonInputSubsystem->GetCurrentInputType(), CommonInputSubsystem->GetCurrentGamepadName()))
			{
				return SlateBrush;
			}
		}
	}
	
	// 否则回退到父类默认（数据表）
	return Super::GetIcon();
}

// 获取本控件的增强输入本地玩家子系统。
UEnhancedInputLocalPlayerSubsystem* UTenkaichiActionWidget::GetEnhancedInputSubsystem() const
{
	// 优先用"绑定控件"的本地玩家（如果这个控件被绑到了别的控件上）
	const UWidget* BoundWidget = DisplayedBindingHandle.GetBoundWidget();
	if (const ULocalPlayer* BindingOwner = BoundWidget ? BoundWidget->GetOwningLocalPlayer() : GetOwningLocalPlayer())
	{
		return BindingOwner->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>();
	}
	return nullptr;
}
```

## 三、关键点讲解

### 1. `GetIcon()` 覆写——实时查键位

```cpp
virtual FSlateBrush GetIcon() const override;
```

`FSlateBrush`：Slate 的"画刷"（图标/纹理 + 绘制设置）。返回这个画刷 = 这个控件画出来的图标。

**逻辑**：
1. 有 `AssociatedInputAction` 吗？
2. 有 → `QueryKeysMappedToAction(action)` 查这个动作当前绑了哪些键。
3. 拿到第一个键 → `TryGetInputBrush(...)` 查这个键的图标画刷。
4. 成功 → 返回这个画刷。
5. 失败/没配 → `Super::GetIcon()`（父类从数据表读）。

### 2. `QueryKeysMappedToAction`——查动作绑定的键

```cpp
TArray<FKey> BoundKeys = EnhancedInputSubsystem->QueryKeysMappedToAction(AssociatedInputAction);
```

`UEnhancedInputLocalPlayerSubsystem::QueryKeysMappedToAction(InputAction)`：返回**这个输入动作当前绑定的所有键**（考虑玩家的重绑设置）。

### 3. `TryGetInputBrush`——按平台/输入方式取图标

```cpp
UCommonInputPlatformSettings::Get()->TryGetInputBrush(SlateBrush, BoundKeys[0], CommonInputSubsystem->GetCurrentInputType(), CommonInputSubsystem->GetCurrentGamepadName())
```

四个参数：
1. `SlateBrush`（输出）：拿到的图标画刷。
2. `BoundKeys[0]`：用第一个绑定键（一个动作可能绑多个键，只显示第一个）。
3. `GetCurrentInputType()`：当前输入方式（键鼠/手柄/触摸）。
4. `GetCurrentGamepadName()`：当前手柄名（不同手柄的 ABXY 图标不同）。

> 这就是"**同一按键在不同手柄上显示不同图标**"的机制。

### 4. `DisplayedBindingHandle.GetBoundWidget()`——绑定控件

```cpp
const UWidget* BoundWidget = DisplayedBindingHandle.GetBoundWidget();
if (const ULocalPlayer* BindingOwner = BoundWidget ? BoundWidget->GetOwningLocalPlayer() : GetOwningLocalPlayer())
```

`DisplayedBindingHandle` 是 `UCommonActionWidget` 的成员——当这个动作控件被"绑到"某个按钮上时（比如按钮旁边显示 `[A]`），`GetBoundWidget()` 返回那个按钮。

**为什么要用绑定控件的本地玩家？** 因为动作控件本身可能没有本地玩家（它是个挂在按钮上的小图标），要从宿主按钮拿。

三元判断：有绑定控件就用它的，没有就用自己。

### 5. `TObjectPtr<UInputAction>` 加了 `const`

```cpp
UPROPERTY(BlueprintReadOnly, EditAnywhere)
const TObjectPtr<UInputAction> AssociatedInputAction;
```

`const TObjectPtr<...>`：指针本身不可改（不能重新赋值指向别的动作）。注意 UE 里这种写法有点特殊，按铁律 23 照抄。

### 6. 为什么这个类不是 `Abstract`

```cpp
UCLASS(BlueprintType, Blueprintable)   // 没有 Abstract
```

对比 P16.3.2 的 `UTenkaichiButtonBase` 是 `UCLASS(Abstract, ...)`。这个类可以直接用（不需要一定继承）。
