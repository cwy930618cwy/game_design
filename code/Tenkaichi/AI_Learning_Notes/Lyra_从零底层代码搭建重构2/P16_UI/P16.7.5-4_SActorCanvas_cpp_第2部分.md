## 〇、这一部分在解决什么

`UpdateCanvas` 是**整个指示器系统的核心算法**——每帧（活跃定时器驱动）做：
1. 懒获取管理器组件（第一次拿到时绑事件 + 补加已有指示器）。
2. 拿相机投影数据。
3. 遍历每个槽位：自动移除失效的 → 投影算屏幕位置 → 更新深度/优先级 → 标脏。
4. 有变化就 `Invalidate(Paint)` 请求重绘。
5. 没指示器了就停定时器。

## 一、完整代码（可直接照抄）

```cpp
// 活跃定时器回调：每帧更新画布。
EActiveTimerReturnType SActorCanvas::UpdateCanvas(double InCurrentTime, float InDeltaTime)
{
	QUICK_SCOPE_CYCLE_COUNTER(STAT_SActorCanvas_UpdateCanvas);

	// ① 还没绘制过（没有几何信息），等下一帧
	if (!OptionalPaintGeometry.IsSet())
	{
		return EActiveTimerReturnType::Continue;
	}

	// ② 拿本地玩家
	ULocalPlayer* LocalPlayer = LocalPlayerContext.GetLocalPlayer();
	UTenkaichiIndicatorManagerComponent* IndicatorComponent = IndicatorComponentPtr.Get();
	if (IndicatorComponent == nullptr)
	{
		// ③ 懒获取管理器组件（第一次）
		IndicatorComponent = UTenkaichiIndicatorManagerComponent::GetComponent(LocalPlayerContext.GetPlayerController());
		if (IndicatorComponent)
		{
			// World 可能变了
			IndicatorPool.SetWorld(LocalPlayerContext.GetWorld());

			IndicatorComponentPtr = IndicatorComponent;
			// 绑增删事件
			IndicatorComponent->OnIndicatorAdded.AddSP(this, &SActorCanvas::OnIndicatorAdded);
			IndicatorComponent->OnIndicatorRemoved.AddSP(this, &SActorCanvas::OnIndicatorRemoved);
			// 补加"已经存在"的指示器
			for (UIndicatorDescriptor* Indicator : IndicatorComponent->GetIndicators())
			{
				OnIndicatorAdded(Indicator);
			}
		}
		else
		{
			//TODO HIDE EVERYTHING
			return EActiveTimerReturnType::Continue;
		}
	}

	// ④ 必须有玩家才能投影
	if (LocalPlayer)
	{
		const FGeometry PaintGeometry = OptionalPaintGeometry.GetValue();

		FSceneViewProjectionData ProjectionData;
		if (LocalPlayer->GetProjectionData(LocalPlayer->ViewportClient->Viewport, /*out*/ ProjectionData))
		{
			SetShowAnyIndicators(true);

			bool IndicatorsChanged = false;

			// ⑤ 遍历所有槽位
			for (int32 ChildIndex = 0; ChildIndex < CanvasChildren.Num(); ++ChildIndex)
			{
				SActorCanvas::FSlot& CurChild = CanvasChildren[ChildIndex];
				UIndicatorDescriptor* Indicator = CurChild.Indicator;

				// ⑥ 槽位内容失效且允许自动移除 → 移除
				if (Indicator->CanAutomaticallyRemove())
				{
					IndicatorsChanged = true;

					RemoveIndicatorForEntry(Indicator);
					// 索引回退（因为删了一个）
					--ChildIndex;
					continue;
				}

				// ⑦ 同步可见性
				CurChild.SetIsIndicatorVisible(Indicator->GetIsVisible());

				if (!CurChild.GetIsIndicatorVisible())
				{
					IndicatorsChanged |= CurChild.bIsDirty();
					CurChild.ClearDirtyFlag();
					continue;
				}

				// ⑧ 钳制状态变化 → 标记需要重绘
				if (CurChild.WasIndicatorClampedStatusChanged())
				{
					//Indicator->OnIndicatorClampedStatusChanged(CurChild.WasIndicatorClamped());
					CurChild.ClearIndicatorClampedStatusChangedFlag();
					IndicatorsChanged = true;
				}

				FVector ScreenPositionWithDepth;

				// ⑨ 投影：世界位置 → 屏幕位置 + 深度
				FIndicatorProjection Projector;
				const bool Success = Projector.Project(*Indicator, ProjectionData, PaintGeometry.Size, OUT ScreenPositionWithDepth);

				if (!Success)
				{
					CurChild.SetHasValidScreenPosition(false);
					CurChild.SetInFrontOfCamera(false);

					IndicatorsChanged |= CurChild.bIsDirty();
					CurChild.ClearDirtyFlag();
					continue;
				}

				// ⑩ 投影成功：更新"在相机前"和"有有效位置"
				CurChild.SetInFrontOfCamera(Success);
				CurChild.SetHasValidScreenPosition(CurChild.GetInFrontOfCamera() || Indicator->GetClampToScreen());

				if (CurChild.HasValidScreenPosition())
				{
					// 只有真能显示时才更新屏幕位置（避免脏标记误触发）
					CurChild.SetScreenPosition(FVector2D(ScreenPositionWithDepth));
					CurChild.SetDepth(ScreenPositionWithDepth.X);
				}

				// ⑪ 同步优先级
				CurChild.SetPriority(Indicator->GetPriority());

				IndicatorsChanged |= CurChild.bIsDirty();
				CurChild.ClearDirtyFlag();
			}

			// ⑫ 有变化就请求重绘
			if (IndicatorsChanged)
			{
				Invalidate(EInvalidateWidget::Paint);
			}
		}
		else
		{
			SetShowAnyIndicators(false);
		}
	}
	else
	{
		SetShowAnyIndicators(false);
	}

	// ⑬ 没指示器了就停定时器
	if (AllIndicators.Num() == 0)
	{
		TickHandle.Reset();
		return EActiveTimerReturnType::Stop;
	}
	else
	{
		return EActiveTimerReturnType::Continue;
	}
}
```

## 二、关键点讲解

### 1. `QUICK_SCOPE_CYCLE_COUNTER`——性能统计

```cpp
QUICK_SCOPE_CYCLE_COUNTER(STAT_SActorCanvas_UpdateCanvas);
```

在 Unreal Insights / Stat 命令里统计这个函数的耗时。零开销（非统计构建时展开为空）。

> 对比 P16.5 的 `SCOPED_BOOT_TIMING`（启动阶段专用）——这个是通用的作用域计时。

### 2. `OptionalPaintGeometry.IsSet()`——等第一次绘制

```cpp
if (!OptionalPaintGeometry.IsSet())
{
	return EActiveTimerReturnType::Continue;
}
```

`OptionalPaintGeometry` 在 `OnPaint` 里被写入（P16.7.5-5 会讲）。**第一次 `UpdateCanvas` 时还没绘制过**，所以没有几何信息 → 跳过（等下一帧）。

> 这是"先有绘制，才能算投影"的依赖关系。

### 3. 懒获取管理器组件（第一次拿到时做 3 件事）

```cpp
if (IndicatorComponent == nullptr)
{
	IndicatorComponent = UTenkaichiIndicatorManagerComponent::GetComponent(LocalPlayerContext.GetPlayerController());
	if (IndicatorComponent)
	{
		IndicatorPool.SetWorld(LocalPlayerContext.GetWorld());   // ① 更新池的 world

		IndicatorComponentPtr = IndicatorComponent;
		IndicatorComponent->OnIndicatorAdded.AddSP(this, &SActorCanvas::OnIndicatorAdded);      // ② 绑事件
		IndicatorComponent->OnIndicatorRemoved.AddSP(this, &SActorCanvas::OnIndicatorRemoved);
		for (UIndicatorDescriptor* Indicator : IndicatorComponent->GetIndicators())            // ③ 补加已有
		{
			OnIndicatorAdded(Indicator);
		}
	}
	else
	{
		//TODO HIDE EVERYTHING
		return EActiveTimerReturnType::Continue;
	}
}
```

**为什么"懒获取"？** 因为 `Construct` 时 PlayerController 可能还没创建（UI 先于 Controller 初始化）。所以每帧检查，拿到就绑事件。

**为什么"补加已有"？** 因为管理器可能在画布创建**之前**就已经有指示器了（比如 HUD 加载晚于任务系统）。绑事件只能收到"未来"的增删，所以要把"已有的"手动补一遍。

`AddSP(this, ...)`：绑 **Slate 对象**（`TSharedPtr`）的成员函数（对比 `AddUObject` 绑 UObject）。

### 4. `GetProjectionData`——拿相机投影数据

```cpp
FSceneViewProjectionData ProjectionData;
if (LocalPlayer->GetProjectionData(LocalPlayer->ViewportClient->Viewport, /*out*/ ProjectionData))
```

`ULocalPlayer::GetProjectionData(视口, out 数据)`：拿到"相机位置/朝向/投影矩阵"等（`FSceneViewProjectionData`）。

**返回 false 的情况**：视口无效/相机还没准备好 → 走 `SetShowAnyIndicators(false)`（全部隐藏）。

### 5. 遍历槽位时的**索引回退**

```cpp
for (int32 ChildIndex = 0; ChildIndex < CanvasChildren.Num(); ++ChildIndex)
{
	...
	if (Indicator->CanAutomaticallyRemove())
	{
		RemoveIndicatorForEntry(Indicator);
		--ChildIndex;      // ← 关键
		continue;
	}
```

**为什么 `--ChildIndex`？** 因为 `RemoveIndicatorForEntry` 会从 `CanvasChildren` 删掉一个元素，后面的元素前移。如果不回退索引，会**跳过**下一个元素。

> 这是"边遍历边删除"的标准处理（P15.3 的倒序遍历是另一种解法）。

### 6. `IndicatorsChanged |= CurChild.bIsDirty()`——累积脏标记

```cpp
IndicatorsChanged |= CurChild.bIsDirty();
CurChild.ClearDirtyFlag();
```

**模式**：把每个槽位的脏标记"或"进总标记，然后清掉槽位的脏标记。

**为什么？** 因为 `bDirty` 是"这个槽位变了"，`IndicatorsChanged` 是"整体需要重绘"。累积后统一 `Invalidate` 一次（避免多次重绘）。

### 7. `SetHasValidScreenPosition(GetInFrontOfCamera() || GetClampToScreen())`

```cpp
CurChild.SetInFrontOfCamera(Success);
CurChild.SetHasValidScreenPosition(CurChild.GetInFrontOfCamera() || Indicator->GetClampToScreen());
```

**"有有效屏幕位置"的两个来源**：
1. 在相机前方（`GetInFrontOfCamera()`）——正常投影。
2. **允许钳制到屏幕**（`GetClampToScreen()`）——即使在相机背后，也能贴边显示。

> 这就是"背后目标也能显示方向箭头"的实现基础。

### 8. 只有"能显示"才更新屏幕位置

```cpp
if (CurChild.HasValidScreenPosition())
{
	CurChild.SetScreenPosition(FVector2D(ScreenPositionWithDepth));
	CurChild.SetDepth(ScreenPositionWithDepth.X);
}
```

**为什么加这个 if？** 因为 `SetScreenPosition` 会标脏。如果指示器不可见（比如在相机背后且不允许钳制），更新位置没意义，还会触发无谓重绘。

### 9. `SetDepth(ScreenPositionWithDepth.X)`——深度用 X？

```cpp
CurChild.SetDepth(ScreenPositionWithDepth.X);
```

**注意**：`FIndicatorProjection::Project` 返回的 `FVector` 是 `(屏幕X, 屏幕Y, 深度)`。但这里 `SetDepth` 用的是 **`.X`**（屏幕 X）？

**这是 Lyra 源码的 bug**（应该用 `.Z`）。按铁律 23 **照抄不修**。

> 影响：深度排序会按"屏幕 X 坐标"排，而不是"到相机距离"。视觉上可能排序不对，但不崩溃。

### 10. `Invalidate(EInvalidateWidget::Paint)`——请求重绘

```cpp
if (IndicatorsChanged)
{
	Invalidate(EInvalidateWidget::Paint);
}
```

`Invalidate(原因)`：告诉 Slate"我需要重绘"。
- `EInvalidateWidget::Paint`：只重绘（不重新布局）。
- `EInvalidateWidget::Layout`：重新布局（P16.6.3 的 `SetRadius` 用的）。

### 11. 定时器自停

```cpp
if (AllIndicators.Num() == 0)
{
	TickHandle.Reset();
	return EActiveTimerReturnType::Stop;
}
else
{
	return EActiveTimerReturnType::Continue;
}
```

**注意**：这里**有**停定时器的逻辑（`TickHandle.Reset()` + `Stop`）——和 P16.7.5-3 里 `UpdateActiveTimer` 只注册不注销形成配合：
- `UpdateActiveTimer`：需要时注册。
- `UpdateCanvas` 末尾：没指示器时停掉。

> 所以是"按需启停"的完整闭环（我上一条说"只注册不注销"不准确，这里补正）。
