## 一、这个类解决什么问题（先讲为什么）

前端主菜单（大厅）通常有一个**3D 背景场景**（比如角色站在一个场景里，后面有动态背景）。这个场景是一个**独立的关卡**（`UWorld` 资产）。

`ULyraLobbyBackground` 就是一个**数据资产**，只存一个字段：`BackgroundLevel`（背景关卡软引用）。前端状态机（P16.8.2）读它来加载背景。

> **类比**：这是"大厅背景的配置卡"——只写"用哪个关卡当背景"，别的什么都不管。

## 三、关键点讲解

### 1. `UPrimaryDataAsset`——主数据资产

```cpp
class UTenkaichiLobbyBackground : public UPrimaryDataAsset
```

`UPrimaryDataAsset`：可以被 AssetManager 管理的主数据资产（有 `FPrimaryAssetId`）。P13.1 的 `UTenkaichiExperienceDefinition`、P13.9 的 `UTenkaichiUserFacingExperienceDefinition` 都是这个基类。

### 2. `UCLASS(config=EditorPerProjectUserSettings, MinimalAPI)`

```cpp
UCLASS(config=EditorPerProjectUserSettings, MinimalAPI)
```

- `config=EditorPerProjectUserSettings`：从 `EditorPerProjectUserSettings.ini` 读配置。
- `MinimalAPI`：精简导出。

> ⚠️ **注意**：`config=EditorPerProjectUserSettings` 对**数据资产**来说很奇怪（数据资产通常不读 ini）。这是 Lyra 源码的**可疑写法**（可能是从别的类复制过来的）。按铁律 23 **照抄不改**。

### 3. 注释 `Developer settings / editor cheats` 与类不符

```cpp
/**
 * 开发者设置 / 编辑器作弊
 */
UCLASS(config=EditorPerProjectUserSettings, MinimalAPI)
class UTenkaichiLobbyBackground : public UPrimaryDataAsset
```

注释说"开发者设置/编辑器作弊"，但类实际是"大厅背景数据资产"——**注释是从别处复制的**（Lyra 源码的瑕疵）。按铁律 23 照抄。

### 4. `TSoftObjectPtr<UWorld>`——软引用关卡

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly)
TSoftObjectPtr<UWorld> BackgroundLevel;
```

`TSoftObjectPtr<UWorld>`：软引用一个关卡资产（`UWorld`）。用软引用是因为背景关卡可能很大，不该在加载数据资产时就加载。

### 5. `.cpp` 只有 UHT 生成

```cpp
#include "TenkaichiLobbyBackground.h"
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiLobbyBackground)
```

`.cpp` 里**没有任何函数实现**（纯数据类，无自定义方法）。

> 对比 P16.6.3 的 `SignificanceManager`（也是空壳）——但那个是 UCLASS 空壳，这个是纯数据。
