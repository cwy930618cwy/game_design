## 三、逐段讲解

### 1. include 与前置声明

```cpp
#include "Inventory/KaizenInventoryItemDefinition.h"  // ← 应为 TenkaichiInventoryItemDefinition.h
#include "UObject/ObjectPtr.h"
```

> ⚠️ 上面注释处我故意写错了占位。**正确写法**：
> ```cpp
> #include "Inventory/TenkaichiInventoryItemDefinition.h"
> ```
> 因为要**继承** `UTenkaichiInventoryItemFragment`，需完整定义（P08.1 ✅）。

- `UObject/ObjectPtr.h`：`TObjectPtr` 智能指针所在的头文件。这是 UE5 的懒加载指针（延迟加载对象引用），现代 UE5 代码里用 `TObjectPtr<T>` 替代裸 `T*` 存 UObject 成员。

```cpp
class USkeletalMesh;
```

- 前置声明：字段是 `TObjectPtr<USkeletalMesh>`（指针），不需要完整定义即可声明。

### 2. 类声明

```cpp
class UInventoryFragment_PickupIcon : public UTenkaichiInventoryItemFragment
```

- 无 `Lyra` 前缀，原样。
- 继承 P08.1 碎片基类。

### 3. 构造函数

```cpp
	UInventoryFragment_PickupIcon();
```

- 声明构造函数（不带参数）。**实现放 `.cpp`**，在里面把 `PadColor` 默认成绿色。

### 4. 三个显示字段

```cpp
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Appearance)
	TObjectPtr<USkeletalMesh> SkeletalMesh;

	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Appearance)
	FText DisplayName;

	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Appearance)
	FLinearColor PadColor;
```

| 字段 | 类型 | 作用 |
|------|------|------|
| `SkeletalMesh` | `TObjectPtr<USkeletalMesh>` | 掉地上的 3D 模型（注意用 `TObjectPtr` 而非裸指针，UE5 新写法） |
| `DisplayName` | `FText` | 掉落物显示名（`FText` 用于需要**本地化**的文本） |
| `PadColor` | `FLinearColor` | 脚下垫子颜色（线性空间颜色，比 `FColor` 更精确） |

- `EditAnywhere`：每个物品资产上可配置。
- `BlueprintReadOnly`：蓝图里**能读、能配**，但不能在蓝图里写代码改它（只读暴露）。
- `Category=Appearance`：字段分组名（源码原样，不翻译）。

> 📌 对比 P08.4：那边字段是 `public` 无 `BlueprintReadOnly`，这边加了 `BlueprintReadOnly`。**为什么？** 因为掉落外观是要给蓝图/UI 读的数据（显示用），加 `BlueprintReadOnly` 让蓝图安全地读；而 `EquippableItem` 的 `EquipmentDefinition` 是给 C++ 装备系统读的，不需要蓝图读接口。按需决定，不是每个字段都要加。
