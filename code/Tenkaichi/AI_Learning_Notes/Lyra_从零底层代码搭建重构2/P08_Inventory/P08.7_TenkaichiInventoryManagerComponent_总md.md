## 一、本文件要解决什么

**这是 P08 真正的核心**。前面几课都是"零件"：
- `Definition` = 菜谱（数据）
- `Instance` = 一道菜（运行时对象）
- `Fragment` = 配料（可插拔特性）

但**"菜谱、菜、配料"都存在了，谁来管这一锅？** 就是本组件。

**InventoryManagerComponent = 物品清单管理器**，挂在角色身上：
- 保存一个"物品清单"（`FInventoryList`）
- 提供增删查（`AddItemDefinition` / `RemoveItemInstance` / `GetAllItems`...）
- 用 **FastArraySerializer** 做增量网络同步（只同步变动的格子，不是整个列表）
- 创建 `Instance` 时**自动触发所有 Fragment 的 `OnInstanceCreated`**（把配料灌进菜里）

一句话：**它是"物品清单"的拥有者 + 操作者 + 同步者。**

## 三、全景：一个文件里装了什么（4 个结构）

### ① `FTenkaichiInventoryChangeMessage`（消息结构体，`.h` 18-39）
清单**变化时广播的消息**，给 UI/逻辑监听用的"通知单"。

| 字段 | 类型 | 含义 |
|------|------|------|
| `InventoryOwner` | `TObjectPtr<UActorComponent>` | 哪个清单变的（持有者的组件） |
| `Instance` | `TObjectPtr<UTenkaichiInventoryItemInstance>` | 哪个物品实例变了 |
| `NewCount` | `int32` | 变化后数量 |
| `Delta` | `int32` | 变化量（+3 / -2） |

### ② `FTenkaichiInventoryEntry`（清单里的一个格子，`.h` 42-64）
**一条物品记录**：一个 `Instance` + 它的堆叠数。

| 字段 | 类型 | 作用 |
|------|------|------|
| `Instance` | `TObjectPtr<UTenkaichiInventoryItemInstance>` | 这个格子装的物品实例 |
| `StackCount` | `int32` | 堆叠数（弹药/数量） |
| `LastObservedCount` | `int32`（`NotReplicated`） | 记录上次看到的数量，用来算增量（只本地用，不网络同步） |

继承 `FFastArraySerializerItem`（FastArray 的格子基类，提供 `INDEX_NONE` 标记）。

### ③ `FTenkaichiInventoryList`（清单列表，`.h` 66-114）
**核心数据结构**，继承 `FFastArraySerializer` 实现增量同步。持有 `TArray<FTenkaichiInventoryEntry> Entries`。

它覆写了 FastArray 的 3 个回调（网络同步时自动触发广播）：
- `PreReplicatedRemove`（条目被移除前）：广播"从 N 变 0"
- `PostReplicatedAdd`（条目新增后）：广播"从 0 变 N"
- `PostReplicatedChange`（条目数量变了）：广播"从旧值变新值"

外加方法：`AddEntry`（增）/ `RemoveEntry`（删）/ `GetAllItems`（查）/ `BroadcastChangeMessage`（发广播）。

### ④ `UTenkaichiInventoryManagerComponent`（管理器，`.h` 134-171）
对外暴露的组件。

| 方法 | 作用 |
|------|------|
| `CanAddItemDefinition` | 能否加（目前恒 true，留了扩展位） |
| `AddItemDefinition` | 按定义加一个物品（建 Instance + 灌 Fragment 数据） |
| `AddItemInstance` | 直接塞一个现成 Instance |
| `RemoveItemInstance` | 移除一个 Instance |
| `GetAllItems` | 取所有物品 |
| `FindFirstItemStackByDefinition` | 按定义找第一个匹配的物品 |
| `GetTotalItemCountByDefinition` | 按定义统计数量 |
| `ConsumeItemsByDefinition` | 按定义消耗（删 N 个） |
| `ReplicateSubobjects` | 网络：把每个 Instance 作为子对象复制给客户端 |
| `ReadyForReplication` | 网络：同步前注册所有已有 Instance |

字段：`InventoryList: FTenkaichiInventoryList`（`Replicated`）—— 整个清单随网络同步。

## 五、核心难点：FastArraySerializer 增量同步（预读）

`FTenkaichiInventoryList : FFastArraySerializer` 是**P02 `FGameplayTagStackContainer` 的同款机制**（P02 已教过）。核心概念：
- 把"物品清单"当成一个数组，每个格子一个 `FTenkaichiInventoryEntry`。
- **只同步变化的那几个格子**（`MarkItemDirty`），不是整个数组——节省带宽。
- 网络同步时自动调用 `PreReplicatedRemove` / `PostReplicatedAdd` / `PostReplicatedChange` 三个回调，在这些回调里**发广播**通知 UI"清单变了"。

> 类比：快递清单。谁改动了哪个条目，就在那个条目上画个"✓"，快递员（网络）只把画勾的条目送过去，而不是整本清单重印。
