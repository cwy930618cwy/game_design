## 三、逐段讲解

### 1. include 与前置声明

```cpp
#include "Inventory/TenkaichiInventoryItemDefinition.h"
#include "Templates/SubclassOf.h"
```

- `Inventory/TenkaichiInventoryItemDefinition.h`：因为**继承** `UTenkaichiInventoryItemFragment`，要完整定义。
- `Templates/SubclassOf.h`：`TSubclassOf` 模板的所在头文件，用到它就要 include（P03 的 `InputConfig` 里也见过）。

```cpp
class ULyraEquipmentDefinition;
class UObject;
```

- `class ULyraEquipmentDefinition;`：**前置声明**。`TSubclassOf<ULyraEquipmentDefinition>` 的模板参数只声明、不实例化，所以编译器只需要"这是个类型名"，不需要完整定义 → **P09 类不存在也能编译**（铁律 30）。
- ⚠️ **保持原样写 `ULyraEquipmentDefinition`**，P09 才改成 `UTenkaichiEquipmentDefinition`（铁律 33：P09 是它的归属阶段，现在先占位）。

### 2. 类声明

```cpp
class UInventoryFragment_EquippableItem : public UTenkaichiInventoryItemFragment
```

- 无 `Lyra` 前缀，原样。
- 继承 P08.1 的碎片基类，成为"第二个真碎片"。

### 3. 唯一字段

```cpp
public:
	UPROPERTY(EditAnywhere, Category=Lyra)
	TSubclassOf<ULyraEquipmentDefinition> EquipmentDefinition;
```

- `TSubclassOf<ULyraEquipmentDefinition>`：**类引用**，不是实例引用。蓝图里给物品定义选一个"装备定义类"。
- `EditAnywhere`：每个物品定义资产上都能单独配置（比 `EditDefaultsOnly` 更自由——本碎片需要在具体物品资产上配置，所以用 `EditAnywhere`；对比 P08.3 的 `InitialItemStats` 是 `EditDefaultsOnly`）。
- `Category=Lyra`：源码原样保留（不翻译成中文，铁律 24 指"类名"，Category 字符串也是源码一部分照抄）。
- `public`：P08.3 的 `InitialItemStats` 是 `protected`，这里是 `public`——**因为它要给人读（P09 的 Equipment 逻辑会读这个字段），不同碎片按需决定访问级别**。

> 📌 **为什么没有方法？** 碎片可以只是"数据声明"。这个物品要不要装备、装备成什么，**不需要碎片自己执行逻辑**——逻辑在 P09 的装备系统里，它们**读**这个字段。碎片的作用是"告诉别人我有这个能力"。
