## 二、完整代码（`.h`，注释已中文化）

```cpp
// 版权声明（Lyra 项目自带，保留）
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "Kismet/BlueprintFunctionLibrary.h"
#include "Templates/SubclassOf.h"
#include "UObject/Interface.h"

#include "UObject/ObjectPtr.h"
#include "IPickupable.generated.h"

// 前置声明：脚本接口模板（UE 接口的智能指针容器）
template <typename InterfaceType> class TScriptInterface;

class AActor;
class UTenkaichiInventoryItemDefinition;
class UTenkaichiInventoryItemInstance;
class UTenkaichiInventoryManagerComponent;
class UObject;
struct FFrame;

// 掉落模板：捡到"一堆同种物品"（一个定义 + 数量）
USTRUCT(BlueprintType)
struct FPickupTemplate
{
	GENERATED_BODY()

public:
	// 数量（默认 1 个）
	UPROPERTY(EditAnywhere)
	int32 StackCount = 1;

	// 物品定义（这是什么物品）
	UPROPERTY(EditAnywhere)
	TSubclassOf<UTenkaichiInventoryItemDefinition> ItemDef;
};

// 掉落实例：捡到"一个现成的、已存在的物品实例"
USTRUCT(BlueprintType)
struct FPickupInstance
{
	GENERATED_BODY()

public:
	// 现成的物品实例
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TObjectPtr<UTenkaichiInventoryItemInstance> Item = nullptr;
};

// 掉落包：捡一次能拿到的一整包东西（现成实例列表 + 模板列表）
USTRUCT(BlueprintType)
struct FInventoryPickup
{
	GENERATED_BODY()

public:
	// 现成实例列表
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TArray<FPickupInstance> Instances;

	// 模板列表（按定义 + 数量批量生成）
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TArray<FPickupTemplate> Templates;
};

// 接口外壳：反射系统登记"这是一个接口"（不能直接在蓝图中实现）
UINTERFACE(MinimalAPI, BlueprintType, meta = (CannotImplementInterfaceInBlueprint))
class UPickupable : public UInterface
{
	GENERATED_BODY()
};

// 拾取接口（C++ 接口体）：实现它的 Actor 声明"我能被捡"
class IPickupable
{
	GENERATED_BODY()

public:
	// 纯虚函数：返回这个掉落物的"掉落包"（子类必须实现）
	UFUNCTION(BlueprintCallable)
	virtual FInventoryPickup GetPickupInventory() const = 0;
};

// 拾取工具类：静态函数库，负责"找能捡的" + "把捡到的塞进背包"
UCLASS()
class UPickupableStatics : public UBlueprintFunctionLibrary
{
	GENERATED_BODY()

public:
	// 构造函数
	UPickupableStatics();

public:
	// 从 Actor 上找出第一个"能捡的"接口（先看 Actor 自己，再看它的组件）
	UFUNCTION(BlueprintPure)
	static TScriptInterface<IPickupable> GetFirstPickupableFromActor(AActor* Actor);

	// 把掉落包里的东西塞进背包管理器（服务器权限）
	UFUNCTION(BlueprintCallable, BlueprintAuthorityOnly, meta = (WorldContext = "Ability"))
	static void AddPickupToInventory(UTenkaichiInventoryManagerComponent* InventoryComponent, TScriptInterface<IPickupable> Pickup);
};
```

## 三、逐段讲解

### 1. include 与前置声明

```cpp
#include "Kismet/BlueprintFunctionLibrary.h"
#include "Templates/SubclassOf.h"
#include "UObject/Interface.h"
#include "UObject/ObjectPtr.h"
```

- `Kismet/BlueprintFunctionLibrary.h`：`UBlueprintFunctionLibrary`（静态工具类基类）所在。
- `Templates/SubclassOf.h`：`TSubclassOf`（类型安全的类引用模板）。
- `UObject/Interface.h`：`UInterface`（接口外壳基类）。
- `UObject/ObjectPtr.h`：`TObjectPtr`（UE5 的对象指针包装）。

```cpp
template <typename InterfaceType> class TScriptInterface;
class AActor;
class UTenkaichiInventoryItemDefinition;
class UTenkaichiInventoryItemInstance;
class UTenkaichiInventoryManagerComponent;
class UObject;
struct FFrame;
```

- `TScriptInterface`：**接口智能指针模板**（前置声明就够，这里只用指针/引用）。
- 其余都是**前置声明**：`AActor`（引擎）、3 个 P08 类型（P08.1/08.2/08.7）、`UObject`、`FFrame`。
- **为什么前置声明够**：`.h` 里这些类型都只以**指针 / `TSubclassOf` / `TScriptInterface`** 出现，不实例化、不继承，编译期只需类型名。

### 2. 结构体①：掉落模板 `FPickupTemplate`

```cpp
USTRUCT(BlueprintType)
struct FPickupTemplate
{
	GENERATED_BODY()
public:
	UPROPERTY(EditAnywhere)
	int32 StackCount = 1;
	UPROPERTY(EditAnywhere)
	TSubclassOf<UTenkaichiInventoryItemDefinition> ItemDef;
};
```

- "捡到一堆同种物品"的模板：`ItemDef`（什么物品）+ `StackCount`（几个）。
- `EditAnywhere`：可在编辑器任意地方编辑。
- `TSubclassOf<...>`：一个"必须是某类（或其子类）的类引用"，比裸 `UClass*` 更安全（类型检查）。

### 3. 结构体②：掉落实例 `FPickupInstance`

```cpp
USTRUCT(BlueprintType)
struct FPickupInstance
{
	GENERATED_BODY()
public:
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TObjectPtr<UTenkaichiInventoryItemInstance> Item = nullptr;
};
```

- 和模板的区别：模板是"定义 + 数量"（还没造出对象），实例是"**已经存在的具体对象**"。
- `TObjectPtr<UTenkaichiInventoryItemInstance>`：指向 P08.2 的实例对象。

### 4. 结构体③：掉落包 `FInventoryPickup`

```cpp
USTRUCT(BlueprintType)
struct FInventoryPickup
{
	GENERATED_BODY()
public:
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TArray<FPickupInstance> Instances;
	UPROPERTY(EditAnywhere, BlueprintReadOnly)
	TArray<FPickupTemplate> Templates;
};
```

- 捡一次 = 一包，里面两类东西：`Instances`（现成实例）+ `Templates`（批量模板）。
- `BlueprintReadOnly`：蓝图只能读，不能改（掉落物内容由逻辑/编辑器定）。

### 5. 接口：`UPickupable` + `IPickupable`

```cpp
UINTERFACE(MinimalAPI, BlueprintType, meta = (CannotImplementInterfaceInBlueprint))
class UPickupable : public UInterface
{
	GENERATED_BODY()
};

class IPickupable
{
	GENERATED_BODY()
public:
	UFUNCTION(BlueprintCallable)
	virtual FInventoryPickup GetPickupInventory() const = 0;
};
```

- **双类结构**（UE 接口机制）：
  - `UPickupable`（`UINTERFACE` 外壳）：让反射系统知道"这是个接口"。`meta=(CannotImplementInterfaceInBlueprint)` = **不能在蓝图中实现**（只能 C++ 实现）。
  - `IPickupable`（C++ 接口体）：真正被继承的纯虚类。
- `GetPickupInventory()`：**纯虚函数（`= 0`）**，实现这个接口的 Actor 必须实现它，返回"捡起来能得到什么"。
- `MinimalAPI`：接口外壳只导出最小 API（和 P08.7 管理器的 `MinimalAPI` 同理）。

### 6. 工具类：`UPickupableStatics`

```cpp
UCLASS()
class UPickupableStatics : public UBlueprintFunctionLibrary
{
	GENERATED_BODY()
public:
	UPickupableStatics();
public:
	UFUNCTION(BlueprintPure)
	static TScriptInterface<IPickupable> GetFirstPickupableFromActor(AActor* Actor);
	UFUNCTION(BlueprintCallable, BlueprintAuthorityOnly, meta = (WorldContext = "Ability"))
	static void AddPickupToInventory(UTenkaichiInventoryManagerComponent* InventoryComponent, TScriptInterface<IPickupable> Pickup);
};
```

- 继承 `UBlueprintFunctionLibrary`：**纯静态工具类**，不需要实例化，蓝图里直接 `UPickupableStatics::GetFirstPickupableFromActor(...)` 调用。
- `GetFirstPickupableFromActor`：`BlueprintPure`（纯函数，无副作用），返回 `TScriptInterface<IPickupable>`（接口智能指针）。
- `AddPickupToInventory`：`BlueprintCallable` + `BlueprintAuthorityOnly`（**只在服务器执行**，捡东西是权威操作）+ `meta=(WorldContext="Ability")`（用 Ability 作为世界上下文拿 World）。
