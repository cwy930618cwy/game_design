## 一、本文件要解决什么

P08 开头讲过：物品 = 「定义（菜谱）+ 实例（那盘菜）+ 碎片（可插拔配料）」三件套。

本文件 `TenkaichiInventoryItemDefinition` 是这三件套里的**最底层、最基础**的那块——**它解决"一个物品定义到底长什么样、怎么把'可插拔的特性'装进去"**。

具体落地为**三个类，塞在同一个 `.h` 里**（因为 Lyra 就这么放的，一比一对应）：

| 类 | 角色 | 一句话 |
|----|------|--------|
| ① `UTenkaichiInventoryItemFragment` | **碎片基类**（抽象） | 所有"物品特性"的父类，本身没内容，只是个"可插拔的插座" |
| ② `UTenkaichiInventoryItemDefinition` | **物品定义** | 菜谱本体：一个名字 + 一堆碎片 |
| ③ `UTenkaichiInventoryFunctionLibrary` | **蓝图工具库** | 给蓝图用的便捷函数：按类名找碎片 |

## 二、为什么要"定义 + 碎片"分开（关键设计）

一个物品（比如一把 AK）有很多**独立的、可复用的特性**：

- 初始属性（`SetStats` 碎片，P08.3）
- 可装备性（`EquippableItem` 碎片，P08.4）
- 掉落物外观（`PickupIcon` 碎片，P08.5）
- 快捷栏图标（`QuickBarIcon` 碎片，P08.6）

如果把这些特性**硬编码进 Definition 里**，每做一种新物品就要改 Definition 类，而且特性之间没法自由组合。

Lyra 的做法：**把每种特性做成一个独立的 `Fragment` 子类**，Definition 里只放一个 `TArray<Fragment>` 数组。蓝图里往数组里"添加哪个碎片、加几个"，就决定了这个物品有哪些特性——**像乐高积木一样自由拼**。

> 类比：Definition 是**一个空盒子**，Fragment 是**各种功能卡**。往盒子里塞"属性卡 + 可装备卡"，这个物品就有了属性和可装备性；再换一张"图标卡"，图标又变了。盒子不变，卡片随意插。

## 三、为什么碎片能"往数组里直接加不同子类对象"（三个 UCLASS 标记）

这是本文件**最核心、最容易看不懂**的地方。靠 `Fragment` 基类身上的三个标记：

```cpp
UCLASS(MinimalAPI, DefaultToInstanced, EditInlineNew, Abstract)
class UTenkaichiInventoryItemFragment : public UObject
```

| 标记 | 作用 | 没它会怎样 |
|------|------|-----------|
| `EditInlineNew` | 允许在编辑器里**直接新建**这个对象的内联实例 | 编辑器里没法"添加新条目" |
| `DefaultToInstanced` | 放进数组时**默认按 instanced（每个对象独立）** 处理 | 数组里存的是引用、不是独立实例 |
| `Abstract` | 声明这是个**抽象基类**，不能直接实例化，只能被子类继承 | 会误把基类本身当成一个可用碎片 |

而 Definition 里的数组字段用 `Instanced` 标记配合：

```cpp
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category=Display, Instanced)
TArray<TObjectPtr<UTenkaichiInventoryItemFragment>> Fragments;
```

> 合起来 = **蓝图里打开 Definition 数据资产，`Fragments` 数组的"+ 添加"按钮会列出所有 `Fragment` 子类，选哪个就 new 哪个进去**。这就是"碎片机制"的全部秘密。

## 四、三个类逐个讲（全景）

### ① `UTenkaichiInventoryItemFragment`（碎片基类）

```cpp
UCLASS(MinimalAPI, DefaultToInstanced, EditInlineNew, Abstract)
class UTenkaichiInventoryItemFragment : public UObject
{
	GENERATED_BODY()
public:
	virtual void OnInstanceCreated(UTenkaichiInventoryItemInstance* Instance) const {}
};
```

- 只继承 `UObject`，内容**只有一个虚函数** `OnInstanceCreated`。
- 这个虚函数是个**钩子**：当"这个物品定义真的被 new 出一个实例"时（P08.2 `InventoryItemInstance` 创建时），会调用每个碎片的 `OnInstanceCreated`，让碎片有机会往实例里塞初始数据（比如 `SetStats` 碎片会在这一步给实例加初始属性）。
- 基类里是空实现 `{}`，具体子类覆写它（P08.3 会用到）。

### ② `UTenkaichiInventoryItemDefinition`（物品定义）

```cpp
UCLASS(Blueprintable, Const, Abstract)
class UTenkaichiInventoryItemDefinition : public UObject
{
	GENERATED_BODY()
public:
	UTenkaichiInventoryItemDefinition(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category=Display)
	FText DisplayName;

	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category=Display, Instanced)
	TArray<TObjectPtr<UTenkaichiInventoryItemFragment>> Fragments;

	const UTenkaichiInventoryItemFragment* FindFragmentByClass(TSubclassOf<UTenkaichiInventoryItemFragment> FragmentClass) const;
};
```

- `UCLASS(Blueprintable, Const, Abstract)`：
  - `Blueprintable` = 蓝图可以继承它做数据资产（`B_xxx`）。
  - `Const` = 这个类被标记为"常量类"，实例数据不可变（呼应"菜谱永不变"）。
  - `Abstract` = 本身不直接实例化，只做基类。
- 两个字段：`DisplayName`（显示名）+ `Fragments`（碎片数组）。
- 一个方法 `FindFragmentByClass`：按碎片类型从数组里找出对应碎片（`IsA` 匹配）。

### ③ `UTenkaichiInventoryFunctionLibrary`（蓝图工具库）

```cpp
UCLASS()
class UTenkaichiInventoryFunctionLibrary : public UBlueprintFunctionLibrary
{
	GENERATED_BODY()
	UFUNCTION(BlueprintCallable, meta=(DeterminesOutputType=FragmentClass))
	static const UTenkaichiInventoryItemFragment* FindItemDefinitionFragment(
		TSubclassOf<UTenkaichiInventoryItemDefinition> ItemDef,
		TSubclassOf<UTenkaichiInventoryItemFragment> FragmentClass);
};
```

- 继承 `UBlueprintFunctionLibrary` → 纯静态函数库，蓝图节点可直接拖。
- 只有一个静态函数 `FindItemDefinitionFragment`：给"物品定义类 + 碎片类"，返回该定义的对应碎片（内部走 `GetDefault<Definition>(ItemDef)->FindFragmentByClass(...)`）。
- `meta=(DeterminesOutputType=FragmentClass)`：告诉蓝图"返回值类型由 `FragmentClass` 参数决定"，这样节点能正确推断返回类型。
