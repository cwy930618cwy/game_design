## 二、完整代码

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "CoreMinimal.h"
#include "Abilities/GameplayAbility.h"
#include "InteractionOption.h"
#include "IInteractableTarget.generated.h"

struct FInteractionQuery;

// 交互选项收集器：帮候选者把「能提供哪些交互」写进系统给的收集表里
class FInteractionOptionBuilder
{
public:
	FInteractionOptionBuilder(TScriptInterface<IInteractableTarget> InterfaceTargetScope, TArray<FInteractionOption>& InteractOptions)
		: Scope(InterfaceTargetScope)
		, Options(InteractOptions)
	{
	}

	void AddInteractionOption(const FInteractionOption& Option)
	{
		FInteractionOption& OptionEntry = Options.Add_GetRef(Option);
		OptionEntry.InteractableTarget = Scope;
	}

private:
	TScriptInterface<IInteractableTarget> Scope;
	TArray<FInteractionOption>& Options;
};

// UINTERFACE 外壳：仅作反射注册用，实际逻辑在下面的 IInteractableTarget
UINTERFACE(MinimalAPI, meta = (CannotImplementInterfaceInBlueprint))
class UInteractableTarget : public UInterface
{
	GENERATED_BODY()
};

// 可交互目标接口：规定候选者要实现的两个虚方法
class IInteractableTarget
{
	GENERATED_BODY()

public:
	// 收集本候选者能提供的所有交互选项（纯虚，必须实现）
	virtual void GatherInteractionOptions(const FInteractionQuery& InteractQuery, FInteractionOptionBuilder& OptionBuilder) = 0;

	// 真正触发交互前，往事件数据里塞额外信息（可选覆盖，默认空实现）
	virtual void CustomizeInteractionEventData(const FGameplayTag& InteractionEventTag, FGameplayEventData& InOutEventData) { }
};
```

## 三、逐段讲解

### 1. 头文件引入（第 5~10 行）

```cpp
#include "CoreMinimal.h"
#include "Abilities/GameplayAbility.h"
#include "InteractionOption.h"
#include "IInteractableTarget.generated.h"

struct FInteractionQuery;
```

| 行 | 作用 |
|----|------|
| `Abilities/GameplayAbility.h` | 引入 `FGameplayTag`、`FGameplayEventData`（接口第二个方法的参数类型）。 |
| `InteractionOption.h` | 引入 `FInteractionOption`（因为 `FInteractionOptionBuilder` 持有它）。 |
| `IInteractableTarget.generated.h` | UHT 生成代码，`UINTERFACE` 必须有。 |
| `struct FInteractionQuery;` | **前置声明**。第一个方法的参数用引用 `const FInteractionQuery&`，只声明不定义即可（软引用，不阻塞编译，铁律 30）。 |

> 💡 **为什么 `FInteractionQuery` 前置声明就够，`FInteractionOption` 却要 `#include`？**
> `FInteractionOptionBuilder` 里 `Options` 是 `TArray<FInteractionOption>&` 引用，`AddInteractionOption` 里还要访问它的成员（`Add_GetRef`、`InteractableTarget`），需要完整定义；而 `FInteractionQuery` 只出现在函数参数里，编译器不需要知道它内部长啥样。

### 2. `FInteractionOptionBuilder`（选项收集器，第 13~31 行）

这是一个**普通 C++ 类**（不是 `UCLASS`），是候选者往"结果表"里塞选项的**工具**。

```cpp
FInteractionOptionBuilder(TScriptInterface<IInteractableTarget> InterfaceTargetScope, TArray<FInteractionOption>& InteractOptions)
```

**构造函数**收两个东西：
- `InterfaceTargetScope`：**当前被问的候选者自己**（那个可交互物体）。
- `InteractOptions`：**结果收集表**（引用传进来的数组，收集完的选项都往这里塞）。

```cpp
void AddInteractionOption(const FInteractionOption& Option)
{
	FInteractionOption& OptionEntry = Options.Add_GetRef(Option);
	OptionEntry.InteractableTarget = Scope;
}
```

**关键点**：候选者只调用 `AddInteractionOption` 传一个"选项草稿"，收集器会**自动做两件事**：
1. `Options.Add_GetRef(Option)`：把草稿追加进结果表；
2. `OptionEntry.InteractableTarget = Scope`：**强制把 `InteractableTarget` 填成候选者自己**。

> 💡 **为什么收集器要强制覆盖 `InteractableTarget`？**
> 候选者填选项时可能忘了填"我是谁"，收集器保证：无论候选者填没填，最终选项的 `InteractableTarget` 一定是候选者自己。这样系统就不会收到"目标写错"的选项。

### 3. `UINTERFACE` 外壳（第 34~38 行）

```cpp
UINTERFACE(MinimalAPI, meta = (CannotImplementInterfaceInBlueprint))
class UInteractableTarget : public UInterface
{
	GENERATED_BODY()
};
```

这是 UE 接口的**固定套路**：一个 `UINTERFACE` 宏修饰的 `UCLASS`（外壳，供反射系统识别），类名是接口名前加 `U`（`IInteractableTarget` → `UInteractableTarget`）。

- `MinimalAPI`：不导出整个类的符号，轻量（只导出必要接口）。
- `CannotImplementInterfaceInBlueprint`：**蓝图不能实现这个接口**，只能 C++ 实现（因为它的方法带 `= 0` 纯虚 + 引用参数，蓝图表达不了）。

### 4. `IInteractableTarget` 接口体（第 41~51 行）

```cpp
class IInteractableTarget
{
	GENERATED_BODY()

public:
	// 收集本候选者能提供的所有交互选项（纯虚，必须实现）
	virtual void GatherInteractionOptions(const FInteractionQuery& InteractQuery, FInteractionOptionBuilder& OptionBuilder) = 0;
	// 真正触发交互前，往事件数据里塞额外信息（可选覆盖，默认空实现）
	virtual void CustomizeInteractionEventData(const FGameplayTag& InteractionEventTag, FGameplayEventData& InOutEventData) { }
};
```

**两个虚方法**：

| 方法 | 是否必实现 | 作用 |
|------|-----------|------|
| `GatherInteractionOptions` | **必须**（`= 0` 纯虚） | 候选者收到查询后，把自己能提供的选项 `AddInteractionOption` 进收集器 |
| `CustomizeInteractionEventData` | 可选（默认空实现 `{ }`） | 真正触发交互时，给候选者一个机会往事件数据里塞额外信息 |

> 💡 **`= 0` 和空实现 `{ }` 的区别**：`= 0` 是纯虚函数，谁实现这个接口谁**必须**写；`{ }` 是普通虚函数给了默认空实现，可选覆盖。
