# P05.6-1 GameplayAbility_Jump —— 教 .h

## 一、本文件要解决什么

把总 md 里"跳跃适配器"这个类落成真实的 `.h` 文件。`TenkaichiGameplayAbility_Jump.h` 定义一个 `UTenkaichiGameplayAbility_Jump` 类——它继承 `UTenkaichiGameplayAbility`（P05.3-B），**零新增字段**，只重写两个生命周期方法 + 加两个蓝图可调用函数。

**这个 `.h` 声明了 5 个方法、0 个字段**：
1. **构造函数** —— 设 2 个策略（`InstancedPerActor` + **`LocalPredicted`**）。
2. **`CanActivateAbility`（重写）** —— 判断能不能跳。
3. **`EndAbility`（重写）** —— 结束时兜底停跳。
4. **`CharacterJumpStart`（UFUNCTION）** —— 开始跳。
5. **`CharacterJumpStop`（UFUNCTION）** —— 停止跳。

> 依赖只有 P05.3-B 基类，**零挂起可独立编译**。

## 四、逐段讲解

### 1. 头文件引用与前置声明

```cpp
#pragma once

#include "TenkaichiGameplayAbility.h"

#include "TenkaichiGameplayAbility_Jump.generated.h"

class UObject;
struct FFrame;
struct FGameplayAbilityActorInfo;
struct FGameplayTagContainer;
```

- **`TenkaichiGameplayAbility.h`（P05.3-B）**：基类。**同目录相对路径，不带 `Abilities/` 前缀**——因为本文件就在 `AbilitySystem\Abilities\` 里。⚠️ 注意和 P05.5-4-1（跨目录，带了 `AbilitySystem/Abilities/` 前缀）写法不同，Lyra 两种都有，**照抄本文件的写法**。
- **`TenkaichiGameplayAbility_Jump.generated.h`**：反射生成头，必须最后一个 include。
- **4 个前置声明**：`UObject`（UE 反射需要）、`FFrame`（蓝图虚拟机栈帧）、`FGameplayAbilityActorInfo`、`FGameplayTagContainer`（`CanActivateAbility` 参数类型）。都是**签名里只用到指针/引用**，前置声明足够，不用 include 完整定义。
- ⚠️ **注意这里没有 include `FGameplayAbilitySpecHandle` 等** —— 它们由基类头间接带进来了。Lyra 原样，别自作主张加。

### 2. 类声明与 `Abstract`

```cpp
/**
 * UTenkaichiGameplayAbility_Jump
 *
 *	用于角色跳跃的技能
 */
UCLASS(Abstract)
class UTenkaichiGameplayAbility_Jump : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()
```

- **`UCLASS(Abstract)`** —— ⚠️ 和 P05.5-4-1 的 `Abstract` 同义：**抽象类，不能直接用，必须建蓝图子类**。为什么？因为跳跃的**输入绑定**、可能还有动画/特效都在蓝图里配，C++ 基类只是"能跳"的壳。
- **继承 `UTenkaichiGameplayAbility`（P05.3-B）** —— 拿到 Lyra GA 基类的全部能力：激活组管理、Tag 关系判定、成本/冷却、`GetTenkaichiCharacterFromActorInfo()` 辅助函数等。
- **文档注释 `/** */`** 是 Lyra 原文（已中文化），里面的类名 `ULyraGameplayAbility_Jump` 换成 `UTenkaichiGameplayAbility_Jump`（铁律 24）。

### 3. 构造函数

```cpp
public:

	// 构造函数：设为按 Actor 实例化 + 本地预测（客户端立即响应）
	UTenkaichiGameplayAbility_Jump(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

- 标准 UE 构造签名 + 默认参数。
- **实现在 `.cpp`**：设 2 个策略 —— `InstancingPolicy = InstancedPerActor` + **`NetExecutionPolicy = LocalPredicted`**。
- **`LocalPredicted` 是本类最重要的设定**：客户端**本地立即执行**跳跃，同时告知服务器；服务器校验后如果不合法会纠正（回滚）。**这就是"跳跃没延迟感"的原因**——如果设成 `ServerInitiated`，客户端按跳要等一个 RTT 才跳起来，手感极差。
- ⚠️ `.h` 写默认参数，`.cpp` 定义处必须省略（C++ 规则）。

### 4. CanActivateAbility（重写）

```cpp
protected:

	// 判断当前是否允许激活本技能（角色存在、可跳、且基类允许）
	virtual bool CanActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayTagContainer* SourceTags, const FGameplayTagContainer* TargetTags, FGameplayTagContainer* OptionalRelevantTags) const override;
```

- **这是引擎 `UGameplayAbility` 的虚函数**，GAS 在每次尝试激活技能前调用它，返回 `false` 就**拒绝激活**。
- **5 个参数**全是 GAS 标准参数：
  - `Handle` —— 技能规格句柄
  - `ActorInfo` —— 谁要激活（含 AvatarActor、OwnerActor、ASC）
  - `SourceTags` / `TargetTags` —— 源/目标的标签容器（用于 Tag 匹配）
  - `OptionalRelevantTags` —— **出参**：可以把"为什么不能激活"的标签填进去，供上层查询
- **`const` + `override`**：不修改对象 + 明确重写。
- **`.cpp` 里的三层判断**（本类逻辑核心）：
  1. `!ActorInfo || !ActorInfo->AvatarActor.IsValid()` → `false`（没角色不能跳）
  2. `Cast<ATenkaichiCharacter>` 失败 或 `!LyraCharacter->CanJump()` → `false`（角色当前不可跳，比如在空中/蹲着被挡）
  3. **`!Super::CanActivateAbility(...)` → `false`（最后问基类）** —— ⚠️ 基类里有 P05.3-B 教的激活组检查、Tag 关系检查，**这层不能漏**。

### 5. EndAbility（重写）

```cpp
	// 技能结束时兜底停止跳跃
	virtual void EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled) override;
```

- **引擎 `UGameplayAbility` 的生命周期虚函数**，技能结束时调用（正常结束或被取消）。
- **`.cpp` 里只做一件事**：`CharacterJumpStop();` 然后 `Super::EndAbility(...)`。
- **为什么需要这个兜底**：Lyra 原注释说得很清楚——"**in case the ability blueprint doesn't call it**"（万一蓝图忘了调）。蓝图子类里应该在跳跃动画结束时调 `CharacterJumpStop()`，但**如果忘了**，角色会卡在 `bPressedJump = true` 状态一直跳。所以在 `EndAbility` 里**无条件兜底**一次。
- ⚠️ **`CharacterJumpStop()` 内部有 `if (bPressedJump)` 判断**，所以"没在跳的时候调"是安全的空操作，不会出问题。

### 6. CharacterJumpStart / CharacterJumpStop（UFUNCTION）

```cpp
	// 让角色开始跳跃
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
	void CharacterJumpStart();

	// 让角色停止跳跃
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
	void CharacterJumpStop();
```

- **`UFUNCTION(BlueprintCallable, ...)`** —— 蓝图可以直接调用这两个函数。这是**蓝图子类驱动跳跃**的入口：蓝图里绑输入 → 调 `CharacterJumpStart()`。
- **`Category = "Tenkaichi|Ability"`** —— ⚠️ **两处，原本是 `"Lyra|Ability"`，`Lyra` 必须换成 `Tenkaichi`**（铁律 24，这是本文件最容易漏的地方）。`|` 表示子分类（`Tenkaichi → Ability`）。
- **为什么是 `public` 段**：要被蓝图调用，蓝图需要能访问。
- **`.cpp` 里的实现套路**（两个函数对称）：
  ```cpp
  if (ATenkaichiCharacter* Character = GetTenkaichiCharacterFromActorInfo())
  {
      if (Character->IsLocallyControlled() && !Character->bPressedJump)
      {
          Character->UnCrouch();
          Character->Jump();
      }
  }
  ```
  - **`IsLocallyControlled()`** —— 只操作**本地控制**的角色，防止越权操作别人的 Pawn。
  - **`!bPressedJump` 判断** —— 防止重复触发（已经按着跳了就不再跳一次）。
  - **`UnCrouch()` 先起身** —— 蹲着的时候不能直接跳，先站起来。
  - **`Jump()` / `StopJumping()`** —— 引擎 `ACharacter` 的原生方法。

## 五、几个要记住的点

1. **零新增字段**：本类只改行为，不加任何数据成员。
2. **`Abstract`**：必须用蓝图子类（输入绑定、动画在蓝图里配）。
3. **`LocalPredicted`（在 `.cpp` 里设）是手感关键**：客户端立即响应，不等服务器。
4. **`CanActivateAbility` 最后必须问 `Super::`**：基类有激活组/Tag 检查，漏了会绕过整套规则。
5. **`EndAbility` 的兜底**：防蓝图忘了 `CharacterJumpStop()` 导致角色一直跳。
6. **`Category = "Tenkaichi|Ability"` 两处都要换**（最容易漏）。
7. **`.h` 零挂起**：只依赖 P05.3-B 基类。
