## 〇、先给一个贯穿全篇的类比：把 GAS 想成「超能力管理局」

| 现实世界 | GAS 里的东西 | 对应 Lyra 类 |
|---------|-------------|-------------|
| **管理局分局**（每个英雄一个） | 能力系统组件 | `UTenkaichiAbilitySystemComponent`（ASC） |
| **技能执照** | 技能 | `UTenkaichiGameplayAbility`（GA） |
| **效果通知书**（加血/扣血/上 buff） | 游戏效果 | `UGameplayEffect`（GE，引擎类） |
| **属性面板**（血量条/攻击力） | 属性集 | `UTenkaichiHealthSet` / `CombatSet` / `AttributeSet` |
| **关键词标签**（"火系""眩晕""死亡中"） | 游戏标签 | `TenkaichiGameplayTags`（第 0 步） |
| **执照工本费** | 技能消耗 | `UTenkaichiAbilityCost` |
| **技能包**（入职发一整套） | 技能集合 | `UTenkaichiAbilitySet` |
| **总局红头文件**（全员统一 buff） | 全局授予 | `UTenkaichiGlobalAbilitySystem` |
| **事件现场记录单**（谁打的、用什么打的） | 效果上下文 | `FTenkaichiGameplayEffectContext` |
| **计算器**（伤害怎么算出来的） | 执行计算 | `UTenkaichiDamageExecution` / `HealExecution` |

> **一句话**：ASC 是"分局"（管一切），GA 是"执照"（能干啥），GE 是"通知"（实际改数值），AttributeSet 是"面板"（数值存在哪），Tag 是"关键词"（互相识别）。

## 二、逐文件一句话职责（25 个，按层归类）

### 第 0 层 · 全局配置（1 个）

| 文件 | 干嘛的 | 类比 |
|------|--------|------|
| `TenkaichiAbilitySystemGlobals` | GAS 的**全局单例**，引擎启动时建一个；主要作用是**让引擎用我们的自定义 EffectContext** 而不是默认的 | 管理局的"规章制度总部" |

> 关键函数就一个：`AllocGameplayEffectContext()` —— "以后所有效果现场记录单，用我们定制的那种"。

### 第 1 层 · 容器（1 个，最重要）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiAbilitySystemComponent`（ASC） | 挂在角色身上的 **GAS 中央处理器**。管技能授予/激活/取消、输入分发、激活组互斥、Tag 关系、失败通知、目标数据 |

**ASC 内部六块能力（记住这六块就懂了 ASC）**：

```
ASC 六大职责
├─ ① 输入分发   AbilityInputTagPressed/Released → ProcessAbilityInput
│               把 InputTag 翻译成"哪些技能该激活"
├─ ② 激活组互斥 ActivationGroupCounts[] + IsActivationGroupBlocked
│               独占组：放了"死亡"就不能放"跳跃"
├─ ③ 批量取消   CancelAbilitiesByFunc / CancelInputActivatedAbilities
│               死的时候把所有技能取消掉（可豁免某些）
├─ ④ Tag 关系   TagRelationshipMapping + GetAdditionalActivationTagRequirements
│               查表：这个技能还需要/被哪些 Tag 阻塞
├─ ⑤ 动态标签   Add/RemoveDynamicTagGameplayEffect
│               用 GE 给角色临时挂 Tag（如"昏迷中"）
└─ ⑥ 失败通知   NotifyAbilityFailed → ClientNotifyAbilityFailed
                技能没放出来时告诉客户端，好播"蓝不够"提示
```

### 第 2 层 · 技能（5 个）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiGameplayAbility` | **技能基类**。定义激活策略、激活组、消耗、失败反馈、相机模式。所有 Lyra 技能的老祖宗 |
| `TenkaichiAbilityCost` | 技能**额外消耗**抽象基类（"放这个技能除了蓝还要什么"） |
| `TenkaichiAbilityCost_InventoryItem` | 消耗**库存物品**（比如扔个手雷消耗 1 个） |
| `TenkaichiAbilityCost_ItemTagStack` | 消耗**物品 Tag 堆栈** |
| `TenkaichiAbilityCost_PlayerTagStack` | 消耗**玩家 Tag 堆栈** |
| `TenkaichiAbilitySimpleFailureMessage` | 技能失败的**小消息结构体**（纯数据） |

### 第 2 层 · 具体技能（3 个，P05.6）

| 文件 | 干嘛的 | 触发方式 | 特点 |
|------|--------|---------|------|
| `TenkaichiGameplayAbility_Jump` | 跳跃技能 | 输入触发 | 最简单，零挂起 |
| `TenkaichiGameplayAbility_Death` | 死亡技能 | `GameplayEvent.Death` 事件 | 取消所有技能 → `StartDeath()` → 蓝图编排 → `FinishDeath()` |
| `TenkaichiGameplayAbility_Reset` | 重置技能 | `GameplayEvent.RequestReset` 事件 | 取消技能 → 角色 `Reset()` → 广播重置消息 |

> **这三个是"样板间"**：看完它们你就知道 Lyra 的技能长什么样 —— 都是**继承 GA 基类 + 重写 `ActivateAbility` + 用 `EndAbility` 兜底**。

### 装配层（2 个）

| 文件 | 干嘛的 | 类比 |
|------|--------|------|
| `TenkaichiAbilitySet` | 把**一组 GA + GE + 属性**打包成一个数据资产，一键授予 | "入职大礼包" |
| `TenkaichiGlobalAbilitySystem` | 一个 **World 子系统**，给**所有** ASC 统一授予技能/效果 | "总局下发的红头文件" |

### 第 3 层 · 数值（3 个，P05.4-1）

| 文件 | 干嘛的 | 字段 |
|------|--------|------|
| `TenkaichiAttributeSet` | 属性集**基类**，`ATTRIBUTE_ACCESSORS` 宏 + 变化委托 | — |
| `TenkaichiCombatSet` | **战斗**属性 | `BaseDamage` / `BaseHeal` |
| `TenkaichiHealthSet` | **生命**属性 | `Health` / `MaxHealth` / `Healing` / `Damage` |

> ⚠️ **这三个是"数值仓库"**，不是"计算逻辑"。伤害**怎么算**在第 4 层。

### 第 4 层 · 计算（2 个，P05.4-2）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiDamageExecution` | **伤害计算**：从 `CombatSet.BaseDamage` 取攻击力、算护甲、队友判定、写进 `HealthSet.Damage` |
| `TenkaichiHealExecution` | **治疗计算**：从 `CombatSet.BaseHeal` 取治疗量，写进 `HealthSet.Healing` |

### 第 5 层 · 数据载体（3 个，P05.5）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiGameplayEffectContext` | **效果上下文**（结构体）：记录"谁打的、用的什么技能、命中结果、物理材质、来源对象"，支持网络序列化 |
| `TenkaichiGameplayAbilityTargetData_SingleTargetHit` | **单目标命中数据**：一次命中的详情（打到谁、哪个部位） |
| `TenkaichiTaggedActor` | **带标签的 Actor 基类**：给任意 Actor 挂 GameplayTag 的容器 |

### 阶段层（3 个，P05.5-4）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiGamePhaseAbility` | **阶段技能**：一个 GA，代表"进入某个游戏阶段" |
| `TenkaichiGamePhaseSubsystem` | **阶段子系统**（World 子系统）：阶段状态机裁判，管 `ActivePhases` 数组、观察者注册 |
| `TenkaichiGamePhaseLog` | 阶段专用**日志分类**（只有 `.h`，7 行） |

### 前置叶子（3 个，P05.1，重构版1 已教直接沿用）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiGameplayCueManager` | 游戏提示管理器（特效/音效的路由） |
| `TenkaichiAbilitySourceInterface` | **能力来源接口**（武器/道具当伤害来源时实现它） |
| `TenkaichiAbilityTagRelationshipMapping` | **Tag 关系表**（数据资产，配置激活/取消/阻塞关系） |

## 六、记忆口诀（5 句，背下来就不晕）

1. **ASC 是心脏** —— 一切能力都经过它，它挂在角色身上。
2. **GA 是执照** —— 具体技能继承它，主要改 `ActivateAbility`。
3. **GE 是通知** —— 真正改数值的是它，不是 GA。
4. **AttributeSet 是仓库** —— 数值存在这；**Execution 是公式** —— 数值怎么算在这。
5. **EffectContext 是快递单** —— 记录"谁寄的、寄给谁、里面是啥"。

## 七、常见混淆点（你晕大概就晕在这）

| 容易混 | 区别 |
|--------|------|
| **GA vs GE** | GA = 技能（"放火球"这个动作）；GE = 效果（"扣 20 血"这个结果）。GA 通常**通过** GE 造成伤害 |
| **AttributeSet vs Execution** | AttributeSet 存数值（血量=100）；Execution 算数值（这次扣多少） |
| **`Health` vs `Damage`**（都在 HealthSet） | `Damage` 是**临时搬运工**（伤害先写进它）；`Health` 才是**真正的血条** |
| **AbilitySet vs GlobalAbilitySystem** | AbilitySet 是**数据包**（被动的，等着被用）；GlobalAbilitySystem 是**执行者**（主动给所有 ASC 发） |
| **ASC 的 `AvatarActor` vs `OwnerActor`** | `AvatarActor` = 角色 Pawn（技能作用在谁身上）；`OwnerActor` = PlayerState（ASC 挂在谁身上） |
| **`CancelAbilities` 的豁免标签** | `Ability_Behavior_SurvivesDeath` —— 带这个标签的技能**不会被死亡/重置取消** |
