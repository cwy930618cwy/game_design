# P05.5-4-1 `ULyraGamePhaseAbility` —— 总 md

## 一、这个类要解决什么

主题总 md（P05.5-4）讲了整套阶段系统的设计：**阶段 = GameplayAbility，互斥靠 Tag 层级**。

`ULyraGamePhaseAbility` 就是这套设计的**载体本身**——**"一个阶段"在代码里就是一个这个类的实例（或它的蓝图子类）**。

**它解决的问题很直接**：

引擎的 `UGameplayAbility`（GA）已经是一套成熟的"激活 / 结束 / 网络复制 / 生命周期"机制。与其自己写一个阶段状态机（要自己管状态、管网络同步、管生命周期），不如**把 GA 借来用**：

- **阶段开始** = 激活这个 GA
- **阶段结束** = 结束这个 GA
- **当前有哪些阶段活跃** = 查 ASC 上哪些 GA 正在激活

但普通 GA 缺一样东西：**它不知道自己代表哪个阶段**。所以 Lyra 只加了一个字段：

> **`FGameplayTag GamePhaseTag`** —— 这个 GA 代表的阶段标签（如 `Game.Playing.WarmUp`）。

加上之后，`ULyraGamePhaseSubsystem`（P05.5-4-2）就能：读这个 Tag → 和别的阶段比较层级 → 决定谁该结束。

**核心一句话**：它是"阶段"这个抽象概念的**最小实现**——一个带阶段标签的 GA，激活即阶段开始，结束即阶段结束。

## 五、几个要记住的点

1. **它是"阶段"的载体**：激活 = 阶段开始，结束 = 阶段结束。不是自己写状态机，是把 GA 借来当状态机。
2. **只加一个字段**：`GamePhaseTag`。GA 的激活/结束/网络机制全靠继承，Lyra 一行都不重写（除了通知 Subsystem）。
3. **和 Subsystem 互相 include（都在 `.cpp`）**：看着像死结，实际 `.h` 互不依赖，**完全可编译**。
4. **构造函数里的 4 个策略是本类的重点**：`ReplicationPolicy = ReplicateNo`（不复制）、`InstancedPerActor`、`ServerInitiated`、`ServerOnly`——因为阶段是**服务器权威**的全局状态。
5. **`IsDataValid` 是编辑器专属**：`#if WITH_EDITOR` 包裹，检查 `GamePhaseTag` 有没有配，没配就在编辑器报错。
6. **零挂起**：依赖 P05.3-B 已就位。
