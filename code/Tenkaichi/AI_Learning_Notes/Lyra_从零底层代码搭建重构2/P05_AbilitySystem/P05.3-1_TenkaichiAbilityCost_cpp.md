UTenkaichiAbilityCost_ItemTagStack::UTenkaichiAbilityCost_ItemTagStack()
{
	Quantity.SetValue(1.0f);
	FailureTag = TAG_ABILITY_FAIL_COST;
}

bool UTenkaichiAbilityCost_ItemTagStack::CheckCost(const UTenkaichiGameplayAbility* Ability, const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, FGameplayTagContainer* OptionalRelevantTags) const
{
	if (const UTenkaichiGameplayAbility_FromEquipment* EquipmentAbility = Cast<const UTenkaichiGameplayAbility_FromEquipment>(Ability))
	{
		if (UTenkaichiInventoryItemInstance* ItemInstance = EquipmentAbility->GetAssociatedItem())
		{
			const int32 AbilityLevel = Ability->GetAbilityLevel(Handle, ActorInfo);

			const float NumStacksReal = Quantity.GetValueAtLevel(AbilityLevel);
			const int32 NumStacks = FMath::TruncToInt(NumStacksReal);
			const bool bCanApplyCost = ItemInstance->GetStatTagStackCount(Tag) >= NumStacks;

			// 当这个代价无法施加时，告知其他技能为什么
			if (!bCanApplyCost && OptionalRelevantTags && FailureTag.IsValid())
			{
				OptionalRelevantTags->AddTag(FailureTag);				
			}
			return bCanApplyCost;
		}
	}
	return false;
}

void UTenkaichiAbilityCost_ItemTagStack::ApplyCost(const UTenkaichiGameplayAbility* Ability, const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo)
{
	if (ActorInfo->IsNetAuthority())
	{
		if (const UTenkaichiGameplayAbility_FromEquipment* EquipmentAbility = Cast<const UTenkaichiGameplayAbility_FromEquipment>(Ability))
		{
			if (UTenkaichiInventoryItemInstance* ItemInstance = EquipmentAbility->GetAssociatedItem())
			{
				const int32 AbilityLevel = Ability->GetAbilityLevel(Handle, ActorInfo);

				const float NumStacksReal = Quantity.GetValueAtLevel(AbilityLevel);
				const int32 NumStacks = FMath::TruncToInt(NumStacksReal);

				ItemInstance->RemoveStatTagStack(Tag, NumStacks);
			}
		}
	}
}

## 四、逐段讲解

### 1. 构造函数：默认消耗量 = 1

三个子类构造函数都一样，先设默认值：

```cpp
UTenkaichiAbilityCost_InventoryItem::UTenkaichiAbilityCost_InventoryItem()
{
	Quantity.SetValue(1.0f);   // 默认每次消耗 1
}
```

- `Quantity` 是 `FScalableFloat`（可缩放浮点），构造函数里 `SetValue(1.0f)` 给它一个**初始值 1**（默认每次耗 1 个）。
- `ItemTagStack` 额外把 `FailureTag` 设成 `TAG_ABILITY_FAIL_COST`（`Ability.ActivateFail.Cost`）——付不起时的默认反馈标签。

### 2. `CheckCost`：检查"付得起吗"（激活前）

```cpp
return InventoryComponent->GetTotalItemCountByDefinition(ItemDefinition) >= NumItemsToConsume;   // InventoryItem
return ItemInstance->GetStatTagStackCount(Tag) >= NumStacks;                                     // ItemTagStack
return PS->GetStatTagStackCount(Tag) >= NumStacks;                                               // PlayerTagStack
```

三个子类的检查逻辑**完全同构**——"你有的 ≥ 你要耗的"：

| 子类 | 从哪拿"你有的" | 你要耗的 |
|------|--------------|---------|
| `InventoryItem` | `InventoryComponent->GetTotalItemCountByDefinition(ItemDefinition)`（背包里该物品总数） | `NumItemsToConsume` |
| `ItemTagStack` | `ItemInstance->GetStatTagStackCount(Tag)`（物品实例上该标签栈层数） | `NumStacks` |
| `PlayerTagStack` | `PS->GetStatTagStackCount(Tag)`（玩家状态上该标签栈层数） | `NumStacks` |

**"你要耗的"从 `Quantity` 算出来**（三处相同）：

```cpp
const float NumStacksReal = Quantity.GetValueAtLevel(AbilityLevel);   // 按技能等级取实际数值（可能是小数，如 1.5）
const int32 NumStacks = FMath::TruncToInt(NumStacksReal);             // 截断成整数（1.5 → 1）
```

- `GetValueAtLevel(AbilityLevel)`：`FScalableFloat` 按当前**技能等级**算消耗量（等级越高可能耗越多）。
- `FMath::TruncToInt`：浮点截断转 int（消耗量是整数，不能耗半个）。

**`ItemTagStack` 特有的失败反馈**：

```cpp
if (!bCanApplyCost && OptionalRelevantTags && FailureTag.IsValid())
{
	OptionalRelevantTags->AddTag(FailureTag);   // 把"付不起"的原因标签塞回去，供 UI/音频反馈
}
```

- 付不起时，把 `FailureTag` 加进 `OptionalRelevantTags`（可能为空指针，所以要判空）。这样外部能知道"因为没弹药所以失败"，给玩家咔哒声/提示。

### 3. `ApplyCost`：扣除代价（激活后）

**只读 Authority**（权威端/服务器才执行）：

```cpp
if (ActorInfo->IsNetAuthority())   // 只在服务器端扣，客户端不扣（防作弊/防重复）
```

**"谁能拿到消耗来源"**：

| 子类 | 消耗来源 |
|------|---------|
| `InventoryItem` | `Ability->GetControllerFromActorInfo()` → 拿到 `AController` → `GetComponentByClass<UTenkaichiInventoryManagerComponent>()` |
| `ItemTagStack` | `Cast<const UTenkaichiGameplayAbility_FromEquipment>(Ability)` → `GetAssociatedItem()` 拿物品实例 |
| `PlayerTagStack` | `Ability->GetControllerFromActorInfo()` → `PC->PlayerState` → `Cast<ATenkaichiPlayerState>` |

**扣除动作**（三处同构，"有 X 个，扣 N 个"）：

```cpp
InventoryComponent->ConsumeItemsByDefinition(ItemDefinition, NumItemsToConsume);   // 扣物品
ItemInstance->RemoveStatTagStack(Tag, NumStacks);                                  // 扣物品标签栈
PS->RemoveStatTagStack(Tag, NumStacks);                                            // 扣玩家标签栈
```

### 4. 为什么 `InventoryItem.cpp` 能编译、另两个要挂起

**`InventoryItem.cpp`**：Lyra 源码**自带 `#if 0 ... #endif`** 把两个函数体里对 `UTenkaichiInventoryManagerComponent` 的调用全包住了（这是 Lyra 官方写法——它自己也知道 Inventory 依赖未就位就先屏蔽），只留 `return false;` / 空实现。你一比一还原它，就**天然能编译、零挂起**。

**`ItemTagStack.cpp` / `PlayerTagStack.cpp`**：它们的 `#include` 涉及工程里**还不存在的头文件**：

| `.cpp` | 不存在的 include | 依赖阶段 |
|--------|----------------|---------|
| `ItemTagStack.cpp` | `Equipment/TenkaichiGameplayAbility_FromEquipment.h` | 阶段九 Equipment |
| | `Inventory/TenkaichiInventoryItemInstance.h` | 阶段八 Inventory |
| `PlayerTagStack.cpp` | `TenkaichiGameplayAbility.h`（`UTenkaichiGameplayAbility`） | P05.3-B（还没教） |

> ⚠️ 挂起方式：整个 `.cpp` 用 `#if 0 ... #endif` 包住（含 include）。因为依赖的 `.h` 文件本身不存在，只挂函数体不挂 include 还是会编译不过——所以**整体挂起**。

### 5. `UE_INLINE_GENERATED_CPP_BY_NAME` 与 `UE_DEFINE_GAMEPLAY_TAG`

```cpp
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiAbilityCost_ItemTagStack)   // UHT 生成的反射实现
```

- 所有反射类 `.cpp` 都要有这一行（宏内部拼出 `TenkaichiAbilityCost_ItemTagStack.gen.cpp` 的 include）。参数是**类名去掉前缀 U**。

```cpp
UE_DEFINE_GAMEPLAY_TAG(TAG_ABILITY_FAIL_COST, "Ability.ActivateFail.Cost");
```

- 在 `.cpp` 里**定义一个原生 GameplayTag**（引擎 `NativeGameplayTags.h` 提供），`TAG_ABILITY_FAIL_COST` 这个全局变量代表 `Ability.ActivateFail.Cost` 标签。只在本 `.cpp` 用（ItemTagStack 的失败反馈标签）。

## 五、几个要记住的点

1. **`#if 0` 是 Lyra 官方做法**：`InventoryItem.cpp` 里 Lyra 自己就把 Inventory 调用 `#if 0` 屏蔽了——印证"依赖没就位就先注释"是官方认可的做法。
2. **`CheckCost`/`ApplyCost` 两拍同构**：都是"你有的 ≥ 你要耗的 → 扣"，只是"从哪拿、怎么扣"因子类而异。
3. **`IsNetAuthority()`**：扣除只在权威端执行（服务器），客户端不扣。
4. **`FScalableFloat` + `FMath::TruncToInt`**：按等级取消耗量 → 截断成整数。
5. **失败反馈标签**：`ItemTagStack` 付不起时把 `FailureTag` 塞进 `OptionalRelevantTags`，供外部反馈。
6. **挂起登记**：`ItemTagStack.cpp`/`PlayerTagStack.cpp` 已登记到注释备忘录。
