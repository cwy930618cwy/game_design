# P05.6 `Abilities/` 剩余三类（Death / Jump / Reset）—— 主题总 md

## 一、这组要解决什么

P05.1~P05.5 教的是 GAS 的**基础设施**（ASC、GA 基类、成本、属性集、执行计算、效果上下文、阶段系统）。

`Abilities/` 里还剩三个**具体的技能实现**——它们是 Lyra 真正在游戏里用的、继承自 `UTenkaichiGameplayAbility`（P05.3-B）的**成品技能**：

| 技能 | 干什么 | 触发方式 |
|------|--------|---------|
| **`GameplayAbility_Jump`** | 角色跳跃 | 输入绑定（蓝图配置） |
| **`GameplayAbility_Death`** | 处理角色死亡流程 | 自动（`GameplayEvent.Death` 触发标签） |
| **`GameplayAbility_Reset`** | 把玩家快速重置回出生状态 | 自动（`GameplayEvent.RequestReset` 触发标签，**仅服务器**） |

**它们共同展示了一件事**：Lyra 是怎么把"游戏玩法"包装成一个个 GA 的。跳跃不是直接调 `Character->Jump()`，而是**走 GA**——这样才能享受 GAS 的**网络预测、标签管理、激活组互斥、取消机制**。

> 这就是为什么"跳跃"这种小事也要做成 GA：GAS 统一管理后，死亡时能自动取消跳跃、能加冷却/成本、能网络预测（客户端立刻响应不等服务器）。

## 五、几个要记住的点

1. **为什么跳跃也要做成 GA**：走 GAS 才能获得网络预测、激活组互斥（死亡时自动取消）、标签管理。
2. **Death / Reset 是"自动触发"的**：靠 `AbilityTriggers` + 触发标签（`GameplayEvent.Death` / `GameplayEvent.RequestReset`），不是输入。⚠️ **在 CDO 里添加**（`HasAnyFlags(RF_ClassDefaultObject)`）。
3. **死亡时的标准套路**：`CancelAbilities(nullptr, &AbilityTypesToIgnore, this)` 取消所有技能（保留带 `Ability.Behavior.SurvivesDeath` 的）→ `SetCanBeCanceled(false)` → 切激活组到 `Exclusive_Blocking`。
4. **`MinimalAPI` + `#define UE_API`**（Reset）：Lyra 的模块导出控制技巧，减少导出符号。`#undef UE_API` 收尾。
5. **Reset 还广播一条消息**：`FLyraPlayerResetMessage` 通过 `UGameplayMessageSubsystem` 广播，让别处知道"有人重置了"。
6. **只有 Death 需挂起**：Jump / Reset 全部零挂起。
