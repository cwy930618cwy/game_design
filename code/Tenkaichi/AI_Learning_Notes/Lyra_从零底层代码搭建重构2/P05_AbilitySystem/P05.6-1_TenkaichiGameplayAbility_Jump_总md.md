# P05.6-1 `ULyraGameplayAbility_Jump` —— 总 md

## 一、这个类要解决什么

**跳跃**。就这一个功能。

你可能会问：**跳跃直接调 `Character->Jump()` 不就行了？为什么要包成一个 GA？**

这是理解 GAS 设计理念的一个绝佳例子。直接调 `Jump()` 的话：

| 问题 | 走 GA 后的解决 |
|------|--------------|
| 网络预测 | 客户端要等服务器回包才能跳，有延迟感 → GA 的 `LocalPredicted` 策略让客户端**立刻响应** |
| 死亡时要中断 | 得自己记状态、自己判断 → GA 的**激活组**机制自动处理（死亡切 `Exclusive_Blocking` 时自动取消） |
| 想加冷却/消耗 | 得自己写计时器 → GA 自带 `Cost`/`Cooldown` GE |
| 想禁止某些状态下跳 | 得自己加一堆 if → GA 的 **Tag 关系**（Blocked/Required/Cancel）声明式搞定 |
| 蓝图要接逻辑 | 得自己暴露接口 → GA 天然蓝图友好 |

**所以 Lyra 把这个 GA 做成**：一个"包装了角色跳跃能力"的壳，把原生 `Jump()` 调用**包进 GAS 的生命周期管理**里。

**它只做两件事**：
1. **`CanActivateAbility`** —— 判断"现在能不能跳"（角色存在 + `CanJump()` + 基类允许）。
2. **`EndAbility`** —— 技能结束时**兜底调 `CharacterJumpStop()`**（防蓝图忘了调导致角色一直跳）。

再加上两个 `UFUNCTION` 给蓝图用：`CharacterJumpStart()` / `CharacterJumpStop()`。

**核心一句话**：它是"角色跳跃"和 "GAS 生命周期"之间的**适配器**。

## 五、几个要记住的点

1. **零新增字段**：本类纯粹改行为，不加数据。
2. **`LocalPredicted` 是手感关键**：客户端本地立即执行，不等服务器。
3. **`EndAbility` 里的兜底**：`CharacterJumpStop()` 保证蓝图忘了调也不会卡在跳跃状态。
4. **`IsLocallyControlled()` 判断**：只控制本地角色，不越权操作别人的 Pawn。
5. **`Category = "Lyra|Ability"`** → 换成 `"Tenkaichi|Ability"`（铁律 24，容易漏）。
6. **完全零挂起**：依赖全就位。
