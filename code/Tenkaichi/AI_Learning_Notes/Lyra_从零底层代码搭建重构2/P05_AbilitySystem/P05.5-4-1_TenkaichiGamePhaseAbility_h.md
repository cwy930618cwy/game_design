# P05.5-4-1 GamePhaseAbility —— 教 .h

## 一、本文件要解决什么

把总 md 里"阶段载体"这个类落成真实的 `.h` 文件。`TenkaichiGamePhaseAbility.h` 定义一个 `UTenkaichiGamePhaseAbility` 类——它继承 `UTenkaichiGameplayAbility`（P05.3-B），**只新增一个字段 `GamePhaseTag`**，并重写激活/结束两个生命周期方法去通知 Subsystem。

**这个 `.h` 声明了 5 个方法 + 1 个字段**：
1. **构造函数** —— 设置 4 个 GA 策略（`.cpp` 教）。
2. **`GetGamePhaseTag`（内联）** —— 返回阶段标签，一行写完。
3. **`IsDataValid`（仅编辑器）** —— 校验 `GamePhaseTag` 有没有配。
4. **`ActivateAbility`（重写）** —— 激活时通知 Subsystem（`.cpp` 教）。
5. **`EndAbility`（重写）** —— 结束时通知 Subsystem（`.cpp` 教）。
6. **`GamePhaseTag` 字段** —— 本类唯一的新增数据。

> 依赖只有 P05.3-B 的 GameplayAbility（已落盘）+ 引擎 `FGameplayTag`，**零挂起可独立编译**。

## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "AbilitySystem/Abilities/TenkaichiGameplayAbility.h"
#include "TenkaichiGamePhaseAbility.generated.h"

/**
 * UTenkaichiGamePhaseAbility
 *
 * 所有用于切换当前游戏阶段的技能的基类
 */
UCLASS(Abstract, HideCategories = Input)
class UTenkaichiGamePhaseAbility : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()

public:

	// 构造函数：设置阶段技能所需的复制/实例化/网络策略
	UTenkaichiGamePhaseAbility(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	// 获取本技能代表的阶段标签
	const FGameplayTag& GetGamePhaseTag() const { return GamePhaseTag; }

#if WITH_EDITOR
	// 编辑器数据校验：检查阶段标签是否已配置
	virtual EDataValidationResult IsDataValid(class FDataValidationContext& Context) const override;
#endif

protected:

	// 激活技能时通知阶段子系统，让新阶段开始
	virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
	// 结束技能时通知阶段子系统，让当前阶段结束
	virtual void EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled) override;

protected:

	// 定义本阶段技能所属的游戏阶段。举例：
	// 如果你的阶段是 GamePhase.RoundStart，那么它会取消所有同级（sibling）阶段。
	// 比如当前活跃的是 GamePhase.WaitingToStart，启动属于 RoundStart 的技能就会结束 WaitingToStart。
	// 但你也可以通过嵌套来实现层级行为。例如，GamePhase.Playing.NormalPlay 是父阶段
	// GamePhase.Playing 的子阶段，所以把子阶段切换到 GamePhase.Playing.SuddenDeath，
	// 会停止所有绑定 GamePhase.Playing.* 的技能，但不会结束绑定 GamePhase.Playing 阶段的技能。
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Tenkaichi|Game Phase")
	FGameplayTag GamePhaseTag;
};
```

## 四、逐段讲解

### 1. 头文件引用

```cpp
#pragma once

#include "AbilitySystem/Abilities/TenkaichiGameplayAbility.h"
#include "TenkaichiGamePhaseAbility.generated.h"
```

只有两个 include：

- **`AbilitySystem/Abilities/TenkaichiGameplayAbility.h`（P05.3-B）**：基类。**用带 `AbilitySystem/Abilities/` 前缀的路径**——因为本文件在 `AbilitySystem/Phases/` 里，跨了一级目录，Lyra 用带前缀写法（从 `Source/LyraGame/` 算起的完整路径）。
- **`TenkaichiGamePhaseAbility.generated.h`**：UE 反射代码生成头，`UCLASS` 必需，且**必须放最后一个 include**。
- ⚠️ **注意这里没有 include Subsystem** —— 本类 `.h` 里 `ULyraGamePhaseSubsystem` 根本不出现（只在 `.cpp` 里才 include）。这就是总 md 说的"**`.h` 互不依赖，所以零挂起**"。
- ⚠️ **也没有 include `GameplayTagContainer.h`** —— `FGameplayTag` 已经由基类的头文件链间接带进来了（P05.3-B 的 `.h` 链里有）。Lyra 原样，别自作主张加。

### 2. 类声明与 UCLASS 说明符

```cpp
/**
 * UTenkaichiGamePhaseAbility
 *
 * 所有用于切换当前游戏阶段的技能的基类
 */
UCLASS(Abstract, HideCategories = Input)
class UTenkaichiGamePhaseAbility : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()
```

- **`UCLASS(Abstract, HideCategories = Input)`** 两个说明符：
  - **`Abstract`**：**抽象类，不能直接拖进关卡或实例化**——必须先做一个蓝图子类（并给它配好 `GamePhaseTag`）才能用。这很合理：光有基类不知道代表哪个阶段。
  - **`HideCategories = Input`**：在编辑器细节面板里**隐藏 `Input` 分类**。因为阶段技能**不是玩家输入触发的**（是 Subsystem 用 `GiveAbilityAndActivateOnce` 直接给的），所以输入绑定那些设置毫无意义，藏起来避免误配。
- **继承 `UTenkaichiGameplayAbility`**：拿到 Lyra GA 基类的全部能力（激活组、输入绑定、成本/冷却、Tag 关系判定……）。本类**只加阶段相关的东西**，其余全部继承。

### 3. 构造函数

```cpp
	// 构造函数：设置阶段技能所需的复制/实例化/网络策略
	UTenkaichiGamePhaseAbility(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

- 标准 UE 构造签名 + 默认参数（`= FObjectInitializer::Get()`）。
- **实现在 `.cpp`**：函数体里设 4 个策略（`ReplicationPolicy` / `InstancingPolicy` / `NetExecutionPolicy` / `NetSecurityPolicy`），是本类 `.cpp` 的重点。
- ⚠️ 和 P05.5-3 一样：`.h` 写默认参数，`.cpp` 定义处**必须省略**。

### 4. GetGamePhaseTag（内联，一行）

```cpp
	// 获取本技能代表的阶段标签
	const FGameplayTag& GetGamePhaseTag() const { return GamePhaseTag; }
```

- **内联函数**：函数体直接写在 `.h` 声明处（一行返回），`.cpp` 不用再写。
- **返回 `const FGameplayTag&`（常量引用）**：不拷贝——`FGameplayTag` 内部是共享的 tag 节点指针，拷贝也没多贵，但 Lyra 用引用是**避免无谓拷贝**的习惯写法。
- **`const` 成员函数**：不修改本对象。
- **谁调用它**：`ULyraGamePhaseSubsystem`（P05.5-4-2）在 `OnBeginPhase` / `OnEndPhase` 里调它，拿到阶段标签去做层级比较（判断谁该结束）。**这就是本类存在的意义——给 Subsystem 提供"我是哪个阶段"这个信息。**

### 5. IsDataValid（编辑器专属）

```cpp
#if WITH_EDITOR
	// 编辑器数据校验：检查阶段标签是否已配置
	virtual EDataValidationResult IsDataValid(class FDataValidationContext& Context) const override;
#endif
```

- **`#if WITH_EDITOR` ... `#endif`** —— 只在编辑器构建存在，打包版没有。**这是本 `.h` 唯一的预处理块**。
- **`class FDataValidationContext&`** —— 参数里**直接写了 `class` 关键字**（前置声明的简写形式），所以 `.h` 不需要 include `Misc/DataValidation.h`（那个留给 `.cpp`）。这是 UE 里常见的"参数里就地前置声明"技巧。
- **`IsDataValid` 是 `UObject` 的虚函数**，UE 编辑器的"资产校验"功能（内容浏览器右键 → Validate）会调它，返回 `Invalid` 就在界面上报错。
- **Lyra 用它干什么**：`.cpp` 里检查 `GamePhaseTag.IsValid()`，没配就 `AddError`（提示"GamePhaseTag must be set..."）。**防止策划建了阶段技能蓝图却忘了配标签**——忘了的话这阶段就是"无名阶段"，层级判断全乱。

### 6. ActivateAbility / EndAbility（重写，本类的核心动作）

```cpp
protected:

	// 激活技能时通知阶段子系统，让新阶段开始
	virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
	// 结束技能时通知阶段子系统，让当前阶段结束
	virtual void EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled) override;
```

- **这是引擎 `UGameplayAbility` 的两个生命周期虚函数**，本类重写它们的目的只有一个：**通知 Subsystem**。
  - `ActivateAbility` → 调 `Subsystem->OnBeginPhase(this, Handle)`（新阶段开始）
  - `EndAbility` → 调 `Subsystem->OnEndPhase(this, Handle)`（当前阶段结束）
- **参数都是 GAS 的标准参数**（P05.3-B 教 GameplayAbility 时已见过）：
  - `FGameplayAbilitySpecHandle Handle` —— 本次激活的句柄（Subsystem 用它当 `ActivePhaseMap` 的 key）
  - `FGameplayAbilityActorInfo* ActorInfo` —— 谁激活的（本类用它取 `AbilitySystemComponent` → `GetWorld()`）
  - `FGameplayAbilityActivationInfo ActivationInfo`、`FGameplayEventData* TriggerEventData` —— 激活信息、触发事件数据
  - `EndAbility` 多两个：`bReplicateEndAbility`（是否复制到客户端）、`bWasCancelled`（是被取消还是正常结束）
- **`protected`**：只有本类和子类能调（引擎内部通过其他机制调用）。
- **`.cpp` 里的写法要点**：先判断 `ActorInfo->IsNetAuthority()`（只在服务器权威端通知），再取 World → 取 Subsystem → 通知。**最后还会调 `Super::` 版本**（保证基类行为不丢）。
- ⚠️ **为什么放在 `protected` 且和 `GamePhaseTag` 分成两个 `protected:` 段**：Lyra 原样（中间隔了注释块）。照抄，别合并。

### 7. GamePhaseTag 字段

```cpp
protected:

	// 定义本阶段技能所属的游戏阶段。举例：
	// 如果你的阶段是 GamePhase.RoundStart，那么它会取消所有同级（sibling）阶段。
	// ...
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Tenkaichi|Game Phase")
	FGameplayTag GamePhaseTag;
```

- **`UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Tenkaichi|Game Phase")`** 三个说明符：
  - **`EditDefaultsOnly`**：**只能在类默认值/蓝图默认里编辑，实例上不可改**——阶段标签是"这个技能属于哪个阶段"的固有属性，不允许运行时改。
  - `BlueprintReadOnly`：蓝图可读不可写。
  - `Category = "Tenkaichi|Game Phase"`：细节面板里归到 `Tenkaichi → Game Phase` 分类（`|` 表示子分类层级）。⚠️ **原来是 `"Lyra|Game Phase"`，按铁律 24 把 `Lyra` 换成 `Tenkaichi`**。
- **`FGameplayTag GamePhaseTag`**：本类**唯一的新增数据**。整套阶段系统的核心就靠它——Subsystem 拿它做 `MatchesTag()` 层级比较。
- **上面那段长注释是 Lyra 原文**（已中文化，铁律 21/39），讲的是**嵌套规则**，和主题总 md 里说的一回事：
  - 启动 `GamePhase.RoundStart` → 结束所有**同级**的 `GamePhase.WaitingToStart`
  - `GamePhase.Playing.NormalPlay` 是 `GamePhase.Playing` 的**子阶段**，切到 `GamePhase.Playing.SuddenDeath` 会结束 `GamePhase.Playing.*`，**但不结束父阶段 `GamePhase.Playing`**

## 五、几个要记住的点

1. **`Abstract` 说明符**：基类不能直接实例化，必须建蓝图子类并配 `GamePhaseTag`。
2. **`HideCategories = Input`**：阶段技能不靠输入触发，藏掉输入设置。
3. **`.h` 里不 include Subsystem**：这就是"和 Subsystem 互相 include 但零挂起"的原因。
4. **`GetGamePhaseTag` 是内联的**：`.cpp` 不写它。
5. **`IsDataValid` 用 `#if WITH_EDITOR` 包裹**，参数里就地 `class FDataValidationContext&` 前置声明。
6. **`Category = "Tenkaichi|Game Phase"`**：`Lyra` 也要换成 `Tenkaichi`。
7. **两个 `protected:` 分段**：Lyra 原样，别合并。
