# P05.6-3 `ULyraGameplayAbility_Reset` —— 总 md

## 一、这个类要解决什么

前面两个技能：

- **P05.6-1 Jump**：玩家**主动**触发（按空格）。
- **P05.6-2 Death**：角色**死亡时自动**触发（靠 `GameplayEvent.Death` 标签）。

`ULyraGameplayAbility_Reset` 是第三种：**别人发一个"请求重置"事件，它就自动跑**。

**触发方式**：同样是构造函数里给 **CDO 加 `AbilityTriggers`**，但触发标签换成 `GameplayEvent.RequestReset`。
Lyra 源码注释写得很清楚——**"Ability is activated automatically via the `GameplayEvent.RequestReset` ability trigger tag (server only)"**：
别的地方（比如作弊指令、重生流程、关卡逻辑）广播这个事件，这个技能就自动激活，**服务器权威**。

**它要解决的问题**：把玩家"瞬间重置回初始出生状态"，是一串固定动作：

```
收到 GameplayEvent.RequestReset 事件
   ↓
① 取消这个角色身上所有正在进行的技能
   ↓ 但保留带 Ability.Behavior.SurvivesDeath 标签的（和死亡同一套豁免逻辑）
② 禁止本技能被取消（SetCanBeCanceled(false)）
   ↓
③ 调角色自己的 Reset()（引擎 AActor::Reset 的重写，让角色回到初始状态）
   ↓
④ 广播 GameplayEvent.Reset 消息，告诉全系统"重置发生了"
   ↓
⑤ 调 Super::ActivateAbility，然后立刻 EndAbility（一次性技能，跑完就收工）
```

**为什么 ③ 要调角色的 `Reset()` 而不是自己写重置逻辑？**

因为"回到初始状态"这件事**每个游戏不一样**（回到出生点？回满血？清背包？）。
Lyra 的做法是：**技能只负责"编排"（取消技能 → 防取消 → 喊一嗓子），具体"怎么重置"交给角色自己的 `Reset()` 去实现**。
这就是**职责分离**：GA 管 GAS 层面的调度，角色管自己的状态恢复。

**核心一句话**：它是"请求重置"这个事件的 **GAS 编排者**——取消技能、防取消、调角色 `Reset()`、广播重置消息，然后自己收工。

## 五、几个要记住的点

1. **自动触发（和 Death 同套路）**：`AbilityTriggers` + `GameplayEvent.RequestReset`，加在 **CDO** 上（`HasAnyFlags(RF_ClassDefaultObject)`）。
2. **服务器权威**：`NetExecutionPolicy = ServerInitiated` —— 只在服务器发起，不像 Jump 那样本地预测。
3. **豁免标签复用**：`Ability.Behavior.SurvivesDeath` 这里也在用（不是"SurvivesReset"，Lyra 就复用这一个）。
4. **职责分离**：GA 只编排，**真正的重置逻辑在 `ATenkaichiCharacter::Reset()`**（P06 会教实现）。
5. **会广播消息**：`FLyraPlayerResetMessage` + `GameplayEvent.Reset` 通道，这是 **P01 消息总线的实战用例**。
6. **`UCLASS(MinimalAPI)`**：不导出全部符号给蓝图/其他模块，比 `Abstract` 更收敛（Jump/Death 用 `Abstract`，这里用 `MinimalAPI`）。
7. **一次性技能**：`ActivateAbility` 末尾直接 `EndAbility(..., bReplicateEndAbility=true, bWasCanceled=false)`，跑完即止。
8. **`.h` 里定义 `USTRUCT`**：Lyra 把 `FLyraPlayerResetMessage` 放在 `.h` 里，不单独建文件（铁律 10，不擅自拆）。
