	const UObject* Outer = GetOuter();
	check(Outer);

}

## 四、逐段讲解

### 1. 头文件与内联生成宏

```cpp
#include "TenkaichiAttributeSet.h"

#include "AbilitySystem/TenkaichiAbilitySystemComponent.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiAttributeSet)

class UWorld;
```

- `TenkaichiAttributeSet.h`：本类自己的头。
- `AbilitySystem/TenkaichiAbilitySystemComponent.h`：**P05.2 已教、工程已落盘**——`.cpp` 里要 `Cast` 到 `UTenkaichiAbilitySystemComponent`，必须完整 include（前置声明不够）。
- `UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiAttributeSet)`：UE 内联反射代码生成宏，每个 `.cpp` 都要有（对应 `.h` 的 `GENERATED_BODY()`）。
- `class UWorld;`：前置声明，因为 `GetWorld()` 返回 `UWorld*` 指针，`.cpp` 里只用到 `Outer->GetWorld()` 的返回值，不需要 `UWorld` 完整定义。

### 2. 构造函数

```cpp
UTenkaichiAttributeSet::UTenkaichiAttributeSet()
{
}
```

- 空的。基类不初始化任何属性成员（具体属性由 CombatSet/HealthSet 定义）。

### 3. GetWorld()

```cpp
UWorld* UTenkaichiAttributeSet::GetWorld() const
{
	const UObject* Outer = GetOuter();
	check(Outer);

	return Outer->GetWorld();
}
```

- 重写引擎 `UObject::GetWorld()`。
- **原理**：属性集不是一个 Actor，它挂在某个 ASC（组件）上，而 ASC 挂在 Pawn/Actor 上。`GetOuter()` 拿到它的外层对象链，往上最终能找到世界。`check(Outer)` 保证外层不为空（空就是 bug）。

### 4. GetTenkaichiAbilitySystemComponent()

```cpp
UTenkaichiAbilitySystemComponent* UTenkaichiAttributeSet::GetTenkaichiAbilitySystemComponent() const
{
	return Cast<UTenkaichiAbilitySystemComponent>(GetOwningAbilitySystemComponent());
}
```

- **原理**：GAS 的 `UAttributeSet` 自带 `GetOwningAbilitySystemComponent()`，返回**通用的** `UAbilitySystemComponent*`。
- 这里把它 `Cast` 成**项目自己的** `UTenkaichiAbilitySystemComponent`——因为项目里所有 ASC 都是 `UTenkaichiAbilitySystemComponent`（P05.2 教的），后续 CombatSet/HealthSet 要用项目 ASC 的扩展方法（如 `GetTagCount` 等），所以提供这个便捷方法。

## 五、几个要记住的点

1. **`.cpp` 依赖 P05.2 `TenkaichiAbilitySystemComponent.h`**——已落盘，**可编译零挂起**。
2. **`GetWorld()` 走 `GetOuter()` 链**：属性集不是 Actor，拿世界要靠外层对象。
3. **`GetTenkaichiAbilitySystemComponent()` 就是一次 `Cast`**：把通用 ASC 转成项目 ASC，方便后续属性集用项目扩展方法。
