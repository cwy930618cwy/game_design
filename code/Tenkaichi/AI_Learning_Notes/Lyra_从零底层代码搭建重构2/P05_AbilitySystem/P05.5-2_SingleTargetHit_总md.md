# P05.5-2 `FLyraGameplayAbilityTargetData_SingleTargetHit` —— 总 md

## 一、这个类要解决什么

P05.5-1 教完了 `FTenkaichiGameplayEffectContext`（效果上下文）。它是"效果的身份证"——GE 执行时靠它知道"谁打的、打到哪、什么来源"。

但有个问题：**效果上下文里的字段是谁填进去的？**

答案是 **TargetData（目标数据）**。GAS 的流程是：
```
技能激活 → 产生 TargetData（我打中了谁、命中点在哪）
        → TargetData 把信息写进 EffectContext
        → GE 拿着 EffectContext 去执行（DamageExecution 读它算伤害）
```

`FLyraGameplayAbilityTargetData_SingleTargetHit` 就是 Lyra 对引擎"单目标命中数据"的扩展。引擎基类已经能带"命中了谁、命中点在哪"，Lyra **只加了一个字段**：

> **`CartridgeID`（弹夹 ID）** —— 标识"同一发霰弹里的多颗子弹"。

**为什么需要它？** 霰弹枪一发打出 8 颗弹丸，每颗弹丸都各自命中、各自造成一次伤害。但游戏逻辑上"这一发"应该算作一次（比如命中反馈只播一次、伤害数字合并成一个）。给这 8 颗弹丸打上**同一个 `CartridgeID`**，上层就能识别"这 8 次命中属于同一发"。

**核心一句话**：它是效果上下文的"填表人"——引擎的命中结果 + Lyra 的 `CartridgeID`，由它一起写进 `FTenkaichiGameplayEffectContext`。

## 五、几个要记住的点

1. **它是结构体不是类**：`USTRUCT()` + `TENKAICHIGAME_API` 导出，和 P05.5-1 的 EffectContext 是同一套路（都靠 `TStructOpsTypeTraits` 声明网络序列化能力）。
2. **只加了一个字段**：`CartridgeID`。Lyra 的克制——引擎基类已经够用，只补真正缺的。
3. **它是"填表人"**：`AddTargetDataToContext` 就是把本结构体的数据写进 EffectContext 的那个函数，DamageExecution 后面读的就是这里写进去的值。
4. **零挂起**：依赖 P05.5-1 已就位，直接可编译。
