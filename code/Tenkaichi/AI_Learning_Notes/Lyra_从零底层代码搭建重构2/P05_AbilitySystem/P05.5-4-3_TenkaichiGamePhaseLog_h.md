## 四、逐段讲解

### 1. `#pragma once`

```cpp
#pragma once
```

- 防止头文件被重复包含（标准写法，P05.5 前面每个 `.h` 都有）。
- 虽然本文件"只有一行宏"，但**照样要写**——`DECLARE_LOG_CATEGORY_EXTERN` 在不同编译单元里被重复展开会出问题。

### 2. include

```cpp
#include "Logging/LogMacros.h"
```

- **`Logging/LogMacros.h`** —— 引擎 `Core` 模块的日志宏头文件，`DECLARE_LOG_CATEGORY_EXTERN`、`UE_LOG`、`TEXT` 相关的声明都在这里。
- ⚠️ **注意是 `LogMacros.h` 不是 `LogCategory.h`**：`DECLARE_LOG_CATEGORY_EXTERN` 这个**宏**定义在 `LogMacros.h` 里。照抄，别自作主张换。
- 本文件**唯一的 include** —— 零工程依赖，所以零挂起。

### 3. DECLARE_LOG_CATEGORY_EXTERN（本文件唯一的内容）

```cpp
DECLARE_LOG_CATEGORY_EXTERN(LogTenkaichiGamePhase, Log, All);
```

**三个参数逐个讲**：

| 位置 | 值 | 含义 |
|------|-----|------|
| **第 1 个** | `LogTenkaichiGamePhase` | **分类名**。后续 `UE_LOG` 的第一个参数就用它。命名惯例：`Log` + 模块/系统名 |
| **第 2 个** | `Log` | **默认显示级别（DefaultVerbosity）**：运行时**低于这个级别的日志会被过滤掉，不显示** |
| **第 3 个** | `All` | **编译级别（CompileTimeVerbosity）**：**编译期**保留到哪个级别 |

**UE 的日志级别（从最啰嗦到最严重）**：

```
VeryVerbose   最啰嗦（每帧细节）
Verbose       啰嗦
Log           常规        ← Lyra 设的默认级别
Warning       警告
Error         错误
Fatal         致命（触发后直接崩溃）
```

**两个级别参数的区别（这是最容易混淆的地方）**：

- **默认级别 `Log`**：决定**运行时默认看不看得到**。设为 `Log`，则 `Verbose`/`VeryVerbose` 的日志**默认不显示**（但可以用控制台命令临时打开：`Log LogTenkaichiGamePhase Verbose`）。
- **编译级别 `All`**：决定**编译期是否编进二进制**。设 `All` = 全保留。如果设成 `Log`，那么所有 `Verbose` 级的 `UE_LOG` **会在编译期被整段剔除**——**打包后即使开控制台命令也永远看不到**。

> **Lyra 的选择 `Log, All`** = "默认只显示 Log 及以上，但**更详细的日志也编译进去了**，发布后想调试还能打开"。这是**兼顾性能和可调试性**的标准配置。

**为什么必须 `DECLARE` + `DEFINE` 分开？**

和 C++ 的 `extern` 变量一个道理：
- `DECLARE_LOG_CATEGORY_EXTERN` —— **声明**：告诉每个 include 它的编译单元"有这么个分类，定义在别处"（不分配存储）。
- `DEFINE_LOG_CATEGORY` —— **定义**：在某个 `.cpp` 里**真正分配静态存储**。**全工程只能有一次**，重复就链接报错。

**本项目的定义在哪**：`TenkaichiGamePhaseSubsystem.cpp` 第 16 行（你已写好）：
```cpp
DEFINE_LOG_CATEGORY(LogTenkaichiGamePhase);
```
✅ **已经有定义了，本步只补声明即可，两边配对就能用。**
