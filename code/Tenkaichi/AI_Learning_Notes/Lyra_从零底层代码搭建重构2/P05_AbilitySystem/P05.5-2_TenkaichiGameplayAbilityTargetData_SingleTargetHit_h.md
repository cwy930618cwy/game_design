# P05.5-2 SingleTargetHit —— 教 .h

## 一、本文件要解决什么

把总 md 里"`CartridgeID` 填表人"这个类落成真实的 `.h` 文件。`TenkaichiGameplayAbilityTargetData_SingleTargetHit.h` 定义一个结构体 `FTenkaichiGameplayAbilityTargetData_SingleTargetHit`——它继承引擎的 `FGameplayAbilityTargetData_SingleTargetHit`（单目标命中数据），**只新增一个字段 `CartridgeID`（弹夹 ID）**。

**这个 `.h` 声明了 4 个方法**：
1. **构造函数** —— 把 `CartridgeID` 初始化成 `-1`（表示"没设置"）。
2. **`AddTargetDataToContext`（重写）** —— **本结构体的核心**：把命中数据写进效果上下文（`.cpp` 教）。
3. **`NetSerialize`** —— 网络序列化，`CartridgeID` 要跟着一起复制。
4. **`GetScriptStruct`（重写）** —— 返回本结构体的反射类型，GAS 靠它识别类型。

再加上尾部的 **`TStructOpsTypeTraits` 特化**——声明"我支持网络序列化"，GAS 网络复制 TargetData 时必需。

> 依赖只有引擎基类 + P05.5-1 的 EffectContext（`.cpp` 才用到），**`.h` 可独立编译零挂起**。

## 四、逐段讲解

### 1. 头文件与前置声明

```cpp
#pragma once

#include "Abilities/GameplayAbilityTargetTypes.h"

#include "TenkaichiGameplayAbilityTargetData_SingleTargetHit.generated.h"

class FArchive;
struct FGameplayEffectContextHandle;
```

- `Abilities/GameplayAbilityTargetTypes.h`：**引擎 GAS 基类头**，`FGameplayAbilityTargetData_SingleTargetHit` 就定义在这。所有 TargetData 类型（单目标命中 / 范围 / Actor 数组）都在这一族里。
- `TenkaichiGameplayAbilityTargetData_SingleTargetHit.generated.h`：UE 反射代码生成头（`USTRUCT` 也要有）。
- **两个前置声明**：
  - `class FArchive;` —— `NetSerialize` 的第一个参数，签名里用到，前置声明就够（不需要知道内部长什么样）。
  - `struct FGameplayEffectContextHandle;` —— `AddTargetDataToContext` 的第一个参数，同理。
  - 这就是为什么 **`.h` 零挂起**——P05.5-1 的 `FTenkaichiGameplayEffectContext` 在 `.h` 里根本不需要出现，只在 `.cpp` 里才 include。

### 2. 结构体声明与 USTRUCT

```cpp
// 对 SingleTargetHit 追踪的游戏特定扩展
USTRUCT()
struct FTenkaichiGameplayAbilityTargetData_SingleTargetHit : public FGameplayAbilityTargetData_SingleTargetHit
{
	GENERATED_BODY()
```

- **`USTRUCT()` 不是 `UCLASS()`**：这是结构体，不是类。GAS 的 TargetData 全是 `USTRUCT`——因为它们是**按值传递的数据**（命中点、命中的 Actor、弹夹 ID），不是需要挂在对象上的组件。
- **继承 `FGameplayAbilityTargetData_SingleTargetHit`**：引擎基类已经带了"命中了哪个 Actor、命中点在哪、法线是什么"这些字段。**Lyra 不重复造，只补缺的**（这一点很关键——铁律 23 要求一比一还原，也就意味着**基类有的不要自己再加**）。
- **`GENERATED_BODY()`**：UE 反射宏，`USTRUCT` 必需。

### 3. 构造函数

```cpp
// 构造函数：把弹夹 ID 初始化为 -1（表示未设置）
FTenkaichiGameplayAbilityTargetData_SingleTargetHit()
	: CartridgeID(-1)
{ }
```

- **初始化列表** `: CartridgeID(-1)`：唯一要做的事。
- **为什么是 `-1`**：`-1` 是"无效/未设置"的约定值（和 P05.5-1 里 `CartridgeID = -1` 一致）。**不是霰弹枪的单发武器，这个字段就一直是 `-1`**，不影响任何逻辑。
- 函数体是空的 `{ }`——基类部分由编译器自动默认构造。

### 4. AddTargetDataToContext（核心方法，重写）

```cpp
// 把本结构体的命中数据写入效果上下文（含游戏特定的弹夹 ID）
virtual void AddTargetDataToContext(FGameplayEffectContextHandle& Context, bool bIncludeActorArray) const override;
```

- **这是本结构体存在的理由**。GAS 的流程是：技能产生 TargetData → 调 `AddTargetDataToContext` 把它写进 EffectContext → GE 读 EffectContext 执行。
- **参数**：
  - `FGameplayEffectContextHandle& Context`：要写入的效果上下文句柄（就是 P05.5-1 那个 `FTenkaichiGameplayEffectContext` 的句柄）。
  - `bool bIncludeActorArray`：是否把 TargetData 里的 Actor 数组也一并写进去。
- **`override`**：重写基类虚函数。`const`：不修改本结构体。
- **具体怎么写在 `.cpp`**：先调基类版本（写入命中的 Actor/命中点），再用 P05.5-1 的 `ExtractEffectContext` 取出 `FTenkaichiGameplayEffectContext`，把 `CartridgeID` 写进去。**这就是为什么必须先教 P05.5-1**（铁律 31）。

### 5. CartridgeID 字段

```cpp
// 用于识别同一弹夹里多颗子弹的 ID
UPROPERTY()
int32 CartridgeID;
```

- **`UPROPERTY()`**：让 UE 反射系统认识它（支持序列化、垃圾回收追踪、蓝图访问）。
- **`int32 CartridgeID`**：弹夹 ID。霰弹一发 8 颗弹丸 → 8 个 TargetData 打上**同一个 ID** → 上层能识别"这 8 次命中属于同一发"（合并伤害数字、命中反馈只播一次）。
- **对应 P05.5-1**：`FTenkaichiGameplayEffectContext` 里也有一个同名字段 `CartridgeID`（默认 `-1`）。本字段的值，就是在 `AddTargetDataToContext` 里**复制给**那边去的。

### 6. NetSerialize（网络序列化）

```cpp
// 网络序列化：序列化基类后，再序列化弹夹 ID
bool NetSerialize(FArchive& Ar, class UPackageMap* Map, bool& bOutSuccess);
```

- **为什么需要它**：TargetData 要跨网络复制（客户端命中 → 服务器确认）。引擎基类有自己的序列化，但**新增的 `CartridgeID` 引擎不知道**，必须自己写。
- **`FArchive& Ar`**：序列化归档器，`Ar << CartridgeID` 这种写法就是读写字段。
- **`.cpp` 里的套路**：先调基类 `NetSerialize`，再 `Ar << CartridgeID`，返回 `true`。
- ⚠️ **注意和 P05.5-1 的区别**：那边 `NetSerialize` 是 `virtual ... override`（重写引擎虚函数），这边是**普通成员函数**（不是 `virtual`）——因为引擎的 TargetData 基类用的是"TStructOpsTypeTraits 约定"而不是虚函数重写。照抄即可，别自作主张加 `virtual`。

### 7. GetScriptStruct（重写）

```cpp
// 返回本结构体的反射类型，供 GAS 识别
virtual UScriptStruct* GetScriptStruct() const override
{
	return FTenkaichiGameplayAbilityTargetData_SingleTargetHit::StaticStruct();
}
```

- **作用**：告诉 GAS"我这个 TargetData 实际是什么类型"。
- **为什么必须重写**：GAS 拿到的是基类指针 `FGameplayAbilityTargetData*`，需要知道真实类型才能正确复制/序列化/网络传输。
- **`StaticStruct()`**：UE 反射自动生成的静态函数，返回本结构体的 `UScriptStruct*`。
- 和 P05.5-1 的 `GetScriptStruct` 完全一样的套路——**两个结构体都要写这个**。

### 8. TStructOpsTypeTraits 特化

```cpp
template<>
struct TStructOpsTypeTraits<FTenkaichiGameplayAbilityTargetData_SingleTargetHit> : public TStructOpsTypeTraitsBase2<FTenkaichiGameplayAbilityTargetData_SingleTargetHit>
{
	enum
	{
		WithNetSerializer = true	// 目前这是必需的，否则 FGameplayAbilityTargetDataHandle 的网络序列化无法工作
	};
};
```

- **这是什么**：UE 的"结构体能力声明"机制——告诉引擎"我这个 `USTRUCT` 具备哪些特殊能力"。
- **`WithNetSerializer = true`**：声明"我有自定义网络序列化"（即上面那个 `NetSerialize`）。**不声明的话引擎就不调它**，`CartridgeID` 就复制不过去。
- **`TStructOpsTypeTraitsBase2`**：基类模板，继承它拿到默认行为。
- ⚠️ **和 P05.5-1 的区别**：那边声明了**两个**能力（`WithNetSerializer = true` + `WithCopy = true`），这边**只有一个**（`WithNetSerializer`）。照抄，别多抄一个 `WithCopy`（铁律 23：一比一，不加不减）。
- **Lyra 原注释说明**：`WithNetSerializer` 目前是**必需**的——`FGameplayAbilityTargetDataHandle` 的网络序列化依赖它。

## 五、几个要记住的点

1. **它是"填表人"**：`AddTargetDataToContext` 把命中数据 + `CartridgeID` 写进 P05.5-1 的 EffectContext，DamageExecution 后面读的就是这里写进去的值。
2. **只加一个字段**：`CartridgeID`。引擎基类已带命中 Actor/命中点，Lyra 不重复造。
3. **两个结构体的 `NetSerialize` 写法不同**：EffectContext 是 `virtual ... override`，本类是普通成员函数——照抄别改。
4. **`TStructOpsTypeTraits` 能力数不同**：EffectContext 有 `WithNetSerializer`+`WithCopy` 两个，本类只有 `WithNetSerializer` 一个。
5. **`.h` 零挂起**：只需要引擎基类头 + 两个前置声明，连 P05.5-1 都不用 include。
