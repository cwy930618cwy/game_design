# P05.6-3 GameplayAbility_Reset —— 教 .cpp

## 一、本文件要解决什么

`.h` 里声明了构造函数和 `ActivateAbility` 两个方法，`.cpp` 就是它们的**实现体**。

这个 `.cpp` 要完成两件事：

1. **构造函数** —— 设两个策略（实例化 / 网络），并**给 CDO 加一个"触发标签"**，让这个技能"听到 `GameplayEvent.RequestReset` 事件就自动激活"。
2. **`ActivateAbility`** —— 真正干活的六步：取消其他技能 → 禁止自己被取消 → 调角色 `Reset()` → 广播"重置了"的消息 → 调父类 → 立刻结束自己。

**为什么触发标签要写在构造函数里？**
因为 `AbilityTriggers` 是**类级别**的配置（所有这个技能的对象都一样），写在构造函数里一次配好，就不用每次激活前手动挂监听。
而 **`if (HasAnyFlags(RF_ClassDefaultObject))`** 保证这段只在 **CDO（类默认对象）** 上跑一次——实例是靠复制 CDO 得到这份配置的，不是每个实例各配一遍。

## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#include "AbilitySystem/Abilities/TenkaichiGameplayAbility_Reset.h"

#include "AbilitySystem/TenkaichiAbilitySystemComponent.h"
#include "Character/TenkaichiCharacter.h"
#include "GameFramework/GameplayMessageSubsystem.h"
#include "TenkaichiGameplayTags.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiGameplayAbility_Reset)

// 构造函数：设置实例化与网络策略，并为 CDO 添加「请求重置」触发标签
UTenkaichiGameplayAbility_Reset::UTenkaichiGameplayAbility_Reset(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;
	NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::ServerInitiated;

	// 只在类默认对象（CDO）上配置一次，所有实例自动继承
	if (HasAnyFlags(RF_ClassDefaultObject))
	{
		// 把触发标签作为默认值添加到 CDO 上
		FAbilityTriggerData TriggerData;
		TriggerData.TriggerTag = TenkaichiGameplayTags::GameplayEvent_RequestReset;
		TriggerData.TriggerSource = EGameplayAbilityTriggerSource::GameplayEvent;
		AbilityTriggers.Add(TriggerData);
	}
}

// 激活时取消其他所有技能、禁止自身被取消，然后调用角色自身的 Reset 并广播重置消息
void UTenkaichiGameplayAbility_Reset::ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData)
{
	check(ActorInfo);

	UTenkaichiAbilitySystemComponent* TenkaichiASC = CastChecked<UTenkaichiAbilitySystemComponent>(ActorInfo->AbilitySystemComponent.Get());

	FGameplayTagContainer AbilityTypesToIgnore;
	AbilityTypesToIgnore.AddTag(TenkaichiGameplayTags::Ability_Behavior_SurvivesDeath);

	// 取消所有技能，并阻止其他技能启动
	TenkaichiASC->CancelAbilities(nullptr, &AbilityTypesToIgnore, this);

	SetCanBeCanceled(false);

	// 由角色执行实际的重置
	if (ATenkaichiCharacter* TenkaichiChar = Cast<ATenkaichiCharacter>(CurrentActorInfo->AvatarActor.Get()))
	{
		TenkaichiChar->Reset();
	}

	// 通知外界已发生重置
	FTenkaichiPlayerResetMessage Message;
	Message.OwnerPlayerState = CurrentActorInfo->OwnerActor.Get();
	UGameplayMessageSubsystem& MessageSystem = UGameplayMessageSubsystem::Get(this);
	MessageSystem.BroadcastMessage(TenkaichiGameplayTags::GameplayEvent_Reset, Message);

	Super::ActivateAbility(Handle, ActorInfo, ActivationInfo, TriggerEventData);

	const bool bReplicateEndAbility = true;
	const bool bWasCanceled = false;
	EndAbility(CurrentSpecHandle, CurrentActorInfo, CurrentActivationInfo, bReplicateEndAbility, bWasCanceled);
}
```

### 2. 构造函数：两个策略

```cpp
UTenkaichiGameplayAbility_Reset::UTenkaichiGameplayAbility_Reset(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;
	NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::ServerInitiated;
```

- **`: Super(ObjectInitializer)`** —— 先调父类构造，Lyra 全项目的标准写法。
- ⚠️ **`.h` 里的默认参数 `= FObjectInitializer::Get()` 在 `.cpp` 定义处要省略**（C++ 规则：默认参数只能写一次）。
- **`InstancingPolicy = InstancedPerActor`** —— 每个 Actor 一个实例（而不是每次激活新建、或全局共享一个）。这样技能里可以存"这个角色"的状态。
- **`NetExecutionPolicy = ServerInitiated`** —— ⚠️ **服务器发起**（和 Death 一致，和 Jump 的 `LocalPredicted` 相反）。
  含义：客户端**不能自己预测**"我重置了"，必须由服务器说了算。重置涉及传送/状态回滚，交给服务器才权威。

### 3. 构造函数：给 CDO 加触发标签（最精妙的一步）

```cpp
	// 只在类默认对象（CDO）上配置一次，所有实例自动继承
	if (HasAnyFlags(RF_ClassDefaultObject))
	{
		// 把触发标签作为默认值添加到 CDO 上
		FAbilityTriggerData TriggerData;
		TriggerData.TriggerTag = TenkaichiGameplayTags::GameplayEvent_RequestReset;
		TriggerData.TriggerSource = EGameplayAbilityTriggerSource::GameplayEvent;
		AbilityTriggers.Add(TriggerData);
	}
```

- **`RF_ClassDefaultObject`** —— 引擎对象标记，表示"我是这个类的默认对象（CDO）"。UE 里每个 `UCLASS` 都有一个 CDO，实例都是靠复制它造出来的。
- **为什么要判断它？** 构造函数在**造 CDO 时跑一次**，之后**造每个实例时还会再跑**。如果都往 `AbilityTriggers` 里 `Add`，实例就会**重复添加**触发标签。所以只在 CDO 上加一次，实例复制得到这份配置。
- **`FAbilityTriggerData`** —— 引擎结构体，源码在 `Abilities/GameplayAbility.h:91`，有两个字段：
  - `TriggerTag` —— 听到哪个标签就激活
  - `TriggerSource` —— 触发来源类型，这里是 `EGameplayAbilityTriggerSource::GameplayEvent`（由 Gameplay 事件触发）
- **`AbilityTriggers`** —— 引擎数组，源码 `Abilities/GameplayAbility.h:747`，GA 基类会读它自动挂监听。
- **效果**：别处只要广播 `GameplayEvent.RequestReset` 事件，这个技能就自动激活 —— **完全不需要输入、也不需要手动调**。

### 4. ActivateAbility 第 1~2 步：取 ASC

```cpp
	check(ActorInfo);

	UTenkaichiAbilitySystemComponent* TenkaichiASC = CastChecked<UTenkaichiAbilitySystemComponent>(ActorInfo->AbilitySystemComponent.Get());
```

- **`check(ActorInfo)`** —— 断言指针非空（开发期抓 bug，假了直接崩并打调用栈）。
- **`CastChecked<UTenkaichiAbilitySystemComponent>`** —— 把引擎基类 ASC 转成我们的 Tenkaichi ASC。
  **`CastChecked` 比 `Cast` 更严格**：转换失败**直接崩溃**，而不是返回 `nullptr`。这里"一定是我们的 ASC"，失败就是 bug，所以用 Checked。
- **变量命名**：Lyra 原文是 `LyraASC`，一比一替换成 `TenkaichiASC`（铁律 24）。

### 5. ActivateAbility 第 3~5 步：取消技能 + 防取消

```cpp
	FGameplayTagContainer AbilityTypesToIgnore;
	AbilityTypesToIgnore.AddTag(TenkaichiGameplayTags::Ability_Behavior_SurvivesDeath);

	// 取消所有技能，并阻止其他技能启动
	TenkaichiASC->CancelAbilities(nullptr, &AbilityTypesToIgnore, this);

	SetCanBeCanceled(false);
```

- **`Ability_Behavior_SurvivesDeath`**（`TenkaichiGameplayTags.cpp:19`）—— "带这个类型标签的技能，不应因死亡而被取消"。
  ⚠️ **这里复用了同一个豁免标签**（Lyra 没有另建一个 `SurvivesReset`），一比一照抄。
- **`CancelAbilities(WithTags, WithoutTags, Ignore)`** —— 引擎方法，源码 `AbilitySystemComponent.h:1086`：
  - 第 1 个参数 `nullptr` —— 不按标签筛选（**所有**技能都在候选范围内）
  - 第 2 个参数 `&AbilityTypesToIgnore` —— **排除**带豁免标签的
  - 第 3 个参数 `this` —— **别把我自己取消了**（否则自己取消自己，后面流程跑不完）
- **`SetCanBeCanceled(false)`** —— 禁止本技能被取消。重置必须跑完，中途被打断会状态错乱。

### 6. ActivateAbility 第 6 步：调角色 Reset()（⚠️ 可能需挂起）

```cpp

	if (ATenkaichiCharacter* TenkaichiChar = Cast<ATenkaichiCharacter>(CurrentActorInfo->AvatarActor.Get()))
	{
		TenkaichiChar->Reset();
	}
```

- **`CurrentActorInfo`** —— GA 基类的成员（`GameplayAbility.h:884`），存"当前这次激活的宿主信息"。
- **`->AvatarActor`** —— 技能作用的**化身**（就是那个角色 Pawn）。`.Get()` 从 `TWeakObjectPtr` 取裸指针。
- **`Cast<ATenkaichiCharacter>`** —— 转成我们的角色类。**用 `if` 包着**：万一 Avatar 不是我们的角色（比如 NPC 用了别的类），就安全跳过、不崩。
- **`TenkaichiChar->Reset()`** —— 调角色自己的重置。**这里体现了职责分离**：
  GA 只管"编排"（取消技能、防取消、广播），**具体怎么重置交给角色**。`ATenkaichiCharacter::Reset()` 是引擎 `AActor::Reset()` 的重写（声明在 `TenkaichiCharacter.h:125`）。

### 7. ActivateAbility 第 7 步：广播重置消息

```cpp
	// 通知外界已发生重置
	FTenkaichiPlayerResetMessage Message;
	Message.OwnerPlayerState = CurrentActorInfo->OwnerActor.Get();
	UGameplayMessageSubsystem& MessageSystem = UGameplayMessageSubsystem::Get(this);
	MessageSystem.BroadcastMessage(TenkaichiGameplayTags::GameplayEvent_Reset, Message);
```

- **`FTenkaichiPlayerResetMessage`** —— 就是 `.h` 里定义的那个 `USTRUCT`。栈上直接建，不用 `NewObject`（`USTRUCT` 是值类型）。
- **`CurrentActorInfo->OwnerActor`** —— 技能的**所有者**（通常是 `PlayerState`）。
  ⚠️ **注意和 `AvatarActor` 区分**：`AvatarActor` = 角色 Pawn；`OwnerActor` = 拥有 ASC 的那个（Lyra 里挂在 `PlayerState` 上）。
  所以这里语义是"**谁的 PlayerState 被重置了**"——正好对上 `USTRUCT` 字段名 `OwnerPlayerState`。
- **`UGameplayMessageSubsystem::Get(this)`** —— 拿消息总线子系统（`GameplayMessageSubsystem.h:99`）。传 `this` 是为了让它知道从哪个 World 取（**WorldContextObject**）。
- **`BroadcastMessage(Channel, Message)`** —— 往 `GameplayEvent.Reset` 这个**频道**广播消息（`GameplayMessageSubsystem.h:117`）。
  任何地方只要监听了这个频道就能收到 —— **这就是 P01 消息总线的实战用例**：技能不需要知道"谁关心重置"，只管广播。

### 8. ActivateAbility 收尾：Super + EndAbility

```cpp
	Super::ActivateAbility(Handle, ActorInfo, ActivationInfo, TriggerEventData);

	const bool bReplicateEndAbility = true;
	const bool bWasCanceled = false;
	EndAbility(CurrentSpecHandle, CurrentActorInfo, CurrentActivationInfo, bReplicateEndAbility, bWasCanceled);
```

- **`Super::ActivateAbility(...)`** —— 先让父类把标准激活流程走完（记日志、设状态等）。**重写虚函数时先调 Super 是好习惯**。
- **`CurrentSpecHandle` / `CurrentActorInfo` / `CurrentActivationInfo`** —— 引擎成员（`GameplayAbility.h:887 / 884 / 727`），表示"当前这次激活"的句柄/宿主信息/激活信息。
  ⚠️ 用它们而**不用参数里的 `Handle`/`ActorInfo`/`ActivationInfo`** —— Lyra 原样，照抄（两者在非实例化的情况下可能不同，用成员更安全）。
- **`bReplicateEndAbility = true`** —— 把"结束"这件事**复制给客户端**（因为本技能是服务器发起的，客户端得知道结束了）。
- **`bWasCanceled = false`** —— 明确表示"我是正常结束，不是被取消的"。
- **为什么立刻 EndAbility？** 因为重置是**一次性动作**，没有"持续状态"。干完活就收工，不用等谁调 `EndAbility`。

## 五、几个要记住的点

1. **CDO 加触发标签**：`if (HasAnyFlags(RF_ClassDefaultObject))` 保证只配一次，实例靠复制继承。
2. **`InstancedPerActor` + `ServerInitiated`** —— 每 Actor 一实例、服务器权威（对比 Jump 的 `LocalPredicted`）。
3. **豁免标签复用 `Ability_Behavior_SurvivesDeath`** —— Lyra 没另建 `SurvivesReset`，照抄。
4. **`CancelAbilities(nullptr, &Ignore, this)`** 三参数含义：不筛选 / 排除豁免 / **别取消自己**。
5. **`AvatarActor` vs `OwnerActor`**：前者是 Pawn，后者是 PlayerState。消息里要的是 `OwnerActor`。
6. **职责分离**：GA 只编排，`Reset()` 的真实逻辑在角色里（P06 教）。
7. **一次性技能**：末尾直接 `EndAbility(..., true, false)`。
8. **⚠️ 可能挂起 1 行**：`TenkaichiChar->Reset();`（登记 ㉗，依赖 P06），其余全部可编译。
