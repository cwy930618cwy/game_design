// 构造函数：设置实例化/网络策略、默认自动开始死亡，并为 CDO 添加死亡触发标签
UTenkaichiGameplayAbility_Death::UTenkaichiGameplayAbility_Death(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;
	NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::ServerInitiated;

	bAutoStartDeath = true;

	if (HasAnyFlags(RF_ClassDefaultObject))
	{
		// 把技能触发标签作为默认值添加到 CDO
		FAbilityTriggerData TriggerData;
		TriggerData.TriggerTag = TenkaichiGameplayTags::GameplayEvent_Death;
		TriggerData.TriggerSource = EGameplayAbilityTriggerSource::GameplayEvent;
		AbilityTriggers.Add(TriggerData);
	}
}

// 激活时：取消其他所有技能（豁免带存活标签的）、禁止自身被取消，并切换到独占阻塞激活组
void UTenkaichiGameplayAbility_Death::ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData)
{
	check(ActorInfo);

	UTenkaichiAbilitySystemComponent* TenkaichiASC = CastChecked<UTenkaichiAbilitySystemComponent>(ActorInfo->AbilitySystemComponent.Get());

	FGameplayTagContainer AbilityTypesToIgnore;
	AbilityTypesToIgnore.AddTag(TenkaichiGameplayTags::Ability_Behavior_SurvivesDeath);

	// 取消所有技能，并阻止其他技能启动
	TenkaichiASC->CancelAbilities(nullptr, &AbilityTypesToIgnore, this);

	SetCanBeCanceled(false);

	if (!ChangeActivationGroup(ETenkaichiAbilityActivationGroup::Exclusive_Blocking))
	{
		UE_LOG(LogTenkaichiAbilitySystem, Error, TEXT("UTenkaichiGameplayAbility_Death::ActivateAbility: Ability [%s] failed to change activation group to blocking."), *GetName());
	}

	if (bAutoStartDeath)
	{
		StartDeath();
	}

	Super::ActivateAbility(Handle, ActorInfo, ActivationInfo, TriggerEventData);
}

// 结束时：兜底完成死亡流程（若死亡已开始），再交给父类处理
void UTenkaichiGameplayAbility_Death::EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled)
{
	check(ActorInfo);

	// 技能结束时总是尝试完成死亡，以防技能自身没有完成。
	// 如果死亡尚未开始，这里不会有任何作用。
	FinishDeath();

	Super::EndAbility(Handle, ActorInfo, ActivationInfo, bReplicateEndAbility, bWasCancelled);
}

### 2. 构造函数（★ CDO 加触发标签）

```cpp
UTenkaichiGameplayAbility_Death::UTenkaichiGameplayAbility_Death(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;
	NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::ServerInitiated;

	bAutoStartDeath = true;

	if (HasAnyFlags(RF_ClassDefaultObject))
	{
		// 把技能触发标签作为默认值添加到 CDO
		FAbilityTriggerData TriggerData;
		TriggerData.TriggerTag = TenkaichiGameplayTags::GameplayEvent_Death;
		TriggerData.TriggerSource = EGameplayAbilityTriggerSource::GameplayEvent;
		AbilityTriggers.Add(TriggerData);
	}
}
```

**★ 最精妙的是最后那个 `if`**（本文件最值得学的技巧）：

1. **`InstancingPolicy = InstancedPerActor`** —— 每个 Actor 一个实例（死亡流程要持续一段时间，必须有实例存状态）。
2. **`NetExecutionPolicy = ServerInitiated`** —— ⚠️ **和 Jump 的 `LocalPredicted` 相反**！死亡是**服务器权威**事件——客户端不能自己宣布"我死了"，必须服务器判定。这对比很能说明 GAS 策略的选择逻辑。
3. **`bAutoStartDeath = true`** —— 给 `.h` 里那个字段设默认值。
4. **`if (HasAnyFlags(RF_ClassDefaultObject))`** —— ⚠️ **关键**：
   - **`RF_ClassDefaultObject`（CDO）** —— UE 里每个 UCLASS 都有一个"类默认对象"当模板，所有实例从它拷贝默认值。
   - **为什么只在 CDO 上加**：`AbilityTriggers` 是**每个实例都会从 CDO 继承**的。如果在**每个实例**的构造函数里都 `Add`，那么蓝图子类实例化时会**重复添加**同一条触发器。
   - 所以 Lyra 只在 **CDO 构造时加一次**，所有实例自动继承这一条。
5. **`FAbilityTriggerData`** —— 引擎的触发配置结构：
   - `TriggerTag = GameplayEvent_Death` —— 监听哪个标签
   - `TriggerSource = GameplayEvent` —— 触发源类型：**GameplayEvent**（还有 `OwnedTagAdded`、`OwnedTagPresent` 等）
   - `AbilityTriggers.Add(TriggerData)` —— 加到技能上

> **这套"CDO 里配 AbilityTriggers"的写法是 Lyra 的通用套路** —— P05.6-3 Reset 技能里也有**一模一样**的一段（只是标签换成 `GameplayEvent_RequestReset`）。学会了这个，Reset 的构造函数就秒懂。

### 3. ActivateAbility（★ 死亡五步流程）

```cpp
void UTenkaichiGameplayAbility_Death::ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData)
{
	check(ActorInfo);

	UTenkaichiAbilitySystemComponent* TenkaichiASC = CastChecked<UTenkaichiAbilitySystemComponent>(ActorInfo->AbilitySystemComponent.Get());

	FGameplayTagContainer AbilityTypesToIgnore;
	AbilityTypesToIgnore.AddTag(TenkaichiGameplayTags::Ability_Behavior_SurvivesDeath);

	// 取消所有技能，并阻止其他技能启动
	TenkaichiASC->CancelAbilities(nullptr, &AbilityTypesToIgnore, this);

	SetCanBeCanceled(false);

	if (!ChangeActivationGroup(ETenkaichiAbilityActivationGroup::Exclusive_Blocking))
	{
		UE_LOG(LogTenkaichiAbilitySystem, Error, TEXT("UTenkaichiGameplayAbility_Death::ActivateAbility: Ability [%s] failed to change activation group to blocking."), *GetName());
	}

	if (bAutoStartDeath)
	{
		StartDeath();
	}

	Super::ActivateAbility(Handle, ActorInfo, ActivationInfo, TriggerEventData);
}
```

**五步逐个讲**：

1. **`check(ActorInfo)`** —— 断言不为空（空了就是 bug，直接崩）。
2. **`CastChecked<UTenkaichiAbilitySystemComponent>(ActorInfo->AbilitySystemComponent.Get())`** —— 取 Lyra ASC。用 `CastChecked` 因为"ASC 必然是 Lyra 类型"，不成立就是 bug。
   - ⚠️ **`.Get()`** —— `AbilitySystemComponent` 是 `TWeakObjectPtr`，要 `.Get()` 拿裸指针。
3. **建豁免容器**：
   ```cpp
   FGameplayTagContainer AbilityTypesToIgnore;
   AbilityTypesToIgnore.AddTag(TenkaichiGameplayTags::Ability_Behavior_SurvivesDeath);
   ```
   `Ability.Behavior.SurvivesDeath` = "**死亡时仍然存活的技能**"。带这个标签的技能（比如某些持续被动）**不会**被死亡取消。
4. **`CancelAbilities(nullptr, &AbilityTypesToIgnore, this)`** —— P05.2 教的 ASC 方法：
   - 第 1 参 `nullptr`：不限定特定标签（取消所有）
   - 第 2 参 `&AbilityTypesToIgnore`：**豁免列表**（这些不取消）
   - 第 3 参 `this`：**调用者**（避免把自己也取消了）
   - 效果：角色正在跳/射击/冲刺 → **全部中断**。这就是总 md 说的"死亡时自动取消所有技能"。
5. **`SetCanBeCanceled(false)`** —— **本技能不可被取消**（死亡一旦开始就不能被打断，除非上层强制）。
6. **`ChangeActivationGroup(Exclusive_Blocking)`** —— 切到**独占阻塞**激活组：别的技能**无法启动**。失败则 `UE_LOG` 报 Error。
7. **`if (bAutoStartDeath) StartDeath();`** —— 自动开始死亡（可被蓝图关掉改手动）。
8. **`Super::ActivateAbility(...)` 最后调** —— ⚠️ 不能漏。

### 4. EndAbility（兜底）

```cpp
void UTenkaichiGameplayAbility_Death::EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled)
{
	check(ActorInfo);

	// 技能结束时总是尝试完成死亡，以防技能自身没有完成。
	// 如果死亡尚未开始，这里不会有任何作用。
	FinishDeath();

	Super::EndAbility(Handle, ActorInfo, ActivationInfo, bReplicateEndAbility, bWasCancelled);
}
```

- **和 Jump 的 `EndAbility` 兜底思路完全一致**：无条件调 `FinishDeath()`，再 `Super::`。
- **Lyra 原注释**（已中文化）："Always try to finish the death when the ability ends in case the ability doesn't. This won't do anything if the death hasn't been started."
- **为什么安全**：`FinishDeath()` 内部判断 `GetDeathState() == DeathStarted`，没开始死亡就是**空操作**。
- ⚠️ 注意：**`FinishDeath()` 现在处于 `#if 0` 挂起块里**，所以这个函数目前调用的是一个"不存在的函数" —— ⚠️ **这也是要把 `FinishDeath()` 定义一起挂起的原因**（定义挂起了，调用点也要跟着挂，否则链接错误）。
  > 如果你**暂时想让 `EndAbility` 也能编译**，需要把 `FinishDeath();` 那一行也一起注释掉。**推荐做法**：整段照写（挂起块里包含定义），`FinishDeath();` 调用行**暂时加 `//` 注释**，并在注释备忘录里记一笔，等 P06 放开时一起恢复。

**两个函数结构对称**，逐个要素：

3. **状态判断（幂等保护）**：
   - `StartDeath` 只在 **`NotDead`** 时执行 → 防重复开始
   - `FinishDeath` 只在 **`DeathStarted`** 时执行 → 防在没开始时误完成

4. **`HealthComponent->StartDeath()` / `FinishDeath()`** —— 真正驱动生命组件的状态机。

## 六、几个要记住的点

1. **★ CDO 里加 `AbilityTriggers`** —— `HasAnyFlags(RF_ClassDefaultObject)` 保证只加一次，所有实例继承。**Reset 技能里有一模一样的套路**。
2. **`ServerInitiated` vs Jump 的 `LocalPredicted`** —— 死亡服务器权威，跳跃本地预测。策略选择的经典对比。
3. **死亡五步**：取消技能（带豁免）→ 防取消 → 切激活组 → StartDeath → `Super::`。
4. **`Ability.Behavior.SurvivesDeath` 是豁免标签** —— 带它的技能不会被死亡取消。
5. **`EndAbility` 兜底 `FinishDeath()`** —— 内部有状态判断所以安全。
6. **`GetAvatarActorFromActorInfo()` 是引擎方法**（返回 `AActor*`），区别于 `GetTenkaichiCharacterFromActorInfo()`（Lyra 封装，返回角色）。
7. **`Trace/Trace.inl` 照抄**（虽然本文件没显式用）。
