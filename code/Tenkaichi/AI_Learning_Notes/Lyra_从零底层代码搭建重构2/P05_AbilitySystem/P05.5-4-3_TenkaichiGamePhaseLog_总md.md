# P05.5-4-3 `LogTenkaichiGamePhase` —— 总 md

## 一、这个"类"要解决什么

⚠️ **它不是一个类** —— 它是一个 **日志分类（Log Category）**，整个"内容"就是**两行代码**。

**什么是日志分类？** UE 的日志系统（`UE_LOG`）要求每条日志**归属一个分类**，这样你可以：
- 在控制台用 `Log LogTenkaichiGamePhase Verbose` **单独打开/关闭**某一类日志
- 在输出窗口**按分类过滤**（只看阶段相关的，屏蔽掉其他噪音）
- 用 `Log list` 查看所有分类

**P05.5-4-2（Subsystem）里已经有 3 处 `UE_LOG(LogTenkaichiGamePhase, ...)`**（阶段开始、结束兄弟阶段、阶段结束），它们都需要这个分类**先被声明+定义**才能编译。

**所以这个"类"的作用就是：给阶段系统提供一个专属的日志通道。**

**为什么 Lyra 把它单独一个文件？**

因为它是**跨文件共享**的：
- `LyraGamePhaseLog.h` 里 `DECLARE_LOG_CATEGORY_EXTERN`（声明：告诉别人"有这个分类"）
- `LyraGamePhaseSubsystem.cpp` 里 `DEFINE_LOG_CATEGORY`（定义：真正分配存储）

任何文件只要 include 那个 `.h`，就能 `UE_LOG(LogTenkaichiGamePhase, ...)`。如果写在 Subsystem 的 `.h` 里，别的模块想用就得 include 整个 Subsystem 头——**不干净**。所以 Lyra 单独拆一个 7 行的文件。

## 三、两个宏的分工（本"类"的核心知识点）

UE 的日志分类必须**声明一次 + 定义一次**，和 C++ 的 `extern` 变量 + 定义是同一个道理：

| 宏 | 作用 | 在哪 | 出现次数 |
|----|------|------|---------|
| **`DECLARE_LOG_CATEGORY_EXTERN(名字, 默认级别, 编译级别)`** | **声明**：告诉编译器"这个分类存在，别处有定义" | `TenkaichiGamePhaseLog.h` | 1 次 |
| **`DEFINE_LOG_CATEGORY(名字)`** | **定义**：真正分配静态存储 | `TenkaichiGamePhaseSubsystem.cpp` | **1 次（全工程唯一）** |

**三个参数**：

| 参数 | Lyra 用的值 | 含义 |
|------|-----------|------|
| 分类名 | `LogTenkaichiGamePhase` | 日志分类名（前缀替换：`LogLyraGamePhase` → `LogTenkaichiGamePhase`） |
| 默认级别 | `Log` | 运行时**默认显示的级别**（低于此级别的日志被过滤掉） |
| 编译级别 | `All` | **编译期**保留到哪个级别（`All` = 全保留；设成 `Log` 的话 Verbose 级日志会被编译期剔除，打包后完全不存在） |

**UE 的日志级别（从低到高）**：
```
Verbose  <  VeryVerbose... 实际顺序：
VeryVerbose (最啰嗦)
Verbose
Log        ← Lyra 默认显示到这一级
Warning
Error      (最严重)
Fatal      (会崩溃)
```

- **默认级别 = `Log`**：意味着 `Verbose` / `VeryVerbose` 级的日志**默认不显示**（想看要手动开 `Log LogTenkaichiGamePhase Verbose`）。
- **编译级别 = `All`**：所有级别的日志**都编译进去了**（只是默认不显示）。这样发布后想调试还能打开。

> Lyra 用的三处 `UE_LOG` 都是 `Log` 级（`UE_LOG(LogTenkaichiGamePhase, Log, TEXT(...))`），所以都符合默认级别，开箱可见。
