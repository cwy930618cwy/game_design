# P05.5-4-2 `ULyraGamePhaseSubsystem` —— 总 md

## 一、这个类要解决什么

P05.5-4-1 教了 `ULyraGamePhaseAbility`——**"一个阶段"的载体**（激活即阶段开始，结束即阶段结束）。

但它只是个"被动的载体"：它会在激活/结束时喊一嗓子（通知 Subsystem），**但"谁该结束、谁该保留"这个判断，它不管**。

`ULyraGamePhaseSubsystem` 就是**做判断的那个人**——整套阶段系统的**大脑**。

**它具体管三件事**：

1. **启动阶段**：`StartPhase()` —— 给 GameState 的 ASC 一个阶段 GA 并激活它。
2. **互斥判定**：`OnBeginPhase()` —— 新阶段来了，**遍历当前活跃的所有阶段，把"不是它祖先"的全部结束**（这就是主题总 md 里"父子共存、兄弟互斥"的实现）。
3. **观察者通知**：`WhenPhaseStartsOrIsActive()` / `WhenPhaseEnds()` —— 让别的代码能"订阅"阶段变化（比如 HUD 想在结算阶段弹面板）。

**为什么它是 Subsystem 而不是 Actor？**

因为阶段是**每个世界（World）唯一**的全局状态。`UWorldSubsystem` 正是 UE 提供的"每个 World 一个实例"的标准机制——不用自己摆 Actor、不用自己管理生命周期，World 创建时自动建、World 销毁时自动销毁。

**核心一句话**：它是阶段系统的**管理者 + 裁判**——管阶段的启动/结束，裁判谁该因阶段冲突而被结束。

## 五、几个要记住的点

1. **它是 WorldSubsystem**：每个 World 一个实例，不用摆 Actor、生命周期自动管理。
2. **`ActivePhaseMap` 用句柄当 key**：`FGameplayAbilitySpecHandle` 唯一标识一次 GA 激活。
3. **互斥判定靠 `MatchesTag()`**：`IncomingPhaseTag.MatchesTag(ActivePhaseTag)` 为真 = 是祖先 = 保留；否则结束。
4. **`friend class ULyraGamePhaseAbility`**：`OnBeginPhase`/`OnEndPhase` 是 private，用友元开放给 4-1。
5. **蓝图桥接用 `K2_` 前缀**：动态委托（`FLyraGamePhaseDynamicDelegate`）↔ 原生委托（`FLyraGamePhaseDelegate`）互转，靠 `CreateWeakLambda`。
6. **4 个委托声明**在 `.h` 顶部，是本类的"对外接口"定义。
7. **零挂起**：P05.2 + P05.5-4-1 双就位。
