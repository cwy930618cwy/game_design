## 一、为什么要有这一节（解决什么问题）

P05.3-A 教了 `AbilityCost`（技能的"代价计算器"），但它只是个被调用的配角。真正的主角是 **`ULyraGameplayAbility`（技能基类）**——Lyra 项目里**所有具体技能**（射击、跳跃、死亡、重置…）都继承它。

它回答三件事：

1. **技能怎么被触发**（`ActivationPolicy` 激活策略）：输入按下触发 / 按住持续触发 / 出生自动触发。
2. **技能跟别的技能怎么互斥**（`ActivationGroup` 激活组）：独立运行 / 被替换 / 阻塞别人。
3. **技能花什么代价**（`AdditionalCosts`，就是 P05.3-A 的 `AbilityCost`）+ **失败时怎么反馈**（消息/动画）。

> 一句话：**`ULyraGameplayAbility` = 技能基类，定义"怎么触发 + 怎么互斥 + 花什么代价 + 失败怎么反馈"，Lyra 所有具体技能都继承它。** 它是 P05 的脊梁，也是 GAS 深度定制的核心。

## 三、全景：这个类里有什么（`.h` 结构）

`ULyraGameplayAbility` 继承引擎 `UGameplayAbility`，核心内容分四块：

| 块 | 内容 | 一句话 |
|----|------|--------|
| **两个枚举** | `ELyraAbilityActivationPolicy` / `ELyraAbilityActivationGroup` | 激活策略 + 激活组（蓝图可见） |
| **一个结构体** | `FLyraAbilityMontageFailureMessage` | 失败时播放蒙太奇的消息 |
| **获取器组** | `GetLyraAbilitySystemComponent/PlayerController/Controller/Character/HeroComponent` 5 个 | 从 ActorInfo 里快速拿到各类组件/控制器 |
| **核心逻辑** | `CanActivateAbility` / `ActivateAbility` / `EndAbility` / `CheckCost` / `ApplyCost` / `MakeEffectContext` / `DoesAbilitySatisfyTagRequirements` 等 override | 深度定制 GAS 技能的激活/消耗/反馈 |
| **配置字段** | `ActivationPolicy` / `ActivationGroup` / `AdditionalCosts` / `FailureTagToUserFacingMessages` / `FailureTagToAnimMontage` / `ActiveCameraMode` | 编辑器中配置技能行为 |
