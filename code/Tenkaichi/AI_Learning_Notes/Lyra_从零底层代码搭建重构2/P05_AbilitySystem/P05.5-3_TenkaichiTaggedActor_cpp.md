## 五、逐段讲解

### 1. 头文件引用

```cpp
#include "TenkaichiTaggedActor.h"
#include "UObject/UnrealType.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiTaggedActor)
```

- 第一行**本类头**：固定套路，`.cpp` 永远先 include 自己的 `.h`。
- **`UObject/UnrealType.h`（引擎）**：`CanEditChange` 里用到的 `FProperty`（UE 反射属性）定义在这里。**这是本 `.cpp` 新增的唯一 include**，且是引擎头。
- `UE_INLINE_GENERATED_CPP_BY_NAME`：固定宏（第 0 步已教过）。

> **为什么 `.h` 不需要 `UnrealType.h` 而 `.cpp` 需要**：`.h` 里 `const FProperty* InProperty` 是指针，前置声明就够（UE 的 `CoreUObject` 已间接提供）；`.cpp` 里要**调用** `InProperty->GetFName()`，必须看到完整定义。这是 UE 里很常见的"`.h` 用指针、`.cpp` 补 include"的套路。

### 2. 构造函数

```cpp
// 构造函数：仅把对象初始化器转发给父类，无额外初始化
ATenkaichiTaggedActor::ATenkaichiTaggedActor(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
}
```

- **`: Super(ObjectInitializer)`** —— 初始化列表，把初始化器原封不动传给父类 `AActor`。
- **函数体是空的 `{ }`** —— 本类不需要任何额外初始化。
- ⚠️ **`.cpp` 里不写默认参数**：`.h` 声明处已经写了 `= FObjectInitializer::Get()`，`.cpp` 定义处**必须省略**（C++ 规则：默认参数只能出现一次，重复写会编译错误）。这是新手常踩的坑。
- **`Super` 是什么**：UE 的宏，`AActor` 子类里 `Super` = `AActor`。比直接写父类名更安全（改继承时不用改代码）。

### 3. GetOwnedGameplayTags（核心，一行）

```cpp
// 把本 Actor 静态配置的 GameplayTag 追加进调用方传入的容器
void ATenkaichiTaggedActor::GetOwnedGameplayTags(FGameplayTagContainer& TagContainer) const
{
	TagContainer.AppendTags(StaticGameplayTags);
}
```

- **只有一行 `TagContainer.AppendTags(StaticGameplayTags);`**。
- **`AppendTags` 是追加不是覆盖** —— 这很重要：调用方可能已经往容器里放了别的来源的标签（比如动态运行时标签），本函数只负责"**再加上我自己的**"，不会清掉别人的。
- **为什么能这么简单**：因为 `StaticGameplayTags` 是**静态的**——编辑器配好就不变，运行时不需要做任何计算或合并逻辑。这就是总 md 里说的"Static 的含义"。
- **调用方是谁**：GAS 的标签查询、GameplayEffect 的标签匹配、任何调 `IGameplayTagAssetInterface` 查询的系统。它们是"问"，这个函数是"答"。

### 4. CanEditChange（编辑器专属，本文件唯一有逻辑的函数）

```cpp
#if WITH_EDITOR
// 判断指定属性能否在编辑器细节面板里被修改
bool ATenkaichiTaggedActor::CanEditChange(const FProperty* InProperty) const
{
	// 禁止编辑另一个标签属性（引擎 Actor 自带的 FName 数组 Tags）
	if (InProperty->GetFName() == GET_MEMBER_NAME_CHECKED(AActor, Tags))
	{
		return false;
	}

	return Super::CanEditChange(InProperty);
}
#endif
```

- **`#if WITH_EDITOR` ... `#endif`** —— 和 `.h` 里的声明**严格配对**。整个函数在打包版本不存在。
- **`InProperty->GetFName()`** —— 拿到"正在被尝试编辑的那个属性"的名字（`FName`）。
- **`GET_MEMBER_NAME_CHECKED(AActor, Tags)`** —— ⚠️ **本文件唯一的新宏**（铁律 18：遇到没教过的方法/宏要先讲）：
  - **它是什么**：UE 的**编译期安全检查宏**，展开成"类 `AActor` 的成员 `Tags` 的名字"。
  - **为什么不用字符串 `"Tags"`**：因为**编译期校验**——如果哪天引擎把 `AActor::Tags` 改名或删了，**这里会直接编译报错**，而写死字符串 `"Tags"` 只会静默失效（运行时永远匹配不上，bug 极难查）。
  - **返回值**：`FName`，可以和 `GetFName()` 直接 `==` 比较。
  - **注意宏里面是引擎类 `AActor`（不是 `ATenkaichiTaggedActor`）** —— 要禁止的是**父类**那个 FName 数组。原样不动，别替换成 Tenkaichi。
- **返回 `false`** = 这个属性**置灰不可编辑**。所以策划在细节面板里看不到/改不了 `AActor::Tags`，只能用 `StaticGameplayTags`。
- **`return Super::CanEditChange(InProperty);`** —— 不是 `Tags` 的其他属性，**交给父类决定**（默认允许编辑）。**这个兜底不能漏**——漏了的话除了 `Tags` 以外**所有属性都变成不可编辑**，Actor 就废了。
- **Lyra 这么干的目的**：避免"两套标签系统混用"——引擎的 `TArray<FName> Tags` 和 GAS 的 `FGameplayTagContainer StaticGameplayTags`。强制只用后者，标签体系统一。

## 六、几个要记住的点

1. **`.cpp` 里不写默认参数**：`.h` 写了 `= FObjectInitializer::Get()`，`.cpp` 必须省略，重复写编译错误。
2. **`AppendTags` 是追加**：不清空调用方容器，只加上自己的。
3. **`GET_MEMBER_NAME_CHECKED` 是编译期安全宏**：比字符串常量安全，成员改名会编译报错。里面是引擎 `AActor`，别替换。
4. **`return Super::CanEditChange(...)` 兜底不能漏**：否则所有属性都不可编辑。
5. **`#if WITH_EDITOR` 与 `.h` 配对**：两边都要有。
6. **零挂起**：只依赖引擎头 + 本类 `.h`，直接可编译。
