## 五、逐段讲解

### 1. 头文件引用

```cpp

```

- 第一行**本类头**：固定套路。
- **`AbilitySystemComponent.h`（引擎）**：`ActorInfo->AbilitySystemComponent->GetWorld()` 需要完整定义。
- **`Engine/World.h`（引擎）**：`UWorld::GetSubsystem<>` 模板需要。
- **`TenkaichiGamePhaseSubsystem.h`（本组 2 号）**：调 `OnBeginPhase`/`OnEndPhase`。⚠️ **同目录相对路径，不带 `Phases/` 前缀**（因为本文件就在 `Phases\` 里）——Lyra 原样。
- **`Misc/DataValidation.h` 用 `#if WITH_EDITOR` 包裹**：和 `.h` 里 `IsDataValid` 的声明**严格配对**——只有编辑器构建才 include。这是 UE 的好习惯：编辑器专用头文件不打进发布包。

### 2. LOCTEXT_NAMESPACE

```cpp
#define LOCTEXT_NAMESPACE "UTenkaichiGamePhaseAbility"
...
#undef LOCTEXT_NAMESPACE
```

- **这是什么**：UE 本地化（多语言）系统的命名空间宏。`LOCTEXT("Key", "English")` 会把字符串登记到**当前 `LOCTEXT_NAMESPACE`** 下。
- **为什么要在文件末尾 `#undef`**：不 undef 的话，这个宏会"泄漏"到后面被 include 的文件里，污染别人的命名空间。所以 UE 的规矩是 `define` 在开头、`undef` 在结尾。
- ⚠️ **`#undef LOCTEXT_NAMESPACE` 不带参数**——原样不动，别画蛇添足加名字。
- ⚠️ `#define` 里的字符串 **`"ULyraGamePhaseAbility"` 要换成 `"UTenkaichiGamePhaseAbility"`**（铁律 24）。

### 3. 构造函数（本文件重点：4 个 GA 策略）

```cpp
UTenkaichiGamePhaseAbility::UTenkaichiGamePhaseAbility(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	ReplicationPolicy = EGameplayAbilityReplicationPolicy::ReplicateNo;
	InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;
	NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::ServerInitiated;
	NetSecurityPolicy = EGameplayAbilityNetSecurityPolicy::ServerOnly;
}
```

**这 4 行是"阶段技能"的行为定义**，逐个讲：

| 策略 | 值 | 含义 | 为什么阶段要这么设 |
|------|-----|------|------------------|
| **`ReplicationPolicy`** | `ReplicateNo` | **不复制**这个 GA 的激活状态到客户端 | 阶段是服务器权威的全局状态，客户端不需要知道 GA 层面的复制；需要的话由 GameState 自己复制 |
| **`InstancingPolicy`** | `InstancedPerActor` | 每个 Actor **一个实例** | 阶段技能挂在 **GameState 的 ASC** 上，一个阶段一个实例，状态独立（配合 `.h` 里的 `GamePhaseTag` 字段需要被读取，必须有实例） |
| **`NetExecutionPolicy`** | `ServerInitiated` | 由**服务器发起** | 阶段只能由服务器切换（防作弊）；客户端不能自己开阶段 |
| **`NetSecurityPolicy`** | `ServerOnly` | **仅服务器**可执行 | 同上，客户端调用直接被拒 |

> **这 4 个策略的共同主题：服务器权威。** 游戏阶段是全局的、影响所有人的状态，绝不能让客户端插手。
> **`: Super(ObjectInitializer)`**：转发初始化器给父类（和 P05.5-3 一样，`.cpp` 不写默认参数）。

### 4. ActivateAbility（重写）

```cpp
void UTenkaichiGamePhaseAbility::ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData)
{
	if (ActorInfo->IsNetAuthority())
	{
		UWorld* World = ActorInfo->AbilitySystemComponent->GetWorld();
		UTenkaichiGamePhaseSubsystem* PhaseSubsystem = UWorld::GetSubsystem<UTenkaichiGamePhaseSubsystem>(World);
		PhaseSubsystem->OnBeginPhase(this, Handle);
	}

	Super::ActivateAbility(Handle, ActorInfo, ActivationInfo, TriggerEventData);
}
```

**三行核心 + 一个兜底**：

1. **`if (ActorInfo->IsNetAuthority())`** —— **只在服务器权威端执行**。客户端激活时直接跳过通知（配合构造函数里的 `ServerOnly`，双保险）。
2. **取 World**：`ActorInfo->AbilitySystemComponent->GetWorld()` —— 从 ASC 拿到所在世界。
3. **取 Subsystem**：`UWorld::GetSubsystem<UTenkaichiGamePhaseSubsystem>(World)` —— **UE 的 WorldSubsystem 获取标准写法**（模板函数，按类型取）。
4. **通知**：`PhaseSubsystem->OnBeginPhase(this, Handle)` —— 把自己（`this`，Subsystem 要调 `GetGamePhaseTag()`）和句柄（当 `ActivePhaseMap` 的 key）传过去。
5. **`Super::ActivateAbility(...)` 在 `if` 外面、最后调** —— ⚠️ **必须调**：不调的话基类（P05.3-B LyraGA）的激活逻辑（激活组检查、Tag 授予等）全丢。**且在 `if` 外**——客户端也要走基类激活流程。

- **`bWasCancelled` 参数**：被取消 vs 正常结束，本类**不区分**——两种情况都算"阶段结束"，Subsystem 那边统一处理。

### 6. IsDataValid（编辑器专属）

```cpp
#if WITH_EDITOR
EDataValidationResult UTenkaichiGamePhaseAbility::IsDataValid(FDataValidationContext& Context) const
{
	EDataValidationResult Result = CombineDataValidationResults(Super::IsDataValid(Context), EDataValidationResult::Valid);

	if (!GamePhaseTag.IsValid())
	{
		Result = EDataValidationResult::Invalid;
		Context.AddError(LOCTEXT("GamePhaseTagNotSet", "GamePhaseTag must be set to a tag representing the current phase."));
	}

	return Result;
}
#endif
```

- **`#if WITH_EDITOR` ... `#endif`** 与 `.h` 声明配对。
- **`CombineDataValidationResults(Super::IsDataValid(Context), EDataValidationResult::Valid)`** —— ⚠️ **新函数**（铁律 18）：
  - 它把**父类的校验结果**和 `Valid` 合并起来。意思："先听父类的，我默认自己没问题"。
  - 为什么要"合并"而不是直接返回：父类可能有自己的校验错误，不能覆盖掉。
- **`if (!GamePhaseTag.IsValid())`** —— 检查阶段标签配没配。`FGameplayTag::IsValid()` 判断标签是否为空。
- **`Result = EDataValidationResult::Invalid;`** —— 没配就标记无效。
- **`Context.AddError(LOCTEXT(...))`** —— 往校验上下文里加一条错误，编辑器界面上会显示。**`LOCTEXT` 就用到了文件开头 `#define` 的命名空间**。
- **`LOCTEXT("GamePhaseTagNotSet", "GamePhaseTag must be set to a tag representing the current phase.")`**：
  - 第一个参数是 **key**（本地化用的键，代码标识符，保持英文）
  - 第二个参数是 **默认英文文本**（翻译时会被替换）——⚠️ **这是 UI 显示文本不是注释，保持英文原样**（铁律 21 只管注释，UI 文本是数据）
