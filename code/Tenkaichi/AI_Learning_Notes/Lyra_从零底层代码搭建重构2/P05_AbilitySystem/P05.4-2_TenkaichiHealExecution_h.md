## 四、逐段讲解

### 1. 头文件与前置声明

```cpp
#pragma once
#include "GameplayEffectExecutionCalculation.h"
#include "TenkaichiHealExecution.generated.h"

class UObject;
```

- `GameplayEffectExecutionCalculation.h`：基类头（和 Damage 同一个基类）。
- `TenkaichiHealExecution.generated.h`：UE 反射代码生成头。
- 前置声明 `class UObject;`：保留以与 Lyra 一致（铁律 23 一字不砍）。

### 2. 类声明

```cpp
UCLASS()
class UTenkaichiHealExecution : public UGameplayEffectExecutionCalculation
{
	GENERATED_BODY()
public:
	UTenkaichiHealExecution();
protected:
	virtual void Execute_Implementation(const FGameplayEffectCustomExecutionParameters& ExecutionParams, FGameplayEffectCustomExecutionOutput& OutExecutionOutput) const override;
};
```

和 DamageExecution 逐字对比，**只有两个名字不同**：
- 类名 `UTenkaichiHealExecution`（vs `UTenkaichiDamageExecution`）
- 构造函数 `UTenkaichiHealExecution()`（vs `UTenkaichiDamageExecution()`）

其余（继承、GENERATED_BODY、虚函数签名）一模一样。因为两个 Execution 走的是同一套 GAS 执行计算机制。

- **构造函数**：`.cpp` 里注册抓取 `BaseHeal`（而非 `BaseDamage`）。
- **`Execute_Implementation`**：每次 GE 施加这个 Execution 时被调用，参数含义同 Damage（`ExecutionParams` 提供数据、`OutExecutionOutput` 写回结果）。

## 五、几个要记住的点

1. **Damage 和 Heal 是孪生类**：结构完全同构，只是抓的属性（`BaseDamage` vs `BaseHeal`）和输出的元属性（`Damage` vs `Healing`）不同。
2. **`.h` 只有骨架**：无属性、无 UPROPERTY，全靠构造函数 + 重写虚函数。
3. **可独立编译**：只依赖引擎基类，无工程依赖。
