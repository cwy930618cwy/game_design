## 五、逐段讲解

### 1. 头文件与 include

```cpp
#include "TenkaichiGameplayAbilityTargetData_SingleTargetHit.h"

```

- 第一行的**本类头**：固定套路，`.cpp` 永远先 include 自己的 `.h`。
- **`TenkaichiGameplayEffectContext.h`（P05.5-1）**：这是本 `.cpp` 唯一的新增工程依赖。要调 `FTenkaichiGameplayEffectContext::ExtractEffectContext`、要写它的 `CartridgeID` 成员，必须看到完整定义。**注意：Lyra 这里写的是同目录相对路径（不带 `AbilitySystem/` 前缀）**，因为本文件就在 `AbilitySystem\` 里——照抄，别加前缀。
- `UE_INLINE_GENERATED_CPP_BY_NAME`：固定宏（第 0 步已教过）。
- `struct FGameplayEffectContextHandle;`：文件里再次前置声明一次（Lyra 原样保留）。虽然 `.h` 已经声明过，这里再写一遍无害——**铁律 23 一字不砍，照抄**。

### 2. AddTargetDataToContext（核心）

```cpp
void FTenkaichiGameplayAbilityTargetData_SingleTargetHit::AddTargetDataToContext(FGameplayEffectContextHandle& Context, bool bIncludeActorArray) const
{
	FGameplayAbilityTargetData_SingleTargetHit::AddTargetDataToContext(Context, bIncludeActorArray);

	// 添加游戏特定的数据
	if (FTenkaichiGameplayEffectContext* TypedContext = FTenkaichiGameplayEffectContext::ExtractEffectContext(Context))
	{
		TypedContext->CartridgeID = CartridgeID;
	}
}
```

**三行结构，非常清晰**：

1. **先调基类** `FGameplayAbilityTargetData_SingleTargetHit::AddTargetDataToContext(Context, bIncludeActorArray);`
   - 基类把"命中了谁、命中点在哪"这些引擎标准字段写进 Context。
   - **必须调**——不调的话命中位置信息全丢，伤害判定就废了。
2. **`ExtractEffectContext(Context)`** —— **这就是 P05.5-1 教的那个函数的用武之地**。
   - 它从句柄里安全取出 `FTenkaichiGameplayEffectContext*`，类型不对就返回 `nullptr`。
   - **为什么不能直接 Cast**：Context 里装的不一定是 Lyra 类型（可能是引擎原版 `FGameplayEffectContext`），所以必须用这个"安全取出"。
3. **`TypedContext->CartridgeID = CartridgeID;`** —— 把本结构体的弹夹 ID 复制进效果上下文。
   - 注意**用 `if` 包着**：`TypedContext` 为 `nullptr` 时直接跳过，不会崩。这是 Lyra 的防御式写法。

**数据流向一句话**：
```
技能命中产生本 TargetData（含 CartridgeID）
   → 本函数把它写进 EffectContext
   → GE 执行 → DamageExecution 从 EffectContext 读出来用
```

> **这就是 P05.5-1 里 `CartridgeID` 字段的值来源**——那边默认 `-1`，是这里填进去的。两个 `CartridgeID` 是"写入方"和"读取方"的关系。

### 3. NetSerialize（网络序列化）

```cpp
bool FTenkaichiGameplayAbilityTargetData_SingleTargetHit::NetSerialize(FArchive& Ar, class UPackageMap* Map, bool& bOutSuccess)
{
	FGameplayAbilityTargetData_SingleTargetHit::NetSerialize(Ar, Map, bOutSuccess);

	Ar << CartridgeID;

	return true;
}
```

- **先调基类** `FGameplayAbilityTargetData_SingleTargetHit::NetSerialize(...)`：序列化命中 Actor、命中点等基类字段。
- **`Ar << CartridgeID;`** —— 这是 UE 序列化操作符的标准写法：
  - `FArchive` 在**写**模式（打包发送）时，`<<` 表示"把 `CartridgeID` 写进包"；
  - 在**读**模式（接收解包）时，同一个 `<<` 表示"从包里读出来填进 `CartridgeID`"。
  - **一个操作符干两件事**，方向由 `Ar` 自己决定——这是 UE 的经典设计。
- **`return true;`**：告诉调用方序列化成功。
- ⚠️ **和 P05.5-1 对比**：那边 `NetSerialize` 里**没有**序列化 `CartridgeID`（Lyra 注释说"目前不序列化 CartridgeID"），**这边序列化了**。两类处理不同——EffectContext 不传弹夹 ID，TargetData 传。照抄，别看那边没写就以为这边也不用写。

### 4. 为什么只有 2 个函数

`.h` 声明了 4 个方法，`.cpp` 只实现 2 个，因为：

| 方法 | 在哪实现 | 原因 |
|------|---------|------|
| 构造函数 | **`.h` 内联** | 只有一行初始化列表，直接写在声明处 |
| `AddTargetDataToContext` | **`.cpp`** | 有实际逻辑，且依赖 EffectContext |
| `NetSerialize` | **`.cpp`** | 有实际逻辑 |
| `GetScriptStruct` | **`.h` 内联** | 只有一行 `return StaticStruct();` |

> 所以 **`.cpp` 只有 2 个函数才是对的**，别以为漏了。

## 六、几个要记住的点

1. **本 `.cpp` 是 P05.5-1 的第一个"使用者"**：`ExtractEffectContext` 在教的时候还没人用，这里就是它的调用点。
2. **`ExtractEffectContext` 必须用 `if` 包**：返回 `nullptr` 时跳过，防御式写法。
3. **`Ar <<` 双向**：写包和读包用同一个操作符，方向由 `FArchive` 决定。
4. **两边 `CartridgeID` 处理不同**：EffectContext 不序列化（P05.5-1），TargetData 序列化（本类）——照抄别统一。
5. **include 路径不带 `AbilitySystem/` 前缀**：Lyra 原样，因为同目录。
