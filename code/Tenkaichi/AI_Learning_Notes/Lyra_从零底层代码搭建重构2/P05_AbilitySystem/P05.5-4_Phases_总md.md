# P05.5-4 `Phases/`（游戏阶段状态机）—— 主题总 md

## 一、这组要解决什么

前面教的三类都是 GAS 的**数据结构 / 标记**：
- P05.5-1 `GameplayEffectContext` —— 效果上下文（GE 执行时带的信息）
- P05.5-2 `SingleTargetHit` —— 目标数据（命中信息）
- P05.5-3 `TaggedActor` —— 带标签的 Actor

`Phases/` 完全不同 —— 它是 **GAS 的一个实际应用**：**用 GameplayTag + GameplayAbility 实现游戏阶段状态机**。

**什么是"游戏阶段"？** 一局游戏的流程分段，比如：
```
Game.Playing.WarmUp        （热身）
Game.Playing.NormalPlay    （正常对战）
Game.Playing.SuddenDeath   （决胜局）
Game.ShowingScore          （结算）
```

**Lyra 的阶段系统最精妙的地方：用 GameplayTag 的层级关系表达阶段的嵌套与互斥。**

> **父子阶段可以共存，兄弟阶段互斥。**

- `Game.Playing` 和 `Game.Playing.WarmUp` **可以同时活跃**（父子，不冲突）
- `Game.Playing` 和 `Game.ShowingScore` **不能同时活跃**（兄弟，互斥）
- 启动新阶段时，**所有"不是它祖先"的活跃阶段都会被结束**
  - 例：当前活跃 `Game.Playing` + `Game.Playing.CaptureTheFlag`，此时启动 `Game.Playing.PostGame` → `Game.Playing` **保留**（它是祖先），`Game.Playing.CaptureTheFlag` **结束**（它是兄弟）

**这套机制的载体是什么？** 每个阶段 = 一个 `ULyraGamePhaseAbility`（挂在 **GameState 的 ASC** 上）。阶段开始 = 激活这个 GA，阶段结束 = 结束这个 GA。阶段切换的"互斥判定"由 `ULyraGamePhaseSubsystem` 用 Tag 层级关系完成。

## 五、几个要记住的点

1. **阶段 = GameplayAbility**：不是自己写状态机，而是把 GAS 的能力系统"借"来当状态机用。阶段开始=激活 GA，结束=结束 GA。
2. **互斥靠 Tag 层级**：`MatchesTag()` 判断是否为祖先。父子共存、兄弟互斥——这是本组最精妙的设计。
3. **阶段 GA 挂在 GameState 的 ASC 上**：不是角色身上。因为阶段是**全局**的，不属于某个玩家。
4. **2 号文件是本组核心**：224 行，占整组 62%。`ActivePhaseMap` + 两个观察者数组是它的核心数据结构。
5. **3 号没有 `.cpp`**：`DEFINE_LOG_CATEGORY` 写在 `Subsystem.cpp` 里，Lyra 原样。
6. **整组零挂起**：P05.2 + P05.3-B 已就位。
