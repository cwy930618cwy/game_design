# P05.4-2 HealExecution —— 教 .cpp

## 一、本文件要解决什么

把 `Execute_Implementation`（治疗算法）落成真实的 `.cpp`。`.h` 里只声明了构造函数和这个虚函数，真正的治疗计算逻辑全在 `.cpp`。

**本文件完成两件事**：
1. **构造函数**：告诉 GAS "我要抓取 `BaseHeal` 属性"（注册捕获定义）。
2. **`Execute_Implementation`**：GE 执行时被 GAS 调用，算出"这次治疗多少"：
   - 从 `CombatSet` 抓 `BaseHeal`（基础治疗量）
   - 钳到 ≥0
   - 输出到 `HealthSet` 的 `Healing` 元属性（HealthSet 再把它转成 +Health）

> 相比 DamageExecution 的"三档衰减 + 命中处理 + 队伍规则"，**HealExecution 简单得多**——治疗不走物理材质/距离/队伍判定，抓完 `BaseHeal` 直接输出即可。

## 四、完整代码（注释已中文化，零挂起）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#include "TenkaichiHealExecution.h"
#include "AbilitySystem/Attributes/TenkaichiHealthSet.h"
#include "AbilitySystem/Attributes/TenkaichiCombatSet.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiHealExecution)

// 治疗计算的静态数据：把"要抓取的属性"提前算好存起来
struct FHealStatics
{
	// 基础治疗属性的捕获定义（从源对象 CombatSet 抓取）
	FGameplayEffectAttributeCaptureDefinition BaseHealDef;

	// 构造函数：用 CombatSet 的 BaseHeal 属性 + 源来源 + 可选 构建捕获定义
	FHealStatics()
	{
		BaseHealDef = FGameplayEffectAttributeCaptureDefinition(UTenkaichiCombatSet::GetBaseHealAttribute(), EGameplayEffectAttributeCaptureSource::Source, true);
	}
};

// 返回治疗计算的静态单例（第一次调用时构造，之后复用）
static FHealStatics& HealStatics()
{
	static FHealStatics Statics;
	return Statics;
}


// 构造函数：往捕获列表注册基础治疗属性，GAS 执行时就会帮我们抓取它
UTenkaichiHealExecution::UTenkaichiHealExecution()
{
	RelevantAttributesToCapture.Add(HealStatics().BaseHealDef);
}

// 执行计算的核心虚函数：GE 施加时被调用，算出这次治疗多少
void UTenkaichiHealExecution::Execute_Implementation(const FGameplayEffectCustomExecutionParameters& ExecutionParams, FGameplayEffectCustomExecutionOutput& OutExecutionOutput) const
{
#if WITH_SERVER_CODE
	const FGameplayEffectSpec& Spec = ExecutionParams.GetOwningSpec();

	const FGameplayTagContainer* SourceTags = Spec.CapturedSourceTags.GetAggregatedTags();
	const FGameplayTagContainer* TargetTags = Spec.CapturedTargetTags.GetAggregatedTags();

	// 评估参数：带上源/目标标签，让属性聚合能正确计算
	FAggregatorEvaluateParameters EvaluateParameters;
	EvaluateParameters.SourceTags = SourceTags;
	EvaluateParameters.TargetTags = TargetTags;

	// 从捕获里取出基础治疗值
	float BaseHeal = 0.0f;
	ExecutionParams.AttemptCalculateCapturedAttributeMagnitude(HealStatics().BaseHealDef, EvaluateParameters, BaseHeal);

	// 治疗量钳到 ≥0（治疗不可能是负数）
	const float HealingDone = FMath::Max(0.0f, BaseHeal);

	if (HealingDone > 0.0f)
	{
		// 施加一个治疗修饰器，这会在目标上转成 +health
		OutExecutionOutput.AddOutputModifier(FGameplayModifierEvaluatedData(UTenkaichiHealthSet::GetHealingAttribute(), EGameplayModOp::Additive, HealingDone));
	}
#endif // #if WITH_SERVER_CODE
}
```

## 五、逐段讲解

### 1. 头文件与 include

```cpp
#include "TenkaichiHealExecution.h"
#include "AbilitySystem/Attributes/TenkaichiHealthSet.h"
#include "AbilitySystem/Attributes/TenkaichiCombatSet.h"
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiHealExecution)
```

- `TenkaichiHealExecution.h`：自己的头文件。
- `TenkaichiHealthSet.h`：要用 `GetHealingAttribute()`（输出到 Healing 元属性）。
- `TenkaichiCombatSet.h`：要用 `GetBaseHealAttribute()`（抓基础治疗）。
- `UE_INLINE_GENERATED_CPP_BY_NAME`：UE5 固定宏（第 02 课 P04-1c 教过），替代老式 `.gen.cpp` include。

> 对比 DamageExecution 的 `.cpp`，这里**少了** `TenkaichiAbilitySourceInterface.h`、`Engine/World.h`、`TenkaichiLogChannels.h`、`Teams/TenkaichiTeamSubsystem.h`——因为治疗不需要衰减接口、距离计算、报错日志、队伍规则。

### 2. 捕获定义（FHealStatics）

```cpp
struct FHealStatics
{
	FGameplayEffectAttributeCaptureDefinition BaseHealDef;
	FHealStatics()
	{
		BaseHealDef = FGameplayEffectAttributeCaptureDefinition(UTenkaichiCombatSet::GetBaseHealAttribute(), EGameplayEffectAttributeCaptureSource::Source, true);
	}
};
static FHealStatics& HealStatics()
{
	static FHealStatics Statics;
	return Statics;
}
```

和 DamageExecution 的 `FDamageStatics` 完全同构，只差两点：
- 结构体名 `FHealStatics`（vs `FDamageStatics`）
- 抓的属性 `GetBaseHealAttribute()`（vs `GetBaseDamageAttribute()`）

- **`FGameplayEffectAttributeCaptureDefinition`**：引擎结构，描述"要抓取哪个属性 + 从哪抓（源/目标）+ 是否可选"。
- **`EGameplayEffectAttributeCaptureSource::Source`**：从**来源**（施法者）抓 `BaseHeal`。
- **第三个参数 `true`**：`bSnapshot`，是否在 GE 施加时快照属性值。
- **`HealStatics()`**：局部静态单例（函数内 static 只构造一次），Lyra 用这种模式避免重复构造。

### 3. 构造函数

```cpp
UTenkaichiHealExecution::UTenkaichiHealExecution()
{
	RelevantAttributesToCapture.Add(HealStatics().BaseHealDef);
}
```

- `RelevantAttributesToCapture`：基类提供的捕获列表。Add 进去后，GAS 每次执行就会自动抓取 `BaseHeal`。

### 4. Execute_Implementation（治疗算法，零挂起）

```cpp
void UTenkaichiHealExecution::Execute_Implementation(...) const
{
#if WITH_SERVER_CODE
	const FGameplayEffectSpec& Spec = ExecutionParams.GetOwningSpec();
	// ... SourceTags / TargetTags / EvaluateParameters
	float BaseHeal = 0.0f;
	ExecutionParams.AttemptCalculateCapturedAttributeMagnitude(HealStatics().BaseHealDef, EvaluateParameters, BaseHeal);

	const float HealingDone = FMath::Max(0.0f, BaseHeal);

	if (HealingDone > 0.0f)
	{
		OutExecutionOutput.AddOutputModifier(FGameplayModifierEvaluatedData(UTenkaichiHealthSet::GetHealingAttribute(), EGameplayModOp::Additive, HealingDone));
	}
#endif
}
```

执行流程（比 Damage 短很多）：
1. **取 Spec + 标签**：`GetOwningSpec()` 拿 GE 规格，取源/目标标签，拼进 `EvaluateParameters`。
2. **抓 BaseHeal**：`AttemptCalculateCapturedAttributeMagnitude` 用捕获定义把基础治疗算出来。
3. **钳 ≥0**：`FMath::Max(0.0f, BaseHeal)`，治疗不可能是负数。
4. **输出**：`AddOutputModifier` 把治疗量以 `Additive` 方式加到 `HealthSet` 的 `Healing` 元属性（HealthSet 再转成 +Health）。

## 六、几个要记住的点

1. **Heal 是 Damage 的"极简版"**：同构但砍掉了命中处理、队伍规则、双衰减，只保留"抓 BaseHeal → 钳 → 输出"。
2. **`Healing` vs `Damage` 元属性**：Damage 输出到 `Damage`（HealthSet 转 -Health），Heal 输出到 `Healing`（HealthSet 转 +Health）。
3. **`WITH_SERVER_CODE`**：治疗逻辑也包在服务端宏里，服务端权威。
4. **Execution 只算数值、不改状态**：只输出 modifier，真正加血由 HealthSet 的 `PostGameplayEffectExecute` 做。
