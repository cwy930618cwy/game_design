# P05.6-2 GameplayAbility_Death —— 教 .h

## 一、本文件要解决什么

把总 md 里"死亡流程编排者"这个类落成真实的 `.h` 文件。`TenkaichiGameplayAbility_Death.h` 定义一个 `UTenkaichiGameplayAbility_Death` 类——它继承 `UTenkaichiGameplayAbility`（P05.3-B），**只新增一个字段 `bAutoStartDeath`**，并重写激活/结束生命周期 + 加两个蓝图可调用函数。

**这个 `.h` 声明了 5 个方法 + 1 个字段**：
1. **构造函数** —— 设 2 个策略 + `bAutoStartDeath = true` + **给 CDO 加触发标签**。
2. **`ActivateAbility`（重写）** —— 死亡流程主逻辑。
3. **`EndAbility`（重写）** —— 兜底 `FinishDeath()`。
4. **`StartDeath`（UFUNCTION）** —— 通知 HealthComponent 开始死亡。
5. **`FinishDeath`（UFUNCTION）** —— 通知 HealthComponent 完成死亡。
6. **`bAutoStartDeath` 字段** —— 是否自动开始死亡（默认 `true`）。

> 依赖只有 P05.3-B 基类，**零挂起可独立编译**（HealthComponent 在 `.h` 里完全不出现，只在 `.cpp` 里用）。

## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "TenkaichiGameplayAbility.h"

#include "TenkaichiGameplayAbility_Death.generated.h"

class UObject;
struct FFrame;
struct FGameplayAbilityActorInfo;
struct FGameplayEventData;


/**
 * UTenkaichiGameplayAbility_Death
 *
 *	用于处理死亡的技能。
 *	该技能通过 "GameplayEvent.Death" 技能触发标签自动激活。
 */
UCLASS(Abstract)
class UTenkaichiGameplayAbility_Death : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()

public:

	// 构造函数：设置实例化/网络策略、默认自动开始死亡，并为 CDO 添加死亡触发标签
	UTenkaichiGameplayAbility_Death(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

protected:

	// 激活时取消其他所有技能、禁止自身被取消，并切换到独占阻塞激活组
	virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
	// 结束时兜底完成死亡流程（若死亡已开始）
	virtual void EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled) override;

	// 开始死亡流程
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
	void StartDeath();

	// 完成死亡流程
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
	void FinishDeath();

protected:

	// 若启用，技能会自动调用 StartDeath。若死亡已开始，则技能结束时总会调用 FinishDeath。
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Tenkaichi|Death")
	bool bAutoStartDeath;
};
```

## 四、逐段讲解

### 1. 头文件引用与前置声明

```cpp
#pragma once

#include "TenkaichiGameplayAbility.h"

#include "TenkaichiGameplayAbility_Death.generated.h"

class UObject;
struct FFrame;
struct FGameplayAbilityActorInfo;
struct FGameplayEventData;
```

- **`TenkaichiGameplayAbility.h`（P05.3-B）**：基类，**同目录相对路径不带前缀**（本文件在 `Abilities\` 里）。和 Jump 的 `.h` 写法一致。
- **`TenkaichiGameplayAbility_Death.generated.h`**：反射生成头，必须最后。
- **4 个前置声明**：
  - `UObject` —— UE 反射需要
  - `FFrame` —— 蓝图虚拟机栈帧（UFUNCTION 需要）
  - `FGameplayAbilityActorInfo` —— `ActivateAbility`/`EndAbility` 参数
  - **`FGameplayEventData`** —— ⚠️ **注意这个和 Jump 不同**：Death 是**事件触发**的技能，所以参数里有 `FGameplayEventData*`（事件携带的数据）；Jump 没有（它是输入触发）。照抄，别混。
- ⚠️ **没有 include HealthComponent** —— `.h` 里根本不需要它（只在 `.cpp` 的两个函数体里用）。**这就是 `.h` 零挂起的原因**。

### 2. 类声明与 Abstract

```cpp
/**
 * UTenkaichiGameplayAbility_Death
 *
 *	用于处理死亡的技能。
 *	该技能通过 "GameplayEvent.Death" 技能触发标签自动激活。
 */
UCLASS(Abstract)
class UTenkaichiGameplayAbility_Death : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()
```

- **`UCLASS(Abstract)`** —— 和 Jump 一样，**抽象类，必须建蓝图子类**。因为死亡动画/特效/时长的编排在蓝图里做。
- **文档注释是 Lyra 原文**（已中文化），明确说了触发方式：**通过 `GameplayEvent.Death` 触发标签自动激活**。⚠️ 注释里的类名换成 Tenkaichi 前缀。
- **继承 `UTenkaichiGameplayAbility`（P05.3-B）** —— 拿到激活组管理（`ChangeActivationGroup`）、`GetTenkaichiCharacterFromActorInfo()` 等能力。

### 3. 构造函数

```cpp
public:

	// 构造函数：设置实例化/网络策略、默认自动开始死亡，并为 CDO 添加死亡触发标签
	UTenkaichiGameplayAbility_Death(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

- **实现在 `.cpp`**，做四件事：
  1. `InstancingPolicy = InstancedPerActor`
  2. `NetExecutionPolicy = ServerInitiated`（⚠️ **和 Jump 的 `LocalPredicted` 相反**——死亡是服务器权威事件，客户端不能自己"死亡"）
  3. `bAutoStartDeath = true`
  4. **`if (HasAnyFlags(RF_ClassDefaultObject))` → 给 CDO 加 `AbilityTriggers`**（这是最精妙的一步，`.cpp` 里详讲）
- ⚠️ `.h` 写默认参数，`.cpp` 定义处省略。

### 4. ActivateAbility（重写，核心）

```cpp
protected:

	// 激活时取消其他所有技能、禁止自身被取消，并切换到独占阻塞激活组
	virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
```

- **`.cpp` 里的五步流程**：
  1. `check(ActorInfo)` —— 断言不为空
  2. `CastChecked<UTenkaichiAbilitySystemComponent>` 取 Lyra ASC
  3. **建豁免容器** `AbilityTypesToIgnore`，加 `Ability_Behavior_SurvivesDeath` 标签
  4. **`LyraASC->CancelAbilities(nullptr, &AbilityTypesToIgnore, this)`** —— 取消所有技能，但**豁免**带那个标签的
  5. `SetCanBeCanceled(false)` + `ChangeActivationGroup(Exclusive_Blocking)` + （可选）`StartDeath()`
  6. 最后 `Super::ActivateAbility(...)`
- **参数 `FGameplayEventData* TriggerEventData`** —— 触发事件携带的数据（比如谁杀的、什么伤害）。本类不用它，但签名必须有。
- **`protected`** —— 引擎内部调用，外部不直接调。

### 5. EndAbility（重写）

```cpp
	// 结束时兜底完成死亡流程（若死亡已开始）
	virtual void EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled) override;
```

- **`.cpp` 里只做**：`FinishDeath();` 然后 `Super::EndAbility(...)`。
- **和 Jump 的兜底思路完全一样**（Lyra 原注释："Always try to finish the death when the ability ends in case the ability doesn't."）——**万一蓝图忘了调 `FinishDeath()`，这里兜底**。
- **为什么安全**：`FinishDeath()` 内部会判断死亡状态（只有 `DeathStarted` 才执行），没开始死亡时是空操作。

### 6. StartDeath / FinishDeath（UFUNCTION）

```cpp
	// 开始死亡流程
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
	void StartDeath();

	// 完成死亡流程
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
	void FinishDeath();
```

- **`UFUNCTION(BlueprintCallable, ...)`** —— 蓝图可调用。**这是蓝图编排死亡动画的入口**：
  ```
  蓝图子类：StartDeath() → 播死亡动画/特效 → [等几秒] → FinishDeath()
  ```
- **`Category = "Tenkaichi|Ability"`** —— ⚠️ **两处，原 `"Lyra|Ability"` 必须换成 `"Tenkaichi|Ability"`**（铁律 24）。
- **为什么在 `protected` 段但蓝图能调**：`BlueprintCallable` 会开放给蓝图，C++ 侧仍受 `protected` 约束。
- **`.cpp` 实现**（⚠️ 这两个函数体**需要挂起**，因为用 HealthComponent）：
  ```cpp
  if (UTenkaichiHealthComponent* HealthComponent = UTenkaichiHealthComponent::FindHealthComponent(GetAvatarActorFromActorInfo()))
  {
      if (HealthComponent->GetDeathState() == ETenkaichiDeathState::NotDead)
      {
          HealthComponent->StartDeath();
      }
  }
  ```
  - `FindHealthComponent` 是 HealthComponent 的**静态查找函数**（P06 教）
  - `GetDeathState()` 返回死亡状态枚举（`NotDead` / `DeathStarted` / `DeathFinished`）
  - **状态判断很重要**：`StartDeath` 只在 `NotDead` 时执行（防重复），`FinishDeath` 只在 `DeathStarted` 时执行

### 7. bAutoStartDeath 字段

```cpp
protected:

	// 若启用，技能会自动调用 StartDeath。若死亡已开始，则技能结束时总会调用 FinishDeath。
	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Tenkaichi|Death")
	bool bAutoStartDeath;
```

- **`UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Tenkaichi|Death")`**：
  - `EditDefaultsOnly` —— 只能在**类默认值/蓝图默认**里改（不能在实例上改）。"这个死亡技能要不要自动开始"是固有属性。
  - `BlueprintReadOnly` —— 蓝图可读不可写。
  - **`Category = "Tenkaichi|Death"`** —— ⚠️ 第三个要换的 Category（前两个是 `"Tenkaichi|Ability"`）。
- **`bool bAutoStartDeath`** —— 默认在构造函数里设成 `true`。
- **它的用途**：有些特殊的死亡技能可能想**手动控制**何时开始死亡（比如先播一段台词再死），就把这个关掉，在蓝图里自己调 `StartDeath()`。
- ⚠️ **第二个 `protected:` 段** —— Lyra 原样，和上面的方法段之间隔了 UFUNCTION 块，**照抄别合并**。

## 五、几个要记住的点

1. **`.h` 里没有 HealthComponent** —— 这就是 `.h` 零挂起的原因（只有 `.cpp` 的两个函数体用）。
2. **参数是 `FGameplayEventData*` 不是 `FGameplayTagContainer*`** —— 事件触发 vs 输入触发的区别（对比 Jump）。
3. **三个 `Category` 都要换前缀**：2 个 `"Tenkaichi|Ability"` + 1 个 `"Tenkaichi|Death"`（最容易漏）。
4. **`NetExecutionPolicy = ServerInitiated`**（在 `.cpp`）—— 和 Jump 的 `LocalPredicted` 相反，死亡是服务器权威。
5. **`EndAbility` 兜底 `FinishDeath()`** —— 和 Jump 兜底思路一致。
6. **两个 `protected:` 段照抄不合并**。
7. **`.h` 零挂起**。
