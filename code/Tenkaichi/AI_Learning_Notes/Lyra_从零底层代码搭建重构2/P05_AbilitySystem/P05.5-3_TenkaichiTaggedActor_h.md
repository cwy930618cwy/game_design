# P05.5-3 TaggedActor —— 教 .h

## 一、本文件要解决什么

把总 md 里"带 GameplayTag 的 Actor"这个类落成真实的 `.h` 文件。`TenkaichiTaggedActor.h` 定义一个 `ATenkaichiTaggedActor` 类——它继承引擎 `AActor`，同时**实现 `IGameplayTagAssetInterface` 接口**，从而让普通 Actor 也能被 GAS 的标签查询系统识别。

**这个 `.h` 声明了 3 个方法 + 1 个字段**：
1. **构造函数** `ATenkaichiTaggedActor(const FObjectInitializer& ...)` —— 最简形式，只转发初始化器。
2. **`GetOwnedGameplayTags`（接口实现）** —— **类的核心**：把本 Actor 的标签追加给调用方。
3. **`CanEditChange`（仅编辑器）** —— 禁止在细节面板里编辑 `AActor::Tags` 那个 FName 数组。
4. **`StaticGameplayTags` 字段** —— 在编辑器里静态配置的一组 GameplayTag。

> 依赖全是引擎头（`AActor` + `IGameplayTagAssetInterface` + `GameplayTagContainer`），**零工程依赖，可独立编译零挂起**。

## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "GameFramework/Actor.h"
#include "GameplayTagAssetInterface.h"
#include "GameplayTagContainer.h"

#include "TenkaichiTaggedActor.generated.h"

// 实现了 GameplayTag 资产接口的 Actor
UCLASS()
class ATenkaichiTaggedActor : public AActor, public IGameplayTagAssetInterface
{
	GENERATED_BODY()

public:

	// 构造函数：仅转发对象初始化器，无额外初始化
	ATenkaichiTaggedActor(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	//~IGameplayTagAssetInterface 接口开始
	virtual void GetOwnedGameplayTags(FGameplayTagContainer& TagContainer) const override;
	//~IGameplayTagAssetInterface 接口结束

	//~UObject 接口开始
#if WITH_EDITOR
	virtual bool CanEditChange(const FProperty* InProperty) const override;
#endif
	//~UObject 接口结束

protected:
	// 与本 Actor 关联的、游戏相关的标签
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Actor)
	FGameplayTagContainer StaticGameplayTags;
};
```

## 四、逐段讲解

### 1. 头文件引用

```cpp
#pragma once

#include "GameFramework/Actor.h"
#include "GameplayTagAssetInterface.h"
#include "GameplayTagContainer.h"

#include "TenkaichiTaggedActor.generated.h"
```

- `GameFramework/Actor.h`：**基类 `AActor`** 的定义。这是引擎最基础的场景对象类。
- `GameplayTagAssetInterface.h`：**接口 `IGameplayTagAssetInterface`** 的定义。**必须 include 完整定义**（不是前置声明）——因为本类要**继承实现它**，编译器需要知道它长什么样、有哪些虚函数。
- `GameplayTagContainer.h`：`FGameplayTagContainer` 类型（下面 `StaticGameplayTags` 字段的类型）+ `GetOwnedGameplayTags` 的参数类型。
- `TenkaichiTaggedActor.generated.h`：UE 反射代码生成头（`UCLASS` 必需，且**必须放在最后一个 include**）。

> **注意**：这三个都是**引擎头**，一个工程依赖都没有。这就是为什么本 `.h` **零挂起**。

### 2. 类声明与双继承（本类最关键的一行）

```cpp
// 实现了 GameplayTag 资产接口的 Actor
UCLASS()
class ATenkaichiTaggedActor : public AActor, public IGameplayTagAssetInterface
{
	GENERATED_BODY()
```

- **`UCLASS()`**：无参数（不需要蓝图可见/编辑器可见之类的额外标记）。
- **双继承 `public AActor, public IGameplayTagAssetInterface`** —— **这是整个类最核心的设计**：
  - `AActor`：拿到 Actor 的一切（能摆进场景、有 Transform、能复制、有组件……）。
  - `IGameplayTagAssetInterface`：拿到"**可被标签系统查询**"的能力。
- **UE 的 UINTERFACE 机制**：`IGameplayTagAssetInterface` 是引擎用 `UINTERFACE` 声明的接口。C++ 里实现 UE 接口就是**像继承基类一样 `public` 继承它**，然后重写它的纯虚函数。注意命名约定——引擎里 `UGameplayTagAssetInterface`（`U` 前缀）是 UObject 壳，`IGameplayTagAssetInterface`（`I` 前缀）才是我们继承的 C++ 接口类。
- **为什么值得单独做一个类**：引擎的 `AActor` 只有 `TArray<FName> Tags`（纯字符串、无层级、拼错不报错）。做了这个类之后，关卡里的物件也能用有层级、可校验、能被 GE 匹配的 `FGameplayTag`。

### 3. 构造函数

```cpp
	// 构造函数：仅转发对象初始化器，无额外初始化
	ATenkaichiTaggedActor(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

- **签名里的 `= FObjectInitializer::Get()` 是默认参数**：调用方不传就用默认的。这是 UE Actor 的**标准写法**——所有 `AActor` 子类都这么声明。
- **实现在 `.cpp`**：函数体只有一行 `Super(ObjectInitializer)` 的初始化列表，什么额外初始化都不做。
- ⚠️ 注意**只有声明没有 `= default` 或内联体**——Lyra 把它放 `.cpp`，照抄。

### 4. GetOwnedGameplayTags（接口实现，核心方法）

```cpp
	//~IGameplayTagAssetInterface 接口开始
	virtual void GetOwnedGameplayTags(FGameplayTagContainer& TagContainer) const override;
	//~IGameplayTagAssetInterface 接口结束
```

- **这是 `IGameplayTagAssetInterface` 接口要求实现的方法**——不实现它就是抽象类，无法实例化。
- **作用**：调用方传进来一个空的 `FGameplayTagContainer`，本 Actor 把自己的标签**追加**进去。GAS / 查询系统通过这个函数"问"这个 Actor："你有哪些标签？"
- **`FGameplayTagContainer& TagContainer`（出参）**：不是返回新容器，而是往调用方已有的容器里 `AppendTags`，这样可以**累积多个来源**的标签。
- **`const`**：查询操作不修改本 Actor 状态。
- **`override`**：明确声明重写接口虚函数（写错了编译器会报错，安全网）。
- **`//~` 分界注释**：Lyra 用 `//~Xxx interface` / `//~End of Xxx interface` 标记"这一段属于哪个接口"。**铁律 36：这类接口分界标记也必须中文化**——所以写成 `//~IGameplayTagAssetInterface 接口开始` / `//~IGameplayTagAssetInterface 接口结束`（接口名是代码标识符，保留原样）。

### 5. CanEditChange（编辑器专属）

```cpp
	//~UObject 接口开始
#if WITH_EDITOR
	virtual bool CanEditChange(const FProperty* InProperty) const override;
#endif
	//~UObject 接口结束
```

- **`#if WITH_EDITOR` 包裹** —— **这是本 `.h` 唯一的预处理条件块**。含义：只有**编辑器构建**才声明这个函数，**打包版本（Shipping）整个不存在**。
- **`WITH_EDITOR` 宏**：UE 的标准宏。编辑器里为 1，打包后为 0。用它可以把"只在编辑器有用的代码"完全排除出发布包（省体积、省性能）。
- **`CanEditChange` 是 `UObject` 的虚函数**：细节面板每次要显示/允许编辑某属性时调用，返回 `false` 就把该项**置灰不可改**。
- **Lyra 用它干什么**：`.cpp` 里判断 `InProperty` 是不是 `AActor::Tags` 那个 FName 数组，是就返回 `false`——**强制美术/策划用 GameplayTag，别去碰那套老的字符串 Tags**，避免两套标签系统混用。
- ⚠️ **别漏了配对的 `#endif`**。

### 6. StaticGameplayTags 字段

```cpp
protected:
	// 与本 Actor 关联的、游戏相关的标签
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Actor)
	FGameplayTagContainer StaticGameplayTags;
```

- **`protected`**：子类可以访问，外部不能直接改——标签应该由本类/子类的逻辑统一提供。
- **`UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Actor)`** 三个说明符：
  - `EditAnywhere`：**在编辑器的细节面板里可编辑**（关卡里摆一个这个 Actor，就能直接在面板配标签）——这是它"静态配置"的实现方式。
  - `BlueprintReadOnly`：蓝图能**读**不能**写**（配合 `protected`，蓝图里也改不了）。
  - `Category=Actor`：细节面板里归到 `Actor` 分类下。
- **`FGameplayTagContainer StaticGameplayTags`**：一组 GameplayTag 容器。
- **名字里的 `Static` 是什么意思**：表示"**在编辑器里静态配置好的、运行时不变**"——区别于运行时动态增删的标签。因为它是静态的，所以 `.cpp` 的 `GetOwnedGameplayTags` 才能简单到只有一行 `AppendTags`。

## 五、几个要记住的点

1. **双继承是核心**：`AActor`（Actor 能力）+ `IGameplayTagAssetInterface`（标签查询能力）。少任何一个都不成立。
2. **`StaticGameplayTags` 是"静态"的**：编辑器配好、运行时只读，所以查询函数只有一行。
3. **`#if WITH_EDITOR` 要配对**：`CanEditChange` 整段在打包版不存在，别漏 `#endif`。
4. **接口分界注释要中文化**（铁律 36）：`//~IGameplayTagAssetInterface 接口开始` / `//~IGameplayTagAssetInterface 接口结束`。
5. **`.h` 零挂起**：三个引擎头，零工程依赖，直接可编译。
