# P05.1-3 AbilityTagRelationshipMapping —— 总 md

## 一、一句话结论

`AbilityTagRelationshipMapping` 是一个 **UDataAsset（数据资产）**，用来在**编辑器里配置"技能标签之间的关系"**：
哪些标签会**阻断（Block）**、**取消（Cancel）**别的技能，以及激活一个技能时**隐式要求/禁止**哪些标签。
运行时通过 3 个查询函数，拿到这些关系。

## 二、为什么需要它（先讲动机）

在 GAS 里，每个技能（Gameplay Ability）都带一堆 GameplayTag（标签）。技能之间不是孤立的，有各种"联动关系"：

1. **阻断（Block）**：我在放"换弹"，你就不能放"开火"。
2. **取消（Cancel）**：我放"翻滚"，会把你正在放的"瞄准"取消掉。
3. **激活要求（Required）**：我放"大招"，隐式要求身上有"满能量"标签。
4. **激活禁止（Blocked）**：我放"冲刺"，隐式禁止"蹲下"状态。

这些关系如果硬编码在 C++ 里，策划每改一次都要程序员改代码。所以 Lyra 的做法是：**把它们做成一个数据资产，策划在编辑器里点一点就能配**。

这就是 `AbilityTagRelationshipMapping` 的价值：**把"技能标签关系"从代码里抽出来，变成可配置的数据**。

## 三、全景（这个类长什么样）

```
LyraAbilityTagRelationshipMapping.h / .cpp
│
├── FLyraAbilityTagRelationship        （USTRUCT，一条"关系"）
│     ├── AbilityTag                   （这条关系是"关于哪个标签"的）
│     ├── AbilityTagsToBlock           （用这个标签的技能，会阻断哪些标签的技能）
│     ├── AbilityTagsToCancel          （用这个标签的技能，会取消哪些标签的技能）
│     ├── ActivationRequiredTags       （有该标签的技能，隐式额外要求这些标签）
│     └── ActivationBlockedTags        （有该标签的技能，隐式额外禁止这些标签）
│
└── ULyraAbilityTagRelationshipMapping （UCLASS，UDataAsset，装一堆"关系"）
      ├── AbilityTagRelationships       （TArray，所有关系条目的列表）
      ├── GetAbilityTagsToBlockAndCancel(...)        → 查"要阻断/取消的标签"
      ├── GetRequiredAndBlockedActivationTags(...)   → 查"激活时隐式要求/禁止的标签"
      └── IsAbilityCancelledByTag(...)               → 查"某技能是否被某动作标签取消"
```

### 核心字段（一条关系里 5 个东西）

| 字段 | 含义 | 举例 |
|------|------|------|
| `AbilityTag` | 这条关系是"关于哪个标签"的 | `Gameplay.Action.Reload`（换弹） |
| `AbilityTagsToBlock` | 用该标签的技能，会**阻断**哪些 | `Gameplay.Action.Fire`（开火） |
| `AbilityTagsToCancel` | 用该标签的技能，会**取消**哪些 | `Gameplay.Action.Aim`（瞄准） |
| `ActivationRequiredTags` | 有该标签的技能，隐式**额外要求**哪些 | `Status.EnergyFull`（满能量） |
| `ActivationBlockedTags` | 有该标签的技能，隐式**额外禁止**哪些 | `Status.Crouching`（蹲下） |

### 3 个查询函数

| 函数 | 干什么 |
|------|--------|
| `GetAbilityTagsToBlockAndCancel` | 给一组技能标签，算出"应该阻断/取消哪些标签" |
| `GetRequiredAndBlockedActivationTags` | 给一组技能标签，算出"激活时额外要求/禁止哪些标签" |
| `IsAbilityCancelledByTag` | 判断某组技能标签，是否被"某个动作标签"取消 |

## 四、为什么它是"叶子"（依赖核实）

读了 `.h` + `.cpp` 全部，依赖如下：

| 依赖 | 类型 | 来源 |
|------|------|------|
| `UDataAsset`（`Engine/DataAsset.h`） | 引擎类 | 引擎自带 |
| `FGameplayTagContainer` / `FGameplayTag`（`GameplayTagContainer.h`） | 引擎类型 | 引擎自带 |

- `.cpp` 里只用了 `AbilityTagRelationships` 数组（自己的字段）+ `FGameplayTagContainer` 的方法（`HasTag`/`AppendTags`/`HasAny`），全是引擎 API。
- **结论：真独立**，不依赖任何 Lyra 自己的类。可以现在教、现在写、现在编译。

## 五、和 P05.1-2 的关系

- P05.1-2 `AbilitySourceInterface` 是**接口**（定义"来源"的抽象）。
- P05.1-3 这个是**数据资产**（定义"标签关系"的配置）。
- 两者**没有互相依赖**，都是 GAS 体系里独立的叶子。只是这个比 P05.1-2 稍大一点（多一个结构体 + 3 个函数）。
