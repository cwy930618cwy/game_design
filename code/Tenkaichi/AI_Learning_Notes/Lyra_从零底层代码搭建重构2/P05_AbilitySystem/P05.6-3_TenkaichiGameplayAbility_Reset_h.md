# P05.6-3 GameplayAbility_Reset —— 教 .h

## 一、本文件要解决什么

把总 md 里"请求重置编排者"这个类落成真实的 `.h` 文件。`TenkaichiGameplayAbility_Reset.h` 定义一个 `UTenkaichiGameplayAbility_Reset` 类——它继承 `UTenkaichiGameplayAbility`（P05.3-B），**只重写 `ActivateAbility`**，并且**在同一个 `.h` 里额外定义一个 `USTRUCT` 消息体 `FTenkaichiPlayerResetMessage`**。

**这个 `.h` 声明了 2 个方法 + 1 个结构体**：
1. **构造函数** —— 设实例化/网络策略 + **给 CDO 加 `GameplayEvent.RequestReset` 触发标签**。
2. **`ActivateAbility`（重写）** —— 重置流程主逻辑（取消技能 → 防取消 → 调角色 `Reset()` → 广播消息 → 收工）。
3. **`FTenkaichiPlayerResetMessage`（USTRUCT）** —— 重置消息体，只有一个字段 `OwnerPlayerState`。

**和前两个技能 `.h` 的三点不同（重点）**：

| 对比项 | Jump | Death | **Reset** |
|--------|------|-------|-----------|
| `UCLASS` 修饰符 | `Abstract` | `Abstract` | **`MinimalAPI`** |
| 导出控制 | 无 | 无 | **`#define UE_API TENKAICHIGAME_API` … `#undef UE_API`** |
| 额外结构体 | 无 | 无 | **`FTenkaichiPlayerResetMessage`（USTRUCT）** |
| 方法数量 | 2 | 5 | **2** |

> **`MinimalAPI` 是啥？** 引擎 `ObjectMacros.h:793/908` 里的 UCLASS 说明符，意思是**这个类只导出"能被引擎反射/序列化用"的最小符号集**，不把全部方法导出给其他模块。
> 配合 `#define UE_API TENKAICHIGAME_API`，只有**显式写了 `UE_API` 前缀的方法**才被导出（本类就是构造函数和 `ActivateAbility` 两个）。这是 Lyra 控制模块导出体积的手法。

> 依赖只有 P05.3-B 基类 + 引擎前置声明，**零挂起可独立编译**。

## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "AbilitySystem/Abilities/TenkaichiGameplayAbility.h"

#include "TenkaichiGameplayAbility_Reset.generated.h"

#define UE_API TENKAICHIGAME_API

class AActor;
class UObject;
struct FGameplayAbilityActorInfo;
struct FGameplayEventData;

/**
 * UTenkaichiGameplayAbility_Reset
 *
 *	用于把玩家快速重置回初始出生状态的技能。
 *	该技能通过 "GameplayEvent.RequestReset" 技能触发标签自动激活（仅服务器）。
 */
UCLASS(MinimalAPI)
class UTenkaichiGameplayAbility_Reset : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()

public:
	UE_API UTenkaichiGameplayAbility_Reset(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

protected:
	
	// 激活时取消其他所有技能、禁止自身被取消，然后调用角色自身的 Reset 并广播重置消息
	UE_API virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
};



// 玩家重置消息：通知外界"某个玩家的 PlayerState 被重置了"
USTRUCT(BlueprintType)
struct FTenkaichiPlayerResetMessage
{
	GENERATED_BODY()

	UPROPERTY(BlueprintReadOnly)
	TObjectPtr<AActor> OwnerPlayerState = nullptr;
};

#undef UE_API
```

## 四、逐段讲解

### 1. 头文件引用（`AbilitySystem/Abilities/` 前缀）

```cpp
#pragma once

#include "AbilitySystem/Abilities/TenkaichiGameplayAbility.h"

#include "TenkaichiGameplayAbility_Reset.generated.h"
```

- ⚠️ **这里和 Jump/Death 不一样！** 那两个写的是 `#include "TenkaichiGameplayAbility.h"`（同目录相对路径，不带前缀），**Reset 写的是带完整前缀的 `"AbilitySystem/Abilities/TenkaichiGameplayAbility.h"`**。
  **Lyra 原文就是这样**，两条路都能编译通过；**一比一还原，照抄 Reset 的写法，别"顺手统一"成 Jump 那种**（铁律 14/17：不擅自改）。
- **`TenkaichiGameplayAbility_Reset.generated.h`** —— 反射生成头，必须放最后（UHT 要求）。

### 2. `#define UE_API TENKAICHIGAME_API`（本文件最大特色）

```cpp
#define UE_API TENKAICHIGAME_API
```

- **`UE_API` 不是引擎关键字**，是 Lyra 自己 `#define` 出来的**临时宏**，纯粹为了少打字 + 方便整文件开关导出。
- **`TENKAICHIGAME_API`** 是 UE 模块系统自动生成的导出宏（模块名大写 + `_API`），加在函数前面表示"这个函数要导出给别的模块用"。
- **为什么这么绕？** 因为类标了 `MinimalAPI` —— 默认**不导出**任何方法。想导出哪个，就在哪个前面手写 `UE_API`。这样比"整个类全导出"更省链接体积。
- ⚠️ **文件末尾一定要 `#undef UE_API`**（Lyra 原样）——防止这个宏泄漏到别的 include 它的文件里，污染全局。
- **本类只有 2 处 `UE_API`**：构造函数 + `ActivateAbility`。

### 3. 前置声明（4 个）

```cpp
class AActor;
class UObject;
struct FGameplayAbilityActorInfo;
struct FGameplayEventData;
```

| 前置声明 | 为什么需要 |
|---------|-----------|
| **`AActor`** | ⚠️ **`FTenkaichiPlayerResetMessage` 里的 `TObjectPtr<AActor> OwnerPlayerState` 用到了**——这是 Jump/Death 没有的 |
| `UObject` | UE 反射系统需要 |
| `FGameplayAbilityActorInfo` | `ActivateAbility` 的参数 |
| `FGameplayEventData` | `ActivateAbility` 的参数（事件触发的技能都有） |

- 前置声明 = 只说"有这个类型"，不引完整定义，**编译更快**。
- ⚠️ **`AActor` 前置声明使 `.h` 保持零挂起**——如果这里改成 `#include "GameFramework/Actor.h"` 也能编，但 Lyra 用前置声明，照抄。

### 4. 类声明与 `MinimalAPI`

```cpp

 *
 *	用于把玩家快速重置回初始出生状态的技能。
 *	该技能通过 "GameplayEvent.RequestReset" 技能触发标签自动激活（仅服务器）。
 */
UCLASS(MinimalAPI)

	GENERATED_BODY()
```

- **`UCLASS(MinimalAPI)`** —— ⚠️ **不是 `Abstract`**！Jump/Death 用 `Abstract`（必须建蓝图子类），Reset 用 `MinimalAPI`（**可以直接实例化使用**，只是不导出全部符号）。
- **文档注释（已中文化）** 明确说了两件事：
  1. 用途：**把玩家快速重置回初始出生状态**
  2. 触发：**通过 `GameplayEvent.RequestReset` 触发标签自动激活（仅服务器）**
- **继承 `UTenkaichiGameplayAbility`（P05.3-B）** —— 拿到激活组管理等能力。

### 5. 构造函数

```cpp
public:
	UE_API UTenkaichiGameplayAbility_Reset(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
```

- ⚠️ **前面有 `UE_API`**（这是和 Jump/Death 构造函数声明的**唯一差别**）。
- **实现在 `.cpp`**，做三件事：
  1. `InstancingPolicy = InstancedPerActor`
  2. `NetExecutionPolicy = ServerInitiated`（服务器权威，和 Death 一致）
  3. **`if (HasAnyFlags(RF_ClassDefaultObject))` → 给 CDO 加 `AbilityTriggers`**，触发标签是 `GameplayEvent_RequestReset`
- ⚠️ `.h` 写默认参数（`= FObjectInitializer::Get()`），`.cpp` 定义处**省略**。

### 6. ActivateAbility（重写，核心）

```cpp
protected:
	
	// 激活时取消其他所有技能、禁止自身被取消，然后调用角色自身的 Reset 并广播重置消息
	UE_API virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
```

- ⚠️ **前面也有 `UE_API`**。
- **`.cpp` 里的六步流程**：
  1. `check(ActorInfo)` —— 断言不为空
  2. `CastChecked<UTenkaichiAbilitySystemComponent>` 取 Tenkaichi ASC
  3. 建豁免容器 `AbilityTypesToIgnore`，加 `Ability_Behavior_SurvivesDeath` 标签
  4. **`ASC->CancelAbilities(nullptr, &AbilityTypesToIgnore, this)`** —— 取消所有技能但豁免带那个标签的
  5. **`SetCanBeCanceled(false)`**
  6. `Cast<ATenkaichiCharacter>(AvatarActor)` → **`LyraChar->Reset()`** → 广播 `GameplayEvent_Reset` 消息 → `Super::ActivateAbility(...)` → `EndAbility(...)`
- **`protected`** —— 引擎内部调用，外部不直接调。

### 7. `FTenkaichiPlayerResetMessage`（USTRUCT，本文件第二个产物）

```cpp
// 玩家重置消息：通知外界"某个玩家的 PlayerState 被重置了"
USTRUCT(BlueprintType)
struct FTenkaichiPlayerResetMessage
{
	GENERATED_BODY()

	UPROPERTY(BlueprintReadOnly)
	TObjectPtr<AActor> OwnerPlayerState = nullptr;
};
```

- ⚠️ **位置在类定义之后、`#undef UE_API` 之前**（Lyra 原样，**照抄别挪**）。
- **`USTRUCT(BlueprintType)`** —— 蓝图可用结构体。**`USTRUCT` 里必须写 `GENERATED_BODY()`**（和 `UCLASS` 一样），否则 UHT 报错。
- **`UPROPERTY(BlueprintReadOnly)`** —— 蓝图只读。`USTRUCT` 的成员要被 UE 反射/GC 识别，**必须加 `UPROPERTY()`**，不能是裸成员。
- **`TObjectPtr<AActor> OwnerPlayerState = nullptr`**：
  - `TObjectPtr` 是 UE5 的**软句柄式对象指针**（替代裸 `AActor*`，支持延迟加载，GC 更安全）。
  - 类型写成 `AActor` 而不是 `APlayerState` —— **Lyra 就是这么写的**（避免引 `PlayerState.h`，靠上面的 `class AActor;` 前置声明就够）。
  - 语义：**谁的 PlayerState 被重置了**，让监听 `GameplayEvent.Reset` 的系统知道是谁。
- **为什么放 `.h` 里不单独建文件**？Lyra 就是这么放的（铁律 10：代码放哪个文件也对应 Lyra，不擅自拆）。

### 8. `#undef UE_API`

```cpp
#undef UE_API
```

- 收尾，撤销第 2 步的宏定义，防止污染其他文件。**Lyra 原样，必须有**。

## 五、几个要记住的点

1. **`UCLASS(MinimalAPI)` 不是 `Abstract`** —— Reset 可直接使用，不强制建蓝图子类。
2. **`#define UE_API TENKAICHIGAME_API` + `#undef UE_API`** 成对出现，中间只有 2 个方法带 `UE_API` 前缀。
3. **include 路径带 `AbilitySystem/Abilities/` 前缀** —— 和 Jump/Death 不同，**照抄别统一**。
4. **`.h` 里定义了 `USTRUCT`** —— `FTenkaichiPlayerResetMessage`，`USTRUCT` 必须有 `GENERATED_BODY()`、成员必须有 `UPROPERTY()`。
5. **前置声明多了 `class AActor;`** —— 因为 `USTRUCT` 里的 `TObjectPtr<AActor>`。
6. **没有 `Category`** —— 本文件没有任何 UFUNCTION/UPROPERTY 带 `Category`，**不用做 Category 前缀替换**（Jump/Death 有，别照搬）。
7. **`.h` 零挂起**。
