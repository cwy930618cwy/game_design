# P05.3-2 GameplayAbility —— 教 .h

## 一、本文件要解决什么

把总 md 里的"技能基类"落成真实的 `.h`。你写 **1 个头文件** `TenkaichiGameplayAbility.h`，放在 `Source/TenkaichiGame/AbilitySystem/Abilities/` 目录下（和 `AbilityCost` 同目录）。

这个 `.h` 定义了四样东西（一个文件里，按 Lyra 原样）：

| 内容 | 是什么 | 一句话 |
|------|--------|--------|
| `ELyraAbilityActivationPolicy` 枚举 | 激活策略 | 技能怎么被触发（按输入/按住/出生） |
| `ELyraAbilityActivationGroup` 枚举 | 激活组 | 技能跟别的技能怎么互斥 |
| `FLyraAbilityMontageFailureMessage` 结构体 | 失败消息 | 技能失败时播放蒙太奇的反馈消息 |
| `ULyraGameplayAbility` 类 | **技能基类** | Lyra 所有具体技能的父类 |

> 本次 `.h` **可独立编译、零挂起**（全是前置声明 + 引擎 include + P06/P12 类 `.h` 已在工程）。挂起发生在下次的 `.cpp`（依赖 P05.2 ASC + P05.5 EffectContext 的函数段）。

## 四、逐段讲解

### 1. 开头的 `#define UE_API` / `#undef UE_API`（本项目特有写法）

```cpp
#define UE_API TENKAICHIGAME_API
...
#undef UE_API
```

- **为什么**：引擎里 `UE_API` 默认是 `ENGINE_API`（引擎导出宏）。但本项目用 UE 源码树外部的代码方式，Lyra 用一个技巧——**把 `UE_API` 临时替换成 `LYRAGAME_API`**，这样这个文件里所有标记 `UE_API` 的函数就都导出了项目模块的 API。
- 替换成我们项目：`LYRAGAME_API` → `TENKAICHIGAME_API`。
- **`#undef UE_API` 必须在文件末尾**：还原回引擎默认，避免污染下一个 include 该头的文件。
- 这就是为什么每个函数/方法前都加 `UE_API`——本文件里它其实 = `TENKAICHIGAME_API`。

### 2. 两个枚举（技能怎么触发 + 怎么互斥）

```cpp
UENUM(BlueprintType)
enum class ELyraAbilityActivationPolicy : uint8
{
	OnInputTriggered,      // 输入触发时激活
	WhileInputActive,      // 输入按住时持续尝试
	OnSpawn                // 出生/分配化身时激活
};

UENUM(BlueprintType)
enum class ELyraAbilityActivationGroup : uint8
{
	Independent,              // 独立运行
	Exclusive_Replaceable,    // 会被其他排他技能替换
	Exclusive_Blocking,      // 阻塞其他排他技能
	MAX	UMETA(Hidden)        // 占位，蓝图隐藏
};
```

| 要点 | 含义 |
|------|------|
| `BlueprintType` | 枚举可在蓝图里当类型用（蓝图节点选枚举值） |
| `: uint8` | 底层用 1 字节存，省内存 |
| `MAX UMETA(Hidden)` | 内部占位值（= 前面数量），蓝图隐藏。用于"枚举上限"判断 |

- **`ActivationPolicy`（激活策略）**：决定技能"什么时候尝试激活"——输入按下（`OnInputTriggered`）、按住不放（`WhileInputActive`）、出生就自动开（`OnSpawn`）。
- **`ActivationGroup`（激活组）**：决定技能跟其他技能怎么互斥——`Independent` 自己玩；`Exclusive_Replaceable` 会被排他技能顶掉；`Exclusive_Blocking` 会顶掉别人。这是 Lyra 实现"换弹时不能射击"这类规则的机制。

### 3. 结构体 `FTenkaichiAbilityMontageFailureMessage`（失败消息）

```cpp
USTRUCT(BlueprintType)
struct FTenkaichiAbilityMontageFailureMessage
{
	TObjectPtr<APlayerController> PlayerController;  // 失败的玩家控制器
	TObjectPtr<AActor> AvatarActor;                   // 失败的化身
	FGameplayTagContainer FailureTags;                // 失败原因标签集合
	TObjectPtr<UAnimMontage> FailureMontage;          // 要播放的失败蒙太奇
};
```

- 一个**结构体**（不是类），描述"技能失败时，要向谁、以什么理由、播放什么动画"。
- 通过 `UGameplayMessageSubsystem`（消息总线，P01 已教）广播出去，UI/表现层收到后播放对应反馈。`FailureTags` 是失败原因（比如"没弹药"标签），`FailureMontage` 是对应要播的动画。
- `TObjectPtr<>` 是 UE5 的智能指针包装（比裸指针更安全，支持引擎资源跟踪）。`FGameplayTagContainer` 是标签集合（第 0 步已教）。

### 4. 类声明 + friend（权限）

```cpp
UCLASS(MinimalAPI, Abstract, HideCategories = Input, Meta = (ShortTooltip = "..."))
class UTenkaichiGameplayAbility : public UGameplayAbility
{
	GENERATED_BODY()
	friend class UTenkaichiAbilitySystemComponent;
```

| 项 | 含义 |
|----|------|
| `MinimalAPI` | 只导出类名级别的最小 API，加快编译 |
| `Abstract` | 抽象类：不能直接实例化，只能被子类继承（具体技能继承它） |
| `HideCategories = Input` | 编辑器属性面板里隐藏 Input 分类 |
| `Meta = (ShortTooltip = "...")` | 编辑器鼠标悬停的简短提示 |
| 继承 `UGameplayAbility` | **引擎 GAS 的技能基类**——我们的基类再套一层，加 Lyra 定制逻辑 |
| `friend class UTenkaichiAbilitySystemComponent;` | 让 ASC 成为友元，可以访问本类的私有/保护成员（ASC 要操作技能的激活组等） |

> **继承链**：`UGameplayAbility`（引擎）→ `UTenkaichiGameplayAbility`（本项目基类）→ 各种具体技能（蓝图/C++）。

### 6. 5 个 Getter（从 ActorInfo 快速取东西）

```cpp
UTenkaichiAbilitySystemComponent* GetTenkaichiAbilitySystemComponentFromActorInfo() const;  // 能力组件
ATenkaichiPlayerController* GetTenkaichiPlayerControllerFromActorInfo() const;              // 玩家控制器
AController* GetControllerFromActorInfo() const;                                            // 控制器（兼容）
ATenkaichiCharacter* GetTenkaichiCharacterFromActorInfo() const;                            // 角色
UTenkaichiHeroComponent* GetHeroComponentFromActorInfo() const;                             // Hero 组件
```

- **`ActorInfo`** = `FGameplayAbilityActorInfo`，GAS 给每个技能提供的"运行时上下文"（谁拥有、谁化身、谁控制）。
- 这 5 个 getter 是**常用快捷方式**：技能里要拿角色/控制器/组件时，直接调这些，不用自己翻 ActorInfo。
- 返回类型都是项目定制类型（`UTenkaichiAbilitySystemComponent`/`ATenkaichiCharacter`/`UTenkaichiHeroComponent`...），所以技能代码里能直接 cast 成项目类型用。
- `GetControllerFromActorInfo` 兼容性最强（还处理非玩家控制器场景），是 P05.3-A `AbilityCost` 里用的那个。

### 7. 激活组切换 + 相机模式

```cpp
bool CanChangeActivationGroup(ELyraAbilityActivationGroup NewGroup) const;  // 能否切组
bool ChangeActivationGroup(ELyraAbilityActivationGroup NewGroup);           // 切组
void SetCameraMode(TSubclassOf<UTenkaichiCameraMode> CameraMode);           // 设相机
void ClearCameraMode();                                                      // 清相机
```

- **`CanChangeActivationGroup` / `ChangeActivationGroup`**：技能运行时切换激活组（比如从"独立"切到"排他阻塞"），配合 ASC 的激活组管理。带 `BlueprintPure = false` + `ExpandBoolAsExecs = "ReturnValue"`（蓝图里布尔返回值变成执行分支引脚）。
- **`SetCameraMode` / `ClearCameraMode`**：技能可以临时切相机（比如瞄准时切换第三人称相机模式）。`UTenkaichiCameraMode` 是 P04 已教类。技能结束 `EndAbility` 会自动 `ClearCameraMode`。

### 8. 蓝图可覆盖的反馈事件

```cpp
void OnAbilityFailedToActivate(const FGameplayTagContainer& FailedReason) const;  // 失败总入口（内联）
virtual void NativeOnAbilityFailedToActivate(...) const;                          // 原生回调（C++ 覆盖）
UFUNCTION(BlueprintImplementableEvent) void ScriptOnAbilityFailedToActivate(...);  // 蓝图事件
```

- `OnAbilityFailedToActivate`（`.h` 内联）**同时调用** C++ 版本和蓝图版本——既让 C++ 处理，又给蓝图留钩子。
- `NativeOnAbilityFailedToActivate`：C++ 里 override 用。
- `ScriptOnAbilityFailedToActivate`：`BlueprintImplementableEvent`，蓝图层可以"实现"它。

同理还有 `K2_OnAbilityAdded` / `K2_OnAbilityRemoved` / `K2_OnPawnAvatarSet`（三个蓝图事件），分别在**技能被授予/移除/赋予化身**时给蓝图发通知。

### 9. 核心：override 引擎 GAS 接口

```cpp
CanActivateAbility   // 能否激活（加激活组互斥检查）
SetCanBeCanceled      // 能否取消（排他可替换组不能阻止取消）
OnGiveAbility         // 授予时（触发 K2_OnAbilityAdded + 出生激活）
OnRemoveAbility       // 移除时
ActivateAbility       // 激活
EndAbility            // 结束（先清相机）
CheckCost             // 检查代价（+ 额外 AdditionalCosts）
ApplyCost             // 施加代价（+ 额外 AdditionalCosts，可只在命中时扣）
MakeEffectContext     // 构造效果上下文（注入能力来源）
ApplyAbilityTagsToGameplayEffectSpec  // 把物理材质标签并入效果
DoesAbilitySatisfyTagRequirements     // 标签要求检查（处理死亡/展开）
```

- 这些都是**引擎 `UGameplayAbility` 的虚函数**，Lyra override 它们做定制。
- 关键定制：
  - `CanActivateAbility`：多加了**激活组互斥**判断（技能被同组阻塞就不能激活）。
  - `CheckCost` / `ApplyCost`：除了引擎自己的消耗，还循环调用 `AdditionalCosts`（P05.3-A 的 `AbilityCost`）——**这就是 AbilityCost 被挂上来的地方**。
  - `ApplyCost` 里还有"只在命中时扣"的逻辑（`DetermineIfAbilityHitTarget` 判断有没有打中目标）。
  - `MakeEffectContext`：给效果上下文注入**能力来源**（武器等）。
  - `DoesAbilitySatisfyTagRequirements`：**重写了引擎的标签检查**，处理"死亡时禁止激活"+"用 ASC 展开额外标签要求"。
- 这些 `override` 的**实现都在 `.cpp`**（下次教）。其中依赖 ASC/EffectContext 的函数段会标注 ⚠️ 挂起。

## 五、几个要记住的点

1. **`#define UE_API TENKAICHIGAME_API`**：本文件特有写法，把 UE_API 临时替换成项目导出宏，末尾 `#undef` 还原。
2. **两个枚举**：`ActivationPolicy`（怎么触发）+ `ActivationGroup`（怎么互斥），是技能配置的骨架。
3. **继承 `UGameplayAbility`**：引擎技能基类 → 本项目基类 → 具体技能。本类是 Lyra 技能体系的根。
4. **`friend class UTenkaichiAbilitySystemComponent`**：ASC 能访问技能私有成员。
5. **5 个 Getter**：从 ActorInfo 快速拿项目定制类型（ASC/控制器/角色/Hero）。
6. **`CheckCost`/`ApplyCost` 挂 `AdditionalCosts`**：这就是 P05.3-A `AbilityCost` 的接入点。
7. **override 一堆引擎虚函数**：实现全在 `.cpp`（下次教），依赖 ASC/EffectContext 的段会挂起。
8. **接口分界标记中文化**：`//~UGameplayAbility 接口开始/结束`。
9. **`.h` 零挂起**：全前置声明，可独立编译。
