### 3.1 基类 `TenkaichiAbilityCost.h`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "CoreMinimal.h"
#include "GameplayAbilitySpec.h"
#include "Abilities/GameplayAbility.h"
#include "TenkaichiAbilityCost.generated.h"

class UTenkaichiGameplayAbility;

/** 技能的代价抽象基类（比如弹药、充能次数） */
UCLASS(MinimalAPI, DefaultToInstanced, EditInlineNew, Abstract)
class UTenkaichiAbilityCost : public UObject
{
	GENERATED_BODY()

public:
	UTenkaichiAbilityCost()
	{
	}

	// 检查这个代价我们是否付得起。失败原因标签可加入 OptionalRelevantTags（若非空），
	// 其他地方可据此给出用户反馈（例如武器没弹药时播放咔哒声）。
	// 进入时 Ability 和 ActorInfo 保证非空，但 OptionalRelevantTags 可能是空指针。
	// @return true 表示付得起，false 表示付不起。
	virtual bool CheckCost(const UTenkaichiGameplayAbility* Ability, const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, FGameplayTagContainer* OptionalRelevantTags) const
	{
		return true;
	}

	// 把技能的代价施加到目标身上。
	// 注意：你的实现不需要检查 ShouldOnlyApplyCostOnHit()，调用方会替你检查。
	// 进入时 Ability 和 ActorInfo 保证非空。
	virtual void ApplyCost(const UTenkaichiGameplayAbility* Ability, const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo)
	{
	}

	// 若为 true，这个代价只在技能命中成功时才施加
	bool ShouldOnlyApplyCostOnHit() const { return bOnlyApplyCostOnHit; }

protected:
	// 若为 true，这个代价只在技能命中成功时才施加
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Costs)
	bool bOnlyApplyCostOnHit = false;
};
```

## 四、逐段讲解

### 1. 基类 `UTenkaichiAbilityCost`（为什么是"抽象基类"）

```cpp
UCLASS(MinimalAPI, DefaultToInstanced, EditInlineNew, Abstract)
class UTenkaichiAbilityCost : public UObject
```

四个类说明符各管一件事：

| 说明符 | 含义 |
|--------|------|
| `MinimalAPI` | 只导出最小 API（`TENKAICHIGAME_API` 级别的类名导出），加快编译。因为这类只在项目内用，不需要完整导出所有成员 |
| `DefaultToInstanced` | 默认"实例化"。配合下面的 `EditInlineNew`：当它作为另一个 UPROPERTY 被编辑时，默认在编辑器里**直接内联编辑一个实例**，而不是引用外部资产 |
| `EditInlineNew` | 允许在属性面板里**内联新建**这个类的实例（而不只是引用已有资产）。`AbilityCost` 是配在 `GameplayAbility` 资产里的，需要能直接在资产里加 |
| `Abstract` | **抽象类**：不能直接实例化，只能被继承。子类（三个实现）才能用 |

> 继承 `UObject`（不是 `UDataAsset`）——它不是"数据资产"，而是"挂在技能上的配置对象"，用 `EditInlineNew` 直接嵌在技能资产里。

**两个虚函数 = 技能消耗的"检查 + 扣除"两拍**：

```cpp
virtual bool CheckCost(...) const { return true; }   // 拍一：付得起吗？默认 true（不检查）
virtual void ApplyCost(...) { }                        // 拍二：扣！默认什么都不扣
```

- `CheckCost`：**激活前**问"钱够不够/弹药够不够"，返回 `bool`。基类默认 `return true`（免费技能）。
- `ApplyCost`：**激活后**把代价扣掉。基类默认空（无消耗）。
- 子类 override 这两个方法，实现各自的"检查/扣除"逻辑（`.cpp` 里）。
- 这俩都带 `FGameplayAbilitySpecHandle` / `FGameplayAbilityActorInfo` / `FGameplayAbilityActivationInfo` 这些 **GAS 技能上下文**参数——告诉代价计算器"这次是哪个技能、谁在施放、激活到哪一步了"。

**`ShouldOnlyApplyCostOnHit` + `bOnlyApplyCostOnHit`**：

```cpp
bool ShouldOnlyApplyCostOnHit() const { return bOnlyApplyCostOnHit; }

UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Costs)
bool bOnlyApplyCostOnHit = false;
```

- `bOnlyApplyCostOnHit`：一个可配置的 bool（编辑器里勾选）——"这个代价只在命中成功时才扣"（比如"射出去没打中也得耗弹"还是"打中才算耗"）。
- `ShouldOnlyApplyCostOnHit()`：**只读访问器**，返回那个 bool。供调用方查询，决定要不要在命中时才 ApplyCost。
- `Category=Costs`：编辑器属性面板里的分组名。

> 基类 `.h` 把两个虚函数和访问器都**内联**实现了，所以**没有 `.cpp` 文件**——一个头文件就够。

### 2. 三个子类（共同骨架）

三个子类结构几乎一样，都：

```cpp
UCLASS(meta=(DisplayName="Inventory Item"))   // 各子类 DisplayName 不同
class UTenkaichiAbilityCost_XXX : public UTenkaichiAbilityCost
```

- `UCLASS(meta=(DisplayName="..."))`：编辑器里显示的名字（`Inventory Item` / `Item Tag Stack` / `Player Tag Stack`）。这样用户加代价时看到的是友好名字。
- 继承 `UTenkaichiAbilityCost`（基类）。
- 声明构造函数 `UTenkaichiAbilityCost_XXX();`（实现在 `.cpp`）。
- `override` 基类的两个虚函数（实现也在 `.cpp`，下次教）。

**子类各自带的"消耗参数"（protected 字段）**：

| 子类 | 字段 | 含义 |
|------|------|------|
| `InventoryItem` | `Quantity`（`FScalableFloat`） | 要消耗**多少数量**（按技能等级缩放） |
| | `ItemDefinition`（`TSubclassOf<UTenkaichiInventoryItemDefinition>`） | 要消耗**哪个物品**（物品定义类） |
| `ItemTagStack` | `Quantity`（`FScalableFloat`） | 要消耗**多少数量** |
| | `Tag`（`FGameplayTag`） | 要消耗**哪个标签** |
| | `FailureTag`（`FGameplayTag`） | 付不起时发回的**反馈标签** |
| `PlayerTagStack` | `Quantity`（`FScalableFloat`） | 要消耗**多少数量** |
| | `Tag`（`FGameplayTag`） | 要消耗**哪个标签** |

> 差异就三个点：
> - `InventoryItem` 用 `TSubclassOf`（指向物品定义类），另两个用 `FGameplayTag`（指向标签）。
> - `ItemTagStack` 多一个 `FailureTag`（付不起时的反馈）。
> - `InventoryItem` 的 Category 是 `AbilityCost`，另两个是 `Costs`（Lyra 源码原样，不统一）。

**`FScalableFloat`（可缩放浮点）**：数值+一张随等级变化的曲线。`Quantity` 用它能实现"技能 1 级耗 1 发、5 级耗 2 发"这类**随等级变化的消耗**。`.cpp` 里用 `GetValueAtLevel` 取某等级下的实际值。

**`TSubclassOf<UTenkaichiInventoryItemDefinition>`**：限定类型的"类引用"（BlueprintReadOnly 下拉只能选这个类或其子类）。注意 `UTenkaichiInventoryItemDefinition` 是**阶段六 Inventory** 的类，现在**只有前置声明** `class UTenkaichiInventoryItemDefinition;`（不阻塞编译，因为 `.h` 里只用了它的指针/类引用，没调用它的成员）。

### 3. 头文件 include 与前置声明

```cpp
#include "CoreMinimal.h"          // 基类：UE 核心（基类用 FGameplayTagContainer 需要）
#include "GameplayAbilitySpec.h"  // 基类：FGameplayAbilitySpecHandle
#include "Abilities/GameplayAbility.h" // 基类：FGameplayAbilityActorInfo / ActivationInfo / FGameplayTagContainer
#include "GameplayTagContainer.h"   // 子类：FGameplayTag
#include "TenkaichiAbilityCost.h"   // 子类：继承基类（⚠️ 铁律 24：Lyra 源码是 "LyraAbilityCost.h"，前缀必须换成 Tenkaichi）
#include "ScalableFloat.h"          // 子类：FScalableFloat
#include "Templates/SubclassOf.h"   // InventoryItem：TSubclassOf
```

- 基类 include 引擎 GAS 头（`GameplayAbilitySpec.h` + `Abilities/GameplayAbility.h`），因为要用 `FGameplayAbilitySpecHandle` / `FGameplayAbilityActorInfo` / `FGameplayAbilityActivationInfo` / `FGameplayTagContainer`。
- 子类 include `GameplayTagContainer.h`（`FGameplayTag`）+ `ScalableFloat.h`（`FScalableFloat`）+ 基类头。
- 各文件最末 `#include "Xxx.generated.h"`（UHT 生成，必须放最后）。

> ⚠️ **易错点（2026-10-27 实测踩坑）**：三个子类的 `#include "TenkaichiAbilityCost.h"` 是**最容易漏改的一行**。
> Lyra 源码写的是 `#include "LyraAbilityCost.h"`，按铁律 24 必须机械替换成 `TenkaichiAbilityCost.h`——
> 因为**工程里根本没有 `LyraAbilityCost.h` 这个文件**，漏改会直接编译报错（找不到头文件）。
> 同理适用于所有 `#include "LyraXxx.h"` 形式的**项目内头文件引用**（引擎头 `GameplayTagContainer.h` 之类不含 `Lyra` 前缀，不受影响）。

**前置声明**（`class UTenkaichiGameplayAbility;` 等）：
- 基类前置声明 `UTenkaichiGameplayAbility`（P05.3 技能基类，还没教，但 `.h` 只用了它的**指针**，前置声明就够）。
- 子类前置声明 `UTenkaichiInventoryItemDefinition`（阶段六）等——同样只用了指针/类引用，不需要完整定义。
- 这些前置声明让 `.h` **能独立编译**，真正需要完整定义时才在 `.cpp` include。

## 五、几个要记住的点

1. **`Abstract` 抽象基类**：不能实例化，只能被三个子类继承；两个虚函数 `CheckCost`/`ApplyCost` 是"检查 + 扣除"两拍。
2. **`EditInlineNew` + `DefaultToInstanced`**：代价对象"内联嵌在技能资产里"编辑，而不是独立引用资产。
3. **基类纯 `.h` 无 `.cpp`**：方法全内联。
4. **`FScalableFloat`**：可随等级缩放的数值——技能消耗量的标准类型。
5. **`TSubclassOf`**：限定类型的类引用，下拉只能选该类型子类。
6. **前置声明保编译**：`UTenkaichiGameplayAbility`（P05）、`UTenkaichiInventoryItemDefinition`（阶段六）都没教，但 `.h` 只碰指针，前置声明即可独立编译。
7. **接口分界标记中文化**：`//~UTenkaichiAbilityCost 接口开始/结束`。
