## 四、逐段讲解

### 1. 挂起的 include

```cpp
#if 0  // ⚠️ 挂起：依赖 P05.5 FLyraGameplayEffectContext
#include "TenkaichiGameplayEffectContext.h"
#endif
```

- 原 Lyra 源码这里直接 `#include "LyraGameplayEffectContext.h"`。
- 但工程还没有 `TenkaichiGameplayEffectContext.h`（P05.5 未教），直接 include 会编译报错。
- 按死结处理铁律：**代码照写、注释挂起**，用 `#if 0 ... #endif` 包住 include，等 P05.5 就位放开。

### 2. UE_INLINE_GENERATED_CPP_BY_NAME

```cpp
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiAbilitySystemGlobals)
```

- UHT 生成内联代码的宏，**`#if 0` 之外**，必须无条件保留（U 类反射依赖它）。
- 参数是类名本身（不带 `.h` 后缀）。

### 3. 构造函数（不挂起）

```cpp
struct FGameplayEffectContext;

UTenkaichiAbilitySystemGlobals::UTenkaichiAbilitySystemGlobals(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
}
```

- `struct FGameplayEffectContext;` 前置声明：源码自带，配合上面的挂起段。
- 构造函数带 `FObjectInitializer`，转发给 `Super`。空函数体。
- 对应 `.h` 里的 `GENERATED_UCLASS_BODY()`。

## 五、几个要记住的点

1. **构造函数不挂**：它只依赖引擎基类，正常编译，证明"挂起要精准到依赖处"。
2. **include 也要挂**：`AllocGameplayEffectContext` 引用了 EffectContext 类型，其 include 一并 `#if 0`。
3. **UE_INLINE_GENERATED_CPP_BY_NAME 永不挂**：U 类反射必需。
