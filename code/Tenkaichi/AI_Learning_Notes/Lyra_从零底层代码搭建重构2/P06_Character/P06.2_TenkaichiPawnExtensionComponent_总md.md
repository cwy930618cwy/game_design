## 一、为什么需要 PawnExtension？（解决什么问题）

现在我们有 `TeamSubsystem`/`TeamStatics`（管队伍）、`PawnData`（管角色数据）、`GameplayTags`（管初始化标签）——**但这些都各管各的，没有谁负责"把角色组装起来"**。

一个 Pawn（角色）要正常跑起来，需要一堆组件按顺序就位：
1. 先**出生**（Spawned）
2. 拿到**角色数据**（DataAvailable，`PawnData`）
3. 数据**初始化**（DataInitialized）
4. 全部就绪 → **可游玩**（GameplayReady）

**PawnExtension 就是那个"总调度器"**——它通过**初始化状态机**（`InitState_*` 那套 GameplayTag），协调 Pawn 上所有组件按顺序初始化，同时管着**能力系统组件（ASC）的挂载**（pawn 成为能力系统的 avatar）。

> 一句话：**PawnExtension = 角色的"开机引导程序"**，决定角色怎么一步步被装配好、以及能力系统何时接入。

## 四、挂起说明（铁律 33/34/35）

**`PawnExtension.cpp` 需 `#if 0` 挂起**，原因：

- `.cpp` include `AbilitySystem/TenkaichiAbilitySystemComponent.h`（GAS 头文件）——**不存在**
- `.cpp` 大量硬调用 ASC 方法（`InitAbilityActorInfo` / `CancelAbilities` / `ClearAbilityInput` / `RemoveAllGameplayCues` / `SetAvatarActor` / `ClearActorInfo` / `RefreshAbilityActorInfo` / `SetTagRelationshipMapping`）——依赖 GAS 断点

`.h` 里 `UTenkaichiAbilitySystemComponent` 只是**前置声明**（成员是指针），不阻塞编译 → **`.h` 可独立编译，不挂起**。

> **结论**：`.cpp` 整体 `#if 0` 挂起。等 **GAS 核心（UTenkaichiAbilitySystemComponent）就位**后放开。
