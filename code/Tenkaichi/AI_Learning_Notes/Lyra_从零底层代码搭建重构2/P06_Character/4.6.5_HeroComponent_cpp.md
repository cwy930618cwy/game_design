## 〇、文件全景（这段 `.cpp` 里有什么）

`.cpp` 实现 `.h` 里声明的全部方法，按职责分 5 组：

1. **常量 + 构造函数** —— `LookYawRate`/`LookPitchRate`、`NAME_*`、构造函数
2. **初始化状态机** —— `OnRegister`/`BeginPlay`/`EndPlay`/`CanChangeInitState`/`HandleChangeInitState`/`OnActorInitStateChanged`/`CheckDefaultInitialization`
3. **输入绑定** —— `InitializePlayerInput`/`AddAdditionalInputConfig`/`RemoveAdditionalInputConfig`/`IsReadyToBindInputs`
4. **输入处理回调** —— `Input_AbilityInputTagPressed`/`Released`、`Input_Move`/`LookMouse`/`LookStick`/`Crouch`/`AutoRun`
5. **相机** —— `DetermineCameraMode`/`SetAbilityCameraMode`/`ClearAbilityCameraMode`

**初始化顺序核心**（先建立直觉，讲解里反复出现）：
```
BeginPlay → 自己进入 Spawned → 等 PawnExtension 到 DataInitialized
→ HandleChangeInitState：初始化能力系统(PawnExtension) + 相机 + 输入
→ 广播 NAME_BindInputsNow → 玩家可操作
```

---## 三、状态机：CanChangeInitState + HandleChangeInitState（第 76~184 行）

```cpp
// 状态机核心：判断能否从当前状态进入目标状态
bool UTenkaichiHeroComponent::CanChangeInitState(UGameFrameworkComponentManager* Manager, FGameplayTag CurrentState, FGameplayTag DesiredState) const
{
	check(Manager);

	APawn* Pawn = GetPawn<APawn>();

	if (!CurrentState.IsValid() && DesiredState == TenkaichiGameplayTags::InitState_Spawned)
	{
		// 只要在合法 Pawn 上，就算作已生成
		if (Pawn)
		{
			return true;
		}
	}
	else if (CurrentState == TenkaichiGameplayTags::InitState_Spawned && DesiredState == TenkaichiGameplayTags::InitState_DataAvailable)
	{
		// 玩家状态是必需的。
		if (!GetPlayerState<ATenkaichiPlayerState>())
		{
			return false;
		}

		// 如果我们是权威端或自主端，需要等一个已配对 PlayerState 所有权的控制器。
		if (Pawn->GetLocalRole() != ROLE_SimulatedProxy)
		{
			AController* Controller = GetController<AController>();

			const bool bHasControllerPairedWithPS = (Controller != nullptr) && \
				(Controller->PlayerState != nullptr) && \
				(Controller->PlayerState->GetOwner() == Controller);

			if (!bHasControllerPairedWithPS)
			{
				return false;
			}
		}

		const bool bIsLocallyControlled = Pawn->IsLocallyControlled();
		const bool bIsBot = Pawn->IsBotControlled();

		if (bIsLocallyControlled && !bIsBot)
		{
			ATenkaichiPlayerController* TenkaichiPC = GetController<ATenkaichiPlayerController>();

			// 本地控制时需要输入组件和本地玩家。
			if (!Pawn->InputComponent || !TenkaichiPC || !TenkaichiPC->GetLocalPlayer())
			{
				return false;
			}
		}

		return true;
	}
	else if (CurrentState == TenkaichiGameplayTags::InitState_DataAvailable && DesiredState == TenkaichiGameplayTags::InitState_DataInitialized)
	{
		// 等玩家状态和扩展组件
		ATenkaichiPlayerState* TenkaichiPS = GetPlayerState<ATenkaichiPlayerState>();

		return TenkaichiPS && Manager->HasFeatureReachedInitState(Pawn, UTenkaichiPawnExtensionComponent::NAME_ActorFeatureName, TenkaichiGameplayTags::InitState_DataInitialized);
	}
	else if (CurrentState == TenkaichiGameplayTags::InitState_DataInitialized && DesiredState == TenkaichiGameplayTags::InitState_GameplayReady)
	{
		// TODO 添加能力初始化检查？
		return true;
	}

	return false;
}
```

**讲解**（状态机四段，对比 4.7 PawnExtension 的 `CanChangeInitState`）：

| 状态转移 | Hero 的条件 | 和 PawnExtension 的区别 |
|---------|------------|----------------------|
| `无 → Spawned` | 在合法 Pawn 上 | 相同 |
| `Spawned → DataAvailable` | ①有 PlayerState；②权威/自主端要控制器已配对 PS；③本地控制非 bot 要有输入组件+PC+LocalPlayer | **多了输入/PC/LocalPlayer 检查**（操控中枢要能操作） |
| `DataAvailable → DataInitialized` | 有 PlayerState **且 PawnExtension 已到 DataInitialized** | **等 PawnExtension 先到**（4.7 教过） |
| `DataInitialized → GameplayReady` | 直接 true | 相同 |

> 核心：**Hero 等 PawnExtension**（`HasFeatureReachedInitState` 检查 `PawnExtension` 特性），所以 PawnExtension 先初始化，Hero 后接输入/相机。这就是"装配（PawnExtension）→ 操控（Hero）"的顺序保证。

```cpp
// 状态改变时的处理：DataAvailable→DataInitialized 时初始化能力系统/输入/相机
void UTenkaichiHeroComponent::HandleChangeInitState(UGameFrameworkComponentManager* Manager, FGameplayTag CurrentState, FGameplayTag DesiredState)
{
	if (CurrentState == TenkaichiGameplayTags::InitState_DataAvailable && DesiredState == TenkaichiGameplayTags::InitState_DataInitialized)
	{
		APawn* Pawn = GetPawn<APawn>();
		ATenkaichiPlayerState* TenkaichiPS = GetPlayerState<ATenkaichiPlayerState>();
		if (!ensure(Pawn && TenkaichiPS))
		{
			return;
		}

		const UTenkaichiPawnData* PawnData = nullptr;

		if (UTenkaichiPawnExtensionComponent* PawnExtComp = UTenkaichiPawnExtensionComponent::FindPawnExtensionComponent(Pawn))
		{
			PawnData = PawnExtComp->GetPawnData<UTenkaichiPawnData>();

			// PlayerState 持有玩家的持久数据（跨死亡、跨多个 Pawn 存活的状态）。
			// 能力系统组件和属性集挂在 PlayerState 上。
			PawnExtComp->InitializeAbilitySystem(TenkaichiPS->GetTenkaichiAbilitySystemComponent(), TenkaichiPS);
		}

		if (ATenkaichiPlayerController* TenkaichiPC = GetController<ATenkaichiPlayerController>())
		{
			if (Pawn->InputComponent != nullptr)
			{
				InitializePlayerInput(Pawn->InputComponent);
			}
		}

		// 为所有 Pawn 挂上相机委托（之后可能观战）
		if (PawnData)
		{
			if (UTenkaichiCameraComponent* CameraComponent = UTenkaichiCameraComponent::FindCameraComponent(Pawn))
			{
				CameraComponent->DetermineCameraModeDelegate.BindUObject(this, &ThisClass::DetermineCameraMode);
			}
		}
	}
}
```

**讲解**：这是 `.cpp` 里**信息量最大**的函数——状态一进入 `DataInitialized`，一次性做三件事：

1. **初始化能力系统**：通过 PawnExtension 的 `InitializeAbilitySystem` 把 PlayerState 上的 ASC 挂到本 Pawn（`GetTenkaichiAbilitySystemComponent()` 来自 PlayerState）。`PawnData` 从 PawnExtension 里取（`GetPawnData<UTenkaichiPawnData>()`）。
2. **初始化输入**：有 PC + 输入组件时，调 `InitializePlayerInput`（绑定移动/视角/蹲伏/技能输入）。
3. **挂相机委托**：有 PawnData + 相机组件时，把 `DetermineCameraMode` 绑定到相机的 `DetermineCameraModeDelegate`（相机问"用哪个模式"时回调本函数）。

> 这三个正好对应 Hero 的三职责：**能力（ASC）+ 输入（Input）+ 相机（Camera）**。全部靠前置函数完成，本函数只做"接线"。

void UTenkaichiHeroComponent::OnActorInitStateChanged(const FActorInitStateChangedParams& Params)

**讲解**：Hero 在 `BeginPlay` 里通过 `BindOnActorInitStateChanged(PawnExtension 的 NAME, ...)` 监听 PawnExtension。当 PawnExtension 状态变成 `DataInitialized` 时触发本函数，Hero 再调 `CheckDefaultInitialization()` 推进自己的状态链。**这是"Hero 等 PawnExtension"的运行时触发点**（配合 `CanChangeInitState` 里的 `HasFeatureReachedInitState` 检查）。

```cpp
// BeginPlay：监听 PawnExtension 的状态变化，然后推进到 Spawned 状态
void UTenkaichiHeroComponent::BeginPlay()
{
	Super::BeginPlay();

	// 监听 pawn 扩展组件的状态变化
	BindOnActorInitStateChanged(UTenkaichiPawnExtensionComponent::NAME_ActorFeatureName, FGameplayTag(), false);

	// 通知状态管理器"已生成"，然后继续默认初始化
	ensure(TryToChangeInitState(TenkaichiGameplayTags::InitState_Spawned));
	CheckDefaultInitialization();
}

// EndPlay：注销初始化状态，再调父类
void UTenkaichiHeroComponent::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
	UnregisterInitStateFeature();

	Super::EndPlay(EndPlayReason);
}
```

**讲解**：
- `BeginPlay`：**只监听 PawnExtension**（`BindOnActorInitStateChanged` 指定它的 `NAME_ActorFeatureName`），然后把自己推到 `Spawned`，再推进默认初始化。注意——Hero 不监听"所有特性"（`NAME_None`），只盯 PawnExtension，因为它只关心装配进度。
- `EndPlay`：`UnregisterInitStateFeature()` 从状态机注销，和 PawnExtension 对称（PawnExtension 还多一步 `UninitializeAbilitySystem`，Hero 不需要，因为 ASC 的初始化/反初始化都由 PawnExtension 管）。

```cpp
// 初始化玩家输入：清空旧映射，绑定 PawnData 里的输入配置
void UTenkaichiHeroComponent::InitializePlayerInput(UInputComponent* PlayerInputComponent)
{
	check(PlayerInputComponent);

	const APawn* Pawn = GetPawn<APawn>();
	if (!Pawn)
	{
		return;
	}

	const APlayerController* PC = GetController<APlayerController>();
	check(PC);

	const UTenkaichiLocalPlayer* LP = Cast<UTenkaichiLocalPlayer>(PC->GetLocalPlayer());
	check(LP);

	UEnhancedInputLocalPlayerSubsystem* Subsystem = LP->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>();
	check(Subsystem);

	Subsystem->ClearAllMappings();
	//...（下面第 2~4 段接续）
}
```

**讲解（第 1 段：拿齐四件套）**：
- `check(PlayerInputComponent)`——断言输入组件存在
- `GetPawn<APawn>()`——拿 Pawn（没有就直接 return）
- `GetController<APlayerController>()`——拿 PC
- `Cast<UTenkaichiLocalPlayer>(PC->GetLocalPlayer())`——拿**本地玩家**（LocalPlayer 是客户端侧的玩家封装）
- `LP->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>()`——拿 **EnhancedInput 本地玩家子系统**（管输入映射的增删）
- `Subsystem->ClearAllMappings()`——**先清空所有旧映射**（防止残留上局的按键绑定）

> 这五步是 EnhancedInput 的标准"取子系统"套路：PC → LocalPlayer → Subsystem。

```cpp
// 移动：把输入向量转成世界方向，加移动输入
void UTenkaichiHeroComponent::Input_Move(const FInputActionValue& InputActionValue)
{
	APawn* Pawn = GetPawn<APawn>();
	AController* Controller = Pawn ? Pawn->GetController() : nullptr;

	// 如果玩家又尝试移动，就取消自动奔跑
	if (ATenkaichiPlayerController* TenkaichiController = Cast<ATenkaichiPlayerController>(Controller))
	{
		TenkaichiController->SetIsAutoRunning(false);
	}
	
	if (Controller)
	{
		const FVector2D Value = InputActionValue.Get<FVector2D>();
		const FRotator MovementRotation(0.0f, Controller->GetControlRotation().Yaw, 0.0f);

		if (Value.X != 0.0f)
		{
			const FVector MovementDirection = MovementRotation.RotateVector(FVector::RightVector);
			Pawn->AddMovementInput(MovementDirection, Value.X);
		}

		if (Value.Y != 0.0f)
		{
			const FVector MovementDirection = MovementRotation.RotateVector(FVector::ForwardVector);
			Pawn->AddMovementInput(MovementDirection, Value.Y);
		}
	}
}
```

**讲解**（移动是核心操控，拆 4 点）：
1. `InputActionValue.Get<FVector2D>()`——输入动作值取成 2D 向量（X=左右，Y=前后）
2. `MovementRotation(0, 控制旋转的Yaw, 0)`——**只取控制器的水平朝向**（Yaw），忽略俯仰，保证移动始终沿水平面
3. `MovementRotation.RotateVector(FVector::RightVector)`——把"世界右"向量绕控制朝向转，得到**朝相机方向的"右"**；`ForwardVector` 同理得"前"
4. `Pawn->AddMovementInput(direction, magnitude)`——按方向+幅度加移动输入（CharacterMovement 消费）

> 关键：移动方向跟随**相机朝向**（不是角色朝向）——所以 WASD 是"朝屏幕方向走"。另外一旦移动就**取消自动奔跑**（`SetIsAutoRunning(false)`）。
