# P06.1 UTenkaichiPawnData —— 总 md（为什么 + 全景 + 依赖分析）

## 一、为什么要有这一节

阶段四先教 `PawnData`（Pawn 数据资产）。它是"**定义一个 Pawn 需要哪些配置**"的**数据容器**。

在 Lyra 里，一个角色（Pawn/Character）不是硬编码"我是什么、我有哪些能力、我的输入怎么绑、我的相机怎么摆"，
而是**指向一份数据资产 `UPrimaryDataAsset`**——这份资产里记录：

- 该 Pawn 用哪个 C++ 类（`PawnClass`）
- 该 Pawn 的能力系统要授予哪些能力集（`AbilitySets`）
- 该 Pawn 用哪套能力标签关系映射（`TagRelationshipMapping`）
- 该 Pawn 用哪个输入配置（`InputConfig`）
- 该 Pawn 默认用哪个相机模式（`DefaultCameraMode`）

**为什么这样设计**：把"定义"和"逻辑"分离。改一个 Pawn 的外观/能力/输入，只需在编辑器里改数据资产，
不用改 C++ 代码。这是 Lyra 数据驱动玩法的基石。

> `PawnData` 会被阶段四后续的角色类（`Character`/`PawnExtensionComponent`/`PlayerState`）引用，
> 也会被阶段五的 `AbilitySystemComponent` 用到。它是角色体系的"配置中枢"之一。

## 二、本文件里有什么（全景）

`ULyraPawnData` 继承 `UPrimaryDataAsset`（引擎的"主数据资产"基类，可被 AssetManager 全局引用）。它包含 **5 个 UPROPERTY 配置字段**：

| 字段 | 类型 | 含义 |
|------|------|------|
| `PawnClass` | `TSubclassOf<APawn>` | 该 Pawn 用哪个类（通常继承 `ALyraPawn`/`ALyraCharacter`） |
| `AbilitySets` | `TArray<TObjectPtr<ULyraAbilitySet>>` | 能力系统要授予的能力集数组 |
| `TagRelationshipMapping` | `TObjectPtr<ULyraAbilityTagRelationshipMapping>` | 能力标签关系映射（✅ 3.4.2 已教） |
| `InputConfig` | `TObjectPtr<ULyraInputConfig>` | 输入配置（✅ 3.4.3 已教） |
| `DefaultCameraMode` | `TSubclassOf<ULyraCameraMode>` | 默认相机模式（阶段六，软引用） |

外加一个构造函数（把 `PawnClass`/`InputConfig`/`DefaultCameraMode` 初始化为 `nullptr`）。

## 四、一个要理解的概念：为什么用 `UPrimaryDataAsset` 而不是 `UDataAsset`

- `UDataAsset`：普通数据资产，可在编辑器里创建实例。
- `UPrimaryDataAsset`：**主数据资产**，多了"资产全局唯一标识"能力，可被 `AssetManager` 用类型+名字全局查找/加载。
- Lyra 选 `UPrimaryDataAsset`，因为 `PawnData` 会被 `AssetManager`（阶段五收口）按 ID 全局加载。
