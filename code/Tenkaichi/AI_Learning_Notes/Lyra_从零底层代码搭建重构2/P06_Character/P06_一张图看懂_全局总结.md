# P06 Character —— 一张图看懂（全局总结 / 反晕眩版）

> **这份 md 的定位**：P06 教了 8 个类、23 个 md，你晕是正常的。
> 这份**不讲怎么教**，只讲「**这些东西合在一起是个啥**」——用**分层 + 类比 + 图**把散的零件拼成一个人。

## 〇、先给一个贯穿全篇的类比：把角色想成「一个入职的员工」

P05 造的 GAS 是"超能力管理局"，但**管理局不会自己长在人身上**。
P06 干的事，就是**造一个"人"，然后把 P05 的能力系统装进去**。

| 现实世界 | P06 里的东西 | 对应 Tenkaichi 类 |
|---------|-------------|------------------|
| **岗位说明书**（这个岗位要会啥、配什么装备） | Pawn 数据资产 | `UTenkaichiPawnData` |
| **人本身**（能走能跳） | 角色 | `ATenkaichiCharacter` |
| **最简版员工**（只有工牌，不会走） | 基础 Pawn | `ATenkaichiPawn` |
| **入职办理处**（按顺序发工牌、装配备、接系统） | Pawn 扩展组件 | `UTenkaichiPawnExtensionComponent` |
| **工位操作台**（键盘鼠标怎么接） | 英雄组件 | `UTenkaichiHeroComponent` |
| **体检中心**（血压/心跳/死亡判定） | 血量组件 | `UTenkaichiHealthComponent` |
| **自带全套装备的特殊岗位** | 带能力的角色 | `ATenkaichiCharacterWithAbilities` |
| **走路方式**（怎么迈腿、怎么测地面） | 移动组件 | `UTenkaichiCharacterMovementComponent` |

> **一句话**：**PawnData 是"说明书"，Character 是"人"，PawnExtension 是"入职处"（负责按顺序把 GAS 接进来），Hero 是"操作台"（负责输入），Health 是"体检中心"（负责生死）。**

## 二、逐文件一句话职责（8 个类，按层归类）

### 第 0 层 · 说明书（1 个）

| 文件 | 干嘛的 | 5 个字段 |
|------|--------|---------|
| `TenkaichiPawnData` | **不可变数据资产**，定义"一个 Pawn 需要哪些配置"。继承 `UPrimaryDataAsset`（可被 AssetManager 全局引用） | `PawnClass`（用哪个类）/ `AbilitySets`（发哪些技能）/ `TagRelationshipMapping`（技能互斥表）/ `InputConfig`（输入配置）/ `DefaultCameraMode`（默认相机） |

> 关键：它**只有 1 个函数**（构造函数），纯数据。是整个 P06 的"配置源头"。

### 第 1 层 · 人（2 个）

| 文件 | 干嘛的 | 函数数 |
|------|--------|-------|
| `TenkaichiCharacter` | ★ **核心角色类**。实现 4 个接口、挂 3 个组件、管复制/移动模式/蹲伏/死亡流程/队伍归属 | **45** |
| `TenkaichiCharacterWithAbilities` | **自带 ASC 的角色**。构造函数里 `CreateDefaultSubobject<ASC + HealthSet + CombatSet>`，`PostInitializeComponents` 里 `InitAbilityActorInfo(this, this)` | **3** |

**ATenkaichiCharacter 内部七块能力（记住这七块就懂了它）**：

```
ATenkaichiCharacter 七大职责
├─ ① 接口实现   4 个：AbilitySystem / GameplayCue / GameplayTagAsset / TeamAgent
│               回答"你的 ASC 在哪""你身上有啥 Tag""你几队的"
├─ ② 组件组合   PawnExtComponent / HealthComponent / CameraComponent（三大件）
├─ ③ 网络复制   GetLifetimeReplicatedProps + PreReplication
│               + FastSharedReplication（★ 移动同步优化，下面单独讲）
├─ ④ 移动模式   OnMovementModeChanged → SetMovementModeTag（走/游泳/飞 → 挂 Tag）
├─ ⑤ 蹲伏       OnStartCrouch / OnEndCrouch / ToggleCrouch / CanJumpInternal
├─ ⑥ 死亡流程   OnDeathStarted（关碰撞关移动）→ OnDeathFinished（断控制器销毁）
│               DisableMovementAndCollision / DestroyDueToDeath / UninitAndDestroy
└─ ⑦ 队伍       SetGenericTeamId / GetGenericTeamId / OnRep_MyTeamID
```

### 第 2 层 · 入职处（1 个）

| 文件 | 干嘛的 | 函数数 |
|------|--------|-------|
| `TenkaichiPawnExtensionComponent` | **协调初始化顺序**的组件。实现 `IGameFrameworkInitStateInterface`，用"状态机"保证 PawnData → PlayerState → ASC → 输入 按序就位 | **20** |

**它的核心价值：解决"谁先谁后"**。

```
为什么需要它？
  Pawn 生成时，PlayerState 可能还没复制过来，ASC 可能还没建好，
  输入组件可能还没绑 —— 直接写代码就会拿到空指针。

PawnExtension 的解法：走「初始化状态机」
  InitState: Spawned → DataAvailable → DataInitialized → GameplayReady

  · DataAvailable    = PawnData 到位（从 PawnData 资产读配置）
  · DataInitialized  = PlayerState 复制到位
  · GameplayReady    = ASC 接好，可以放技能了

  每个组件（Hero / Health）都向它注册"我等 GameplayReady"，
  它到点了统一通知 → 谁都不抢跑，谁都不空指针。
```

> 关键方法：`CheckDefaultInitialization()`（检查能不能进下一状态）、
> `OnAbilitySystemInitialized_RegisterAndCall()`（★ 别人靠这个"等 ASC 就绪"）、
> `InitializeAbilitySystem()` / `UninitializeAbilitySystem()`（接/卸 ASC）。

### 第 2.5 层 · 操作台（1 个）

| 文件 | 干嘛的 | 函数数 | 挂起 |
|------|--------|-------|------|
| `TenkaichiHeroComponent` | **玩家输入接入**。绑定 EnhancedInput 的 Move/Look/Crouch/AutoRun，把 InputTag 转发给 ASC，管相机模式、额外输入配置 | **24** | ⚠️ ⑦ 待 P15 |

**它把"按键"翻译成"技能"**：

```
键盘/手柄
   │ Input_Move / Input_LookMouse / Input_LookStick / Input_Crouch / Input_AutoRun
   ▼
HeroComponent
   ├─ 移动/视角 → 直接调 Character / Controller
   └─ 技能键   → Input_AbilityInputTagPressed(InputTag)
                    ▼
                  ASC::AbilityInputTagPressed  ← 接回 P05 的链路！
```

> ⚠️ **为什么它挂起**：`.h` 硬 include `GameFeatures/GameFeatureAction_AddInputContextMapping.h`（P15 才教）。
> 按死结处理铁律：代码照写、`.h`+`.cpp` 整体 `#if 0`、登记 ⑦、继续推进。

### 第 3 层 · 体检中心（1 个）

| 文件 | 干嘛的 | 函数数 | 挂起 |
|------|--------|-------|------|
| `TenkaichiHealthComponent` | **把 GAS 的 HealthSet 翻译成"游戏层生死"**。监听血量变化 → 广播委托 → 管三态死亡 | **16** | ㉘ 待 P14 |

**它是 P05（GAS 数值）和 P06（游戏逻辑）之间的翻译官**：

```
P05 侧（GAS 内部）                P06 侧（游戏逻辑）
HealthSet.Health = 0        →    HealthComponent
（只是个数字，没人知道"死了"）         ├─ 广播 OnHealthChanged（UI 血条动）
                                   ├─ HandleOutOfHealth → 广播 GameplayEvent.Death
                                   └─ DeathState 三态流转（会网络复制）
```

**三态死亡机**（`ETenkaichiDeathState`）：

```
NotDead ──StartDeath()──→ DeathStarted ──FinishDeath()──→ DeathFinished
  （活着）                  （倒地动画中）                  （可以移除尸体）
```

> 4 个委托：`OnHealthChanged` / `OnMaxHealthChanged` / `OnDeathStarted` / `OnDeathFinished`（全 `BlueprintAssignable`）。

### 第 4 层 · 移动（1 个）

| 文件 | 干嘛的 | 函数数 |
|------|--------|-------|
| `TenkaichiCharacterMovementComponent` | **自定义移动组件**。地面检测缓存、复制加速度、去掉"蹲着不能跳"限制、Tag 控制移动 | **8** |

**四个改动点**（相对引擎 `UCharacterMovementComponent`）：

| 改动 | 干嘛 |
|------|------|
| `GetGroundInfo()` + `CachedGroundInfo` | **缓存**地面信息，同一帧多次查询只算一次（引擎每次都算，浪费） |
| `SetReplicatedAcceleration()` + `SimulateMovement()` | 把加速度**压缩复制**给模拟端，网络同步更准 |
| `CanAttemptJump()` | 去掉引擎的"蹲着不能跳"检查（Lyra 允许蹲跳） |
| `GetDeltaRotation()` / `GetMaxSpeed()` | 挂了 `TAG_Gameplay_MovementStopped` 就返回 0（定身效果） |

> 附带一个 NativeGameplayTag：`TAG_Gameplay_MovementStopped`（第 15 行 `UE_DECLARE_GAMEPLAY_TAG_EXTERN`）。

### 旁挂 · 最简版（1 个）

| 文件 | 干嘛的 | 函数数 |
|------|--------|-------|
| `TenkaichiPawn` | **最简 Pawn**：继承 `AModularPawn`，**只实现 `ITenkaichiTeamAgentInterface`**。给不需要 GAS 的东西用（载具/箱子/炮台） | **11** |

> 注意：它和 `Character` **没有继承关系**，是两条平行线。
> `Pawn` = 只要队伍；`Character` = 队伍 + GAS + 血量 + 相机。

## 三、完整链路图：一个角色从"生成"到"能放技能"走完全程

这是**把上面所有层串起来**的图，看完就不晕了：

```
【第 0 步】服务器生成一个 Pawn
   │ GameMode 读 PawnData 资产（说明书）
   ▼
┌──────────────────────────────────────────────────────────┐
│ ATenkaichiCharacter::PreInitializeComponents()            │
│   → 拿到 PawnExtComponent（入职办理处）                     │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────┐
│ PawnExtension::SetPawnData(PawnData)  ← 发说明书            │
│   → 状态推进到 DataAvailable                               │
│   → 广播"PawnData 就绪"（别的组件可以读配置了）              │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────┐
│ Character::OnRep_PlayerState() / PossessedBy()            │
│   → PawnExtension::HandlePlayerStateReplicated()          │
│   → 状态推进到 DataInitialized                             │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────┐
│ PawnExtension::InitializeAbilitySystem(ASC, OwnerActor)   │
│   ← ASC 从 PlayerState 借过来（Character 自己不造）         │
│   → ASC->InitAbilityActorInfo(OwnerActor, this)           │
│   → 状态推进到 GameplayReady  ★                            │
│   → 广播 OnAbilitySystemInitialized                        │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────┐
│ HealthComponent::InitializeWithAbilitySystem(ASC)         │
│   （它注册过"等 ASC 就绪"，现在被唤醒）                      │
│   → 取 HealthSet → 绑定血量变化回调                         │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────┐
│ HeroComponent 收到"可绑输入"事件（NAME_BindInputsNow）      │
│   → InitializePlayerInput() → 绑 Move/Look/Crouch/技能键   │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────┐
│ ★ 可以玩了：按键 → HeroComponent → ASC → 技能（回到 P05）    │
└──────────────────────────────────────────────────────────┘


【死亡链路】（血量归零时反向走一遍）
   HealthSet.Health = 0
     → HealthComponent::HandleOutOfHealth → 广播 GameplayEvent.Death
     → P05 的 Death 技能激活 → CancelAbilities → StartDeath()
     → DeathState: NotDead → DeathStarted → Character::OnDeathStarted（关碰撞关移动）
     → 蓝图播死亡动画 → FinishDeath()
     → DeathState: DeathStarted → DeathFinished → Character::OnDeathFinished（销毁）
```

## 六、记忆口诀（5 句，背下来就不晕）

1. **PawnData 是说明书** —— 5 个字段定死角色配置，是 P03/P04/P05 的连接器。
2. **PawnExtension 是入职处** —— 管"谁先谁后"，用状态机保证不空指针。
3. **Character 是人** —— 45 个函数，挂三大组件，实现四大接口。
4. **HealthComponent 是翻译官** —— 把 GAS 的 `Health` 数字翻成"死了"这件事。
5. **WithAbilities 是自带工作站的人** —— ASC 自己造，不从 PlayerState 借。

## 七、常见混淆点（你晕大概就晕在这）

| 容易混 | 区别 |
|--------|------|
| **Pawn vs Character** | **没有继承关系**！`Pawn` 只要队伍（11 函数）；`Character` 要 GAS+血量+相机（45 函数）。`Character` 走 `AModularCharacter` 那条线 |
| **Character vs CharacterWithAbilities** | 普通 `Character` 的 ASC **从 PlayerState 借**；`WithAbilities` **自己造 ASC**（构造里 `CreateDefaultSubobject`） |
| **PawnExtension vs Hero** | PawnExtension 管**初始化顺序**（所有 Pawn 都要）；Hero 只管**玩家输入**（只有玩家控制的才有） |
| **HealthSet（P05）vs HealthComponent（P06）** | HealthSet 是 **GAS 里的数字**（血量=100）；HealthComponent 是**游戏逻辑**（血变了要广播、要判死、要三态） |
| **`Damage` vs `Health`**（都在 HealthSet） | `Damage` 是临时搬运工（伤害先写这）；`Health` 才是真血条 |
| **`DeathStarted` vs `DeathFinished`** | `Started` = 倒地动画开始（还能被救）；`Finished` = 真结束（销毁/移除） |
| **`DetermineNewTeamAfterPossessionEnds`** | 控制器离开后队伍怎么办。**`Pawn` 和 `Character` 各有一份**（Lyra 就是这么重复写的），默认都返回 `NoTeam` |
| **`FastSharedReplication`** | 移动同步优化：把位置/旋转/加速度**打包成一个结构体**一次发，省带宽 |
| **Movement 的 `CachedGroundInfo`** | 别直接读！只能通过 `GetGroundInfo()` 访问（它才负责"过期就重算"） |
