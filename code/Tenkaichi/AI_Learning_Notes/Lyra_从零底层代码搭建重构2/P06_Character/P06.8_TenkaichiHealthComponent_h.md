# P06.8 TenkaichiHealthComponent —— 教 .h

## 一、本文件要解决什么

把总 md 里"GAS 数值 → 游戏语义翻译器"这个类落成真实的 `.h` 文件。`TenkaichiHealthComponent.h` 定义 `UTenkaichiHealthComponent` 类，它继承**引擎**的 `UGameFrameworkComponent`（ModularGameplay 插件）。

**这个 `.h` 声明了 3 组东西**：

1. **`ELyraDeathState` 枚举**（3 值）—— 死亡三态：`NotDead` / `DeathStarted` / `DeathFinished`。
2. **2 个动态多播委托** —— `FTenkaichiHealth_DeathEvent`（死亡事件）、`FTenkaichiHealth_AttributeChanged`（属性变化事件）。
3. **`UTenkaichiHealthComponent` 类本身** —— 14 个方法 + 3 个字段。

**它和前几个类 `.h` 的三点不同（重点）**：

| 对比项 | P05.6-3 Reset | P05.4-1 HealthSet | **P06.8 HealthComponent** |
|--------|--------------|-------------------|--------------------------|
| 基类 | `UTenkaichiGameplayAbility` | `UAttributeSet` | **`UGameFrameworkComponent`（引擎）** |
| 枚举 | 无 | 无 | **`ELyraDeathState`（本文件里定义）** |
| 委托 | 无 | `FTenkaichiAttributeEvent` | **2 个（`_DeathEvent` + `_AttributeChanged`）** |
| 内联函数 | 无 | 少量 | **3 个（`FindHealthComponent` / `GetDeathState` / `IsDeadOrDying`）** |
| `Category` | 无 | 无 | ⚠️ **8 处 `"Tenkaichi|Health"`** |

> **`UGameFrameworkComponent` 是啥？** 引擎 `ModularGameplay` 插件的组件基类（教学分级 ①，**只讲不拆**）。
> 它的价值：能接入 `UGameFrameworkComponentManager` 总线的**初始化时机**（InitState 系统）——组件可以在"角色数据就绪""技能系统就绪"等确切时机被初始化，而不是靠 `BeginPlay` 抢跑。
> **本类暂时没用到 InitState**，只是用它的基类身份（Lyra 原样，照抄）。

> 依赖只有引擎 + 2 个前置声明（ASC / HealthSet），**零挂起可独立编译**。

## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "Components/GameFrameworkComponent.h"

#include "TenkaichiHealthComponent.generated.h"

// 把 UE_API 宏临时替换成项目的导出宏（TENKAICHIGAME_API），文件结束再还原成引擎默认
#define UE_API TENKAICHIGAME_API

class UTenkaichiHealthComponent;

class UTenkaichiAbilitySystemComponent;
class UTenkaichiHealthSet;
class UObject;
struct FFrame;
struct FGameplayEffectSpec;

// 死亡事件委托：死亡开始 / 死亡完成时触发，参数是拥有者 Actor
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FTenkaichiHealth_DeathEvent, AActor*, OwningActor);
// 属性变化事件委托：血量 / 最大血量变化时触发，携带组件、旧值、新值、施加者
DECLARE_DYNAMIC_MULTICAST_DELEGATE_FourParams(FTenkaichiHealth_AttributeChanged, UTenkaichiHealthComponent*, HealthComponent, float, OldValue, float, NewValue, AActor*, Instigator);

/**
 * ETenkaichiDeathState
 *
 *	定义当前的死亡状态（三态：活着 / 开始死亡 / 死亡完成）。
 */
UENUM(BlueprintType)
enum class ETenkaichiDeathState : uint8
{
	NotDead = 0,
	DeathStarted,
	DeathFinished
};


/**
 * UTenkaichiHealthComponent
 *
 *	一个 Actor 组件，用来处理与血量相关的一切。
 */
UCLASS(MinimalAPI, Blueprintable, Meta=(BlueprintSpawnableComponent))
class UTenkaichiHealthComponent : public UGameFrameworkComponent
{
	GENERATED_BODY()

public:

	// 构造函数：关闭 Tick、开启网络复制，并把三个字段置空
	UE_API UTenkaichiHealthComponent(const FObjectInitializer& ObjectInitializer);

	// 如果指定的 Actor 上存在血量组件，则返回它
	UFUNCTION(BlueprintPure, Category = "Tenkaichi|Health")
	static UTenkaichiHealthComponent* FindHealthComponent(const AActor* Actor) { return (Actor ? Actor->FindComponentByClass<UTenkaichiHealthComponent>() : nullptr); }

	// 使用给定的能力系统组件来初始化本组件
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	UE_API void InitializeWithAbilitySystem(UTenkaichiAbilitySystemComponent* InASC);

	// 反初始化本组件，清空对能力系统的所有引用
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	UE_API void UninitializeFromAbilitySystem();

	// 返回当前的血量值
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	UE_API float GetHealth() const;

	// 返回当前的最大血量值
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	UE_API float GetMaxHealth() const;

	// 返回当前血量归一化后的值，范围 [0.0, 1.0]
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	UE_API float GetHealthNormalized() const;

	// 返回当前的死亡状态
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	ETenkaichiDeathState GetDeathState() const { return DeathState; }

	// 判断是否已经死亡或正在死亡
	UFUNCTION(BlueprintCallable, BlueprintPure = false, Category = "Tenkaichi|Health", Meta = (ExpandBoolAsExecs = "ReturnValue"))
	bool IsDeadOrDying() const { return (DeathState > ETenkaichiDeathState::NotDead); }

	// 为拥有者开启死亡流程
	UE_API virtual void StartDeath();

	// 为拥有者结束死亡流程
	UE_API virtual void FinishDeath();

	// 施加足以杀死拥有者的伤害
	UE_API virtual void DamageSelfDestruct(bool bFellOutOfWorld = false);

public:

	// 血量值发生变化时触发的委托（在客户端也会触发，但施加者可能无效）
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_AttributeChanged OnHealthChanged;

	// 最大血量值发生变化时触发的委托（在客户端也会触发，但施加者可能无效）
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_AttributeChanged OnMaxHealthChanged;

	// 死亡流程开始时触发的委托
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_DeathEvent OnDeathStarted;

	// 死亡流程完成时触发的委托
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_DeathEvent OnDeathFinished;

protected:

	// 组件注销时自动反初始化，避免残留引用
	UE_API virtual void OnUnregister() override;

	// 清空本组件施加的所有游戏标签
	UE_API void ClearGameplayTags();

	// 血量属性变化时的内部处理：转发为 OnHealthChanged 广播
	UE_API virtual void HandleHealthChanged(AActor* DamageInstigator, AActor* DamageCauser, const FGameplayEffectSpec* DamageEffectSpec, float DamageMagnitude, float OldValue, float NewValue);
	// 最大血量属性变化时的内部处理：转发为 OnMaxHealthChanged 广播
	UE_API virtual void HandleMaxHealthChanged(AActor* DamageInstigator, AActor* DamageCauser, const FGameplayEffectSpec* DamageEffectSpec, float DamageMagnitude, float OldValue, float NewValue);
	// 血量耗尽时的内部处理：广播死亡游戏事件与击杀消息
	UE_API virtual void HandleOutOfHealth(AActor* DamageInstigator, AActor* DamageCauser, const FGameplayEffectSpec* DamageEffectSpec, float DamageMagnitude, float OldValue, float NewValue);

	// 死亡状态从服务器复制到客户端时的回调
	UFUNCTION()
	UE_API virtual void OnRep_DeathState(ETenkaichiDeathState OldDeathState);

protected:

	// 本组件所使用的能力系统组件
	UPROPERTY()
	TObjectPtr<UTenkaichiAbilitySystemComponent> AbilitySystemComponent;

	// 本组件所使用的血量属性集
	UPROPERTY()
	TObjectPtr<const UTenkaichiHealthSet> HealthSet;

	// 用于处理死亡的、带复制的状态
	UPROPERTY(ReplicatedUsing = OnRep_DeathState)
	ETenkaichiDeathState DeathState;
};

// 文件末尾还原 UE_API 为引擎默认（不要影响其他文件）
#undef UE_API
```

## 四、逐段讲解

### 1. include 与前置声明

```cpp
#pragma once

#include "Components/GameFrameworkComponent.h"

#include "TenkaichiHealthComponent.generated.h"
```

- **`Components/GameFrameworkComponent.h`** —— 引擎 `ModularGameplay` 插件的组件基类（教学分级 ①，**只讲不拆**）。
  ⚠️ **它是引擎文件，不换前缀**。第 0 步 `Build.cs` 已启用 `ModularGameplay`，能编。
- **`TenkaichiHealthComponent.generated.h`** —— 反射生成头，必须最后。

```cpp
class UTenkaichiHealthComponent;

class UTenkaichiAbilitySystemComponent;
class UTenkaichiHealthSet;
class UObject;
struct FFrame;
struct FGameplayEffectSpec;
```

| 前置声明 | 为什么需要 | 来源 |
|---------|-----------|------|
| **`UTenkaichiHealthComponent`** | ⚠️ **自己前置声明自己** —— 因为下面 2 个委托的参数里用到了 `UTenkaichiHealthComponent*`，而此时类还没定义 | Lyra 原样 |
| `UTenkaichiAbilitySystemComponent`（P05.2） | `AbilitySystemComponent` 字段 + `InitializeWithAbilitySystem` 参数 | ✅ 已落盘 |
| `UTenkaichiHealthSet`（P05.4-1） | `HealthSet` 字段 | ✅ 已落盘 |
| `UObject` | UE 反射需要 | 引擎 |
| `FFrame` | 蓝图虚拟机栈帧（UFUNCTION 需要） | 引擎 |
| **`FGameplayEffectSpec`** | 3 个 `Handle*Changed` 函数的参数 | 引擎 GAS |

> 🔑 **零挂起的关键全在这里** —— 所有 Lyra 侧的依赖（ASC / HealthSet）**只前置声明、不 include**。
> **前置声明不阻塞编译**（铁律 30），所以 `.h` 能独立编译；只有 `.cpp` 里真的调用 ASC 方法时才需要 include。

### 2. 两个动态多播委托

```cpp
// 死亡事件委托：死亡开始 / 死亡完成时触发，参数是拥有者 Actor
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FTenkaichiHealth_DeathEvent, AActor*, OwningActor);
// 属性变化事件委托：血量 / 最大血量变化时触发，携带组件、旧值、新值、施加者
DECLARE_DYNAMIC_MULTICAST_DELEGATE_FourParams(FTenkaichiHealth_AttributeChanged, UTenkaichiHealthComponent*, HealthComponent, float, OldValue, float, NewValue, AActor*, Instigator);
```

- **`DECLARE_DYNAMIC_MULTICAST_DELEGATE_*`** —— 引擎宏，**动态**=蓝图可绑定，**多播**=可以有多个监听者。
- **`_OneParam` / `_FourParams`** —— 参数个数，宏名末尾声明，参数成对写（类型, 名字）。
- **为什么 `_AttributeChanged` 第一个参数回传 `HealthComponent`？**
  因为监听者可能监听了多个角色的血量，回传自己才能知道"是谁的血变了"。
- **命名**：Lyra 用 `FLyraHealth_XXX`（下划线分隔，不是 `FXXXHealth`），一比一只换前缀。
- ⚠️ **必须在类定义之前声明**（Lyra 原样，`.h` 第 19~20 行）—— 因为类里的 `UPROPERTY(BlueprintAssignable)` 要用它们。

### 3. `ETenkaichiDeathState` 枚举

```cpp
UENUM(BlueprintType)
enum class ETenkaichiDeathState : uint8
{
	NotDead = 0,
	DeathStarted,
	DeathFinished
};
```

- **`UENUM(BlueprintType)`** —— 蓝图可用枚举。
- **`enum class ... : uint8`** —— 强类型枚举，底层 1 字节（省网络带宽）。
- **`NotDead = 0`** —— ⚠️ **显式写 0 很重要**：因为 `DeathState` 是复制属性，默认值必须是"活着"；而且 `IsDeadOrDying()` 用 `> NotDead` 判断，依赖 0 起始。
- **三个值的语义**（总 md 讲过，这里再扣一遍）：

  | 值 | 语义 | 对应 Death 技能 |
  |----|------|----------------|
  | `NotDead` | 活着 | — |
  | `DeathStarted` | 开始死亡（正在播倒地动画） | `StartDeath()` 把它从 `NotDead` 推到这 |
  | `DeathFinished` | 死亡完成（可移除尸体） | `FinishDeath()` 把它从 `DeathStarted` 推到这 |

> ⚠️ 注意 `.h` 里枚举定义和类定义之间**有两个空行**（Lyra 原样），照抄。

### 4. 类声明：`MinimalAPI` + `Blueprintable` + `Meta`

```cpp
UCLASS(MinimalAPI, Blueprintable, Meta=(BlueprintSpawnableComponent))
class UTenkaichiHealthComponent : public UGameFrameworkComponent
```

| 修饰符 | 含义 |
|--------|------|
| **`MinimalAPI`** | 只导出最小符号集，方法要导出得手写 `UE_API`（和 Reset 一样） |
| **`Blueprintable`** | 蓝图**可以继承**这个 C++ 类 |
| **`Meta=(BlueprintSpawnableComponent)`** | 蓝图里**能作为组件添加到 Actor 上**（在"添加组件"面板里能看到） |

- **继承 `UGameFrameworkComponent`**（引擎）—— 拿到 ModularGameplay 总线的初始化时机能力。
- **文档注释**已中文化：*"一个 Actor 组件，用来处理与血量相关的一切。"*

### 5. 构造函数 + 静态查找（3 个内联函数）

```cpp
	// 构造函数：关闭 Tick、开启网络复制，并把三个字段置空
	UE_API UTenkaichiHealthComponent(const FObjectInitializer& ObjectInitializer);
```

- ⚠️ **没有默认参数**（和 Reset 的 `= FObjectInitializer::Get()` 不同）—— Lyra 原样，照抄别加。
- **实现在 `.cpp`**：关 Tick、开复制、置空三字段。

```cpp
	// 如果指定的 Actor 上存在血量组件，则返回它
	UFUNCTION(BlueprintPure, Category = "Tenkaichi|Health")
	static UTenkaichiHealthComponent* FindHealthComponent(const AActor* Actor) { return (Actor ? Actor->FindComponentByClass<UTenkaichiHealthComponent>() : nullptr); }
```

- ⭐ **这是全类最重要的函数之一** —— **Death 技能（㉖）靠它找到本组件**！
  ```cpp
  // TenkaichiGameplayAbility_Death.cpp 里这么用：
  UTenkaichiHealthComponent::FindHealthComponent(GetAvatarActorFromActorInfo())
  ```
- **`static`** —— 不需要实例，直接 `类名::函数名` 调。
- **`UFUNCTION(BlueprintPure, ...)`** —— `Pure` = 纯函数（无副作用，蓝图里显示为**无执行引脚**的绿色节点）。
- **函数体写在 `.h` 里（内联）** —— 因为只有一行。⚠️ 这意味着**改它要重新编译所有 include 它的文件**，但 Lyra 就这么写，照抄。
- **`Actor ? ... : nullptr`** —— 防御式：Actor 为空时安全返回 nullptr。
- ⚠️ **`Category = "Tenkaichi|Health"` 第 1 处**（共 8 处）。

```cpp
	// 返回当前的死亡状态
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Health")
	ETenkaichiDeathState GetDeathState() const { return DeathState; }

	// 判断是否已经死亡或正在死亡
	UFUNCTION(BlueprintCallable, BlueprintPure = false, Category = "Tenkaichi|Health", Meta = (ExpandBoolAsExecs = "ReturnValue"))
	bool IsDeadOrDying() const { return (DeathState > ETenkaichiDeathState::NotDead); }
```

- **`GetDeathState()`** —— 直接返回字段。⚠️ **Death 技能（㉖）要调它判断 `NotDead`**。
- **`IsDeadOrDying()`** —— `DeathState > NotDead`，也就是"开始死亡 **或** 死亡完成"都算。
- **`BlueprintPure = false`** —— 虽然叫 "Is" 开头，但**显式声明它不是纯函数**（Lyra 特意加的）。
- **`Meta = (ExpandBoolAsExecs = "ReturnValue")`** —— 蓝图里把 `bool` 返回值**展开成两个执行引脚**（True / False），像分支节点一样好用。
- ⚠️ **`Category` 第 7、8 处**。

### 6. 生命周期：初始化 / 反初始化（2 个）


- **`InitializeWithAbilitySystem(InASC)`** —— ⭐ **整类的入口**。`.cpp` 里它做五件事：

### 8. 死亡三方法

```cpp
	// 为拥有者开启死亡流程
	UE_API virtual void StartDeath();

	// 为拥有者结束死亡流程
	UE_API virtual void FinishDeath();

	// 施加足以杀死拥有者的伤害
	UE_API virtual void DamageSelfDestruct(bool bFellOutOfWorld = false);
```

- **`StartDeath()` / `FinishDeath()`** —— ⭐ **Death 技能（㉖）调的就是这两个**。
  `.cpp` 里它们做：状态检查 → 改 `DeathState` → 设死亡 Tag → 广播委托 → `ForceNetUpdate()`。
  **状态检查很关键**：`StartDeath` 只在 `NotDead` 生效，`FinishDeath` 只在 `DeathStarted` 生效（防重复）。
- **`virtual`** —— 允许子类（蓝图）重写死亡逻辑。
- **`DamageSelfDestruct(bool bFellOutOfWorld = false)`** —— 自毁：
  - `bFellOutOfWorld = true` → 掉出世界（加 `FellOutOfWorld` 标签）
  - `false` → 普通自杀
  - ⚠️ **`.cpp` 实现要挂起**（依赖 P14 `AssetManager` 取默认伤害 GE），登记 **㉘**。
- ⚠️ **这三个没有 `Category`**（不是 UFUNCTION，蓝图不能直接调）—— 是 `public` 的普通虚函数，C++ 侧调用。

### 9. 四个委托字段

```cpp
public:

	// 血量值发生变化时触发的委托（在客户端也会触发，但施加者可能无效）
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_AttributeChanged OnHealthChanged;

	// 最大血量值发生变化时触发的委托（在客户端也会触发，但施加者可能无效）
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_AttributeChanged OnMaxHealthChanged;

	// 死亡流程开始时触发的委托
	UPROPERTY(BlueprintAssignable)
	FTenkaichiHealth_DeathEvent OnDeathStarted;

	// 死亡流程完成时触发的委托

	FTenkaichiHealth_DeathEvent OnDeathFinished;
```

- **`UPROPERTY(BlueprintAssignable)`** —— ⭐ **蓝图可以绑定**（在蓝图里对组件右键 "Assign OnHealthChanged" 就能加事件）。
  这是 `DECLARE_DYNAMIC_MULTICAST_DELEGATE` + `BlueprintAssignable` 的经典组合。
- **Lyra 原注释点明了一个坑**：*"在客户端也会触发，但施加者可能无效"* —— 因为施加者（`Instigator`）是 Actor 指针，**客户端上可能还没复制过来**。⚠️ 用 `Instigator` 前要判空。
- ⚠️ **第二个 `public:` 段** —— 和方法段之间隔开了，Lyra 原样，**照抄别合并**（和 Death 的 `.h` 一样）。
- **`OnDeathStarted` / `OnDeathFinished`** —— 角色（`TenkaichiCharacter.h:168` 的 `OnDeathStarted`）就绑它。

### 10. protected 段：内部处理（5 个方法）

```cpp
protected:

	// 组件注销时自动反初始化，避免残留引用
	UE_API virtual void OnUnregister() override;

	// 清空本组件施加的所有游戏标签
	UE_API void ClearGameplayTags();

	// 血量属性变化时的内部处理：转发为 OnHealthChanged 广播
	UE_API virtual void HandleHealthChanged(AActor* DamageInstigator, AActor* DamageCauser, const FGameplayEffectSpec* DamageEffectSpec, float DamageMagnitude, float OldValue, float NewValue);
	// 最大血量属性变化时的内部处理：转发为 OnMaxHealthChanged 广播
	UE_API virtual void HandleMaxHealthChanged(AActor* DamageInstigator, AActor* DamageCauser, const FGameplayEffectSpec* DamageEffectSpec, float DamageMagnitude, float OldValue, float NewValue);
	// 血量耗尽时的内部处理：广播死亡游戏事件与击杀消息
	UE_API virtual void HandleOutOfHealth(AActor* DamageInstigator, AActor* DamageCauser, const FGameplayEffectSpec* DamageEffectSpec, float DamageMagnitude, float OldValue, float NewValue);

	// 死亡状态从服务器复制到客户端时的回调
	UFUNCTION()
	UE_API virtual void OnRep_DeathState(ETenkaichiDeathState OldDeathState);
```

| 方法 | 干嘛 |
|------|------|
| **`OnUnregister()`（重写引擎）** | 组件注销时自动 `UninitializeFromAbilitySystem()`，**防残留引用**（好习惯） |
| **`ClearGameplayTags()`** | 把 `Status_Death_Dying` / `Status_Death_Dead` 两个 Tag 计数清 0 |
| **`HandleHealthChanged`** | 血量变了 → 广播 `OnHealthChanged` |
| **`HandleMaxHealthChanged`** | 最大血量变了 → 广播 `OnMaxHealthChanged` |
| **`HandleOutOfHealth`** | ⭐ **血尽** → 广播 `GameplayEvent.Death`（触发 Death 技能）+ `Tenkaichi.Elimination.Message`（击杀播报） |
| **`OnRep_DeathState`** | 客户端收到复制状态，补做转换（含"预测超过服务器"处理） |

- **3 个 `Handle*` 参数完全一样**（6 个参数）—— 因为它们是绑到 `HealthSet` 的 `FTenkaichiAttributeEvent` 委托上的，**签名必须匹配**（`.cpp` 详讲）。
- **`OnRep_DeathState` 有 `UFUNCTION()`** —— `ReplicatedUsing` 的回调**必须是 UFUNCTION**（引擎要求），否则 UHT 报错。

### 11. protected 段：3 个字段

```cpp
protected:

	// 本组件所使用的能力系统组件
	UPROPERTY()
	TObjectPtr<UTenkaichiAbilitySystemComponent> AbilitySystemComponent;

	// 本组件所使用的血量属性集
	UPROPERTY()
	TObjectPtr<const UTenkaichiHealthSet> HealthSet;

	// 用于处理死亡的、带复制的状态
	UPROPERTY(ReplicatedUsing = OnRep_DeathState)
	ETenkaichiDeathState DeathState;
```

- **`TObjectPtr<...>`** —— UE5 的对象指针（替代裸指针，GC 更安全）。
- ⚠️ **`TObjectPtr<const UTenkaichiHealthSet>` 带 `const`** —— 因为本组件**只读** HealthSet，不该改它（改数值是 GE 的事）。Lyra 原样，照抄。
- ⚠️ **`UPROPERTY()` 空括号也要写** —— 不写的话 GC 不知道这里有个引用，会把对象回收掉（**经典崩溃坑**）。
- **`UPROPERTY(ReplicatedUsing = OnRep_DeathState)`** —— ⭐ **网络复制的核心**：
  服务器改 `DeathState` → 自动复制到所有客户端 → 客户端调 `OnRep_DeathState(OldValue)` 补做转换。
  ⚠️ 有 `ReplicatedUsing` 就**必须**在 `.cpp` 里写 `GetLifetimeReplicatedProps` + `DOREPLIFETIME`（`.cpp` 详讲）。
- ⚠️ **第三个 `protected:` 段** —— 本文件共 **2 个 `public:` + 2 个 `protected:`**，Lyra 原样**照抄别合并**。

### 12. `#undef UE_API`

```cpp
#undef UE_API
```

- 撤销开头的宏定义，防污染其他文件。**必须有**（和 Reset 一样）。

## 五、几个要记住的点

1. **基类是引擎的 `UGameFrameworkComponent`**（教学分级 ①，不换前缀、只讲不拆）。
2. **`.h` 里声明了枚举 + 2 个委托 + 1 个类** —— 三样东西，不只是类。
3. **8 处 `Category = "Tenkaichi|Health"`** —— 最容易漏（UFUNCTION 共 8 个带 Category）。
4. **`FindHealthComponent` / `GetDeathState` / `IsDeadOrDying` 三个内联** —— 函数体直接写在 `.h`。
5. **`FindHealthComponent` 是 ㉖ 的钥匙** —— Death 技能靠它找到本组件。
6. **`MinimalAPI` + `UE_API`** —— 只有 14 个方法带 `UE_API` 前缀会被导出。
7. **3 个 `protected:`/`public:` 段（实际 2+2）照抄不合并**。
8. **`ReplicatedUsing = OnRep_DeathState`** —— 网络复制核心，`OnRep` 必须是 `UFUNCTION()`。
9. **`TObjectPtr<const UTenkaichiHealthSet>` 带 `const`** —— 只读语义。
10. **`.h` 零挂起** —— 所有 Lyra 依赖只前置声明。
