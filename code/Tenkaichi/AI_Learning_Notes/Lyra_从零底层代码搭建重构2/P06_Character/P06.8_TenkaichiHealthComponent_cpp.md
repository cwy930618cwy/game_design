# P06.8 TenkaichiHealthComponent —— 教 .cpp

## 一、本文件要解决什么

`.h` 声明了 14 个方法（3 个内联的已经在 `.h` 写完了），`.cpp` 实现**剩下 11 个**。

这个 `.cpp` 完成四件事：

1. **建立与 GAS 的连接** —— `InitializeWithAbilitySystem`：拿到 ASC + HealthSet，注册 3 个属性监听，初始化满血。
2. **翻译数值成游戏语义** —— 3 个查询 + 3 个 `Handle*` 转发成委托广播。
3. **管理死亡状态机** —— `StartDeath` / `FinishDeath` 推状态 + 设 Tag + 广播；`OnRep_DeathState` 处理客户端同步。
4. **血尽时广播死亡** —— `HandleOutOfHealth` 一次发**两个**消息（GAS 事件 + 消息总线击杀播报）。

> 🔑 **一句话**：`.cpp` 就是"**接上 GAS → 翻译成事件 → 管死亡 → 广播出去**"。

// 使用给定的能力系统组件来初始化本组件
void UTenkaichiHealthComponent::InitializeWithAbilitySystem(UTenkaichiAbilitySystemComponent* InASC)
{
	AActor* Owner = GetOwner();
	check(Owner);

	if (AbilitySystemComponent)
	{
		UE_LOG(LogTenkaichi, Error, TEXT("TenkaichiHealthComponent: Health component for owner [%s] has already been initialized with an ability system."), *GetNameSafe(Owner));
		return;
	}

	AbilitySystemComponent = InASC;
	if (!AbilitySystemComponent)
	{
		UE_LOG(LogTenkaichi, Error, TEXT("TenkaichiHealthComponent: Cannot initialize health component for owner [%s] with NULL ability system."), *GetNameSafe(Owner));
		return;
	}

	HealthSet = AbilitySystemComponent->GetSet<UTenkaichiHealthSet>();
	if (!HealthSet)
	{
		UE_LOG(LogTenkaichi, Error, TEXT("TenkaichiHealthComponent: Cannot initialize health component for owner [%s] with NULL health set on the ability system."), *GetNameSafe(Owner));
		return;
	}

	// 注册监听属性变化
	HealthSet->OnHealthChanged.AddUObject(this, &ThisClass::HandleHealthChanged);
	HealthSet->OnMaxHealthChanged.AddUObject(this, &ThisClass::HandleMaxHealthChanged);
	HealthSet->OnOutOfHealth.AddUObject(this, &ThisClass::HandleOutOfHealth);

	// 临时：把属性重置为默认值。将来会改由一张配置表驱动。
	AbilitySystemComponent->SetNumericAttributeBase(UTenkaichiHealthSet::GetHealthAttribute(), HealthSet->GetMaxHealth());

	ClearGameplayTags();

	OnHealthChanged.Broadcast(this, HealthSet->GetHealth(), HealthSet->GetHealth(), nullptr);
	OnMaxHealthChanged.Broadcast(this, HealthSet->GetHealth(), HealthSet->GetHealth(), nullptr);
}

// 反初始化本组件，清空对能力系统的所有引用
void UTenkaichiHealthComponent::UninitializeFromAbilitySystem()
{
	ClearGameplayTags();

	if (HealthSet)
	{
		HealthSet->OnHealthChanged.RemoveAll(this);
		HealthSet->OnMaxHealthChanged.RemoveAll(this);
		HealthSet->OnOutOfHealth.RemoveAll(this);
	}

	HealthSet = nullptr;
	AbilitySystemComponent = nullptr;
}

// 清空本组件施加的所有游戏标签
void UTenkaichiHealthComponent::ClearGameplayTags()
{
	if (AbilitySystemComponent)
	{
		AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dying, 0);
		AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dead, 0);
	}
}

// 返回当前的血量值
float UTenkaichiHealthComponent::GetHealth() const
{
	return (HealthSet ? HealthSet->GetHealth() : 0.0f);
}

// 返回当前的最大血量值
float UTenkaichiHealthComponent::GetMaxHealth() const
{
	return (HealthSet ? HealthSet->GetMaxHealth() : 0.0f);
}

// 返回当前血量归一化后的值，范围 [0.0, 1.0]
float UTenkaichiHealthComponent::GetHealthNormalized() const
{
	if (HealthSet)
	{
		const float Health = HealthSet->GetHealth();
		const float MaxHealth = HealthSet->GetMaxHealth();

		return ((MaxHealth > 0.0f) ? (Health / MaxHealth) : 0.0f);
	}

	return 0.0f;
}

// 死亡状态从服务器复制到客户端时的回调
void UTenkaichiHealthComponent::OnRep_DeathState(ETenkaichiDeathState OldDeathState)
{
	const ETenkaichiDeathState NewDeathState = DeathState;

	// 暂时回退死亡状态，因为我们依赖 StartDeath 和 FinishDeath 来改变它
	DeathState = OldDeathState;

	if (OldDeathState > NewDeathState)
	{
		// 服务器试图把我们设回去，但我们本地已经预测得比服务器更远了
		UE_LOG(LogTenkaichi, Warning, TEXT("TenkaichiHealthComponent: Predicted past server death state [%d] -> [%d] for owner [%s]."), (uint8)OldDeathState, (uint8)NewDeathState, *GetNameSafe(GetOwner()));
		return;
	}

	if (OldDeathState == ETenkaichiDeathState::NotDead)
	{
		if (NewDeathState == ETenkaichiDeathState::DeathStarted)
		{
			StartDeath();
		}
		else if (NewDeathState == ETenkaichiDeathState::DeathFinished)
		{
			StartDeath();
			FinishDeath();
		}
		else
		{
			UE_LOG(LogTenkaichi, Error, TEXT("TenkaichiHealthComponent: Invalid death transition [%d] -> [%d] for owner [%s]."), (uint8)OldDeathState, (uint8)NewDeathState, *GetNameSafe(GetOwner()));
		}
	}
	else if (OldDeathState == ETenkaichiDeathState::DeathStarted)
	{
		if (NewDeathState == ETenkaichiDeathState::DeathFinished)
		{
			FinishDeath();
		}
		else
		{
			UE_LOG(LogTenkaichi, Error, TEXT("TenkaichiHealthComponent: Invalid death transition [%d] -> [%d] for owner [%s]."), (uint8)OldDeathState, (uint8)NewDeathState, *GetNameSafe(GetOwner()));
		}
	}

	ensureMsgf((DeathState == NewDeathState), TEXT("TenkaichiHealthComponent: Death transition failed [%d] -> [%d] for owner [%s]."), (uint8)OldDeathState, (uint8)NewDeathState, *GetNameSafe(GetOwner()));
}

// 为拥有者开启死亡流程
void UTenkaichiHealthComponent::StartDeath()
{
	if (DeathState != ETenkaichiDeathState::NotDead)
	{
		return;
	}

	DeathState = ETenkaichiDeathState::DeathStarted;

	if (AbilitySystemComponent)
	{
		AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dying, 1);
	}

	AActor* Owner = GetOwner();
	check(Owner);

	OnDeathStarted.Broadcast(Owner);

	Owner->ForceNetUpdate();
}

// 为拥有者结束死亡流程
void UTenkaichiHealthComponent::FinishDeath()
{
	if (DeathState != ETenkaichiDeathState::DeathStarted)
	{
		return;
	}

	DeathState = ETenkaichiDeathState::DeathFinished;

	if (AbilitySystemComponent)
	{
		AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dead, 1);
	}

	AActor* Owner = GetOwner();
	check(Owner);

	OnDeathFinished.Broadcast(Owner);

	Owner->ForceNetUpdate();
}

### 3. 构造函数 + 复制注册

```cpp
UTenkaichiHealthComponent::UTenkaichiHealthComponent(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	PrimaryComponentTick.bStartWithTickEnabled = false;
	PrimaryComponentTick.bCanEverTick = false;

	SetIsReplicatedByDefault(true);

	AbilitySystemComponent = nullptr;
	HealthSet = nullptr;
	DeathState = ETenkaichiDeathState::NotDead;
}
```

- **关两处 Tick** —— 血量组件**不需要每帧跑**（是事件驱动的），省性能。
- **`SetIsReplicatedByDefault(true)`** —— ⭐ **开启网络复制**。没有它，`DeathState` 的 `ReplicatedUsing` 就不生效。
- **三个字段置空** —— 尤其是 `DeathState = NotDead`（初始值必须是活着）。

```cpp
void UTenkaichiHealthComponent::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
	Super::GetLifetimeReplicatedProps(OutLifetimeProps);

	DOREPLIFETIME(UTenkaichiHealthComponent, DeathState);
}
```

- ⚠️ **`DOREPLIFETIME` 必须有** —— `.h` 里写了 `ReplicatedUsing`，`.cpp` 就**必须**在这里注册，否则复制不生效（**经典坑**）。
- **只复制 `DeathState`** —— `AbilitySystemComponent` / `HealthSet` 是本地引用，不需要复制。

### 4. `InitializeWithAbilitySystem`（⭐ 整类入口）

```cpp
	AActor* Owner = GetOwner();
	check(Owner);

	if (AbilitySystemComponent)
	{
		UE_LOG(LogTenkaichi, Error, TEXT("... has already been initialized ..."));
		return;
	}
```

- **五步走**：
  1. `check(Owner)` —— 组件必须有拥有者
  2. **防重复初始化** —— 已初始化就报错返回（不覆盖，避免监听泄漏）
  3. 存 `AbilitySystemComponent`，空则报错
  4. **`ASC->GetSet<UTenkaichiHealthSet>()` 取血量属性集**，空则报错
  5. 注册 3 个监听 + 初始化满血 + 清 Tag + 广播初始值

```cpp
	// 注册监听属性变化
	HealthSet->OnHealthChanged.AddUObject(this, &ThisClass::HandleHealthChanged);
	HealthSet->OnMaxHealthChanged.AddUObject(this, &ThisClass::HandleMaxHealthChanged);
	HealthSet->OnOutOfHealth.AddUObject(this, &ThisClass::HandleOutOfHealth);
```

- **`AddUObject(this, &ThisClass::HandleXxx)`** —— 把 `UObject` 的成员函数绑到委托上。
  **`ThisClass`** 是 `GENERATED_BODY()` 生成的 typedef（= 本类），Lyra 惯用写法，比写全类名省事。
- ⭐ **这就是"桥"的接入口** —— HealthSet（GAS 侧）一有变化，就调本组件的 `Handle*`。

```cpp
	// 临时：把属性重置为默认值。将来会改由一张配置表驱动。
	AbilitySystemComponent->SetNumericAttributeBase(UTenkaichiHealthSet::GetHealthAttribute(), HealthSet->GetMaxHealth());
```

- **把血量初始化成满血** —— ⚠️ Lyra 原注释写了 `TEMP`（将来会由配置表驱动），**照抄不删**。
- **`SetNumericAttributeBase`** —— 设**基础值**（区别于 `SetNumericAttributeCurrent`，后者是临时值）。

```cpp
	ClearGameplayTags();

	OnHealthChanged.Broadcast(this, HealthSet->GetHealth(), HealthSet->GetHealth(), nullptr);
	OnMaxHealthChanged.Broadcast(this, HealthSet->GetHealth(), HealthSet->GetHealth(), nullptr);
```

- **最后广播两次初始值**（旧值=新值=当前血）—— 让 UI 一上来就有正确显示，而不是等第一次受伤才更新。
  ⚠️ Lyra 这里**第三个参数（NewValue）写的是 `GetHealth()` 两次**（`OnMaxHealthChanged` 那行也没用 `GetMaxHealth()`）—— 这是 **Lyra 原样的小瑕疵**，一比一照抄别"顺手修正"（铁律 14）。

### 5. `UninitializeFromAbilitySystem` + `OnUnregister`

```cpp
void UTenkaichiHealthComponent::OnUnregister()
{
	UninitializeFromAbilitySystem();

	Super::OnUnregister();
}
```

- **`OnUnregister` 里先解绑再调 Super** —— ⭐ **防残留引用的好习惯**：组件要没了，先把对 ASC/HealthSet 的监听摘掉，否则委托持有野指针会崩。
- **解绑用 `RemoveAll(this)`** —— 一次性移除本对象在该委托上的**所有**绑定（比 `Remove` 逐个删省事）。

### 6. `ClearGameplayTags`

```cpp
	AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dying, 0);
	AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dead, 0);
```

- **`SetLooseGameplayTagCount(Tag, N)`** —— 设"松散标签"的计数（不通过 GE，直接挂）。
- **设成 0 = 清除**。这两个 Tag 是"正在死亡"/"已死亡"，其他系统靠它们判断状态。

### 8. `HandleOutOfHealth`（⭐ 最精彩的一段）

血耗尽时，**一次干两件事**：

**① 发 GAS 事件（触发死亡技能）**

```cpp
#if WITH_SERVER_CODE
	if (AbilitySystemComponent && DamageEffectSpec)
	{
		FGameplayEventData Payload;
		Payload.EventTag = TenkaichiGameplayTags::GameplayEvent_Death;
		Payload.Instigator = DamageInstigator;
		Payload.Target = AbilitySystemComponent->GetAvatarActor();
		Payload.OptionalObject = DamageEffectSpec->Def;
		Payload.ContextHandle = DamageEffectSpec->GetEffectContext();
		Payload.InstigatorTags = *DamageEffectSpec->CapturedSourceTags.GetAggregatedTags();
		Payload.TargetTags = *DamageEffectSpec->CapturedTargetTags.GetAggregatedTags();
		Payload.EventMagnitude = DamageMagnitude;

		FScopedPredictionWindow NewScopedWindow(AbilitySystemComponent, true);
		AbilitySystemComponent->HandleGameplayEvent(Payload.EventTag, &Payload);
	}
#endif
```

- **`#if WITH_SERVER_CODE`** —— ⭐ **只在服务器编译**。死亡是服务器权威的，客户端不该自己"死亡"。
- **`FGameplayEventData Payload`** —— 事件载荷，塞满了信息：谁杀的、杀的谁、用的什么 GE、来源/目标 Tag、伤害量。
- ⭐ **`Payload.EventTag = GameplayEvent_Death`** —— 还记得吗？**Death 技能在构造函数里给 CDO 挂的触发标签就是这个**！
  ```
  Chain：血尽 → HandleOutOfHealth → 广播 GameplayEvent.Death
        → Death 技能（CDO 上挂了该触发标签）自动激活
        → StartDeath() → 播动画 → FinishDeath()
  ```
  **这就是 GAS 事件驱动技能的完整闭环 —— P05.6-2 的 Death 技能在这里终于被"点燃"了。**
- **`FScopedPredictionWindow(ASC, true)`** —— 开启预测窗口，让这次事件在客户端也能被预测执行（减少延迟感）。

**② 发消息总线击杀播报**

```cpp
		FTenkaichiVerbMessage Message;
		Message.Verb = TAG_Tenkaichi_Elimination_Message;
		Message.Instigator = DamageInstigator;
		Message.InstigatorTags = *DamageEffectSpec->CapturedSourceTags.GetAggregatedTags();
		Message.Target = UTenkaichiVerbMessageHelpers::GetPlayerStateFromObject(AbilitySystemComponent->GetAvatarActor());
		Message.TargetTags = *DamageEffectSpec->CapturedTargetTags.GetAggregatedTags();

		UGameplayMessageSubsystem& MessageSystem = UGameplayMessageSubsystem::Get(GetWorld());
		MessageSystem.BroadcastMessage(Message.Verb, Message);
```

- **`FTenkaichiVerbMessage`**（P01.1）—— 动词消息（"谁 对 谁 做了什么"）。
- **`Message.Target` 用 `GetPlayerStateFromObject(AvatarActor)`** —— 因为 `VerbMessage` 的 Target 语义是 PlayerState 不是 Pawn（P01 教过这个 Helper）。
- **`BroadcastMessage(Verb, Message)`** —— 往 `Tenkaichi.Elimination.Message` 频道广播。**UI（击杀播报）、计分系统**监听它就行 —— **这就是 P01 消息总线的实战价值**。

### 9. `OnRep_DeathState`（客户端同步，最绕的一段）

```cpp
	const ETenkaichiDeathState NewDeathState = DeathState;

	// 暂时回退死亡状态，因为我们依赖 StartDeath 和 FinishDeath 来改变它
	DeathState = OldDeathState;
```

- ⭐ **先存新值，再回退到旧值** —— 因为接下来要**重新走一遍** `StartDeath()`/`FinishDeath()`（它们内部会正确设状态、设 Tag、广播委托）。
  如果直接用复制来的新值，那些副作用（Tag、委托）就**全丢了** —— 这是这段最精妙的地方。

```cpp
	if (OldDeathState > NewDeathState)
	{
		// 服务器试图把我们设回去，但我们本地已经预测得比服务器更远了
		UE_LOG(LogTenkaichi, Warning, TEXT("... Predicted past server death state ..."));
		return;
	}
```

- **"预测超过服务器"** —— 客户端已经预测到 `DeathFinished`，服务器却发来 `DeathStarted`（回滚）。**直接忽略**，以客户端更"前进"的状态为准。

```cpp
	if (OldDeathState == ETenkaichiDeathState::NotDead)
	{
		if (NewDeathState == ETenkaichiDeathState::DeathStarted)
		{
			StartDeath();
		}
		else if (NewDeathState == ETenkaichiDeathState::DeathFinished)
		{
			StartDeath();
			FinishDeath();
		}
		...
```

- ⭐ **补齐中间态** —— 如果从 `NotDead` 直接跳到 `DeathFinished`（网络丢包跳过中间），就**连着调两次** `StartDeath()` + `FinishDeath()`，保证状态机完整走过一遍。
- **`ensureMsgf`** 收尾 —— 验证最终状态确实等于新值（开发期断言，不崩但会提示）。

### 10. `StartDeath` / `FinishDeath`

```cpp
void UTenkaichiHealthComponent::StartDeath()
{
	if (DeathState != ETenkaichiDeathState::NotDead)
	{
		return;
	}

	DeathState = ETenkaichiDeathState::DeathStarted;

	if (AbilitySystemComponent)
	{
		AbilitySystemComponent->SetLooseGameplayTagCount(TenkaichiGameplayTags::Status_Death_Dying, 1);
	}

	AActor* Owner = GetOwner();
	check(Owner);

	OnDeathStarted.Broadcast(Owner);

	Owner->ForceNetUpdate();
}
```

- **四步**：状态检查 → 改状态 → 设 Tag → 广播委托 → `ForceNetUpdate()`。
- ⭐ **状态检查是幂等保护** —— `StartDeath` 只在 `NotDead` 生效（重复调无效）。**这就是 Death 技能 `EndAbility` 敢无条件兜底 `FinishDeath()` 的原因**（P05.6-2 讲过）。
- **`Status_Death_Dying` vs `Status_Death_Dead`** —— 前者"正在死"，后者"死透了"，两个不同 Tag。
- **`ForceNetUpdate()`** —— 强制立即网络更新（不等下次复制周期），让死亡状态**尽快**同步给所有人。
