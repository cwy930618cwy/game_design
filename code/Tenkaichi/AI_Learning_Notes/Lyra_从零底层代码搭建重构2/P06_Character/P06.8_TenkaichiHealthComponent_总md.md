## 一、这个类解决什么问题（为什么）

P05 搭好了 GAS，但有个**断层**：

- `UTenkaichiHealthSet`（P05.4-1）是 **GAS 侧的数值仓库** —— 它知道"血量 = 37.5"，但它**不懂游戏语义**（不知道"死了"、"该播死亡动画了"）。
- 蓝图/UI/角色想知道的是："**我还活着吗？**"、"**谁杀了我？**"、"**血量百分比是多少（画血条）**"。

**`UTenkaichiHealthComponent` 就是这座桥**：把 GAS 的数值翻译成**游戏层的血量 / 死亡事件**。

它干四件事：

| 职责 | 说明 |
|------|------|
| ① **绑定 GAS** | `InitializeWithAbilitySystem(InASC)` —— 拿到 ASC 和 HealthSet，注册属性变化监听 |
| ② **暴露查询** | `GetHealth()` / `GetMaxHealth()` / `GetHealthNormalized()` / `IsDeadOrDying()` —— 给 UI 画血条 |
| ③ **管理死亡状态机** | `ELyraDeathState` 三态 `NotDead` → `DeathStarted` → `DeathFinished`，并**网络复制** |
| ④ **血尽时发死亡事件** | `HandleOutOfHealth` → 广播 `GameplayEvent.Death`（触发 Death 技能）+ `Lyra.Elimination.Message`（击杀消息） |

> 🔑 **一句话**：**HealthComponent = GAS 数值 → 游戏语义 的翻译器**，也是**死亡流程的状态机管理员**。

## 三、全景：这个类的完整家当

### 3.1 一个枚举

```cpp
UENUM(BlueprintType)
enum class ELyraDeathState : uint8
{
    NotDead = 0,       // 活着
    DeathStarted,      // 开始死亡（正在播死亡动画）
    DeathFinished      // 死亡完成（可以移除尸体了）
};
```

> ⚠️ **为什么是三态不是两态？**
> 因为死亡**有过程**：`DeathStarted`（倒地动画开始）→ 播几秒 → `DeathFinished`（真正结束）。
> Death 技能的 `StartDeath()` / `FinishDeath()` **正好对应这两个转换点**。

### 3.2 两个委托

| 委托 | 参数 | 何时触发 |
|------|------|---------|
| `FLyraHealth_AttributeChanged` | `(HealthComponent, OldValue, NewValue, Instigator)` | 血量/最大血量变化时 |
| `FLyraHealth_DeathEvent` | `(OwningActor)` | 死亡开始 / 死亡完成时 |

## 六、几个要记住的点

1. **它是桥** —— 把 GAS 数值翻译成游戏语义（"还活着吗""血条百分比"）。
2. **死亡三态** —— `NotDead` → `DeathStarted` → `DeathFinished`，对应 Death 技能的两个调用点。
3. **`FindHealthComponent` 是静态内联** —— 别人（`Death` 技能）靠它找到本组件，**写在 `.h` 里**。
4. **`DeathState` 带 `ReplicatedUsing=OnRep_DeathState`** —— 客户端靠 `OnRep` 补做状态转换（含"预测超过服务器"的特殊处理）。
5. **`HandleOutOfHealth` 一次发两个消息** —— `GameplayEvent.Death`（GAS 侧，触发死亡技能）+ `Lyra.Elimination.Message`（消息总线，击杀播报）。
6. **`DamageSelfDestruct` 需挂起** —— 唯一的 P14 依赖（㉘）。
7. **继承 `UGameFrameworkComponent`** —— 引擎 ModularGameplay 插件的基类（① 只讲不拆）。
