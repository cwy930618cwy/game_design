## 〇、本节全景（这一节教什么）

P00 Physics 有 2 个内容：P00.1 碰撞通道头文件（纯宏，已教完），P00.2 是这个 `PhysicalMaterialWithTags` 类——它是 P00 里**唯一真正的类**（有 `.h` + `.cpp`）。

| 类 | 继承 | 干什么的 |
|----|------|---------|
| `UPhysicalMaterialWithTags` | `UPhysicalMaterial`（引擎） | 一个"身上能挂 GameplayTag 的物理材质"——用 Tag 描述"这材质是什么"，供游戏逻辑判断 |

> 一句话：**物理材质 = 地面/墙面/身体等东西的"手感属性"**。引擎的物理材质能决定"走上去什么声音、多滑、多弹"，但没法让代码问"这材质是草地还是金属"。Lyra 给它加了个 `Tags` 容器，让**游戏逻辑用 GameplayTag 来认识它**。

## 一、为什么需要它（解决什么问题）

**问题**：打击感、脚步声、子弹穿墙效果……很多玩法都要根据"我打中的是什么材质"做不同反应。引擎的 `UPhysicalMaterial` 本身没有"给代码打标签"的入口——它主要管物理参数（摩擦、弹性），不是给逻辑做判断的。

**解决**：Lyra 派生出 `UPhysicalMaterialWithTags`，**多加一个 `FGameplayTagContainer Tags`**。于是物理材质也能挂标签，比如：

- 给"草地"材质挂 `Damage.Footstep.Grass`，走路就播草地的脚步声。
- 给"金属"材质挂 `Impact.Bullet.Metal`，被子弹打中就弹火花。
- 给"敌人"的材质挂 `Status.HitStun`，被打到就触发受击硬直。

> 类比：引擎的物理材质是"手感数据卡"（多滑、多弹），`Tags` 是给这张卡**贴上分类标签**，让游戏逻辑一眼认出"这是啥材质"。

## 二、关键概念（先建立认知）

### 概念 1：`UPhysicalMaterial` 是引擎的物理材质基类

材质（Material）决定"看起来什么样"，**物理材质（PhysicalMaterial）决定"摸起来/碰撞起来什么参数"**——摩擦力、弹性、脚步声、表面特效等。它在引擎的 `PhysicalMaterials/` 模块里，是个普通的 UObject。

### 概念 2：`FGameplayTagContainer` 是标签容器

L1 已经教过 GameplayTags（`TenkaichiGameplayTags.h/.cpp`）。`FGameplayTagContainer` 是"能装一堆 GameplayTag 的集合"，常用来描述一个对象的属性。这里它挂在物理材质上，就是"这材质有哪些特性标签"。

### 概念 3：`Tags` 用 `EditAnywhere, BlueprintReadOnly` 暴露

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=PhysicalProperties)
FGameplayTagContainer Tags;
```

- `EditAnywhere`：在编辑器细节面板里**手动填标签**（美术/策划给每个物理材质资产配好）。
- `BlueprintReadOnly`：蓝图能**读**，但不能随便改。
- `Category=PhysicalProperties`：在细节面板里归到"物理属性"分类下。

### 概念 4：构造函数体是空的

```cpp
UPhysicalMaterialWithTags::UPhysicalMaterialWithTags(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
}
```

这个类**没加任何自己的成员初始化**，构造函数只调用父类。那为什么还要写？——**因为要确保它能被正确创建**。加上 `.cpp` 里的 `UE_INLINE_GENERATED_CPP_BY_NAME`，让 UHT（Unreal Header Tool）生成的代码能被编译进来。

> 一句话：这个类很"空"，核心价值就是**多了一个 `Tags` 标签容器**。教学意义是学会"派生引擎 UObject 类"的完整骨架。
