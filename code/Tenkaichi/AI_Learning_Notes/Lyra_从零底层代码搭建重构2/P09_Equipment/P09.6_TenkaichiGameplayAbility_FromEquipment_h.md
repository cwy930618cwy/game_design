## 三、逐段讲解

### 1. include 与前置声明

```cpp
#include "AbilitySystem/Abilities/TenkaichiGameplayAbility.h"
```

- 继承 `UTenkaichiGameplayAbility`（P05.3-B 的 Lyra 技能基类），必须 include 完整定义。

```cpp
class UTenkaichiEquipmentInstance;
class UTenkaichiInventoryItemInstance;
```

- 两个前置声明：装备实例（P09.2）+ 物品实例（P08）。都只以指针返回值出现，前置声明够。

### 2. 类声明

```cpp
UCLASS()
class UTenkaichiGameplayAbility_FromEquipment : public UTenkaichiGameplayAbility
{
	GENERATED_BODY()
public:
	UTenkaichiGameplayAbility_FromEquipment(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());
	...
};
```

- 继承 `UTenkaichiGameplayAbility`（P05.3-B 的 Lyra 技能基类，而它又继承引擎的 `UGameplayAbility`）。
- `UCLASS()`：**无额外标记**（不是 `Blueprintable`），说明它是纯 C++ 基类，蓝图里直接继承它需要另建蓝图类。

### 3. 两个查询方法

```cpp
UFUNCTION(BlueprintCallable, Category="Tenkaichi|Ability")
UTenkaichiEquipmentInstance* GetAssociatedEquipment() const;

UFUNCTION(BlueprintCallable, Category = "Tenkaichi|Ability")
UTenkaichiInventoryItemInstance* GetAssociatedItem() const;
```

- `GetAssociatedEquipment`：取授予这个技能的装备实例。
- `GetAssociatedItem`：取装备对应的物品实例。
- 都标 `BlueprintCallable`（蓝图可调），`Category="Tenkaichi|Ability"`（Lyra 原文 `Lyra|Ability`，换前缀）。

### 4. 编辑器校验

```cpp
#if WITH_EDITOR
virtual EDataValidationResult IsDataValid(class FDataValidationContext& Context) const override;
#endif
```

- `WITH_EDITOR`：只在编辑器构建时编译（运行时游戏不编译这段）。
- `IsDataValid`：覆写 UObject 的数据校验函数，编辑器里检查这个技能资产是否配置正确（`.cpp` 里实现：装备技能必须 Instanced）。
