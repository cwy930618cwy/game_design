## 一、本文件要解决什么

P09.1~P09.3 讲完了装备的定义/实例/管理器，但玩家**怎么在多个装备之间快速切换**？ 就是本组件。

`TenkaichiQuickBarComponent` = **快捷栏**，挂在 Controller 上：
- 有 N 个槽位（默认 3），每个槽放一个物品实例。
- `CycleActiveSlotForward/Backward`：向前/向后循环切换当前激活槽。
- 切换激活槽时，自动**脱下旧装备 + 穿上新装备**（`UnequipItemInSlot` + `EquipItemInSlot`）。
- 槽位/激活槽变化时广播消息（UI 监听更新）。

一句话：**快捷栏 = 玩家快速切换装备的槽位系统**，它是"装备管理器"的上层使用者。

---

## 二、为什么放在 P09.5（QuickBar 依赖装备管理器）

QuickBar 的核心动作是"切换装备"：

```cpp
EquippedItem = EquipmentManager->EquipItem(EquipDef);   // 穿上
EquipmentManager->UnequipItem(EquippedItem);            // 脱下
```

它**依赖 P09.3 的装备管理器**来做实际穿脱。同时它还依赖 P08.4 的 `InventoryFragment_EquippableItem`（判断某个物品是不是"可装备的"）。所以排在 P09.3 之后、P09.6 之前。

## 五、核心概念：`UControllerComponent` + Server RPC

1. **`UControllerComponent`**：挂在 Controller 上的组件（不是 Pawn）。快捷栏属于"玩家控制器"层面的东西（不是角色身体）。

2. **`SetActiveSlotIndex` 是 Server RPC**：
```cpp
UFUNCTION(Server, Reliable, BlueprintCallable)
void SetActiveSlotIndex(int32 NewIndex);
```
- 客户端调用 → **只在服务器执行**（`SetActiveSlotIndex_Implementation`）。
- 为什么：切换装备是权威操作（要改 `EquippedItem`、要穿脱装备），必须服务器决定。

3. **`ReplicatedUsing` 回调广播**：`Slots` 和 `ActiveSlotIndex` 复制时触发 `OnRep_Slots`/`OnRep_ActiveSlotIndex`，广播消息给 UI。
