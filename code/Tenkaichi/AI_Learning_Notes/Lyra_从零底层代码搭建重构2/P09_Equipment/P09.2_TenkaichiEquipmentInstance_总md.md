## 一、本文件要解决什么

P09.1 的 `EquipmentDefinition` 是"菜谱"（数据），本类是**"做出来的那件装备"**（运行时对象）。

- 菜谱（Definition）告诉你"穿这件装备要生成什么、授予什么"。
- **实例（Instance）就是"穿在角色身上的那一件"**：它持有实际生成的 Actor（武器模型），记录"是谁穿的"（Instigator），提供"装备/卸下"的生命周期钩子。

对应 P08 的 `InventoryItemInstance`（物品实例），本类是**装备实例**——一件具体的、穿在身上的、会复制的装备。

一句话：**装备实例 = 从菜谱做出来的、穿在角色身上的那件装备**（持有生成的 Actor + 记录穿戴者）。

---

## 二、为什么它是"运行时核心"

Definition 是静态配置，Instance 是动态对象。所有"装备/卸下"的实际动作都发生在 Instance 上：

- `SpawnEquipmentActors`：按 Definition 的 `ActorsToSpawn` 生成武器模型，挂到角色身上。
- `OnEquipped` / `OnUnequipped`：装备/卸下的钩子（触发蓝图事件）。
- `GetPawn` / `GetInstigator`：查"这件装备是谁的、穿在谁身上"。

它是 P09.3 Manager 管理的对象，也是 P09.6 FromEquipment 技能"关联的装备"。

## 五、核心概念：装备实例的"外层"是 Pawn

`GetPawn()` 的实现是 `Cast<APawn>(GetOuter())`——**装备实例的 Outer（外层对象）就是穿戴它的 Pawn**。

这是 UE 的惯用法：用 `Outer` 建立对象归属关系。装备实例创建时 `NewObject<UTenkaichiEquipmentInstance>(Pawn)`，这样：
- `GetOuter()` 直接拿到 Pawn。
- `GetWorld()` 通过 `GetPawn()->GetWorld()` 拿到世界。
- 垃圾回收时，Pawn 销毁 → 装备实例跟着销毁。

> 类比：装备实例"寄生"在 Pawn 身上，Pawn 是它的"宿主"。
