## 二、关键点讲解

### 1. 两个请求结构体——Layout vs Widget

| 结构体 | 字段 | 用途 |
|--------|------|------|
| `FTenkaichiHUDLayoutRequest` | `LayoutClass`（`UCommonActivatableWidget`）+ `LayerID` | 整块布局推到某个"层" |
| `FTenkaichiHUDElementEntry` | `WidgetClass`（`UUserWidget`）+ `SlotID` | 单个控件注册到某个"插槽" |

**注意类型差异**：
- Layout 用 `UCommonActivatableWidget`（可激活控件，有激活/停用生命周期，能推层）。
- Widget 用 `UUserWidget`（普通控件，注册到扩展插槽）。

### 2. `meta=(Categories="UI.Layer")` + `FGameplayTag`

```cpp
UPROPERTY(EditAnywhere, Category=UI, meta=(Categories="UI.Layer"))
FGameplayTag LayerID;
```

`Categories="UI.Layer"`：编辑器里的 GameplayTag 选择器**只显示 `UI.Layer` 分类下的 tag**（限制范围，避免选错）。

### 3. `meta=(TitleProperty="{LayerID} -> {LayoutClass}")`

```cpp
UPROPERTY(EditAnywhere, Category=UI, meta=(TitleProperty="{LayerID} -> {LayoutClass}"))
TArray<FTenkaichiHUDLayoutRequest> Layout;
```

数组元素在编辑器列表里显示为 `UI.Layer.Game -> 我的布局类` ——**多字段组合标题**（比 P15.4 的单字段更直观）。

### 4. 三层数据结构

```
FPerContextData
  ├─ ComponentRequests      （组件请求句柄）
  └─ ActorData: TMap<FObjectKey, FPerActorData>
        └─ FPerActorData
             ├─ LayoutsAdded        （已加的布局，弱引用）
             └─ ExtensionHandles    （UI 扩展句柄）
```

为什么再分一层 `FPerActorData`？因为**客户端可能同时有多个 HUD Actor**（分屏多玩家），每个 HUD 各自有自己的布局和句柄。

> `FObjectKey` 做 Key（P15.3 已教，可哈希 + 防悬空）。

### 5. `AddAdditionalAssetBundleData`（`WITH_EDITORONLY_DATA`）

```cpp
#if WITH_EDITORONLY_DATA
virtual void AddAdditionalAssetBundleData(FAssetBundleData& AssetBundleData) override;
#endif
```

`WITH_EDITORONLY_DATA`：这个宏只在"编辑器构建 + 需要编辑器数据"时开启（比 `WITH_EDITOR` 更严格——打包后连数据都没有）。

这个函数让编辑器把 `Widgets` 里引用的控件**自动加进 AssetBundle**（这样运行时按 Bundle 批量加载时能找到）。

### 6. 只有 `OnGameFeatureDeactivating`（没有 Activating）

```cpp
virtual void OnGameFeatureDeactivating(FGameFeatureDeactivatingContext& Context) override;
```

对比 P15.5/P15.6 有 `OnGameFeatureActivating`——这个类**不需要**，因为激活时的准备工作由基类 `WorldActionBase::OnGameFeatureActivating` 完成（它调 `AddToWorld`），这里只需要额外处理停用（清理 UI）。
