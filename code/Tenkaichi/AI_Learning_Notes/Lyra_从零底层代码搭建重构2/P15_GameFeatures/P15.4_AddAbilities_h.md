## 〇、这个 `.h` 在解决什么

声明 3 个配置结构体（`Grant` → `Entry` → `AbilitiesList`）+ 动作类 + 2 个私有运行时结构体。

**文件拆解：**

| 块 | 代码 | 作用 |
|----|------|------|
| ① | `FTenkaichiAbilityGrant` | 一个要授予的能力 |
| ② | `FTenkaichiAttributeSetGrant` | 一个要授予的属性集 |
| ③ | `FGameFeatureAbilitiesEntry` | 一条配置（类 + 3 个授予列表） |
| ④ | `UGameFeatureAction_AddAbilities` | 动作类 |
| ⑤ | `FActorExtensions`（私有） | 某 Actor 已授予的东西 |
| ⑥ | `FPerContextData`（私有） | 每上下文的活跃扩展 + 组件请求 |

// 一条配置：给某个类 Actor 加什么。
USTRUCT()

	GENERATED_BODY()

	UPROPERTY(EditAnywhere, Category="Abilities")
	TSoftClassPtr<AActor> ActorClass;

	UPROPERTY(EditAnywhere, Category="Abilities")

	UPROPERTY(EditAnywhere, Category="Attributes")

	UPROPERTY(EditAnywhere, Category="Attributes", meta=(AssetBundles="Client,Server"))

## 二、关键点讲解

### 1. 三个配置结构体的层次

```
FGameFeatureAbilitiesEntry       ← 一条配置
  ├─ ActorClass                   （给哪个类）
  ├─ GrantedAbilities[]           （FTenkaichiAbilityGrant：单个能力）
  ├─ GrantedAttributes[]          （FTenkaichiAttributeSetGrant：单个属性集）
  └─ GrantedAbilitySets[]         （FTenkaichiAbilitySet：能力集资产）
```

- `FTenkaichiAbilityGrant`：一个能力（`TSoftClassPtr<UGameplayAbility>`）。
- `FTenkaichiAttributeSetGrant`：一个属性集（`TSoftClassPtr<UAttributeSet>` + 可选初始化数据表）。
- `FGameFeatureAbilitiesEntry`：把"类"和"给它加的东西"绑在一起。

### 2. `meta=(AssetBundles="Client,Server")`

```cpp
UPROPERTY(EditAnywhere, BlueprintReadOnly, meta=(AssetBundles="Client,Server"))
TSoftClassPtr<UGameplayAbility> AbilityType;
```

`AssetBundles`：指定这个软引用资产属于哪个 Bundle——`Client,Server` 表示"客户端和服务器都需要加载"。配合 P14.3 AssetManager 的 `FTenkaichiBundles::Equipped` 使用（按 Bundle 批量加载）。

### 3. `FTenkaichiAbilityGrant` 里注释掉的行

```cpp
// 	UPROPERTY(EditAnywhere, BlueprintReadOnly)
// 	TSoftObjectPtr<UInputAction> InputAction;
```

Lyra 源码里这一行**本来就是注释掉的**（原始源码就这样）。按铁律 23，**保持注释状态照抄**（不要取消注释）。

### 4. `FGameFeatureAbilitiesEntry` 的 `USTRUCT()` vs `USTRUCT(BlueprintType)`

- `FTenkaichiAbilityGrant` / `FTenkaichiAttributeSetGrant`：`USTRUCT(BlueprintType)`（蓝图可用）。
- `FGameFeatureAbilitiesEntry`：`USTRUCT()`（仅反射，不暴露蓝图）。

### 5. `meta=(TitleProperty="ActorClass", ShowOnlyInnerProperties)`

```cpp
UPROPERTY(EditAnywhere, Category="Abilities", meta=(TitleProperty="ActorClass", ShowOnlyInnerProperties))
TArray<FGameFeatureAbilitiesEntry> AbilitiesList;
```

- `TitleProperty="ActorClass"`：数组元素在编辑器列表里用 `ActorClass` 作为标题显示（一眼看出这行是给哪个类的）。
- `ShowOnlyInnerProperties`：数组展开时直接显示元素内部属性（不显示结构体名）。

### 6. `FActorExtensions`——记录"已授予了什么"

```cpp
struct FActorExtensions
{
	TArray<FGameplayAbilitySpecHandle> Abilities;             // 已给的能力句柄
	TArray<UAttributeSet*> Attributes;                        // 已给的属性集实例
	TArray<FTenkaichiAbilitySet_GrantedHandles> AbilitySetHandles;  // 已给的能力集句柄
};
```

这是"收据"——记下这个 Actor 领了哪些东西，停用时按它精确收回。

> `FTenkaichiAbilitySet_GrantedHandles` 是 P05 `TenkaichiAbilitySet.h` 里的结构体（已核实存在，第 90 行）。

### 7. `FPerContextData` + `ContextData`

```cpp
struct FPerContextData
{
	TMap<AActor*, FActorExtensions> ActiveExtensions;   // Actor → 已授予的东西
	TArray<TSharedPtr<FComponentRequestHandle>> ComponentRequests;  // 组件请求句柄
};

TMap<FGameFeatureStateChangeContext, FPerContextData> ContextData;
```

- 一次激活（一个 Context）对应一份数据（`ActiveExtensions` 记住哪些 Actor 加了什么，`ComponentRequests` 记住组件请求句柄）。
- `ContextData` 用 Context 做 Key，支持"同一 Action 在不同 world/上下文各有一份"。

### 8. 模板 + 非模板重载

```cpp
template<class ComponentType>
ComponentType* FindOrAddComponentForActor(AActor* Actor, ...)
{
	return Cast<ComponentType>(FindOrAddComponentForActor(ComponentType::StaticClass(), Actor, ...));
}

UActorComponent* FindOrAddComponentForActor(UClass* ComponentType, AActor* Actor, ...);
```

模板版只是"类型安全包装"——拿到 `ComponentType::StaticClass()` 调非模板版，再 `Cast` 回具体类型。实际逻辑在非模板版（`.cpp` 里）。
