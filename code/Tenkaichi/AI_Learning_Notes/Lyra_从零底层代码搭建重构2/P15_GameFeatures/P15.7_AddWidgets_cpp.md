void UGameFeatureAction_AddWidgets::Reset(FPerContextData& ActiveData)
{
	ActiveData.ComponentRequests.Empty();

	for (TPair<FObjectKey, FPerActorData>& Pair : ActiveData.ActorData)
	{

		{
			Handle.Unregister();
		}
	}
	ActiveData.ActorData.Empty();
}

{
	FPerContextData& ActiveData = ContextData.FindOrAdd(ChangeContext);
	// 扩展/接收者被移除 → 移除控件
	if ((EventName == UGameFrameworkComponentManager::NAME_ExtensionRemoved) || (EventName == UGameFrameworkComponentManager::NAME_ReceiverRemoved))

		RemoveWidgets(Actor, ActiveData);
	}

	else if ((EventName == UGameFrameworkComponentManager::NAME_ExtensionAdded) || (EventName == UGameFrameworkComponentManager::NAME_GameActorReady))
	{
		AddWidgets(Actor, ActiveData);
	}
}

## 二、关键点讲解

### 1. `AddAdditionalAssetBundleData`——编辑器登记 Bundle

```cpp
AssetBundleData.AddBundleAsset(UGameFeaturesSubsystemSettings::LoadStateClient, Entry.WidgetClass.ToSoftObjectPath().GetAssetPath());
```

把每个 Widget 的资产路径加进"客户端加载 Bundle"（`LoadStateClient`）。这样即使 `Widgets` 是软引用，打包时也会被正确分配到 Bundle 里。

### 2. `IsDataValid`——两组校验（带作用域块）

```cpp
{
	int32 EntryIndex = 0;
	for (const FTenkaichiHUDLayoutRequest& Entry : Layout) { ... }
}

{
	int32 EntryIndex = 0;
	for (const FTenkaichiHUDElementEntry& Entry : Widgets) { ... }
}
```

用**裸花括号**包成两个作用域块——这样两个循环可以各用同名变量 `EntryIndex`（作用域隔离）。这是 C++ 的小技巧。

每组校验两件事：类非空（`IsNull()`）+ tag 有效（`IsValid()`）。

### 3. `AddToWorld` 结构（内层整体挂起）

外层 `if ((GameInstance) && (World) && World->IsGameWorld())` **保留**（不依赖 HUD），内层 `#if 0` 挂起（依赖 `ATenkaichiHUD`）。

> 这样外层逻辑可编译（虽然内层空，但语法正确）。

### 4. `Reset`——只清句柄，不碰 HUD

```cpp
ActiveData.ComponentRequests.Empty();
for (TPair<FObjectKey, FPerActorData>& Pair : ActiveData.ActorData)
{
	for (FUIExtensionHandle& Handle : Pair.Value.ExtensionHandles)
	{
		Handle.Unregister();
	}
}
ActiveData.ActorData.Empty();
```

`Reset` 里**不需要 `ATenkaichiHUD`**（只遍历 `ActorData` 的句柄注销），所以**可编译，不用挂起**。

> 注意它**没有**调 `RemoveWidgets`（不像 P15.4/P15.5 的 Reset 会遍历调用 Remove）——因为 `RemoveWidgets` 需要 HUD Actor，`Reset` 直接用 `FPerActorData` 里存的句柄注销。

### 5. `HandleActorExtension`——用 `NAME_GameActorReady`

```cpp
else if ((EventName == NAME_ExtensionAdded) || (EventName == UGameFrameworkComponentManager::NAME_GameActorReady))
```

对比：
- P15.5 用 `UTenkaichiHeroComponent::NAME_BindInputsNow`（Hero 就绪）。
- P15.7 用 `NAME_GameActorReady`（**引擎常量**，游戏 Actor 就绪）——HUD Actor 就绪时加 UI，不需要 Lyra 自定义事件。

### 6. `AddWidgets`——两条添加路径

```cpp
// ① 布局：推到 CommonUI 层
ActorData.LayoutsAdded.Add(UCommonUIExtensions::PushContentToLayer_ForPlayer(LocalPlayer, Entry.LayerID, ConcreteWidgetClass));

// ② 控件：注册到 UI 扩展插槽
ActorData.ExtensionHandles.Add(ExtensionSubsystem->RegisterExtensionAsWidgetForContext(Entry.SlotID, LocalPlayer, Entry.WidgetClass.Get(), -1));
```

- `PushContentToLayer_ForPlayer`：CommonUI 的工具函数，把控件推到指定层的栈上（可返回可激活控件）。
- `RegisterExtensionAsWidgetForContext`：UIExtension 系统，把控件注册到"插槽 tag"，返回句柄（注销用）。最后的 `-1` 是 ZOrder（默认）。

### 7. `RemoveWidgets`——先停用布局，再注销扩展

```cpp
for (TWeakObjectPtr<UCommonActivatableWidget>& AddedLayout : ActorData->LayoutsAdded)
{
	if (AddedLayout.IsValid())
	{
		AddedLayout->DeactivateWidget();   // 布局用 Deactivate（不是 Destroy）
	}
}
for (FUIExtensionHandle& Handle : ActorData->ExtensionHandles)
{
	Handle.Unregister();
}
```

- 布局：`DeactivateWidget()`（可激活控件的停用，会走淡出动画等）。
- 扩展：`Handle.Unregister()`（注销句柄）。

### 8. 为什么 `RemoveWidgets` 要注释"只在同一个 HUD" 

```cpp
// 只在"和注册时是同一个 HUD Actor"时才注销——客户端可能同时有多个活跃的 HUD
FPerActorData* ActorData = ActiveData.ActorData.Find(HUD);
```

分屏时一个客户端有多个 HUD Actor，`Find(HUD)` 确认是注册过的那个才处理。
