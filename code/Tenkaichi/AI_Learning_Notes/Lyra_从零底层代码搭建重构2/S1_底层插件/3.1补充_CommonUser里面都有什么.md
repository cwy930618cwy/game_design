# 3.1 补充 —— CommonUser 插件里都有什么、都是干嘛的

> **归属**：阶段三 3.1（装 CommonGame/CommonUser 插件）的补充讲解。
> **目标**：把 CommonUser 插件里每个类"认个脸"——它们是什么、干嘛的、将来谁继承它。
> **源码依据**：`E:\ue5\game_design\code\Tenkaichi\Plugins\CommonUser\Source\CommonUser\Public\*.h`（真实查证，非凭印象）。
> **性质**：只认脸、不拆源码。这些是插件（不是要一比一还原的项目 Source），用到时再深讲。

## 一、一句话定位

CommonUser 是 Epic 提供的一套 **"用户身份 + 在线会话"管理插件**。它回答两个每个联网游戏都要面对的问题：

1. **"这个玩家是谁？"** —— 用户登录、身份、权限（能不能联机、能不能聊天）。
2. **"游戏怎么连起来？"** —— 创建房间、搜索房间、加入房间、邀请好友。

它和 CommonGame 是搭档：**CommonGame 管"玩家/会话的对象框架"，CommonUser 管"玩家身份 + 在线会话的具体流程"**。

核心是**两个子系统**（`UCommonUserSubsystem` 管用户、`UCommonSessionSubsystem` 管会话）+ 一堆辅助类：

```
两个核心子系统（都是 UGameInstanceSubsystem）
  UCommonUserSubsystem    用户登录/身份/权限
  UCommonSessionSubsystem 创建/搜索/加入在线会话

辅助类
  UCommonUserInfo               单个用户的"信息卡"
  UCommonUserBasicPresence      在线状态（presence）推送
  UAsyncAction_CommonUserInitialize  异步初始化用户的蓝图节点
  UCommonSession_HostSessionRequest     建房请求参数
  UCommonSession_SearchSessionRequest   搜房请求参数
  UCommonSession_SearchResult           搜到的房间结果
  CommonUserTypes.h 里的一堆枚举        登录状态/权限/可用性等
```

## 二、两个核心子系统

### 1. `UCommonUserSubsystem`（继承 `UGameInstanceSubsystem`）

> 文件：`CommonUserSubsystem.h`（34.1KB，最大的一块）

**干嘛的**：处理**用户身份与登录状态的查询和变更**。每个 GameInstance 一个，蓝图和 C++ 都能访问。

关键能力（从真实源码看）：
- **初始化用户**：`TryToInitializeForLocalPlay`（本地游玩，含游客）、`TryToLoginForOnlinePlay`（在线登录）、`TryToInitializeUser`（通用登录，带参数结构体）。
- **查询用户**：`GetUserInfoForLocalPlayerIndex` / `GetUserInfoForPlatformUser` / `GetUserInfoForUniqueNetId` 等一堆 `GetUserInfoFor...`，用各种方式找到对应的 `UCommonUserInfo`。
- **登录监听**：`ListenForLoginKeyInput`（监听手柄按键触发登录，做"按任意键开始"）、`CancelUserInitialization`、`TryToLogOutUser`。
- **平台特征标签**：`SetTraitTags` / `HasTraitTag`（比如"主机平台要求严格控制器映射"这类平台特性）。
- **权限/可用性**：`GetPrivilegeDescription` / `GetPrivilegeResultDescription`，把权限查询结果转成给人看的话。
- 三个可绑定委托：`OnUserInitializeComplete`（初始化完成）、`OnHandleSystemMessage`（系统消息）、`OnUserPrivilegeChanged`（权限变化）。

**重要**：它**同时支持 OSS v1 和 OSS v2**（在线子系统两套 API），源码里用 `#if COMMONUSER_OSSV1` 分支。你项目里默认走 v2（`UE::Online` 那套）。

**Lyra 怎么用**：Lyra 的 `GameInstance` / 玩家登录流程会调用它来做"玩家登录 + 权限检查"。

---

### 2. `UCommonSessionSubsystem`（继承 `UGameInstanceSubsystem`）

> 文件：`CommonSessionSubsystem.h`（22.7KB）

**干嘛的**：处理**主持（Host）与加入（Join）在线游戏**的请求。同样是每个 GameInstance 一个。

关键能力：
- **建房**：`HostSession`（创建房间）、`CreateOnlineHostSessionRequest`（生成建房请求）。
- **搜房**：`FindSessions`（搜索可加入的房间）、`CreateOnlineSearchSessionRequest`（生成搜房请求）。
- **快速匹配**：`QuickPlaySession`（找不到就自己建）。
- **加入**：`JoinSession`（加入指定房间）。
- **清理**：`CleanUpSessions`（返回主菜单时清掉所有会话）。
- 一堆事件委托：`OnCreateSessionComplete` / `OnJoinSessionComplete` / `OnUserRequestedSessionEvent`（平台邀请加入）/ `OnDestroySessionRequestedEvent`（平台请求退出）等。

**重要**：它内部还用了 **Beacon（信标）** 机制（`PartyBeaconHost` / `PartyBeaconClient`），用于在正式连进服务器前"预约座位"。同样支持 OSS v1/v2 双分支。

**Lyra 怎么用**：Lyra 的 `TenkaichiGameInstance` 会继承或配合它做"主菜单 → 建房/搜房/加入 → 进地图"的完整流程。

## 三、辅助类（认脸即可）

### 1. `UCommonUserInfo`（继承 `UObject`）

> 文件：`CommonUserSubsystem.h`（定义在同一个文件里）

**干嘛的**：**单个用户的"信息卡"**。每个已初始化的本地玩家都有一个。

关键字段/方法：
- `PlatformUser`（平台用户 ID）、`LocalPlayerIndex`（本地玩家索引）、`bIsGuest`（是否游客）。
- `InitializationState`（初始化状态：登录中/在线/仅本地/失败）。
- `IsLoggedIn()` / `IsDoingLogin()`：是否已登录/正在登录。
- `GetCachedPrivilegeResult` / `GetPrivilegeAvailability`：查询某权限（能不能联机、能不能聊天）的结果。
- `GetNetId` / `GetNickname` / `SetNickname`：网络 ID 和昵称。
- 内部 `FCachedData` 结构缓存每个在线系统的网络 ID、昵称、权限结果。

> 类比：`UCommonUserInfo` = 一张"玩家名片"，子系统按名片管理每个登录进来的人。

---

### 2. `UCommonUserBasicPresence`（继承 `UGameInstanceSubsystem`）

> 文件：`CommonUserBasicPresence.h`

**干嘛的**：**在线状态（presence）推送**。把"玩家正在干嘛"（主菜单/匹配中/游戏中）推送到平台的在线状态系统，让好友看到。

关键点：
- 接在 `UCommonSessionSubsystem` 上，会话信息一变就 `OnNotifySessionInformationChanged`。
- 一堆 `Config` 字符串把"游戏内/主菜单/匹配中"映射到平台后端键。
- 注释明确说这是个"概念验证示例"，不是完整实现。

> 它是个可选的轻量模块，Lyra 里通常有自己的 presence 逻辑，这个主要作参考。

---

### 3. `UAsyncAction_CommonUserInitialize`（继承 `UCancellableAsyncAction`）

> 文件：`AsyncAction_CommonUserInitialize.h`

**干嘛的**：把 `UCommonUserSubsystem` 的初始化用户流程**包装成蓝图异步节点**。

关键点：
- 静态方法 `InitializeForLocalPlay`（本地游玩初始化）、`LoginForOnlinePlay`（在线登录），都是 `BlueprintCallable`。
- 完成时广播 `OnInitializationComplete` 委托。
- 让蓝图不用直接跟 C++ 子系统打交道，就能发起"登录 + 权限检查"。

---

### 4. 会话相关的三个请求/结果类

> 文件：`CommonSessionSubsystem.h`（都定义在这个文件里）

| 类 | 干嘛的 |
|----|--------|
| `UCommonSession_HostSessionRequest` | **建房请求**：存建房参数（在线模式、地图 ID、最大玩家数、额外参数），方法 `ConstructTravelURL` 拼出服务器转移 URL |
| `UCommonSession_SearchSessionRequest` | **搜房请求**：存搜索参数（在线模式、是否搜大厅），搜完结果填进 `Results` 数组 |
| `UCommonSession_SearchResult` | **单个搜到的房间**：`GetDescription` / `GetNumOpenPublicConnections` / `GetPingInMs` 等读取房间信息 |

> 类比：`HostSessionRequest` = 填一张"我要开房"的表；`SearchSessionRequest` = 填一张"我要找房"的表；`SearchResult` = 找到的每个房间的门牌信息。

---

### 5. `CommonUserTypes.h` 里的一堆枚举

> 文件：`CommonUserTypes.h`（纯枚举/结构体定义，无类）

这些枚举贯穿整个插件，描述"登录/权限"的各种状态：

| 枚举 | 干嘛的 |
|------|--------|
| `ECommonUserOnlineContext` | 指定在哪查在线信息：`Game`（游戏默认）/ `Service`（外部服务）/ `Platform`（平台）/ 以及各种 `OrDefault` 回退版本 |
| `ECommonUserInitializationState` | 用户初始化状态：`Unknown` / `DoingInitialLogin` / `DoingNetworkLogin` / `LoggedInOnline` / `LoggedInLocalOnly` / `FailedtoLogin` |
| `ECommonUserPrivilege` | 用户权限种类：`CanPlay` / `CanPlayOnline` / `CanCommunicateViaTextOnline` / `CanCommunicateViaVoiceOnline` / `CanUseUserGeneratedContent` / `CanUseCrossPlay` |
| `ECommonUserAvailability` | 某功能的总体可用性：`NowAvailable` / `PossiblyAvailable` / `CurrentlyUnavailable` / `AlwaysUnavailable` |
| `ECommonUserPrivilegeResult` | 权限被拒的具体原因：`UserNotLoggedIn` / `LicenseInvalid` / `VersionOutdated` / `AgeRestricted` / `AccountTypeRestricted` 等 |
| `ECommonUserAsyncTaskState` | 异步任务进度：`NotStarted` / `InProgress` / `Done` / `Failed` |

另外还有一个结构体 `FOnlineResultInformation`（`bWasSuccessful` + `ErrorId` + `ErrorText`），是各种在线操作结果的通用封装。

> 另外还有个 `FCommonUserTags` 结构体（也在 `CommonUserSubsystem.h` 里），定义了一组系统消息标签（`SystemMessage.Error` 等）和平台特征标签（`Platform.Trait.RequiresStrictControllerMapping` 等）。

## 四、模块入口

### `FCommonUserModule`（`CommonUserModule.h` / `.cpp`）

就是一个普通 UE 模块的入口类，实现 `StartupModule` / `ShutdownModule`，本身没什么游戏逻辑。

### `CommonUser.Build.cs`

依赖了 `OnlineSubsystem`（在线子系统）、`UMG`（UI）、`CommonUI` 等模块。注意它引入了 `COMMONUSER_OSSV1` 这个编译宏，用来在 OSS v1 / v2 两套 API 之间切换。

## 五、依赖关系小结（谁继承谁）

```
UGameInstanceSubsystem ← UCommonUserSubsystem
UGameInstanceSubsystem ← UCommonSessionSubsystem
UGameInstanceSubsystem ← UCommonUserBasicPresence
UObject                 ← UCommonUserInfo
UObject                 ← UCommonSession_HostSessionRequest
UObject                 ← UCommonSession_SearchSessionRequest
UObject                 ← UCommonSession_SearchResult
UCancellableAsyncAction ← UAsyncAction_CommonUserInitialize
IModuleInterface        ← FCommonUserModule
```

> 一句话总结：**CommonUser = 用户身份登录（UCommonUserSubsystem）+ 在线会话创建/搜索/加入（UCommonSessionSubsystem）+ 一堆描述这些流程的参数类、结果类、枚举**。它负责"人是谁、怎么连起来"，CommonGame 负责"玩家/会话的对象框架"——两者配合构成 Lyra 的联网地基。
