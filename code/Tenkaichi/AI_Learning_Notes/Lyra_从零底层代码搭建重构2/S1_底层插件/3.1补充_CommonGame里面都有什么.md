# 3.1 补充 —— CommonGame 插件里都有什么、都是干嘛的

> **归属**：阶段三 3.1（装 CommonGame/CommonUser 插件）的补充讲解。
> **目标**：把 CommonGame 插件里每个类"认个脸"——它们是什么、干嘛的、将来谁继承它。
> **源码依据**：`E:\ue5\game_design\code\Tenkaichi\Plugins\CommonGame\Source\Public\*.h`（真实查证，非凭印象）。
> **性质**：只认脸、不拆源码。这些是插件（不是要一比一还原的项目 Source），用到时再深讲。

## 一、一句话定位

CommonGame 是 Epic 提供的一套 **"通用 gameplay 基础类"**——它把"玩家、会话、UI 布局"这些每个游戏都要用的地基做成了可继承的基类。Lyra 就是站在这些基类上盖楼的。

核心是三大类 + 一套 UI 体系：

```
玩家/会话（被 Lyra 继承）
  UCommonGameInstance        ← 阶段五 LyraGameInstance 继承它
  ACommonPlayerController    ← 阶段四 LyraPlayerController 继承它
  UCommonLocalPlayer         ← 阶段四 LyraLocalPlayer 继承它

UI 体系（阶段六才用）
  UPrimaryGameLayout         主 UI 布局（分层管理所有界面）
  UGameUIManagerSubsystem    UI 管理器（抽象，游戏自己继承实现）
  UGameUIPolicy              UI 策略（决定分屏/多玩家怎么排界面）
  UCommonUIExtensions        UI 静态工具函数库（蓝图可调）
  UCommonMessagingSubsystem  弹窗/确认框子系统

辅助
  UCommonPlayerInputKey      输入按键管理（键盘/手柄/触摸）
  一组 AsyncAction（异步 UI 操作，蓝图节点）
```

## 二、玩家/会话三大类（阶段四、五会继承）

这三个是 CommonGame 最核心的"地基"，Lyra 的对应类直接继承它们。

### 1. `UCommonGameInstance`（继承 `UGameInstance`）

> 文件：`CommonGameInstance.h`

**干嘛的**：游戏实例的基类，负责**玩家初始化、会话（Session）流程、系统消息处理**。

关键能力（从真实源码看）：
- `AddLocalPlayer` / `RemoveLocalPlayer`：加/减本地玩家（重写引擎的）。
- `Init()`：初始化。
- `ReturnToMainMenu()`：返回主菜单。
- 处理**会话请求流程**：`OnUserRequestedSession` / `SetRequestedSession` / `CanJoinRequestedSession` / `JoinRequestedSession`（玩家从平台邀请加入某会话）。
- 处理**用户系统消息**：`HandleSystemMessage`、`HandlePrivilegeChanged`、`HandlerUserInitialized`（登录/权限变化时回调）。

**Lyra 怎么用**：阶段五的 `TenkaichiGameInstance` 继承它，加上 AssetManager 等游戏专属逻辑。

---

### 2. `ACommonPlayerController`（继承 `AModularPlayerController`）

> 文件：`CommonPlayerController.h`

**干嘛的**：玩家控制器基类。注意它继承的是 **`AModularPlayerController`**（来自你阶段二装的 `ModularGameplayActors` 插件），不是引擎原生的 `APlayerController`。

关键能力（重写了引擎的这些钩子）：
- `ReceivedPlayer()`：控制器被分配玩家时。
- `SetPawn()` / `OnPossess()` / `OnUnPossess()`：控制/释放 Pawn 时。
- `OnRep_PlayerState()`：PlayerState 网络复制到客户端时。

**Lyra 怎么用**：阶段四的 `TenkaichiPlayerController` 继承它，加上相机辅助、团队等。

---

### 3. `UCommonLocalPlayer`（继承 `ULocalPlayer`）

> 文件：`CommonLocalPlayer.h`

**干嘛的**：本地玩家基类。管理"一个本地玩家"的**控制器、PlayerState、Pawn** 三者的绑定。

关键能力：
- 三个委托：`OnPlayerControllerSet` / `OnPlayerStateSet` / `OnPlayerPawnSet`——当本地玩家被分配控制器/状态/Pawn 时广播。
- `GetRootUILayout()`：拿到这个玩家的主 UI 布局。
- `IsPlayerViewEnabled`：控制该玩家视角是否启用（分屏时用）。

**Lyra 怎么用**：阶段四的 `TenkaichiLocalPlayer` 继承它。

## 三、UI 体系（阶段六才用到，先认脸）

CommonGame 还带了一套完整的 **UI 布局管理框架**，Lyra 的 UI 全建在它上面。

### 1. `UPrimaryGameLayout`（继承 `UCommonUserWidget`）

> 文件：`PrimaryGameLayout.h`

**干嘛的**：**主 UI 布局**。把屏幕划分成一个个"层"（Layer，用 GameplayTag 标识，如 `UI.Layer.Game`、`UI.Layer.Menu`），往层里推入/弹出界面。

关键能力：
- `PushWidgetToLayerStack`：往某个层推入一个界面（支持异步加载）。
- `FindAndRemoveWidgetFromLayer`：从层里移除界面。
- `RegisterLayer`：注册一个层。
- 每个玩家（分屏时）各有一个自己的主布局。

> 类比：主布局 = 一块"公告板"，上面钉了多个"层"（游戏层、菜单层、弹窗层），UI 就是往对应层里贴纸条。

### 2. `UGameUIManagerSubsystem`（继承 `UGameInstanceSubsystem`）

> 文件：`GameUIManagerSubsystem.h`，**抽象类**（注释明确说"这个类要被你游戏自己的实现替换"）

**干嘛的**：UI 管理器，负责**创建/切换 UI 策略、通知玩家加入/离开**。

关键能力：
- `SwitchToPolicy`：切换 UI 策略。
- `NotifyPlayerAdded` / `NotifyPlayerRemoved` / `NotifyPlayerDestroyed`：玩家增减时通知。
- 抽象类，**游戏要自己继承实现**（Lyra 在 `System/` 里有自己的 UIManager）。

### 3. `UGameUIPolicy`（继承 `UObject`，抽象类）

> 文件：`GameUIPolicy.h`

**干嘛的**：UI 策略，决定**分屏/多玩家时界面怎么排**。

关键能力：
- `ELocalMultiplayerInteractionMode` 枚举：`PrimaryOnly`（只显示主玩家）/ `SingleToggle`（单屏可切换）/ `Simultaneous`（多屏同时显示）。
- `GetRootLayout` / `CreateLayoutWidget`：给每个本地玩家创建根布局。
- 被 `UGameUIManagerSubsystem` 持有。

### 4. `UCommonUIExtensions`（继承 `UBlueprintFunctionLibrary`）

> 文件：`CommonUIExtensions.h`

**干嘛的**：一堆**静态工具函数**（蓝图可调），处理"UI 和玩家输入"的关系。

关键能力：
- `GetOwningPlayerInputType` / `IsOwningPlayerUsingTouch` / `IsOwningPlayerUsingGamepad`：判断玩家输入类型。
- `PushContentToLayer_ForPlayer` / `PopContentFromLayer`：往玩家层推/弹内容。
- `SuspendInputForPlayer` / `ResumeInputForPlayer`：暂停/恢复玩家输入（弹 UI 时暂停游戏输入，关 UI 恢复）。

### 5. `UCommonMessagingSubsystem`（继承 `ULocalPlayerSubsystem`）

> 文件：`Messaging/CommonMessagingSubsystem.h`

**干嘛的**：**弹窗/确认框子系统**。管理"确认/错误"对话框。

关键能力：
- `ShowConfirmation`：显示确认框（返回 `Confirmed`/`Declined`/`Cancelled`）。
- `ShowError`：显示错误框。
- 配合 `UCommonGameDialogDescriptor`（对话框描述）和 `ECommonMessagingResult`（结果枚举）。

## 四、辅助类（认脸即可）

### `UCommonPlayerInputKey`（`CommonPlayerInputKey.h`）

**干嘛的**：**输入按键管理**。把"某个功能"映射到"键盘/手柄/触摸"具体哪个键，处理跨平台输入差异。文件较大（13.6KB），阶段六输入时再细讲。

### 一组 AsyncAction（`Actions/` 目录）

| 类 | 干嘛的 |
|----|--------|
| `AsyncAction_CreateWidgetAsync` | 异步创建 UI 控件（蓝图节点） |
| `AsyncAction_PushContentToLayerForPlayer` | 异步往玩家层推内容 |
| `AsyncAction_ShowConfirmation` | 异步显示确认框 |

这些是给蓝图用的"异步节点"，封装了上面的 UI 能力，让蓝图能方便地调。

## 五、依赖关系小结（谁继承谁）

```
UGameInstance              ← UCommonGameInstance          ←（阶段五）TenkaichiGameInstance
AModularPlayerController   ← ACommonPlayerController      ←（阶段四）TenkaichiPlayerController
ULocalPlayer               ← UCommonLocalPlayer           ←（阶段四）TenkaichiLocalPlayer

UCommonUserWidget          ← UPrimaryGameLayout
UGameInstanceSubsystem     ← UGameUIManagerSubsystem      ←（Lyra System/）LyraUIManager
UObject                    ← UGameUIPolicy
UBlueprintFunctionLibrary  ← UCommonUIExtensions
ULocalPlayerSubsystem      ← UCommonMessagingSubsystem
```

> 一句话总结：**CommonGame = 玩家会话地基（3 类）+ UI 布局框架（5 类）+ 输入/异步辅助**。Lyra 的玩家类和 UI 全站在它肩膀上。阶段四继承前 3 类，阶段六用后 5 类。
