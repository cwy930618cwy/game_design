## 一、这个类解决什么问题？

**把"相机模式栈"真正接到引擎的相机上**。前面教的 `UTenkaichiCameraMode` 是"计算相机该在哪"的纯逻辑，`CameraModeStack` 是"一堆模式混合成一张视图"的容器——但它们都还没接入实际渲染用的相机。

`UTenkaichiCameraComponent` 继承引擎的 `UCameraComponent`，做这件事：

| 做的事 | 类比 |
|--------|------|
| **① 每帧调用栈求最终视图**：`EvaluateStack` 得出最终相机位置/旋转/FOV | 导演喊"卡"前，把所有分镜叠成最终画面 |
| **② 把视图同步给控制器和相机组件**：`SetControlRotation` + `SetWorldLocationAndRotation` | 把导演决定的机位告诉掌机的人和机器 |
| **③ 提供"当前用哪个相机模式"的委托**：`DetermineCameraModeDelegate` 由外部绑定，决定栈顶该放什么模式 | 导演决定这一镜用什么镜头 |
| **④ 支持单帧 FOV 偏移**：`AddFieldOfViewOffset`（如瞄准时临时放大） | 特写镜头临时推进 |
| **⑤ 从 Actor 上找相机组件**：`FindCameraComponent` 静态工具 | 后勤查"这个演员的机器在哪" |

> 一句话：**`UCameraComponent` 是"引擎的相机槽"，`CameraModeStack` 是"算好的画面"，相机组件把两者接起来**。

## 二、全景（本类有哪些成员）

### 2.1 成员属性

| 成员 | 类型 | 干什么 |
|------|------|--------|
| `CameraModeStack` | `TObjectPtr<UTenkaichiCameraModeStack>` | 相机模式栈（P04.2-1），负责混合所有模式 |
| `FieldOfViewOffset` | `float` | 单帧 FOV 偏移（应用后清零） |
| `DetermineCameraModeDelegate` | `FTenkaichiCameraModeDelegate` | 委托，外部绑定"当前该用哪个相机模式" |

### 2.2 成员方法

| 方法 | 干什么 |
|------|--------|
| `FindCameraComponent(Actor)` | **静态工具**：在指定 Actor 上找相机组件 |
| `GetTargetActor()` | 返回相机看的 Actor（默认 = Owner） |
| `AddFieldOfViewOffset(FovOffset)` | 累加单帧 FOV 偏移 |
| `DrawDebug(Canvas)` | 调试绘制（showdebug） |
| `GetBlendInfo(Weight, Tag)` | 取栈顶模式权重 + 标签 |
| `OnRegister()` | **注册时**：创建相机模式栈 |
| `GetCameraView(DeltaTime, DesiredView)` | **核心，覆盖引擎**：每帧求最终视图并同步 |
| `UpdateCameraModes()` | 通过委托查询当前相机模式并压栈 |

### 2.3 委托类型

```cpp
DECLARE_DELEGATE_RetVal(TSubclassOf<UTenkaichiCameraMode>, FTenkaichiCameraModeDelegate);
```

> 返回"相机模式子类"的委托。外部（如角色 Pawn）绑定它，返回当前应该用的相机模式类型。
