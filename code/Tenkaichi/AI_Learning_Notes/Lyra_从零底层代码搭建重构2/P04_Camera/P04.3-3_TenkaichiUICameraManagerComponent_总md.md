## 一、这个类解决什么问题？

**作为一个内嵌组件，让 UI 能在"UI 正在做重要事情"时接管相机控制权**。它挂在 `PlayerCameraManager` 身上（`Within=LyraPlayerCameraManager` 强制约束），是相机的"副驾驶"：

| 做的事 | 类比 |
|--------|------|
| **① 挂在 PlayerCameraManager 上**：`UCLASS(Transient, Within=LyraPlayerCameraManager)` | 副驾驶座位固定在驾驶舱里 |
| **② 提供静态 `GetComponent(PC)`**：从玩家控制器找到 UI 相机组件 | 前台广播"副驾驶在哪" |
| **③ 提供 `SetViewTarget`**：让 UI 相机看向指定对象（并把目标转发给主相机管理器） | 副驾驶抢方向盘开向某处 |
| **④ 提供 `NeedsToUpdateViewTarget`**：问"副驾驶要不要接管" | 副驾驶举手"我来开" |
| **⑤ 提供 `UpdateViewTarget`**：UI 相机自己更新视图 | 副驾驶实际操作 |
| **⑥ `OnShowDebugInfo`**：showdebug 钩子 | showdebug 时能响应 |

> 一句话：**它是挂在玩家相机管理器上的一个组件，UI 需要时能接管相机（SetViewTarget），但目前是骨架（NeedsToUpdateViewTarget 直接返回 false，UpdateViewTarget 空实现）——真正的接管逻辑后续版本再补**。

> **⚠️ 重要**：P04.3-2 里 `UpdateViewTarget` 判断 `UICamera->NeedsToUpdateViewTarget()`，而本组件当前**直接 return false**——所以现在 UI 相机从不接管，走引擎默认。这是 Lyra 的真实骨架状态，一比一还原。

## 二、全景（本类有哪些成员）

### 2.1 类声明元数据

```cpp
UCLASS( Transient, Within=TenkaichiPlayerCameraManager )
class UTenkaichiUICameraManagerComponent : public UActorComponent
```

| 元数据 | 干什么 |
|--------|--------|
| `Transient` | 运行时组件，不序列化 |
| `Within=TenkaichiPlayerCameraManager` | **强约束**：只能作为 `PlayerCameraManager` 的子对象创建（不能随便挂到别的 Actor 上） |
| `: public UActorComponent` | 继承**引擎 Actor 组件** |
