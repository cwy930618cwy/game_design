## 〇、先给一个类比：把相机想成「电视台摄影棚」

| 摄影棚 | 相机系统 | 对应类 |
|--------|---------|--------|
| 📹 **一台摄像机 + 拍摄方案** | 相机模式（放哪、看哪、FOV 多少） | `TenkaichiCameraMode` |
| 🎚️ **导播台**（多个机位画面混合） | 相机模式栈（叠加多个模式，按权重混合） | `TenkaichiCameraModeStack` |
| 🎬 **一套具体拍法**（跟拍第三人称） | 第三人称相机模式 | `TenkaichiCameraMode_ThirdPerson` |
| 📡 **摄像机本体**（装在摇臂上） | 相机组件（挂在角色身上） | `TenkaichiCameraComponent` |
| 📏 **探杆**（探测会不会撞到墙） | 防穿透探针 | `FLyraPenetrationAvoidanceFeeler` |
| 🎛️ **总控台**（切换/接管信号） | 玩家相机管理器 | `ALyraPlayerCameraManager` |
| 🖼️ **广告插播**（临时抢画面） | UI 相机组件 | `UTenkaichiUICameraManagerComponent` |
| 📜 **穿墙规则手册**（哪些能穿） | 相机辅助接口 | `ITenkaichiCameraAssistInterface` |

> **一句话**：Lyra 用「**相机模式栈 + 第三人称模式 + 防穿墙探针**」搭了一套**可配置、可叠加、防穿模**的第三人称相机，替换 UE 默认相机。

## 一、核心概念图：相机模式栈（⭐ 理解了它就理解了 P04）

```
                     TenkaichiCameraComponent（挂在角色身上）
                                  │
                                  │ 每帧问一次："现在该怎么看？"
                                  ▼
                    ┌──────────────────────────┐
                    │   CameraModeStack 模式栈    │
                    │  （像 Photoshop 图层）       │
                    └────────────┬─────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        ▼                        ▼                        ▼
  ┌──────────┐            ┌──────────┐            ┌──────────┐
  │ 模式 A   │            │ 模式 B   │            │ 模式 C   │
  │ 第三人称  │            │ 瞄准     │            │ 过场     │
  │ 权重 1.0 │            │ 权重 0.6 │            │ 权重 0.0 │
  └────┬─────┘            └────┬─────┘            └────┬─────┘
       │                       │                       │
       │ 各自算出自己的：位置 / 旋转 / FOV / 过渡速度        │
       │                       │                       │
       └───────────────────────┼───────────────────────┘
                               ▼
                    ⚖️ 按权重混合（Blend）
                               │
                               ▼
                    最终视图 FMinimalViewInfo
                               │
                               ▼
                  PlayerCameraManager 应用给玩家
```

**为什么要"栈"而不是"一个模式"？**
因为游戏里经常要**同时**满足多个需求：

- 正常走路 → 第三人称模式
- 举枪瞄准 → **叠加**一个瞄准模式（镜头拉近、FOV 变小）
- 播过场动画 → **临时压上**一个过场模式

如果是"一个模式"，就得写个巨大的 `if-else`；用**栈**就是各自算各自的、按权重混合，**干净且可扩展**。

## 五、常见混淆点（你晕大概晕在这）

| 容易混 | 区别 |
|--------|------|
| **`CameraMode` vs `CameraModeStack`** | `Mode` 是**一个算法**（第三人称怎么算）；`Stack` 是**容器**（装一堆 Mode 并按权重混合）。**同一个 `.h` 文件里** |
| **`CameraMode` vs `CameraComponent`** | `Mode` 是**算法/数据**（不算视图）；`Component` 是**挂在角色上的执行者**（每帧驱动 Stack 算视图） |
| **`CameraComponent` vs `PlayerCameraManager`** | `Component` 在**角色身上**（跟角色走）；`Manager` 在**玩家控制器层**（全局，决定最终用哪个视图） |
| **`PlayerCameraManager` vs `UICameraManagerComponent`** | 前者是**常态总控**；后者是**临时抢镜头**（过场/菜单时盖掉它） |
| **`PenetrationAvoidanceFeeler` vs `CameraAssistInterface`** | `Feeler` 是**探针参数**（射线怎么打）；`AssistInterface` 是**规则**（哪些东西允许被穿透） |
| **`CameraMode_ThirdPerson` 为什么最复杂** | 它要干三件事：跟随目标 + 视角偏移 + **防穿墙**（用 Feeler + AssistInterface） |

## 六、记忆口诀（4 句）

1. **模式栈是灵魂** —— 多个相机模式像图层一样叠加混合。
2. **`Mode` 是算法，`Component` 是执行者** —— 别混。
3. **`Manager` 在玩家层，`Component` 在角色层** —— 层级不同。
4. **P04 零挂起** —— 全靠引擎 + 文件夹内部引用，不碰 GAS。
