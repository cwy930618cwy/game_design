### 1.2 UINTERFACE 模板类


| 行 | 干什么 |
|----|--------|
| `UINTERFACE(BlueprintType)` | 声明这是一个 UE 接口，且**标记为蓝图可用**（BlueprintType） |
| `class UTenkaichiCameraAssistInterface : public UInterface` | 这个 `U` 开头的类是 UHT 的"接口模板类"，**不是真接口** |
| `GENERATED_BODY()` | UHT 宏，生成反射代码 |

> 关键：**U 开头的类是"模板"，I 开头的类才是真接口**。UE 接口 = `UINTERFACE` + 一对 `U`/`I` 类。这个模板类体是空的，只是 UHT 需要它来登记"这是个接口"。

### 1.4 方法 1 —— 允许穿透的 Actor 列表

```cpp
	// 获取"允许相机穿透"的 Actor 列表。第三人称相机跟随时，用来忽略掉 view target、Pawn、载具等一堆不该挡镜头的对象。
	virtual void GetIgnoredActorsForCameraPentration(TArray<const AActor*>& OutActorsAllowPenetration) const { }
```

| 段 | 干什么 |
|----|--------|
| `virtual void ... const` | 纯虚接口方法（返回 void），`const` 表示不修改状态 |
| `TArray<const AActor*>& OutActorsAllowPenetration` | **输出参数**：调用方传一个空数组进来，实现者往里填"允许被相机穿透的 Actor" |
| `{ }` | 空实现——不实现时，就是"不额外忽略任何 Actor" |

> 类比：**"给我一份可以穿过我的名单"**——实现者往名单里塞一堆 Actor（角色/载具），相机就不会被它们挡了。用**输出引用参数**（`&`）而不是返回值，是 UE 里避免拷贝大数组的常见写法。

### 1.5 方法 2 —— 禁止穿透的目标

```cpp
	// 返回"绝不能穿透"的目标 Actor。正常情况下几乎总是 view target（未实现时默认保持 true）。
	// 但有时 view target 和你要始终框在画面里的根 Actor 不是同一个。
	virtual TOptional<AActor*> GetCameraPreventPenetrationTarget() const
	{
		return TOptional<AActor*>();
	}
```

| 段 | 干什么 |
|----|--------|
| `virtual TOptional<AActor*> ... const` | 返回一个"可选"的 Actor 指针 |
| `TOptional<AActor*>` | **可空包装**：可能没有值（空），也可能有值 |
| `return TOptional<AActor*>()` | 默认返回空——表示"没指定特别目标，就用默认的 view target" |
| `TOptional` | 引擎的"可选值"容器，语义上区分"没有值"和"值为空指针" |

> 类比：**"哪个是绝不能被镜头穿过的宝贝？"**——默认没指定（返回空），就用系统默认的 view target；如果 view target 不是那个关键的根 Actor，就返回那个根 Actor。`TOptional` 让"没有"和"空指针"两种状态清晰分开。
