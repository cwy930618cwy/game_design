## 一、这个 `.h` 解决什么问题（为什么）

声明一个**蓝图函数库** `UTenkaichiDevelopmentStatics`——把"开发调试"用的一批静态函数暴露给蓝图。

两个作用：
1. **给蓝图查"开发设置"开关**：跳过开场/加载背景/机器人攻击（这三个依赖 P18 Settings，但 `.h` 里只是声明，不 include Settings，所以 `.h` 不挂起）。
2. **给 cheat/命令按名字查类**：找 PIE 服务器世界、按短名找类/蓝图。

> 🔑 **一句话**：蓝图函数库 = 一堆 `static` 函数，蓝图里直接当全局函数拖出来用，无需实例。

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

// 蓝图函数库基类：让静态函数能被蓝图调用
#include "Kismet/BlueprintFunctionLibrary.h"
// TSubclassOf 模板：保存"某个类的子类"引用
#include "Templates/SubclassOf.h"

// 生成头文件（UHT 用，放最后）
#include "TenkaichiDevelopmentStatics.generated.h"

// 前置声明（.h 里只需要声明，不展开头文件）
class UClass;
class UObject;
class UWorld;
struct FAssetData;
struct FFrame;

UCLASS()
class UTenkaichiDevelopmentStatics : public UBlueprintFunctionLibrary
{
	GENERATED_BODY()

public:
	// 游戏逻辑是否应跳过开场直接进玩法（跳过热身/等待玩家等环节）。
	// 除"在编辑器里玩且 bTestFullGameFlowInPIE（见 Lyra 开发设置）为假"外，恒返回 false。
	UFUNCTION(BlueprintCallable, Category="Tenkaichi")
	static bool ShouldSkipDirectlyToGameplay();

	// 游戏逻辑是否应在编辑器里加载外观背景？
	// 除"在编辑器里玩且 bSkipLoadingCosmeticBackgroundsInPIE（见 Lyra 开发设置）为真"外，恒返回 true。
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi", meta=(ExpandBoolAsExecs="ReturnValue"))
	static bool ShouldLoadCosmeticBackgrounds();

	// 机器人（Bot）是否允许攻击？
	// 除"在编辑器里玩且 bAllowPlayerBotsToAttack（见 Lyra 开发设置）为真"外，恒返回 true。
	UFUNCTION(BlueprintCallable, Category = "Tenkaichi")
	static bool CanPlayerBotsAttack();

	// 找出最适合在"服务器"上跑 cheat 的 play-in-editor 世界。
	//   单机时可能是唯一世界、监听服务器，或专用服务器。
	static UWorld* FindPlayInEditorAuthorityWorld();

	// 尝试按短名找一个类（带一些启发式规则，提升通过 cheat 控制台使用的易用性）。
	static UClass* FindClassByShortName(const FString& SearchToken, UClass* DesiredBaseClass, bool bLogFailures = true);

	// 按短名找类的模板重载：自动用 DesiredClass 的类型做基类。
	template <typename DesiredClass>
	static TSubclassOf<DesiredClass> FindClassByShortName(const FString& SearchToken, bool bLogFailures = true)
	{
		return FindClassByShortName(SearchToken, DesiredClass::StaticClass(), bLogFailures);
	}

private:
	// 扫描资产注册表，拿到所有蓝图资产。
	static TArray<FAssetData> GetAllBlueprints();
	// 按名字找一个蓝图生成类。
	static UClass* FindBlueprintClass(const FString& TargetNameRaw, UClass* DesiredBaseClass);
};
```

## 三、逐段拆解

### include 区 + 前置声明

```cpp
#include "Kismet/BlueprintFunctionLibrary.h"
#include "Templates/SubclassOf.h"
#include "TenkaichiDevelopmentStatics.generated.h"

class UClass;
class UObject;
class UWorld;
struct FAssetData;
struct FFrame;
```

| 行 | 干什么 |
|----|--------|
| `#include "Kismet/BlueprintFunctionLibrary.h"` | 引擎蓝图函数库基类——`UTenkaichiDevelopmentStatics` 继承它，静态函数才能进蓝图 |
| `#include "Templates/SubclassOf.h"` | `TSubclassOf` 模板：`FindClassByShortName` 模板重载的返回类型 |
| `#include "TenkaichiDevelopmentStatics.generated.h"` | UHT 生成的反射代码 |
| `class UClass; ...` 前置声明 | `UClass`/`UObject`/`UWorld`/`FAssetData`/`FFrame` 只需声明 |

> **为什么蓝图函数库要用 `UBlueprintFunctionLibrary` 基类？** 这是引擎提供的"静态函数进蓝图"的基类。`UCLASS()` 普通 UObject 类的 `static` 函数不会自动出现在蓝图节点里，继承 `UBlueprintFunctionLibrary` + 函数标 `UFUNCTION(BlueprintCallable)` 后，蓝图就能搜到这些函数。

### UCLASS —— 类头 + 3 个 Settings 相关函数（组 A）

```cpp
UCLASS()
class UTenkaichiDevelopmentStatics : public UBlueprintFunctionLibrary
{
	GENERATED_BODY()

public:
	UFUNCTION(BlueprintCallable, Category="Tenkaichi")
	static bool ShouldSkipDirectlyToGameplay();

	UFUNCTION(BlueprintCallable, Category = "Tenkaichi", meta=(ExpandBoolAsExecs="ReturnValue"))
	static bool ShouldLoadCosmeticBackgrounds();

	UFUNCTION(BlueprintCallable, Category = "Tenkaichi")
	static bool CanPlayerBotsAttack();
```

| 行 | 干什么 |
|----|--------|
| `UCLASS()` | 无修饰，普通函数库 |
| `class UTenkaichiDevelopmentStatics : public UBlueprintFunctionLibrary` | 继承蓝图函数库 |
| `UFUNCTION(BlueprintCallable, ...)` | 蓝图可调用（静态函数） |
| `Category="Tenkaichi"` | 蓝图搜索分类（`Lyra`→`Tenkaichi`） |
| `meta=(ExpandBoolAsExecs="ReturnValue")` | 蓝图里把 `bool` 返回值拆成"真/假"两个执行引脚（更直观） |
| 三个函数 | 都查 `UTenkaichiDeveloperSettings`（P18），**仅 `.cpp` 挂起，`.h` 声明不影响编译** |

> **`ExpandBoolAsExecs="ReturnValue"` 是什么？** 默认蓝图函数返回 `bool` 时是一个"返回值"节点。加上这个 meta，蓝图里会变成**两个执行输出引脚（True / False）**，调用后直接分流——非常适合"是否加载背景"这种分支判断。

> **这三个函数 `.h` 为什么不挂起？** 挂起看 `.cpp` 的硬调用（铁律 30）。`.h` 只是声明 `static bool ShouldSkipDirectlyToGameplay();`，根本没 include `TenkaichiDeveloperSettings.h`，编译完全不需要它。**只有 `.cpp` 里 `GetDefault<UTenkaichiDeveloperSettings>()` 才依赖 P18**。

### 组 B：类/世界查找函数（全引擎，可编译）

```cpp
	static UWorld* FindPlayInEditorAuthorityWorld();

	static UClass* FindClassByShortName(const FString& SearchToken, UClass* DesiredBaseClass, bool bLogFailures = true);

	template <typename DesiredClass>
	static TSubclassOf<DesiredClass> FindClassByShortName(const FString& SearchToken, bool bLogFailures = true)
	{
		return FindClassByShortName(SearchToken, DesiredClass::StaticClass(), bLogFailures);
	}

private:
	static TArray<FAssetData> GetAllBlueprints();
	static UClass* FindBlueprintClass(const FString& TargetNameRaw, UClass* DesiredBaseClass);
```

| 行 | 干什么 |
|----|--------|
| `FindPlayInEditorAuthorityWorld()` | 找 PIE 服务器世界（单机/监听/专用服务器优先） |
| `FindClassByShortName(SearchToken, DesiredBaseClass, bLogFailures)` | 按短名找类，需指定"期望基类"，失败可选是否打日志 |
| `template <typename DesiredClass> FindClassByShortName(...)` | **模板重载**：自动用 `DesiredClass::StaticClass()` 当基类，调用更省事 |
| `private: GetAllBlueprints()` | 私有——扫描资产注册表拿所有蓝图（内部辅助） |
| `private: FindBlueprintClass(...)` | 私有——按名字找蓝图生成类（内部辅助） |

> **`private` 函数为什么也有？** `GetAllBlueprints`/`FindBlueprintClass` 是内部实现细节，只在 `.cpp` 里被 `FindClassByShortName` 调用，所以放 `private`——外部（含蓝图）用不到，但蓝图函数库的私有静态函数一样能实现功能。

> **`template <typename DesiredClass>` 是模板重载**：`FindClassByShortName` 有两个版本——一个要手动传 `UClass* DesiredBaseClass`，一个用模板自动拿。调用 `FindClassByShortName<UMyClass>("Name")` 时，编译器自动展开成传 `UMyClass::StaticClass()`。模板重载**定义在 `.h` 里**（`.cpp` 只实现非模板版本），所以模板版本在 `.h` 里就有函数体。
