## 一、这个文件解决什么问题（为什么）

`GameData` 是一个**"全局游戏数据"资产**——它是一份**不可变（Non-mutable）数据资产**，存放全游戏通用的"默认玩法数据"，供任何系统读取。

**为什么需要它？** 有些数据是全游戏共用的，不属于某个角色、某个关卡：
- 通用的**伤害**玩法效果（Damage Gameplay Effect）
- 通用的**治疗**玩法效果（Heal Gameplay Effect）
- 通用的**动态标签**玩法效果（Dynamic Tag Gameplay Effect）

这些不写死在代码里，而是做成一份**数据资产**，策划/开发者能在编辑器里配置，代码运行时读取。`GameData` 就是装这些的"总配置文件"。

> 🔑 **一句话**：`GameData` = 一份"全局配置数据资产"，里面放几个通用玩法效果（伤害/治疗/动态标签），代码里任何地方都能通过 `GameData::Get()` 拿到它。


## 四、新知识点预告（教到时会拆开讲）

1. **`UPrimaryDataAsset`**：能被 `UAssetManager` 管理的资产基类（区别于普通 `UDataAsset`）。
2. **`TSoftClassPtr<UGameplayEffect>`**：**软类引用**——引用一个"类"但不加载它，用到时才异步加载。
3. **`SetByCaller`**：玩法效果里用"调用方动态传值"的方式设定数值（伤害/治疗量由调用方给，不写死在资产里）。
4. **`#define UE_API` / `LYRAGAME_API`**：模块导出宏，控制类/函数的 DLL 可见性。
5. **`Get()` 静态方法 + AssetManager**：全局单例式获取数据资产（依赖 P14）。
6. **`UGameplayEffect`**：GAS 玩法效果类（P05 才详教，这里只当"被引用的类型"）。
