## 一、这个 `.h` 解决什么问题（为什么）

`.h` 声明一份**"全局游戏数据"资产** `UTenkaichiGameData`——存全游戏通用的"默认玩法效果"（伤害/治疗/动态标签），供任何系统运行时读取。

核心是两件事：
1. **数据成员**：3 个软类引用（`TSoftClassPtr<UGameplayEffect>`），分别指向伤害/治疗/动态标签效果。软引用 = 不强制加载，用到才异步加载。
2. **获取方式**：静态 `Get()` 返回这份数据的引用（依赖 AssetManager，`.cpp` 挂起）。

> 🔑 **一句话**：`.h` 定义"全局游戏数据"资产类，里面放 3 个通用玩法效果的软类引用，任何系统都能 `GameData::Get()` 拿到。

## 三、逐段拆解（先讲清为什么，再给代码）

### include 区 + 宏 + 前置声明

```cpp
#include "Engine/DataAsset.h"
#include "TenkaichiGameData.generated.h"

#define UE_API TENKAICHIGAME_API

class UGameplayEffect;
class UObject;
```

| 行 | 干什么 |
|----|--------|
| `#include "Engine/DataAsset.h"` | 引擎数据资产基类——`UPrimaryDataAsset` 在这里定义，`UTenkaichiGameData` 继承它 |
| `#include "TenkaichiGameData.generated.h"` | UHT 生成的反射代码（文件名带前缀 `Tenkaichi`） |
| `#define UE_API TENKAICHIGAME_API` | **模块导出宏**：本文件里 `UE_API` 都替换成 `TENKAICHIGAME_API`（类/方法要导出给其他模块用） |
| `class UGameplayEffect;` | GAS 玩法效果类前置声明（软类引用只需声明） |
| `class UObject;` | `UObject` 前置声明 |

> **`#define UE_API` 是干嘛的？** `UE_API` 在引擎里默认是"当前模块的导出宏"。这里 `#define UE_API TENKAICHIGAME_API` 把它重定义成我们 `TenkaichiGame` 模块的 API 宏，然后 `#undef UE_API` 结尾撤销。这样文件里 `UE_API` 前缀的方法/类就会被**导出给其他模块**用（比如 `Get()` 要在别处调用）。第 0 步已建模块 API 宏 `TENKAICHIGAME_API`。

> **为什么软类引用不用 include `UGameplayEffect.h`？** `TSoftClassPtr<T>` 内部只存一个"类路径字符串"，**不需要 `T` 的完整定义**，只要前置声明 `class UGameplayEffect;` 就够——这就是铁律 30 说的"软引用不阻塞编译"。只有真正加载那个类时才需要完整头文件。

### UCLASS —— UTenkaichiGameData 类头

```cpp
UCLASS(MinimalAPI, BlueprintType, Const, Meta = (DisplayName = "Tenkaichi Game Data", ShortTooltip = "Data asset containing global game data."))
class UTenkaichiGameData : public UPrimaryDataAsset
{
	GENERATED_BODY()

public:
	UE_API UTenkaichiGameData();
	static UE_API const UTenkaichiGameData& Get();
```

| 行 | 干什么 |
|----|--------|
| `UCLASS(MinimalAPI, ...)` | `MinimalAPI`：类**自身**只导出必要 API，其他模块能实例化/继承但访问成员受限（配合 `UE_API` 精确控制） |
| `BlueprintType` | 蓝图里可作为变量类型使用 |
| `Const` | 数据不可变——读取用，不修改 |
| `DisplayName = "Tenkaichi Game Data"` | 编辑器里显示的名字（`Lyra`→`Tenkaichi`） |
| `class UTenkaichiGameData : public UPrimaryDataAsset` | 继承**主数据资产**基类（可被 AssetManager 管理） |
| `UE_API UTenkaichiGameData();` | 构造函数（`UE_API` 导出，`.cpp` 空实现） |
| `static UE_API const UTenkaichiGameData& Get();` | **静态获取**：返回已加载的全局游戏数据（`.cpp` 依赖 AssetManager，届时挂起） |

> **`UPrimaryDataAsset` vs `UDataAsset`**：`UDataAsset` 是普通数据资产；`UPrimaryDataAsset` 是**能被 `UAssetManager` 按类型扫描/管理的"主资产"**——`GetGameData()` 就是从 AssetManager 里按类型找它。这是 `GameData` 能被全局获取的基础。

### 三个数据成员

```cpp
UPROPERTY(EditDefaultsOnly, Category = "Default Gameplay Effects", meta = (DisplayName = "Damage Gameplay Effect (SetByCaller)"))
TSoftClassPtr<UGameplayEffect> DamageGameplayEffect_SetByCaller;

UPROPERTY(EditDefaultsOnly, Category = "Default Gameplay Effects", meta = (DisplayName = "Heal Gameplay Effect (SetByCaller)"))
TSoftClassPtr<UGameplayEffect> HealGameplayEffect_SetByCaller;

UPROPERTY(EditDefaultsOnly, Category = "Default Gameplay Effects")
TSoftClassPtr<UGameplayEffect> DynamicTagGameplayEffect;
```

| 行 | 干什么 |
|----|--------|
| `UPROPERTY(EditDefaultsOnly, ...)` | 仅可在**类默认值**里编辑（实例上不让改）——符合"全局不可变配置" |
| `Category = "Default Gameplay Effects"` | 编辑器属性分类 |
| `meta = (DisplayName = "...")` | 编辑器显示名（第一个标了 SetByCaller，提示伤害/治疗数值靠调用方传） |
| `TSoftClassPtr<UGameplayEffect> Xxx` | **软类引用**：指向一个 `UGameplayEffect` 子类，但不强制加载（用到才异步加载） |
| 三个成员 | `DamageGameplayEffect_SetByCaller` 伤害 / `HealGameplayEffect_SetByCaller` 治疗 / `DynamicTagGameplayEffect` 动态标签 |

> **`SetByCaller` 是什么？** 玩法效果（GameplayEffect）的伤害/治疗数值通常写在资产里固定。`SetByCaller` 则是**调用方（代码/蓝图）动态传值**——比如"这拳打多少伤害"由攻击方现场算好传进去，资产里只留一个占位。所以命名里带 `_SetByCaller` 后缀提醒用法。

> **为什么用 `TSoftClassPtr` 而不是直接 `UPROPERTY(EditDefaultsOnly)` 选类？** 软类引用不强制打包加载，AssetManager 能懒加载——游戏启动更快，只有实际用到伤害/治疗时才加载对应效果类。
