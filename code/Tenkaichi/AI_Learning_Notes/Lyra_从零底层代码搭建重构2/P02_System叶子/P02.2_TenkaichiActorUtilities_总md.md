## 一、这个类解决什么问题（为什么）

P02 开头说过：很多玩法事件在触发前，要先问"**我现在是服务器还是客户端？**"——因为"这个事件该不该在这端处理"取决于当前网络模式。

`ULyraActorUtilities` 就是干这件事的**一个极简工具库**：

> **给它一个 `UObject`（Actor 或 Component），它告诉你当前处于哪种网络模式（单机/纯服务器/监听服务器/客户端）。**

> 🔑 **一句话**：`ULyraActorUtilities` = 一个"**查网络模式**"的小函数库，只提供一个 `SwitchOnNetMode` 函数，配合蓝图 `Switch On` 节点按网络模式分支执行。

## 二、内部结构全景

```
UCLASS()  class ULyraActorUtilities : public UBlueprintFunctionLibrary
└─ GENERATED_BODY()
└─ UFUNCTION(BlueprintCallable, ...)  static EBlueprintExposedNetMode SwitchOnNetMode(const UObject* WorldContextObject)
     └─ 用 ENetMode（引擎枚举）判断：通过传入对象的 GetNetMode() 拿当前模式
     └─ 返回 EBlueprintExposedNetMode（本文件自定义的蓝图友好枚举）
```

涉及**两个枚举**（一个自定义、一个引擎自带）：
| 枚举 | 来源 | 值 | 说明 |
|------|------|----|------|
| `EBlueprintExposedNetMode` | **本文件自定义**（`UENUM()`） | `Standalone` / `DedicatedServer` / `ListenServer` / `Client` | 蓝图友好版（可 `Switch`） |
| `ENetMode` | **引擎自带**（`Actor.h`） | `NM_Standalone` / `NM_DedicatedServer` / `NM_ListenServer` / `NM_Client` | 引擎内部真实模式 |

> 为什么自定义一个枚举而不直接用引擎的 `ENetMode`？因为 `ENetMode` 的 `NM_*` 值不是连续的、蓝图 `Switch On Enum` 不便用；`ExpandEnumAsExecs=ReturnValue` 让蓝图端直接展开成"多分支执行节点"，用起来最顺。

## 四、新知识点预告（教到时会拆开讲）

1. **`UBlueprintFunctionLibrary`**（复用 P01.5）：静态函数暴露给蓝图。
2. **`ENetMode` / `GetNetMode()`**：引擎网络模式枚举——服务器/客户端/单机怎么判断。
3. **`UENUM()` + `enum class`**：蓝图友好的自定义枚举（C++ 枚举暴露给蓝图）。
4. **`UFUNCTION` 的 `meta=(WorldContext="WorldContextObject")`**：让蓝图端不用手动传 World 参数。
5. **`meta=(ExpandEnumAsExecs=ReturnValue)`**：把枚举返回值在蓝图里展开成"多分支执行"。
6. **`WorldContextObject` + `GetOuter()` 向上回溯**：兼容传 Actor / Component / 任意 UObject 的情况。
