## 二、整份 `.cpp` 一比一还原（照着写）

> **注释中文化**（铁律 21/28）：注释已翻成中文；代码本体（类名/函数/宏/枚举）与 Lyra 原样一字不差，只换了前缀。

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

// 先包含自己的 .h（里面声明了 SwitchOnNetMode）
#include "TenkaichiActorUtilities.h"

// 用到 AActor / UActorComponent 的 GetNetMode()，这是它们定义的地方
#include "GameFramework/Actor.h"

// UHT 生成的 .cpp 实现（对应 TenkaichiActorUtilities.generated.h）
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiActorUtilities)

// 根据传入的"世界上下文对象"判断当前是哪种网络模式，并返回蓝图友好的枚举
EBlueprintExposedNetMode UTenkaichiActorUtilities::SwitchOnNetMode(const UObject* WorldContextObject)
{
	// 先默认单机
	ENetMode NetMode = NM_Standalone;

	// 从传入对象一路向上找 Outer（外层宿主），直到找到能给出网络模式的 Actor 或 Component
	for (const UObject* TestObject = WorldContextObject; TestObject != nullptr; TestObject = TestObject->GetOuter())
	{
		// 如果是 Component：直接拿它的网络模式
		if (const UActorComponent* Component = Cast<const UActorComponent>(WorldContextObject))
		{
			NetMode = Component->GetNetMode();
			break;
		}
		// 否则如果是 Actor：拿 Actor 的网络模式
		else if (const AActor* Actor = Cast<const AActor>(WorldContextObject))
		{
			NetMode = Actor->GetNetMode();
			break;
		}
	}

	// 把引擎的 ENetMode 翻译成蓝图友好的 EBlueprintExposedNetMode
	switch (NetMode)
	{
	case NM_Client:
		return EBlueprintExposedNetMode::Client;
	case NM_Standalone:
		return EBlueprintExposedNetMode::Standalone;
	case NM_DedicatedServer:
		return EBlueprintExposedNetMode::DedicatedServer;
	case NM_ListenServer:
		return EBlueprintExposedNetMode::ListenServer;
	default:
		ensure(false);  // 理论到不了这，到了就断言提醒
		return EBlueprintExposedNetMode::Standalone;
	}
}
```

## 三、逐段讲解（每一段在干嘛）

### 段 1：头文件包含（1~8 行）
```cpp
#include "TenkaichiActorUtilities.h"
#include "GameFramework/Actor.h"
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiActorUtilities)
```
- 第 3 行：自己的 `.h`，里面声明了 `SwitchOnNetMode`。
- 第 6 行：`GameFramework/Actor.h`——`AActor` 和 `UActorComponent` 的 `GetNetMode()` 在这里定义。**`.cpp` 里硬调用它俩，所以必须包含**。
- 第 8 行：UHT 生成的 `.cpp` 实现，`UE_INLINE_GENERATED_CPP_BY_NAME` 是宏，名字必须跟类名一致。

### 段 2：`SwitchOnNetMode`（9~40 行）★ 核心
逻辑分三步：
1. **沿 Outer 链找网络模式**（12~24 行）：
   - 传入的 `WorldContextObject` 可能是 Actor、Component，也可能是更外围的对象（比如 Pawn 的 Outer 是它的 Owner）。
   - `GetOuter()` 沿"外层宿主"链向上走，每层试 `Cast` 成 Component 或 Actor，**第一个命中就拿它的 `GetNetMode()`** 并 `break`。
   - 这样不管传进来的是谁，只要它能向上追溯到某个 Actor/Component，就能拿到正确的网络模式。
2. **翻译枚举**（26~39 行）：把引擎 `ENetMode` 四个值一一对应到蓝图友好的 `EBlueprintExposedNetMode`。
3. **兜底**（36~38 行）：`default` 分支理论到不了，用 `ensure(false)` 断言提醒 + 返回 `Standalone`。

> 为什么要包一层？引擎的 `ENetMode` 是普通 enum，**不能直接给蓝图做 Switch**（值不连续、蓝图不认识）；`EBlueprintExposedNetMode` 是 `UENUM`，配合 `.h` 里的 `ExpandEnumAsExecs=ReturnValue`，就能在蓝图里当"分支节点"用了。

## 五、整体回顾：这份文件到底在做什么

把 `.h` + `.cpp` 合起来看，`TenkaichiActorUtilities` 是一个**纯工具类**（`UBlueprintFunctionLibrary`）：
- `.h` 声明枚举 + 静态函数 + 蓝图友好标记（`BlueprintCallable` / `ExpandEnumAsExecs`）。
- `.cpp` 实现 `SwitchOnNetMode`：沿 Outer 链找到网络模式，翻译成蓝图友好的枚举返回。
- 上层任何地方都能在蓝图里用它**快速判断"我现在是服务器还是客户端"**（比如 UI 要不要显示服务器专属按钮、客户端能不能执行某逻辑）。
- **无任何 GAS/角色体系依赖，独立可编译，无挂起**。
