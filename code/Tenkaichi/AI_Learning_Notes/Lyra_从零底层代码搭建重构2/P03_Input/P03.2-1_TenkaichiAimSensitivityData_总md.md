# P03.2-1 UTenkaichiAimSensitivityData —— 总 md（为什么 + 全景 + 依赖）

> P03.2 有两个类：`LyraAimSensitivityData`（本文件，先教，因为它被 InputModifiers 依赖）+ `LyraInputModifiers`。每个类都按铁律 35 建自己的总 md。

## 一、为什么要有这一节

**灵敏度数据资产**：把"手柄灵敏度档位"（枚举）映射到具体 **float 数值**（倍数）。

举个栗子：手柄上玩家调灵敏度，档位有 `Slow`（慢）/ `Normal`（普通）/ `Fast`（快）……这个数据资产就是一张"档位 → 数值"对照表：
- `Slow` → `0.5f`（移动是普通的一半）
- `Normal` → `1.0f`（普通）
- `Fast` → `1.5f`（是普通的 1.5 倍）

将来 P03.2 的 `InputModifierGamepadSensitivity`（手柄灵敏度修饰器）会**根据当前选的档位，查这张表拿到数值**，去缩放摇杆输入。

## 三、本文件里有什么（全景）

一个 `UPrimaryDataAsset`（数据资产，编辑器里配置）：

```cpp
UCLASS(MinimalAPI, BlueprintType, Const, Meta = (DisplayName = "...", ShortTooltip = "..."))
class UTenkaichiAimSensitivityData : public UPrimaryDataAsset
{
	// 查询：根据档位枚举，返回对应灵敏度数值（找不到返回 1.0f）
	UE_API const float SensitivtyEnumToFloat(const ELyraGamepadSensitivity InSensitivity) const;

	// 档位 → 数值 映射表（默认值由构造函数填充）
	UPROPERTY(EditAnywhere, BlueprintReadWrite)
	TMap<ELyraGamepadSensitivity, float> SensitivityMap;
};
```

## 四、两个关键点

1. **继承 `UPrimaryDataAsset`**（而非 `UDataAsset`）：`PrimaryDataAsset` 是"主数据资产"——它是游戏里一个**独立、可引用、可被 AssetManager 管理**的资产（P14 AssetManager 会用到）。`UDataAsset` 是更轻量的普通数据资产。这里用 `PrimaryDataAsset` 因为灵敏度表是全局共享的关键数据。
2. **`MinimalAPI` + `UE_API`**：Lyra 的模块导出宏模式——`MinimalAPI` 声明"最小可导出"，只有标了 `UE_API` 的成员（构造函数 + 查询函数）才对外导出，供其他模块调用。映射到 Tenkaichi 时 `LYRAGAME_API` → `TENKAICHIGAME_API`。
