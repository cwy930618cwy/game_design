# P03.1-2 `TenkaichiInputComponent` —— 总 md

## 一、本类要解决什么

P03.1 已经教了 `TenkaichiInputConfig`（**数据层**：把「输入动作 UInputAction」和「游戏标签 FGameplayTag」绑成一张表）。
但光有表没用——还得有人**把这张表真正接到 Enhanced Input 系统上去**。这件事就是 `UTenkaichiInputComponent` 干的。

一句话定位：

> **`UTenkaichiInputComponent` = 「输入绑定器」**：拿着 `InputConfig` 这张表，①把映射上下文登记进 LocalPlayer 的增强输入子系统，②把表里每条动作绑到具体 C++ 回调函数上，③提供统一的解绑入口。

它解决的问题（为什么不直接用引擎的 `UEnhancedInputComponent`）：

| 直接用引擎 `UEnhancedInputComponent` 的麻烦 | 本类的做法 |
|---|---|
| 每次绑动作都要手写 `BindAction(IA, TriggerEvent, this, &Func)`，动作多了散落一地 | 由 `InputConfig` 数据资产集中描述，代码只写一句 `BindNativeAction(..., InputTag, ...)` |
| 「技能输入」要绑按下 + 抬起两个事件，还要记录 handle 以便解绑 | `BindAbilityActions` 一次循环全绑完，handle 存进 `TArray<uint32>&` |
| 换 Pawn / 换 Experience 时要手动一个个解绑 | `RemoveBinds(TArray<uint32>&)` 一把清空 |

### 关键判断（铁律 31）

1. **`.h` 零挂起**：只 include 引擎头 + 已落盘的 `TenkaichiInputConfig.h`；`UEnhancedInputLocalPlayerSubsystem` / `UInputAction` / `UObject` 都是**前置声明**，不阻塞编译（铁律 30）。
2. **`.cpp` 函数体零挂起**：4 个函数（构造 / `AddInputMappings` / `RemoveInputMappings` / `RemoveBinds`）**只用了引擎 API**（`check`、`RemoveBindingByHandle`、`BindHandles.Reset()`）。Lyra 原文件虽然 include 了 `LyraLocalPlayer.h` 和 `LyraSettingsLocal.h`，但函数体里**一个符号都没用到**——是 Lyra 留下的冗余 include。
   - `Player/TenkaichiLocalPlayer.h`：工程**已落盘**（`Source/TenkaichiGame/Player/TenkaichiLocalPlayer.h`）→ 照写不挂起。
   - `Settings/TenkaichiSettingsLocal.h`：工程**未落盘**（P18 才教）→ 这一行 include 用 `// #include "Settings/TenkaichiSettingsLocal.h"` 注释挂起，登记注释备忘录，P18 就位时解开。
3. **两个模板函数写在 `.h` 里**（`BindNativeAction` / `BindAbilityActions`）：模板必须在头文件定义，所以 `.h` 有 72 行而不是 30 行——这是理解本文件结构的钥匙。

## 四、全景：本文件的 4 个成员 + 2 个模板

| 成员 | 位置 | 干嘛的 |
|------|------|--------|
| `UTenkaichiInputComponent(const FObjectInitializer&)` | `.cpp` | 构造函数（Lyra 里是空实现，留扩展位） |
| `AddInputMappings(InputConfig, InputSubsystem)` | `.cpp` | 把 InputConfig 的映射上下文加进增强输入子系统（Lyra 空实现） |
| `RemoveInputMappings(InputConfig, InputSubsystem)` | `.cpp` | 反向移除（Lyra 空实现） |
| `BindNativeAction<...>(...)` 模板 | `.h` | 按 **标签** 绑一条「原生输入」到回调函数 |
| `BindAbilityActions<...>(...)` 模板 | `.h` | 遍历「技能输入」表，按下/抬起各绑一次，handle 存进数组 |
| `RemoveBinds(TArray<uint32>&)` | `.cpp` | 按 handle 批量解绑并清空数组 |

> 🔑 **`Config = Input`**：类声明上的 `UCLASS(Config = Input)` 表示本类的 `UPROPERTY` 配置从 `DefaultInput.ini` 读（本类当前没有配置属性，是预留）。
