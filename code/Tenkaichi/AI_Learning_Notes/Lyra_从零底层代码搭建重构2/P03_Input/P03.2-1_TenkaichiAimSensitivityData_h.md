## 四、逐段讲解

### 1. 头文件

```cpp
#include "Engine/DataAsset.h"
#include "TenkaichiAimSensitivityData.generated.h"

#define UE_API TENKAICHIGAME_API

enum class ELyraGamepadSensitivity : uint8;

class UObject;
```

- `Engine/DataAsset.h`：提供 `UPrimaryDataAsset` 基类。
- `generated.h`：UHT 生成，放最后。
- `#define UE_API TENKAICHIGAME_API`：**导出宏**。UE 用 `UE_API` 控制模块对外导出符号。这里把它临时定义成当前模块的导出宏 `TENKAICHIGAME_API`（对应 `TenkaichiGame.Build.cs` 里自动生成的 `TENKAICHIGAME_API`），下面的成员标上 `UE_API` 就能被其他模块调用。末尾 `#undef UE_API` 用完即撤，避免污染。
- `enum class ELyraGamepadSensitivity : uint8;` —— **前置声明枚举**。只声明"存在这个枚举类型"，不展开它的成员。`.h` 里 `SensitivityMap` 只是用它做 `TMap` 的键（`.h` 不需要知道枚举有哪些档位就能声明这个类型），所以**不用 include 定义它的 P18 头文件**，可独立编译。
- `class UObject;` —— 给 UHT 用的前置声明。

> 注意：这里的枚举名仍写 `ELyraGamepadSensitivity`（不是 `Tenkaichi`）。因为这个枚举定义在 **P18 Settings 的 `TenkaichiSettingsShared.h`** 里，届时按铁律 24 会替换成 `Tenkaichi` 前缀。现在 P18 未教，`.h` 里先按 Lyra 原样写这个**前置声明**（枚举名本身是"声明引用"），等 P18 教 `TenkaichiSettingsShared.h` 时把定义处替换成 `ETenkaichiGamepadSensitivity`，这里的前置声明名也一并同步。这是"引用还没定义的枚举"——因为只是前置声明 + 指针/TMap 键，不阻塞编译。

### 2. 数据资产类 `UTenkaichiAimSensitivityData`

```cpp
UCLASS(MinimalAPI, BlueprintType, Const, Meta = (DisplayName = "Tenkaichi Aim Sensitivity Data", ShortTooltip = "Data asset used to define a map of Gamepad Sensitivty to a float value."))
class UTenkaichiAimSensitivityData : public UPrimaryDataAsset
{
	GENERATED_BODY()
	...
};
```

- `UCLASS(MinimalAPI, BlueprintType, Const, ...)`：
  - `MinimalAPI`：**最小 API 导出**——只导出标了 `UE_API` 的成员，减少编译依赖（只有别模块真正要调用的函数才导出）。
  - `BlueprintType`：能在蓝图里作为类型使用。
  - `Const`：不可变资产（运行时数据不改）。
  - `Meta = (DisplayName = "...", ShortTooltip = "...")`：编辑器里显示的名字和悬停提示（中文化文案）。
- 继承 `UPrimaryDataAsset`：**主数据资产**——游戏里独立、可引用、可被 AssetManager 管理的资产（P14 AssetManager 会用它加载）。比 `UDataAsset` 更"重"，适合全局共享的关键数据。

### 3. 构造函数 + 查询函数（标 `UE_API` 导出）

```cpp
UE_API UTenkaichiAimSensitivityData(const FObjectInitializer& ObjectInitializer);

UE_API const float SensitivtyEnumToFloat(const ELyraGamepadSensitivity InSensitivity) const;
```

- 构造函数：UE 反射类标准写法，实现填 `SensitivityMap` 默认表（`.cpp` 里写）。
- `SensitivtyEnumToFloat`：查询函数，输入档位枚举，返回对应数值。标 `UE_API` 导出，供其他模块（P03.2-2 InputModifiers 的 GamepadSensitivity 修饰器）调用。
- 都标 `UE_API` 因为 `MinimalAPI` 下只有带 `UE_API` 的成员才会导出。

### 4. 映射表

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite)
TMap<ELyraGamepadSensitivity, float> SensitivityMap;
```

- `TMap<ELyraGamepadSensitivity, float>`：**键=灵敏度档位枚举，值=数值**的映射表。
- `EditAnywhere`：编辑器里任何地方都能编辑（默认值填好后，编辑器里也能改档位对应的数值）。
- `BlueprintReadWrite`：蓝图可读可写。
- `protected`：表本身不直接暴露给外部改，通过查询函数访问（封装）。

## 五、几个要记住的点

1. **`UPrimaryDataAsset`**：主数据资产，能被 AssetManager 管理（P14 用）。
2. **`MinimalAPI` + `UE_API`**：最小导出 + 只导出需要的成员；`#define UE_API` / `#undef UE_API` 临时宏模式。
3. **前置声明枚举 `enum class ... : uint8;`**：`.h` 只需要类型名（TMap 键/指针），不用完整定义，可独立编译——这是"软引用"不阻塞编译的典型（铁律 30）。
4. **`TMap` 键值映射**：档位 → 数值。
5. **`EditAnywhere` + `BlueprintReadWrite`**：编辑器可编辑 + 蓝图可读写。
6. **`protected` 封装**：表不直接暴露，通过查询函数访问。
