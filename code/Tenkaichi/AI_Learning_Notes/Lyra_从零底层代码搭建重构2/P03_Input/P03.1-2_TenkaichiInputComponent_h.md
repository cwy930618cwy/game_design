# P03.1-2 `TenkaichiInputComponent` —— `.h` 声明层

## 一、本文件要解决什么

总 md 说了：本类是「输入绑定器」，把 `TenkaichiInputConfig` 那张表接进 Enhanced Input 系统。

这个 `.h` 有 **72 行**，但类声明只有 39 行——**多出来的 30 行是两个模板函数在头文件里的实现**。这是本文件结构的钥匙：

> 模板函数（`template<class UserClass, typename FuncType>`）**必须在头文件里给出完整实现**，否则别的 `.cpp` 实例化它时编译器看不到函数体 → 链接错误。
> 所以 `BindNativeAction` / `BindAbilityActions` 写在 `.h` 底部，而不是 `.cpp`。

## 三、完整代码（注释已中文化，前缀已替换）

新建文件：`Source/TenkaichiGame/Input/TenkaichiInputComponent.h`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "EnhancedInputComponent.h"
#include "TenkaichiInputConfig.h"

#include "TenkaichiInputComponent.generated.h"

class UEnhancedInputLocalPlayerSubsystem;
class UInputAction;
class UObject;


/**
 * UTenkaichiInputComponent
 *
 *	用于通过输入配置数据资产来管理输入映射与绑定的组件。
 */
UCLASS(Config = Input)
class UTenkaichiInputComponent : public UEnhancedInputComponent
{
	GENERATED_BODY()

public:

	UTenkaichiInputComponent(const FObjectInitializer& ObjectInitializer);

	// 把输入配置里的映射上下文登记进玩家的增强输入子系统
	void AddInputMappings(const UTenkaichiInputConfig* InputConfig, UEnhancedInputLocalPlayerSubsystem* InputSubsystem) const;
	// 把之前登记进去的映射上下文从增强输入子系统里移除
	void RemoveInputMappings(const UTenkaichiInputConfig* InputConfig, UEnhancedInputLocalPlayerSubsystem* InputSubsystem) const;

	// 按标签把一条「原生输入」绑定到回调函数上
	template<class UserClass, typename FuncType>
	void BindNativeAction(const UTenkaichiInputConfig* InputConfig, const FGameplayTag& InputTag, ETriggerEvent TriggerEvent, UserClass* Object, FuncType Func, bool bLogIfNotFound);

	// 遍历「技能输入」表，按下和抬起各绑一次，产生的绑定句柄存进 BindHandles 供后续解绑
	template<class UserClass, typename PressedFuncType, typename ReleasedFuncType>
	void BindAbilityActions(const UTenkaichiInputConfig* InputConfig, UserClass* Object, PressedFuncType PressedFunc, ReleasedFuncType ReleasedFunc, TArray<uint32>& BindHandles);

	// 按句柄批量解绑，然后清空句柄数组
	void RemoveBinds(TArray<uint32>& BindHandles);
};


template<class UserClass, typename FuncType>
void UTenkaichiInputComponent::BindNativeAction(const UTenkaichiInputConfig* InputConfig, const FGameplayTag& InputTag, ETriggerEvent TriggerEvent, UserClass* Object, FuncType Func, bool bLogIfNotFound)
{
	check(InputConfig);
	if (const UInputAction* IA = InputConfig->FindNativeInputActionForTag(InputTag, bLogIfNotFound))
	{
		BindAction(IA, TriggerEvent, Object, Func);
	}
}

template<class UserClass, typename PressedFuncType, typename ReleasedFuncType>
void UTenkaichiInputComponent::BindAbilityActions(const UTenkaichiInputConfig* InputConfig, UserClass* Object, PressedFuncType PressedFunc, ReleasedFuncType ReleasedFunc, TArray<uint32>& BindHandles)
{
	check(InputConfig);

	for (const FTenkaichiInputAction& Action : InputConfig->AbilityInputActions)
	{
		if (Action.InputAction && Action.InputTag.IsValid())
		{
			if (PressedFunc)
			{
				BindHandles.Add(BindAction(Action.InputAction, ETriggerEvent::Triggered, Object, PressedFunc, Action.InputTag).GetHandle());
			}

			if (ReleasedFunc)
			{
				BindHandles.Add(BindAction(Action.InputAction, ETriggerEvent::Completed, Object, ReleasedFunc, Action.InputTag).GetHandle());
			}
		}
	}
}
```

## 四、逐段讲解

### 1. include 区 + 前置声明

```cpp
#include "EnhancedInputComponent.h"
#include "TenkaichiInputConfig.h"

#include "TenkaichiInputComponent.generated.h"

class UEnhancedInputLocalPlayerSubsystem;
class UInputAction;
class UObject;
```

- **`EnhancedInputComponent.h`**：父类 `UEnhancedInputComponent` 所在，必须完整 include（继承要求完整类型）。
- **`TenkaichiInputConfig.h`**：P03.1 已落盘。必须完整 include——函数参数 `const UTenkaichiInputConfig*` 虽然只是指针，但模板实现里要访问 `InputConfig->AbilityInputActions` 成员。
- **`TenkaichiInputComponent.generated.h`**：UHT 生成头，**必须放在所有 include 的最后**（UHT 强制要求）。
- **三个前置声明**：`UEnhancedInputLocalPlayerSubsystem` / `UInputAction` / `UObject` 只作为**指针类型**出现在签名里，不需要完整定义 → 前置声明即可，**不阻塞编译**（铁律 30）。

> ⚠️ `UInputAction` 在模板实现里被用于 `const UInputAction* IA = ...`（只是声明指针变量，不解引用）→ 前置声明够用。

### 2. 类声明

```cpp
UCLASS(Config = Input)
class UTenkaichiInputComponent : public UEnhancedInputComponent
{
	GENERATED_BODY()

public:
	UTenkaichiInputComponent(const FObjectInitializer& ObjectInitializer);
	void AddInputMappings(const UTenkaichiInputConfig* InputConfig, UEnhancedInputLocalPlayerSubsystem* InputSubsystem) const;
	void RemoveInputMappings(const UTenkaichiInputConfig* InputConfig, UEnhancedInputLocalPlayerSubsystem* InputSubsystem) const;
	template<class UserClass, typename FuncType>
	void BindNativeAction(...);
	template<class UserClass, typename PressedFuncType, typename ReleasedFuncType>
	void BindAbilityActions(...);
	void RemoveBinds(TArray<uint32>& BindHandles);
};
```

- **`UCLASS(Config = Input)`**：本类的 `UPROPERTY` 配置从 `DefaultInput.ini` 读取。当前类里没有配置属性，是 Lyra 预留的扩展位。
- **继承 `UEnhancedInputComponent`**：拿到引擎增强输入组件的 `BindAction` / `RemoveBindingByHandle` 等能力。
- **`AddInputMappings` / `RemoveInputMappings` 是 `const` 成员函数**：签名尾巴带 `const`，表示"不改自己的成员变量"（`.cpp` 里 Lyra 是空实现，可见它只是预留钩子）。
- **两个模板函数**：参数用了 `UserClass` / `FuncType` / `PressedFuncType` / `ReleasedFuncType` 四个模板参数——这样调用方传 UFUNCTION、lambda、`TUniquePtr` 成员回调都能自动推导。
- **`TArray<uint32>& BindHandles`**：出参，收集绑定句柄供 `RemoveBinds` 用。

### 3. 模板一：`BindNativeAction`

```cpp
template<class UserClass, typename FuncType>
void UTenkaichiInputComponent::BindNativeAction(const UTenkaichiInputConfig* InputConfig, const FGameplayTag& InputTag, ETriggerEvent TriggerEvent, UserClass* Object, FuncType Func, bool bLogIfNotFound)
{
	check(InputConfig);
	if (const UInputAction* IA = InputConfig->FindNativeInputActionForTag(InputTag, bLogIfNotFound))
	{
		BindAction(IA, TriggerEvent, Object, Func);
	}
}
```

**干嘛的**：给一个「游戏标签」（比如 `InputTag.Move`），去 `InputConfig` 的 **NativeInputActions** 表里查出对应的 `UInputAction`，然后绑到 `Object` 的 `Func` 回调上。

逐行：
- `check(InputConfig)`：断言配置非空。注意是 `check` 不是 `checkf`——发布版会被编译掉（Shipping 下 `check` 不生效）。
- `FindNativeInputActionForTag(InputTag, bLogIfNotFound)`：P03.1 教过的函数，按标签查原生输入动作；`bLogIfNotFound=true` 时查不到会打日志。
- `BindAction(IA, TriggerEvent, Object, Func)`：**引擎** `UEnhancedInputComponent` 的方法，四参数版（不传标签）。
- 整个函数**没有 else**：查不到就静默跳过（除了可能打的日志）。

> 🔑 **为什么叫「Native」**：原生输入 = 不走 GAS 技能系统、由 C++ 直接处理的输入（如移动、看向）。对应 `InputConfig` 里的 `NativeInputActions` 数组。

### 4. 模板二：`BindAbilityActions`

```cpp
template<class UserClass, typename PressedFuncType, typename ReleasedFuncType>
void UTenkaichiInputComponent::BindAbilityActions(const UTenkaichiInputConfig* InputConfig, UserClass* Object, PressedFuncType PressedFunc, ReleasedFuncType ReleasedFunc, TArray<uint32>& BindHandles)
{
	check(InputConfig);

	for (const FTenkaichiInputAction& Action : InputConfig->AbilityInputActions)
	{
		if (Action.InputAction && Action.InputTag.IsValid())
		{
			if (PressedFunc)
			{
				BindHandles.Add(BindAction(Action.InputAction, ETriggerEvent::Triggered, Object, PressedFunc, Action.InputTag).GetHandle());
			}

			if (ReleasedFunc)
			{
				BindHandles.Add(BindAction(Action.InputAction, ETriggerEvent::Completed, Object, ReleasedFunc, Action.InputTag).GetHandle());
			}
		}
	}
}
```

**干嘛的**：遍历 `InputConfig` 的 **AbilityInputActions** 表，每条有效动作绑**两次**（按下 + 抬起），绑定句柄存进 `BindHandles`。

逐行：
- `for (const FTenkaichiInputAction& Action : InputConfig->AbilityInputActions)`：`const` 引用遍历，不拷贝。
- `Action.InputAction && Action.InputTag.IsValid()`：**双重校验**——动作指针非空 **且** 标签有效。任一条不满足就跳过（配置表里可能留空行）。
- `ETriggerEvent::Triggered` → 绑 `PressedFunc`：**触发中**（按下并持续）回调。
- `ETriggerEvent::Completed` → 绑 `ReleasedFunc`：**完成**（抬起）回调。
- `BindAction(..., Action.InputTag)`：**五参数版**——比 `BindNativeAction` 的调用多传了 `Action.InputTag`。引擎会把它存进绑定的 `FEnhancedActionKeyMapping`，之后回调能拿到"是哪个标签触发的"。
- `.GetHandle()`：`BindAction` 返回 `FEnhancedInputActionEventBinding`，取它的 `uint32` 句柄 → 存进 `BindHandles`，供 `RemoveBinds` 解绑。
- `if (PressedFunc)` / `if (ReleasedFunc)`：回调为空就不绑那一半——允许只绑按下不绑抬起。

> 🔑 **与 `BindNativeAction` 的两个区别**：① 遍历整表 vs 查一条；② 绑两次（Triggered + Completed）vs 绑一次（调用方指定 TriggerEvent）。

## 五、几个要记住的点

1. **模板函数必须写在 `.h` 里**——这是本文件 72 行而不是 39 行的唯一原因。放到 `.cpp` 会链接报错。
2. **`BindAction` 有 4 参 / 5 参两个重载**：4 参（不带标签）给原生输入；5 参（带标签）给技能输入，标签会随绑定传递下去。
3. **`ETriggerEvent::Triggered` = 按下/持续，`Completed` = 抬起**：技能输入成对绑这两个。
4. **`check(InputConfig)` 而非 `ensure`**：参数契约问题（调用方传空是 bug），Shipping 版编译掉。
5. **`BindHandles` 是出参**（`TArray<uint32>&`）：调用方持有它，换 Pawn / 换 Experience 时调 `RemoveBinds` 一把清。
6. **`.h` 零挂起**：只依赖引擎 `EnhancedInputComponent.h` + 已落盘的 `TenkaichiInputConfig.h`，三个前置声明不阻塞编译 → **可直接编译通过**。
