# P03 Input —— 一张图看懂（全局总结 / 反晕眩版）

> **这份 md 的定位**：P03 教了 8 个类，名字都带 `Input`，很容易混成一片。
> 这份不讲怎么教，只讲「**一个按键是怎么走到游戏逻辑的**」——用链路把 8 个类串成一条流水线。
> 想看细节 → 回到各自 `总md / _h / _cpp`。

---

## 〇、先给一个类比：把输入想成「自来水厂」

| 水厂环节 | 输入系统环节 | 对应类 |
|---------|------------|--------|
| 🚰 **水源（河水）** | 玩家按键盘/手柄 | 引擎 `EnhancedInput` |
| 📋 **调度表**（这根管子通哪户） | 输入动作 ↔ 游戏标签 的映射表 | `TenkaichiInputConfig` |
| 🔌 **总阀门/管道** | 把映射表接到系统上 | `TenkaichiInputComponent` |
| 🧪 **过滤净化**（调水压/除杂质） | 输入修饰器（死区/灵敏度/反转） | `TenkaichiInputModifiers`（4 个类） |
| 🎚️ **水压档位表** | 灵敏度档位 → 具体数值 | `TenkaichiAimSensitivityData` |
| 🚿 **出水（到用户家）** | 变成 InputTag，交给 GAS | P05 的 ASC |
| 📟 **水表（记录延迟）** | 玩家输入类 + 延迟标记 | `TenkaichiPlayerInput` |
| 🗂️ **用户档案**（我家水压设多少） | 按键映射档案 / 用户设置 | `PlayerMappableKeyProfile` / `InputUserSettings` |

> **一句话**：P03 = **EnhancedInput 插件 + Lyra 的封装**，让「按键 → 输入值 → 游戏逻辑」这条链路**可配置、可调灵敏度、可自定义按键**。

## 二、逐文件一句话职责（8 个类，按分组）

### P03.1 映射层（2 个，重构版1 已教，直接沿用）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiInputConfig` | **映射表**：`UInputAction` ↔ `FGameplayTag`。**"按这个键 = 触发这个游戏标签"** |
| `TenkaichiInputComponent` | **绑定器**：把 `InputConfig` 绑到 `EnhancedInputComponent`，监听动作并触发回调 |

### P03.2 修饰层（5 个 = 1 个文件里 4 个类 + 1 个数据资产）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiInputModifiers` | ⚠️ **一个 `.h` 里定义 4 个修饰器类**（见下表） |
| ↳ `UTenkaichiSettingBasedScalar` | 按**设置里的某个属性**缩放 X/Y/Z 轴 |
| ↳ `UTenkaichiInputModifierDeadZone` | **死区**：摇杆轻微推动不响应（防漂移） |
| ↳ `UTenkaichiInputModifierGamepadSensitivity` | **手柄灵敏度**：查 `AimSensitivityData` 换算 |
| ↳ `UTenkaichiInputModifierAimInversion` | **瞄准反转**：Y 轴取反 |
| `TenkaichiAimSensitivityData` | **灵敏度档位表**（数据资产）：`ELyraGamepadSensitivity` 枚举 → float 值 |

### P03.3 自定义/存档层（3 个）

| 文件 | 干嘛的 |
|------|--------|
| `TenkaichiPlayerInput` | 自定义玩家输入类，加**输入延迟标记**（latency flash） |
| `TenkaichiPlayerMappableKeyProfile` | **按键映射档案**（一套键位方案，可装备/卸下） |
| `TenkaichiInputUserSettings` | **输入用户设置**（存档 + 按键设置提示）；⚠️ 同文件里还有 `PlayerMappableKeySettings` |

## 五、常见混淆点（你晕大概晕在这）

| 容易混 | 区别 |
|--------|------|
| **`InputAction` vs `InputTag`** | `InputAction` 是**引擎的**（"按下空格"）；`InputTag` 是**游戏的**（"跳跃意图"）。`InputConfig` 负责翻译 |
| **`InputConfig` vs `InputComponent`** | `Config` 是**数据**（一张表）；`Component` 是**执行者**（照着表去绑定） |
| **4 个 Modifier 各自的职责** | `DeadZone` 管"太小不算"；`Sensitivity` 管"摇多少算多"；`AimInversion` 管"上下颠倒"；`SettingBasedScalar` 管"按设置缩放" |
| **`AimSensitivityData` 是数据还是逻辑** | **纯数据**（`UDataAsset`），就是一张"档位→数值"的表 |
| **`PlayerInput` vs `InputComponent`** | `PlayerInput` 是**玩家的输入状态容器**（存按键状态、延迟）；`InputComponent` 是**组件**（负责绑定回调） |
| **`InputUserSettings` vs `PlayerMappableKeyProfile`** | `UserSettings` 是**总设置存档**；`KeyProfile` 是**一套具体键位方案**（可以有多个档案） |

## 六、记忆口诀（4 句）

1. **InputConfig 是翻译官** —— 把"按键"翻译成"游戏标签"。
2. **Modifier 是过滤器** —— 死区/灵敏度/反转，修饰原始输入值。
3. **链路终点是 Tag** —— 输入层不认识"跳跃技能"，只产出 `InputTag`，交给 ASC。
4. **挂起的都在 `.cpp`** —— 它们在等 P12 LocalPlayer 和 P18 Settings。
