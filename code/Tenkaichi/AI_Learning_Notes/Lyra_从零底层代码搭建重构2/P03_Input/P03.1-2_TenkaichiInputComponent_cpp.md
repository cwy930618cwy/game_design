## 四、逐段讲解

### 1. include 区

```cpp
#include "TenkaichiInputComponent.h"

#include "EnhancedInputSubsystems.h"
#include "Player/TenkaichiLocalPlayer.h"
// #include "Settings/TenkaichiSettingsLocal.h"   // ⚠️ 挂起：P18 Settings 未就位

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiInputComponent)

class UTenkaichiInputConfig;
```

- **`TenkaichiInputComponent.h`**：自己的头，**必须第一个**（UE 约定，便于检测头自洽性）。
- **`EnhancedInputSubsystems.h`**：`UEnhancedInputLocalPlayerSubsystem` 的完整定义所在。本 `.cpp` 函数签名里用到它（虽然只作指针参数），Lyra 原样 include 了。
- **`Player/TenkaichiLocalPlayer.h`**：工程**已落盘**（`Source/TenkaichiGame/Player/TenkaichiLocalPlayer.h`）→ 照写，不挂起。注意这是 Lyra 的**冗余 include**——本 `.cpp` 函数体里一个 `ULyraLocalPlayer` 符号都没用到，Lyra 只是留着。
- **`Settings/TenkaichiSettingsLocal.h`**：工程**未落盘**（P18 才教）→ 注释挂起，登记注释备忘录。同样也是冗余 include（函数体没用到）。
- **`UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiInputComponent)`**：把 UHT 生成的 `.gen.cpp` **内联展开**到本文件里，减少编译单元数量、加快编译。UE5 的标准写法。
- **`class UTenkaichiInputConfig;`**：文件底部的**冗余前置声明**（`.h` 里已经完整 include 了 `TenkaichiInputConfig.h`）。Lyra 原样有，一比一保留。

### 3. `AddInputMappings` / `RemoveInputMappings`

```cpp
void UTenkaichiInputComponent::AddInputMappings(const UTenkaichiInputConfig* InputConfig, UEnhancedInputLocalPlayerSubsystem* InputSubsystem) const
{
	check(InputConfig);
	check(InputSubsystem);

	// 如果你需要从输入配置里加点自定义的东西，就在这里处理

```

- **两个 `check`**：契约校验——配置和子系统都不能为空。不是 `ensure`，说明"传空是调用方 bug"。
- **函数体空**：Lyra 原样。函数是 `const` 成员（`.h` 声明里尾巴带 `const`），实现处**不再重复写 `const`**（C++ 规则：`const` 只在声明写一次）。
- **为什么 Lyra 留空**：真正的 `AddMappingContext` 走数据驱动路线——P15 GameFeatures 的 `GameFeatureAction_AddInputContextMapping` 在 Experience 加载时批量添加，不需要组件手动做。所以这里只留钩子。
- 原英文注释 `// Here you can handle any custom logic to add something from your input config if required` → 中文化（铁律 28/39）。

### 4. `RemoveBinds`（本文件唯一有真实逻辑的函数）

```cpp
void UTenkaichiInputComponent::RemoveBinds(TArray<uint32>& BindHandles)
{
	for (uint32 Handle : BindHandles)
	{
		RemoveBindingByHandle(Handle);
	}
	BindHandles.Reset();
}
```

**干嘛的**：把 `.h` 里 `BindAbilityActions` 收集到的所有绑定句柄逐个解绑，然后清空数组。

- **`for (uint32 Handle : BindHandles)`**：范围 for，按值拷贝 `uint32`（4 字节，比引用还便宜）。
- **`RemoveBindingByHandle(Handle)`**：**引擎** `UEnhancedInputComponent` 的方法，按句柄移除一条绑定。
- **`BindHandles.Reset()`**：清空数组（保留已分配内存，`Empty()` 才是连内存一起释放）。
- **不是 `const` 函数**：`RemoveBinds` 声明处没带 `const`——因为它**修改了** `BindHandles`（虽然 BindHandles 是参数不是成员，但语义上属于"会改动"）。
- **调用时机**：P06 `HeroComponent::ReleaseInputComponent` / P12 `LocalPlayer` 切换时调它一把清。

> 🔑 **为什么必须记录句柄**：Enhanced Input 的绑定没有"按名字移除"的 API，只能靠 `BindAction` 返回的句柄精确定位。这就是 `BindAbilityActions` 要出参 `TArray<uint32>&` 的原因。

## 五、几个要记住的点

1. **Lyra 的 `Add/RemoveInputMappings` 本来就空**——不是挂起、不是漏教，是**扩展钩子**。真正的映射添加在 P15 GameFeatures 走数据驱动。
2. **`UE_INLINE_GENERATED_CPP_BY_NAME(Xxx)`**：UE5 标准，把 `.gen.cpp` 内联进 `.cpp`，减少编译单元。名字参数 = **去掉前缀的类名**（`TenkaichiInputComponent`，不是 `UTenkaichiInputComponent`）。
3. **`const` 成员函数在 `.cpp` 实现处不重复写 `const`**——只在 `.h` 声明写。
4. **`RemoveBindingByHandle` 是引擎方法**——Enhanced Input 按句柄解绑的唯一手段。
5. **`Reset()` vs `Empty()`**：`Reset()` 只清元素保留内存；`Empty()` 清元素+释放内存。这里用 `Reset()`（马上要重用）。
6. **本 `.cpp` 函数体零挂起**：4 个函数只用了引擎 API（`check` / `RemoveBindingByHandle` / `Reset`），Lyra 的两个项目内 include 都是冗余的。唯一挂起 = `Settings/TenkaichiSettingsLocal.h` 一行。
