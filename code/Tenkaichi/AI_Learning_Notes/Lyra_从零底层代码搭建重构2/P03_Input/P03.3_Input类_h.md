### 文件 1：`TenkaichiPlayerInput.h`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "EnhancedPlayerInput.h"

#include "TenkaichiPlayerInput.generated.h"

/**
 * Tenkaichi 的自定义玩家输入类。它在 Enhanced Input 的基础上，额外追踪按键按下时的输入延迟。
 *
 * 如果你有任何想在按键按下或输入刷新时运行的逻辑，就继承这个类。
 */
UCLASS(config = Input, transient)
class UTenkaichiPlayerInput : public UEnhancedPlayerInput
{
	GENERATED_BODY()

public:
	UTenkaichiPlayerInput();
	virtual ~UTenkaichiPlayerInput() override;

protected:
	//~ UEnhancedPlayerInput 接口开始
	virtual bool InputKey(const FInputKeyEventArgs& Params) override;
	//~ UEnhancedPlayerInput 接口结束

	// 为延迟标记处理本次按键事件
	void ProcessInputEventForLatencyMarker(const FInputKeyEventArgs& Params);
	// 绑定到延迟标记设置变更事件
	void BindToLatencyMarkerSettingChange();
	// 解绑延迟标记设置变更监听
	void UnbindLatencyMarkerSettingChangeListener();
	// 处理延迟标记设置变更（开关各延迟模块的闪光）
	void HandleLatencyMarkerSettingChanged();

	// 是否应触发延迟闪光
	bool bShouldTriggerLatencyFlash = false;
};
```

## 四、逐段讲解

### 文件 1：`TenkaichiPlayerInput.h`

```cpp
UCLASS(config = Input, transient)
class UTenkaichiPlayerInput : public UEnhancedPlayerInput
{
	...
	virtual bool InputKey(const FInputKeyEventArgs& Params) override;
	void ProcessInputEventForLatencyMarker(const FInputKeyEventArgs& Params);
	void BindToLatencyMarkerSettingChange();
	void UnbindLatencyMarkerSettingChangeListener();
	void HandleLatencyMarkerSettingChanged();
	bool bShouldTriggerLatencyFlash = false;
};
```

- **`config = Input`**：这个类的 UPROPERTY 配置读自 `DefaultInput.ini`。
- **`transient`**：瞬态类，不存档/不序列化（PlayerInput 每局重建）。
- 重写 `InputKey`：Enhanced Input 的按键入口，Lyra 在这里插入延迟标记逻辑。
- 私有成员函数 `ProcessInputEventForLatencyMarker` / `Bind...` / `Unbind...` / `Handle...`：延迟标记的绑定/解绑/处理。
- `bShouldTriggerLatencyFlash`：是否触发延迟闪光（由设置驱动）。
- **无 UE_API 导出宏**：本类没有需要跨模块导出的成员，不写 `#define UE_API` 块。

### 文件 2：`TenkaichiPlayerMappableKeyProfile.h`

```cpp
#define UE_API TENKAICHIGAME_API
UCLASS(MinimalAPI)
class UTenkaichiPlayerMappableKeyProfile : public UEnhancedPlayerMappableKeyProfile
{
	UE_API virtual void EquipProfile() override;
	UE_API virtual void UnEquipProfile() override;
```

- **`#define UE_API TENKAICHIGAME_API`**：临时把 `UE_API` 定义为模块导出宏，让类里的成员能跨模块导出；`#undef UE_API` 用完撤销。
- 重写 `EquipProfile` / `UnEquipProfile`：按键映射配置被装备/卸载时的钩子（`.cpp` 里只调 `Super`，留空扩展位）。

### 文件 3：`TenkaichiInputUserSettings.h`（2 个类）

```cpp
#define UE_API TENKAICHIGAME_API

UCLASS(MinimalAPI)
class UTenkaichiInputUserSettings : public UEnhancedInputUserSettings
{
	UE_API virtual void ApplySettings() override;
	//UPROPERTY(SaveGame, ...) bool bSomeExampleProperty;  // 注释示例
};

UCLASS(MinimalAPI)
class UTenkaichiPlayerMappableKeySettings : public UPlayerMappableKeySettings
{
	UE_API const FText& GetTooltipText() const;
	UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Settings", meta=(AllowPrivateAccess=true))

```

- **`UTenkaichiInputUserSettings`**：继承 `UEnhancedInputUserSettings`（引擎的输入用户设置，可云存档）。重写 `ApplySettings`。被注释掉的 `bSomeExampleProperty` 是 Lyra 给的"加属性就标记 SaveGame"的示例。
- **`UTenkaichiPlayerMappableKeySettings`**：继承 `UPlayerMappableKeySettings`（引擎按键设置基类）。新增 `Tooltip` 字段 + `GetTooltipText()`。
- `FText`：本地化文本类型，设置界面显示用。
- `meta=(AllowPrivateAccess=true)`：允许蓝图访问受保护/私有成员。

## 五、几个要记住的点

1. **`#define UE_API XXX` + `#undef UE_API`**：临时导出宏模式，跨模块导出类成员（`TENKAICHIGAME_API` 定义在 Build.cs 的模块导出头里）。**有成员要跨模块导出才写**（PlayerInput 没有，所以不写）。
2. **`config = Input`**：配置读自 `DefaultInput.ini`。
3. **`transient`**：瞬态，不存档。
4. **`FText` vs `FString`**：面向 UI 的本地化文本用 `FText`。
5. **一个 `.h` 可定义多个类**（`InputUserSettings.h` 里 2 个类），对应 Lyra 原文件结构，不拆。
6. **`.h` 全可独立编译**：只依赖引擎 EnhancedInput 插件（已装）。
