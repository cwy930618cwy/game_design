## 一、这个类解决什么问题（为什么）

P01.3 的复制器负责"**把消息从服务器送到客户端**"。但有些玩法需要**"监听一堆消息、并可能基于它们重新发出新消息"**——比如：

> 检测到"连续 3 次击杀"（监听击杀消息）→ 自己**重新发出一条"连杀"消息**。

这类"**观察者 + 再发射器**"的公共逻辑，抽成一个**基类** `UGameplayMessageProcessor`：

> **它挂在一个 Actor 上（是个 `UActorComponent`），负责"订阅某些消息（StartListening）→ 处理 → 取消订阅（StopListening）"，并在结束后清理所有监听句柄。** 具体监听哪条消息、怎么处理，由**子类**在 `StartListening` 里用 `AddListenerHandle` 注册。

> 🔑 **一句话**：P01.4 是"**消息处理器**的公共底座"——一个组件基类，帮你管好"开始监听 / 停止监听 / 结束时注销监听"这套生命周期，**具体逻辑留给子类写**（`StartListening`/`StopListening` 空实现，子类覆盖）。

## 二、内部结构全景

```
UCLASS(MinimalAPI, BlueprintType, Blueprintable, meta=(BlueprintSpawnableComponent))
class UGameplayMessageProcessor : public UActorComponent
├─ public:
│   ├─ BeginPlay() override                  ← 组件开始时 → StartListening()
│   ├─ EndPlay(EndPlayReason) override       ← 组件结束时 → StopListening() + 注销所有监听句柄
│   ├─ StartListening()                       ← 虚函数，子类覆盖：在这注册要听的消息（空实现）
│   └─ StopListening()                        ← 虚函数，子类覆盖：在这停止听（空实现）
├─ protected:
│   ├─ AddListenerHandle(Handle&&)            ← 子类把新监听句柄存进数组（方便统一清理）
│   └─ GetServerTime() const                 ← 拿服务器时间（用 GameState 的服务器时钟）
└─ private:
    └─ TArray<FGameplayMessageListenerHandle> ListenerHandles  ← 存所有监听句柄
```

> 关键设计：**子类在 `StartListening` 里用 `AddListenerHandle` 把监听句柄存进 `ListenerHandles` 数组**，这样 `EndPlay` 时能统一 `UnregisterListener` 注销，不用子类自己记着清理。

1. **`UCLASS(MinimalAPI)`**：模块导出宏的"按需导出"模式——配合 `.h` 里 `#define UE_API LYRAGAME_API` / `#undef UE_API` 的技巧，让每个方法单独带导出宏（P01.5 也会用，是 Lyra 的常见手法）。
2. **`BlueprintSpawnableComponent`**：让这个组件能被蓝图当作组件 spawn。
3. **`FGameplayMessageListenerHandle`**：S1 插件的"监听句柄"——订阅消息后拿到的一个"凭据"，用它注销监听。
4. **`AddListenerHandle(Handle&&)`** + `MoveTemp`：右值引用 + 移动语义，把监听句柄高效存入数组。
