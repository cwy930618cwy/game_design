## 一、这个类解决什么问题（为什么）

游戏里除了"击杀/拾取"这种**带数据的事件**（P01.1 的 `FLyraVerbMessage`），还有一类**瞬时的、给玩家看的日志消息**——比如屏幕上的"你击杀了 XXX"、"你拾取了 XX"、"队伍提示"。

这类消息和 `FLyraVerbMessage` 不一样：它**不关心"谁对谁造成了多少伤害"**，只关心**"要把哪句话显示到哪条通道上"**。

`FLyraNotificationMessage` 就是**通知/日志消息体**：

> **"把一句话（PayloadMessage）发到某个通道（TargetChannel），显示给某个玩家（TargetPlayer），附带点额外信息（PayloadTag / PayloadObject）。"**

> 🔑 **一句话**：P01.1 是"**带数值的事件**"（谁对谁做了什么、多少伤害），P01.2 是"**给人看的通知**"（把一句话显示到哪条日志）。一个走逻辑，一个走 UI。

## 二、内部结构全景

```
LYRAGAME_API UE_DECLARE_GAMEPLAY_TAG_EXTERN(TAG_Lyra_AddNotification_Message);   ← 声明"加一条通知"这个 Tag

USTRUCT(BlueprintType)  struct FLyraNotificationMessage
├─ GENERATED_BODY()
└─ 5 个 UPROPERTY 成员：
      ├─ FGameplayTag TargetChannel            ← 显示到哪条通道（如"击杀播报"）
      ├─ TObjectPtr<APlayerState> TargetPlayer ← 给哪个玩家看（空=所有本地玩家）
      ├─ FText PayloadMessage                  ← 要显示的那句话
      ├─ FGameplayTag PayloadTag               ← 额外类型标签（如样式）
      └─ TObjectPtr<UObject> PayloadObject     ← 额外对象载荷（如定义资产）
```

> 和 P01.1 一样是**纯数据载体 USTRUCT**：没有继承、没有生命周期。但注意它多了一个**文件级 Tag 声明**（`TAG_Lyra_AddNotification_Message`）——`.cpp` 里就一行，专门"实例化"这个 Tag。
