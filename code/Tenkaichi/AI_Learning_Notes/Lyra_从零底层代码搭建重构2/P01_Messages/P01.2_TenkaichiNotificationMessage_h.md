## 三、完整代码（注释已中文化）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "NativeGameplayTags.h"

#include "TenkaichiNotificationMessage.generated.h"

class UObject;

// 声明一个"添加通知"的标签（真正的定义在 .cpp 里用 UE_DEFINE_GAMEPLAY_TAG 完成）
TENKAICHIGAME_API UE_DECLARE_GAMEPLAY_TAG_EXTERN(TAG_Tenkaichi_AddNotification_Message);

class APlayerState;

// 发往"临时日志"的消息（例如击杀播报、物品拾取流）
USTRUCT(BlueprintType)
struct FTenkaichiNotificationMessage
{
	GENERATED_BODY()

	// 目标通道（显示到哪条日志，如"击杀播报"）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	FGameplayTag TargetChannel;

	// 目标玩家（留空 = 显示给所有本地玩家）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	TObjectPtr<APlayerState> TargetPlayer = nullptr;

	// 要显示的那句话
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	FText PayloadMessage;

	// 目标通道专属的额外载荷（如样式或定义资产）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	FGameplayTag PayloadTag;

	// 目标通道专属的额外载荷（如样式或定义资产）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	TObjectPtr<UObject> PayloadObject = nullptr;
};
```

## 四、逐段讲解

### 1. include 区 + 前置声明

```cpp
#include "NativeGameplayTags.h"

#include "TenkaichiNotificationMessage.generated.h"

class UObject;

class APlayerState;
```

| 行 | 干什么 |
|----|--------|
| `#include "NativeGameplayTags.h"` | 引擎 GameplayTags 模块的头，`UE_DECLARE_GAMEPLAY_TAG_EXTERN` 宏和 `FNativeGameplayTag` 在这里定义 |
| `#include "TenkaichiNotificationMessage.generated.h"` | UHT 生成的反射代码（文件名带前缀 `Tenkaichi`） |
| `class UObject;` | 前置声明——`.h` 里只用到 `TObjectPtr<UObject>` 指针，不用 include 整个 UObject.h，声明一下类型即可 |
| `class APlayerState;` | 同上，前置声明 `APlayerState`（成员里用到 `TObjectPtr<APlayerState>`） |

> 注意这里**没有 include `GameplayTagContainer.h`**——但成员里用了 `FGameplayTag`。为什么能编译？因为 `NativeGameplayTags.h` 内部已经间接 include 了 GameplayTagContainer（`FGameplayTag` 的定义可见）。**Lyra 怎么写，我们就怎么写**，不加多余的 include（铁律 23 一字不差）。

### 2. 声明 Tag（新知识点）

```cpp
// 声明一个"添加通知"的标签（真正的定义在 .cpp 里用 UE_DEFINE_GAMEPLAY_TAG 完成）
TENKAICHIGAME_API UE_DECLARE_GAMEPLAY_TAG_EXTERN(TAG_Tenkaichi_AddNotification_Message);
```

| 部分 | 干什么 |
|------|--------|
| `TENKAICHIGAME_API` | 模块导出宏——让外部模块也能看到这个 Tag |
| `UE_DECLARE_GAMEPLAY_TAG_EXTERN(TAG_Tenkaichi_AddNotification_Message)` | **声明**一个 GameplayTag。引擎里这个宏展开是 `extern FNativeGameplayTag TAG_Tenkaichi_AddNotification_Message;` |

**为什么要在 `.h` 里"声明"而不直接"定义"？** 因为"添加通知"这个 Tag 要被多个文件共用。在 `.h` 里声明（`extern`），真正的定义放在**唯一的 `.cpp`**里（P01.2 的 `.cpp` 用 `UE_DEFINE_GAMEPLAY_TAG` 实例化一次），这样**全工程只有一处真实定义**，不会重复定义链接报错。

| 概念 | 说明 |
|------|------|
| `FNativeGameplayTag` | 引擎 GameplayTags 模块提供的结构体，**构造时会自动把标签注册进游戏**（比手写 `FGameplayTag` 更省事） |
| `UE_DECLARE_GAMEPLAY_TAG_EXTERN` | 在 `.h` 里**声明** Tag（`extern`） |
| `UE_DEFINE_GAMEPLAY_TAG` | 在 `.cpp` 里**定义/实例化** Tag（P01.2 的 `.cpp` 才用到） |

> 🔑 一句话：**"声明 Tag" = 告诉别处"有个叫 `TAG_Tenkaichi_AddNotification_Message` 的标签"；真正的"创建"在 `.cpp` 里只做一次**。这样全工程共享同一个标签对象。

### 3. USTRUCT —— FTenkaichiNotificationMessage

```cpp
// 发往"临时日志"的消息（例如击杀播报、物品拾取流）
USTRUCT(BlueprintType)
struct FTenkaichiNotificationMessage
{
	GENERATED_BODY()
```

| 行 | 干什么 |
|----|--------|
| 顶部 `//` 注释 | 说明这个消息体的用途："发往临时日志的消息（击杀播报/拾取流）" |
| `USTRUCT(BlueprintType)` | 标记为 USTRUCT 反射结构体，`BlueprintType` = 蓝图里可当变量用 |
| `struct FTenkaichiNotificationMessage` | 定义结构体（`F` 前缀 = 非 UObject 的普通结构体） |
| `GENERATED_BODY()` | UHT 要求的标准宏 |

### 4. 五个 UPROPERTY 成员

```cpp
	// 目标通道（显示到哪条日志，如"击杀播报"）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	FGameplayTag TargetChannel;

	// 目标玩家（留空 = 显示给所有本地玩家）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	TObjectPtr<APlayerState> TargetPlayer = nullptr;

	// 要显示的那句话
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	FText PayloadMessage;

	// 目标通道专属的额外载荷（如样式或定义资产）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	FGameplayTag PayloadTag;

	// 目标通道专属的额外载荷（如样式或定义资产）
	UPROPERTY(BlueprintReadWrite, Category=Notification)
	TObjectPtr<UObject> PayloadObject = nullptr;
```

| 成员 | 类型 | 含义 |
|------|------|------|
| `TargetChannel` | `FGameplayTag` | **显示到哪条通道**（如"击杀播报"），订阅方靠它决定去哪个日志 UI 渲染 |
| `TargetPlayer` | `TObjectPtr<APlayerState>` | **给哪个玩家看**，留空 = 所有本地玩家（默认 `nullptr`） |
| `PayloadMessage` | `FText` | **要显示的那句话**（`FText` 用于本地化文本，不是 `FString`） |
| `PayloadTag` | `FGameplayTag` | 额外类型标签（如样式） |
| `PayloadObject` | `TObjectPtr<UObject>` | 额外对象载荷（如定义资产），默认 `nullptr` |

| 通用点 | 说明 |
|--------|------|
| `UPROPERTY(BlueprintReadWrite, Category=Notification)` | 蓝图可读可写，归到"Notification"分类（5 个成员统一写法，注意分类是 `Notification` 不是 P01.1 的 `Gameplay`） |
| `TObjectPtr<...> = nullptr` | 智能对象指针，默认置空 |
| `FText` | 本地化文本类型（`PayloadMessage` 用 `FText` 而非 `FString`——要显示给人看、支持翻译） |

> 🔑 一句话：**这 5 个成员凑齐就是一条"日志通知"——说给谁听（TargetPlayer）、显示在哪（TargetChannel）、说什么（PayloadMessage）、带什么料（PayloadTag / PayloadObject）**。

### 5. 注意：P01.2 的 `.h` 没有方法

这个 `.h` 是**纯数据**，连 P01.1 的 `ToString()` 都没有——它比 `FLyraVerbMessage` 更纯粹，只是装数据的袋子。`.cpp`（9 行）只做一件事：**用 `UE_DEFINE_GAMEPLAY_TAG` 实例化上面声明的那个 Tag**。
