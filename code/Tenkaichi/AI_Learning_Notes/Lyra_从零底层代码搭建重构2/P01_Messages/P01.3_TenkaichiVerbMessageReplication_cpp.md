# P01.3 FLyraVerbMessageReplication —— 教 `.cpp`

## 一、本文件要解决什么

把 `.h` 里**声明**的方法**实现**出来。`.cpp` 有 60 行，实现三件事：

1. **`Entry::GetDebugString()`** —— 返回这条消息的调试字符串（调 `Message.ToString()`）
2. **`Replication::AddMessage()`** —— 服务器把一条消息加进数组并标记脏（`MarkItemDirty`）
3. **FastArray 三回调 + `RebroadcastMessage()`** —— 客户端收到新增/变更的消息后，**经 S1 插件 `UGameplayMessageSubsystem` 重新广播**给本地订阅者

> 🔑 一句话：**`.cpp` 是"复制器的动作"——服务器加消息（AddMessage），客户端收到后重新广播（三回调 → RebroadcastMessage）**。

### 3. AddMessage —— 服务器加消息

```cpp
// 从服务器向客户端广播一条消息：把消息加进数组并标记脏，触发 FastArray 增量复制
void FTenkaichiVerbMessageReplication::AddMessage(const FTenkaichiVerbMessage& Message)

```

| 行 | 干什么 |
|----|--------|
| `CurrentMessages.Emplace_GetRef(Message)` | 用 `Message` 在数组**末尾构造**一个新 Entry，返回它的引用 |
| `MarkItemDirty(NewStack)` | **标记这个元素"脏"**——告诉 FastArray"这里变了"，下次复制时把它增量同步出去（引擎 `FFastArraySerializerItem` 的方法） |

> 🔑 服务器调 `AddMessage`，消息进数组 + 标记脏 → 引擎 FastArray 检测到 → 增量同步给客户端。

### 5. RebroadcastMessage —— 本地重新广播（核心）

```cpp
// 把消息重新广播给本地订阅者（经 GameplayMessageRouter 插件的消息系统）
void FTenkaichiVerbMessageReplication::RebroadcastMessage(const FTenkaichiVerbMessage& Message)
{
	check(Owner);
	UGameplayMessageSubsystem& MessageSystem = UGameplayMessageSubsystem::Get(Owner);
	MessageSystem.BroadcastMessage(Message.Verb, Message);
}
```

| 行 | 干什么 |
|----|--------|
| `check(Owner)` | 断言 `Owner` 非空（空就崩溃报警——它必须是合法的持有者） |
| `UGameplayMessageSubsystem::Get(Owner)` | 从 `Owner` 找到全局消息系统（S1 插件 GameplayMessageRouter 提供） |
| `MessageSystem.BroadcastMessage(Message.Verb, Message)` | **用 `Message.Verb`（标签）作为频道，把整条 `Message` 广播出去**——本地所有订阅了这个标签的人都收到 |

> 🔑 **这就是整个复制器的终点**：服务器 `AddMessage` → FastArray 同步 → 客户端 `PostReplicatedAdd/Change` → `RebroadcastMessage` → `UGameplayMessageSubsystem::BroadcastMessage` 在客户端本地广播，订阅者处理。
>
> `UGameplayMessageSubsystem` 是 S1 插件，**只讲用途不拆**（插件已装，不是要还原的代码）。
