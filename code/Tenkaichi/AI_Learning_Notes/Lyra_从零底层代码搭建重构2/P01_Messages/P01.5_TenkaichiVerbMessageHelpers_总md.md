## 一、这个类解决什么问题（为什么）

P01.1~P01.4 是"**消息怎么定义、怎么复制、怎么监听**"。但实际玩法里经常要：

1. **从一个对象（Actor/Pawn/Controller/PlayerState）反查它的 PlayerState 或 PlayerController**——比如"这条击杀消息的发起者是谁的玩家状态"。
2. **在"消息体"和"GAS 的 GameplayCue 参数"之间互相转换**——有些系统用 VerbMessage 发事件，有些用 GameplayCue，两者字段很像，需要桥接。

`UTenkaichiVerbMessageHelpers` 是一个 **`UBlueprintFunctionLibrary`（蓝图函数库）**，把这些常用转换做成**静态函数**，蓝图和 C++ 都能直接调：

> 🔑 一句话：**它是"消息的辅助工具箱"**——4 个静态工具函数：反查 PlayerState、反查 PlayerController、消息→GameplayCue 参数、GameplayCue 参数→消息。**外加一个特殊角色：`FTenkaichiVerbMessage::ToString()` 的实现在这个 `.cpp` 里**（P01.1 声明的方法，在这里落地）。

## 二、内部结构全景

```
UCLASS(MinimalAPI)
class UTenkaichiVerbMessageHelpers : public UBlueprintFunctionLibrary
└─ 4 个 static 蓝图函数：
    ├─ GetPlayerStateFromObject(UObject*) → APlayerState*     ← 从任意对象反查 PlayerState
    ├─ GetPlayerControllerFromObject(UObject*) → APlayerController* ← 从任意对象反查 PlayerController
    ├─ VerbMessageToCueParameters(VerbMessage) → FGameplayCueParameters ← 消息 → GAS 参数（⚠️ 挂起）
    └─ CueParametersToVerbMessage(GAS参数) → VerbMessage       ← GAS 参数 → 消息（⚠️ 挂起）

另外（不在类里，是 .cpp 顶部）：
    └─ FLyraVerbMessage::ToString() 的实现  ← P01.1 声明的方法在这里落地
```

> 关键设计：类名 `UTenkaichiVerbMessageHelpers` 带 **`MinimalAPI`**（按需导出），配合 `.h` 里 `#define UE_API TENKAICHIGAME_API` 的技巧，让每个函数单独带导出宏（和 P01.4 同款手法）。
