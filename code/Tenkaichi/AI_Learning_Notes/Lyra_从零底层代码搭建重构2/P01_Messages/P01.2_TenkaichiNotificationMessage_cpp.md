## 四、逐段讲解

### 1. include 头文件

```cpp
#include "TenkaichiNotificationMessage.h"
```

| 行 | 干什么 |
|----|--------|
| `#include "TenkaichiNotificationMessage.h"` | 引入对应的 `.h`——`.cpp` 要"定义/实现" `.h` 里声明的东西，必须先 include 它 |

### 2. 内联生成宏

```cpp
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiNotificationMessage)
```

| 行 | 干什么 |
|----|--------|
| `UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiNotificationMessage)` | UHT 生成反射代码（UE5.4+ 新写法，把 `.cpp` 需要的反射实现内联进这个 `.cpp`）。参数填**本文件名（不带后缀）**。每个 UCLASS/USTRUCT 的 `.cpp` 都要有这一行 |

> 这是 UE5.4+ 的标准 `.cpp` 标配（替代老版的 `#include "LyraNotificationMessage.generated.cpp"` 写法）。只要这个 `.h` 里有 UCLASS/USTRUCT/UENUM，它的 `.cpp` 就必须写这一行，否则反射代码缺失编译报错。

### 3. 实例化 Tag（核心）

```cpp
UE_DEFINE_GAMEPLAY_TAG(TAG_Tenkaichi_AddNotification_Message, "Tenkaichi.AddNotification.Message");
```

| 部分 | 干什么 |
|------|--------|
| `UE_DEFINE_GAMEPLAY_TAG` | 引擎宏：**定义/实例化**一个 GameplayTag |
| `TAG_Tenkaichi_AddNotification_Message` | 变量名——**必须和 `.h` 里 `UE_DECLARE_GAMEPLAY_TAG_EXTERN` 声明的是同一个** |
| `"Tenkaichi.AddNotification.Message"` | 标签字符串——这个 Tag 的完整名字（`项目.功能.行为` 的分层命名） |

**这一行展开后**（引擎 `NativeGameplayTags.h` 第 41 行）大概长这样：

```cpp
FNativeGameplayTag TAG_Tenkaichi_AddNotification_Message(
    UE_PLUGIN_NAME, UE_MODULE_NAME, TEXT("Tenkaichi.AddNotification.Message"),
    TEXT(""), ENativeGameplayTagToken::PRIVATE_USE_MACRO_INSTEAD);
```

> 不需要手动写这些参数——宏帮你填好了。你只需要记住：**`.h` 声明 + `.cpp` 定义，成对出现，变量名一致**（这就是铁律 11 的"`.h` 声明 ↔ `.cpp` 实现成对核"）。

**为什么标签字符串叫 `Tenkaichi.AddNotification.Message`？**
- 这是**分层命名**：`项目(Tenkaichi).功能(AddNotification).消息(Message)`。
- 前缀按铁律 24 替换：Lyra 里是 `Lyra.AddNotification.Message` → 我们换成 `Tenkaichi.AddNotification.Message`。
- 游戏里别处要用这个 Tag 时，就引用 `TAG_Tenkaichi_AddNotification_Message` 这个变量，或直接写字符串 `"Tenkaichi.AddNotification.Message"`。
