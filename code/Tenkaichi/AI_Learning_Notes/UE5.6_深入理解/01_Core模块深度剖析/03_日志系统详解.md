# 03 — 日志系统详解（UE_LOG）

> **定位**：UE 最常用的调试工具。不用打断点、不用 `print`，用 `UE_LOG` 往日志窗口/控制台输出信息，定位问题。
>
> **文件**：`Engine/Source/Runtime/Core/Public/Misc/Logging/`（`Log.h`、`LogCategory.h` 等）
>
> **一句话**：`UE_LOG(类别, 级别, 格式串, 参数...)` —— 打日志就这一条，剩下的是选类别、选级别、写格式。

---

## 一、最基础的用法（先能打出来）

```cpp
// 最简单的日志
UE_LOG(LogTemp, Log, TEXT("Hello World"));

// 带变量
int32 Score = 100;
UE_LOG(LogTemp, Warning, TEXT("玩家得分: %d"), Score);
```

**四个参数拆开看**：

| 参数 | 含义 | 例子 |
|------|------|------|
| `LogTemp` | **类别**（Log Category）：给日志分类，方便过滤 | `LogTemp` / `LogGameplay` / `LogMyGame` |
| `Log` | **级别**（Verbosity）：日志的重要程度 | `Log` / `Warning` / `Error` |
| `TEXT("...")` | **格式串**：内容 + `%d`、`%s` 这种占位符 | `TEXT("得分: %d")` |
| `变量` | 对应格式串里的占位符 | `Score` |

> **必须 `TEXT()`**：`TEXT("...")` 把字符串变成宽字符，否则乱码或编译警告。

---

## 二、具体场景：用它调试"角色掉血"

假设角色掉血了，你想看每次掉了多少、血条变没变：

```cpp
void AMyCharacter::TakeDamage(float Amount) {
    Health -= Amount;
    // 打日志：看掉血数值和当前血量
    UE_LOG(LogTemp, Log, TEXT("受到伤害 %f，当前血量 %f"), Amount, Health);

    if (Health <= 0.f) {
        // 血扣光了，用 Warning 级别更显眼
        UE_LOG(LogTemp, Warning, TEXT("角色死亡！"));
    }
}
```

**运行时**：打开「输出日志」窗口（Window → Output Log，快捷键 Ctrl+Shift+O），就能实时看到每行日志滚动出来。

---

## 三、格式串占位符（%d、%s 是什么）

`TEXT()` 里的 `%` 是**占位符**，按顺序被后面的变量替换：

```cpp
UE_LOG(LogTemp, Log, TEXT("名字=%s，等级=%d，坐标=%s"),
       *PlayerName, Level, *Location.ToString());
```

| 占位符 | 代表类型 | 例子 |
|--------|---------|------|
| `%d` | int | `Level` |
| `%f` | float | `Health`（默认 6 位小数） |
| `%s` | 字符串（要加 `*`） | `*Name` |
| `%f` | FVector/FString（要 `.ToString()`） | `*Location.ToString()` |

**两个最容易错的地方**：
- **`%s` 前面要 `*`**：`FString` 传进日志要取原始指针 `*Name`
- **`FVector` 要 `.ToString()`**：`FVector` 不能直接打，得转字符串

```cpp
// ✅ 正确
FString Name = TEXT("Hero");
UE_LOG(LogTemp, Log, TEXT("名字: %s"), *Name);   // FString 加 *

FVector Loc(1.f, 2.f, 3.f);
UE_LOG(LogTemp, Log, TEXT("坐标: %s"), *Loc.ToString());  // FVector 转字符串

// ❌ 错误：漏了 * 或没转字符串，会乱码或编译错
UE_LOG(LogTemp, Log, TEXT("名字: %s"), Name);   // 缺 *
UE_LOG(LogTemp, Log, TEXT("坐标: %s"), Loc);    // FVector 没 .ToString()
```

## 四、日志级别（Verbosity）—— 重要程度分级

| 级别 | 颜色 | 用途 | 场景 |
|------|:---:|------|------|
| `VeryVerbose` | 灰 | 最详细，几乎不用 | 海量调试信息 |
| `Verbose` | 灰 | 详细 | 每帧细节 |
| `Log` | 白 | **普通信息**（最常用） | 正常流程、数值变化 |
| `Display` | 白 | 显示在屏幕 | 要在屏幕上显示的提示 |
| `Warning` | 黄 | 警告 | 有问题但不致命 |
| `Error` | 红 | 错误 | 出错了，要修 |
| `Fatal` | 红 | **致命错误，会崩溃** | 直接让游戏崩溃 |

**具体场景**：不同级别应对不同情况

```cpp
UE_LOG(LogTemp, Log,     TEXT("玩家进入关卡"));          // 普通流程
UE_LOG(LogTemp, Warning, TEXT("血量偏低：%f"), Health);  // 警告，要注意
UE_LOG(LogTemp, Error,   TEXT("加载地图失败！"));        // 出错
// UE_LOG(LogTemp, Fatal, TEXT("..."))                  // 会崩，慎用
```

**为什么分级**：日志一多很难看，分级别后**能按级别过滤**。调试时只看 `Warning` 以上的，普通 `Log` 可以关掉，不吵。

---

## 五、日志类别（Log Category）—— 分类管理

类别把日志按"模块/系统"分组，方便过滤。常用的内置类别：

| 类别 | 用途 |
|------|------|
| `LogTemp` | 临时调试（新手最常用） |
| `LogGameplay` | 游戏玩法逻辑 |
| `LogAbility` | 技能系统 |
| `LogAIModule` | AI |
| `LogInventory` | 背包 |
| ... | 每个模块都有对应类别 |

**具体场景：为什么不要全用 LogTemp？**

如果你在技能、背包、AI 里全用 `LogTemp`，几千条日志混在一起，**根本分不清是谁打的**。用不同类别就能：

```
日志窗口过滤：
  Log  → 只显示技能系统的日志
  LogAI → 只看 AI 的日志
```

```cpp
// 技能系统
UE_LOG(LogAbility, Log, TEXT("释放技能：%s"), *AbilityName);
// 背包系统
UE_LOG(LogInventory, Log, TEXT("获得物品：%s x%d"), *ItemName, Count);
```

## 六、自定义日志类别（项目正式用）

`LogTemp` 是临时的，项目正式开发要**自己定义类别**。两步：

```cpp
// ① 在头文件里声明（比如 MyGame.h）
DECLARE_LOG_CATEGORY_EXTERN(LogMyGame, Log, All);
//                            ↑类别名   ↑默认级别  ↑最大级别

// ② 在 .cpp 文件里定义（比如 MyGame.cpp）
DEFINE_LOG_CATEGORY(LogMyGame);
```

然后在任意 .cpp 里用：

```cpp
// 先 #include 头文件
#include "MyGame.h"
UE_LOG(LogMyGame, Warning, TEXT("我的自定义日志"));
```

## 七、高级用法（遇到再看）

### 7.1 屏幕上显示（便于运行时看，不用切日志窗口）

```cpp
if (GEngine) {
    GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Yellow,
        TEXT("血量不足！"));   // 屏幕黄字显示 5 秒
}
```

**具体场景**：游戏运行时你想马上看到某个值（比如 AI 状态），切日志窗口麻烦，直接打到屏幕上：

```cpp
// 每秒打印 AI 当前状态到屏幕
if (GEngine) {
    GEngine->AddOnScreenDebugMessage(0, 0.1f, FColor::Green,
        FString::Printf(TEXT("AI状态: %d，目标: %s"), State, *TargetName));
}
```

### 7.2 条件日志（只在满足条件时打）

```cpp
// 只在玩家进入触发器时打
if (OverlapActor == Player) {
    UE_LOG(LogMyGame, Log, TEXT("玩家进入区域！"));
}
```

### 7.3 用 Format 格式化字符串（拼复杂内容）

```cpp
UE_LOG(LogMyGame, Log, TEXT("角色 %s 在 %s 被 %s 击杀"),
       *VictimName, *MapName, *KillerName);
```

## 八、常见陷阱

**① 忘记 `*` → 乱码/编译错**
```cpp
FString Name = TEXT("Hero");
// ❌ UE_LOG(LogTemp, Log, TEXT("名字: %s"), Name);   // 缺 *
UE_LOG(LogTemp, Log, TEXT("名字: %s"), *Name);        // ✅ 加 *
```

**② FVector/FVector 没转字符串**
```cpp
FVector Loc(1,2,3);
// ❌ UE_LOG(LogTemp, Log, TEXT("位置: %s"), Loc);   // 编译错
UE_LOG(LogTemp, Log, TEXT("位置: %s"), *Loc.ToString());  // ✅
```

**③ `%d` 和 `%f` 用反了**
```cpp
float Health = 50.f;
// ❌ UE_LOG(LogTemp, Log, TEXT("血量: %d"), Health);  // float 用了 %d
UE_LOG(LogTemp, Log, TEXT("血量: %f"), Health);        // ✅ 用 %f
```

**④ `Fatal` 会用崩游戏**
调试时别乱用 `Fatal`，它会让游戏直接崩溃。

**⑤ 没加 `TEXT()`**
```cpp
// ❌ UE_LOG(LogTemp, Log, "Hello");   // 字符串字面量不加 TEXT，宽字符环境出问题
UE_LOG(LogTemp, Log, TEXT("Hello"));   // ✅
```

## 九、总结速查

```
打日志：     UE_LOG(类别, 级别, TEXT("格式 %d %s"), 数值, *字符串);
屏幕上显示：  GEngine->AddOnScreenDebugMessage(-1, 秒数, 颜色, 内容);
自定义类别：  DECLARE_LOG_CATEGORY_EXTERN(名字, Log, All) + DEFINE_LOG_CATEGORY(名字)

最常见组合：
  UE_LOG(LogTemp, Log, TEXT("数值=%f"), Value);       // 普通
  UE_LOG(LogTemp, Warning, TEXT("注意：%s"), *Name);  // 警告
```

**实战建议**：
- 新手阶段全用 `LogTemp` + `Log`/`Warning` 就够
- 正式项目定义 `LogMyGame` 等自定义类别，按系统分类
- 运行时想看，用 `AddOnScreenDebugMessage` 打到屏幕

## 十、具体场景：完整调试一个小案例

**场景：技能释放时，排查"为什么没造成伤害"**

```cpp
void AMyCharacter::CastSkill(int32 SkillIndex) {
    // 第 1 步：技能释放了没
    UE_LOG(LogAbility, Log, TEXT("释放技能，编号=%d"), SkillIndex);

    UGameplayAbility* Ability = GetAbility(SkillIndex);
    if (!Ability) {
        // 第 2 步：没找到技能 → 报警告，帮定位
        UE_LOG(LogAbility, Error, TEXT("找不到技能 %d！"), SkillIndex);
        return;
    }

    if (Ability->ManaCost > CurrentMana) {
        // 第 3 步：蓝不够
        UE_LOG(LogAbility, Warning, TEXT("蓝不够：需要 %d，当前 %d"),
               Ability->ManaCost, CurrentMana);
        return;
    }

    // 第 4 步：一切正常，造成伤害
    UE_LOG(LogAbility, Log, TEXT("技能 %s 命中，造成伤害 %f"),
           *Ability->Name, Ability->Damage);
}
```

这样跑一遍，看日志就知道卡在哪一步——是没找到技能、蓝不够、还是正常命中。**这就是日志的实战价值：不用打断点，看输出就知道流程走到哪、哪里错了。**

## 十一、打断点（调试进阶，学完日志再看）

> 日志看"流程走到哪"，断点看"停住时变量是啥"。两者互补，先掌握日志，再学断点。

### 11.1 打断点：点行号左侧

在代码编辑器**行号左侧点一下**，出现红点 = 断点设好：

```
代码行号         断点
  10  void TakeDamage(float Amount) {
  11      ●  Health -= Amount;        ← 在 11 行左侧点一下，出现红点
  12      UE_LOG(...);
  13  }
```

### 11.2 让断点生效：按 F5 以调试模式运行

断点只是"标记"，必须**以调试模式（Debug）运行**才会停：

1. 设好断点（红点）
2. 按 **F5** 启动调试
3. 游戏执行到红点那行**自动停住**（黄点标记当前位置）
4. 鼠标悬停变量 → 看当前值

> **注意**：Release 模式下断点不生效；改了代码要重编译。

### 11.3 停住后的操作（最常用的键）

| 按键 | 作用 |
|------|------|
| **F5** | 启动调试 / 继续运行到下一个断点 |
| **F10** | 单步执行（逐行走，不进函数内部） |
| **F11** | 单步进入（进函数内部看细节） |
| **Shift+F11** | 跳出当前函数 |
| **F9** | 设/取消断点 |
| 鼠标悬停变量 | 直接看当前值 |

### 11.4 具体场景：调试"角色掉血异常"

```
1. 在 "Health -= Amount" 行左侧设断点
2. 按 F5 启动
3. 游戏里让角色受伤
4. 程序在断点处停住
5. 鼠标悬停 Health、Amount → 看当前值
6. 按 F10 走下一步，观察 Health 变化
7. 发现问题（如 Amount 是负数，把掉血当成了回血）
```

### 11.5 UE 特有：断点里看各种类型

- 悬停 `FString` → 直接显示字符串内容
- 悬停 `AActor*` / `TObjectPtr` → 看对象地址，可展开看属性
- 悬停 `TObjectPtr` → 可能要看 `.Get()` 或展开

### 11.6 日志 vs 断点，怎么选

| | 日志（UE_LOG） | 断点 |
|---|---|---|
| 看什么 | 流程、数值变化**记录** | 停下来**实时看变量** |
| 优点 | 跑一次全记录，不用停 | 一步步走、能看中间值 |
| 缺点 | 看不到临时中间变量 | 每次都停，慢 |
| 适合 | 知道大概哪出错 | 精确定位某一行 |

**组合用法**：先用日志锁定大概位置，再在那附近设断点精确定位。

### 11.7 常用技巧

- **条件断点**：右键红点 → Conditions，输入 `Health < 0`，只有满足才停（不用每帧停）
- **断点不生效**：检查是不是 Release 模式、改了代码没重编译
- **看调用栈**：停住后看 Call Stack 窗口，知道是**谁**调到了这一行（排查超有用）

### 11.8 一句话记住打断点

```
1. 在要停的那行左侧点一下 → 出现红点
2. 按 F5 以调试模式启动
3. 游戏跑到位就自动停住，鼠标悬停看变量
4. F10/F11 一步步走，F5 继续跑
```
