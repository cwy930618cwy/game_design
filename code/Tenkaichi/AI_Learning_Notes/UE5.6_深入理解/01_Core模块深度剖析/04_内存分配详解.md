# 04 — 内存分配详解（FMemory / 分配器 / 内存池）

> **定位**：UE 里管理"内存从哪来、怎么分配、怎么释放"的底层系统。前面笔记标过"这是最该延后学的"，但理解它有助于看懂引擎、优化性能。
>
> **一句话**：日常开发你**几乎不用手动管内存**（UE 自动管了），但要知道"对象存在哪、内存池是啥、为什么不要频繁 new/delete"。
>
> **文件**：`Engine/Source/Runtime/Core/Public/HAL/`（`MemoryBase.h`、`UnrealMemory.h`）、`Misc/MemStack.h` 等。

---

## 一、先建立直觉：内存分配的"两种方式"

任何程序要一块内存，无非两种：

| | 从哪拿 | 特点 |
|---|:---:|---|
| **栈（Stack）** | 函数调用时自动分配，返回自动释放 | **极快**，但大小有限 |
| **堆（Heap）** | `new` / `malloc` 手动申请，手动释放 | 灵活，但**慢 + 要管** |

UE 的 FMemory 主要管的是**堆内存**——所有 `new`、`MakeShared`、容器扩容，底层都走它。

---

## 二、UE 的 FMemory：统一的内存入口

UE 封装了一层 `FMemory`，让你**不要直接用 C++ 的 `new` / `malloc`**，而是走它的接口：

```cpp
// 不推荐：直接用 C++ 的 malloc / free
void* P = malloc(1024);
free(P);

// 推荐：走 UE 的 FMemory（能统计、能换底层分配器）
void* P = FMemory::Malloc(1024);
FMemory::Free(P);
```

**好处**：FMemory 底层可以切换不同分配器（调试/发布用不同策略），还能做内存统计、追踪泄漏。**统一入口 = 统一管理**。

**具体场景**：你用 `new TArray<...>` 时，UE 的分配器（`TDefaultAllocator`）内部其实调的就是 `FMemory::Malloc`。所以容器、智能指针、字符串的内存，全都在 UE 的掌控下。

---

## 三、为什么"频繁 new/delete"不好？（性能杀手）

这是内存优化最核心的一条。`new` / `delete`（堆分配）**很慢**，原因：

1. 要向操作系统"申请内存" → 系统调用，慢
2. 会产生**内存碎片** → 导致后续分配变慢、内存浪费
3. 每次都要找"空闲块" → 有查找开销

**具体场景**：游戏里每帧创建大量临时对象

```cpp
// ❌ 每帧 new 一堆临时对象，用完 delete —— 性能灾难
void Tick() {
    for (int i = 0; i < 1000; i++) {
        auto Temp = new FEffect();   // 每帧申请 1000 次堆内存
        // ...用
        delete Temp;                 // 每帧释放 1000 次
    }
}
```

**后果**：频繁堆分配 → 卡顿、碎片化、GC 压力大。**新手最常犯的性能错误就是"循环里反复 new"**。

---

## 四、解决办法 1：内存池（Memory Pool）—— 预先分配，重复使用

内存池的思路：**一次性申请一大块，用的时候从池里拿，用完还回池里，不真正释放给系统**。

```
不用内存池：
  申请 → 释放 → 申请 → 释放...（每次都跟系统打交道，慢）

用内存池：
  提前申请一大块 [   ] [   ] [   ] [   ]   ← 一次性
  用 → 从池里拿一个块 → 用完还回池里 → 再拿   ← 快，不跟系统打交道
```

**具体场景**：子弹/粒子这种"大量、快速创建销毁"的对象，用对象池：

```cpp
// 对象池：预创建一批子弹，用完回收复用
class FBulletPool {
    TArray<FBullet*> FreeBullets;   // 空闲子弹
public:
    FBullet* Get() {
        if (FreeBullets.Num() > 0) return FreeBullets.Pop();  // 从池里拿
        return new FBullet();                                  // 池空才 new
    }
    void Return(FBullet* B) {
        FreeBullets.Add(B);   // 用完还回池里，不真正 delete
    }
};
```

**优点**：避免频繁堆分配，性能大幅提升。这就是很多游戏"子弹/特效复用"的底层原理。

---

## 五、解决办法 2：用栈内存 / 栈分配器

有些临时数据用**栈内存**（`MemStack`）分配，用完自动回收，比堆快得多：

```cpp
// UE 的栈分配器（用于临时数据，用完自动释放）
void SomeFunction() {
    FMemStack& Stack = FMemStack::Get();
    void* TempData = Stack.Alloc(256);   // 从栈拿，很快
    // ...用
    Stack.~FMemStack();                  // 一次性全部释放
}
```

**具体场景**：碰撞检测、物理计算里大量临时向量/矩阵，用栈分配避免堆压力。

---

## 六、核心分配器（了解即可）

UE 有几种内存分配器，不同构建用不同的：

| 分配器 | 用途 |
|--------|------|
| `FMallocAnsi` | 调试用（带内存检查） |
| `FMallocBinned` | 发布用（分桶优化，**推荐给游戏**） |
| `FMallocBinned2` | 改进版分桶，更快 |
| `FMallocMimalloc` | 第三方高性能分配器 |

**关键点**：`FMallocBinned` 是 UE 的"分桶分配器"——它把内存按大小分桶，小对象直接从桶里拿，**大大减少碎片和查找开销**。这解释了为什么"用 UE 的分配器比裸 new 快"。

---

## 七、实际开发中你该怎么想（重要）

**新手/日常开发，你基本不用碰内存分配**，记住这几条就行：

1. **别手动 new/delete**，用 UE 的容器、智能指针、`MakeShared` 让它们自己管
2. **别在循环/高频函数里 new 对象**，会卡
3. **大量临时对象用对象池**（子弹、粒子、特效）
4. 容器用 `Reserve()` 预分配容量，避免反复扩容
5. 想追内存泄漏，用 UE 的"内存分析"（MemReport / 调试器）

---

## 八、具体场景：完整优化一个小案例

**场景：打怪掉金币，每掉一个就 new 一个金币对象 → 卡**

```cpp
// ❌ 每掉一个金币就 new —— 大量堆分配
void DropCoin() {
    ACoin* Coin = NewObject<ACoin>();   // new 金币
    // ...
}

// ✅ 用对象池：预先创建一批金币，掉落时从池里拿
class ACoinPool {
    TArray<ACoin*> Pool;
public:
    ACoin* GetCoin() {
        if (Pool.Num() == 0) return NewObject<ACoin>();  // 池空才 new
        return Pool.Pop();                                // 复用
    }
    void Recycle(ACoin* C) { Pool.Add(C); }               // 回收复用
};
```

**效果**：第一波怪可能 still new 几十个，之后**全部复用**，不再堆分配 → 不卡。

## 九、常见误区

**① 觉得"反正 UE 管了，随便 new"**
```cpp
// ❌ 高频函数里反复 new/delete 依然伤性能
void OnHit() { auto Temp = new FImpact(); delete Temp; }
// ✅ 用对象池或栈分配
```

**② 不知道容器会反复扩容**
```cpp
// ❌ 循环 Add 不预留，容器反复扩容
for (int i = 0; i < 100000; i++) Arr.Add(i);   // 反复 realloc
// ✅ 预留容量
Arr.Reserve(100000);
for (int i = 0; i < 100000; i++) Arr.Add(i);   // 只分配一次
```

**③ 手动 delete UObject**（应该交给 GC）
```cpp
// ❌ UObject 归 GC 管，不该手动 delete
delete MyActor;   // 会出问题
// ✅ 用 Destroy() / 交给 GC
MyActor->Destroy();
```

## 十、总结速查

```
堆内存：   FMemory::Malloc / Free（统一入口）
分配器：   FMallocBinned（发布）FMallocAnsi（调试）
对象池：   大量临时对象复用，避免频繁 new
栈分配：   临时数据用 MemStack，快
新手：     别手动 new，用容器/智能指针，别在循环里 new
优化：     容器 Reserve() 预分配，临时对象用池
```

**核心心法**：UE 内存分配的核心就一句话——**"别频繁跟堆要内存"**。能用栈、能用池、能用容器预留，就别反复 new/delete。日常开发你很少主动碰它，但理解"为什么要避开频繁堆分配"，就能写出性能更好的代码。
