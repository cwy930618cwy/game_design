# 03 — 反射宏全族详解（UCLASS / UPROPERTY / UFUNCTION / USTRUCT / UENUM / GENERATED_BODY）

> **定位**：UE 反射系统**不是只有 `UCLASS` 一个宏**，而是一整族。它们配合 UHT 工具，让 C++ 类能被蓝图、序列化、GC 认识。
>
> **一句话**：UE 反射宏 = **给 UHT 的"标记指令"**。你标记类（`UCLASS`）、属性（`UPROPERTY`）、函数（`UFUNCTION`）、结构体（`USTRUCT`）、枚举（`UENUM`），UHT 扫描后自动生成反射代码，引擎就能"认识"你的 C++ 代码。
>
> **文件**：`CoreUObject/Public/UObject/ObjectMacros.h`（宏都在这定义）

---

## 一、反射宏全家福（先看总表）

| 宏 | 标记什么 | 写在 | 作用 |
|------|---------|------|------|
| `UCLASS()` | **类** | 类前 | 让类被反射（可被蓝图/序列化） |
| `UPROPERTY()` | **属性（成员变量）** | 属性前 | 让属性被序列化/蓝图读写/GC 认识 |
| `UFUNCTION()` | **函数** | 函数前 | 让函数可被蓝图调用/网络复制 |
| `USTRUCT()` | **结构体** | struct 前 | 让结构体被反射 |
| `UENUM()` | **枚举** | enum 前 | 让枚举被反射 |
| `UINTERFACE()` | **接口** | interface 前 | 让接口被反射 |
| `UENUM()` | 枚举值 | enum 前 | - |
| `GENERATED_BODY()` | **插入点** | 类内部 | 让 UHT 生成代码插入 |
| `GENERATED_USTRUCT_BODY()` | 结构体插入点 | struct 内部 | 结构体版 |
| `DECLARE_DYNAMIC_MULTICAST_DELEGATE` | 委托 | - | 让委托被反射（见 Core 委托篇） |

> **核心认识**：这些宏**都不是普通替换**，而是给 UHT 看的"标记"。UHT 扫描 → 生成 `.generated.h` → 引擎运行时能反射。

---

## 二、逐个讲解（配具体场景）

### 2.1 UCLASS() —— 标记"反射类"

告诉 UHT：这个类要生成反射代码。

```cpp
UCLASS(BlueprintType, Blueprintable)   // 蓝图可当类型、可建子类
class UMyCharacter : public UObject {
    GENERATED_BODY()
};
```

**常用参数**：

| 参数 | 作用 |
|------|------|
| `BlueprintType` | 蓝图能把这个类当变量类型 |
| `Blueprintable` | 蓝图能创建这个类的子类 |
| `NotBlueprintable` | 蓝图不能继承 |
| `Abstract` | 抽象类，不能直接实例化 |
| `Category="X"` | 编辑器里分类 |

### 2.2 UPROPERTY() —— 标记"属性"（最常用）

告诉 UHT：这个成员变量要序列化、能蓝图读写、被 GC 管。

```cpp
UCLASS()
class UMyCharacter : public UObject {
    GENERATED_BODY()
public:
    UPROPERTY(BlueprintReadWrite, Category="Stats")   // 蓝图可读写
    float Health;

    UPROPERTY(BlueprintReadOnly)                       // 蓝图只读
    int32 Level;

    UPROPERTY(EditAnywhere)                            // 编辑器可改
    FVector SpawnLocation;
};
```

**常用参数（必背）**：

| 参数 | 作用 |
|------|------|
| `BlueprintReadWrite` | 蓝图可读可写 |
| `BlueprintReadOnly` | 蓝图只读 |
| `EditAnywhere` | 编辑器里可改（每个实例） |
| `EditDefaultsOnly` | 只在蓝图默认值可改 |
| `VisibleAnywhere` | 编辑器可见但不可改 |
| `Category="X"` | 编辑器里分组 |
| `Transient` | 不序列化（不存盘） |
| `Replicated` | 网络复制（网络同步用） |

**具体场景：角色属性，可蓝图编辑 + 网络同步**

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category="Stats")
float MaxHealth;             // 编辑器可改，蓝图可读写

UPROPERTY(Replicated)         // 网络同步
float CurrentHealth;          // 多人游戏要同步的血量
```

### 2.3 UFUNCTION() —— 标记"函数"

告诉 UHT：这个函数可被蓝图调用、可网络复制。

```cpp
UCLASS()
class UMyCharacter : public UObject {
    GENERATED_BODY()
public:
    UFUNCTION(BlueprintCallable, Category="Combat")   // 蓝图可调用
    void TakeDamage(float Amount);

    UFUNCTION(BlueprintImplementableEvent)   // 蓝图可覆盖实现
    void OnDied();

    UFUNCTION(BlueprintPure)                 // 纯函数（不改变状态）
    float GetHealth() const;
};
```

**常用参数**：

| 参数 | 作用 |
|------|------|
| `BlueprintCallable` | 蓝图可调用 |
| `BlueprintPure` | 纯函数（无副作用） |
| `BlueprintImplementableEvent` | 蓝图可覆盖实现 |
| `BlueprintNativeEvent` | C++ 有默认实现，蓝图可覆盖 |
| `Server` / `Client` / `NetMulticast` | 网络复制（RPC） |
| `Category="X"` | 编辑器分组 |

**具体场景：技能释放，蓝图可调用 + 网络同步**

```cpp
UFUNCTION(BlueprintCallable, Server, Reliable)   // 客户端调用，服务器执行
void CastAbility(FName AbilityId);
```

### 2.4 USTRUCT() —— 标记"结构体"

让结构体（用 `F` 开头）也能被反射。

```cpp
USTRUCT(BlueprintType)
struct FDamageInfo {
    GENERATED_BODY()

    UPROPERTY(BlueprintReadWrite)
    float Amount;

    UPROPERTY(BlueprintReadWrite)
    AActor* Source;
};
```

**场景**：伤害信息、物品数据这类"组合数据"，用 USTRUCT 让蓝图能用。

### 2.5 UENUM() —— 标记"枚举"

让枚举也能被反射、被蓝图用。

```cpp
UENUM(BlueprintType)
enum class EEnemyState : uint8 {
    Idle,
    Chasing,
    Attacking,
    Dead
};
```

**场景**：敌人 AI 状态，用 UENUM 让蓝图能选。

### 2.6 UINTERFACE() —— 标记"接口"

让接口被反射（注意要配 `class IMyInterface : public UInterface` + `GENERATED_BODY()`）。

```cpp
UINTERFACE(Blueprintable)
class UInteractable : public UInterface {
    GENERATED_BODY()
};

class IInteractable {
    GENERATED_BODY()
public:
    UFUNCTION(BlueprintNativeEvent)
    void OnInteract(AActor* Interactor);
};
```

**场景**：所有可交互物体（门、NPC、宝箱）都实现"OnInteract"，用接口统一调用。

## 三、GENERATED_BODY() —— 所有宏的"落点"

### 3.1 它是什么

`GENERATED_BODY()` 是**"让 UHT 生成的代码插入到这里"的占位符**。它是**反射类的必备**，没有它编译就报错。

### 3.2 底层展开（简化）

```cpp
// 你写的
UCLASS()
class UMyClass : public UObject {
    GENERATED_BODY()   // ← 展开成下面的生成代码
public:
    int32 Health;
};

// GENERATED_BODY() 底层大致展开成：
class UMyClass : public UObject {
    // ====== UHT 生成的代码 ======
    friend class UPackage;
    static void StaticRegisterNativesUMyClass();
    #include "UMyClass.generated.h"   // ← 关键！插入生成的反射代码
    // ====== 生成代码结束 ======
public:
    int32 Health;
};
```

**关键点**：
1. `GENERATED_BODY()` 展开成 **`#include "UMyClass.generated.h"`**（那个文件是 UHT 生成的）
2. `.generated.h` 里有 **`StaticClass()` 的实现、反射表、`Super` 定义**等
3. 所以**反射类必须写** `GENERATED_BODY()`，否则没有反射代码，`StaticClass()` 等都不存在

### 3.3 位置要求

```cpp
UCLASS()
class UMyClass : public UObject {
    GENERATED_BODY()   // ← 必须放在类的最开头（第一个成员）
public:
    int32 Health;
};
```

> `GENERATED_BODY()` 必须**紧跟类声明、放在第一个**。放错了或漏了都会编译报错。

## 四、UHT 的完整工作流程（把宏串起来）

```
你写代码：
  UCLASS() class UMyClass : public UObject {
      GENERATED_BODY()
  public:
      UPROPERTY() int32 Health;
      UFUNCTION() void TakeDamage(float);
  };
        │
        ▼
UHT 工具（编译前扫描，读 UCLASS/UPROPERTY/UFUNCTION/USTRUCT/UENUM）
        │ 识别标记、参数
        ▼
生成 UMyClass.generated.h（反射代码）
  - StaticClass() 实现
  - 反射表（属性/函数/枚举注册）
  - GENERATED_BODY() 展开引用的代码
        │
        ▼
引擎编译运行，能反射：
  - 蓝图看到你的属性/函数
  - 序列化能存你的属性
  - GC 认识你的引用
```

## 五、宏参数速查（一表搞定）

| 宏 | 最常用参数 | 场景 |
|------|-----------|------|
| `UCLASS` | BlueprintType、Blueprintable、Abstract | 类能力 |
| `UPROPERTY` | BlueprintReadWrite、EditAnywhere、Replicated、Transient | 属性可见性/存储/网络 |
| `UFUNCTION` | BlueprintCallable、BlueprintPure、Server、BlueprintNativeEvent | 函数能力 |
| `USTRUCT` | BlueprintType | 结构体被蓝图用 |
| `UENUM` | BlueprintType | 枚举被蓝图用 |

## 六、常见陷阱

**① 反射类漏写 GENERATED_BODY()**
```cpp
// ❌ 编译错
UCLASS() class UMyData : public UObject { };   // 缺 GENERATED_BODY()
// ✅
UCLASS() class UMyData : public UObject { GENERATED_BODY() };
```

**② GENERATED_BODY 没放在类开头**
```cpp
// ❌ 放在后面，编译错
UCLASS() class UMyData : public UObject {
public:
    int32 A;
    GENERATED_BODY();   // 错！必须第一个
};
```

**③ UPROPERTY 参数用错（不该暴露给蓝图的暴露了）**
```cpp
// ❌ 内部临时值不该给蓝图
UPROPERTY(BlueprintReadWrite) int32 TempCache;   // 内部缓存暴露了
// ✅ 内部临时用 Transient 或不写 UPROPERTY
UPROPERTY(Transient) int32 TempCache;
```

**④ 忘了 Replicated 就网络同步不上**
```cpp
// ❌ 网络游戏里忘了 Replicated
UPROPERTY() float Health;   // 客户端看不到变化
// ✅
UPROPERTY(Replicated) float Health;
```

## 七、总结速查

```
反射宏全家福：
  UCLASS()      → 标记类
  UPROPERTY()   → 标记属性（序列化/蓝图/GC/网络）
  UFUNCTION()   → 标记函数（蓝图调用/网络 RPC）
  USTRUCT()     → 标记结构体
  UENUM()       → 标记枚举
  UINTERFACE()  → 标记接口
  GENERATED_BODY() → 反射代码插入点（必须第一个）

核心原理：
  宏 = 给 UHT 的标记
  UHT 扫描 → 生成 .generated.h → 引擎能反射

必记参数：
  UPROPERTY：BlueprintReadWrite / EditAnywhere / Replicated / Transient
  UFUNCTION：BlueprintCallable / BlueprintPure / Server
```

**一句话**：UE 反射宏是一整族（`UCLASS`/`UPROPERTY`/`UFUNCTION`/`USTRUCT`/`UENUM`），本质是**给 UHT 的标记**。`GENERATED_BODY()` 是"让生成的反射代码插入的地方"，反射类**必须有且放第一个**。写 UObject 代码的核心就是**用这些宏告诉 UHT"哪些要反射、怎么反射"**。
