### 教学节奏与 md 产物
- **03** 教学中每遇到问题主动自建 md 总结（问题/背景/原因/解决办法/源码依据/一句话结论），不等提醒。

- **05** 每步落独立小 md，每 md 只放 3~5 知识点（用户「很讨厌文件太大」），宁可多建小文件。
- **07** 每教完一小步，**同一轮**立刻建好对应 md；拆几步=建几个 md；禁止只口头拆、禁止等用户催。
- **08** md/讲解开场先讲「这一小步解决什么问题 + 为什么这么写」，再给代码，贴完逐段回扣「为什么」。
- **18** 代码里出现没教过的方法/宏，先讲「干嘛用 + 源码在哪 + 为什么这么用」再往下，并登记 `已教方法.md`（教前查表去重）。

- **29** 判断「下一步」回总 md 全景清单逐项核对（不凭进度表）；**教 = 建 md**（讲义不能只发聊天）；收到「下一步」先读用户工程真实代码确认写完了再推进。
- **35** 每个独立教学内容（一个类/文件）必须先建它自己的总 md；上级总 md 只是目录，不能替代（哪怕上级是我刚建的）。
- **37** 新建 md 前先列目录看既有命名格式照抄：`主号_类名_总md/_h/_cpp`，下划线分隔，不用 `-h`、不用中文后缀、不用 `.0`。
- **38** 每教一步，同一轮同步更新总纲 + 阶段总 md 的进度状态（✅/🟡/⬜/⏳）。
- **40** 教同类内容先套已被用户认可的正确范本结构（一、本文件要解决什么 → 二、对应 Lyra 源码（只给路径+前缀说明）→ 三、完整代码（替换版+中文注释）→ 四、逐段讲解），禁止自创「原文→拆解→替换版」三段式。

### 代码交付与注释（反复翻车红线）
- **21** 教学代码注释一律中文（说人话），代码标识符原样不动。
- **28** 还原大段真实源码（`Target.cs`/`Build.cs`/配置）注释也中文化，别拿「源码原文要保真」当借口。
- **32** 每次教方法，方法正上方加一行 `// 中文注释`（`.h` 和 `.cpp` 都加、意思一致），其余与 Lyra 一模一样。
- **33** 依赖未就位的后期内容：代码一比一写全，但提示「注释挂起」（`//` 或 `#if 0`），依赖就位再解开。
- **34** 遇到注释挂起，**当场同一轮**登记 `注释备忘录.md`（条目/原因/依赖阶段/解开时机/状态），不等提醒。
- **36** 注释中文化无条件全量，连 `//~AActor interface` → `//~AActor 接口开始`、`//~End of ...` → `//~AActor 接口结束` 也要改。
- **39** 代码块注释必须**当场直接改**成中文，禁止「代码块留英文、只在表格写中文化说明」；检查扫代码块，不扫表格。
- **41** 代码块必须是「已替换好 `Tenkaichi` 前缀 + 中文注释 + 零 `// ← 改成XXX` 行内提示」的干净最终版，用户照抄即可编译；前缀说明只写在代码块外。
- **42** 方法注释写在方法**正上方一行**，禁止空 `/**  */` 占位、禁止只写讲解表格不带注释。
- **43** 巩固：方法注释必须写进**代码块**；md 补了，工程已落盘的对应文件也要同步补。
- **44** 巩固：从代码块第一行到最后一个 `}`，逐个方法 / `UPROPERTY` / 成员变量查注释，别只检查开头；构造函数、虚函数覆写、私有回调、后半段最容易漏。
- **45** 铁律：交付教学代码块前**强制逐行扫描**，缺任何一处中文注释就不算完成；这是硬动作，不是软提醒。
