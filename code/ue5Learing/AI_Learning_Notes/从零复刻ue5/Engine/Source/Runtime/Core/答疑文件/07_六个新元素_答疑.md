## 二、`PrivateDependencyModuleNames` vs `PrivateIncludePathModuleNames`（最容易混）

### 2.1 源码原文

```csharp
// ModuleRules.cs:1275~1278
/// <summary>
/// List of modules name (no path needed) with header files that our module's private code files needs access to,
/// but we don't need to "import" or link against.
/// </summary>
public List<string> PrivateIncludePathModuleNames = new();

// ModuleRules.cs:1280~1284
/// <summary>
/// List of private dependency module names.  These are modules that our private code depends on but nothing in our public
/// include files depend on.
/// </summary>
public List<string> PrivateDependencyModuleNames = new();
```

### 2.2 区别（核心）

| 项 | `PrivateDependencyModuleNames` | `PrivateIncludePathModuleNames` |
|---|---|---|
| 加头路径 | ✅ 加 | ✅ 加 |
| **链接库** | ✅ **链接** | ❌ **不链接** |
| 对外传递 | ❌ 不传递 | ❌ 不传递 |
| 用途 | 真的要用它的函数 / 类 | 只要 include 它的头（比如只用到宏、类型声明） |
| 引擎注释原话 | *modules that our private code depends on* | *we don't need to "import" or link against* |

> 🔑 **一句话**：`DependencyModuleNames` = **连人带设备一起借**；`IncludePathModuleNames` = **只借说明书，不借设备**。

### 2.3 `Core.Build.cs` 里的实际用法

```csharp
// 第 19 行：真的要用 GoogleGameSDK 的代码 → 连库
PrivateDependencyModuleNames.Add("GoogleGameSDK");

// 第 21 行：AndroidPlatformMisc 只要 VulkanRHI 的头 → 不连库
PrivateIncludePathModuleNames.Add("VulkanRHI");   // AndroidPlatformMisc 需要
```

### 2.4 四个清单的完整对照

| 清单 | 出处 | 加头 | 链接 | 对外传递 |
|---|---|---|---|---|
| `PublicDependencyModuleNames` | `:1273` | ✅ | ✅ | ✅ |
| `PrivateDependencyModuleNames` | `:1284` | ✅ | ✅ | ❌ |
| `PublicIncludePathModuleNames` | `:1268` | ✅ | ❌ | ✅ |
| `PrivateIncludePathModuleNames` | `:1278` | ✅ | ❌ | ❌ |

> 记忆法：**`Dependency` = 连库，`IncludePath` = 只要头；`Public` = 对外传递，`Private` = 只自己用。**

## 三、`Utils.MakePathRelativeTo`（算相对路径）

### 3.1 源码

```csharp
// System\Utils.cs:740
public static string MakePathRelativeTo(string SourcePath, string RelativeToDirectory, bool AlwaysTreatSourceAsDirectory = false)
{
	if (String.IsNullOrEmpty(RelativeToDirectory))
	{
		// Assume CWD
		RelativeToDirectory = ".";
	}

	string AbsolutePath = SourcePath;
	if (!Path.IsPathRooted(AbsolutePath))
	{
		AbsolutePath = Path.GetFullPath(SourcePath);
	}
	...
	Uri AbsolutePathUri = new Uri(AbsolutePath);
	...
	Uri UriRelativePath = AbsoluteRelativeDirectoryUri.MakeRelativeUri(AbsolutePathUri);
	string RelativePath = Uri.UnescapeDataString(UriRelativePath.ToString()).Replace('/', Path.DirectorySeparatorChar);
	...
}
```

### 3.2 三个参数

| 参数 | 类型 | 含义 |
|---|---|---|
| `SourcePath` | `string` | 要转的路径（可以是绝对或相对） |
| `RelativeToDirectory` | `string` | 以哪个目录为基准 |
| `AlwaysTreatSourceAsDirectory` | `bool`（默认 `false`） | 是否强制把 `SourcePath` 当目录（末尾补分隔符） |

### 3.3 实现思路（4 步）

| 步 | 干什么 |
|---|---|
| ① | 空基准 → 用 `"."`（当前目录） |
| ② | `SourcePath` 不是绝对路径 → `Path.GetFullPath` 转绝对 |
| ③ | 两个路径都转成 `Uri`（`new Uri(...)`） |
| ④ | 用 `Uri.MakeRelativeUri` 算相对路径，再把 `/` 换回系统分隔符 |

> 类比：`MakePathRelativeTo` 是「问路」——「从引擎根出发，怎么走到 Core 模块？」答案就是 `Engine/Source/Runtime/Core`。

### 3.4 `Core.Build.cs` 第 29 行在干什么

## 四、`AdditionalPropertiesForReceipt`（构建回执附加属性）

### 4.1 源码

```csharp
// ModuleRules.cs:1435~1438
/// <summary>
/// List of additional properties to be added to the build receipt
/// </summary>
public ReceiptPropertyList AdditionalPropertiesForReceipt = new();
```

```csharp
// ModuleRules.cs:413~452
[Serializable]
public class ReceiptPropertyList
{
	readonly List<ReceiptProperty> _inner = new();

	internal IReadOnlyList<ReceiptProperty> Inner => _inner.AsReadOnly();

	public ReceiptPropertyList() { }

	/// <summary>
	/// Add a receipt property to the list
	/// </summary>
	public void Add(string name, string value)
	{
		_inner.Add(new ReceiptProperty(name, value));
	}

	public int RemoveAll(Predicate<ReceiptProperty> match)
	{
		return _inner.RemoveAll(match);
	}
}
```

### 4.2 是什么

| 项 | 内容 |
|---|---|
| 类型 | `ReceiptPropertyList`（自定义类，内部是 `List<ReceiptProperty>`） |
| 干什么 | 往**构建回执文件**（`.target` JSON）里写键值对 |
| 谁读 | 打包工具（如 `UEDeployAndroid`）读回执，按 key 找 value |

## 六、`Target.RelativeEnginePath`（引擎根相对路径）

### 6.1 源码

```csharp
// ReadOnlyTargetRules.cs:650~652
/// Provide access to the RelativeEnginePath property for code referencing ModuleRules.BuildConfiguration.
public string RelativeEnginePath => Unreal.EngineDirectory.MakeRelativeTo(DirectoryReference.GetCurrentDirectory()) + Path.DirectorySeparatorChar;
```

### 6.2 是什么

| 项 | 内容 |
|---|---|
| 类型 | `string`（只读属性） |
| 值 | 引擎根目录**相对当前工作目录**的路径，**末尾带分隔符** |
| 干什么 | 作为 `MakePathRelativeTo` 的基准目录 |

### 6.3 举例

| 场景 | 值 |
|---|---|
| 当前目录 = 引擎根 | `.\`（Windows）或 `./`（Linux） |
| 当前目录 = 引擎根的上一级 | `UE_5.6\` |
| 当前目录 = 项目目录 | `..\..\..\UE_5.6\` |

> 注意末尾那个 `+ Path.DirectorySeparatorChar` —— 保证是「目录」而不是「文件」。
