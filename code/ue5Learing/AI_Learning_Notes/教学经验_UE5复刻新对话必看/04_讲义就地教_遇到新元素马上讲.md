## 二、正确写法（照抄这个结构）

**每段代码下面固定两节：`本段新元素` + `这段在干什么`**

````markdown
### 3.3 Android 块（第 18~31 行）

```csharp
		if (Target.Platform == UnrealTargetPlatform.Android)
		{
			PrivateDependencyModuleNames.Add("GoogleGameSDK");
			...
		}
```

**本段新元素**

- `Target.Platform` —— 当前编译平台（`ReadOnlyTargetRules.cs:56`）
- `UnrealTargetPlatform.Android` —— Android 平台名，struct 静态属性（`UEBuildTarget.cs:267`）
- `PrivateDependencyModuleNames` —— 私有依赖模块清单，连库不对外传递（`ModuleRules.cs:1284`）
- `PrivateIncludePathModuleNames` —— 私有头路径模块清单，只要头不连库（`ModuleRules.cs:1278`）
- `Target.Configuration` —— 当前编译配置（`ReadOnlyTargetRules.cs:58`）
- `UnrealTargetConfiguration.Shipping` —— 发布配置枚举值（`UEBuildTarget.cs:1096`）
- `Utils.MakePathRelativeTo` —— 算相对路径（`System\Utils.cs`）
- `ModuleDirectory` —— 本模块目录绝对路径（`ModuleRules.cs:1550`）
- `Target.RelativeEnginePath` —— 引擎根相对当前目录的路径（`ReadOnlyTargetRules.cs:652`）
- `AdditionalPropertiesForReceipt` —— 构建回执附加属性（`ModuleRules.cs:1438`）
- `Path.Combine` —— .NET 拼路径（`System.IO`）

**这段在干什么**

| 行 | 干什么 |
|---|---|
| `GoogleGameSDK` | Android 私有依赖 |
| `VulkanRHI`（仅头路径） | `AndroidPlatformMisc` 要用它的头，但不链接 |
| `libGPUCounters` / `heapprofd` | 只在非 Shipping 加 |
| `AdditionalPropertiesForReceipt.Add(...)` | 把 `Core_APL.xml` 注册进 Android 打包流程 |

> 类比：最后一行是「把 xml 说明书塞进 Android 打包机的插槽」。
````

## 三、硬规则（4 条）

| # | 规则 |
|---|---|
| 1 | **就地教**：每段代码后**立刻**列「本段新元素」，**不许攒到最后统一列** |
| 2 | **一行一个**：`类名.属性名` —— 一句话 —— 出处行号（`文件:行号`） |
| 3 | **只列首次出现的**：台账里已登记过的**跳过**，不重复讲 |
| 4 | **禁止四行表格**：不许写「是什么 / 从哪来 / 干什么 / 默认值」四行 |

---

## 四、为什么（用户痛点）

| 痛点 | 后果 |
|---|---|
| 属性攒到最后统一列 | 读代码时不知道这行在干什么，得翻到末尾找 |
| 每个属性四行表格 | 讲义膨胀 50%，读不下去 |
| 反复讲已讲过的 | 浪费时间 |

**解法**：**代码 → 立刻讲新元素（一行一个）→ 讲这段干什么**。读完一段就懂一段。
