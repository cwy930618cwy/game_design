# 08 — 一个文件三件套一次建完（总 md + 逐行注释版 + 还原文件）

> **定位**：2026-11-17 用户明确要求 —— 「不用这么慢啊 直接三个一起建」。
> **用户原话**：「不用这么慢啊 直接三个一起建 PixelFormat.h —— 总 md、答疑文件\12_PixelFormat.h逐行注释版.md、生成还原文件」。
> **适用范围**：`从零复刻ue5\` 全线所有还原源码文件。

---

## 一、我犯的错

教 `PixelFormat.h` 时，我按旧节奏走：

1. 先只建**总 md** → 停下等「懂了/继续」
2. 等用户确认后才建**逐行注释版 md**
3. 再等确认才**生成还原文件**

用户反应：**「不用这么慢啊 直接三个一起建」**。

**问题**：`05` 里写的「3 步流程」被我理解成了「3 个来回」，实际用户要的是**同一轮内一次做完**。

---

## 二、正确做法（一轮三件套）

收到「教 `<文件名>`」或「下一步」时，**同一轮内**依次产出：

| # | 产物 | 路径 |
|---|---|---|
| ① | **总 md** | `从零复刻ue5\<引擎路径>\NN_<文件名>_总md.md` |
| ② | **逐行注释版 md** | `...\答疑文件\NN_<文件名>逐行注释版.md` |
| ③ | **还原文件** | `ue_5.6\<同名路径>\<文件名>` |

然后**同一轮内**跑脚本验收，报结论。

> ⚠️ 不再「建完总 md 就停」。总 md 只是三件套里的第一件，不是独立交付点。

## 三、和旧规则的关系

| 规则 | 变化 |
|---|---|
| `02_讲义写法_照旧Lyra格式.md` | 仍要求「每个文件 = 总 md + 完整代码 md」；**逐行注释版 md 取代完整代码 md**（见 `05`） |
| `05_新教学流程_超详细注释md加AI生成文件.md` | 3 步流程**不变**，但**不再分 3 个来回**，同一轮做完 |
| `01_下一步前先检查还原文件.md` | 不变：收到「下一步」仍先验收上一份 |

---

## 四、硬规则（3 条）

| # | 规则 |
|---|---|
| 1 | **一轮三件套**：总 md + 逐行注释版 md + 还原文件，同一轮全部产出，不许中途停 |
| 2 | **生成后立刻脚本验收**：`codeOurs / codeEngine / diff`，diff 必须为 0（剔除注释后） |
| 3 | **验收通过才报完成**，并在回复里报三件套路径 + 代码行数 |

---

## 五、为什么（用户痛点）

| 痛点 | 后果 |
|---|---|
| 建完总 md 就停 | 用户要连说三次「继续」，节奏太慢 |
| 分三轮做 | 每轮都要重新读上下文，浪费 token |
| 用户只想要结果 | 用户要的是「文件建好 + 验收通过」，不是过程 |

**解法**：**一轮三件套 + 立刻验收 + 一次报完**。
