## 二、边界（最重要，先记这个）

| 场景 | 算不算「教学」 | 要不要登记台账 |
|---|---|---|
| 教 `Core.Build.cs` 完整代码，逐段拆解里讲到的属性 | ✅ **算** | ✅ **要登记** |
| 教 `Core_APL.xml` / `Public\` 头文件 / `Private\` 实现时讲到的属性 | ✅ **算** | ✅ **要登记** |

| 用户问「这两个 PCH 是啥」→ 我建答疑 md | ❌ **不算** | ❌ **不登记** |

> 🔑 **一句话**：**只有「我主动教还原源码」时讲的属性才登记；用户提问引出的答疑一律不进台账。**

## 三、硬动作（每次写还原源码讲义都执行）

### 3.1 写讲义前

| 步骤 | 动作 |
|---|---|
| ① | 打开 `从零复刻ue5\Engine\属性教学台账.md` |
| ② | 把本课要出现的所有 `Xxx.Yyy` 属性列出来 |
| ③ | 逐个查台账：**已登记** → 讲义里只写「见台账 #N」，不展开；**未登记** → 标记为「本课必讲」 |

### 3.2 写讲义时（**就地教，一行一个**）

**核心原则：遇到新元素就马上教，不要攒到最后统一列。**

每段代码下面按这个顺序写：

```markdown
### 3.3 Android 块（第 18~31 行）

```csharp
<这段代码>
```

**本段新元素**

- `Target.Platform` —— 当前编译平台（`ReadOnlyTargetRules.cs:56`）
- `UnrealTargetPlatform.Android` —— Android 平台名，struct 静态属性（`UEBuildTarget.cs:267`）
- `PrivateDependencyModuleNames` —— 私有依赖模块清单，连库不对外传递（`ModuleRules.cs:1284`）
- ...

**这段在干什么**

| 行 | 干什么 |
|---|---|
| ... | ... |

> 类比：...
```

**规则**：
1. **每段代码后立刻列「本段新元素」** —— 只列**第一次出现**的，已登记过的跳过
2. **一行一个**：`类名.属性名` —— 一句话 —— 出处行号
3. **不许攒到最后统一列**（用户 2026-11-16 18:33 明确要求：「能不能遇到新元素就马上教我」）
4. **不许写四行表格**（是什么/从哪来/干什么/默认值）—— 太长

### 3.3 写讲义后（同一轮内）

| 步骤 | 动作 |
|---|---|
| ① | 把本课新讲的属性**追加到台账**（照第四节格式） |
| ② | 更新台账头部「最后更新」日期与「已登记 N 项」 |
| ③ | 在回复里明确报：`本轮新登记 N 项：xxx / yyy` |

## 四、判定「首次出现」的标准

| 情况 | 算不算首次 |
|---|---|
| 属性名第一次在**还原源码讲义**里出现 | ✅ 算 |
| 属性名出现过但**没讲清**（只提了名字） | ✅ 算（补讲） |
| 属性名讲过但**换了用法**（如从 `==` 变 `IsInGroup`） | ✅ 算（补讲新用法） |
| 属性名讲过且用法相同 | ❌ 不算（查台账即可） |
| 枚举值第一次出现（如 `UnrealTargetConfiguration.Shipping`） | ✅ 算（讲清这个值什么意思） |
| **只在答疑 md 里讲过** | ❌ **不算**（答疑不进台账） |

## 五、台账登记格式（照抄，一行一个）

```markdown
| N | `ModuleRules.NumIncludedBytesPerUnityCPPOverride` | `ModuleRules.cs:1162` | Unity 合批字节上限覆盖，0=不覆盖 | `01_Core.Build.cs_完整代码.md` |
```

**硬要求**：
1. **属性名写全**：`类名.属性名`（如 `ModuleRules.NumIncludedBytesPerUnityCPPOverride`、`Target.bUseIris`）
2. **出处精确到文件:行号**
3. **一句话说明**：只写「干什么」，不写「是什么 / 默认值」
4. **首次教学位置**写讲义文件名（**不是答疑文件名**）

## 七、为什么这么做（用户痛点）

| 痛点 | 后果 |
|---|---|
| 属性突然蹦出来，不知道哪来的 | 看不懂代码，只能死记 |
| 同一个属性反复讲 | 浪费时间，讲义臃肿 |
| 讲过的属性没记录 | 下次自己也想不起来讲过没 |

**解法**：**教还原源码时首次必讲 + 讲完登记 + 之后查表**。台账是「已讲过的证据」，也是「下次不重复的依据」。
