# 01 — 下一步前先检查还原文件（硬动作铁律）

> **定位**：2026-11-14 用户新增铁律，**优先级最高**：每次收到「下一步 / 继续」的第一件事。
> **用户原话**：「这是我的还原目录 以后我说下一步之前 你先检查下我是不是写对了 记到经验里」。
> 旧版只要求「收到下一步先核对文件是否真建好」（有没有），这条把它升级成「**逐行比对内容对不对**」。

---

## 一、为什么加这条（先讲为什么）

用户是照着讲义**亲手还原代码**的：写错一个缩进、漏一行、留一句英文注释，后面所有课都盖在错的基础上。所以「推进条件」从「文件存在」升级为「**逐行验收通过**」。

**说个场景**：施工队盖楼，上一层砖没砌正，下一层盖上去只会更歪 —— 所以每层验收合格，才发下一张图纸。你说「下一步」= 申请下一张图纸，我先去验收上一层。

> **记忆点（考点）**：**没检查完，不许建下一份教学 md，不许推进。**

## 三、硬动作：每次「下一步」之前必做

1. **定位当前这一步对应的真实文件**（例：上一步教 `UnrealEditor.Target.cs` → 检查 `ue_5.6\Engine\Source\UnrealEditor.Target.cs`）。
2. **同时读两份原文件**：还原文件 + 引擎真实源码。不许凭记忆、不许只对照自己写的讲义当基准。
3. **逐行比对**，按第四节 6 项判定。
4. **在回复里明确报出检查结论**：通过 / 不通过 + 逐项结果。
5. **全部通过**才准建下一份教学 md、才准推进一步。
6. **不通过或文件不存在 → 不推进**：逐条列出差异（引擎行号 ↔ 还原文件行号 + 期望内容），让用户先改正；等用户说「改好了 / 下一步」再**重新检查**一遍。
7. 用户没说「下一步」但甩了还原目录过来 → 也当场检查一次并报结果（本轮已这么做）。

## 四、判定表（按口径，不是逐字全等）

| 检查项 | 通过标准 |
|---|---|
| 路径 / 名字 | 与引擎同名同层级，零改名、零后缀变化 |
| 代码行 | 与引擎原文**逐字一致**（含缩进、空格、括号位置）；不删不跳、不多不少、不简化、不自己加代码 |
| 注释中文化 | 原注释译中文；类 / 方法 / `UPROPERTY` / 成员变量正上方补中文注释；**零英文注释** |
| 零教学噪声 | 无 `// ← 改成XXX`、无行内提示、无空注释占位 |
| 完整性 | 一比一贴全，不能只写一半、不能留 `TODO 以后补` |
| 交付版一致 | 与上一课给的**干净最终版代码块**一致（讲义就是标准答案） |

> ⚠️ 因为注释允许中文化 + 补注释，**行数可以不同**（例：引擎 16 行 → 还原 18 行，多出的 2 行是中文注释），但**代码行必须逐字一致**。别拿「行数不一样」误判为写错。
>
> ⚠️ **脚本比对必须按文件类型剔除注释**（`.h/.cpp` 剔 `//` + `/* */`；`.xml` 剔 `<!-- -->`），否则块注释会被当成代码行 → 假报警。详见 `07_验收脚本必须剔除块注释.md`。

---

## 五、检查结论怎么写进回复

- **通过**：`✅ 已核对 <文件>：路径/名字 ✓、代码行逐字一致 ✓、注释全中文 ✓、零提示 ✓、完整性 ✓ → 准推进`
- **不通过**：`❌ 未通过：第 N 行 …（引擎原文 … / 还原文件 …）→ 先改正，本轮不推进`
