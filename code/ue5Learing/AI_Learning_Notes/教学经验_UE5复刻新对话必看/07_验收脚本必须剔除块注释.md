# 07 — 验收脚本必须剔除块注释（否则误判「代码不一致」）

> **定位**：2026-11-17 验收 `Core_APL.xml` 与 `Public\` 5 个散头时踩到的坑，补进 `01` 的验收动作里。
> **触发场景**：用「只剔除 `//` 行」的脚本比对，`CoreMinimal.h` 报 `diffLines=173`、`Core.h` 报 `300`，看起来像全错；换成剔除块注释后 **diff=0**。
> **结论**：**不是还原文件写错了，是验收脚本写错了。**

---

## 一、我犯的错

第一版脚本只做了两件事：

```powershell
Get-Content $f -Encoding UTF8 | Where-Object { $_.Trim() -ne '' -and -not $_.TrimStart().StartsWith('//') }
```

问题：引擎头文件里大量注释是 **块注释**，不是 `//`：

| 文件类型 | 注释形式 | 只剔 `//` 会怎样 |
|---|---|---|
| `.h` / `.cpp` | `/* ---------- */` 分节横幅、`/** ... */` 文档注释 | 整块被当成「代码行」参与比对 → 全错位 |
| `.xml`（`Core_APL.xml`） | `<!-- ... -->` | 同上，`diff=116` 假报警 |
| `.cs`（`Core.Build.cs`） | 基本只有 `//` | 不受影响（所以之前没暴露） |

**误判后果**：差点把「已验收通过」的文件判成「未通过」，让用户去改一份本来正确的文件。

---

## 二、正确脚本（按文件类型选注释规则）

### 2.1 C/C++ 头文件（`//` + `/* */`）

```powershell
function Get-Code($path){
  $inBlock = $false; $out = @()
  foreach($l in (Get-Content $path -Encoding UTF8)){
    $t = $l.Trim()
    if($inBlock){ if($t -match '\*/'){ $inBlock = $false }; continue }
    if($t -eq ''){ continue }
    if($t.StartsWith('//')){ continue }
    if($t.StartsWith('/*')){ if($t -notmatch '\*/'){ $inBlock = $true }; continue }
    $out += $t
  }
  return $out
}
```

### 2.2 XML（`<!-- -->`）

```powershell
function Get-Code($path){
  $inBlock = $false; $out = @()
  foreach($l in (Get-Content $path -Encoding UTF8)){
    $t = $l.Trim()
    if($inBlock){ if($t -match '-->'){ $inBlock = $false }; continue }
    if($t -eq ''){ continue }
    if($t.StartsWith('<!--')){ if($t -notmatch '-->'){ $inBlock = $true }; continue }
    $out += $t
  }
  return $out
}
```

### 2.3 比对主体（两种通用）

```powershell
$o = Get-Code $ours; $e = Get-Code $engine
$diff = 0; $max = [Math]::Max($o.Count, $e.Count)
for($i=0; $i -lt $max; $i++){
  $a = if($i -lt $o.Count){ $o[$i] } else { '<none>' }
  $b = if($i -lt $e.Count){ $e[$i] } else { '<none>' }
  if($a -ne $b){ $diff++ }
}
"codeOurs=$($o.Count) codeEngine=$($e.Count) diff=$diff"
```

**通过标准**：`codeOurs == codeEngine` 且 `diff == 0`。

## 四、硬规则（补进 `01` 的验收动作）

| # | 规则 |
|---|---|
| 1 | 验收脚本**必须按文件类型剔除注释**：`.h/.cpp` 剔 `//` + `/* */`；`.xml` 剔 `<!-- -->`；`.cs` 剔 `//` |
| 2 | 比对前**统一 `Trim()`**（还原文件可能补了缩进/空行） |
| 3 | **diff > 0 时先怀疑脚本**，打印前 8 条差异逐条看，确认是真差异再报「未通过」 |
| 4 | 报结论时**同时报代码行数**（`codeOurs/codeEngine`），让用户能自己复核 |

---

## 五、为什么（用户痛点）

| 痛点 | 后果 |
|---|---|
| 脚本假报警 | 用户被要求改一份本来正确的文件，白费时间 |
| 只剔 `//` | 头文件/XML 全量误判，验收结论不可信 |
| 不报代码行数 | 用户无法判断「通过」是不是真的 |

**解法**：**按文件类型剔注释 + 先看差异再下结论 + 报代码行数**。
