## 一、要解决什么问题

`UE_LOG(LogHAL, Log, TEXT("..."))` 里第一个参数 `LogHAL` 不是变量、不是字符串，是一个**带身份的全局对象**：它要告诉日志系统「这条日志属于 HAL 类别」，这样运行时才能按类别单独过滤（`LogHAL Verbose` 命令只放开 HAL 的详细日志，别的类别不动）。

问题：`LogHAL` 这个对象得**有且只有一个**（多个链接器报重复符号），而且要放在 Core 模块里造好，让其他模块（你的 TenkaichiGame、Engine、Runtime）都能用。这就是「**头文件声明、cpp 定义、API 宏跨模块链接**」三件套要干的事。

## 二、宏长什么样（原文，LogMacros.h:332）

```cpp
#define DECLARE_LOG_CATEGORY_EXTERN(CategoryName, DefaultVerbosity, CompileTimeVerbosity) \
    extern struct FLogCategory##CategoryName : public FLogCategory<ELogVerbosity::DefaultVerbosity, ELogVerbosity::CompileTimeVerbosity> \
    { \
        FORCEINLINE FLogCategory##CategoryName() : FLogCategory(TEXT(#CategoryName)) {} \
    } CategoryName;
```

三个参数：
| 参数 | 含义 | `LogHAL` 例子里传的是什么 |
|------|------|--------------------------|
| `CategoryName` | 类别名（同时当 C++ 变量名） | `LogHAL` |
| `DefaultVerbosity` | **运行时默认**级别：启动后这类日志默认可见程度 | `Log`（默认只显示到普通信息，Verbose 要手动开） |
| `CompileTimeVerbosity` | **编译期上限**：比这个更弱的日志连代码都不生成 | `All`（= `VeryVerbose`，什么级别都保留） |

两个 C 预处理器技巧藏在这段里：
- `FLogCategory##CategoryName`：`##` 拼接，生成**专属结构体类型** `FLogCategoryLogHAL`（每个类别一个唯一类型，`UE_LOG_ACTIVE` 靠类型在编译期做判断）
- `TEXT(#CategoryName)`：`#` 把参数变成字符串字面量 `"LogHAL"`，这个字符串就是日志系统里显示的类别名

## 三、展开成什么（把 LogHAL 代进去）

```cpp
// CoreGlobals.h:52 原文：
CORE_API DECLARE_LOG_CATEGORY_EXTERN(LogHAL, Log, All);

// 展开后等价于：
extern struct FLogCategoryLogHAL : public FLogCategory<ELogVerbosity::Log, ELogVerbosity::All>
{
    FORCEINLINE FLogCategoryLogHAL() : FLogCategory(TEXT("LogHAL")) {}
} LogHAL;
```

三个细节：
1. **`extern`**：只声明不分配，真正的对象在 `CoreGlobals.cpp:771` 由 `DEFINE_LOG_CATEGORY(LogHAL);` 创建（展开为 `FLogCategoryLogHAL LogHAL;`）
2. **构造时的副作用**：`FLogCategory` 基类构造函数会把类别注册进「日志抑制系统」（`LogCategory.h:27` 注释原话：*"registers with the log suppression system and sets up the default values"*）——引擎启动时每个类别报到一次，后面 `LogHAL Verbose` 这种控制台命令改的就是这里的运行时级别
3. **`CORE_API` 为什么在这**：Core 模块里它 = 导出符号；别的模块 include 这个头时它 = `__declspec(dllimport)`。你自己在 TenkaichiGame 里声明类别时**不加** `CORE_API`（类别只在自己模块用）；引擎跨模块共用的类别才加

## 四、两级过滤怎么分工（为什么要有两个 Verbosity 参数）

```
一条 UE_LOG(LogHAL, Verbose, ...) 发出来时：
  ① 编译期：这条日志级别(Verbose) 超过类别的 CompileTimeVerbosity？
            超过 → 这条日志的代码直接不生成（零成本，省二进制体积）
  ② 运行期：没超过的，还要看 DefaultVerbosity（可被控制台命令改）
            Verbose > Log(当前级别)？→ 不打印；否则打印
```

`LogHAL` 传 `(Log, All)` 的意思 = 「**所有级别的代码都编进来**（调试时随时能开 Verbose），但**运行时默认只显示到 Log**」。这就是 `All` 不是「全打印」，而是「编译上限拉满」的原因。

## 五、关闭日志时的形态（NO_LOGGING=1）

`LogMacros.h:195` 有另一个分支：整个模块设了 `NO_LOGGING` 时，宏退化成

```cpp
#define DECLARE_LOG_CATEGORY_EXTERN(CategoryName, ...) extern FNoLoggingCategory CategoryName;
```

对象变成一个**空结构体**（`:149` `struct FNoLoggingCategory {};`），`UE_LOG` 也只剩 Fatal 会执行——日志功能被彻底裁掉，给对日志没需求的模块省体积。

## 速查

| 要做什么 | 写法 |
|---------|------|
| 头文件声明类别 | `DECLARE_LOG_CATEGORY_EXTERN(LogMyGame, Log, All);` |
| cpp 里创建对象 | `DEFINE_LOG_CATEGORY(LogMyGame);`（必须和声明配对，否则链接不到） |
| 只在单个 cpp 用的类别 | `DEFINE_LOG_CATEGORY_STATIC(LogLocal, Log, All);`（不跨文件） |
| 运行时临时改级别 | 控制台敲 `LogMyGame Verbose` |
