# 铁律 42：方法注释必须「写在方法正上方一行」，禁止只用空 JSDoc 占位 / 只写讲解表格不带注释

> **定位**：本条是 [32](./32_每次教方法上面都要加注释_其余与Lyra一模一样.md) 的**执行层收口版**，堵住"方法上面"这句被钻空子的漏洞。
> **教训**：2026-11-03 P10.2 `IInteractableTarget` 的 `.h` 教学 md 里，两个方法（`GatherInteractionOptions` / `CustomizeInteractEventData`）上面只放了空注释 `/**  */`，真正的"这方法干嘛的"写在了**下面表格**里，没写在方法正上方。用户照抄代码块，工程里就完全没有方法注释。

---

## 一、这条铁律怎么来的（真实场景，2026-11-03）

教 P10.2 `IInteractableTarget.h` 时，AI 在"完整代码"和"逐段讲解"里展示了两个虚方法，但方法上面只有：

```cpp
public:
	/**  */                                          ← 空注释占位，什么都没写
	virtual void GatherInteractionOptions(const FInteractionOption& ...) = 0;

	/**  */                                          ← 空注释占位
	virtual void CustomizeInteractionEventData(...) { }
```

真正的方法说明写在了**方法下面的表格**里（"这个方法是干嘛的"），而不是方法**上面**。用户照着代码块抄进工程，工程里的方法**一个注释都没有**。

**根因**：
1. 把"讲解文字（表格）"当成"方法注释"的替代品——觉得"反正下面表格讲了，方法上面就不用写"。这是 [39](./39_代码块注释要直接写中文_别只写说明不实际改.md) / [41](./41_代码块必须直接给替换好前缀的中文完整版_禁止留Lyra原文加行内改前缀提示.md) 的同款病：**该落实在代码块里的，没落实**。
2. 写了空 JSDoc `/**  */` 自我欺骗——以为"有个注释结构"就算数，其实里面是空的。
3. 用户是**照抄代码块**的，代码块里方法没注释，工程里就永远没注释。

---

## 二、核心规则（硬动作）

**凡是出现在教学 md（不管总 md 还是 `.h` / `.cpp` 教学）代码块里的方法 / 函数，必须满足：**

1. **注释写在方法正上方**：`// 中文注释` 或 `/** 中文 */` 紧跟方法上面，讲清"这方法干嘛的、何时被调用"。
2. **禁止空 JSDoc 占位**：`/**  */`、`/** TODO */` 一律视为没写，必须填真实中文说明。
3. **禁止只写表格不带注释**：表格 / 正文讲解只是解说，**不能替代方法上方的行注释**。
4. **`// 注释` 与 `/** */` 都行**，但内容必须是真的中文说明，不能空。

---

## 三、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 教一个方法 | 方法正上方写 `// 返回这个 Actor 能提供的所有交互选项` | 方法上面空着，只在下面表格讲 |
| 有下面表格 | 表格照讲，但**方法正上方必须同时有行注释** | 用表格顶替方法上方注释 |
| 注释格式 | `// 中文` 或 `/** 中文 */`，内容真实 | `/**  */` 空注释占位 |
| 收尾检查 | 扫一遍代码块，每个方法上方都有中文注释 | 只看正文表格有没有讲解 |

## 四、和 32 / 39 / 41 的关系

- **32 号**：教方法上面要加注释（**是什么**）。
- **42 号（本号）**：注释必须**写正上方**、内容**真实中文**、**不得空占位**、**不得用表格替代**（**怎么落实**）。

> 32 说"要加"，42 说"怎么算加到位"——正上方 + 真实中文 + 非空。
