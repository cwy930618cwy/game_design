# `__ExternalActors__` 和 `__ExternalObjects__` 到底是什么

> **定位**：你项目 `Content/` 下突然冒出两个带 `__` 前缀的怪目录，里面全是乱码名的 `.uasset`。这篇讲清它们是啥、能不能删、要不要提交 Git。**最后有个故事，看不懂正文直接跳到最后一节。**
>
> **一句话**：它们是**你的关卡数据本身**，只是被 UE5 从"一个大文件"拆成了"每个物件一个小文件"。**不是缓存，不能删，必须提交版本控制。**

---

## 一、先补一个前提：场景里的东西存在哪

你在编辑器里往场景摆一个灯、一个箱子、一个敌人出生点 —— 这些东西在 UE 里统一叫 **Actor**。

UE4 时代，一张地图里**所有 Actor 全部塞进同一个 `.umap` 文件**：

```
Content/
└── oneMAP.umap   ← 1 个文件，装着 138 个灯/箱子/出生点/...
```

你的 `oneMAP.umap` 里现在就有 138 个物件。以前它们全挤在这一个文件里。

---

## 二、一个文件装所有，有什么毛病

| 毛病 | 具体表现 |
|---|---|
| **协作必冲突** | 你改 3 号灯，同事改 50 号箱子，但你们改的是**同一个文件**。Git 合并冲突，谁后保存覆盖谁，另一个人的活白干 |
| **保存巨慢** | 动一个灯，整个 `.umap`（几十上百 MB）要重写一遍 |
| **浪费资源** | 只想加载地图一角，也得把整个文件读进来 |

> 关卡越大、人越多，这三件事越致命。Lyra 那种开放世界地图，几十人协作，老办法直接没法干活。

---

## 三、UE5 的解法：One File Per Actor（一物件一文件）

简称 **OFPA**。思路简单粗暴：**别挤一个文件了，每个 Actor 单独存一个 `.uasset`。**

于是你的目录变成这样：

```
Content/
├── oneMAP.umap                    ← 只剩"壳子"：关卡设置、分区网格配置
├── oneMAP_HLOD0_Instancing.uasset ← 远景 LOD（大地图专用，自动生成）
│
└── __ExternalActors__/oneMAP/     ← 【新】138 个物件 = 138 个独立文件
    ├── 3/A5/QKY4V0XJDGCXUUBU6NMC28.uasset   ← 可能是某个灯
    ├── B/XX/................................uasset   ← 可能是某个箱子
    └── ...（共 138 个）
```

**带来的好处，正好治上面三个毛病：**

| 之前 | 现在 |
|---|---|
| 改啥都冲突 | 你改 `3/A5/xxx`，同事改 `B/XX/yyy`，**两个文件，零冲突** |
| 保存要重写整个 umap | 只重写变动的那一张卡片，**秒存** |
| 加载要读整个关卡 | 按网格单元按需加载，走进哪片读哪片 |

---

## 四、乱码目录名怎么读

```
__ExternalActors__/oneMAP/3/A5/QKY4V0XJDGCXUUBU6NMC28.uasset
                       │   │  │
       地图名 ─────────┘   │  │
       身份证第 1 位 ──────┘  │
       身份证第 2-3 位 ───────┘
       身份证剩下的部分 = 文件名
```

每个 Actor 有个全局唯一 ID（类似身份证号），UE 把它编码成一串 26 位的乱码。**取前 3 位分两级抽屉**（第一级 1 位，第二级 2 位），剩下的做文件名。

所以你看到 `0~9` 和 `A~F` 共 **16 个顶层抽屉** —— 只是为了**防止一个文件夹里堆几万个文件把系统卡死**。

> ⚠️ **名字没有任何含义**，看不出这是灯还是箱子。想知道是哪个物件，只能在编辑器里选中它看名字。**所以千万别去手动改这些文件名。**

---

## 五、那 `__ExternalObjects__` 又是什么

看名字就懂：

| 目录 | 装的 | 你的项目 |
|---|---|---|
| `__ExternalActors__` | **Actor**（灯、箱子、出生点这些"主角"） | 138 个文件 |
| `__ExternalObjects__` | **不是 Actor、但挂在 Actor 身上的小零碎**（内嵌子对象） | 只有 6 个抽屉有东西，很少 |

打个比方：Actor 是"家具"，Object 是"家具上拆下来的灯泡、靠垫"。它们也得有地方放，但自己不算独立家具，所以另开一个柜子。

**实际项目中这个目录通常文件很少（你这就是）**，不用太在意它，知道它跟 `__ExternalActors__` 是同一套机制的副产品就行。

---

## 六、这三个必须记住的结论

| 问题 | 答案 |
|---|---|
| 是缓存吗？能删吗？ | ❌ **是关卡数据**。删了 = 场景里物件消失 |
| 要提交 Git 吗？ | ✅ **必须**，和 `.umap` 同等重要 |
| 能手动改文件名/内容吗？ | ❌ 全由编辑器自动管理，手改必坏 |
| 我 `.gitignore` 里要不要排除？ | ❌ **不要**。你现在的 `.gitignore` 没排除它们，是对的 ✅ |
| 冲突了怎么办？ | 别手改，用编辑器重新打开保存，让它自己重新导出 |

> 💡 **最常见的翻车**：看到 `__` 前缀以为是临时文件，`gitignore` 一加，队友一拉代码，场景里一半东西没了。

---

## 七、我为啥会有这俩目录？（World Partition）

因为你的 `oneMAP` 是一张 **World Partition（世界分区）地图** —— UE5 的大地图方案，把地图切成网格单元，按需流式加载。OFPA 是它的配套存储机制。

证据（都在你项目里）：
- 有 `oneMAP_HLOD0_Instancing.uasset` ← HLOD 是 World Partition 专属的远景 LOD
- `Config/DefaultEngine.ini` 里有 `WorldPartitionEditorSettings` 配置节

**小场景其实用不上它**，反而让 Git 多出上百个文件。想关掉：

```
编辑器里打开地图 → Window → World Partition 面板 → 取消 Enable World Partition
```

但如果你后面要做 Lyra 那种中大型场景，**留着是对的**，现在熟悉一下不亏。

---

## 八、常见误区

| 误区 | 正确理解 |
|---|---|
| "这是缓存/临时文件" | ❌ 是关卡数据，删了物件就没了 |
| "这么多文件好乱，我想合并回去" | ❌ 合并不了，这是引擎机制 |
| "文件名改成中文好认" | ❌ 改名 = 引用断裂，物件丢失 |
| "我可以手动删掉不用的 uasset" | ❌ 要在编辑器里删 Actor，让引擎自己清理 |
| "它太大了占空间" | 总量和原来的单个 umap 差不多，只是被拆散了 |
| "`__ExternalObjects__` 是给蓝图用的" | ❌ 是 Actor 的内嵌子对象，跟蓝图无关 |

## 九、最后：一个故事

> 正文没看懂的话，看这个就够了。

想象你开了一家**大型家具展厅**（= 你的地图 `oneMAP`），展厅里摆着 138 件家具 —— 沙发、台灯、地毯、假人模特……（= 138 个 Actor）。

### 老办法：一本厚册子

以前你只有**一本厚厚的《展厅布置总册》**。每一件家具摆在哪、什么颜色、朝哪个方向，全部画在这**同一本册子**上。

日子一长，两个问题越来越折磨人：

**第一，员工打架。**
你让小明去调一下 3 号台灯的位置，让小红去换个 50 号沙发的颜色。但小明和小红**得抢同一本册子**——册子只有一本，谁先写完谁保存，另一个人打开一看，自己刚写的那一页被覆盖回旧版本了。活白干，还互相埋怨。

> 这就是 UE4：所有人抢同一个 `.umap`。

**第二，改一个字要重印整本。**
小明只是把台灯挪了 5 厘米，但因为是同一本册子，你必须把**整整 138 页全部重新打印一遍**。展厅越大，册子越厚，改一个字越慢。

> 这就是 UE4：动一个 Actor，整个 umap 重写。

### 新办法：一个分格文件柜

后来你换了个思路：买了一个**带 16 个抽屉的文件柜**（就是那 `0~9` `A~F` 十六个顶层目录）。

**每件家具单独写一张卡片**，卡片编号用家具的身份证号算出来，所以看着像 `3/A5/QKY4V0XJDGCXUUBU6NMC28` 这种鬼画符。然后按编号**塞进对应的抽屉**：

- 台灯的卡片 → 塞进 `3` 号抽屉的 `A5` 格
- 沙发的卡片 → 塞进 `B` 号抽屉的某个格

> 这就是 `__ExternalActors__`：一物件一文件。

现在好事发生了：

- 小明拿台灯的卡片改，小红拿沙发的卡片改，**各拿各的，谁也不碍着谁** → 协作零冲突
- 台灯改完只重印一张卡片，不用重印整本册子 → 保存飞快
- 顾客只看客厅区，你就只抽客厅那几张卡片给他看 → 按需加载

而那本《展厅布置总册》还在（`oneMAP.umap`），但它现在**只剩封面、目录和展厅的分区规划图**了，不再画具体家具。

### 那 `__ExternalObjects__` 呢？

有些家具自带小零碎——台灯上的灯泡、沙发上的靠垫。它们**不算独立家具**（不是 Actor），但你拆家具的时候它们也得跟着拆下来单独放。

于是你又摆了个**小一号的柜子**专门装这些零碎：`__ExternalObjects__`。

东西很少 —— 你家这个柜子只有 6 个抽屉里有货。

### 最后一句要命的

**这些卡片不是草稿，它们就是你的展厅。**

哪天你觉得"柜子里这一堆乱码文件好碍眼，清了吧"，然后 `Delete` —— 恭喜，展厅空了，家具全没了。

所以：**别删，别改名，别 gitignore，老老实实提交上去。**

## 十、总结速查

```
__ExternalActors__   = 关卡里每个 Actor 单独存成一个文件（138 个 = 138 个物件）
__ExternalObjects__  = Actor 身上挂的小零碎（非 Actor 子对象），通常很少
oneMAP.umap          = 只剩壳子 + 分区配置，不再装具体物件

目录规则：地图名 / 身份证前1位 / 前2-3位 / 剩下部分.uasset
         目的只是防止单目录文件过多，名字没有语义

三要三不要：
  ✅ 提交 Git    ✅ 交给编辑器管理    ✅ 冲突时重开编辑器保存
  ❌ 不删        ❌ 不改名            ❌ 不 gitignore

出现原因：这张地图开了 World Partition（UE5 大地图方案）
小场景想去掉：World Partition 面板 → 取消 Enable World Partition
```

**一句话**：`__ExternalActors__` 就是把原本挤在一个 `.umap` 里的上百个物件**拆成上百个小文件**，为的是**多人协作不打架、保存快、按需加载**——它是**关卡数据本身**，不是缓存，删了物件就没了。
