# `SynchronousLoadAsset` / `AddLoadedAsset` / `StartInitialLoading` 等 —— 内部辅助与重写函数

> **定位**：解释 `LyraAssetManager.h` 第 70-84 行这一批函数。
>
> **原代码**：
> ```cpp
> static UE_API UObject* SynchronousLoadAsset(const FSoftObjectPath& AssetPath);   // 同步加载
> static UE_API bool ShouldLogAssetLoads();                                       // 是否记录加载日志
>
> // Thread safe way of adding a loaded asset to keep in memory.
> UE_API void AddLoadedAsset(const UObject* Asset);                               // 线程安全地记录已加载资源
>
> //~UAssetManager interface
> UE_API virtual void StartInitialLoading() override;                             // 重写：初始加载入口
> #if WITH_EDITOR
>     UE_API virtual void PreBeginPIE(bool bStartSimulate) override;              // 重写：编辑器 PIE 前
> #endif
> //~End of UAssetManager interface
>
> UE_API UPrimaryDataAsset* LoadGameDataOfClass(...);                             // 加载游戏数据类
> ```
>
> **一句话**：这几个是资产管理器的**内部辅助函数**（同步加载、记录日志、线程安全存资源）和**重写引擎的函数**（启动加载、PIE 前处理）。它们支撑起前面讲的 `GetAsset`/`GetOrLoadTypedGameData` 等对外接口——是"幕后工作者"。

---

## 一、总览：这几个函数分两类

| 函数 | 类型 | 作用 |
|------|------|------|
| `SynchronousLoadAsset` | 内部辅助 | **同步加载**一个资源（阻塞等加载完） |
| `ShouldLogAssetLoads` | 内部辅助 | 判断要不要记录加载日志（调试用） |
| `AddLoadedAsset` | 内部辅助 | **线程安全地**把资源加进"已加载"集合 |
| `StartInitialLoading` | **重写引擎** | 游戏启动时的初始加载入口 |
| `PreBeginPIE` | **重写引擎** | 编辑器里点"运行"前的处理 |
| `LoadGameDataOfClass` | 内部辅助 | 加载一个游戏数据类（存进缓存） |

> 前三个是"**幕后工作者**"（被 `GetAsset` 等调用），后两个是"**接管引擎时机**"（重写引擎的加载节点）。

## 二、`SynchronousLoadAsset` —— 同步加载（阻塞）

```cpp
static UE_API UObject* SynchronousLoadAsset(const FSoftObjectPath& AssetPath);
```

### 实现

```cpp
UObject* ULyraAssetManager::SynchronousLoadAsset(const FSoftObjectPath& AssetPath)
{
    if (AssetPath.IsValid())
    {
        if (UAssetManager::IsInitialized())
        {
            return UAssetManager::GetStreamableManager().LoadSynchronous(AssetPath, false);
        }
        // 资产管理器还没就绪，用 LoadObject
        return AssetPath.TryLoad();
    }
    return nullptr;
}
```

### 讲什么

- **同步加载** = **阻塞式**加载，代码停在这行，直到资源加载完才继续。
- 传入资源路径（`FSoftObjectPath`），返回加载好的对象。
- **两种加载方式**：
  - 资产管理器就绪 → 用 `StreamableManager.LoadSynchronous`（引擎的资源流送系统）。
  - 还没就绪 → 用 `AssetPath.TryLoad()`（更底层的直接加载）。
- 还带**计时日志**（`ShouldLogAssetLoads` 开启时记录加载耗时）。

> **对比异步加载**：异步加载是"发起加载后继续干别的，加载完回调通知"；同步是"死等，加载完才往下走"。Lyra 这里很多用同步，因为游戏逻辑常需要"立刻拿到资源"。

## 三、`ShouldLogAssetLoads` —— 要不要记录加载日志

```cpp
static UE_API bool ShouldLogAssetLoads();
```

### 实现

```cpp
bool ULyraAssetManager::ShouldLogAssetLoads()
{
    static bool bLogAssetLoads = FParse::Param(FCommandLine::Get(), TEXT("LogAssetLoads"));
    return bLogAssetLoads;
}
```

### 讲什么

- 判断**命令行**里有没有 `-LogAssetLoads` 参数。
- 有 → 返回 true → 加载资源时记录耗时日志（调试用）。
- `static` 局部变量：只读一次命令行，之后缓存结果（不用每次都解析）。

> **用途**：调试性能时，启动加 `-LogAssetLoads`，就能看到每个资源加载花了多久，定位"哪个资源加载拖慢了启动"。

## 四、`AddLoadedAsset` —— 线程安全地记录已加载资源

```cpp
// Thread safe way of adding a loaded asset to keep in memory.
UE_API void AddLoadedAsset(const UObject* Asset);
```

### 实现

```cpp
void ULyraAssetManager::AddLoadedAsset(const UObject* Asset)
{
    if (ensureAlways(Asset))
    {
        FScopeLock LoadedAssetsLock(&LoadedAssetsCritical);   // ← 加锁
        LoadedAssets.Add(Asset);
    }
}
```

### 讲什么

- 把加载好的资源加进 `LoadedAssets` 集合（前面讲过的"防 GC 集合"）。
- **`FScopeLock` 加锁**：因为资源可能在**多线程**加载，同时修改 `LoadedAssets` 会数据竞争，用临界区锁（`LoadedAssetsCritical`）保证安全。
- `ensureAlways(Asset)`：保证传入非空。

> **呼应前面**：`GetAsset`/`GetSubclass` 里 `bKeepInMemory=true` 时就是调它，把资源记进"常驻集合"防止被垃圾回收。**线程安全**是生产级代码的严谨之处。

## 五、`StartInitialLoading` —— 重写引擎的初始加载入口 ★

```cpp
//~UAssetManager interface
UE_API virtual void StartInitialLoading() override;
```

### 实现

```cpp
void ULyraAssetManager::StartInitialLoading()
{
    Super::StartInitialLoading();              // ① 先调父类（引擎的扫描逻辑）

    STARTUP_JOB(InitializeGameplayCueManager());  // ② 加入启动任务：初始化 Cue 管理器

    {
        STARTUP_JOB_WEIGHTED(GetGameData(), 25.f);  // ③ 加入启动任务：加载 GameData（权重 25）
    }

    DoAllStartupJobs();                        // ④ 执行所有排队的启动任务
}
```

### 讲什么

- **重写引擎的加载入口**——游戏启动、引擎初始化资源时触发。
- **`Super::StartInitialLoading()`**：先调父类（引擎的通用扫描逻辑）。
- **`STARTUP_JOB`**：把任务加进"启动任务队列"（`StartupJobs`）——这里加了两个：
  - `InitializeGameplayCueManager()`：初始化 GAS 的 Cue 管理器（加载必加载的 Cue）。
  - `GetGameData()`：加载全局游戏数据（权重 25，表示占 25% 进度）。
- **`DoAllStartupJobs()`**：逐个执行排队的任务，并更新加载进度（喂给加载界面）。

> **这就是 Lyra 启动进度条的来源**：启动任务被拆成一个个 job，按权重算进度百分比，喂给 loading screen。

## 六、`PreBeginPIE` —— 重写引擎的"运行前"处理

```cpp
#if WITH_EDITOR
UE_API virtual void PreBeginPIE(bool bStartSimulate) override;
#endif
```

### 讲什么

- **只在编辑器里有效**（`#if WITH_EDITOR` 包裹，发布版没有）。
- **重写引擎的 PIE 前回调**——你在编辑器点"运行"（Play）时，正式进入游戏前触发。
- 实现里：显示一个"Loading PIE Data"进度对话框，调 `GetGameData()` 确保游戏数据加载好，还能在这里预加载该体验需要的其他资源。

> **PIE** = Play In Editor（编辑器里点运行测试）。这个函数让你在"点运行 → 真正进入游戏"之间插入自定义的准备工作。

## 七、`LoadGameDataOfClass` —— 加载游戏数据类

```cpp
UE_API UPrimaryDataAsset* LoadGameDataOfClass(
    TSubclassOf<UPrimaryDataAsset> DataClass,
    const TSoftObjectPtr<UPrimaryDataAsset>& DataClassPath,
    FPrimaryAssetType PrimaryAssetType);
```

### 讲什么

- 真正执行"加载一个游戏数据资产"的函数。
- 上一篇的 `GetOrLoadTypedGameData` 缓存没命中时，就是调它去加载。
- 参数：要加载的类型（`DataClass`）、路径（`DataClassPath`）、资源类型（`PrimaryAssetType`）。
- 内部会加载资源、存进 `GameDataMap` 缓存（编辑器下还带进度条 `FScopedSlowTask`）。

> **关系链**：`GetGameData()` → `GetOrLoadTypedGameData()`（查缓存）→ 没命中 → `LoadGameDataOfClass()`（真加载 + 存缓存）。

## 八、这些函数怎么串起来（完整链路）

```
【启动时】
  引擎触发 StartInitialLoading()（重写）
     ↓ 排队启动任务
     ↓ DoAllStartupJobs() 执行
  加载 GameData、初始化 Cue 管理器
     ↓ 加载资源时调
  SynchronousLoadAsset()（同步加载）
     ↓ 加载完调
  AddLoadedAsset()（线程安全存进常驻集合，防 GC）

【运行时某处要 GameData】
  GetGameData()
     ↓
  GetOrLoadTypedGameData()（查缓存）
     ↓ 没命中
  LoadGameDataOfClass()（真加载）
     ↓ 内部调
  SynchronousLoadAsset() → AddLoadedAsset()

【编辑器点运行】
  引擎触发 PreBeginPIE()（重写）
     ↓ 确保 GameData 加载好、预加载体验资源
```

> **分工清晰**：对外接口（`GetAsset`/`GetGameData`）→ 缓存逻辑（`GetOrLoadTypedGameData`）→ 底层加载（`LoadGameDataOfClass`/`SynchronousLoadAsset`）→ 记录防 GC（`AddLoadedAsset`）。启动/PIE 时机由重写函数接管。

## 九、为什么这些大多标了 UE_API？

注意这批函数**大部分标了 `UE_API`**（`SynchronousLoadAsset`、`AddLoadedAsset`、`StartInitialLoading`、`LoadGameDataOfClass`），但它们是 `protected`（内部用）。

**看似矛盾，其实合理**：
- 它们是 `protected`，外部不能直接调——但**子类**（如果别的模块继承 `ULyraAssetManager`）可能需要调。
- `StartInitialLoading`/`PreBeginPIE` 是**虚函数重写**，引擎要通过基类指针调用，跨模块场景，需要导出。

> 标 `UE_API` 是为了"万一别的模块继承/调用"留有余地，比漏标导致链接错误更安全。

## 十、JS 对照

```js
class AssetManager {
    #loadedAssets = new Set();
    #critical = new Lock();  // 模拟临界区

    // 同步加载（JS 里模拟阻塞）
    synchronousLoadAsset(path) {
        return this.loadBlocking(path);  // 阻塞直到加载完
    }

    // 线程安全地记录
    addLoadedAsset(asset) {
        this.#critical.lock();           // 加锁
        this.#loadedAssets.add(asset);
        this.#critical.unlock();
    }

    // 启动加载（重写引擎钩子）
    startInitialLoading() {
        super.startInitialLoading();
        this.startupJobs.push(() => this.getGameData());
        this.doAllStartupJobs();
    }
}
```

| 概念 | JS | C++（本批函数） |
|------|-----|----------------|
| 同步加载 | 阻塞 await | `LoadSynchronous` |
| 线程安全 | Worker + 锁 | `FScopeLock` + `FCriticalSection` |
| 重写引擎钩子 | 覆盖父类方法 | `virtual ... override` |
| 命令行参数 | `process.argv` | `FParse::Param` |

## 十二、总结

```
这批函数 = 内部辅助 + 重写引擎钩子（幕后工作者）

内部辅助（被对外接口调用）：
  SynchronousLoadAsset  → 同步阻塞加载资源
  ShouldLogAssetLoads    → 是否记录加载日志（调试）
  AddLoadedAsset        → 线程安全存进常驻集合（防 GC）
  LoadGameDataOfClass    → 真加载游戏数据 + 存缓存

重写引擎（接管加载时机）：
  StartInitialLoading   → 启动时初始加载（排队 startup jobs + 显示进度）
  PreBeginPIE           → 编辑器点运行前的准备（仅编辑器）

完整链路：
  对外接口 → 缓存逻辑 → 底层加载(SynchronousLoadAsset) → 记录(AddLoadedAsset)
  启动/PIE 时机由重写函数接管
```

**一句话**：这几个是资产管理器的**幕后工作者**——`SynchronousLoadAsset`（同步阻塞加载）、`ShouldLogAssetLoads`（调试日志开关）、`AddLoadedAsset`（线程安全记录防 GC）是内部辅助；`StartInitialLoading`（启动初始加载、排任务队列）、`PreBeginPIE`（编辑器运行前准备）、`LoadGameDataOfClass`（真加载数据存缓存）是接管引擎加载时机的重写函数。它们共同支撑起对外的 `GetAsset`/`GetGameData` 等接口。
