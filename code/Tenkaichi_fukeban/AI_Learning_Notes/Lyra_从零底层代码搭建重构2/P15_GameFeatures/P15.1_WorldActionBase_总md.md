## 一、这个类解决什么问题（先讲为什么）

引擎的 `UGameFeatureAction` 是"游戏特性动作"的基类，但它**不区分 world**——有些动作是"进程级"的（加 GameplayTag、加 GameplayCue 路径），有些是"世界级"的（给某个 world 里的 Actor 加能力、加输入）。

`UGameFeatureAction_WorldActionBase` 是**世界特定动作的基类**：它覆写了 `OnGameFeatureActivating`/`Deactivating`，把"插件激活/停用"转成"对每个适用的 world 调用 `AddToWorld`"。

> **类比**：`UGameFeatureAction` 是"动作清单项"的通用模板；`WorldActionBase` 是"需要在具体 world 里执行的动作"模板——它帮你处理"找到所有适用 world、在 game instance 启动时也要补调"这些琐事，子类只需实现 `AddToWorld` 做具体的事。

---

## 二、内部结构全景

| 成员 | 作用 |
|------|------|
| `OnGameFeatureActivating`（覆写） | 插件激活：注册 GameInstance 启动回调 + 对已初始化的 world 调用 AddToWorld |
| `OnGameFeatureDeactivating`（覆写） | 插件停用：移除 GameInstance 启动回调 |
| `HandleGameInstanceStart`（私有） | GameInstance 启动时补调 AddToWorld |
| `AddToWorld`（纯虚） | 子类实现：在某个 world 里做具体动作 |
| `GameInstanceStartHandles`（成员） | 记录已注册的 GameInstance 启动句柄 |
