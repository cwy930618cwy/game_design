## 二、关键点讲解

### 1. 和 P15.4 AddAbilities 的结构对比

| 方面 | P15.4 AddAbilities | P15.5 AddInputBinding |
|------|-------------------|---------------------|
| 注册的类 | 每条配置各自的 `ActorClass` | 固定 `APawn` |
| 数据 | `ActiveExtensions`（Actor→已给的东西） | `PawnsAddedTo`（Pawn 弱引用列表） |
| 每上下文数据 | `ActiveExtensions` + `ComponentRequests` | `ExtensionRequestHandles` + `PawnsAddedTo` |
| 授予方式 | ASC 直接给能力 | 转交给 `HeroComponent` |

> 结构骨架完全一致（`FPerContextData` + `ContextData` + `AddToWorld` + `Reset` + `HandleXxxExtension`），只是具体内容不同。

### 2. `TWeakObjectPtr<APawn> PawnsAddedTo`

```cpp
TArray<TWeakObjectPtr<APawn>> PawnsAddedTo;
```

**为什么用弱引用？** Pawn 可能被销毁（玩家死亡/离开），弱引用会自动变 null，不会悬空。对比 P15.4 用 `TMap<AActor*, FActorExtensions>`（裸指针）——因为 P15.4 在 Remove 时会立即清理，而这里列表可能残留已销毁 Pawn（`.cpp` 的 `Reset` 里专门检查 `PawnPtr.IsValid()`）。

### 3. `#include "UObject/SoftObjectPtr.h"`

```cpp
#include "UObject/SoftObjectPtr.h"
```

因为用了 `TSoftObjectPtr<const UTenkaichiInputConfig>`，需要这个头文件提供完整定义（不是前置声明能解决的，因为是模板参数）。

### 4. `meta=(AssetBundles="Client,Server")`

和 P15.4 一样——输入配置属于客户端和服务器都要加载的 Bundle。

### 5. 前置声明的一堆类

```cpp
class AActor;  class UInputMappingContext;  class UPlayer;  class APlayerController;
struct FComponentRequestHandle;  class UTenkaichiInputConfig;
```

这些大多是**Lyra 源码里保留但未直接使用**的（比如 `UInputMappingContext`/`UPlayer` 只在注释/间接用到）。按铁律 23 全部照抄保留。
