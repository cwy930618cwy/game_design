// 初始化 GameFeature 管理器（注册 2 个观察者）。
void UTenkaichiGameFeaturePolicy::InitGameFeatureManager()
{
	// 创建两个观察者
	Observers.Add(NewObject<UTenkaichiGameFeature_HotfixManager>());
	Observers.Add(NewObject<UTenkaichiGameFeature_AddGameplayCuePaths>());

	// 把它们注册进 GameFeatures 子系统
	UGameFeaturesSubsystem& Subsystem = UGameFeaturesSubsystem::Get();
	for (UObject* Observer : Observers)
	{
		Subsystem.AddObserver(Observer);
	}

	Super::InitGameFeatureManager();
}

// 关闭 GameFeature 管理器（移除观察者）。
void UTenkaichiGameFeaturePolicy::ShutdownGameFeatureManager()
{
	Super::ShutdownGameFeatureManager();

	// 从 GameFeatures 子系统移除观察者
	UGameFeaturesSubsystem& Subsystem = UGameFeaturesSubsystem::Get();
	for (UObject* Observer : Observers)
	{
		Subsystem.RemoveObserver(Observer);
	}
	Observers.Empty();
}

## 二、关键点讲解

### 1. `Get()`——从子系统拿策略

```cpp
return UGameFeaturesSubsystem::Get().GetPolicy<UTenkaichiGameFeaturePolicy>();
```

`UGameFeaturesSubsystem::Get()`：引擎 GameFeatures 子系统的单例。`GetPolicy<T>()`：取出当前配置的策略对象（引擎按 `DefaultGame.ini` 的配置创建的是 `UTenkaichiGameFeaturePolicy`，所以能转成这个类型）。

> 这就是为什么 `.h` 里 `UCLASS(Config = Game)` 很关键——引擎靠配置知道"用哪个策略类"。

### 2. `InitGameFeatureManager`——注册观察者

```cpp
Observers.Add(NewObject<UTenkaichiGameFeature_HotfixManager>());
Observers.Add(NewObject<UTenkaichiGameFeature_AddGameplayCuePaths>());

UGameFeaturesSubsystem& Subsystem = UGameFeaturesSubsystem::Get();
for (UObject* Observer : Observers)
{
	Subsystem.AddObserver(Observer);
}

Super::InitGameFeatureManager();
```

流程：创建 2 个观察者 → 逐个 `AddObserver` 注册进子系统 → 调父类（顺序重要：先注册自己的，再让父类初始化）。

`NewObject<T>()`：运行时创建 UObject（无 Outer 参数 = 用 transient package）。这些观察者存进 `Observers`（`UPROPERTY`），保证不被 GC。

### 3. `GetGameFeatureLoadingMode`——真实逻辑

```cpp
bLoadClientData = !IsRunningDedicatedServer();   // 不是专用服务器 → 加载客户端数据
bLoadServerData = !IsRunningClientOnly();        // 不是纯客户端 → 加载服务器数据
```

- **专用服务器**（`IsRunningDedicatedServer()`）：`bLoadClientData = false`（不需要客户端表现数据）、`bLoadServerData = true`。
- **纯客户端**（`IsRunningClientOnly()`）：`bLoadClientData = true`、`bLoadServerData = false`。
- **单机/编辑器**：两个都 `true`。

这是"按 NetMode 精简加载"——服务器不加载纯表现的资产，客户端不加载纯服务器的资产，省内存和带宽。

### 4. 4 个"回退父类"的覆写

```cpp
return Super::GetPreloadAssetListForGameFeature(GameFeatureToLoad, bIncludeLoadedAssets);
return Super::GetPreloadBundleStateForGameFeature();
return Super::IsPluginAllowed(PluginURL, OutReason);
```

Lyra 保留这些覆写只是为了"将来可能要定制"——目前完全转发父类。按铁律 23 照抄保留。

> 为什么留着？因为这些是**策略的定制点**，继承时显式覆写一遍，将来改起来有位置可改。
