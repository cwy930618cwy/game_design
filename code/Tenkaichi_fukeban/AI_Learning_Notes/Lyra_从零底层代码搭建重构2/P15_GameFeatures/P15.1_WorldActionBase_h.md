## 〇、这个 `.h` 在解决什么

`UGameFeatureAction_WorldActionBase` 是世界特定动作基类。`.h` 声明了：2 个 interface 覆写 + 1 个私有回调 + 1 个纯虚函数 + 1 个成员。

**类声明拆解：**

| 块 | 代码 | 作用 |
|----|------|------|
| ① 基类 | `UGameFeatureAction` | 引擎游戏特性动作基类 |
| ② 特殊宏 | `UCLASS(Abstract)` | 抽象类（不能实例化） |
| ③ 接口覆写 | `OnGameFeatureActivating`/`Deactivating` | 激活/停用 |
| ④ 私有回调 | `HandleGameInstanceStart` | GameInstance 启动时补调 |
| ⑤ 纯虚函数 | `AddToWorld`（`PURE_VIRTUAL`） | 子类实现具体动作 |
| ⑥ 成员 | `GameInstanceStartHandles`（`TMap`） | 记录回调句柄 |

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "GameFeatureAction.h"
#include "GameFeaturesSubsystem.h"

#include "GameFeatureAction_WorldActionBase.generated.h"

class FDelegateHandle;
class UGameInstance;
class UObject;
struct FGameFeatureActivatingContext;
struct FGameFeatureDeactivatingContext;
struct FGameFeatureStateChangeContext;
struct FWorldContext;

/**
 * 那些希望做"世界特定"事情的 GameFeatureAction 的基类。
 */
UCLASS(Abstract)
class UGameFeatureAction_WorldActionBase : public UGameFeatureAction
{
	GENERATED_BODY()

public:
	//~UGameFeatureAction 接口开始
	// 游戏特性激活时调用。
	virtual void OnGameFeatureActivating(FGameFeatureActivatingContext& Context) override;
	// 游戏特性停用时调用。
	virtual void OnGameFeatureDeactivating(FGameFeatureDeactivatingContext& Context) override;
	//~UGameFeatureAction 接口结束

private:
	// GameInstance 启动时的回调（补调 AddToWorld）。
	void HandleGameInstanceStart(UGameInstance* GameInstance, FGameFeatureStateChangeContext ChangeContext);

	// 用动作特定的逻辑覆盖这个函数。
	virtual void AddToWorld(const FWorldContext& WorldContext, const FGameFeatureStateChangeContext& ChangeContext) PURE_VIRTUAL(UGameFeatureAction_WorldActionBase::AddToWorld,);

private:
	// 每个状态变化上下文对应的 GameInstance 启动回调句柄。
	TMap<FGameFeatureStateChangeContext, FDelegateHandle> GameInstanceStartHandles;
};
```

## 二、关键点讲解

### 1. `UCLASS(Abstract)`——抽象基类

```cpp
UCLASS(Abstract)
class UGameFeatureAction_WorldActionBase : public UGameFeatureAction
```

`Abstract`：抽象类，不能直接实例化（编辑器里看不到它，只能被继承）。因为它是"基类模板"，`AddToWorld` 是纯虚函数，必须子类实现。

### 2. `PURE_VIRTUAL` 宏——纯虚函数的 UE 写法

```cpp
virtual void AddToWorld(const FWorldContext& WorldContext, const FGameFeatureStateChangeContext& ChangeContext) PURE_VIRTUAL(UGameFeatureAction_WorldActionBase::AddToWorld,);
```

`PURE_VIRTUAL(类名::函数名, 返回值)` 是 UE 的"纯虚函数"写法（不是 C++ 的 `= 0`）。它的效果：
- 子类**必须**覆写（否则编译报错，同纯虚）。
- 但如果真的被调到基类版本，会**打印错误并返回指定值**（这里是空返回）——比 C++ 纯虚更安全（不会链接错误）。

> 为什么 UE 用它而不是 `= 0`？因为 UObject 体系里，有些情况会调用到基类实现（如 Super 调用），`PURE_VIRTUAL` 提供了明确的错误提示。

### 3. `TMap<FGameFeatureStateChangeContext, FDelegateHandle>`

```cpp
TMap<FGameFeatureStateChangeContext, FDelegateHandle> GameInstanceStartHandles;
```

- Key：`FGameFeatureStateChangeContext`（状态变化上下文，标识"哪次激活"）。
- Value：`FDelegateHandle`（委托句柄，用来后续 `Remove` 解绑）。

为什么要存句柄？因为 `OnGameFeatureActivating` 里注册回调，`OnGameFeatureDeactivating` 里要按句柄精确移除（不能 RemoveAll，可能误删别的）。

### 4. `FDelegateHandle` / `FGameFeatureStateChangeContext` 前置声明

```cpp
class FDelegateHandle;
struct FGameFeatureStateChangeContext;
```

这些结构体/类只用**引用/值类型**（`TMap` 的 Key/Value），但 `.h` 里仍然前置声明——因为 `TMap` 需要完整类型？实际上 `TMap<Key, Value>` 成员需要 Key/Value 完整定义，所以这里的前置声明配合 `GameFeaturesSubsystem.h`（已 include，里面定义了 `FGameFeatureStateChangeContext`）使用。

> 注意：`FGameFeatureStateChangeContext` 定义在 `GameFeaturesSubsystem.h`（已 include），所以前置声明是冗余的，但 Lyra 源码保留（铁律 23 照抄）。
