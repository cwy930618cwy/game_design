## 〇、这个 `.cpp` 在解决什么

`.h` 声明了基类骨架，`.cpp` 实现 3 个方法：激活时注册 GameInstance 启动回调 + 对已存在的 world 调 `AddToWorld`；停用时移除回调；GameInstance 启动时补调 `AddToWorld`。

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "GameFeatureAction_WorldActionBase.h"

#include "Engine/GameInstance.h"
#include "Engine/World.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(GameFeatureAction_WorldActionBase)

// 游戏特性激活：注册 GameInstance 启动回调 + 对已初始化的 world 调 AddToWorld。
void UGameFeatureAction_WorldActionBase::OnGameFeatureActivating(FGameFeatureActivatingContext& Context)
{
	// 登记"GameInstance 启动"回调，按上下文存句柄（停用时精确移除）
	GameInstanceStartHandles.FindOrAdd(Context) = FWorldDelegates::OnStartGameInstance.AddUObject(this,
		&UGameFeatureAction_WorldActionBase::HandleGameInstanceStart, FGameFeatureStateChangeContext(Context));

	// 对所有已经初始化、且这个上下文应该应用的 world，调用 AddToWorld
	for (const FWorldContext& WorldContext : GEngine->GetWorldContexts())
	{
		if (Context.ShouldApplyToWorldContext(WorldContext))
		{
			AddToWorld(WorldContext, Context);
		}
	}
}

// 游戏特性停用：移除 GameInstance 启动回调。
void UGameFeatureAction_WorldActionBase::OnGameFeatureDeactivating(FGameFeatureDeactivatingContext& Context)
{
	FDelegateHandle* FoundHandle = GameInstanceStartHandles.Find(Context);
	if (ensure(FoundHandle))
	{
		FWorldDelegates::OnStartGameInstance.Remove(*FoundHandle);
	}
}

// GameInstance 启动时的回调（补调 AddToWorld）。
void UGameFeatureAction_WorldActionBase::HandleGameInstanceStart(UGameInstance* GameInstance, FGameFeatureStateChangeContext ChangeContext)
{
	if (FWorldContext* WorldContext = GameInstance->GetWorldContext())
	{
		if (ChangeContext.ShouldApplyToWorldContext(*WorldContext))
		{
			AddToWorld(*WorldContext, ChangeContext);
		}
	}
}
```

## 二、关键点讲解

### 1. `OnGameFeatureActivating`——两件事

```cpp
// ① 登记回调
GameInstanceStartHandles.FindOrAdd(Context) = FWorldDelegates::OnStartGameInstance.AddUObject(this, &HandleGameInstanceStart, FGameFeatureStateChangeContext(Context));

// ② 对已有 world 立即执行
for (const FWorldContext& WorldContext : GEngine->GetWorldContexts())
{
	if (Context.ShouldApplyToWorldContext(WorldContext))
	{
		AddToWorld(WorldContext, Context);
	}
}
```

**为什么两件事都要做？**
- 插件激活时，可能**已经有 world 存在**（比如游戏已经在跑）→ 立即对它们 `AddToWorld`。
- 插件激活后，**未来可能有新 world**（比如新开一局）→ 注册 `OnStartGameInstance`，新 world 启动时补调。

`FindOrAdd(Context)`：按上下文找到（或新建）句柄槽位，把注册返回的 `FDelegateHandle` 存进去。

### 2. `FWorldDelegates::OnStartGameInstance`——引擎全局委托

```cpp
FWorldDelegates::OnStartGameInstance.AddUObject(this, &HandleGameInstanceStart, FGameFeatureStateChangeContext(Context));
```

`FWorldDelegates::OnStartGameInstance` 是引擎的全局多播委托，**每次 GameInstance 启动**都会广播。这里注册 `HandleGameInstanceStart`，并把 `Context`（状态变化上下文）作为**额外参数**传进去（`AddUObject` 可以带附加参数）。

### 3. `ShouldApplyToWorldContext`——上下文过滤

```cpp
if (Context.ShouldApplyToWorldContext(WorldContext))
```

`FGameFeatureStateChangeContext` 记录了"这次激活应该应用到哪些 world"（PIE 下可能只应用到某个客户端/服务器 world）。`ShouldApplyToWorldContext` 判断某个 world 是否在这个范围内。

> 这是 PIE（多 world）下的关键过滤——避免把客户端的东西应用到服务器 world 上。

### 4. `OnGameFeatureDeactivating`——精确移除

```cpp
FDelegateHandle* FoundHandle = GameInstanceStartHandles.Find(Context);
if (ensure(FoundHandle))
{
	FWorldDelegates::OnStartGameInstance.Remove(*FoundHandle);
}
```

`ensure(FoundHandle)`：如果找不到句柄就报警（说明激活/停用不配对，是 bug）。找到就 `Remove(*FoundHandle)` 精确移除（不影响其他注册的回调）。

### 5. 为什么 `ensure` 而不是 `check`

- `ensure`：失败时**打警告 + 继续执行**（不崩溃），适合"不该发生但崩了影响大"的情况。
- `check`：失败时**直接崩溃**，适合"绝对不可能发生"的断言。

这里停用时找不到句柄是逻辑 bug，但不该让游戏崩，所以用 `ensure`。
