## 一、这个结构体解决什么问题（先讲为什么）

游戏启动时，`AssetManager` 要做一堆"启动加载"工作：加载默认 Pawn 数据、加载游戏全局数据、加载能力集等等。这些工作有些是异步的（要等资产流式加载完成），需要**追踪每个任务的进度**（好给加载屏显示百分比）。

`FTenkaichiAssetManagerStartupJob` 就是**"一个启动加载任务"的封装**：
- 记一个任务的名字、权重、要执行的函数。
- 执行时（`DoJob`）调用那个函数，拿到一个 `FStreamableHandle`（流式加载句柄），**阻塞等待它完成**，并周期上报进度。

> **类比**：AssetManager 是"搬家公司总调度"，`StartupJob` 是"一张搬家任务单"——写清楚"搬什么（JobFunc）、叫什么名字（JobName）、占多少进度权重（JobWeight）"，执行时"开始搬 → 报进度 → 搬完"。

| `UpdateSubstepProgressFromStreamable` | `void` | 从流式句柄取进度并上报（带节流） |

### `.cpp`（25 行）

只有一个函数 `DoJob()`：计时 → 执行 JobFunc → 绑进度委托 → 阻塞等待 → 打印耗时。
