## 二、关键点讲解

### 1. 空壳继承——为什么还要建它

```cpp
UCLASS()
class UTenkaichiSignificanceManager : public USignificanceManager
{
	GENERATED_BODY()
};
```

- 类体**完全为空**（只有 `GENERATED_BODY()`，没有构造、没有方法、没有成员）。
- 但为什么要建？因为：
  1. **命名/类型占位**：将来要自定义重要性逻辑时，直接在这个类里加，不用改别处的类型引用。
  2. **`GENERATED_BODY()` + `.generated.h`**：它是 `UCLASS`（反射类），能通过配置指定"用这个重要性管理器"，引擎会实例化它。

### 2. `USignificanceManager` 基类

引擎的 `USignificanceManager` 是"重要性系统"的基础——根据对象的重要性（通常由距离/可见性决定）动态调整它们的更新频率（Tick 频率、复制频率）。Lyra 现在用默认实现，所以空壳。

### 3. `.cpp` 只有 UHT 生成

```cpp
#include "TenkaichiSignificanceManager.h"
#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiSignificanceManager)
```

`.cpp` 里**没有任何函数实现**，只有 `#include` 自己 + `UE_INLINE_GENERATED_CPP_BY_NAME`（UHT 生成的反射代码）。因为空壳类没有自定义函数。

### 4. 前置声明 `class UObject;`

```cpp
class UObject;
```

和 GameSession 一样，这个前置声明**没被用到**（类体为空）。Lyra 源码留着，按铁律 23 照抄保留。
