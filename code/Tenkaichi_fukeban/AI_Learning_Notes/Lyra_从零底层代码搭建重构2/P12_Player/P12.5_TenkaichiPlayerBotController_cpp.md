## 〇、这个 `.cpp` 在解决什么

`.h` 只声明了骨架，`.cpp` 才是"机器人控制器"真正干活的地方。它实现：

| 方法 | 作用 |
|------|------|
| 构造 | `bWantsPlayerState = true`（机器人要档案）+ `bStopAILogicOnUnposses = false`（失配不停止 AI） |

// 当关联的 PlayerState 队伍改变时：把新旧队伍转发成"队伍变更广播"。

// 核心：PlayerState 变了 → 解绑旧回调、绑定新回调、广播队伍变更。
void ATenkaichiPlayerBotController::BroadcastOnPlayerStateChanged()
{
	// 先让子类有机会处理"状态变更"这个事件。
	OnPlayerStateChanged();

	// 解绑旧 PlayerState 的队伍回调（如果有的话）。
	FGenericTeamId OldTeamID = FGenericTeamId::NoTeam;
	if (LastSeenPlayerState != nullptr)
	{
		if (ITenkaichiTeamAgentInterface* PlayerStateTeamInterface = Cast<ITenkaichiTeamAgentInterface>(LastSeenPlayerState))
		{
			// 记下旧队伍 ID，并解绑旧状态的回调。
			OldTeamID = PlayerStateTeamInterface->GetGenericTeamId();
			PlayerStateTeamInterface->GetTeamChangedDelegateChecked().RemoveAll(this);
		}
	}

	// 绑定新 PlayerState 的队伍回调（如果有的话）。
	FGenericTeamId NewTeamID = FGenericTeamId::NoTeam;
	if (PlayerState != nullptr)
	{
		if (ITenkaichiTeamAgentInterface* PlayerStateTeamInterface = Cast<ITenkaichiTeamAgentInterface>(PlayerState))
		{
			// 记下新队伍 ID，并绑定新状态的回调（队伍变了会触发 OnPlayerStateChangedTeam）。
			NewTeamID = PlayerStateTeamInterface->GetGenericTeamId();
			PlayerStateTeamInterface->GetTeamChangedDelegateChecked().AddDynamic(this, &ThisClass::OnPlayerStateChangedTeam);
		}
	}

	// 如果新旧队伍真的不一样，就广播出去。
	ConditionalBroadcastTeamChanged(this, OldTeamID, NewTeamID);

	// 记录本次的 PlayerState，下次解绑用。
	LastSeenPlayerState = PlayerState;
}

// 控制器挂上 PlayerState 时触发。
void ATenkaichiPlayerBotController::InitPlayerState()
{
	Super::InitPlayerState();
	BroadcastOnPlayerStateChanged();
}

// 控制器清除 PlayerState 时触发。
void ATenkaichiPlayerBotController::CleanupPlayerState()
{
	Super::CleanupPlayerState();
	BroadcastOnPlayerStateChanged();
}

// 客户端收到 PlayerState 复制时触发。
void ATenkaichiPlayerBotController::OnRep_PlayerState()

	Super::OnRep_PlayerState();

}

	{
		return PSWithTeamInterface->GetGenericTeamId();
	}
	return FGenericTeamId::NoTeam;
}

		ResetIgnoreInputFlags();

		// 让 GameMode 帮我们重启这个玩家。
		GameMode->RestartPlayer(this);
	}

// 判定对方是敌/友/中立（AI 感知系统用）。
ETeamAttitude::Type ATenkaichiPlayerBotController::GetTeamAttitudeTowards(const AActor& Other) const
{
	if (const APawn* OtherPawn = Cast<APawn>(&Other)) {

		if (const ITenkaichiTeamAgentInterface* TeamAgent = Cast<ITenkaichiTeamAgentInterface>(OtherPawn->GetController()))
		{
			FGenericTeamId OtherTeamID = TeamAgent->GetGenericTeamId();

			// 对比对方的队伍 ID 和我的队伍 ID。
			if (OtherTeamID.GetId() != GetGenericTeamId().GetId())
			{
				return ETeamAttitude::Hostile; // 不同队 = 敌对
			}
			else
			{
				return ETeamAttitude::Friendly; // 同队 = 友好
			}
		}
	}

	return ETeamAttitude::Neutral; // 无法判定 = 中立
}

	}
}

// 失配时：确保被失配的 Pawn 不再作为 ASC 的头像（防止技能系统引用悬空）。
void ATenkaichiPlayerBotController::OnUnPossess()
{
	// 确保被失配的 Pawn 不再作为我们 ASC 的头像 Actor。
	if (APawn* PawnBeingUnpossessed = GetPawn())
	{
		if (UAbilitySystemComponent* ASC = UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(PlayerState))
		{
			if (ASC->GetAvatarActor() == PawnBeingUnpossessed)
			{
				ASC->SetAvatarActor(nullptr);
			}
		}
	}

	Super::OnUnPossess();
}

## 二、关键点讲解

### 1. 构造：机器人要不要 PlayerState / AI 逻辑？
```cpp
bWantsPlayerState = true;          // 要 PlayerState（机器人也有档案/队伍）
bStopAILogicOnUnposses = false;   // 失配不停止 AI（还能决策/重生）
```
`bWantsPlayerState = true` 是"我有 PlayerState"的开关；`bStopAILogicOnUnposses = false` 表示**失去 Pawn 时 AI 逻辑不暂停**——这样机器人死后还能继续决策、等待重生。

### 2. `BroadcastOnPlayerStateChanged()` —— 整个类的核心
三步走：
1. **解绑旧的**：记下旧 PlayerState 的队伍，`RemoveAll(this)` 解除旧回调
2. **绑定新的**：给新 PlayerState 的队伍回调 `AddDynamic` 挂上 `OnPlayerStateChangedTeam`
3. **广播**：`ConditionalBroadcastTeamChanged`（P07 工具，只有队伍真的变了才广播）

`LastSeenPlayerState` 记录上一次的状态，下次解绑用。这样"PlayerState 换了"事件被统一处理，不会重复绑定/漏解绑。

### 3. `GetTeamAttitudeTowards()` —— AI 敌我判定
```
对方 Pawn 的控制器 → 它有没有队伍接口？→ 对比队伍 ID
   不同队 → Hostile（敌对）
   同队   → Friendly（友好）
   拿不到 → Neutral（中立）
```
这是 AI 攻击/支援判断的依据（AI 会打"异队"的、帮"同队"的）。

### 4. `ServerRestartController()` —— 重生（挂起 P13）
`GameMode->ControllerCanRestart(this)` + `GameMode->RestartPlayer(this)` 都来自 **P13 的 `ATenkaichiGameMode`**。所以这段整体 `#if 0` 挂起，等 P13 建好 `TenkaichiGameMode.h` 后解开（翻注释备忘录提醒）。

### 5. `OnUnPossess()` —— 清 ASC 头像
机器人失配（失去 Pawn）时，如果那个 Pawn 恰好是 ASC 的 Avatar，就把 `SetAvatarActor(nullptr)` 清掉，防止技能系统继续引用一个已经失控的 Pawn。
