## 二、逐行讲解

### 1. 头文件依赖

```cpp
#include "Inventory/TenkaichiInventoryItemDefinition.h"
#include "InventoryFragment_ReticleConfig.generated.h"
```

| 头文件 | 提供什么 |
|--------|---------|
| `TenkaichiInventoryItemDefinition.h` | P08 的 `UTenkaichiInventoryItemFragment` 基类 |
| `InventoryFragment_ReticleConfig.generated.h` | UHT 自动生成的反射代码（每个 UCLASS 都要 include） |

### 2. 前置声明

```cpp
class UTenkaichiReticleWidgetBase;
class UObject;
```

- `class UTenkaichiReticleWidgetBase;` —— **前置声明** P16 的准星控件基类。
  - 只声明"有这么个类"，不 include 完整定义。
  - 这样 `TSubclassOf<UTenkaichiReticleWidgetBase>` 编译器知道类型名就能编译（不需要完整头文件）。
  - **这就是为什么注释挂起后本文件还能编译** —— 连前置声明都不用删。

### 3. 类声明

```cpp
UCLASS()
class UInventoryFragment_ReticleConfig : public UTenkaichiInventoryItemFragment
{
	GENERATED_BODY()
```

- 类名 `UInventoryFragment_ReticleConfig` —— **无 `Lyra` 前缀**，保持原样（Lyra 原版就这样）。
- 继承 P08 的 `UTenkaichiInventoryItemFragment`。
- `GENERATED_BODY()` —— UHT 宏，必须有。

### 4. 被挂起的属性

```cpp
//UPROPERTY(EditAnywhere, BlueprintReadOnly, Category=Reticle)
//TArray<TSubclassOf<UTenkaichiReticleWidgetBase>> ReticleWidgets;
```

**为什么注释挂起？**
- `TSubclassOf<UTenkaichiReticleWidgetBase>` 需要 `UTenkaichiReticleWidgetBase` 类型**完整定义**（因为它要 `#include "ReticleWidgetBase.h"` 或至少能通过 UHT 处理）。
- `UTenkaichiReticleWidgetBase` 属于 **P16 UI**，还没实现。
- 注释掉后，本类变成一个"空骨架"，能正常编译。

**解开条件**：P16 完成 `UTenkaichiReticleWidgetBase` 后，取消注释即可。

> ⚠️ **注意**：`class UTenkaichiReticleWidgetBase;` 前置声明**保留着**，不删——等 P16 到位直接取消属性注释就行，前置声明到时候如果没用到编译器会提示，但保留无害。
