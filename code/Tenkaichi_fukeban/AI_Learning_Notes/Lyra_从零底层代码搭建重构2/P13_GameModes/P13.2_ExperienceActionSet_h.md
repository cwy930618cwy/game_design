## 〇、这个 `.h` 在解决什么

`UTenkaichiExperienceActionSet` 继承 `UPrimaryDataAsset`，是"可复用的动作包"（总 md 已讲）。`.h` 声明 2 个字段 + 2 个编辑器钩子 + 构造。

**类声明拆解：**

| 块 | 代码 | 作用 |
|----|------|------|
| ① 基类 | `UPrimaryDataAsset` | 数据资产 |
| ② 构造 | `UTenkaichiExperienceActionSet()` | 空构造 |
| ③ 校验钩子 | `IsDataValid`（编辑器） | 数据资产校验（仅编辑环境） |
| ④ 资源钩子 | `UpdateAssetBundleData`（编辑器数据） | 更新资源包（仅编辑数据） |
| ⑤ 两字段 | `Actions` / `GameFeaturesToEnable` | 动作包的实际内容 |

> 和 P13.1 结构几乎一样，但更简单：没有 `DefaultPawnData`/`ActionSets` 字段，也没有 P13.1 里那套"禁止蓝图二次子类化"的复杂校验。

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "Engine/DataAsset.h"
#include "TenkaichiExperienceActionSet.generated.h"

class UGameFeatureAction;

/**
 * 经验动作集（ExperienceActionSet）
 *
 * 把一组动作和一组 GameFeature 插件打包成可复用片段，
 * 供 ExperienceDefinition 通过 ActionSets 字段引用（用组合代替蓝图继承）。
 */
UCLASS(BlueprintType, NotBlueprintable)
class UTenkaichiExperienceActionSet : public UPrimaryDataAsset
{
	GENERATED_BODY()

public:
	UTenkaichiExperienceActionSet();

	//~UObject 接口
#if WITH_EDITOR
	// 数据资产校验（仅编辑器环境）：检查 Actions 数组没有空项。
	virtual EDataValidationResult IsDataValid(class FDataValidationContext& Context) const override;
#endif
	//~UObject 接口结束

	//~UPrimaryDataAsset 接口
#if WITH_EDITORONLY_DATA
	// 更新资源包数据（仅编辑器数据）：让动作的依赖资产能被打进 Bundle。
	virtual void UpdateAssetBundleData() override;
#endif
	//~UPrimaryDataAsset 接口结束

public:
	// 这一组要执行的动作列表（引擎 GameFeatureAction，每个可独立配置）。
	UPROPERTY(EditAnywhere, Instanced, Category="Actions to Perform")
	TArray<TObjectPtr<UGameFeatureAction>> Actions;

	// 这一组要激活的 Game Feature 插件名列表。
	UPROPERTY(EditAnywhere, Category="Feature Dependencies")
	TArray<FString> GameFeaturesToEnable;
};
```

## 二、关键点讲解

### 1. `UCLASS(BlueprintType, NotBlueprintable)`
- `BlueprintType`：能在蓝图里作为变量类型用。
- `NotBlueprintable`：**不能**在蓝图里作为基类被继承/创建蓝图子类。和 P13.1 的 `Const` 不同——这里强调"不能蓝图化"。

### 2. 基类 `UPrimaryDataAsset` + 两个编辑器钩子
和 P13.1 一模一样：
- `IsDataValid`（`#if WITH_EDITOR`）→ 编辑器校验。
- `UpdateAssetBundleData`（`#if WITH_EDITORONLY_DATA`）→ 资源打包。
- 都只在编辑器编译，游戏运行时跳过。

### 3. 字段的 `EditAnywhere` + `Instanced`
- **`EditAnywhere`**（对比 P13.1 的 `EditDefaultsOnly`）：不仅默认值能改，**任何地方（实例/蓝图资产）都能编辑**。动作集是"可复用片段"，允许更灵活地配置。
- **`Instanced`**（Actions 上）：`Actions` 数组里的每个 `UGameFeatureAction` 都是**实例化的**，能各自配置参数。
- 两个 `Category` 分组：`"Actions to Perform"`（动作）和 `"Feature Dependencies"`（插件依赖）。

### 4. 前置声明 `class UGameFeatureAction;`
只用 `TObjectPtr` 指针，前置声明够用，不 include 引擎头 → `.h` 保持轻量。
