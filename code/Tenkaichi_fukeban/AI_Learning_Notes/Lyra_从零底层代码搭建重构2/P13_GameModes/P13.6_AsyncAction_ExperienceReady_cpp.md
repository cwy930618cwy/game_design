## 〇、这个 `.cpp` 在解决什么

`.h` 声明了节点的骨架，`.cpp` 把"等经验加载完"的 4 步流程真正跑起来：

1. `WaitForExperienceReady`（静态入口）：创建节点、保存 World、注册到 GameInstance 保活
2. `Activate`：GameState 有了就进 Step2，没有就等 `GameStateSetEvent`
3. `Step1/Step2`：找到 `ExperienceManagerComponent`，听经验加载
4. `Step3/Step4`：经验加载完 → 广播 `OnReady` → 销毁自己

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "GameModes/AsyncAction_ExperienceReady.h"

#include "Engine/Engine.h"
#include "Engine/World.h"
#include "GameModes/TenkaichiExperienceManagerComponent.h"
#include "TimerManager.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(AsyncAction_ExperienceReady)

// 构造函数：空实现（基类构造函数处理初始化）。
UAsyncAction_ExperienceReady::UAsyncAction_ExperienceReady(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
}

// 静态入口：创建节点、保存 World、注册到 GameInstance 保活。
UAsyncAction_ExperienceReady* UAsyncAction_ExperienceReady::WaitForExperienceReady(UObject* InWorldContextObject)
{
	UAsyncAction_ExperienceReady* Action = nullptr;

	if (UWorld* World = GEngine->GetWorldFromContextObject(InWorldContextObject, EGetWorldErrorMode::LogAndReturnNull))
	{
		Action = NewObject<UAsyncAction_ExperienceReady>();
		Action->WorldPtr = World;
		Action->RegisterWithGameInstance(World);
	}

	return Action;
}

// 节点激活：GameState 有了就听经验，没有就先等 GameState 出现。
void UAsyncAction_ExperienceReady::Activate()
{
	if (UWorld* World = WorldPtr.Get())
	{
		if (AGameStateBase* GameState = World->GetGameState())
		{
			Step2_ListenToExperienceLoading(GameState);
		}
		else
		{
			World->GameStateSetEvent.AddUObject(this, &ThisClass::Step1_HandleGameStateSet);
		}
	}
	else
	{
		// 没有 World，就永远不会自然完成了
		SetReadyToDestroy();
	}
}

// 第 1 步：GameState 出现后的回调（先移除监听，再进第 2 步）。
void UAsyncAction_ExperienceReady::Step1_HandleGameStateSet(AGameStateBase* GameState)
{
	if (UWorld* World = WorldPtr.Get())
	{
		World->GameStateSetEvent.RemoveAll(this);
	}

	Step2_ListenToExperienceLoading(GameState);
}

// 第 2 步：找到经验管理器组件，经验已加载就延迟一帧广播，否则注册"加载完成"回调。
void UAsyncAction_ExperienceReady::Step2_ListenToExperienceLoading(AGameStateBase* GameState)
{
	check(GameState);
	UTenkaichiExperienceManagerComponent* ExperienceComponent = GameState->FindComponentByClass<UTenkaichiExperienceManagerComponent>();
	check(ExperienceComponent);

	if (ExperienceComponent->IsExperienceLoaded())
	{
		UWorld* World = GameState->GetWorld();
		check(World);

		// 经验恰好已经加载完了，但还是故意延迟一帧，
		// 确保没人写出"依赖这个节点永远异步"的代码。
		//@TODO: 考虑对动态生成的东西 / 加载屏已经消失之后的任何时刻不延迟？
		//@TODO: 也许直接在经验加载里注入一个随机 0-1 秒延迟？
		World->GetTimerManager().SetTimerForNextTick(FTimerDelegate::CreateUObject(this, &ThisClass::Step4_BroadcastReady));
	}
	else
	{
		ExperienceComponent->CallOrRegister_OnExperienceLoaded(FOnTenkaichiExperienceLoaded::FDelegate::CreateUObject(this, &ThisClass::Step3_HandleExperienceLoaded));
	}
}

// 第 3 步：经验加载完成的回调（直接进第 4 步）。
void UAsyncAction_ExperienceReady::Step3_HandleExperienceLoaded(const UTenkaichiExperienceDefinition* CurrentExperience)
{
	Step4_BroadcastReady();
}

// 第 4 步：广播 OnReady，然后销毁自己。
void UAsyncAction_ExperienceReady::Step4_BroadcastReady()
{
	OnReady.Broadcast();

	SetReadyToDestroy();
}
```

## 二、关键点讲解

### 1. `WaitForExperienceReady`（静态入口，创建节点）

```cpp
if (UWorld* World = GEngine->GetWorldFromContextObject(InWorldContextObject, EGetWorldErrorMode::LogAndReturnNull))
{
	Action = NewObject<UAsyncAction_ExperienceReady>();
	Action->WorldPtr = World;
	Action->RegisterWithGameInstance(World);
}
```

- `GEngine->GetWorldFromContextObject(...)`：根据"世界上下文对象"（`WorldContextObject`）反查 `UWorld`。拿不到就返回 `nullptr`（`LogAndReturnNull` 模式）。
- `NewObject<...>()`：运行时创建节点实例（对比 `CreateDefaultSubobject` 是构造期创建）。
- `RegisterWithGameInstance(World)`：把节点挂到 GameInstance 上保活，防 GC 回收（P07.9 已教）。

### 2. `Activate()`：分支——GameState 有了吗？

```cpp
if (AGameStateBase* GameState = World->GetGameState())
{
	Step2_ListenToExperienceLoading(GameState);   // 有了，直接听经验
}
else
{
	World->GameStateSetEvent.AddUObject(this, &ThisClass::Step1_HandleGameStateSet);  // 没有，等 GameState 出现
}
```

- `World->GetGameState()`：拿当前 GameState。刚进图时可能还是 `nullptr`（GameState 还没复制/创建完）。
- `World->GameStateSetEvent`：一个"GameState 被设置好"的事件。没 GameState 时注册 Step1 等它。

### 3. `GameStateSetEvent` 的绑定与解绑

Step1 里先 `World->GameStateSetEvent.RemoveAll(this)` 再进 Step2——这是**一次性事件**的正确用法：触发一次就解绑，避免重复触发/悬空。

### 4. `Step2_ListenToExperienceLoading`：核心分叉

```cpp
UTenkaichiExperienceManagerComponent* ExperienceComponent = GameState->FindComponentByClass<UTenkaichiExperienceManagerComponent>();
```

`FindComponentByClass<T>()`：从 GameState 身上找到经验管理器组件（P13.5 挂在那上面的）。

然后两条路：
- **经验已加载**（`IsExperienceLoaded()`）→ `SetTimerForNextTick` 延迟一帧再广播（下面第 5 点详讲）。
- **经验还没加载** → `CallOrRegister_OnExperienceLoaded(...)` 注册回调，等加载完触发 Step3。

> 注意这里用的是 `FOnTenkaichiExperienceLoaded`（P13.5 声明的 C++ 多播委托类型），不是本类的 `FExperienceReadyAsyncDelegate`。因为 `ExperienceManagerComponent` 广播的是它自己的委托类型。

### 5. `SetTimerForNextTick`——为什么经验已加载还要延迟一帧

```cpp
World->GetTimerManager().SetTimerForNextTick(FTimerDelegate::CreateUObject(this, &ThisClass::Step4_BroadcastReady));
```

- `SetTimerForNextTick`：安排"下一帧"执行某个委托（不是定时，是下一帧立刻）。
- **为什么延迟**：如果经验恰好已经加载完，直接同步广播 `OnReady`，会让蓝图里的节点**立即**触发。但如果蓝图作者假设"这个节点一定是异步的"（比如在 OnReady 里读某个"加载完成后才有的数据"），同步触发就可能踩到时序 bug。延迟一帧，让节点**永远保持异步语义**，避免这种隐患。

### 6. `Step4_BroadcastReady`：广播 + 销毁

```cpp
OnReady.Broadcast();   // 触发蓝图绑定的 OnReady 事件
SetReadyToDestroy();   // 销毁自己（P07.9 已教：解除 GameInstance 注册，允许回收）
```

异步节点的标准收尾：广播结果 → `SetReadyToDestroy()` 自我销毁。
