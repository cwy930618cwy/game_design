## 〇、这个 `.h` 在解决什么

`UTenkaichiExperienceManagerComponent` 是经验系统的"发动机"——挂在 GameState 上，跑一个**加载状态机**，把"指定经验 → 加载资产 → 激活 GameFeature → 执行 Action → 广播 loaded"整条链走完。`.h` 声明了：1 个构造 + 7 个公开方法 + 7 个私有方法 + 6 个成员字段 + 1 个枚举 + 1 个委托类型。

**类声明拆解：**

| 块 | 代码 | 作用 |
|----|------|------|
| ① 双基类 | `UGameStateComponent` + `ILoadingProcessInterface` | 挂 GameState 的组件 + 加载屏接口 |
| ② 特殊宏 | `UCLASS(MinimalAPI)` + `#define UE_API LYRAGAME_API` | 精简导出（同 P13.4） |
| ③ 枚举 | `ELyraExperienceLoadState` | 加载状态机的 7 个状态 |
| ④ 委托 | `FOnLyraExperienceLoaded` | "经验加载完"的回调类型 |
| ⑤ 公开方法 | `SetCurrentExperience` 等 7 个 | 外部怎么启动/查询/注册回调 |
| ⑥ 私有方法 | `OnRep_CurrentExperience` 等 7 个 | 状态机内部流水线 |
| ⑦ 成员字段 | `CurrentExperience`（复制）等 6 个 | 状态机要记的东西 |

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "Components/GameStateComponent.h"
#include "LoadingProcessInterface.h"

#include "TenkaichiExperienceManagerComponent.generated.h"

#define UE_API TENKAICHIGAME_API

namespace UE::GameFeatures { struct FResult; }

class UTenkaichiExperienceDefinition;

// 声明一个"经验加载完成"的多播委托：带一个参数（指向经验定义的指针）。
DECLARE_MULTICAST_DELEGATE_OneParam(FOnTenkaichiExperienceLoaded, const UTenkaichiExperienceDefinition* /*Experience*/);

// 经验加载的状态机：表示"经验加载走到哪一步了"。
enum class ETenkaichiExperienceLoadState
{
	Unloaded,                // 还没加载
	Loading,                 // 正在加载资产
	LoadingGameFeatures,     // 正在激活 GameFeature 插件
	LoadingChaosTestingDelay,// 可选的测试用随机延迟
	ExecutingActions,        // 正在执行 Action
	Loaded,                  // 加载完成
	Deactivating             // 正在卸载（退出时反向走）
};

UCLASS(MinimalAPI)
class UTenkaichiExperienceManagerComponent final : public UGameStateComponent, public ILoadingProcessInterface
{
	GENERATED_BODY()

public:

	// 构造函数：初始化状态机。
	UE_API UTenkaichiExperienceManagerComponent(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

	//~UActorComponent 接口开始
	// 组件生命周期结束时的回调：负责停用 GameFeature、卸载 Action。
	UE_API virtual void EndPlay(const EEndPlayReason::Type EndPlayReason) override;
	//~UActorComponent 接口结束

	//~ILoadingProcessInterface 接口开始
	// 问加载屏系统"我是不是还没加载完、要不要显示加载画面"。
	UE_API virtual bool ShouldShowLoadingScreen(FString& OutReason) const override;
	//~ILoadingProcessInterface 接口结束

	// 尝试设置当前要用的经验（可以是 UI 经验，也可以是玩法经验）。
	UE_API void SetCurrentExperience(FPrimaryAssetId ExperienceId);

	// 保证这个委托在经验加载完成后、其他委托之前被调用；
	// 但如果经验已经加载完了，就立刻调用它。
	UE_API void CallOrRegister_OnExperienceLoaded_HighPriority(FOnTenkaichiExperienceLoaded::FDelegate&& Delegate);

	// 保证这个委托在经验加载完成后被调用；
	// 如果经验已经加载完了，就立刻调用它。
	UE_API void CallOrRegister_OnExperienceLoaded(FOnTenkaichiExperienceLoaded::FDelegate&& Delegate);

	// 保证这个委托在经验加载完成后被调用；
	// 如果经验已经加载完了，就立刻调用它。
	UE_API void CallOrRegister_OnExperienceLoaded_LowPriority(FOnTenkaichiExperienceLoaded::FDelegate&& Delegate);

	// 返回当前经验（前提是它已经完全加载完，否则会 assert 报错）。
	UE_API const UTenkaichiExperienceDefinition* GetCurrentExperienceChecked() const;

	// 返回"经验是不是已经完全加载完"。
	UE_API bool IsExperienceLoaded() const;

private:
	// 网络复制回调：客户端收到"当前经验"后，也启动自己的加载流程。
	UFUNCTION()
	void OnRep_CurrentExperience();

	// 开始加载经验资产（Bundle + 原始资产）。
	void StartExperienceLoad();
	// 资产加载完成后的回调：收集并激活 GameFeature 插件。
	void OnExperienceLoadComplete();
	// 单个 GameFeature 插件激活完成的回调。
	void OnGameFeaturePluginLoadComplete(const UE::GameFeatures::FResult& Result);
	// 全部就绪后的回调：执行 Action 并广播"加载完成"。
	void OnExperienceFullLoadCompleted();

	// 单个 Action 停用完成的回调。
	void OnActionDeactivationCompleted();
	// 所有 Action 都停用完成的回调。
	void OnAllActionsDeactivated();

private:
	// 当前经验定义（网络复制，客户端通过 OnRep_CurrentExperience 同步）。
	UPROPERTY(ReplicatedUsing=OnRep_CurrentExperience)
	TObjectPtr<const UTenkaichiExperienceDefinition> CurrentExperience;

	// 当前加载状态。
	ETenkaichiExperienceLoadState LoadState = ETenkaichiExperienceLoadState::Unloaded;

	// 还在加载中的 GameFeature 插件计数。
	int32 NumGameFeaturePluginsLoading = 0;
	// 本经验要激活的 GameFeature 插件 URL 列表。
	TArray<FString> GameFeaturePluginURLs;

	// 卸载时"观察到的暂停者"计数。
	int32 NumObservedPausers = 0;
	// 卸载时"期望的暂停者"计数。
	int32 NumExpectedPausers = 0;

	// 经验加载完成后、先于其他委托被调用的委托（比如给"准备常规玩法"的子系统用）。
	FOnTenkaichiExperienceLoaded OnExperienceLoaded_HighPriority;

	// 经验加载完成后被调用的委托。
	FOnTenkaichiExperienceLoaded OnExperienceLoaded;

	// 经验加载完成后被调用的委托。
	FOnTenkaichiExperienceLoaded OnExperienceLoaded_LowPriority;
};

#undef UE_API
```

## 二、关键点讲解

### 1. 双基类：`UGameStateComponent` + `ILoadingProcessInterface`

```cpp
class UTenkaichiExperienceManagerComponent final : public UGameStateComponent, public ILoadingProcessInterface
```

- `UGameStateComponent`：只能挂在 `AGameState` 上的组件基类（普通组件挂 Actor，这个专门挂 GameState）。经验要全房间共享，所以挂在 GameState 上。
- `ILoadingProcessInterface`：引擎的"加载进程"接口，带一个 `ShouldShowLoadingScreen()`。实现它，等于告诉引擎的加载屏系统"经验没加载完时，别关加载画面"。
- `final`：这个类**不允许再被继承**（经验管理器是终点类，不是给别人继承的基类）。

### 2. `UCLASS(MinimalAPI)` + `#define UE_API`（和 P13.4 同一套）

`MinimalAPI` 只导出反射必需的部分，想给别的模块用的成员手动标 `UE_API`（本文件里 = `TENKAICHIGAME_API`）。文件末尾 `#undef UE_API` 回收别名。P13.4 已讲过，这里照用。

### 3. 枚举 `ETenkaichiExperienceLoadState`（状态机的心脏）

```cpp
enum class ETenkaichiExperienceLoadState
{
	Unloaded, Loading, LoadingGameFeatures, LoadingChaosTestingDelay,
	ExecutingActions, Loaded, Deactivating
};
```

加载状态机就是靠这个枚举驱动：`Unloaded → Loading → LoadingGameFeatures → (LoadingChaosTestingDelay) → ExecutingActions → Loaded`，退出时反向走 `Deactivating`。`enum class` 是 C++11 强类型枚举（不会隐式转 int，作用域安全）。

### 4. 委托 `DECLARE_MULTICAST_DELEGATE_OneParam`

```cpp
DECLARE_MULTICAST_DELEGATE_OneParam(FOnTenkaichiExperienceLoaded, const UTenkaichiExperienceDefinition* /*Experience*/);
```

- `DECLARE_MULTICAST_DELEGATE_OneParam(委托名, 参数类型)`：声明一个**多播委托**（可以绑多个回调），带 1 个参数。
- 参数写 `const UTenkaichiExperienceDefinition* /*Experience*/`：`/*Experience*/` 是**参数名注释**（参数名可省略，这里注释掉了，只留类型）。
- 三档优先级（High / 普通 / Low）都用这个委托类型，靠三个成员字段分开存。

### 5. 网络复制字段 `CurrentExperience`

```cpp
UPROPERTY(ReplicatedUsing=OnRep_CurrentExperience)
TObjectPtr<const UTenkaichiExperienceDefinition> CurrentExperience;
```

- `ReplicatedUsing=OnRep_CurrentExperience`：服务器改了 `CurrentExperience` 会复制到客户端，客户端收到后**自动调用 `OnRep_CurrentExperience`**。
- `TObjectPtr<const ...>`：UE5 的智能对象指针（`TObjectPtr`），`const` 表示这个组件**不修改**经验定义，只读它。
- 为什么经验要复制？因为客户端也要知道"这局用哪个经验"，好加载自己这边需要的东西（HUD、输入映射等）。

### 6. 为什么 `.h` 零挂起（关键）

```cpp
class UTenkaichiExperienceDefinition;   // 只前置声明，不 include
namespace UE::GameFeatures { struct FResult; }  // 只前置声明命名空间里的结构体
```

`.h` 里凡是出现 `UTenkaichiExperienceDefinition` 的地方，要么是**指针**（`TObjectPtr`、函数参数指针），要么是**委托参数指针**——指针只需要前置声明 `class X;` 就够了，**不需要完整定义**，所以不用 include `ExperienceDefinition.h`，也就不拖任何断点。

`UE::GameFeatures::FResult` 同理：只声明"这个命名空间里有这么个结构体"，不 include GameFeatures 头文件，`.cpp` 里真要用到才 include。
