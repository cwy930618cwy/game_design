## 〇、这个 `.cpp` 在解决什么

`.h` 声明了 3 个方法 + 计数表，`.cpp` 实现 3 个（全部 `#if WITH_EDITOR`）：
1. `OnPlayInEditorBegun`：PIE 开始前清空计数表
2. `NotifyOfPluginActivation`：激活插件 → 计数 +1
3. `RequestToDeactivatePlugin`：停用插件 → 计数 -1，归零才真停

**实现拆解：**

| 函数 | 作用 |
|------|------|
| `OnPlayInEditorBegun` | ensure 计数表为空 + 清空 |
| `NotifyOfPluginActivation` | `FindOrAdd` + `++Count` |
| `RequestToDeactivatePlugin` | `FindChecked` + `--Count`，归零返回 true 且移除 |

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiExperienceManager.h"
#include "GameModes/TenkaichiExperienceManager.h"
#include "Engine/Engine.h"
#include "Subsystems/SubsystemCollection.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiExperienceManager)

#if WITH_EDITOR

void UTenkaichiExperienceManager::OnPlayInEditorBegun()
{
	// 正常情况计数表应该本来就是空的（上个 PIE 结束已清空），清一遍保险。
	ensure(GameFeaturePluginRequestCountMap.IsEmpty());
	GameFeaturePluginRequestCountMap.Empty();
}

void UTenkaichiExperienceManager::NotifyOfPluginActivation(const FString PluginURL)
{
	if (GIsEditor)
	{
		UTenkaichiExperienceManager* ExperienceManagerSubsystem = GEngine->GetEngineSubsystem<UTenkaichiExperienceManager>();
		check(ExperienceManagerSubsystem);

		// 记录申请激活该插件的请求方数量。多次加载/激活总是允许的（并发请求会被合并处理）。
		int32& Count = ExperienceManagerSubsystem->GameFeaturePluginRequestCountMap.FindOrAdd(PluginURL);
		++Count;
	}
}

bool UTenkaichiExperienceManager::RequestToDeactivatePlugin(const FString PluginURL)
{
	if (GIsEditor)
	{
		UTenkaichiExperienceManager* ExperienceManagerSubsystem = GEngine->GetEngineSubsystem<UTenkaichiExperienceManager>();
		check(ExperienceManagerSubsystem);

		// 只有最后一个请求方允许真正停用该插件。
		int32& Count = ExperienceManagerSubsystem->GameFeaturePluginRequestCountMap.FindChecked(PluginURL);
		--Count;

		if (Count == 0)
		{
			ExperienceManagerSubsystem->GameFeaturePluginRequestCountMap.Remove(PluginURL);
			return true;
		}

		return false;
	}

	return true;
}

#endif
```

## 二、关键点讲解

### 1. `#if WITH_EDITOR` 包裹整个实现
这个 `.cpp` 所有函数都在 `#if WITH_EDITOR` 里。因为 PIE 多会话仲裁只在编辑器有用；发布包直接编译 `.h` 里的内联空实现，不链接这些。

### 2. `OnPlayInEditorBegun`：PIE 开始前清空
```cpp
ensure(GameFeaturePluginRequestCountMap.IsEmpty());
GameFeaturePluginRequestCountMap.Empty();
```
- `ensure(...)`：断言"计数表应为空"，若不为空会在日志打警告（不崩溃）。
- `Empty()`：无条件清空，防止上次 PIE 残留。

### 3. `NotifyOfPluginActivation`：激活 +1
```cpp
if (GIsEditor)  // 只在编辑器进程执行
{
	UTenkaichiExperienceManager* ... = GEngine->GetEngineSubsystem<UTenkaichiExperienceManager>();
	check(...);  // 拿引擎子系统实例，失败直接断

	int32& Count = ...->GameFeaturePluginRequestCountMap.FindOrAdd(PluginURL);
	++Count;  // 计数 +1
}
```
- `GIsEditor`：全局布尔，判断是否编辑器进程。
- `GetEngineSubsystem<UTenkaichiExperienceManager>()`：拿全局单例（static 方法靠它访问实例）。
- `FindOrAdd(Key)`：键不存在就插入并返回引用，存在就直接返回引用 → `++Count` 无论首次/多次都能 +1。

### 4. `RequestToDeactivatePlugin`：停用 -1，归零才停
```cpp
int32& Count = ...->GameFeaturePluginRequestCountMap.FindChecked(PluginURL);
--Count;
if (Count == 0) { Remove(PluginURL); return true; }
return false;
```
- `FindChecked(Key)`：键必须存在，否则断言失败（因为能停用说明之前激活过）。
- `--Count` 后：
  - **归 0** → 移除该键，返回 `true`（允许停用）。
  - **没归 0** → 还有请求方在用，返回 `false`（暂不停用）。
- 非编辑器分支返回 `true`（恒允许）。

> **"先入后出"保证**：多个请求方激活同一个插件时，只有**最后一个请求方**申请停用（计数归 0）才会真正关插件，前面的都返回 false——避免误关别人还在用的插件。
