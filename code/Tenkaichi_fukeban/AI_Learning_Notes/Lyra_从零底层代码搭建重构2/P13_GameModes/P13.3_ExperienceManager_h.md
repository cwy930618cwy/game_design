## 〇、这个 `.h` 在解决什么

`UTenkaichiExperienceManager` 继承 `UEngineSubsystem`（引擎级子系统），是"GameFeature 插件的激活计数仲裁者"（总 md 已讲）。`.h` 声明 3 个方法 + 1 张计数表。

**类声明拆解：**

| 块 | 代码 | 作用 |
|----|------|------|
| ① 基类 | `UEngineSubsystem` | 引擎级子系统，全局唯一 |
| ② 编辑器方法 | `OnPlayInEditorBegun` | PIE 开始前清空计数表 |
| ③ 计数方法 | `NotifyOfPluginActivation` / `RequestToDeactivatePlugin` | 激活 +1 / 停用 -1（静态，编辑器 vs 空实现） |
| ④ 计数表 | `GameFeaturePluginRequestCountMap` | 插件名 → 激活次数 |

## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "Subsystems/EngineSubsystem.h"
#include "TenkaichiExperienceManager.generated.h"

/**
 * 经验管理器（ExperienceManager）
 *
 * 主要用于多个 PIE 会话之间仲裁：同一个 GameFeature 插件被多次请求激活/停用时，
 * 用引用计数保证"最后一个请求者才能停用"。
 */
UCLASS(MinimalAPI)
class UTenkaichiExperienceManager : public UEngineSubsystem
{
	GENERATED_BODY()

public:
#if WITH_EDITOR
	// PIE 开始前调用：清空插件请求计数表。
	TENKAICHIGAME_API void OnPlayInEditorBegun();

	// 通知：某个插件被激活了（静态方法，计数 +1）。
	static void NotifyOfPluginActivation(const FString PluginURL);
	// 请求停用某个插件（静态方法，计数 -1，归零才真停）。
	static bool RequestToDeactivatePlugin(const FString PluginURL);
#else
	// 非编辑器（发布包）：插件激活什么都不做（空实现）。
	static void NotifyOfPluginActivation(const FString PluginURL) {}
	// 非编辑器（发布包）：插件停用永远允许（返回 true）。
	static bool RequestToDeactivatePlugin(const FString PluginURL) { return true; }
#endif

private:
	// 插件名 → 请求激活次数 的计数表
	// （用于 PIE 期间"先入后出"的激活管理：最后申请的人才允许停用）。
	TMap<FString, int32> GameFeaturePluginRequestCountMap;
};
```

## 二、关键点讲解

### 1. `UCLASS(MinimalAPI)`
只导出最小 API，类本身在模块内用，外部模块只能拿到"最小接口"（不像 `LYRAGAME_API` 那样全量导出）。但这里 `OnPlayInEditorBegun` 单独标了 `TENKAICHIGAME_API`，说明这个方法需要对外（编辑器工具链）可用。

### 2. `#if WITH_EDITOR / #else` 双版本方法
这是本类**最核心的结构**：

| 环境 | `NotifyOfPluginActivation` | `RequestToDeactivatePlugin` |
|------|---------------------------|-----------------------------|
| 编辑器（`#if WITH_EDITOR`） | 声明，`.cpp` 实现（计数 +1） | 声明，`.cpp` 实现（计数 -1） |
| 发布包（`#else`） | 空实现 `{}` | 直接 `return true`（恒允许） |

**为什么？** 计数仲裁只在编辑器多 PIE 会话才有意义。发布包单会话，插件由引擎正常管理，不需要这套记账，所以空实现 / 恒真。

### 3. `OnPlayInEditorBegun`
只在编辑器编译（在 `#if WITH_EDITOR` 块内），带 `TENKAICHIGAME_API` 导出。PIE 开始前把计数表清空，防止上次运行的残留计数干扰。

### 4. 计数表 `GameFeaturePluginRequestCountMap`
```cpp
TMap<FString, int32> GameFeaturePluginRequestCountMap;
```
- `FString` = 插件 URL/名，`int32` = 激活请求次数。
- **private**：只有本类（+ 友元）能改，封装计数逻辑。
- `.cpp` 里通过 `FindOrAdd`（激活 +1）和 `FindChecked`（停用 -1）操作它。

### 5. 静态方法
`NotifyOfPluginActivation`/`RequestToDeactivatePlugin` 是 **static**——不依赖实例，通过 `GEngine->GetEngineSubsystem<UTenkaichiExperienceManager>()` 拿单例再操作计数表。
