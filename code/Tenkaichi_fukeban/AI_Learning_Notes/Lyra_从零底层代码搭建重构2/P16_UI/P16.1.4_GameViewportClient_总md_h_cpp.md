## 一、这个类解决什么问题（先讲为什么）

`UGameViewportClient` 是引擎的"游戏视口客户端"——管理游戏窗口/视口本身（渲染目标、鼠标、输入路由、CommonUI 的控件栈）。

Lyra 继承它（实际继承 CommonGame 插件的 `UCommonGameViewportClient`），只为了做一件事：**根据平台决定用"软件光标"还是"硬件光标"**。

- **主机/移动平台**：需要软件光标（用 UI 控件画的鼠标指针，能自定义外观、支持手柄导航）。
- **桌面平台（Windows 等）**：直接用硬件光标（系统鼠标，性能更好、更跟手）。

> **类比**：视口客户端是"显示器 + 鼠标管理"。硬件光标 = 系统原生鼠标指针；软件光标 = 自己画一个鼠标指针（可以变大、变色、跟随手柄）。

## 三、关键点讲解

### 1. 基类 `UCommonGameViewportClient`（CommonGame 插件）

```cpp
class UTenkaichiGameViewportClient : public UCommonGameViewportClient
```

CommonGame 插件的视口客户端——它已经做了 CommonUI 的控件栈管理（`UCommonGameViewportClient` 管"UI 层叠 + 输入路由"）。Lyra 只再加"光标模式"这一件事。

### 2. `namespace GameViewportTags` + `UE_DEFINE_GAMEPLAY_TAG_STATIC`

```cpp
namespace GameViewportTags
{
	UE_DEFINE_GAMEPLAY_TAG_STATIC(TAG_Platform_Trait_Input_HardwareCursor, "Platform.Trait.Input.HardwareCursor");
}
```

注意这里用**命名空间包裹**本地 tag（区别于 P16.1.3 直接定义在文件作用域）。这样使用时写 `GameViewportTags::TAG_Platform_Trait_Input_HardwareCursor`——更清晰、避免和其他文件的同名变量冲突。

### 3. `HasTag` vs `HasAll`

```cpp
ICommonUIModule::GetSettings().GetPlatformTraits().HasTag(GameViewportTags::TAG_Platform_Trait_Input_HardwareCursor)
```

- P16.1.3 用的是 `HasAll(容器)`（要求**全部** tag 都有）。
- 这里用 `HasTag(单个tag)`（只要求**这一个**有）。

### 4. `SetUseSoftwareCursorWidgets(!UseHardwareCursor)`

```cpp
SetUseSoftwareCursorWidgets(!UseHardwareCursor);
```

**取反**：平台支持**硬件**光标 → 就**不用软件**光标。

| 平台 | `UseHardwareCursor` | `SetUseSoftwareCursorWidgets(...)` |
|------|--------------------|-----------------------------------|
| 桌面（Win/Mac） | tag 有 → true | `false`（不画软件光标） |
| 主机/移动 | tag 无 → false | `true`（画软件光标） |

### 5. `Init` 的 `struct FWorldContext&` 内联 `struct`

```cpp
virtual void Init(struct FWorldContext& WorldContext, UGameInstance* OwningGameInstance, bool bCreateNewAudioDevice = true) override;
```

`.h` 里参数写 `struct FWorldContext&`（内联 struct 关键字=前置声明效果），避免 include `Engine/World.h`。`.cpp` 里则不需要再声明（继承来的签名）。

### 6. 构造函数的特殊写法

```cpp
UTenkaichiGameViewportClient::UTenkaichiGameViewportClient()
	: Super(FObjectInitializer::Get())
{
}
```

注意这里**没有** `const FObjectInitializer& ObjectInitializer` 参数——`UGameViewportClient` 的构造函数签名就是无参，所以 `Super(FObjectInitializer::Get())` 自己造一个初始化器传上去。这是 UObject 构造的另一种形式。
