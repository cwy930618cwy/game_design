## 一、这个类解决什么问题（先讲为什么）

玩家启动游戏后，要经过一串**前端流程**才能进主菜单：

```
① 等用户初始化（登录平台账号）
② 显示 "Press Start" 屏（某些平台需要）
③ 尝试加入请求的会话（比如从好友邀请进来）
④ 显示主菜单
```

这串流程有**异步等待**（登录要等、UI 要等玩家按键），用普通 if/else 写会变成"回调地狱"。

Lyra 用 **ControlFlow**（引擎插件）把它写成**线性步骤队列**——每步做完调 `ContinueFlow()` 进下一步，需要等待就"挂起"（不调 Continue）。

`ULyraFrontendStateComponent` 就是这个流程的**编排者**，挂在 GameState 上。

> **类比**：这是"登机流程调度员"——值机 → 安检 → 登机口 → 上飞机，每步做完才放行下一步，某步要等（比如安检排队）就停在那。

## 三、`.h` 关键点讲解

### 1. 双基类：`UGameStateComponent` + `ILoadingProcessInterface`

```cpp
class UTenkaichiFrontendStateComponent : public UGameStateComponent, public ILoadingProcessInterface
```

- `UGameStateComponent`：只能挂 GameState（P13.5 的 `ExperienceManagerComponent` 也是这个基类）。
- `ILoadingProcessInterface`：加载屏接口（`ShouldShowLoadingScreen`）——**前端流程没走完时，加载屏不能消失**。

> 这个组合很关键：前端流程（登录/按键）可能要好几秒，期间必须显示加载屏，否则玩家看到黑屏。

### 2. `UCLASS(Abstract)`——抽象类

```cpp
UCLASS(Abstract)
```

因为它是"基类模板"——项目要继承它做具体的前端状态机（配自己的 Press Start / 主菜单控件）。

### 3. `FControlFlow` / `FControlFlowNodeRef` / `FControlFlowNodePtr`——ControlFlow 三件套

```cpp
class FControlFlow;                    // 流程本体（步骤队列）
void FlowStep_Xxx(FControlFlowNodeRef SubFlow);   // 步骤函数签名（收节点引用）
FControlFlowNodePtr InProgressPressStartScreen;   // 节点指针（记住"正在等哪一步"）
```

| 类型 | 作用 |
|------|------|
| `FControlFlow` | 流程对象（`QueueStep` 排队 + `ExecuteFlow` 执行） |
| `FControlFlowNodeRef` | **节点引用**（步骤函数参数，用来 `ContinueFlow`/`CancelFlow`） |
| `FControlFlowNodePtr` | **节点指针**（可空，用来"记住"某个挂起的步骤） |

> `Ref` vs `Ptr`：`Ref` 是"一定有值"（步骤执行时传入），`Ptr` 是"可能为空"（成员变量存）。

### 4. `TSoftClassPtr<UCommonActivatableWidget>`——软引用 UI 类

```cpp
UPROPERTY(EditAnywhere, Category = UI)
TSoftClassPtr<UCommonActivatableWidget> PressStartScreenClass;
```

两个 UI 类都是软引用（按需加载）——因为前端 UI 可能很大（一整套菜单），不该在组件创建时就加载。

### 5. `FDelegateHandle OnJoinSessionCompleteEventHandle`

```cpp
FDelegateHandle OnJoinSessionCompleteEventHandle;
```

存"加入会话完成"事件的句柄——因为要**手动解绑**（`Remove(句柄)`），不能 `RemoveAll`（可能误删别的）。

### 6. `enum class ECommonUserOnlineContext : uint8;`——枚举前置声明

```cpp
enum class ECommonUserOnlineContext : uint8;
enum class ECommonUserPrivilege : uint8;
```

`enum class` 可以前置声明（**必须指定底层类型** `: uint8`）。这样 `.h` 里不用 include CommonUser 的头文件。

> 对比 P16.1.2 的 `namespace EEndPlayReason { enum Type : int; }`（旧式枚举的前置声明写法）——`enum class` 简单得多。

```cpp
	UTenkaichiExperienceManagerComponent* ExperienceComponent = GameState->FindComponentByClass<UTenkaichiExperienceManagerComponent>();

}

void UTenkaichiFrontendStateComponent::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
	Super::EndPlay(EndPlayReason);
}

// 是否显示加载屏（前端流程没走完就显示）。
bool UTenkaichiFrontendStateComponent::ShouldShowLoadingScreen(FString& OutReason) const
{
	if (bShouldShowLoadingScreen)
	{
		OutReason = TEXT("Frontend Flow Pending...");
		
		if (FrontEndFlow.IsValid())
		{
			// 用当前步骤的调试名作为加载屏原因
			const TOptional<FString> StepDebugName = FrontEndFlow->GetCurrentStepDebugName();
			if (StepDebugName.IsSet())
			{
				OutReason = StepDebugName.GetValue();
			}
		}
		
		return true;
	}

	return false;
}

// 经验加载完成：创建并执行前端流程。
void UTenkaichiFrontendStateComponent::OnExperienceLoaded(const UTenkaichiExperienceDefinition* Experience)
{
	// 链式创建 4 个步骤
	FControlFlow& Flow = FControlFlowStatics::Create(this, TEXT("FrontendFlow"))
		.QueueStep(TEXT("Wait For User Initialization"), this, &ThisClass::FlowStep_WaitForUserInitialization)
		.QueueStep(TEXT("Try Show Press Start Screen"), this, &ThisClass::FlowStep_TryShowPressStartScreen)
		.QueueStep(TEXT("Try Join Requested Session"), this, &ThisClass::FlowStep_TryJoinRequestedSession)
		.QueueStep(TEXT("Try Show Main Screen"), this, &ThisClass::FlowStep_TryShowMainScreen);

	Flow.ExecuteFlow();

	FrontEndFlow = Flow.AsShared();
}
```

### 第 1 部分关键点

**1. `CallOrRegister_OnExperienceLoaded_HighPriority`（P13.5 已教）**

```cpp
ExperienceComponent->CallOrRegister_OnExperienceLoaded_HighPriority(FOnTenkaichiExperienceLoaded::FDelegate::CreateUObject(this, &ThisClass::OnExperienceLoaded));
```

用**高优先级**——因为前端流程要**最先**开始（其他系统可能依赖"用户已登录"）。

**2. 注释"不用在 EndPlay 里解绑"**

```cpp
// 这个委托在生命周期相同的组件上，所以不用在 EndPlay 里解绑
```

因为 `ExperienceManagerComponent` 和本组件**都挂在 GameState 上**（生命周期相同）——一起销毁，不会出现"我还在但对方没了"的悬空。

**3. `ShouldShowLoadingScreen` 用步骤名做原因**

```cpp
const TOptional<FString> StepDebugName = FrontEndFlow->GetCurrentStepDebugName();
if (StepDebugName.IsSet())
{
	OutReason = StepDebugName.GetValue();
}
```

`GetCurrentStepDebugName()`：拿到当前步骤的调试名（就是 `QueueStep` 里传的 `TEXT("Wait For User Initialization")` 等）。

**效果**：加载屏上显示"Wait For User Initialization"——玩家知道卡在哪一步。

**4. `FControlFlowStatics::Create(...).QueueStep(...).QueueStep(...)`——链式建流程**

```cpp
FControlFlow& Flow = FControlFlowStatics::Create(this, TEXT("FrontendFlow"))
	.QueueStep(TEXT("Wait For User Initialization"), this, &ThisClass::FlowStep_WaitForUserInitialization)
	.QueueStep(TEXT("Try Show Press Start Screen"), this, &ThisClass::FlowStep_TryShowPressStartScreen)
	.QueueStep(TEXT("Try Join Requested Session"), this, &ThisClass::FlowStep_TryJoinRequestedSession)
	.QueueStep(TEXT("Try Show Main Screen"), this, &ThisClass::FlowStep_TryShowMainScreen);
```

`FControlFlowStatics::Create(Outer, 流程名)`：创建流程对象。
`.QueueStep(步骤名, 对象, 成员函数)`：排队一个步骤（链式调用）。

**4 个步骤**：
| 步骤 | 作用 |
|------|------|
| `Wait For User Initialization` | 等用户登录 |
| `Try Show Press Start Screen` | 显示 Press Start |
| `Try Join Requested Session` | 加入请求的会话 |
| `Try Show Main Screen` | 显示主菜单 |

**5. `Flow.ExecuteFlow()` + `Flow.AsShared()`**

```cpp
Flow.ExecuteFlow();          // 开始执行
FrontEndFlow = Flow.AsShared();   // 存成共享指针（成员变量）
```

`AsShared()`：把 `FControlFlow&` 转成 `TSharedPtr<FControlFlow>`（因为 `Create` 返回引用，但成员要存指针）。

> 注意顺序：**先 `ExecuteFlow()` 再 `AsShared()`**——因为 `ExecuteFlow` 可能同步跑完所有步骤（如果都不需要等待），此时 `FrontEndFlow` 还没赋值，`ShouldShowLoadingScreen` 里 `IsValid()` 为 false（走默认原因）。

### 5.1 `FlowStep_WaitForUserInitialization`（第 80~108 行）

```cpp
// 流程步骤 1：等用户初始化（清理旧状态）。
void UTenkaichiFrontendStateComponent::FlowStep_WaitForUserInitialization(FControlFlowNodeRef SubFlow)
{
	// 如果是硬断开，显式销毁所有用户和会话状态
	// TODO: 重构引擎的断开流程，让它更明确地说明为什么断开
	bool bWasHardDisconnect = false;
	AGameModeBase* GameMode = GetWorld()->GetAuthGameMode<AGameModeBase>();
	UGameInstance* GameInstance = UGameplayStatics::GetGameInstance(this);

	if (ensure(GameMode) && UGameplayStatics::HasOption(GameMode->OptionsString, TEXT("closed")))
	{
		bWasHardDisconnect = true;
	}

	// 只在硬断开时重置用户
	UCommonUserSubsystem* UserSubsystem = GameInstance->GetSubsystem<UCommonUserSubsystem>();
	if (ensure(UserSubsystem) && bWasHardDisconnect)
	{
		UserSubsystem->ResetUserState();
	}

	// 总是重置会话
	UCommonSessionSubsystem* SessionSubsystem = GameInstance->GetSubsystem<UCommonSessionSubsystem>();
	if (ensure(SessionSubsystem))
	{
		SessionSubsystem->CleanUpSessions();
	}

	SubFlow->ContinueFlow();
}
```

**讲解**：
- `HasOption(OptionsString, TEXT("closed"))`：检查 URL 参数里有没有 `?closed`（引擎在"硬断开"时会加）。
- **硬断开**（`bWasHardDisconnect`）→ `ResetUserState()`（清用户登录状态）。
- **总是** → `CleanUpSessions()`（清会话）。
- 最后 `ContinueFlow()` 进下一步（这一步**不需要等待**，同步完成）。

### 5.2 `FlowStep_TryShowPressStartScreen`（第 110~160 行）

```cpp
// 流程步骤 2：尝试显示 Press Start 屏。
void UTenkaichiFrontendStateComponent::FlowStep_TryShowPressStartScreen(FControlFlowNodeRef SubFlow)
{
	const UGameInstance* GameInstance = UGameplayStatics::GetGameInstance(this);
	UCommonUserSubsystem* UserSubsystem = GameInstance->GetSubsystem<UCommonUserSubsystem>();

	// 检查第一个玩家是否已登录，已登录就跳过 Press Start 屏
	if (const UCommonUserInfo* FirstUser = UserSubsystem->GetUserInfoForLocalPlayerIndex(0))
	{
		if (FirstUser->InitializationState == ECommonUserInitializationState::LoggedInLocalOnly ||
			FirstUser->InitializationState == ECommonUserInitializationState::LoggedInOnline)
		{
			SubFlow->ContinueFlow();
			return;
		}
	}

	// 检查平台是否真的需要 'Press Start' 屏。只有"可能有多个在线用户"的平台才需要
	// （取决于哪个玩家的手柄按了 Start，决定用哪个账号登录）
	if (!UserSubsystem->ShouldWaitForStartInput())
	{
		// 开始自动登录，应该很快完成，会用默认输入设备 ID
		InProgressPressStartScreen = SubFlow;
		UserSubsystem->OnUserInitializeComplete.AddDynamic(this, &UTenkaichiFrontendStateComponent::OnUserInitialized);
		UserSubsystem->TryToInitializeForLocalPlay(0, FInputDeviceId(), false);

		return;
	}

	// 加 Press Start 屏，它停用时进下一步
	if (UPrimaryGameLayout* RootLayout = UPrimaryGameLayout::GetPrimaryGameLayoutForPrimaryPlayer(this))
	{
		constexpr bool bSuspendInputUntilComplete = true;
		RootLayout->PushWidgetToLayerStackAsync<UCommonActivatableWidget>(FrontendTags::TAG_UI_LAYER_MENU, bSuspendInputUntilComplete, PressStartScreenClass,
			[this, SubFlow](EAsyncWidgetLayerState State, UCommonActivatableWidget* Screen) {
			switch (State)
			{
			case EAsyncWidgetLayerState::AfterPush:
				bShouldShowLoadingScreen = false;
				Screen->OnDeactivated().AddWeakLambda(this, [this, SubFlow]() {
					SubFlow->ContinueFlow();
				});
				break;
			case EAsyncWidgetLayerState::Canceled:
				bShouldShowLoadingScreen = false;
				SubFlow->ContinueFlow();
				return;
			}
		});
	}
}
```

**讲解（三条分支）**：

| 分支 | 条件 | 行为 |
|------|------|------|
| ① 跳过 | 第一个玩家已登录 | `ContinueFlow()` 直接进下一步 |
| ② 自动登录 | 平台不需要 Press Start | 绑 `OnUserInitializeComplete` + `TryToInitializeForLocalPlay`，**挂起**（等回调） |
| ③ 显示 Press Start | 平台需要 | `PushWidgetToLayerStackAsync` 推屏，**挂起**（等玩家按键） |

**关键点**：
- `ShouldWaitForStartInput()`：平台是否"需要玩家按 Start 才决定登录哪个账号"（主机多用户场景）。
- `InProgressPressStartScreen = SubFlow`：**记住当前节点**（因为要等异步回调，回调里才能 `ContinueFlow`）。
- `AddDynamic`（绑 UFUNCTION）—— 因为 `OnUserInitializeComplete` 是**动态委托**。
- `PushWidgetToLayerStackAsync`（异步推层）+ `EAsyncWidgetLayerState`（`AfterPush` / `Canceled`）。
- `Screen->OnDeactivated().AddWeakLambda(...)`：**屏停用时**才 `ContinueFlow`（玩家按了 Start 或关闭屏）。
- `bSuspendInputUntilComplete = true`：推屏期间**暂停输入**（防止玩家乱按）。

### 5.4 `FlowStep_TryJoinRequestedSession`（第 186~220 行）

```cpp
// 流程步骤 3：尝试加入请求的会话。
void UTenkaichiFrontendStateComponent::FlowStep_TryJoinRequestedSession(FControlFlowNodeRef SubFlow)
{
	UCommonGameInstance* GameInstance = Cast<UCommonGameInstance>(UGameplayStatics::GetGameInstance(this));
	if (GameInstance->GetRequestedSession() != nullptr && GameInstance->CanJoinRequestedSession())
	{
		UCommonSessionSubsystem* SessionSubsystem = GameInstance->GetSubsystem<UCommonSessionSubsystem>();
		if (ensure(SessionSubsystem))
		{
			// 绑会话加入完成事件，决定继续还是取消流程
			// TODO: 需要确保会话加入完成后，服务器传送也完成
			OnJoinSessionCompleteEventHandle = SessionSubsystem->OnJoinSessionCompleteEvent.AddWeakLambda(this, [this, SubFlow, SessionSubsystem](const FOnlineResultInformation& Result)
			{
				// 解绑委托。SessionSubsystem 是触发这个事件的对象，所以它一定还有效
				SessionSubsystem->OnJoinSessionCompleteEvent.Remove(OnJoinSessionCompleteEventHandle);
				OnJoinSessionCompleteEventHandle.Reset();

				if (Result.bWasSuccessful)
				{
					// 不再过渡到主菜单
					SubFlow->CancelFlow();
				}
				else
				{
					// 继续到主菜单
					SubFlow->ContinueFlow();
					return;
				}
			});
			GameInstance->JoinRequestedSession();
			return;
		}
	}
	// 如果没请求加入会话，跳过这一步
	SubFlow->ContinueFlow();
}
```

**讲解**：
- `GetRequestedSession() != nullptr && CanJoinRequestedSession()`：有请求的会话且能加入。
- 绑 `OnJoinSessionCompleteEvent`（`AddWeakLambda` + 存句柄）。
- `JoinRequestedSession()`：发起加入。
- **成功 → `CancelFlow()`**（整个流程取消，因为要进游戏了，不需要主菜单）。
- **失败 → `ContinueFlow()`**（继续到主菜单）。
- 没请求会话 → 直接 `ContinueFlow()`。

> **`CancelFlow()` vs `ContinueFlow()`**：`Cancel` 是"整个流程终止"，`Continue` 是"进下一步"。

```cpp
void UTenkaichiFrontendStateComponent::FlowStep_TryShowMainScreen(FControlFlowNodeRef SubFlow)
{
	if (UPrimaryGameLayout* RootLayout = UPrimaryGameLayout::GetPrimaryGameLayoutForPrimaryPlayer(this))
	{
		constexpr bool bSuspendInputUntilComplete = true;
		RootLayout->PushWidgetToLayerStackAsync<UCommonActivatableWidget>(FrontendTags::TAG_UI_LAYER_MENU, bSuspendInputUntilComplete, MainScreenClass,
			[this, SubFlow](EAsyncWidgetLayerState State, UCommonActivatableWidget* Screen) {
			switch (State)
			{
			case EAsyncWidgetLayerState::AfterPush:
				bShouldShowLoadingScreen = false;
				SubFlow->ContinueFlow();
				return;
			case EAsyncWidgetLayerState::Canceled:
				bShouldShowLoadingScreen = false;
				SubFlow->ContinueFlow();
				return;
			}
		});
	}
}
```

**讲解**：
- 和 Press Start 屏几乎一样（`PushWidgetToLayerStackAsync`）。
- 区别：**推完就 `ContinueFlow()`**（不等玩家操作）——因为主菜单是终点，流程走完。
- `bShouldShowLoadingScreen = false`：主菜单出来了，加载屏可以消失。

```
BeginPlay
  └─ 监听经验加载完成（HighPriority）
       └─ OnExperienceLoaded
            └─ 建 4 步流程 + ExecuteFlow

                 ├─ ② TryShowPressStartScreen

                 │
                 ├─ ③ TryJoinRequestedSession
                 │     ├─ 有请求会话 → JoinRequestedSession（挂起）
                 │     │     ├─ 成功 → CancelFlow（进游戏）
                 │     │     └─ 失败 → ContinueFlow
                 │     └─ 无请求 → ContinueFlow
                 │
                 └─ ④ TryShowMainScreen
                       └─ 推主菜单 → ContinueFlow（流程结束）
```
