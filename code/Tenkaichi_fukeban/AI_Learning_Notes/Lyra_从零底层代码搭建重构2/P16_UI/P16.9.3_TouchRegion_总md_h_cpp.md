## 一、这个类解决什么问题（先讲为什么）

移动端需要一个"**屏幕上的按钮区域**"——玩家手指按在这个区域里，就持续产生某个输入（比如"按住开火"）。

`ULyraTouchRegion` 继承 P16.9.2 的 `UTenkaichiSimulatedInputWidget`，只做一件事：**把触摸事件转成"是否应该模拟输入"的开关**。

> **类比**：P16.9.2 是"假肢的神经接口"（能注入输入），`ULyraTouchRegion` 是"假肢上的压力传感器"——手指按上去就告诉神经接口"开始注入"，松开就"停止"。

## 二、完整代码（可直接照抄）

### `TenkaichiTouchRegion.h`（43 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "UI/TenkaichiSimulatedInputWidget.h"

#include "TenkaichiTouchRegion.generated.h"

#define UE_API TENKAICHIGAME_API

class UObject;
struct FFrame;
struct FGeometry;
struct FPointerEvent;

/**
 * "触摸区域"用来定义屏幕上的一个区域，当用户手指按上去时应该触发某种输入
 */
UCLASS(MinimalAPI, meta=( DisplayName="Tenkaichi Touch Region" ))
class UTenkaichiTouchRegion : public UTenkaichiSimulatedInputWidget
{
	GENERATED_BODY()
	
public:
	
	//~UUserWidget 接口开始
	// 触摸开始（开始模拟输入）。
	UE_API virtual FReply NativeOnTouchStarted(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent) override;
	// 触摸移动（继续模拟输入）。
	UE_API virtual FReply NativeOnTouchMoved(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent) override;
	// 触摸结束（停止模拟输入）。
	UE_API virtual FReply NativeOnTouchEnded(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent) override;
	// 每帧 Tick（持续注入输入）。
	UE_API virtual void NativeTick(const FGeometry& MyGeometry, float InDeltaTime) override;
	//~UUserWidget 接口结束

	// 是否应该模拟输入（正在被触摸）。
	UFUNCTION(BlueprintCallable)
	bool ShouldSimulateInput() const { return bShouldSimulateInput; }

protected:

	/** 这个控件正在被触摸时为 true */
	bool bShouldSimulateInput = false;
};

#undef UE_API
```

### `TenkaichiTouchRegion.cpp`（40 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "UI/TenkaichiTouchRegion.h"


#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiTouchRegion)

struct FGeometry;
struct FPointerEvent;

// 触摸开始（开始模拟输入）。
FReply UTenkaichiTouchRegion::NativeOnTouchStarted(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent)
{
	bShouldSimulateInput = true;
	return Super::NativeOnTouchStarted(InGeometry, InGestureEvent);
}

// 触摸移动（继续模拟输入）。
FReply UTenkaichiTouchRegion::NativeOnTouchMoved(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent)
{
	// 只要玩家在边界内触摸，就输入我们关联的键
	//InputKeyValue(FVector::OneVector);
	bShouldSimulateInput = true;
	// 如果应该的话，持续触发输入
	return Super::NativeOnTouchMoved(InGeometry, InGestureEvent);
}

// 触摸结束（停止模拟输入）。
FReply UTenkaichiTouchRegion::NativeOnTouchEnded(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent)
{
	bShouldSimulateInput = false;
	return Super::NativeOnTouchEnded(InGeometry, InGestureEvent);
}

// 每帧 Tick（持续注入输入）。
void UTenkaichiTouchRegion::NativeTick(const FGeometry& MyGeometry, float InDeltaTime)
{
	Super::NativeTick(MyGeometry, InDeltaTime);
	if(bShouldSimulateInput)
	{
		InputKeyValue(FVector::OneVector);
	}
}
```

## 三、关键点讲解

### 1. 三个触摸回调 + 一个 Tick（完整生命周期）

| 回调 | 行为 |
|------|------|
| `NativeOnTouchStarted` | `bShouldSimulateInput = true`（开始） |
| `NativeOnTouchMoved` | `bShouldSimulateInput = true`（保持） |
| `NativeOnTouchEnded` | `bShouldSimulateInput = false`（停止） |
| `NativeTick` | `if (bShouldSimulateInput) InputKeyValue(FVector::OneVector)`（持续注入） |

**为什么 `NativeOnTouchMoved` 也要设 true？** 因为触摸可能"从外面滑进来"（`Started` 没触发，但 `Moved` 触发了）——保险起见再设一次。

### 2. `InputKeyValue(FVector::OneVector)`——注入"满值"

```cpp
InputKeyValue(FVector::OneVector);
```

`FVector::OneVector` = `(1, 1, 1)` —— 注入"最大值"。

**效果**：模拟"摇杆推到底"或"按键按满"。因为触摸区域是**数字式**的（按了就是 1，没按就是 0），不需要模拟量。

> 对比虚拟摇杆（P16.9.4）会注入**连续值**（根据手指位置算方向/幅度）。

### 3. `NativeTick` 里持续注入（不是只注入一次）

```cpp
void UTenkaichiTouchRegion::NativeTick(const FGeometry& MyGeometry, float InDeltaTime)
{
	Super::NativeTick(MyGeometry, InDeltaTime);
	if(bShouldSimulateInput)
	{
		InputKeyValue(FVector::OneVector);
	}
}
```

**为什么每帧都注入？** 因为引擎的输入状态会"衰减"（`FlushPressedKeys` 或输入系统清理）。持续注入保证"按住期间一直有效"。

> 这是"持续输入"的标准做法（对比"单次触发"只需调一次）。

### 4. 注释掉的 `InputKeyValue` 在 `NativeOnTouchMoved` 里

```cpp
void UTenkaichiTouchRegion::NativeOnTouchMoved(const FGeometry& InGeometry, const FPointerEvent& InGestureEvent)
{
	// 只要玩家在边界内触摸，就输入我们关联的键
	//InputKeyValue(FVector::OneVector);      // ← 注释掉的
	bShouldSimulateInput = true;
	// 如果应该的话，持续触发输入
	return Super::NativeOnTouchMoved(InGeometry, InGestureEvent);
}
```

**Lyra 注释掉了这里的 `InputKeyValue`**——因为改到 `NativeTick` 里统一处理（避免 `Moved` 事件频率不稳定）。

> 按铁律 23 照抄（保留注释掉的行）。

### 5. `#define UE_API` / `#undef UE_API`

```cpp

...
#undef UE_API
```

`MinimalAPI` 类 + 成员手动标 `UE_API`（P13.4 起的标准模式）。

