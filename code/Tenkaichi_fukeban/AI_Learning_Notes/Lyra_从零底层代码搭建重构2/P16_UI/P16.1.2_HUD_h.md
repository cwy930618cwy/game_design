## 二、关键点讲解

### 1. `namespace EEndPlayReason { enum Type : int; }`——枚举的"命名空间前置声明"技巧

```cpp
namespace EEndPlayReason { enum Type : int; }
```

`EEndPlayReason` 是引擎的一个 `namespace`，里面有个 `enum Type`。C++ **不能直接前置声明嵌套在命名空间/类里的枚举**，所以要这样写：先开命名空间，在里面声明枚举，再闭合。

> 为什么要这个？因为 `EndPlay` 的参数是 `EEndPlayReason::Type`。前置声明后，`.h` 里就不用 include 定义它的头文件。这是 UE 代码里的常见技巧。

### 2. `UCLASS(Config = Game)`

和前面一致（P15.8 等）：支持 `DefaultGame.ini` 配置。

> 注意这里**没有 `MinimalAPI`**——`ALyraHUD` 需要完整导出（P15.7 要 `ATenkaichiHUD::StaticClass()`）。而且类名 `ATenkaichiHUD` 在 P15.7 的 `.cpp` 里被引用，所以必须跨模块可见。

### 3. 三个接口分组（`//~` 分界标记）

```cpp
//~UObject 接口开始
virtual void PreInitializeComponents() override;
//~UObject 接口结束

//~AActor 接口开始
virtual void BeginPlay() override;
virtual void EndPlay(const EEndPlayReason::Type EndPlayReason) override;
//~AActor 接口结束

//~AHUD 接口开始
virtual void GetDebugActorList(TArray<AActor*>& InOutList) override;
//~AHUD 接口结束
```

三组：
- `UObject`：`PreInitializeComponents`（组件级初始化）。
- `AActor`：`BeginPlay` / `EndPlay`（Actor 生命周期）。
- `AHUD`：`GetDebugActorList`（HUD 特有）。

> 注意 `PreInitializeComponents` 归在 `//~UObject` 下（Lyra 原文如此——它虽然是 Actor 的方法，但 Lyra 标注成 UObject 接口，按铁律 23 照抄）。

### 4. `GetDebugActorList(TArray<AActor*>& InOutList)`——注意是"输入输出"参数

```cpp
virtual void GetDebugActorList(TArray<AActor*>& InOutList) override;
```

参数名 `InOutList`（输入输出）——传进来是已有列表，函数往里**追加**（不是覆盖）。这是引擎调试视图的约定。

### 5. `protected` 而非 `public`

```cpp
protected:
	virtual void PreInitializeComponents() override;
```

这些覆写都在 `protected`——因为它们是引擎内部调用的生命周期钩子，外部不需要（也不该）调用。
