## 一、这个类解决什么问题（先讲为什么）

P16.7.2/3/4 解决了"指示器数据 + 管理器 + 蓝图入口"。但**没人真正画**。

`SActorCanvas` 就是**绘制核心**：它是一个 Slate `SPanel`（可容纳多个子控件），负责：
1. **为每条指示器创建/回收 UI 控件**（用 `FUserWidgetPool` 对象池，避免频繁 new/destroy）。
2. **每帧算每条指示器的屏幕位置**（调 `FIndicatorProjection::Project`）。
3. **钳制到屏幕边缘**（超出屏幕的指示器贴边显示 + 画箭头）。
4. **按深度/优先级排序**，然后交给 Slate 绘制。

> **类比**：这是"显示器"——它把一堆"任务卡"（Descriptor）变成屏幕上真实可见的 UI，还要处理"超出屏幕要怎么显示"。

## 二、内部结构全景

### `.h`（254 行）分 4 块

| 块 | 内容 |
|----|------|
| ① `FSlot`（内部类） | **一条指示器的 Slate 槽位**（屏幕位置/深度/优先级/可见性/钳制状态 + 脏标记） |
| ② `FArrowSlot`（内部类） | 箭头的槽位（空类，只是类型区分） |
| ③ `SLATE_BEGIN_ARGS` | 参数声明（`Slots` 槽位数组 + 默认可见性 `HitTestInvisible`） |
| ④ 主类 `SActorCanvas` | 三继承：`SPanel` + `FAsyncMixin` + `FGCObject` |

### 主类关键成员

| 成员 | 作用 |
|------|------|
| `AllIndicators` | 所有指示器（UObject 数组，GC 追踪） |
| `InactiveIndicators` | 待移除的指示器 |
| `LocalPlayerContext` | 本地玩家上下文 |
| `IndicatorComponentPtr` | 管理器组件弱引用 |
| `CanvasChildren`（`TPanelChildren<FSlot>`） | 指示器槽位容器 |
| `ArrowChildren`（`mutable`） | 箭头槽位容器 |
| `AllChildren`（`FCombinedChildren`） | 合并两个容器 |
| `IndicatorPool`（`FUserWidgetPool`） | **对象池**（复用 UUserWidget） |
| `ActorCanvasArrowBrush` | 箭头图片 |
| `bDrawElementsInOrder` | 按添加顺序绘制（关闭合批） |
| `TickHandle`（`FActiveTimerHandle`） | 活跃定时器句柄 |

### 主类关键方法

| 方法 | 作用 |
|------|------|
| `Construct(InArgs, InCtx, ArrowBrush)` | 初始化 + 绑管理器事件 |
| `OnArrangeChildren` | Slate 布局：算每个槽位的位置 |
| `ComputeDesiredSize` → 0 | 不占布局空间 |
| `GetChildren` | 返回合并容器 |
| `OnPaint` | **绘制入口**（核心） |
| `AddReferencedObjects` / `GetReferencerName` | GC 追踪（`FGCObject`） |
| `OnIndicatorAdded` / `OnIndicatorRemoved` | 管理器事件回调 |
| `AddIndicatorForEntry` / `RemoveIndicatorForEntry` | 创建/回收指示器控件 |
| `AddActorSlot` / `RemoveActorSlot` | 增删槽位 |
| `UpdateCanvas`（活跃定时器） | 每帧更新（投影/排序/钳制） |
| `GetOffsetAndSize` | 算控件偏移和尺寸（考虑锚点/钳制） |
| `UpdateActiveTimer` | 按需启停定时器 |
