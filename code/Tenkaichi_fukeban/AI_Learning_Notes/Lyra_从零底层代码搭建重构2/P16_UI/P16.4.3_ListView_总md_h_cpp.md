## 一、这个类解决什么问题（先讲为什么）

`UCommonListView` 是 CommonUI 的列表控件——把一组数据（`UObject*` 数组）显示成一行行条目。它默认让每条数据都用**同一个**控件类（`EntryWidgetClass`）。

`ULyraListView` 加了一层：**按数据选控件**。它持有 `FactoryRules`（一组 P16.4.1 的工厂规则），生成每条条目前先问工厂"这条数据该用哪个控件类"。

> **类比**：`UCommonListView` 是"流水线"（统一模板生产条目），`ULyraListView` 是"智能流水线"——先看货（数据）再决定用哪个模具（控件类）。

// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "CommonListView.h"

#include "TenkaichiListView.generated.h"

#define UE_API TENKAICHIGAME_API

class UUserWidget;
class ULocalPlayer;
class UTenkaichiWidgetFactory;

// 列表视图：按"工厂规则"为每条数据选控件类。
UCLASS(MinimalAPI, meta = (DisableNativeTick))
class UTenkaichiListView : public UCommonListView
{
	GENERATED_BODY()

public:
	// 构造函数：空实现。
	UE_API UTenkaichiListView(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());

#if WITH_EDITOR
	// 编辑器校验：必须至少配一条工厂规则。
	UE_API virtual void ValidateCompiledDefaults(IWidgetCompilerLog& InCompileLog) const override;
#endif

protected:
	// 生成单条条目控件（先问工厂规则选类）。
	UE_API virtual UUserWidget& OnGenerateEntryWidgetInternal(UObject* Item, TSubclassOf<UUserWidget> DesiredEntryClass, const TSharedRef<STableViewBase>& OwnerTable) override;
	//virtual bool OnIsSelectableOrNavigableInternal(UObject* SelectedItem) override;

protected:
	// 工厂规则列表（内联实例化）。
	UPROPERTY(EditAnywhere, Instanced, Category="Entry Creation")
	TArray<TObjectPtr<UTenkaichiWidgetFactory>> FactoryRules;
};

### `TenkaichiListView.cpp`（54 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiListView.h"
#include "TenkaichiWidgetFactory.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiListView)

#if WITH_EDITOR
#include "Editor/WidgetCompilerLog.h"
#endif

#define LOCTEXT_NAMESPACE "TenkaichiListView"

// 构造函数：空实现。
UTenkaichiListView::UTenkaichiListView(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
}

#if WITH_EDITOR

// 编辑器校验：必须至少配一条工厂规则。
void UTenkaichiListView::ValidateCompiledDefaults(IWidgetCompilerLog& InCompileLog) const
{
	Super::ValidateCompiledDefaults(InCompileLog);

	if (FactoryRules.Num() == 0)
	{
		InCompileLog.Error(FText::Format(FText::FromString("{0} has no Factory Rules defined, can't create widgets without them."), FText::FromString(GetName())));
	}
}

#endif

// 生成单条条目控件（先问工厂规则选类）。
UUserWidget& UTenkaichiListView::OnGenerateEntryWidgetInternal(UObject* Item, TSubclassOf<UUserWidget> DesiredEntryClass, const TSharedRef<STableViewBase>& OwnerTable)
{
	TSubclassOf<UUserWidget> WidgetClass = DesiredEntryClass;
	
	// 逐个问工厂规则，第一个给出答案的生效
	for (const UTenkaichiWidgetFactory* Rule : FactoryRules)
	{
		if (Rule)
		{
			if (const TSubclassOf<UUserWidget> EntryClass = Rule->FindWidgetClassForData(Item))
			{
				WidgetClass = EntryClass;
				break;
			}
		}
	}
	
	// 用最终确定的类生成条目控件
	UUserWidget& EntryWidget = GenerateTypedEntry<UUserWidget>(WidgetClass, OwnerTable);

	return EntryWidget;
}

#undef LOCTEXT_NAMESPACE
```

## 三、关键点讲解

### 1. `meta = (DisableNativeTick)`——禁用原生 Tick

```cpp
UCLASS(MinimalAPI, meta = (DisableNativeTick))
```

`DisableNativeTick`：**禁止 `UUserWidget` 的原生 Tick**（`NativeTick`）。列表控件不需要每帧 Tick，禁用可省性能。

> 注意这是 `meta`（编辑器/工具用的标记），UHT 会据此不生成 Tick 调用。

### 2. `UPROPERTY(EditAnywhere, Instanced, ...)`——**Instanced** 内联实例

```cpp
UPROPERTY(EditAnywhere, Instanced, Category="Entry Creation")
TArray<TObjectPtr<UTenkaichiWidgetFactory>> FactoryRules;
```

`Instanced`：这个属性的对象是**内联实例**（属于本对象，不共享）。

配合 P16.4.1 的 `EditInlineNew`：
- `EditInlineNew`（在工厂类上）：允许"内联新建"。
- `Instanced`（在拥有者属性上）：声明"这里存的是内联实例"。

**两者必须配对**：只有工厂类标了 `EditInlineNew`，持有它的属性标 `Instanced`，编辑器里才能"展开 → 新建一个工厂实例 → 直接配参数"。

> 关键区别：普通 UObject 属性只能**引用**已有资产；`Instanced` 属性可以**拥有**实例（像子对象一样）。

### 3. `OnGenerateEntryWidgetInternal`——生成条目的钩子

```cpp
virtual UUserWidget& OnGenerateEntryWidgetInternal(UObject* Item, TSubclassOf<UUserWidget> DesiredEntryClass, const TSharedRef<STableViewBase>& OwnerTable) override;
```

参数：
- `Item`：这条数据（`UObject*`）。
- `DesiredEntryClass`：父类默认想用的控件类。
- `OwnerTable`：宿主表格（Slate 的 `STableViewBase`）。

返回 `UUserWidget&`：生成的条目控件。

### 4. 工厂规则查找——"第一个给出答案的生效"

```cpp
TSubclassOf<UUserWidget> WidgetClass = DesiredEntryClass;   // ① 先用默认

for (const UTenkaichiWidgetFactory* Rule : FactoryRules)
{
	if (Rule)
	{
		if (const TSubclassOf<UUserWidget> EntryClass = Rule->FindWidgetClassForData(Item))
		{
			WidgetClass = EntryClass;   // ② 找到了就替换
			break;                      // ③ 第一个答上的就停
		}
	}
}
```

优先顺序：
1. 默认 `DesiredEntryClass`（父类给的）。
2. 遍历 `FactoryRules`，**第一个**返回非空类的规则生效（`break`）。
3. 都没返回 → 用默认。

> 所以 `FactoryRules` 的**顺序有意义**（越靠前优先级越高）。

### 5. `if (Rule)`——防御空指针

```cpp
if (Rule)
```

数组里可能有空槽（编辑器里加了但没配），跳过。

### 6. `GenerateTypedEntry<UUserWidget>(WidgetClass, OwnerTable)`

```cpp
UUserWidget& EntryWidget = GenerateTypedEntry<UUserWidget>(WidgetClass, OwnerTable);
```

`UListViewBase::GenerateTypedEntry<T>(类, 表格)`：按指定类**生成条目控件实例**并挂到表格上，返回引用。

> 这是父类的工具函数——`OnGenerateEntryWidgetInternal` 的标准用法就是"算好类 → 调它生成"。

### 7. `if (const TSubclassOf<UUserWidget> EntryClass = ...)`——TSubclassOf 的隐式 bool

```cpp
if (const TSubclassOf<UUserWidget> EntryClass = Rule->FindWidgetClassForData(Item))
```

`TSubclassOf<T>` 有 `operator bool`（隐式转换）——为空时返回 false。所以可以直接写 `if (TSubclassOf)`。

### 8. `.cpp` 里 `FText::FromString("{0} ...")` 没走 LOCTEXT

```cpp
InCompileLog.Error(FText::Format(FText::FromString("{0} has no Factory Rules defined, can't create widgets without them."), FText::FromString(GetName())));
```

注意这里 Lyra **没有用 `LOCTEXT(...)`**，而是直接 `FText::FromString(...)`——这意味着这句错误信息**不可本地化**。

> 按铁律 23 照抄（Lyra 原文如此，虽然是瑕疵）。

### 9. 注释掉的 `OnIsSelectableOrNavigableInternal`

```cpp
//virtual bool OnIsSelectableOrNavigableInternal(UObject* SelectedItem) override;
```

Lyra 保留了一行注释掉的覆写声明（表示"考虑过但没用"）。按铁律 23 **照抄保留**。
