## 二、关键点讲解

### 1. `GetDesiredInputConfig`——switch 分发

```cpp
switch (InputConfig)
{
case ETenkaichiWidgetInputMode::GameAndMenu:
	return FUIInputConfig(ECommonInputMode::All, GameMouseCaptureMode);
case ETenkaichiWidgetInputMode::Game:
	return FUIInputConfig(ECommonInputMode::Game, GameMouseCaptureMode);
case ETenkaichiWidgetInputMode::Menu:
	return FUIInputConfig(ECommonInputMode::Menu, EMouseCaptureMode::NoCapture);
case ETenkaichiWidgetInputMode::Default:
default:
	return TOptional<FUIInputConfig>();
}
```

| InputConfig | ECommonInputMode | 鼠标捕获 |
|-------------|-----------------|---------|
| `GameAndMenu` | `All`（游戏+菜单都收） | 用配置的 `GameMouseCaptureMode` |
| `Game` | `Game`（只有游戏收） | 用配置的 `GameMouseCaptureMode` |
| `Menu` | `Menu`（只有菜单收） | **强制 `NoCapture`**（鼠标可见） |
| `Default` | — | 返回空（用父类默认） |

**关键细节**：`Menu` 模式**强制 `NoCapture`**（不用 `GameMouseCaptureMode`）——因为菜单必须能看见鼠标指针。这是"菜单一定要能看到鼠标"的硬性保证。

`FUIInputConfig(ECommonInputMode, EMouseCaptureMode)`：CommonUI 的输入配置结构体，两个参数（输入模式 + 鼠标捕获）。

### 2. `return TOptional<FUIInputConfig>();` —— 默认构造 = 无值

```cpp
case ETenkaichiWidgetInputMode::Default:
default:
	return TOptional<FUIInputConfig>();
```

`TOptional<T>()` 默认构造 = **没有值**（`IsSet() == false`）。表示"我不指定，用父类默认"。

> 对比 `TOptional<FUIInputConfig>(FUIInputConfig(...))` 是"有值"。

### 3. `switch` 里的 `default` 兜底

```cpp
case ETenkaichiWidgetInputMode::Default:
default:
```

两个标签连在一起——`Default` 枚举值 和 "其他所有值" 都走同一条路。这是防御性写法（万一枚举加了新值没处理，也走默认）。

### 4. `IsFunctionImplementedInScript`——检查蓝图是否实现

```cpp
GetClass()->IsFunctionImplementedInScript(GET_FUNCTION_NAME_CHECKED(UTenkaichiActivatableWidget, BP_GetDesiredFocusTarget))
```

`IsFunctionImplementedInScript`：检查**蓝图脚本是否实现了**某个函数（不是 C++ 实现）。`BP_GetDesiredFocusTarget` 是 CommonUI 的蓝图事件（决定焦点给谁）。

`GET_FUNCTION_NAME_CHECKED(类, 函数名)`：编译期检查"这个函数真的存在"，返回它的 `FName`。如果函数名写错，**编译报错**（而不是运行时才炸）。

### 5. `GetParentNativeClass`——区分"直接继承"还是"经原生子类继承"

```cpp
if (GetParentNativeClass(GetClass()) == UTenkaichiActivatableWidget::StaticClass())
{
	CompileLog.Warning(...);   // 直接继承本类：警告
}
else
{
	CompileLog.Note(...);      // 经由原生子类：只记 note
}
```

`GetParentNativeClass`：拿到这个蓝图类的**原生（C++）基类**。

- 如果蓝图直接继承 `UTenkaichiActivatableWidget` → **警告**（确定它没实现，手柄会出问题）。
- 如果蓝图继承的是某个 C++ 子类（比如 `UTenkaichiHUDLayout`）→ 只记 **Note**（因为可能在那个 C++ 子类里实现了，无法确定）。

这是"避免误报"的细致处理。

### 6. `CompileLog.Warning` vs `CompileLog.Note`

- `Warning`：黄色警告（真的要关注）。
- `Note`：灰色提示（只是提醒，可能没问题）。

### 7. `#include "Editor/WidgetCompilerLog.h"` 在 `.cpp` 顶部（无 `#if WITH_EDITOR`）

```cpp
#include "Editor/WidgetCompilerLog.h"
```

注意 Lyra 把这个 include 放在 `.cpp` 顶部，**没有包在 `#if WITH_EDITOR` 里**。而函数体是包在 `#if WITH_EDITOR` 里的。

> 这在打包时会 include 编辑器头文件——通常能编译（`Editor/` 目录在打包时也被包含），只是不推荐。按铁律 23 照抄。
