## 二、关键点讲解

### 1. `UENUM(BlueprintType)` + `enum class ... : uint8`

```cpp
UENUM(BlueprintType)
enum class ETenkaichiWidgetInputMode : uint8
{
	Default,
	GameAndMenu,
	Game,
	Menu
};
```

- `UENUM(BlueprintType)`：反射枚举 + **蓝图可见**（蓝图里能选这个枚举）。
- `enum class ... : uint8`：强类型枚举，底层 1 字节（省内存，适合小枚举）。

> 对比 P13.5 的 `ELyraExperienceLoadState`（`enum class` 但**没有** `UENUM`）——那个只在 C++ 内部用；这个要暴露给蓝图，所以加 `UENUM(BlueprintType)`。

### 2. `UCLASS(Abstract, Blueprintable)`

```cpp
UCLASS(Abstract, Blueprintable)
class UTenkaichiActivatableWidget : public UCommonActivatableWidget
```

- `Abstract`：抽象类，**不能直接实例化**——它是基类，必须被子类（C++ 或蓝图）继承。
- `Blueprintable`：**可以被蓝图继承**（蓝图里建 Widget Blueprint，Parent Class 选它）。

> 这个组合很常见：既是 C++ 基类，又要在蓝图里做子类。

### 3. `TOptional<FUIInputConfig>`——可选返回值

```cpp
virtual TOptional<FUIInputConfig> GetDesiredInputConfig() const override;
```

`TOptional<T>`：可能"有值"也可能"没值"（类似 `std::optional`）。这里"没值"表示"用父类默认输入配置"。

> 为什么不用指针？`TOptional` 是值语义，不需要 new/delete，也不会悬空。

### 4. 两个 `EditDefaultsOnly` 属性

```cpp
UPROPERTY(EditDefaultsOnly, Category = Input)
ETenkaichiWidgetInputMode InputConfig = ETenkaichiWidgetInputMode::Default;

UPROPERTY(EditDefaultsOnly, Category = Input)
EMouseCaptureMode GameMouseCaptureMode = EMouseCaptureMode::CapturePermanently;
```

- `EditDefaultsOnly`：只能在**类默认值**（CDO）或蓝图默认值上编辑，不能在实例上改（UI 控件通常这样）。
- `protected`：子类能访问，外部不能。

### 5. `ValidateCompiledWidgetTree` 的参数

```cpp
virtual void ValidateCompiledWidgetTree(const UWidgetTree& BlueprintWidgetTree, class IWidgetCompilerLog& CompileLog) const override;
```

- `UWidgetTree&`：蓝图编译出来的控件树（只读）。
- `class IWidgetCompilerLog&`：编译日志（可往里加警告/错误）。
- 内联写 `class IWidgetCompilerLog`（前置声明式写法）——避免在 `.h` 里 include 编辑器头文件。

### 6. `struct FUIInputConfig;` 前置声明

```cpp
struct FUIInputConfig;
```

因为只用在**返回值** `TOptional<FUIInputConfig>` 里。等等——模板参数需要完整类型？实际上 `TOptional<T>` 的声明可以只前置声明 `T`（因为成员函数体在 `.cpp`），但**返回值类型需要完整定义时**才需要。这里 UHT 处理特殊，Lyra 源码这样写能编译，照抄。

> ⚠️ 如果编译报"不完整类型"，说明需要 include `CommonInputTypeEnum.h`——但 CommonUI 的 `CommonActivatableWidget.h` 已经间接 include 了，所以没问题。
