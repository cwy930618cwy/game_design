## 一、这个类解决什么问题（先讲为什么）

P16.7.3 的 `UTenkaichiIndicatorManagerComponent::GetComponent(AController*)` 是 C++ 静态方法——**蓝图里调不到**。

但实际使用指示器的大多是**蓝图**（策划在蓝图里给任务加标记）。所以需要一个"蓝图可调的入口"。

`UIndicatorLibrary` 就是**一层薄的蓝图包装**：把 `GetComponent` 暴露成 `UFUNCTION(BlueprintCallable)`。

> **类比**：`GetComponent` 是"内部电话分机号"（C++ 能打），`IndicatorLibrary` 是"对外的总机号码"（蓝图也能打）——只是转接一下。

## 三、关键点讲解

### 1. `UBlueprintFunctionLibrary`——蓝图函数库基类

```cpp
class UIndicatorLibrary : public UBlueprintFunctionLibrary
```

`UBlueprintFunctionLibrary`：UE 的"蓝图函数库"基类。它**不需要实例化**——里面的函数都是 `static`，蓝图里作为"纯函数节点/函数调用节点"使用。

> 类比 P02 的 `UTenkaichiSystemStatics` / `UTenkaichiActorUtilities`（同样是函数库）。

### 2. `UCLASS(MinimalAPI)` + `#define UE_API`

```cpp
#define UE_API TENKAICHIGAME_API

UCLASS(MinimalAPI)
class UIndicatorLibrary : public UBlueprintFunctionLibrary
```

`MinimalAPI`（精简导出）+ 成员手动标 `UE_API`（= `TENKAICHIGAME_API`）——P13.4 起一直用的模式。

注意**静态函数也要标 `UE_API`**：
```cpp
static UE_API UTenkaichiIndicatorManagerComponent* GetIndicatorManagerComponent(AController* Controller);
```
因为它跨模块被蓝图调用。

### 3. `UFUNCTION(BlueprintCallable)` + `static` 组合

```cpp
UFUNCTION(BlueprintCallable, Category = Indicator)
static UE_API UTenkaichiIndicatorManagerComponent* GetIndicatorManagerComponent(AController* Controller);
```

- `BlueprintCallable`：蓝图可调。
- `static`：静态（函数库的惯例，不需要实例）。
- `Category = Indicator`：蓝图节点面板里的分类是 "Indicator"。

### 4. 实现就是一行转发

```cpp
UTenkaichiIndicatorManagerComponent* UIndicatorLibrary::GetIndicatorManagerComponent(AController* Controller)
{
	return UTenkaichiIndicatorManagerComponent::GetComponent(Controller);
}
```

**纯转发**——没有任何额外逻辑。这是"适配层/门面层"的典型写法。

> 为什么不在 `GetComponent` 上直接加 `UFUNCTION`？因为 `GetComponent` 在 **UControllerComponent 子类**上，而 `UControllerComponent` 的蓝图可见性有限；放在函数库里更符合 UE 惯例（蓝图工具函数集中在 `*Library` / `*Statics`）。

### 5. 构造函数 `UIndicatorLibrary()` 空实现

```cpp
UIndicatorLibrary::UIndicatorLibrary()
{
}
```

函数库虽然不需要实例，但 Lyra 还是显式声明了构造函数（`.h` 里 `UE_API UIndicatorLibrary();`，`.cpp` 里空实现）。

> 按铁律 23 照抄——不要因为"函数库不需要构造"就删掉。

### 6. `class AController;` 在 `.cpp` 里重复前置声明

```cpp
// .h 里有
class AController;

// .cpp 里也有
class AController;
```

Lyra 在 `.cpp` 里**又写了一次**前置声明（虽然 `.h` 已经声明过）。

> 这是 Lyra 源码的冗余写法，按铁律 23 照抄保留。
