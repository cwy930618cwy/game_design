## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "TenkaichiHUD.h"

#include "AbilitySystemComponent.h"
#include "AbilitySystemGlobals.h"
#include "Async/TaskGraphInterfaces.h"
#include "Components/GameFrameworkComponentManager.h"
#include "UObject/UObjectIterator.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(TenkaichiHUD)

class AActor;
class UWorld;

//////////////////////////////////////////////////////////////////////
// ATenkaichiHUD

// 构造函数：关闭 Tick。
ATenkaichiHUD::ATenkaichiHUD(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	PrimaryActorTick.bStartWithTickEnabled = false;
}

// 组件预初始化（注册为 GameFramework 组件接收者）。
void ATenkaichiHUD::PreInitializeComponents()
{
	Super::PreInitializeComponents();

	// 注册为"GameFramework 组件接收者"：这样 ComponentManager 能给它发扩展事件
	UGameFrameworkComponentManager::AddGameFrameworkComponentReceiver(this);
}

// 开始游戏（广播"游戏 Actor 就绪"事件）。
void ATenkaichiHUD::BeginPlay()
{
	// 广播"游戏 Actor 就绪"——P15.7 AddWidgets 监听的就是这个事件
	UGameFrameworkComponentManager::SendGameFrameworkComponentExtensionEvent(this, UGameFrameworkComponentManager::NAME_GameActorReady);

	Super::BeginPlay();
}

// Actor 生命周期结束（注销组件接收者）。
void ATenkaichiHUD::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
	UGameFrameworkComponentManager::RemoveGameFrameworkComponentReceiver(this);

	Super::EndPlay(EndPlayReason);
}

// 返回调试用的 Actor 列表（收集所有带能力系统的 Actor）。
void ATenkaichiHUD::GetDebugActorList(TArray<AActor*>& InOutList)
{
	UWorld* World = GetWorld();

	Super::GetDebugActorList(InOutList);

	// 添加所有带能力系统组件的 Actor。
	for (TObjectIterator<UAbilitySystemComponent> It; It; ++It)
	{
		if (UAbilitySystemComponent* ASC = *It)
		{
			// 跳过 CDO 和原型对象
			if (!ASC->HasAnyFlags(RF_ClassDefaultObject | RF_ArchetypeObject))
			{
				AActor* AvatarActor = ASC->GetAvatarActor();
				AActor* OwnerActor = ASC->GetOwnerActor();

				if (AvatarActor && UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(AvatarActor))
				{
					AddActorToDebugList(AvatarActor, InOutList, World);
				}
				else if (OwnerActor && UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(OwnerActor))
				{
					AddActorToDebugList(OwnerActor, InOutList, World);
				}
			}
		}
	}
}
```

## 二、关键点讲解

### 1. `PrimaryActorTick.bStartWithTickEnabled = false`

```cpp
PrimaryActorTick.bStartWithTickEnabled = false;
```

HUD 不需要每帧 Tick（UI 由控件自己管理），关掉省性能。

### 2. `AddGameFrameworkComponentReceiver(this)`——注册为"组件接收者"

```cpp
UGameFrameworkComponentManager::AddGameFrameworkComponentReceiver(this);
```

这是**关键一步**。ModularGameplay 的 `UGameFrameworkComponentManager` 只会向"注册过的接收者"发送扩展事件。注册后，P15.7 的 `AddExtensionHandler(ATenkaichiHUD::StaticClass(), ...)` 才能真正收到这个 HUD 的事件。

> 类比：先"在物业登记"（`AddGameFrameworkComponentReceiver`），物业才会给你送通知（扩展事件）。

在 `PreInitializeComponents` 里注册（比 `BeginPlay` 早），保证激活前就位。

### 3. `SendGameFrameworkComponentExtensionEvent(this, NAME_GameActorReady)`

```cpp
UGameFrameworkComponentManager::SendGameFrameworkComponentExtensionEvent(this, UGameFrameworkComponentManager::NAME_GameActorReady);
```

**手动广播**"游戏 Actor 就绪"事件。这就是 **P15.7 `AddWidgets` 监听的那个事件**：

```cpp
// P15.7 里：
else if ((EventName == NAME_ExtensionAdded) || (EventName == UGameFrameworkComponentManager::NAME_GameActorReady))
{
	AddWidgets(Actor, ActiveData);
}
```

所以链路是：
```
ATenkaichiHUD::BeginPlay()
  → SendGameFrameworkComponentExtensionEvent(NAME_GameActorReady)
    → P15.7 的 HandleActorExtension 收到
      → AddWidgets()  真正把 UI 加上去
```

> **为什么在 `BeginPlay` 里发？** 因为此时 HUD Actor 已经完整初始化（组件就绪），可以安全地挂 UI。而且 `BeginPlay` 在 `Super::BeginPlay()` **之前**发送——确保 UI 先于 HUD 自身逻辑准备好。

### 4. `RemoveGameFrameworkComponentReceiver(this)`——注销

```cpp
UGameFrameworkComponentManager::RemoveGameFrameworkComponentReceiver(this);
```

`EndPlay` 里注销（成对出现）。否则 HUD 销毁后 ComponentManager 还向它发事件 → 悬空崩溃。

### 5. `TObjectIterator<UAbilitySystemComponent>`——遍历所有 ASC

```cpp
for (TObjectIterator<UAbilitySystemComponent> It; It; ++It)
{
	if (UAbilitySystemComponent* ASC = *It)
	{
		if (!ASC->HasAnyFlags(RF_ClassDefaultObject | RF_ArchetypeObject))
		...
	}
}
```

`TObjectIterator<T>`：遍历进程里所有该类型的对象（P14.7 也用过 `TObjectIterator<UClass>`）。

- `RF_ClassDefaultObject`：跳过 CDO（类默认对象）。
- `RF_ArchetypeObject`：跳过原型对象。
- 只处理"真实实例"。

### 6. `GetAvatarActor` / `GetOwnerActor`——ASC 的两个关联 Actor

```cpp
AActor* AvatarActor = ASC->GetAvatarActor();   // 化身（比如角色）
AActor* OwnerActor = ASC->GetOwnerActor();     // 拥有者（比如 PlayerState）

if (AvatarActor && UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(AvatarActor))
{
	AddActorToDebugList(AvatarActor, InOutList, World);
}
else if (OwnerActor && ...)
{
	AddActorToDebugList(OwnerActor, InOutList, World);
}
```

GAS 的 ASC 可以挂在不同 Actor 上：
- **Pawn（角色）**：ASC 通常在 PlayerState 上，Avatar 是 Pawn。
- **GameState**：ASC 在 GameState 自己身上（Avatar 和 Owner 都是它）。

这里优先加 Avatar，没有再加 Owner——尽量把"玩家看得见的那个 Actor"加进调试列表。

### 7. `AddActorToDebugList`——基类方法

```cpp
AddActorToDebugList(AvatarActor, InOutList, World);
```

`AHUD` 的 protected 方法，把 Actor 加进调试列表（去重 + 过滤世界）。
