## 一、这个类解决什么问题（先讲为什么）

### `HitMarkerConfirmationWidget.cpp`（40 行）

```cpp
// 版权声明（可保留或省略，不影响编译）
#include "HitMarkerConfirmationWidget.h"

#include "Blueprint/UserWidget.h"
#include "SHitMarkerConfirmationWidget.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(HitMarkerConfirmationWidget)

class SWidget;

// 构造函数：设默认可见性 + 易变标记 + 默认不画"任意命中"图。
UHitMarkerConfirmationWidget::UHitMarkerConfirmationWidget(const FObjectInitializer& ObjectInitializer)
	: Super(ObjectInitializer)
{
	SetVisibility(ESlateVisibility::HitTestInvisible);
	bIsVolatile = true;
	AnyHitsMarkerImage.DrawAs = ESlateBrushDrawType::NoDrawType;
}

// 释放 Slate 资源。
void UHitMarkerConfirmationWidget::ReleaseSlateResources(bool bReleaseChildren)
{
	Super::ReleaseSlateResources(bReleaseChildren);

	MyMarkerWidget.Reset();
}

// 重建 Slate 控件（创建 S 层实例，并传自定义参数）。
TSharedRef<SWidget> UHitMarkerConfirmationWidget::RebuildWidget()
{
	UUserWidget* OuterUserWidget = GetTypedOuter<UUserWidget>();
	FLocalPlayerContext DummyContext;
	const FLocalPlayerContext& PlayerContextRef = (OuterUserWidget != nullptr) ? OuterUserWidget->GetPlayerContext() : DummyContext;

	MyMarkerWidget = SNew(SHitMarkerConfirmationWidget, PlayerContextRef, PerHitMarkerZoneOverrideImages)
		.PerHitMarkerImage(&(this->PerHitMarkerImage))
		.AnyHitsMarkerImage(&(this->AnyHitsMarkerImage))
		.HitNotifyDuration(this->HitNotifyDuration);

	return MyMarkerWidget.ToSharedRef();
}
```

## 三、关键点讲解

### 1. `SNew(类, 自定义参数...)`——传 Construct 的额外参数（本节核心）

```cpp
MyMarkerWidget = SNew(SHitMarkerConfirmationWidget, PlayerContextRef, PerHitMarkerZoneOverrideImages)
	.PerHitMarkerImage(&(this->PerHitMarkerImage))
	.AnyHitsMarkerImage(&(this->AnyHitsMarkerImage))
	.HitNotifyDuration(this->HitNotifyDuration);
```

**`SNew(类名, 参数1, 参数2, ...)`**：`SNew` 后面除了类名，**还可以跟参数**——这些参数直接传给 `Construct` 的自定义部分。

对应 P16.6.5 的声明：
```cpp
void Construct(const FArguments& InArgs,
               const FLocalPlayerContext& InContext,              // ← PlayerContextRef
               const TMap<FGameplayTag, FSlateBrush>& ZoneOverrideImages);  // ← PerHitMarkerZoneOverrideImages
```

**两种参数的区别**：

| 传法 | 对应声明 | 例子 |
|------|---------|------|
| `SNew(类, X, Y)` | `Construct(InArgs, X, Y)` 的**额外参数** | `PlayerContextRef`, `PerHitMarkerZoneOverrideImages` |
| `.参数名(...)` | `SLATE_ARGUMENT` / `SLATE_ATTRIBUTE` | `.PerHitMarkerImage(...)` |

> 对比 P16.6.4（`UCircumferenceMarkerWidget`）：那里 `Construct` 只有一个 `InArgs`，所以 `SNew` 只跟类名。

### 2. `GetTypedOuter<UUserWidget>()`——找外层 UUserWidget

```cpp
UUserWidget* OuterUserWidget = GetTypedOuter<UUserWidget>();
```

`GetTypedOuter<T>()`：沿 Outer 链往上找**第一个 `T` 类型的对象**。这里找"包含这个控件的 UUserWidget"。

> 因为 `UHitMarkerConfirmationWidget` 是放在某个 `UUserWidget`（HUD 里的 UserWidget）里的子控件，要拿外层那个 UserWidget 的 PlayerContext。

### 3. `DummyContext`——空上下文的兜底

```cpp
FLocalPlayerContext DummyContext;
const FLocalPlayerContext& PlayerContextRef = (OuterUserWidget != nullptr) ? OuterUserWidget->GetPlayerContext() : DummyContext;
```

**为什么要 Dummy？** 因为要用**引用**（`const FLocalPlayerContext&`），不能用三元表达式返回"空指针/临时值"。

做法：先建一个空的 `DummyContext`（栈上变量），三元里两个分支都返回**引用**：
- 有外层 UserWidget → `OuterUserWidget->GetPlayerContext()`（返回引用）。
- 没有 → `DummyContext`（返回引用）。

这样类型统一（都是引用），不会悬空（`DummyContext` 在本函数作用域内有效）。

> **关键**：`Construct` 里会 `MyContext = InContext`（**拷贝**），所以 `DummyContext` 离开作用域后不影响 —— 安全。

### 4. `&(this->PerHitMarkerImage)`——取成员地址（加括号）

```cpp
.PerHitMarkerImage(&(this->PerHitMarkerImage))
```

`SLATE_ARGUMENT(const FSlateBrush*, PerHitMarkerImage)` 要的是**指针**，所以取地址。

`&(this->PerHitMarkerImage)` 加括号是**防止宏展开优先级问题**（Slate 的宏链式调用可能有坑）。按铁律 23 照抄括号。

### 5. `AnyHitsMarkerImage.DrawAs = ESlateBrushDrawType::NoDrawType`——默认不画

```cpp
AnyHitsMarkerImage.DrawAs = ESlateBrushDrawType::NoDrawType;
```

构造函数里把 `AnyHitsMarkerImage` 默认设成"**不绘制**"（`NoDrawType`）。

**为什么？** 因为"屏幕中心单一标记"是**可选**的——默认不显示，策划需要在编辑器里配了图片才显示。

> 对比 P16.6.5 里的判断：`if (AnyHitsMarkerImage != nullptr)`——但这里 `AnyHitsMarkerImage` 是 `FSlateBrush`（不是指针），永远传地址（非空）。所以 Slate 层的 `!= nullptr` 永远成立。
>
> 真正"不画"靠 `DrawAs = NoDrawType`（Slate 绘制时跳过）。

### 6. `SynchronizeProperties` **没有覆写**（对比 P16.6.4）

注意这个类**没有**覆写 `SynchronizeProperties`！

为什么？因为所有参数（画刷指针、时长）都在 `RebuildWidget` 里传了。UMG 属性变更时会触发 `RebuildWidget`（重新创建 Slate 控件），不需要增量同步。

> 对比 P16.6.4 `UCircumferenceMarkerWidget` 覆写了 `SynchronizeProperties`（用 `SetRadius`/`SetMarkerList` 增量更新）。
>
> **差异原因**：P16.6.4 的 Slate 控件有 `SetRadius`/`SetMarkerList` 这类 Setter；P16.6.5 的 Slate 控件**没有** Setter，只能靠重建。

### 7. `ComputeVolatility` 对应的 UMG 侧

```cpp
bIsVolatile = true;
```

UMG 层标记"易变"——Slate 层的 `ComputeVolatility()` 返回 true 也是同样效果（每帧重绘）。
