## 一、这个类解决什么问题（先讲为什么）

换地图（map transition）时，旧的 GameInstance 子系统和 UI 都会销毁重建。但"加载屏该显示什么内容"这个配置**不该丢失**——玩家从 A 图到 B 图，加载屏应该还是同一个。

`ULyraLoadingScreenSubsystem` 是 `UGameInstanceSubsystem`（挂在 GameInstance 上，**跨地图切换存活**），专门存"加载屏内容控件类"。

> **类比**：这是"加载屏的记事本"——它不在某个地图里，而是跟着整个游戏进程，所以换图后还能记住"上次设置的加载屏内容"。

## 三、关键点讲解

### 1. `UGameInstanceSubsystem`——跨地图存活

```cpp
class UTenkaichiLoadingScreenSubsystem : public UGameInstanceSubsystem
```

UE 有几种 Subsystem 生命周期：
| 类型 | 生命周期 |
|------|---------|
| `UEngineSubsystem` | 整个引擎进程 |
| `UGameInstanceSubsystem` | **整个游戏实例（跨地图）** |
| `UWorldSubsystem` | 单个世界/地图 |
| `ULocalPlayerSubsystem` | 单个本地玩家 |

这里选 `UGameInstanceSubsystem`——因为要**跨地图切换**保留加载屏配置。

### 2. `DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam`——蓝图可绑的委托

```cpp
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FTenkaichiLoadingScreenWidgetChangedDelegate, TSubclassOf<UUserWidget>, NewWidgetClass);
```

`DYNAMIC`：动态委托（可序列化，蓝图可绑）。参数是 `TSubclassOf<UUserWidget>`。

### 3. `meta=(AllowPrivateAccess)`——私有成员可在蓝图访问

```cpp
UPROPERTY(BlueprintAssignable, meta=(AllowPrivateAccess))
FTenkaichiLoadingScreenWidgetChangedDelegate OnLoadingScreenWidgetChanged;
```

这个委托在 `private:` 段，但标了 `BlueprintAssignable`（蓝图可绑）。按理私有成员蓝图访问不到，所以要 `AllowPrivateAccess` 放行。

> 这是 UE 的常见 trick：想"私有 + 蓝图可绑"，就加 `AllowPrivateAccess`。

### 4. 只有值变了才广播

```cpp
if (LoadingScreenWidgetClass != NewWidgetClass)
{
	LoadingScreenWidgetClass = NewWidgetClass;
	OnLoadingScreenWidgetChanged.Broadcast(LoadingScreenWidgetClass);
}
```

避免重复设置同一个类时触发无谓的广播（监听者不用重复刷新）。

### 5. `BlueprintPure`——纯函数

```cpp
UFUNCTION(BlueprintPure)
TSubclassOf<UUserWidget> GetLoadingScreenContentWidget() const;
```

`BlueprintPure`：蓝图里的"纯函数"节点（无执行引脚，只输出值）——适合 getter。

### 6. `#define UE_API` / `#undef UE_API`

```cpp
#define UE_API TENKAICHIGAME_API
...
#undef UE_API
```

和 P13.4/P13.5 一样的 MinimalAPI 模式：`MinimalAPI` 类里需要导出的成员标 `UE_API`（= `TENKAICHIGAME_API`）。

> 注意这个类**用 `MinimalAPI`**（跨模块需要导出 `SetLoadingScreenContentWidget`/`GetLoadingScreenContentWidget`）。
