## 一、这个接口解决什么问题（先讲为什么）

指示器要显示**具体的 UI 控件**（队友头像、任务图标、敌人血条）。但系统不能假设那些控件是什么类——它们可能是任何 `UUserWidget` 子类。

所以定义这个接口：**"能作为指示器显示的控件"必须实现它**。实现后就能接收"绑定/解绑指示器"的通知，自己去读取指示器数据（位置/距离/朝向）并更新显示。

> **类比**：这是"指示器演员的合同"——你想当指示器（在屏幕上被贴到某个 Actor 位置），就签这个合同：答应能接收"你被绑定到哪条指示器了"和"解除绑定"两个通知。

## 二、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "CoreMinimal.h"
#include "UObject/ObjectMacros.h"
#include "UObject/Interface.h"

#include "IActorIndicatorWidget.generated.h"

class AActor;
class UIndicatorDescriptor;

// 接口的 UObject 壳（蓝图可见）。
UINTERFACE(MinimalAPI, BlueprintType)
class UIndicatorWidgetInterface : public UInterface
{
	GENERATED_BODY()
};

// 接口的 C++ 侧：能作为指示器显示的控件实现它。
class IIndicatorWidgetInterface
{
	GENERATED_BODY()

public:
	// 绑定到某条指示器时调用（蓝图可实现）。
	UFUNCTION(BlueprintNativeEvent, Category = "Indicator")
	void BindIndicator(UIndicatorDescriptor* Indicator);

	// 从某条指示器解绑时调用（蓝图可实现）。
	UFUNCTION(BlueprintNativeEvent, Category = "Indicator")
	void UnbindIndicator(const UIndicatorDescriptor* Indicator);
};
```

## 三、关键点讲解

### 1. 文件名 vs 类名不一致（Lyra 原文如此）

| 项 | 名字 |
|----|------|
| 文件名 | `IActorIndicatorWidget.h` |
| 接口 U 类 | `UIndicatorWidgetInterface` |
| 接口 I 类 | `IIndicatorWidgetInterface` |

Lyra 原文文件名是 `IActorIndicatorWidget.h`（带 `Actor`），但类名没有 `Actor`。**按铁律 23/10 照抄**——不改文件名，不挪位置。

### 2. `UINTERFACE(MinimalAPI, BlueprintType)` + `I` 前缀类（P16.4.5 同模式）

```cpp
UINTERFACE(MinimalAPI, BlueprintType)
class UIndicatorWidgetInterface : public UInterface
{
	GENERATED_BODY()
};

class IIndicatorWidgetInterface
{
	GENERATED_BODY()
public:
	...
};
```

- `U` 前缀类：UObject 壳（反射系统用）。
- `I` 前缀类：真正的 C++ 接口（成员函数在这）。
- `MinimalAPI`：精简导出（跨模块用）。
- `BlueprintType`：蓝图可作类型。

### 3. 两个 `BlueprintNativeEvent`——C++ 有默认实现，蓝图可覆写

```cpp
UFUNCTION(BlueprintNativeEvent, Category = "Indicator")
void BindIndicator(UIndicatorDescriptor* Indicator);

UFUNCTION(BlueprintNativeEvent, Category = "Indicator")
void UnbindIndicator(const UIndicatorDescriptor* Indicator);
```

对比 P16.4.5 的 `SetTabLabelInfo`（也是 `BlueprintNativeEvent`）——同一种模式。

**注意 `UnbindIndicator` 的参数是 `const UIndicatorDescriptor*`（带 const）**，而 `BindIndicator` 不带。因为解绑时不需要改描述符。

> ⚠️ **重要**：因为是接口的 `BlueprintNativeEvent`，**实现类必须提供 `_Implementation`**（`.cpp` 里）。但如果实现类**只在蓝图里实现**，C++ 也可以不提供（UHT 会生成空实现）？实际上接口的 `BlueprintNativeEvent` **必须**有 C++ 的 `_Implementation`（在实现类里）——但 Lyra 这里**没有任何 C++ 实现类**（都是蓝图 UUserWidget 实现）。
>
> 这能成立是因为：接口的 `BlueprintNativeEvent` 在"纯蓝图实现"时，UHT 对接口生成默认空实现。这是 UE 接口的特殊行为。

### 4. `class AActor;` 前置声明但未使用

```cpp
class AActor;
class UIndicatorDescriptor;
```

`AActor` 在接口里**没用到**（Lyra 原文留着）。按铁律 23 照抄保留。

### 5. 没有 `UE_API` / `MinimalAPI` 的成员导出

注意这个文件**没有** `#define UE_API`——因为接口的两个方法都是 `BlueprintNativeEvent`（由 UHT 生成执行函数，不需要手动导出）。
