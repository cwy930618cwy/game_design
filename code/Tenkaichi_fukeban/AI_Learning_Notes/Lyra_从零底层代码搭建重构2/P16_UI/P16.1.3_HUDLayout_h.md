## 一、完整代码（可直接照抄）

```cpp
// 版权声明（可保留或省略，不影响编译）
#pragma once

#include "TenkaichiActivatableWidget.h"
#include "Containers/Ticker.h"
#include "GameplayTagContainer.h"

#include "TenkaichiHUDLayout.generated.h"

class UCommonActivatableWidget;
class UObject;
class UTenkaichiControllerDisconnectedScreen;

/**
 * UTenkaichiHUDLayout
 *
 *	用来布局玩家 HUD 的控件（通常由经验里的 Add Widgets 动作指定）。
 */
UCLASS(Abstract, BlueprintType, Blueprintable, Meta = (DisplayName = "Tenkaichi HUD Layout", Category = "Tenkaichi|HUD"))
class UTenkaichiHUDLayout : public UTenkaichiActivatableWidget
{
	GENERATED_BODY()

public:

	// 构造函数：加默认的平台 trait tag。
	UTenkaichiHUDLayout(const FObjectInitializer& ObjectInitializer);

	// 控件初始化（注册 Esc 动作 + 绑手柄事件）。
	virtual void NativeOnInitialized() override;
	// 控件销毁（解绑手柄事件 + 移除 Ticker）。
	virtual void NativeDestruct() override;

protected:
	// 处理 Esc 动作：推暂停菜单。
	void HandleEscapeAction();
	
	/** 
	* 控制器断开时的回调。这会检查玩家现在是否已经没有映射到它的输入设备了，
	* 这意味着他们无法玩游戏。
	* 
	* 如果是这种情况，就调用 DisplayControllerDisconnectedMenu。
	*/
	void HandleInputDeviceConnectionChanged(EInputDeviceConnectionState NewConnectionState, FPlatformUserId PlatformUserId, FInputDeviceId InputDeviceId);

	/**
	* 控制器改变其所属平台用户时的回调。我们用这个来检查
	* 是否不再需要显示"控制器已断开"菜单。
	*/
	void HandleInputDevicePairingChanged(FInputDeviceId InputDeviceId, FPlatformUserId NewUserPlatformId, FPlatformUserId OldUserPlatformId);
	
	/**
	* 通知这个控件：玩家的控制器状态变了。下一帧排队一个计时器来
	* 处理它们，看是否需要显示/隐藏"控制器已断开"控件。
	*/
	void NotifyControllerStateChangeForDisconnectScreen();

	/**
	 * 这会检查连接到玩家的控制器状态。如果它们没有连接任何控制器，
	 * 我们就应该显示断开菜单。如果它们有连接的控制器，我们就可以
	 * 隐藏断开菜单（如果正在显示的话）。
	 */
	virtual void ProcessControllerDevicesHavingChangedForDisconnectScreen();

	/**
     * 如果这个平台支持"控制器已断开"屏，返回 true。
     */
    virtual bool ShouldPlatformDisplayControllerDisconnectScreen() const;
	
	/**
	* 把 ControllerDisconnectedMenuClass 推到菜单层（UI.Layer.Menu）。
	*/
	UFUNCTION(BlueprintNativeEvent, Category="Controller Disconnect Menu")
	void DisplayControllerDisconnectedMenu();

	/**
	* 如果控制器断开菜单是激活的，就隐藏它。
	*/
	UFUNCTION(BlueprintNativeEvent, Category="Controller Disconnect Menu")
	void HideControllerDisconnectedMenu();
	
	/**
	 * 当用户按下"暂停"或"Esc"按钮时要显示的菜单。
	 */
	UPROPERTY(EditDefaultsOnly)
	TSoftClassPtr<UCommonActivatableWidget> EscapeMenuClass;

	/** 
	* 如果用户所有控制器都断开了，应该呈现给用户的控件。
	*/
	UPROPERTY(EditDefaultsOnly, Category="Controller Disconnect Menu")
	TSubclassOf<UTenkaichiControllerDisconnectedScreen> ControllerDisconnectedScreen;

	/**
	 * 为了显示"控制器已断开"屏所需的平台 tag。
	 *
	 * 如果这些 tag 没有在这个平台的 INI 文件里设置，那么控制器断开屏
	 * 将永远不会显示。
	 */
	UPROPERTY(EditDefaultsOnly, Category="Controller Disconnect Menu")
	FGameplayTagContainer PlatformRequiresControllerDisconnectScreen;

	/** 指向当前激活的"控制器已断开"菜单（如果有的话）。 */
	UPROPERTY(Transient)
	TObjectPtr<UCommonActivatableWidget> SpawnedControllerDisconnectScreen;

	/** FTSTicker 的句柄，用于我们想要处理玩家控制器状态时。 */
	FTSTicker::FDelegateHandle RequestProcessControllerStateHandle;
};
```

## 二、关键点讲解

### 1. `UCLASS(Abstract, BlueprintType, Blueprintable, Meta = (...))`

```cpp
UCLASS(Abstract, BlueprintType, Blueprintable, Meta = (DisplayName = "Tenkaichi HUD Layout", Category = "Tenkaichi|HUD"))
```

比 P16.1.1 多了：
- `BlueprintType`：这个类型可以在蓝图里**作为变量类型**（不只是可继承）。
- `Meta = (DisplayName = "...", Category = "Tenkaichi|HUD")`：编辑器里显示为 "Tenkaichi HUD Layout"，并在 "Tenkaichi|HUD" 分类下（`Category` 里的 `Lyra` → `Tenkaichi`，铁律 24）。

### 2. `NativeOnInitialized` / `NativeDestruct`——UUserWidget 的原生生命周期

```cpp
virtual void NativeOnInitialized() override;
virtual void NativeDestruct() override;
```

这是 `UUserWidget` 的生命周期（不是 Actor 的）：
- `NativeOnInitialized`：控件初始化完成（比 `Construct` 早，只调一次）。
- `NativeDestruct`：控件销毁前（清理资源）。

> 注意不是 `BeginPlay`/`EndPlay`——UI 控件用的是 UUserWidget 体系的生命周期。

### 3. `FTSTicker::FDelegateHandle RequestProcessControllerStateHandle`

```cpp
FTSTicker::FDelegateHandle RequestProcessControllerStateHandle;
```

`FTSTicker` 是引擎的"每帧 Tick 管理器"（比 `FTimerManager` 轻量，用于非 Actor 对象的 tick）。

`FDelegateHandle`：注册 ticker 后返回的句柄（用于 `RemoveTicker`）。

### 4. 三个 `UPROPERTY` 配置

| 属性 | 类型 | 说明 |
|------|------|------|
| `EscapeMenuClass` | `TSoftClassPtr<UCommonActivatableWidget>` | 软引用（按需加载） |
| `ControllerDisconnectedScreen` | `TSubclassOf<UTenkaichiControllerDisconnectedScreen>` | 硬引用类 |
| `PlatformRequiresControllerDisconnectScreen` | `FGameplayTagContainer` | 平台 tag 容器 |

**为什么 `EscapeMenuClass` 用软引用、`ControllerDisconnectedScreen` 用硬引用？**
- Esc 菜单可能很重（一整套暂停界面），用软引用延迟加载。
- 断线屏很轻（一个小提示），且要立即弹出，用硬引用。

> 这是 Lyra 的取舍，照抄。

### 5. `TSubclassOf<UTenkaichiControllerDisconnectedScreen>` 只需前置声明

```cpp
class UTenkaichiControllerDisconnectedScreen;  // 前置声明

UPROPERTY(EditDefaultsOnly, Category="Controller Disconnect Menu")
TSubclassOf<UTenkaichiControllerDisconnectedScreen> ControllerDisconnectedScreen;
```

`TSubclassOf<T>` 内部只存 `UClass*`（固定大小），所以**声明成员只需前置声明 `T`**，不需要完整定义。这就是 `.h` 能零挂起的原因。

### 6. 两个 `UFUNCTION(BlueprintNativeEvent)`

```cpp
UFUNCTION(BlueprintNativeEvent, Category="Controller Disconnect Menu")
void DisplayControllerDisconnectedMenu();
```

`BlueprintNativeEvent`：C++ 有默认实现（`_Implementation`），蓝图可以**覆写**。这样策划可以在蓝图里定制断线提示的表现，而 C++ 提供默认逻辑。

### 7. `virtual` 与 `BlueprintNativeEvent` 混用

```cpp
virtual void ProcessControllerDevicesHavingChangedForDisconnectScreen();   // 纯 C++ 虚函数
virtual bool ShouldPlatformDisplayControllerDisconnectScreen() const;      // 纯 C++ 虚函数

UFUNCTION(BlueprintNativeEvent, ...) void DisplayControllerDisconnectedMenu();  // 蓝图可覆写
```

- 前两个是 `virtual`（C++ 子类可覆写，蓝图不可）。
- 后两个是 `BlueprintNativeEvent`（C++ 有默认实现 + 蓝图可覆写）。

> 这种"混合"设计：核心逻辑（检查断线）留给 C++，表现（显示/隐藏菜单）开放给蓝图。
