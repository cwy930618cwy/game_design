#pragma once

#include "CoreMinimal.h"
#include "Abilities/GameplayAbility.h"
#include "InteractionOption.h"

struct FInteractionQuery;

	GENERATED_BODY()

class IInteractionInstigator

	GENERATED_BODY()

	virtual FInteractionOption ChooseBestInteractionOption(const FInteractionQuery& InteractQuery, const TArray<FInteractionOption>& InteractOptions) = 0;
};

## 三、逐段讲解

### 1. 头文件引入（第 5~10 行）

```cpp
#include "CoreMinimal.h"
#include "Abilities/GameplayAbility.h"
#include "InteractionOption.h"
#include "IInteractionInstigator.generated.h"

struct FInteractionQuery;
```

| 行 | 作用 |
|----|------|
| `Abilities/GameplayAbility.h` | 引入引擎的 `FGameplayTag`、`FGameplayEventData` 等基础类型（本文件虽未直接用，但 Lyra 原文件如此保留）。 |
| `InteractionOption.h` | 引入 `FInteractionOption`（方法签名里 `TArray<FInteractionOption>` 需要完整定义）。 |
| `IInteractionInstigator.generated.h` | UHT 生成代码，`UINTERFACE` 必须有。 |
| `struct FInteractionQuery;` | **前置声明**。方法参数里只用引用 `const FInteractionQuery&`，不占内存、不需要完整定义，软引用不阻塞编译（铁律 30）。 |

> 💡 **为什么 `FInteractionOption` 要 `#include`，`FInteractionQuery` 只要前置声明？**
> `TArray<FInteractionOption>` 是**值类型数组**，编译器要算它的大小就得知道 `FInteractionOption` 的完整定义；而 `FInteractionQuery` 只作为引用出现，声明一个"有这么个类型"就够了。

### 2. `UINTERFACE` 外壳（第 13~18 行）

```cpp
UINTERFACE(MinimalAPI, meta = (CannotImplementInterfaceInBlueprint))
class UInteractionInstigator : public UInterface
{
	GENERATED_BODY()
};
```

- **`UINTERFACE` 外壳**：UE 反射系统要求接口有"外壳类"（`UInteractionInstigator`）+ "真实接口"（`IInteractionInstigator`）两层。外壳只负责把接口注册进反射系统，方法全写在真实接口里。
- `MinimalAPI`：不导出整个类符号，轻量（只导出必要接口）。
- `CannotImplementInterfaceInBlueprint`：蓝图不能实现它，只能 C++ 实现——因为方法带 `= 0` 纯虚 + `TArray` 引用参数，蓝图表达不了。

> 💡 **和 P10.2 一模一样的外壳结构**：P10.2 的 `UInteractableTarget` 也长这样。接口类 = `U外壳 + I真实类` 固定两件套，以后写任何接口都照此套路。

### 3. `IInteractionInstigator` 接口体（第 21~31 行）

```cpp
class IInteractionInstigator
{
	GENERATED_BODY()

public:
	// 当收集到的交互选项多于一个时被调用，返回挑中的那一个
	virtual FInteractionOption ChooseBestInteractionOption(const FInteractionQuery& InteractQuery, const TArray<FInteractionOption>& InteractOptions) = 0;
};
```

**单个纯虚方法** `ChooseBestInteractionOption`：
- **纯虚**（`= 0`），谁实现这个接口谁**必须**实现它。
- **输入**：`InteractQuery`（这次是谁、在什么条件下发起交互）+ `InteractOptions`（收集到的所有候选选项，`TArray`）。
- **输出**：从候选中挑出的**一个** `FInteractionOption`。

> 💡 **什么时候被调用**（源码注释第 29 行）：
> "Will be called if there are more than one InteractOptions that need to be decided on."——**只有候选多于一个时**才调用它仲裁。真正调用它的地方在 **P10.9 `ULyraGameplayAbility_Interact`**（交互系统核心技能）里，现在只需知道"有仲裁接口这回事"。
