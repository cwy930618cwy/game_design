## 一、本文件要解决什么

P10 交互系统要回答三个基础问题，正好对应这三个结构体：

1. **"谁在交互、带了什么信息？"** → `FInteractionQuery`（交互查询：一次交互的发起者是谁）。
2. **"交互出来有哪些选项？"** → `FInteractionOption`（交互选项：可交互目标 + 文本 + 技能 + UI）。
3. **"交互按了多久/进行中要广播什么？"** → `FLyraInteractionDurationMessage`（交互时长消息：谁 + 持续多久）。

一句话：**这三个结构体是交互系统的"数据信封"**——查询是"发问的信封"，选项是"回答的信封"，时长消息是"进行中播报的信封"。

## 四、核心概念预读

### 1. `FInteractionQuery`（查询信封）
- 存"谁在发起交互"：`RequestingAvatar`（发起交互的身体）+ `RequestingController`（控制器，可不匹配）。
- 还有一个万能口袋 `OptionalObjectData`：装任意额外数据（`UObject*`）。
- 用途：交互系统问"附近有什么可交互的"，把这个信封递给每个候选者。

### 2. `FInteractionOption`（选项信封）
- 交互系统**最终产出的成果**：一个选项 = 一个可交互目标 + 显示文本 + 触发方式。
- 触发方式二选一：
  - **给发起者授予技能**：`InteractionAbilityToGrant`（给发起者身上的技能）。
  - **直接触发目标身上的技能**：`TargetAbilitySystem` + `TargetInteractionHandle`（目标自己有能力系统时的方案）。
- 带 UI：`InteractionWidgetClass`（展示用什么控件）。
- 重载了 `==` / `!=` / `<`：为了能放进数组、判重、排序。

### 3. `FLyraInteractionDurationMessage`（时长消息信封）
- 配合 GameplayTag `TAG_INTERACTION_DURATION_MESSAGE` 广播"交互进行中"。
- 存 `Instigator`（发起者）+ `Duration`（持续秒数）。
- 用途：**进度条类 UI** 监听这个消息，显示"按住 X 键 3 秒"这类交互进度。
