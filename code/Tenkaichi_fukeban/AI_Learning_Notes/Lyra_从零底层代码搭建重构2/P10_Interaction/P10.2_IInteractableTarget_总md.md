## 一、本文件要解决什么

交互系统的核心机制是**"候选者自我报告"**：

> 交互系统想知道"你附近有什么可交互的"，它不会自己去猜，而是把问题**丢给每个候选者**："你（这个 Actor）能提供哪些交互选项？"

`IInteractableTarget` 就是定义这个"被提问接口"的东西。任何想被交互的物体（门、箱子、NPC、道具）只要实现这个接口，就会被交互系统自动识别为"可交互目标"。

**一句话**：`IInteractableTarget` 是"可交互物体的身份证 + 自我报告协议"。

## 四、核心概念预读

### 1. 为什么用接口（`UINTERFACE`）而不是继承具体类？
- 一个物体可能"又是可交互的、又是可伤害的、又是可装备的"——**一个类只能继承一个基类**，但可以实现**多个接口**。
- `UINTERFACE(MinimalAPI, meta=(CannotImplementInterfaceInBlueprint))`：`MinimalAPI` 表示不导出整个类（轻量）；`CannotImplementInterfaceInBlueprint` 表示蓝图不能实现它，**只能 C++ 实现**（因为接口是纯虚函数）。

### 2. 接口的两个虚方法（候选者必须/可选实现）
```cpp
virtual void GatherInteractionOptions(const FInteractionQuery& InteractQuery, FInteractionOptionBuilder& OptionBuilder) = 0;
virtual void CustomizeInteractionEventData(const FGameplayTag& InteractionEventTag, FGameplayEventData& InOutEventData) { }
```
- `GatherInteractionOptions`：**纯虚函数**（`= 0`），候选者**必须实现**。收到查询后，把自己能提供的选项 `AddInteractionOption` 进收集器。
- `CustomizeInteractionEventData`：**带默认空实现的虚函数**（可选覆盖）。交互系统真正触发交互时，会给候选者一个机会"往事件数据里塞额外信息"（比如门告诉系统"我需要的钥匙 ID"）。

### 3. `FInteractionOptionBuilder`（选项收集器）
- 系统创建它时传入两个东西：**当前被问的候选者**（`Scope`）+ **结果收集表**（`Options`，`TArray<FInteractionOption>&` 引用）。
- 候选者只需调用 `AddInteractionOption`，它会自动把 `Scope`（候选者自己）填进选项的 `InteractableTarget` 字段，再追加到收集表。
- **好处**：候选者不用知道"收集表里有没有我、要不要填我的引用"——收集器全包了。
