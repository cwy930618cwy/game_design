## 一、本文件要解决什么

P10.2 解决了"物体怎么自我报告可交互"。但**候选者可能有好几个**——玩家站在一扇门旁边，地上同时有把剑、一个箱子，交互系统收集到了 3 个选项。那到底该选哪个？让玩家自己选，还是系统自动挑一个？

`IInteractionInstigator` 就是给"发起交互的那一方"一个**仲裁接口**：

> 当收集到的交互选项**多于一个**时，交互系统会问发起者（实现这个接口的物体）："你来挑一个最合适的。"

**一句话**：`IInteractionInstigator` 是"交互仲裁接口"——多选项时由发起者决定选哪个。

## 四、核心概念预读

### 1. 接口的单个纯虚方法
```cpp
virtual FInteractionOption ChooseBestInteractionOption(const FInteractionQuery& InteractQuery, const TArray<FInteractionOption>& InteractOptions) = 0;
```
- **纯虚函数**（`= 0`），实现者必须实现。
- 输入：查询（`InteractQuery`，这次谁发起交互）+ 所有候选（`InteractOptions`）。
- 输出：从候选中挑出的**一个** `FInteractionOption`。

### 2. 什么时候被调用（源码注释的关键信息）
源码注释（第 19~23 行）明确：
> "Will be called if there are more than one InteractOptions that need to be decided on."

**注意**：这个接口是"可选仲裁"——只有**实现它的发起者**才会触发仲裁逻辑。真正调用它的地方在 **P10.9 `ULyraGameplayAbility_Interact`** 里（交互系统核心技能），届时才把多个候选交给它裁决。现在只需知道"有仲裁接口这回事"。

### 3. 和 P10.2 的分工

| 接口 | 谁实现 | 干什么 |
|------|--------|--------|
| `IInteractableTarget`（P10.2） | **被交互的物体**（门/箱子/NPC） | 自我报告"我能怎么被交互" |
| `IInteractionInstigator`（P10.3） | **发起交互的一方**（玩家/技能） | 多选项时挑"选哪个" |
