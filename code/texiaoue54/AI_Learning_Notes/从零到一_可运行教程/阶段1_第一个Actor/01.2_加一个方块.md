## 一、为什么需要组件（场景 + 类比）

01.1 的 `AMyFirstActor` 是**空壳**：它在关卡里存在，但**没有任何可见的东西**。
视口里只能看到一个白色小箭头（那是引擎给「无组件 Actor」画的占位图标）。

要让 Actor「看得见」，必须给它挂**组件（Component）**。

### 1.1 Actor 与 Component 的关系

| 概念 | 是什么 | 类比 |
|---|---|---|
| `AActor` | 场景里的一个**实体**，本身不渲染任何东西 | 一辆**车**（车架） |
| `UActorComponent` | 挂在 Actor 上的**零件**，负责一项能力 | 车的**零件** |
| `USceneComponent` | 有**变换**（位置/旋转/缩放）的组件，能挂子组件 | 有安装位置的零件 |
| `UStaticMeshComponent` | 能渲染一个**静态网格**的场景组件 | **车身外壳** |

继承链：

```
UObject
 └─ UActorComponent          ← 最基础的组件，只有生命周期，没有位置
     └─ USceneComponent      ← 加了 Transform（位置/旋转/缩放），能挂父子
         └─ UPrimitiveComponent   ← 加了「能被渲染 / 能碰撞」
             └─ UMeshComponent    ← 网格类组件的公共基类（材质相关）
                 └─ UStaticMeshComponent   ← 本课用的：静态网格
```

> 🔑 **一句话**：Actor 是**容器**，Component 是**内容**。
> 一个 Actor 可以挂 0 个组件（01.1 的空壳），也可以挂几十个（角色：网格 + 骨骼 + 胶囊碰撞 + 相机臂 + 相机 + 移动组件…）。

### 1.2 为什么必须有「根组件」

UE 的 Actor 有一个特殊成员 `RootComponent`（`AActor.h:881`）：

```cpp
TObjectPtr<USceneComponent> RootComponent;
```

它是**整个 Actor 的变换基准**：
- 你在关卡里拖动 Actor → 实际是移动 `RootComponent`
- 其他组件都挂在 `RootComponent` 下面，跟着一起动
- 没有 `RootComponent` 的 Actor 在关卡里**无法被选中/移动**（只能看到占位箭头）

> 类比：`RootComponent` = 车的**底盘**。所有零件都装在底盘上，底盘一动，整车跟着动。

本课只有一个组件，所以**它自己就是根组件**。

### 2.2 `Source\texiaoue54\01_Actor\MyFirstActor.cpp`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.
// 版权声明，同 .h

#include "MyFirstActor.h"
// IWYU 规则：.cpp 的第一个 include 必须是自己的 .h
// 不写 → 报 C2039 / C2065：AMyFirstActor 未定义

#include "Components/StaticMeshComponent.h"
// UStaticMeshComponent 的完整定义（引擎路径：Engine\Source\Runtime\Engine\Classes\Components\StaticMeshComponent.h）
// 为什么在 .cpp 里 include 而不是 .h 里：
//   · .h 里只用了指针（前置声明够了）
//   · .cpp 里要调 CreateDefaultSubobject<UStaticMeshComponent>() 和 SetStaticMesh()，
//     必须知道类的完整定义（大小、成员函数签名）
// 不写 → 报 C2027: 使用了未定义类型 "UStaticMeshComponent"

#include "UObject/ConstructorHelpers.h"
// ConstructorHelpers::FObjectFinder 的定义所在
// （引擎路径：Engine\Source\Runtime\CoreUObject\Public\UObject\ConstructorHelpers.h）
// 这个工具类专门用于「在构造函数里按路径加载资源」
// 不写 → 报 C2653: "ConstructorHelpers": 不是类或命名空间名

AMyFirstActor::AMyFirstActor()
// 类外定义构造函数：格式是「类名::类名()」
{
	// PrimaryActorTick 是 AActor 的成员（类型 FActorTickFunction），控制「这个 Actor 要不要 Tick」
	// bCanEverTick = false → 引擎永远不会为这个 Actor 调用 Tick()
	// 好处：省掉每帧的函数调用开销
	PrimaryActorTick.bCanEverTick = false;

	// ★ 本课新增：创建组件
	// CreateDefaultSubobject<T>(名字)
	//   · 只能在构造函数里调用（引擎内部有断言检查，别处调用会崩）
	//   · 作用：创建一个「默认子对象」，它会随 Actor 一起被创建、序列化、复制
	//   · 模板参数 <UStaticMeshComponent> ：要创建什么类型的组件
	//   · 参数 TEXT("MeshComponent") ：子对象名，必须唯一
	//     这个名字会出现在：
	//       · 蓝图里的组件列表
	//       · 存档 / 网络复制的标识
	//       · 报错信息里
	//     改名会导致已有蓝图/存档找不到组件 → 所以定下来就别改
	//   · 返回值：指向新组件的指针
	// 不调用 → MeshComponent 是空指针 → 后面 SetStaticMesh 直接崩溃
	MeshComponent = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("MeshComponent"));

	// ★ 本课新增：设为根组件
	// RootComponent 是 AActor 的成员（AActor.h:881），类型 TObjectPtr<USceneComponent>
	// 把 MeshComponent 赋给它 = 「这个组件就是整个 Actor 的变换基准」
	// 为什么可以直接赋值（UStaticMeshComponent* → USceneComponent*）：
	//   继承链 UStaticMeshComponent → UMeshComponent → UPrimitiveComponent → USceneComponent
	//   子类指针可以隐式转成父类指针
	// 不设置 → Actor 没有根组件 → 关卡里无法选中/移动，组件也不会被渲染
	RootComponent = MeshComponent;

	// ★ 本课新增：加载 Cube 网格资源
	// ConstructorHelpers::FObjectFinder<UStaticMesh>
	//   · 专门用于「构造函数里按路径加载资源」的工具
	//   · 内部调用 StaticLoadObject，只在「第一次构造」时真正加载，之后走缓存
	//   · 必须声明为 static：
	//       原因 —— 构造函数会被调用很多次（编辑器加载、蓝图编译、CDO 创建…），
	//               static 保证「只加载一次」，后续直接复用
	//       不写 static → 每次构造都重新加载 → 编辑器启动变慢、内存浪费
	//   · 参数 TEXT("/Engine/BasicShapes/Cube.Cube") ：
	//       格式 = 「包路径.对象名」
	//       /Engine/BasicShapes/Cube  = 包路径（.uasset 文件位置，不含扩展名）
	//       .Cube                     = 包里的对象名（通常与文件名相同）
	//       完整磁盘路径 = D:\ue5\Epic Games\UE_5.4\Engine\Content\BasicShapes\Cube.uasset
	//       ⚠️ /Engine/ 是引擎内容目录的虚拟根，不是磁盘路径
	//   · 为什么用引擎自带 Cube 而不是自己导入：
	//       本课目标是「验证组件能渲染」，不引入额外资产依赖
	static ConstructorHelpers::FObjectFinder<UStaticMesh> CubeAsset(TEXT("/Engine/BasicShapes/Cube.Cube"));

	// Succeeded() ：判断资源是否加载成功（内部就是 return !!Object;）
	// 为什么要判断：
	//   · 路径写错 / 引擎内容被裁剪 → 加载失败
	//   · 不判断直接 SetStaticMesh(CubeAsset.Object) → 传 nullptr → 组件变成空网格（不崩溃但看不见）
	//   · 判断后可以打日志，方便定位问题
	if (CubeAsset.Succeeded())
	{
		// SetStaticMesh(UStaticMesh*) ：给组件指定要渲染的网格
		// （声明在 StaticMeshComponent.h:363）
		// CubeAsset.Object ：FObjectFinder 的成员，类型 TObjectPtr<UStaticMesh>
		// 调用后：组件有了几何数据 → 关卡里就能看到方块
		MeshComponent->SetStaticMesh(CubeAsset.Object);
	}
}

void AMyFirstActor::BeginPlay()
{
	// Super = 父类 AActor 的指针别名（由 GENERATED_BODY() 生成）
	// Super::BeginPlay() 必须第一个调用：
	//   AActor::BeginPlay() 里做了 bHasBegunPlay = true、通知所有组件 BeginPlay、
	//   触发蓝图 BeginPlay 事件等初始化
	// 漏掉 → 组件不初始化、蓝图事件不触发、后续出现各种诡异 bug
	Super::BeginPlay();

	// UE_LOG(日志分类, 级别, 格式串, 参数...)
	//   LogTemp  ：临时日志分类（引擎内置，不用自己声明）
	//   Warning  ：级别。Log / Warning / Error / Fatal，Warning 默认显示
	//   TEXT("...")：把普通字符串转成 UE 的宽字符 TCHAR
	//   %s       ：格式化占位符，对应 const TCHAR*
	//   *GetName()：GetName() 返回 FString，* 取出内部 const TCHAR*
	UE_LOG(LogTemp, Warning, TEXT("AMyFirstActor::BeginPlay 已执行，Actor 名称：%s"), *GetName());
}

void AMyFirstActor::Tick(float DeltaSeconds)
{
	// 调父类 Tick。AActor::Tick 目前是空实现，但保持惯例
	// DeltaSeconds 本课没用到，01.4 会用它做「每秒转 90 度」这类与帧率无关的旋转
```

### 3.1 `.h` 新增的前置声明

```cpp
class UStaticMeshComponent;
```

| 写法 | 干什么 |
|---|---|
| `class UStaticMeshComponent;` | 前置声明 —— 只告诉编译器「有这么个类」，不给完整定义 |

**本段新元素**

**这段在干什么**

| 写法 | 编译速度 | 能用什么 |

> - 只用指针 / 引用（`UStaticMeshComponent* Ptr;`）→ 前置声明就够

### 3.2 `.h` 新增的组件成员

```cpp
UPROPERTY(VisibleAnywhere, Category = "MyFirstActor")
TObjectPtr<UStaticMeshComponent> MeshComponent;
```

| 部分 | 干什么 |
|---|---|
| `UPROPERTY(...)` | 告诉 UHT「这是反射属性」，GC 会追踪它 |
| `VisibleAnywhere` | Details 面板里可见但不可编辑 |
| `Category = "MyFirstActor"` | Details 面板里的分组名 |
| `TObjectPtr<UStaticMeshComponent>` | UE5 的对象指针包装类型 |
| `MeshComponent` | 成员名 |

**本段新元素**
- `UPROPERTY()` —— 标记反射属性，GC 靠它追踪 —— `MyFirstActor.h:38`
- `VisibleAnywhere` —— 编辑器可见不可改 —— `MyFirstActor.h:38`
- `Category` —— Details 面板分组 —— `MyFirstActor.h:38`
- `TObjectPtr<T>` —— UE5 对象指针包装 —— `MyFirstActor.h:39`

**这段在干什么**

| 不写会怎样 | 后果 |
|---|---|
| 不写 `UPROPERTY()` | 组件不被 GC 追踪 → 被回收 → 访问野指针崩溃 |
| 写 `EditAnywhere` 而不是 `VisibleAnywhere` | 用户能在 Details 里把组件换成别的 → 破坏组件层级 |
| 用裸 `UStaticMeshComponent*` | 能编译，但 UE5 官方推荐 `TObjectPtr`（更好的 GC 追踪 + 编辑器内访问追踪） |

> 类比：`UPROPERTY()` = 给这个成员**登记户口**，GC 才知道「这个对象还有人用，别回收」。

> 💡 **`VisibleAnywhere` vs `EditAnywhere` vs `VisibleDefaultsOnly`**：
> | 说明符 | 实例 Details 可见 | 实例可改 | 蓝图默认值可改 |
> |---|---|---|---|
> | `VisibleAnywhere` | ✅ | ❌ | ❌ |
> | `EditAnywhere` | ✅ | ✅ | ✅ |
> | `VisibleDefaultsOnly` | ❌ | ❌ | ✅（仅默认值） |
> | `EditDefaultsOnly` | ❌ | ❌ | ✅ |
>
> 组件指针用 `VisibleAnywhere` 是 UE 惯例（参考引擎里所有 `ACharacter`、`APawn` 的组件声明）。

### 3.4 创建组件

```cpp
MeshComponent = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("MeshComponent"));
```

| 部分 | 干什么 |
|---|---|
| `CreateDefaultSubobject<T>(名字)` | 创建默认子对象，只能在构造函数里调 |
| `<UStaticMeshComponent>` | 要创建什么类型的组件 |
| `TEXT("MeshComponent")` | 子对象名，必须唯一 |

**本段新元素**
- `CreateDefaultSubobject<T>()` —— 创建默认子对象 —— `MyFirstActor.cpp:17`

**这段在干什么**

| 关键点 | 说明 |
|---|---|
| 只能在构造函数里调 | 引擎内部有 `check(IsInConstructor())`，别处调用直接崩 |
| 名字必须唯一 | 同一 Actor 里两个组件同名 → 报错 |
| 名字定下别改 | 蓝图 / 存档 / 网络复制都靠这个名字找组件 |

> 类比：`CreateDefaultSubobject` = **在装配线上装零件**。只能在「出厂」（构造函数）时装，出厂后不能再用这个方法加零件。

> 💡 **`CreateDefaultSubobject` vs `NewObject`**：
> | | `CreateDefaultSubobject` | `NewObject` |
> |---|---|---|
> | 调用位置 | 只能在构造函数 | 任何地方 |
> | 用途 | Actor 的「固有组件」 | 运行时动态创建对象 |
> | 序列化 | 随 Actor 一起存 | 需要自己管理 |
> | 蓝图可见 | ✅ 出现在组件列表 | ❌ 不出现 |

### 3.5 设为根组件

```cpp
RootComponent = MeshComponent;
```

| 部分 | 干什么 |
|---|---|
| `RootComponent` | `AActor` 的成员（`AActor.h:881`），类型 `TObjectPtr<USceneComponent>` |
| `= MeshComponent` | 子类指针隐式转父类指针 |

**本段新元素**
- `RootComponent` —— Actor 的变换基准 —— `AActor.h:881`

**这段在干什么**

| 不设置会怎样 | 后果 |
|---|---|
| 没有 `RootComponent` | 关卡里无法选中 / 移动 Actor，组件不渲染 |
| 有多个组件但没设根 | 组件之间没有父子关系，各自独立 |

> 类比：`RootComponent` = **底盘**。所有零件装在底盘上，底盘一动整车跟着动。

> 💡 **另一种写法 `SetRootComponent()`**：
> ```cpp
> SetRootComponent(MeshComponent);
> ```
> 效果一样，但 `SetRootComponent` 会额外做「解绑旧根组件」的处理。
> 构造函数里直接赋值 `RootComponent = ...` 是引擎自己的写法（见 `StaticMeshActor.cpp:38`）。

### 3.6 加载 Cube 资源

```cpp
static ConstructorHelpers::FObjectFinder<UStaticMesh> CubeAsset(TEXT("/Engine/BasicShapes/Cube.Cube"));

if (CubeAsset.Succeeded())
{
	MeshComponent->SetStaticMesh(CubeAsset.Object);
}
```

| 部分 | 干什么 |
|---|---|
| `static` | 保证只加载一次（构造函数会被调多次） |
| `ConstructorHelpers::FObjectFinder<UStaticMesh>` | 构造函数专用资源加载器 |
| `TEXT("/Engine/BasicShapes/Cube.Cube")` | 包路径 + 对象名 |
| `.Succeeded()` | 判断是否加载成功 |
| `.Object` | 加载到的对象指针 |
| `SetStaticMesh(...)` | 给组件指定网格 |

**本段新元素**
- `ConstructorHelpers` —— 构造函数资源加载工具类 —— `MyFirstActor.cpp:26`
- `FObjectFinder<T>` —— 按路径查找/加载资源 —— `MyFirstActor.cpp:26`
- `Succeeded()` —— 判断加载是否成功 —— `MyFirstActor.cpp:28`
- `Object` —— 加载到的对象 —— `MyFirstActor.cpp:30`
- `SetStaticMesh()` —— 设置组件的网格 —— `MyFirstActor.cpp:30`

**这段在干什么**

| 路径部分 | 含义 |
|---|---|
| `/Engine/` | 引擎内容目录的虚拟根（对应 `Engine\Content\`） |
| `BasicShapes/` | 子目录 |
| `Cube` | 包名（对应 `Cube.uasset`） |
| `.Cube` | 包里的对象名（通常与包名相同） |

> 类比：`FObjectFinder` = **按地址取快递**。`/Engine/BasicShapes/Cube.Cube` = 地址，`Succeeded()` = 确认取到了，`.Object` = 包裹本身。

> ⚠️ **`static` 漏了会怎样**：构造函数每次调用都重新加载资源。
> 编辑器启动时会创建几百个 CDO（Class Default Object），每个都加载一次 Cube → 启动慢几秒 + 内存浪费。
> 引擎会打警告：`FObjectFinder` should be static。

> 💡 **为什么用 `ConstructorHelpers` 而不是 `LoadObject`**：
> | | `ConstructorHelpers::FObjectFinder` | `LoadObject<T>()` |
> |---|---|---|
> | 调用位置 | 只能在构造函数 | 任何地方 |
> | 同步/异步 | 同步 | 同步（有异步版 `LoadObjectAsync`） |
> | 用途 | 硬引用引擎内置资源 | 运行时按需加载 |
> | 打包时 | 资源会被打进包 | 需要手动加 `AlwaysCook` 或软引用 |

> 💡 **`/Engine/BasicShapes/` 里还有哪些**（本课只用 Cube）：
> `Cube` / `Sphere` / `Cylinder` / `Cone` / `Plane` —— 都是 100 单位基准尺寸。

## 七、本课你学到了什么（复盘）

1. **Actor 是容器，Component 是内容** —— 空 Actor 看不见，挂组件才看得见。
2. **组件继承链**：`UObject → UActorComponent → USceneComponent → UPrimitiveComponent → UMeshComponent → UStaticMeshComponent`。
3. **`RootComponent` 是变换基准** —— 没有它，Actor 在关卡里无法选中/移动。
4. **`CreateDefaultSubobject` 只能在构造函数里调** —— 名字定下别改。
5. **`UPROPERTY()` 必须写** —— 否则组件被 GC 回收，运行时崩溃。
6. **`ConstructorHelpers::FObjectFinder` 必须 `static`** —— 保证只加载一次。
7. **资源路径格式**：`/Engine/BasicShapes/Cube.Cube` = 包路径 + `.` + 对象名。
