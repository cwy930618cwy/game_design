# 动起来后人物谱 —— 从"按键"到"死亡重生判胜负"的运行时链路

> **定位**：[02_开演后_玩家与角色人物谱](./02_开演后_玩家与角色人物谱.md) 讲到"✅ 玩家能玩了"。本文接着讲**玩家动起来之后**真正发生的事：按键 → 放技能 → 开火 → 命中 → 扣血 → 死亡 → 重生 → 判胜负，这条**运行时动态链路**里每个"谁"在干什么。
>
> **涉及目录**：`AbilitySystem`（技能/伤害核心）、`Weapons`（武器开火）、`GameModes`（重生/胜负）。
>
> **一句话**：你按一下键，指令顺着"**操作台 → 技能总管 → 技能 → 武器 → 伤害计算 → 血量属性**"传下去，血量归 0 就触发"**死神**"，死神通知"**导演**"安排重生，"**比赛记录员**"全程记分——这就是运行时的一切。

---

## 一、承接：玩家能玩了，然后呢？

```
【前情】玩家附身角色，操作台就绪
        ↓
你按下"开火键" → 发生什么？
        ↓
① 操作台把"开火"翻译成一次"技能激活请求"
② 技能总管审核：够不够条件？能不能放？
③ 开火技能执行：射线检测，打中谁了？
④ 命中 → 对目标施加"伤害效果"
⑤ 目标的血量属性被扣减
⑥ 血量归 0 → 触发"死亡技能"
⑦ 死亡技能通知导演 → 导演安排重生
⑧ 比赛记录员更新比分，广播给所有人
```

> **本文主角**：这条链上的 8 个"运行时专班"角色。

---

## 二、核心：一条"指令下传链"（先看懂这个）★

玩家的一个操作，是**层层下传**的。以"开火"为例：

```
🎮 操作台(HeroComponent)
   "玩家按了开火键" 
        ↓ 转交
🧠 技能总管(ASC)
   "审核：能放吗？" 
        ↓ 批准
⚡ 开火技能(RangedWeaponAbility)
   "射线检测：打中谁？" 
        ↓ 命中
💣 武器实例(WeaponInstance)
   "提供子弹数据" 
        ↓
💥 伤害效果(GameplayEffect + DamageExecution)
   "算出扣多少血" 
        ↓
📉 血量属性(HealthSet)
   "扣血：100 → 60" 
        ↓ (若归 0)
💀 死神(DeathAbility)
   "他死了，走死亡流程"
```

> **关键认知**：Lyra 里**"万物皆技能"**。开火、跳跃、死亡、换弹……全是 `GameplayAbility`。技能总管（ASC）是所有技能的"总闸"。

## 三、人物名单（运行时 8 个专班角色）

### 🧠 22. 技能总管 —— `ULyraAbilitySystemComponent`（ASC）

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraAbilitySystemComponent`（AbilitySystem 目录） |
| **职务** | 所有技能的**总闸/审核官** |
| **口头禅** | "想放技能？先过我这一关：条件够不够、有没有被禁、会不会冲突。" |

**他是干嘛的**：
- 挂在**记分牌（PlayerState）**上的技能中枢（呼应上一篇"ASC 在 PlayerState 上"）。
- 管所有技能的**激活/取消/结束**：
  - `AbilityInputTagPressed` / `AbilityInputTagReleased` → 接收"按键按下/抬起"（操作台转交来的）。
  - `ProcessAbilityInput` → 每帧处理输入，决定激活哪些技能。
  - `IsActivationGroupBlocked` → 判断"这个技能现在能不能放"（比如正在放别的技能，被互斥挡住了）。
- **管技能的"激活组"互斥**（`ELyraAbilityActivationGroup`）：
  - `Independent`（独立）/ `Exclusive_Replaceable`（互相顶替）/ `Exclusive_Blocking`（占着不让别人放）。
- `NotifyAbilityActivated` / `NotifyAbilityFailed` → 技能激活成功/失败的回调。

> **记忆点**：`ASC` = 技能总闸。所有技能都要经它审核、激活、互斥管理。**它是运行时最忙的角色**——每次按键、每次放技能都找它。

---

### ⚡ 23. 技能本身 —— `ULyraGameplayAbility`（含开火/跳跃/死亡...）

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraGameplayAbility` 及其子类（AbilitySystem/Abilities 目录） |
| **职务** | 一个个具体的"技能" |
| **口头禅** | "我是技能。开火、跳跃、死亡……都是我的同类。" |

**它是干嘛的**：
- Lyra 里**所有行为都是技能**，都继承自 `ULyraGameplayAbility`：
  - `LyraGameplayAbility_RangedWeapon` → **开火技能**（远程武器）。
  - `LyraGameplayAbility_Jump` → 跳跃技能。
  - `LyraGameplayAbility_Death` → **死亡技能**（见角色 27）。
  - `LyraGameplayAbility_Reset` → 重置技能。
- 每个技能有**激活策略**（`ELyraAbilityActivationPolicy`）：
  - `OnInputTriggered`（按键触发一次）/ `WhileInputActive`（按住持续）/ `OnSpawn`（生成时自动）。
- 生命周期：`CanActivateAbility`（能不能放）→ `ActivateAbility`（执行）→ `EndAbility`（结束）。
- 有**代价**（`AdditionalCosts`，放技能要耗资源）、**失败处理**（`FailureTagToUserFacingMessages`，放不出来给提示）。

> **记忆点**：`GameplayAbility` = 一个具体技能。"万物皆技能"——开火、跳、死、换弹都是它。技能总管激活它，它执行自己的逻辑。

---

### 🎯 24. 武器实例 —— `ULyraRangedWeaponInstance` / `ULyraWeaponInstance`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraRangedWeaponInstance`（Weapons 目录） |
| **职务** | 武器的**数据载体**（这把枪的属性） |
| **口头禅** | "我装着这把枪的弹容量、伤害、射程数据，开火时给技能用。" |

**它是干嘛的**：
- 一把武器的**数据实体**——弹容量、射速、伤害值、射程都在这。
- 开火技能（`RangedWeaponAbility`）通过 `GetWeaponInstance()` 拿到它，读武器数据。
- 开火技能做的事（看头文件）：
  - `WeaponTrace` / `DoSingleBulletTrace` → **射线检测**：从枪口朝准星打一条射线，看碰到谁。
  - `TraceBulletsInCartridge` → 一次打出整梭子子弹的射线。
  - `PerformLocalTargeting` → 本地算命中目标。
- 命中后，把"打中了谁"打包成**目标数据**（`OnTargetDataReadyCallback`）。

> **记忆点**：`WeaponInstance` = 武器数据 + 射线检测。开火技能用它算"子弹飞出去碰到谁"。它是"枪"，不是"开枪的动作"（动作是技能）。

---

### 💥 25. 伤害效果 —— `GameplayEffect` + `ULyraDamageExecution`

| 项 | 内容 |
|----|------|
| **技术对应** | `GameplayEffect`（引擎）+ `ULyraDamageExecution`（AbilitySystem/Executions） |
| **职务** | 把"打中"变成"扣多少血"的**伤害计算器** |
| **口头禅** | "打中了？我算算该扣多少血——考虑护甲、抗性、暴击。" |

**它是干嘛的**：
- **GameplayEffect（GE）** = GAS 里"改变属性"的标准载体。伤害、治疗都是 GE。
- `ULyraDamageExecution` → **伤害的自定义计算逻辑**（Execution 是 GE 里最复杂的一种，能写公式）。
- 开火技能命中后 → 对目标施加一个"伤害 GE" → GE 跑 `DamageExecution` 算出最终扣血量。
- 呼应最早那篇：`LyraGameData` 里存的就是**伤害/治疗 GE 的软引用**——一个 GE 复用多种数值场景（SetByCaller）。

> **记忆点**：`GameplayEffect` = 改变属性的载体；`DamageExecution` = 伤害计算公式。"命中"必须通过 GE 才能扣血——这是 GAS 的铁律。

---

### 📉 26. 血量属性 —— `ULyraHealthSet`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraHealthSet`（AbilitySystem/Attributes 目录） |
| **职务** | 管血量/护盾/抗性的**属性表** |
| **口头禅** | "血量 100 → 60。掉光了？我喊一声'没血了'。" |

**它是干嘛的**：
- 一张**属性表**（`AttributeSet`），存：`Health`（当前血）、`MaxHealth`（上限）、`Healing`（治疗中）、`Damage`（伤害中）。
- 关键设计（看头文件注释）：
  - `Damage` 是"进来的伤害"，**直接映射成 -Health**。
  - `Healing` 是"进来的治疗"，**直接映射成 +Health**。
  - `Health` 被 `HideFromModifiers` 保护——**只有 Execution 能改它**，普通 GE 不能随便改（防作弊/防乱改）。
- **血量归 0 的侦测**：`OnOutOfHealth` 委托——血量到 0 时广播"这人没血了"。
- `PostGameplayEffectExecute` → GE 执行后，它检查血量是否归 0。

> **记忆点**：`HealthSet` = 血量属性表。伤害 GE 扣这里的血，归 0 时它广播 `OnOutOfHealth`——**死亡链路的起点**。

---

### 💀 27. 死神 —— `ULyraGameplayAbility_Death`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraGameplayAbility_Death`（AbilitySystem/Abilities 目录） |
| **职务** | 专门处理死亡的**死神技能** |
| **口头禅** | "血量归 0 了？接下来交给我，走死亡流程。" |

**它是干嘛的**：
- 一个**特殊的技能**，专门处理死亡。
- **自动触发**（头文件注释）：通过 `"GameplayEvent.Death"` 触发标签自动激活——血量归 0 时，系统发这个事件，死神技能被唤醒。
- 干两件事：
  - `StartDeath` → 开始死亡流程（关碰撞、关移动，见上一篇随队医生 `HealthComponent`）。
  - `FinishDeath` → 结束死亡（脱离控制器、销毁角色）。
- `bAutoStartDeath` → 可配"激活就自动开始死亡"。

> **记忆点**：`DeathAbility` = 死神。血量归 0 → 触发"GameplayEvent.Death" → 死神技能激活 → StartDeath/FinishDeath。**死亡也是一个技能**——体现"万物皆技能"。

---

### 🏁 28. 比赛记录员 —— `ALyraGameState`

| 项 | 内容 |
|----|------|
| **技术对应** | `ALyraGameState`（GameModes 目录） |
| **职务** | 记录**整场比赛**的状态 + 广播消息 |
| **口头禅** | "谁击杀了谁、现在比分多少、比赛还剩多久，全记我这儿。" |

**它是干嘛的**：
- **一局比赛的"全局记录"**——区别于 PlayerState（记单个玩家）：GameState 记**整场**。
- 管所有玩家状态（`AddPlayerState` / `RemovePlayerState`——谁进场谁退场）。
- **广播消息给所有客户端**：
  - `MulticastMessageToClients` → 大概率收到（可能丢，用于击杀提示等）。
  - `MulticastReliableMessageToClients` → 保证收到（用于不能丢的消息）。
- 挂着 **ExperienceManagerComponent**（场记小流，加载剧本）——GameState 是剧本加载的宿主。
- 还有全局技能库（GameState 自己的 ASC，主要管全场的 GameplayCue 表现）。

> **记忆点**：`GameState` = 比赛记录员（全局）；`PlayerState` = 记分牌（单人）。击杀播报、比分、比赛计时都在 GameState。

---

### 🔄 29. 重生调度员 —— `ALyraGameMode`（重生部分）

| 项 | 内容 |
|----|------|
| **技术对应** | `ALyraGameMode`（GameModes 目录，重生相关方法） |
| **职务** | 安排玩家**死亡后重生**的调度员 |
| **口头禅** | "死了？别急，我下帧给你重新安排个身体和出生点。" |

**他是干嘛的**（重生这条线）：
- 上一篇讲过导演（GameMode）生成玩家，这里是他**重生**的活：
  - `RequestPlayerRestartNextFrame` → **下帧重生**这个玩家（死亡后调用）。
  - `ControllerCanRestart` → 判断"这玩家现在能不能重生"。
  - `ChoosePlayerStart_Implementation` → 挑出生点（**外包给上场口管理员** `PlayerSpawningManagerComponent`）。
  - `FinishRestartPlayer` → 重生完成（重新生成身体、放到出生点）。
  - `SpawnDefaultPawnAtTransform_Implementation` → 在指定位置生成新身体。
- `GetPawnDataForController` → 查这个玩家该用什么身体（读 PawnData 设计稿）。
- `OnExperienceLoaded` → 剧本加载好了，导演才开始干活。

> **记忆点**：`GameMode` 的重生职责 = 死亡后"重新发一个身体"。它挑点（外包）、生成、复位。死亡→重生闭环的最后一环。

## 六、四个关键认知（串起整个 Lyra）

### ① 万物皆技能
开火、跳跃、换弹、死亡、重生……在 Lyra 里**全是 `GameplayAbility`**。技能总管（ASC）统一调度。这是 GAS 的核心思想。

### ② 属性改动必须走 GameplayEffect
血量不能直接改——**必须通过 GE + Execution**。`HealthSet` 里 `Health` 被 `HideFromModifiers` 保护，只有 Execution 能碰。这是防作弊、保证网络同步一致的设计。

### ③ 死亡是一个"事件驱动的技能"
血量归 0 → `OnOutOfHealth` → 发 `GameplayEvent.Death` → 死神技能被**自动激活**。死亡不是某个 if 判断，而是一个**事件触发技能**的优雅流程。

### ④ 死亡→重生是闭环
死神 FinishDeath → 通知导演 → 导演 `RequestPlayerRestartNextFrame` → 挑点 → 生成新身体 → 玩家又能玩。**身体可以换（ASC 在 PlayerState 上，技能数据不丢）**，这就是为什么 ASC 挂在 PlayerState 而不是 Character 上。

## 七、三篇人物谱的完整串联

```
【幕后建造层】（游戏跑起来前）
  🏛️立项书 → 📐施工总工 → 🔧装修队/🎭主演出团 → 📖运营手册
        ↓ 造好开门
【台上演出层】（开演前就位）
  👔葛总管 → 📜剧本 → 📋场记 → 🎪节目团 → 🔌插座 → 📦仓管 → 🎬导演
        ↓ 导演喊开演
【开演后·静态结构】（玩家与角色怎么连）
  🎮观众 → 🎯遥控器 → 🎭演员；🧩装配组长协调；📊记分牌保管🫀技能库
        ↓ 玩家能玩
【动起来后·运行时链路】（本文）
  🎮操作台 → 🧠技能总管 → ⚡技能 → 💣武器 → 💥伤害 → 📉血量
  → 💀死神 → 🔄重生调度员 → 🏁比赛记录员 → 闭环回到"能玩"
```
