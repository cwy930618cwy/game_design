# 05 - 第 4 层：业务基类 — AActor / UActorComponent 等

> **源码位置**：`Engine\Source\Runtime\Engine\Classes\...`
> 
> 这一层是引擎自带的**功能类**，你写代码时最常继承的就是这些。

---

## 一、常见的业务基类

| 基类 | 用途 | 路径 |
|------|------|------|
| `AActor` | 能放进关卡的东西 | `GameFramework/Actor.h` |
| `APawn` | 能被玩家/AI 控制的 Actor | `GameFramework/Pawn.h` |
| `ACharacter` | 带移动组件的角色 | `GameFramework/Character.h` |
| `UActorComponent` | Actor 组件 | `Components/ActorComponent.h` |
| `USceneComponent` | 有 Transform 的组件 | `Components/SceneComponent.h` |
| `UPrimitiveComponent` | 有碰撞/物理的组件 | `Components/PrimitiveComponent.h` |
| `UUserWidget` | UI 控件 | `Blueprint/UserWidget.h` |
| `UGameInstance` | 游戏实例（全局单例） | `Engine/GameInstance.h` |
| `UDataAsset` | 数据资产 | `Engine/DataAsset.h` |

---

## 二、继承关系图

```
UObject
    ├── AActor（能放关卡）
    │       ├── APawn（能被控制）
    │       │     └── ACharacter（带移动组件的角色）
    │       ├── APlayerController（玩家控制器）
    │       ├── AGameModeBase（游戏规则）
    │       └── AGameStateBase（游戏状态）
    │
    ├── UActorComponent（组件基类）
    │       └── USceneComponent（有位置的组件）
    │             └── UPrimitiveComponent（有碰撞的组件）
    │
    ├── UUserWidget（UI）
    └── UDataAsset（数据资产）
```

---

## 三、怎么选？

| 需求 | 继承 | 说明 |
|------|------|------|
| 只是存数据/管理器 | `UObject` | 不能放关卡，纯逻辑类 |
| 想放关卡里 | `AActor` | 能拖进关卡，有位置/旋转 |
| 想做角色（能走跑跳） | `ACharacter` | 自带移动组件和胶囊碰撞 |
| 想做成组件挂在 Actor 上 | `UActorComponent` | 不能独立存在，必须挂载 |
| 做 UI | `UUserWidget` | HUD、菜单、按钮 |
| 存配置数据 | `UDataAsset` | 编辑器里配数据用 |

## 四、AActor vs APawn vs ACharacter

### AActor（最基础）

```cpp
// 能放进关卡，但什么都不会做
UCLASS()
class AMyBox : public AActor {
    // 只是个"东西"，没有移动能力
};
```

### APawn（能被控制）

```cpp
// 能被玩家或 AI 控制
UCLASS()
class AMyPawn : public APawn {
    // 可以接收输入，但没有移动组件
};
```

### ACharacter（角色）

```cpp
// 带移动组件的角色，能走跑跳
UCLASS()
class AMyCharacter : public ACharacter {
    // 自带 CharacterMovementComponent
    // 自带 CapsuleComponent（胶囊碰撞）
    // 自带 SkeletalMeshComponent（骨骼网格）
};
```

---

## 五、组件化设计（重要！）

UE 鼓励**组件化**，把功能拆成一个个 Component：

```
ACharacter（角色）
    ├── CapsuleComponent（胶囊碰撞）
    ├── SkeletalMeshComponent（骨骼网格）
    ├── CharacterMovementComponent（移动逻辑）
    ├── AbilitySystemComponent（GAS 技能系统）← 挂在这里
    └── HealthComponent（自定义血量组件）← 挂在这里
```

**好处**：
- 功能解耦，好维护
- 可以动态添加/移除组件
- Lyra 就是这种设计的典范

---

## 六、一句话总结

> **业务基类 = 引擎自带的"户型房"**
> 
> - `AActor` — 能放关卡的基础款
> - `ACharacter` — 带移动能力的角色款
> - `UActorComponent` — 可挂载的组件款
> 
> 你写的类从这里开始继承，就能获得对应的能力。
