# 01 - 第 0 层：C++ 语言本身

> 这是最底层，不是 UE 的，是 C++ 标准提供的。
> 
> 理解这一层，你才能明白 **UE 为什么要做后面那些事**。

---

## 一、C++ 提供了什么？

### 1. 内存分配/释放

```cpp
// C 风格
void* ptr = malloc(sizeof(MyClass));   // 申请内存
free(ptr);                              // 释放内存

// C++ 风格（更常用）
MyClass* p = new MyClass();             // 申请内存 + 构造对象
delete p;                               // 析构对象 + 释放内存
```

### 2. 构造函数 / 析构函数

```cpp
class MyClass {
public:
    MyClass() { }      // 构造函数：创建对象时自动调用
    ~MyClass() { }     // 析构函数：销毁对象时自动调用
};

// 使用
{
    MyClass obj;       // ← 这里自动调用构造函数
}                      // ← 离开作用域，自动调用析构函数
```

### 3. 基础类型

```cpp
int a = 1;
float b = 2.5f;
char* str = "hello";
bool flag = true;
```

## 二、普通 C++ 类的问题

**编译完就没人认识它了**：

```cpp
class Player {
    int Health;
};

Player p;
p.Health = 100;   // ✅ 编译时写死，只能这样访问
// p.("Health") = 100;  // ❌ 运行时不行！编译器不认识字符串 "Health"
```

**特点**：
- 变量名只是给程序员看的
- 编译完成后，名字消失，只剩内存地址
- 无法通过字符串动态访问变量/函数

---

## 三、UE 想要什么？

UE 想要的是**运行时也能**：

| 需求 | 说明 |
|------|------|
| 通过字符串找到变量 | 序列化时需要知道"有哪些属性要保存" |
| 通过字符串调用函数 | 蓝图调用 C++ 函数时需要 |
| 动态创建对象 | 根据配置加载不同类型的对象 |
| 自动管理内存 | GC 需要知道对象的大小和生命周期 |

**怎么办？** → 需要**反射系统** → 这就是 UE 从第 1 层开始做的事。

---

## 四、关键概念：operator new

当你写 `new MyClass()` 时，实际发生了两件事：

```cpp
// 第 1 步：分配内存（调用 operator new）
void* memory = operator new(sizeof(MyClass));

// 第 2 步：在内存上构造对象（调用构造函数）
MyClass* p = new (memory) MyClass();
```

**`operator new` 是什么？**
- 它是一个**函数**，负责分配内存
- C++ 允许你重写它（运算符重载）
- UE 就是靠重写它来实现统一内存管理

---

## 五、类比理解

| 场景 | 比喻 |
|------|------|
| 普通 C++ 类 | 你自己写的笔记本，只有你自己看得懂 |
| UE 想要的 | 把笔记本交给秘书登记，所有人都能查阅 |

**第 0 层的问题**：笔记本内容很好，但没人帮你登记，外人看不懂。

**UE 的解决方案**：从第 1 层开始，给每个类加上"登记信息"，让引擎能认识它。

---

## 六、一句话总结

> **C++ 语言提供了基础能力（内存、构造/析构），但缺少"运行时自我描述"的能力。**
> 
> UE 的反射系统就是为了弥补这个缺陷而设计的。
