# 19 — 教学铁律：能用代码/配置完成的，不要教用户动编辑器

> **定位**：本文件规定"教学操作步骤"的选型偏好。新对话开始教学前，除 00~18 外，**必须读本文件**。
>
> **一句话**：凡是能用**写代码 / 改配置文件**完成的操作，**禁止叫用户去编辑器里点半天**。编辑器找菜单、卡界面、翻面板浪费时间——能写进文件的东西，直接写文件。

## 一、这条铁律怎么来的（真实教训，2026-09-24）

教 P02（GameMode + Possess）第 4 步"让关卡用上 GameMode"时，我给的方案是：

> 方式 A：`Edit → Project Settings → Maps & Modes → Default GameMode`，把默认 GameMode 设成 `TenkaichiGameMode`。

用户当场指出：**"这个可以写在代码配置里的""代码就能完成的，不要叫我动编辑器，编辑器找半天还卡"**，并强调前提——**"前提是 Lyra 也是这么写的，不是你编的"**。

我核实后发现用户完全正确：**Lyra 根本不在编辑器里点，而是直接写在 `Config/DefaultEngine.ini` 里**：

```65:68:e:\ue5\LyraStarterGame5.6\LyraStarterGame\Config\DefaultEngine.ini
[/Script/EngineSettings.GameMapsSettings]
GlobalDefaultGameMode=/Game/B_LyraGameMode.B_LyraGameMode_C
GameInstanceClass=/Game/B_LyraGameInstance.B_LyraGameInstance_C
GameDefaultMap=/Game/System/FrontEnd/Maps/L_LyraFrontEnd.L_LyraFrontEnd
```

**根因复盘**：
- 我图省事，给了"编辑器点选"这种可视化方案，没去想"这能不能用配置写死"。
- 项目设置面板本质就是编辑 `DefaultEngine.ini`——面板能点的，ini 里都有对应字段。我舍近求远。
- 更关键：用户要的是"**Lyra 真实怎么做**"，不是我自己想的"教学简化版"。Lyra 用配置文件，我就该教配置文件。

## 二、核心规则

**教学时，操作步骤的选型优先级：写代码 / 改配置 ＞ 动编辑器。**

1. **能写进文件的，直接写文件**：项目设置、关卡设置、输入映射、很多"看起来只能点面板"的东西，底层都是一个 ini / 一个资产文件。能定位到文件，就写文件。
2. **给配置方案时，必须附 Lyra/引擎真实证据**：不能凭空说"可以写配置"。要去 `LyraStarterGame5.6` / `UE_5.6` 里查到 Lyra/引擎确实这么用，再教（遵守 00/01 铁律）。
3. **编辑器方式只作为"不得已的备选"**：确实无法用文本配置表达的（如摆放 Actor 位置、拖拽蓝图节点连线），才让用户动编辑器；且要说清"为什么这个只能手动"。

## 四、C++ 类 vs 蓝图在配置里的路径格式（关键，别写错）

写 `GlobalDefaultGameMode` 这类引用资产的配置时，路径格式因类型而异（本次真实踩到，务必记牢）：

| 类型 | 路径格式 | 例子 |
|------|---------|------|
| **纯 C++ 类** | `/Script/模块名.类名`（**不带 `_C`**） | `/Script/Tenkaichi.TenkaichiGameMode` |
| **蓝图资产** | `/Game/.../资产名.资产名_C`（**带 `_C`**） | `/Game/B_LyraGameMode.B_LyraGameMode_C` |

- 我们的 `ATenkaichiGameMode` 是纯 C++ 类 → 用 `/Script/Tenkaichi.TenkaichiGameMode`。
- Lyra 的 `B_LyraGameMode` 是蓝图 → 用 `/Game/B_LyraGameMode.B_LyraGameMode_C`。
- 规律：`/Script/` 走 C++（无 `_C`），`/Game/` 走蓝图（有 `_C`）。写错会加载不到，PIE 后没人。

## 五、执行要求

1. **主动**：给操作步骤前，先想"这能不能写文件搞定"，能就别提编辑器。
2. **真实**：配置方案必须附 Lyra/引擎源码证据（引用到具体文件行号），证明"Lyra 也这么写"，不是编的。
3. **只教不写（服从 01 号根本铁律）**：配置/代码**由用户自己动手写**——我把"改哪个文件、加哪一行、为什么"教清楚，并贴出 Lyra 真实配置作示例，但**不擅自替用户编辑工程里的文件**（`DefaultEngine.ini` 等也一样，我上一版擅自帮用户改了 ini 是错的，已回退）。打印日志是唯一例外（我写我删）。
4. **同步记忆**：本条长期稳定，已同步进 `MEMORY.md`。

## 六、一句话结论

**能用代码/配置完成的，绝不教用户动编辑器（编辑器找半天还卡）；且配置方案必须先查到 Lyra/引擎真实用法再教，不能自己编。典型：指定默认 GameMode 写 `Config/DefaultEngine.ini` 的 `GlobalDefaultGameMode`——Lyra 就是这么干的（`DefaultEngine.ini` 第 66 行），C++ 类路径 `/Script/模块.类`（不带 `_C`），蓝图 `/Game/.../名.名_C`（带 `_C`）。**
