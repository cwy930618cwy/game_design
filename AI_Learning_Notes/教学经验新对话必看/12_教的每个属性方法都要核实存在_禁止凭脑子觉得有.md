# 12 — 教学铁律：教的每个属性/方法/宏都要核实"真实存在"，禁止凭脑子觉得有

> **定位**：本文件是 [11_给教学代码前必须做两个核对](./11_给教学代码前必须做两个核对.md) 的**前置强化版**——把核对范围从"`.h`↔`.cpp` 成对"扩大到"**每一个被教到的符号是否真实存在**"。新对话开始教学前，除 00~11 外，**必须读本文件**。
>
> **一句话**：教学里讲到的**每一个属性、方法、宏、函数、类**，教之前都要到 Lyra 源码或引擎源码里核实"它真的存在、真的这么用"，**禁止凭脑子觉得"应该有这个"**。

---

## 一、这条铁律怎么来的（真实教训，2026-09-22）

同一天连续暴露"凭脑子写"的毛病：
1. 漏了 `.h` 里两个函数声明（[11](./11_给教学代码前必须做两个核对.md) 已记录）——因为凭脑子想"基类给个最简骨架"，没照抄 Lyra。
2. 你进一步指出：**不只是 `.h`/`.cpp` 核对，教学里教的每个属性、每个方法，都要核对是否真实存在**，不能凭脑子觉得"应该有这个函数/这个宏"。

**根因**：AI 有"用常识/记忆补全"的倾向——脑子里觉得"GAS 应该有个 XX 函数""这里应该能调 YY"，就写进教学，**没去源码里确认它到底存不存在、签名是什么**。一旦记忆有偏差，就会教一个**根本不存在或用法错误**的东西，你照着写必然编译报错。

---

## 二、核心规则：教每个符号前，先核实"真实存在"

**教学里凡是要你写、要你用的每一个符号（类 / 属性 / 方法 / 宏 / 函数 / 头文件 / 关键字），教之前都必须到源码里核实：**

| 要核实的对象 | 去哪核 | 核什么 |
|-------------|--------|--------|
| 某个**类**（如 `UAttributeSet`） | 引擎源码 `UE_5.6` | 这个类真的存在吗？在哪个头文件？ |
| 某个**方法**（如 `GetOwningAbilitySystemComponent`） | Lyra / 引擎源码 | 这方法真有吗？签名（参数/返回值/const）是什么？ |
| 某个**属性/宏**（如 `ATTRIBUTE_ACCESSORS`、`GAMEPLAYATTRIBUTE_REPNOTIFY`） | Lyra 源码 | 宏真这么定义的吗？展开成什么？ |
| 某个**include**（如 `AttributeSet.h`） | 引擎源码 | 这个头文件真提供我要的东西吗？ |
| 某个**用法/流程**（如 `InitHealth` 绕过 GE） | Lyra 真实调用处 | Lyra 真是这么用的吗？ |

**核实动作 = 用工具（search_content / read_file / lsp）到 `LyraStarterGame5.6` 或 `UE_5.6` 里搜到、读到、看到它真实存在，再教。**

> 判断标准：**我教你的每一行代码里的符号，我都能指出"它在哪个真实文件第几行"。** 指不出来 = 没核实 = 不许教。

---

## 三、"凭脑子觉得有"的高危场景（重点防范）

| 高危念头 | 正确做法 |
|---------|---------|
| "GAS 应该有个获取 ASC 的方法" | 去源码搜，确认方法名真是 `GetOwningAbilitySystemComponent` |
| "这个宏应该能生成 getter" | 去 Lyra 读宏定义，看它真实展开成什么 |
| "属性变化应该能回调" | 去 Lyra 看 `OnRep_Xxx` / `PostAttributeChange` 真实怎么写的 |
| "这个类应该在某头文件里" | 去引擎源码确认头文件路径，别猜 |
| "我记得这函数叫这个名字" | 记忆不可靠，去搜真实名字 |

> ⚠️ **记忆/常识会骗人**：AI 的训练数据里有大量 UE 知识，但**版本差异、项目定制、记忆偏差**都可能导致"我觉得有"其实是错的或用法不对。**一律以源码为准。**

---

## 四、三个核对的完整链条（09→11→12）

教一段代码，从头到尾要过这三关：

1. **核对③（本文件，最前置）**：每个符号**真实存在**吗？（去源码搜到、读到）
2. **核对①（[11](./11_给教学代码前必须做两个核对.md)）**：对照 Lyra 源码，我给的代码**没缺行/漏函数**吗？
3. **核对②（[11](./11_给教学代码前必须做两个核对.md)）**：`.h` 声明 ↔ `.cpp` 实现**成对**吗？

> 顺序：**先确认"每个东西真实存在"（12）→ 再确认"照 Lyra 没漏"（11①）→ 再确认".h/.cpp 成对"（11②）**。

---

## 五、对照表（做什么 / 不做什么）

| 场景 | ✅ 我做 | ❌ 我不做 |
|------|--------|----------|
| 教某方法/属性/宏 | 先到源码搜到、读到，确认存在+签名 | 凭脑子"应该有这个"就教 |
| 记不清签名 | 去源码查真实签名 | 凭记忆写个"差不多"的 |
| 用某 include | 确认它真提供我要的东西 | 想当然引一个头文件 |
| 你问"这存在吗" | 给出真实文件+行号证据 | 含糊说"应该有" |

---

## 六、执行要求（每次教学自检清单）

教一段代码前，逐条打勾：

- [ ] **核对③**：这段代码里每个类/方法/宏/属性/include，我都到 `LyraStarterGame5.6` 或 `UE_5.6` 搜到、读到了吗？能指出"在哪个文件第几行"吗？
- [ ] 有没有任何一个符号是"我凭脑子觉得有"、没实际查过的？（有 → 立刻查，查不到就不教）
- [ ] 签名（参数/返回值/const/宏展开）和源码一致吗？
- [ ] 之后再做 [11](./11_给教学代码前必须做两个核对.md) 的核对①②。
