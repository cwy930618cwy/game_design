# 11 — 什么时候必须重写？什么时候不用重写？（C++ 彻底讲清）

> **定位**：彻底讲清 C++ 里"**为什么有的方法必须重写，有的不用重写**"。这个困惑的根源是——**由"父类怎么声明这个方法"决定**，不是看心情。
>
> **一句话**：**父类声明方法时有三种情况**——纯虚（必须重写）、普通虚（可选重写）、普通（不能/不用重写）。搞清楚"父类怎么写的"，就知道"你要不要写"。

---

## 一、核心：父类声明方法的方式，决定了"你要不要重写"

C++ 里，父类的方法分**三种**，对应子类的三种义务：

| 父类怎么写 | 子类要不要重写 | 例子 |
|-----------|:---:|------|
| `virtual ... = 0`（纯虚） | **必须重写**（不写编译报错） | 接口方法 |
| `virtual ... { 实现 }`（普通虚） | **可选**（不写用父的默认） | 有默认实现 |
| `void ... { 实现 }`（普通） | **不用/不能重写**（就父的） | 普通函数 |

**记住一句话**：
- **父类写了 `= 0`** → 你必须写（不写报错）
- **父类写了 `virtual`（有实现）** → 你可写可不写（不写用默认）
- **父类没写 `virtual`** → 你不用写（写了也不是重写）

---

## 二、第一种：`= 0`（纯虚函数）→ 必须重写

**父类声明"这个方法我不管，你子类必须实现"**。

```cpp
class ISpeakable {
public:
    virtual void speak() const = 0;   // = 0：纯虚，我没实现，你必须实现
};

class Dog : public ISpeakable {
public:
    void speak() const override { cout << "汪汪"; }   // ★ 必须写！不写编译报错
};

// ❌ 不写 speak() 会编译报错："未实现的纯虚函数"
class Cat : public ISpeakable { };   // 编译错！没实现 speak()
```

**什么时候用 `= 0`**：
- 接口（纯接口）的方法：**不想提供默认实现**，强制每个子类自己写
- 例：`ISpeakable::speak()` —— 狗叫猫叫完全不同，父类提供不了统一实现

**记忆**：**`= 0` = "强制"**，父类说"这个方法你子类必须自己写"。

---

## 三、第二种：`virtual`（有默认实现）→ 可选重写

**父类声明"我给个默认实现，你想用就用，想改就改"**。

```cpp
class IGenericTeamAgentInterface {
public:
    virtual void SetGenericTeamId(FGenericTeamId id) { /* 默认逻辑 */ }   // 有实现
    virtual FGenericTeamId GetGenericTeamId() const { return FGenericTeamId::NoTeam; }  // 有实现
};

// 子类 A：不重写，直接用父的默认实现
class A : public IGenericTeamAgentInterface { };   // 用默认，没问题

// 子类 B：重写，改成自己的
class B : public IGenericTeamAgentInterface {
public:
    void SetGenericTeamId(FGenericTeamId id) override { /* 自己的逻辑 */ }
};
```

**什么时候用 `virtual`（有默认实现）**：
- 想给**通用默认行为**，但允许子类**按需改**
- 例：`IGenericTeamAgentInterface::SetGenericTeamId` —— 默认是"设队伍"，大部分子类能用，个别要改

**记忆**：**`virtual`（有实现） = "可选"**，父类说"我给你个答案，你想改就改，不想改用我的"。

---

## 四、第三种：普通函数（没 `virtual`）→ 不用重写

**父类声明"这个方法就是这样的，子类别改"**（不是虚函数）。

```cpp
class Animal {
public:
    void eat() { cout << "吃东西"; }   // 没 virtual，普通函数
};

class Dog : public Animal { };   // 不用管 eat()，用父的
```

**注意**：子类也可以写一个同名函数，但**那不是"重写"**，是"隐藏"（隐藏父的），和多态无关：

```cpp
class Dog : public Animal {
public:
    void eat() { cout << "吃狗粮"; }   // 这叫"隐藏"，不是"重写"（没 virtual）
};
// 通过 Animal* 调用 eat() 时，还是调 Animal 的（因为没 virtual）
```

**记忆**：**普通函数 = 不用重写**（写了也不是多态重写）。

## 五、场景速查表（判断"要不要重写"就看这个）

| 父类声明 | 要不要重写 | 不重写会怎样 |
|---------|:---:|-----------|
| `virtual void f() = 0` | **必须** | 编译报错 |
| `virtual void f() { ... }` | **可选** | 用父的默认实现 |
| `void f() { ... }` | **不用** | 就父的实现 |

**判断步骤**：
```
看父类怎么声明方法：
  有 = 0 ？ → 必须重写
  有 virtual ？ → 可选重写（不写用默认）
  都没有 → 不用重写
```

## 六、回到你困惑的 Lyra 例子（对照实战）

```cpp
// 第 1 层：引擎接口（有默认实现 = 可选重写）
class IGenericTeamAgentInterface {
public:
    virtual void SetGenericTeamId(FGenericTeamId) { /* 默认 */ }      // 可选重写
    virtual FGenericTeamId GetGenericTeamId() const { return NoTeam; } // 可选重写
};

// 第 2 层：Lyra 接口
class ILyraTeamAgentInterface : public IGenericTeamAgentInterface {
public:
    virtual FOnLyraTeamIndexChangedDelegate* GetOnTeamIndexChangedDelegate() { return nullptr; }
    // ↑ 这是【新增方法】，不是重写父的
};

// 第 3 层：实际角色类
class ALyraCharacter : public ... , public ILyraTeamAgentInterface {
public:
    // GetGenericTeamId：父有默认实现，【可选】——Lyra 选择重写（返回真队伍）
    FGenericTeamId GetGenericTeamId() const override { return MyTeamID; }

    // GetOnTeamIndexChangedDelegate：接口新增的，【必须】实现（因为要真正返回委托）
    FOnLyraTeamIndexChangedDelegate* GetOnTeamIndexChangedDelegate() override { return &OnTeamChangedDelegate; }
};
```

**对照理解**：
- `GetGenericTeamId`（父有默认）→ **可选**，Lyra 为了返回真队伍，重写了
- `GetOnTeamIndexChangedDelegate`（接口新增，`= 0` 或虚函数）→ 实际类**要实现**，因为要真正返回委托

## 七、终极记忆口诀

```
父类怎么写 → 你要不要写：
  = 0（纯虚）      → 必须写（强制）
  virtual（有实现）→ 可写可不写（用默认）
  普通函数         → 不用写（就父的）

一句话：
  = 0 是"你必须做"
  virtual 是"你可以做"
  普通是"你不需要做"
```

---

## 八、总结

**"必须重写"还是"不用重写"，完全由父类声明方式决定**：

1. **父类 `= 0`（纯虚）** → **必须重写**（不写编译报错）。因为父类"没提供实现，要你实现"。
2. **父类 `virtual`（有实现）** → **可选重写**（不写用默认）。因为父类"给了默认，你按需改"。
3. **父类普通函数** → **不用重写**。因为父类"就这个实现"。

**你困惑的根源**：之前看 `= 0`（必须重写）和 `virtual` 有默认（不用重写）混在一起了。**记住"看父类怎么声明"**，就不乱了。

**一句话**：**`= 0` 强制你重写，`virtual` 允许你重写，普通函数不用你重写。看父类怎么写，就知道你要不要写。**
