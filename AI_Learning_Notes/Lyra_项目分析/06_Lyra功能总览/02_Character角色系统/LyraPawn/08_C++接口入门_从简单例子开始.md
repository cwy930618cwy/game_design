# C++ 接口入门 —— 从一个能跑的简单例子开始

> **定位**：抛开 UE，用最纯粹的 C++ 写一个能编译运行的例子，手把手教你理解"接口（Interface）"到底是什么、怎么用。
>
> **关联**：
> - [06_接口Interface与类Class的区别](./06_接口Interface与类Class的区别.md) — 概念对比
> - [07_父接口如何提供默认实现](./07_父接口如何提供默认实现_继承与多态.md) — 进阶机制
>
> **一句话**：接口就是"**一张能力清单**"——它只规定"你必须会哪些函数"，具体怎么做由每个类自己决定。

## 一、先看最终效果（运行结果）

```
狗旺财 正在叫：汪汪汪！
猫咪咪 正在叫：喵喵喵！
鸭子唐老鸭 正在叫：嘎嘎嘎！
```

三种完全不同的动物，都能"叫"——但它们叫的方式各不相同。我们用**接口**来统一管理"叫"这个行为。

## 二、完整代码（直接可跑）

```cpp
#include <iostream>
#include <vector>
using namespace std;

// ============================================
// 第 1 步：定义一个接口（Interface）
// ============================================
// 接口 = 一张"能力清单"，只声明函数，不写具体怎么做
class ISpeakable {
public:
    // 纯虚函数：= 0 表示"只有声明，没有实现"
    // 意思：谁想用我，就必须自己把 speak() 写出来
    virtual void speak() const = 0;

    // 析构函数（接口必须有虚析构，保证正确清理）
    virtual ~ISpeakable() {}
};

// ============================================
// 第 2 步：让具体的类"实现"这个接口
// ============================================

// 狗：实现 ISpeakable
class Dog : public ISpeakable {          // ← "继承接口" = "签了这张能力清单"
public:
    string name;
    Dog(string n) : name(n) {}

    // ★ 必须重写 speak()，否则编译报错
    void speak() const override {
        cout << name << " 正在叫：汪汪汪！" << endl;
    }
};

// 猫：实现 ISpeakable
class Cat : public ISpeakable {
public:
    string name;
    Cat(string n) : name(n) {}

    void speak() const override {
        cout << name << " 正在叫：喵喵喵！" << endl;
    }
};

// 鸭子：实现 ISpeakable
class Duck : public ISpeakable {
public:
    string name;
    Duck(string n) : name(n) {}

    void speak() const override {
        cout << name << " 正在叫：嘎嘎嘎！" << endl;
    }
};

// ============================================
// 第 3 步：使用接口（关键！统一处理）
// ============================================
void makeSound(vector<ISpeakable*>& animals) {
    // ★ 注意：这里用的是"接口指针"，不是具体类的指针
    // 不管你是狗是猫是鸭子，只要实现了 ISpeakable，我都能让你"叫"
    for (auto a : animals) {
        a->speak();   // 多态：自动调用每个对象自己的 speak()
    }
}

int main() {
    Dog dog("旺财");
    Cat cat("咪咪");
    Duck duck("唐老鸭");

    // 把不同动物放进同一个"袋子"——因为它们都有 ISpeakable 这个共同身份
    vector<ISpeakable*> zoo = { &dog, &cat, &duck };

    makeSound(zoo);   // 一行代码，统一让它们叫
    return 0;
}



void makeSound(any animals) {
    // ★ 注意：这里用的是"接口指针"，不是具体类的指针
    // 不管你是狗是猫是鸭子，只要实现了 ISpeakable，我都能让你"叫"
    for (auto a : animals) {
        a->speak();   // 多态：自动调用每个对象自己的 speak()
    }
}

int main() {
    Dog dog("旺财");
    Cat cat("咪咪");
    Duck duck("唐老鸭");

    // 把不同动物放进同一个"袋子"——因为它们都有 ISpeakable 这个共同身份
    zoo = [dog, cat, duck ];

    makeSound(zoo);   // 一行代码，统一让它们叫
    return 0;
}


```

## 三、逐段拆解（对照代码理解概念）

### ① 接口定义：`class ISpeakable`

```cpp
class ISpeakable {
public:
    virtual void speak() const = 0;   // 纯虚函数
    virtual ~ISpeakable() {}          // 虚析构函数
};
```

| 要素 | 含义 |
|------|------|
| `virtual ... = 0` | **纯虚函数**：只声明"有 speak 这个能力"，但不规定怎么叫 |
| `= 0` | 告诉编译器："这个函数必须由子类来实现" |
| 接口名 `I` 开头 | 约定俗成，`I` = Interface（不是强制，但好习惯） |

> **类比**：`ISpeakable` 就是一张"会叫"的证书。它只写"持有者必须会叫"，但不管你学的是狗叫还是猫叫。

### ② 实现接口：`class Dog : public ISpeakable`

```cpp
class Dog : public ISpeakable {
    void speak() const override { ... }   // ★ 必须实现，否则编译报错
};
```

- `: public ISpeakable` = "我继承了这张证书" = "我承诺我会 speak"
- `override` = "我在重写父类/接口的函数"（明确告诉编译器：我就是来实现它的）
- **如果 Dog 不写 speak()，编译直接报错**：`"未实现的纯虚函数"`

### ③ 使用接口：`vector<ISpeakable*>`

```cpp
void makeSound(vector<ISpeakable*>& animals) {
    for (auto a : animals) {
        a->speak();   // 多态
    }
}
```

**这是接口的精髓**：`makeSound` 函数**不需要知道**每只是狗还是猫，它只认"你有没有 ISpeakable 这个身份"。只要有，就能叫。

```
没有接口的话，你得这样写：
  if (是狗) ((Dog*)a)->speak();
  else if (是猫) ((Cat*)a)->speak();
  else if (是鸭) ((Duck*)a)->speak();
  ... 每加一种动物就要回来改这里

有了接口，永远不用改：
  a->speak();   // 完事
```

## 四、如果没有接口会怎样（对比）

```cpp
// ❌ 没有接口：得分类讨论，代码越来越臃肿
void makeSoundBad(Dog* d) { d->speak(); }
void makeSoundBad(Cat* c) { c->speak(); }
void makeSoundBad(Duck* d) { d->speak(); }
// 每加一种动物，就要多加一个函数 + 改调用处

// ✅ 有接口：一行搞定，永不过时
void makeSound(vector<ISpeakable*>& animals) {
    for (auto a : animals) a->speak();
}
```

## 五、一张图看懂数据流向

```
┌─────────────┐
│ ISpeakable  │  接口（能力清单）：你必须会 speak()
│  (证书)     │
└──────┬──────┘
       │ 被实现（Implement）
   ┌───┼───────┐
   ▼   ▼       ▼
 ┌───┐ ┌───┐ ┌──────┐
 │Dog│ │Cat│ │Duck  │   具体类（真正造出来的东西）
 └─┬─┘ └─┬─┘ └──┬───┘
   │      │      │
   └──────┼──────┘
          ▼
   vector<ISpeakable*>   ← 用"接口指针"统一装起来
          │
          ▼
     a->speak()          ← 多态：各自用自己的版本
```

## 六、四个必记要点

| 要点 | 说明 |
|------|------|
| **接口不能实例化** | 不能 `new ISpeakable()`——它只是个清单，没有实体 |
| **纯虚函数必须实现** | `= 0` 的函数，子类不写就编译报错 |
| **用接口指针/引用调用** | `ISpeakable* p` 或 `ISpeakable& r`，才能触发多态 |
| **接口要有虚析构函数** | `virtual ~I(){}` 保证 delete 时正确清理 |

## 七、从 C++ 原生接口 → UE 接口（过渡）

上面是**标准 C++** 的接口写法。UE（虚幻引擎）在此基础上又加了反射系统的支持，所以 UE 接口长这样：

```cpp
// UE 里一个接口其实是"一对"
UINTERFACE()                          // ← UE 反射宏（C++ 原生没有）
class UMyInterface : public UInterface { ... };   // U 开头：给引擎看

class IMyInterface {                   // I 开头：你真正写代码的地方
    virtual void Foo() = 0;
};
```

| | 标准 C++ | UE |
|---|---|---|
| 接口本质 | 纯虚类 | 纯虚类 + 反射宏 |
| 名字 | 随便起 | 约定 `U`/`I` 开头成对出现 |
| 能否蓝图用 | 不能 | 可以（配合 UFUNCTION） |

> 你在 Lyra 里看到的 `ILyraTeamAgentInterface`，本质就是上面那个 `ISpeakable`，只不过套了 UE 的反射外壳而已。**核心思想完全一样**。

## 九、总结

```
接口（Interface）= 一张"能力清单"

它规定：
  ├─ 你必须会某些函数（纯虚函数 = 0）
  └─ 但不管你具体怎么做

好处：
  ├─ 统一处理：不用分类讨论每种类型
  ├─ 易扩展：新增类型不用改老代码
  └─ 解耦：调用者不关心你是什么，只关心你会不会

记住四点：
  1. 接口不能实例化（只能当指针/引用）
  2. 纯虚函数必须实现
  3. 用接口指针调用才有多态
  4. 接口要有虚析构函数
```

**一句话**：接口就是"**只要你会 XX，我就能用你**"——你不需要知道对方是狗是猫，只要它会叫（实现了接口），你就能让它叫。这就是面向对象里最重要的"解耦"思想。
