# 00.1 — 工程体检：`Source\` 里那 5 个文件到底是什么

> **本课目标**：搞清 `Source\` 下 5 个文件的职责，知道「改哪个文件会发生什么」。
> **改动文件**：无（纯认知课）
> **前置**：无
> ✅ 本课结束：你能指着任意一个文件说出它管什么。

---

## 一、为什么先做体检（场景 + 类比）

你现在有一个 UE 5.4 的 C++ 空白工程。`Source\` 里躺着 5 个文件，你大概知道「这是代码」，但不知道：

- 为什么有 `texiaoue54.Target.cs` 和 `texiaoue54Editor.Target.cs` 两个？
- `texiaoue54.Build.cs` 和 `texiaoue54.cpp` 有什么区别？
- `texiaoue54.h` 是空的，能删吗？

**不搞清这些，后面加文件就会乱放**——放错位置 UHT 直接报错，而且报错信息很难懂。

> 🔑 **类比**：`Source\` 就像一栋楼的**施工图纸 + 承重结构**。
> - `Target.cs` = 「这栋楼要盖几个版本」（游戏版 / 编辑器版）
> - `Build.cs` = 「这栋楼要用哪些材料」（依赖哪些引擎模块）
> - `Module.cpp` = 「这栋楼的大门」（模块加载入口）
> - `.h` = 「门牌」（可以没有）

## 二、5 个文件的真实内容与职责

### 2.1 目录结构

```
Source\
├── texiaoue54.Target.cs          ← 游戏版编译目标
├── texiaoue54Editor.Target.cs    ← 编辑器版编译目标
└── texiaoue54\                   ← 模块目录（名字 = 模块名）
    ├── texiaoue54.Build.cs       ← 模块依赖清单
    ├── texiaoue54.cpp            ← 模块入口
    └── texiaoue54.h              ← 模块头（空壳）
```

> ⚠️ **关键**：`Target.cs` 在 `Source\` **根目录**，`Build.cs` 在 `Source\texiaoue54\` **模块目录里**。位置不能换。

---

### 2.2 `texiaoue54.Target.cs`（15 行）

```csharp
// Copyright Epic Games, Inc. All Rights Reserved.

using UnrealBuildTool;
using System.Collections.Generic;

public class texiaoue54Target : TargetRules
{
	public texiaoue54Target(TargetInfo Target) : base(Target)
	{
		Type = TargetType.Game;
		DefaultBuildSettings = BuildSettingsVersion.V5;
		IncludeOrderVersion = EngineIncludeOrderVersion.Unreal5_4;
		ExtraModuleNames.Add("texiaoue54");
	}
}
```

| 行 | 干什么 |
|---|---|
| `public class texiaoue54Target : TargetRules` | 定义一个「编译目标」，类名必须是 `<名字>Target` |
| `Type = TargetType.Game;` | 这是**游戏版**（打包出去给玩家跑的） |
| `DefaultBuildSettings = BuildSettingsVersion.V5;` | 用 UE5 的默认编译设置（V5 = 5.4+ 的规则） |
| `IncludeOrderVersion = EngineIncludeOrderVersion.Unreal5_4;` | 头文件包含顺序按 5.4 规则（**5.4 工程就该是这一行，别改**） |
| `ExtraModuleNames.Add("texiaoue54");` | **这个目标要编译哪个模块** —— 就是 `Source\texiaoue54\` |

**本段新元素**
- `TargetRules` —— 编译目标基类，每个 `*.Target.cs` 必须继承它 —— `texiaoue54.Target.cs:6`
- `TargetType.Game` —— 目标类型枚举，`Game` = 游戏版，`Editor` = 编辑器版 —— `texiaoue54.Target.cs:10`
- `BuildSettingsVersion.V5` —— 编译设置版本，V5 对应 UE5.4+ —— `texiaoue54.Target.cs:11`
- `EngineIncludeOrderVersion.Unreal5_4` —— 头文件包含顺序版本 —— `texiaoue54.Target.cs:12`
- `ExtraModuleNames` —— 该目标额外要编译的模块名列表 —— `texiaoue54.Target.cs:13`

**这段在干什么**

| 概念 | 说明 |
|---|---|
| Target | 「编译产物」的配置。一个工程可以有多个 Target（游戏版、编辑器版、服务器版…） |
| Module | 「代码组织单位」。一个 Target 可以包含多个 Module |

> 类比：Target = 「要盖哪种楼」，Module = 「楼里的一个单元」。

### 2.3 `texiaoue54Editor.Target.cs`（15 行）

```csharp
// Copyright Epic Games, Inc. All Rights Reserved.

using UnrealBuildTool;
using System.Collections.Generic;

public class texiaoue54EditorTarget : TargetRules
{
	public texiaoue54EditorTarget(TargetInfo Target) : base(Target)
	{
		Type = TargetType.Editor;
		DefaultBuildSettings = BuildSettingsVersion.V5;
		IncludeOrderVersion = EngineIncludeOrderVersion.Unreal5_4;
		ExtraModuleNames.Add("texiaoue54");
	}
}
```

**和游戏版唯一的区别**：`Type = TargetType.Editor;`

| 项 | 游戏版 | 编辑器版 |
|---|---|---|
| `Type` | `TargetType.Game` | `TargetType.Editor` |
| 产物 | 打包用的 exe | 编辑器里加载的 DLL |
| 什么时候用 | 打包 / 独立运行 | **日常开发（99% 时间用这个）** |

> ⚠️ **重要**：你平时改代码后编译，编的是 **Editor** 版。所以本教程所有编译命令都用 `texiaoue54Editor`。

### 2.4 `texiaoue54\texiaoue54.Build.cs`（23 行）

```csharp
// Copyright Epic Games, Inc. All Rights Reserved.

using UnrealBuildTool;

public class texiaoue54 : ModuleRules
{
	public texiaoue54(ReadOnlyTargetRules Target) : base(Target)
	{
		PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;

		PublicDependencyModuleNames.AddRange(new string[] { "Core", "CoreUObject", "Engine", "InputCore", "EnhancedInput" });

		PrivateDependencyModuleNames.AddRange(new string[] {  });

		// Uncomment if you are using Slate UI
		// PrivateDependencyModuleNames.AddRange(new string[] { "Slate", "SlateCore" });

		// Uncomment if you are using online features
		// PrivateDependencyModuleNames.Add("OnlineSubsystem");

		// To include OnlineSubsystemSteam, add it to the plugins section in your uproject file with the Enabled attribute set to true
	}
}
```

| 行 | 干什么 |
|---|---|
| `public class texiaoue54 : ModuleRules` | 定义模块，**类名必须 = 模块名 = 文件夹名** |
| `PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;` | 预编译头策略（UE5 标准写法，别改） |
| `PublicDependencyModuleNames` | **公开依赖**：本模块用，引用本模块的别人也能用 |
| `PrivateDependencyModuleNames` | **私有依赖**：只本模块内部用 |

**当前 5 个公开依赖**：

| 模块 | 提供什么 |
|---|---|
| `Core` | `FString` / `TArray` / `TMap` / 日志宏 `UE_LOG` |
| `CoreUObject` | `UObject` / `UPROPERTY` / `UFUNCTION` / 反射系统 |
| `Engine` | `AActor` / `UActorComponent` / `UWorld` / 大部分游戏类 |
| `InputCore` | 按键枚举 `EKeys` |
| `EnhancedInput` | 增强输入系统（`UInputAction` / `UInputMappingContext`） |

**本段新元素**
- `ModuleRules` —— 模块规则基类，每个 `*.Build.cs` 必须继承 —— `texiaoue54.Build.cs:5`
- `PCHUsageMode.UseExplicitOrSharedPCHs` —— 预编译头模式，UE5 默认 —— `texiaoue54.Build.cs:9`
- `PublicDependencyModuleNames` —— 公开依赖列表 —— `texiaoue54.Build.cs:11`
- `PrivateDependencyModuleNames` —— 私有依赖列表 —— `texiaoue54.Build.cs:13`

**这段在干什么**

| 概念 | 说明 |
|---|---|
| 依赖（Dependency） | 「我要用别的模块的类，就得在这里声明」 |
| 不声明会怎样 | 编译报 `Cannot open include file` 或 `unresolved external symbol` |

> 类比：`Build.cs` = 采购清单。你要用 `UStaticMeshComponent`，就得先买 `Engine` 这个材料。

> 💡 **本教程后续会往这里加依赖**（比如阶段 7 加 `GameplayAbilities`、`GameplayTags`）。每次加都会明确告诉你加哪一行。

### 2.5 `texiaoue54\texiaoue54.cpp`（6 行）

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.

#include "texiaoue54.h"
#include "Modules/ModuleManager.h"

IMPLEMENT_PRIMARY_GAME_MODULE( FDefaultGameModuleImpl, texiaoue54, "texiaoue54" );
```

| 行 | 干什么 |
|---|---|
| `#include "Modules/ModuleManager.h"` | 模块系统头 |
| `IMPLEMENT_PRIMARY_GAME_MODULE(...)` | **注册主游戏模块**，三个参数：模块实现类 / 模块名 / 模块名字符串 |

**本段新元素**
- `IMPLEMENT_PRIMARY_GAME_MODULE` —— 注册主游戏模块的宏，一个工程只能有一个 —— `texiaoue54.cpp:6`
- `FDefaultGameModuleImpl` —— 引擎默认模块实现（`StartupModule`/`ShutdownModule` 都是空的） —— `texiaoue54.cpp:6`

**这段在干什么**

| 概念 | 说明 |
|---|---|
| 模块入口 | UE 启动时靠这个宏知道「哪个是主游戏模块」 |
| 为什么是空的 | 空白工程不需要在模块加载时做任何事 |

> 类比：这是「大门钥匙」——引擎拿着它才能进你的代码。

> ⚠️ **本教程全程不改这个文件**。除非以后要在模块启动时注册全局对象（阶段 7 可能会）。

## 三、`.uproject` 里的模块声明（顺带看一眼）

`texiaoue54.uproject` 第 6~12 行：

```json
"Modules": [
	{
		"Name": "texiaoue54",
		"Type": "Runtime",
		"LoadingPhase": "Default"
	}
],
```

| 字段 | 含义 |
|---|---|
| `Name` | 模块名，**必须和 `Build.cs` 类名、文件夹名一致** |
| `Type` | `Runtime` = 运行时模块（游戏逻辑）；`Editor` = 只在编辑器里加载 |
| `LoadingPhase` | `Default` = 引擎初始化后加载 |

> ⚠️ **三处名字必须完全一致**：`.uproject` 的 `Name` = `Build.cs` 的类名 = 模块文件夹名。改一个不改其他两个 → 编译报「找不到模块」。

## 四、怎么验证（本课无代码，验证认知）

打开这 5 个文件，对照上面的表格，确认你能回答：

1. `texiaoue54.Target.cs` 和 `texiaoue54Editor.Target.cs` 差在哪一行？→ `Type`
2. 我要用 `UStaticMeshComponent`，需要改哪个文件？→ `Build.cs`（`Engine` 已在，不用改）
3. 我要用 `UGameplayAbility`，需要改哪个文件？→ `Build.cs`（加 `GameplayAbilities`）
4. 新建一个 `AMyActor` 类，文件放哪？→ `Source\texiaoue54\` 下（可以建子目录）

## 五、常见报错（本课相关）

| 症状 | 原因 | 改法 |
|---|---|---|
| `Cannot find module 'texiaoue54'` | `.uproject` 的 `Name` 和文件夹名不一致 | 三处名字对齐 |
| `Cannot open include file: 'XXX.h'` | `Build.cs` 没声明对应模块依赖 | 在 `PublicDependencyModuleNames` 加模块名 |
| `unresolved external symbol` | 声明了但没实现，或依赖没加 | 检查 `.cpp` 是否实现 / `Build.cs` 依赖 |
| 改了 `.h` 但编辑器没反应 | 没重新编译 | 跑 `Build.bat`（见 00.2） |
