## 一、为什么先学这个（场景 + 类比）

UE 的 C++ 开发有个特点：**代码不是"保存就生效"**。

你改完 `.h` / `.cpp`，编辑器**不会**自动重新编译。必须：

```
改代码 → 关编辑器 → 编译 → 开编辑器 → 看效果
```

新手最常卡的三件事：

1. 改完代码直接开编辑器 → 发现没生效（因为没编译）
2. 编辑器开着就编译 → 报 `LNK1104: cannot open file ...dll`（DLL 被占用）
3. 编译报错看不懂 → 不知道是 UHT 错还是 C++ 错

> 🔑 **类比**：UE 的 C++ 就像**盖房子**。
> - 改 `.h`/`.cpp` = 改图纸
> - 编译 = 按图纸施工（生成 `.dll`）
> - 开编辑器 = 住进去
> 图纸改了不施工，房子当然还是老样子。

## 二、三个关键目录（先认清，后面天天用）

```
E:\ue5\game_design\code\texiaoue54\
├── Source\          ← 你写的代码（唯一要手动编辑的）
├── Binaries\        ← 编译产物（.dll / .exe），别手动改
├── Intermediate\    ← 编译中间文件（.obj / 生成的头），可随时删
├── Saved\           ← 日志、配置缓存、自动备份
│   └── Logs\        ← ★ 日志在这里
└── Content\         ← 资产（蓝图 / 关卡 / 模型）
```

| 目录 | 是什么 | 能删吗 | 什么时候看它 |
|---|---|---|---|
| `Source\` | 你的 C++ 源码 | ❌ 绝对不能 | 写代码时 |
| `Binaries\` | 编译出的 `UnrealEditor-texiaoue54.dll` | ✅ 可删（会重新生成） | 报 `LNK1104` 时看是否被占用 |
| `Intermediate\` | `.obj`、UHT 生成的 `.generated.h` | ✅ 可删（编译变慢） | 编译出现诡异错误时**删掉重编** |
| `Saved\Logs\` | `texiaoue54.log` | ✅ 可删 | **任何运行时问题都先看这里** |

> 💡 **万能修复**：编译出现莫名其妙的错误 → 删 `Binaries\` + `Intermediate\` → 重新编译。90% 的诡异问题能解决。

## 三、编译命令（背下来，每课都用）

### 3.1 标准命令

```powershell
& "D:\ue5\Epic Games\UE_5.4\Engine\Build\BatchFiles\Build.bat" texiaoue54Editor Win64 Development -Project="E:\ue5\game_design\code\texiaoue54\texiaoue54.uproject" -WaitMutex
```

拆开看：

| 片段 | 含义 |
|---|---|
| `Build.bat` | 引擎自带的编译脚本 |
| `texiaoue54Editor` | **编译目标名** = `texiaoue54Editor.Target.cs` 去掉 `.Target.cs` |
| `Win64` | 平台 |
| `Development` | 配置（`Development` 开发 / `Shipping` 发布 / `DebugGame` 调试） |
| `-Project="..."` | 指定工程 |
| `-WaitMutex` | 等锁（防止多个编译同时跑） |

**本段新元素**
- `Build.bat` —— 引擎编译入口脚本，位于 `<引擎>\Engine\Build\BatchFiles\` —— `D:\ue5\Epic Games\UE_5.4\Engine\Build\BatchFiles\Build.bat`
- `texiaoue54Editor` —— 编译目标名，必须与 `Source\texiaoue54Editor.Target.cs` 对应 —— `Source\texiaoue54Editor.Target.cs:6`
- `Development` —— 编译配置，日常开发用这个 —— 引擎 `UnrealBuildTool` 内置枚举
- `-WaitMutex` —— 等待编译互斥锁，避免并发冲突 —— `Build.bat` 参数

**这段在干什么**

| 参数 | 作用 |
|---|---|
| 目标名 | 决定编哪个 Target（Editor 版 / Game 版） |
| 平台 | Win64 / Linux / Mac |
| 配置 | Development（带调试信息）/ Shipping（优化、无调试） |

> 类比：`Build.bat` = 施工队，目标名 = 盖哪栋楼，配置 = 精装还是简装。

---

### 3.2 编译前必做：关掉编辑器

**为什么**：编辑器运行时会把 `Binaries\Win64\UnrealEditor-texiaoue54.dll` **加载进内存并锁定**。编译要写这个文件 → 写不进去 → 报错：

```
LINK : fatal error LNK1104: 无法打开文件“...\UnrealEditor-texiaoue54.dll”
```

**怎么确认编辑器是否开着**：

```powershell
Get-Process | Where-Object { $_.ProcessName -like "*UnrealEditor*" } | Select-Object Id, ProcessName, Path
```

有输出 = 开着，需要关掉。

**关掉**：

```powershell
Get-Process | Where-Object { $_.ProcessName -like "*UnrealEditor*" } | Stop-Process -Force
```

> ⚠️ 关之前**先保存关卡和蓝图**，否则改动丢失。

---

### 3.3 编译成功的标志

输出末尾出现：

```
Total execution time: 12.34 seconds
```

并且**没有** `error` 字样（`warning` 可以有）。

失败则是：

```
Result: Failed (OtherCompilationError)
Total execution time: 430.87 seconds
```

## 五、日志在哪看（三种方式）

| 方式 | 位置 | 用途 |
|---|---|---|
| **编辑器内 Output Log** | 窗口 → 开发人员工具 → 输出日志 | 实时看 `UE_LOG` 输出 |
| **日志文件** | `Saved\Logs\texiaoue54.log` | 编辑器崩溃后看最后几行 |
| **控制台命令** | Output Log 底部输入框 | 输入 `stat fps` 等命令 |

**过滤日志**：Output Log 上方有 `Filters` 下拉，可以只看 `LogTemp` / `Warning` / `Error`。

> 💡 本教程所有 `UE_LOG` 都用 `LogTemp` 分类，方便你过滤。

## 六、读懂编译报错（三类，按出现频率排）

### 6.1 UHT 报错（最常见）

```
error : Unrecognized type 'UMyComponent' - type must be a UCLASS, USTRUCT or UENUM
```

**原因**：`.h` 里用了 `U` 开头的类型，但没加 `UCLASS()` 宏，或者没 `#include` 对应头文件。

**改法**：检查类声明上方有没有 `UCLASS()`，检查 `#include`。

---

### 6.2 C++ 编译报错

```
error C2065: 'MyVariable': undeclared identifier
```

**原因**：变量没声明 / 拼错 / 没 include。

**改法**：看报错给的**文件名 + 行号**，直接跳过去。

---

### 6.3 链接报错

```
error LNK2019: 无法解析的外部符号 "public: void __cdecl AMyActor::MyFunc(void)"
```

**原因**：`.h` 里声明了函数，但 `.cpp` 里**没实现**（或实现签名不一致）。

**改法**：去 `.cpp` 补实现，注意 `const` / 参数类型要完全一致。

---

### 6.4 报错定位技巧

编译输出里，**第一个 `error`** 才是根因，后面的往往是连锁反应。

```powershell
# 只看错误行
& "D:\ue5\Epic Games\UE_5.4\Engine\Build\BatchFiles\Build.bat" texiaoue54Editor Win64 Development -Project="E:\ue5\game_design\code\texiaoue54\texiaoue54.uproject" -WaitMutex 2>&1 | Select-String "error"
```

## 八、常见报错速查

| 症状 | 原因 | 改法 |
|---|---|---|
| `LNK1104: cannot open file ...dll` | 编辑器开着，DLL 被占用 | 关编辑器再编译 |
| `Cannot open include file: 'XXX.h'` | `Build.cs` 缺依赖 | 在 `PublicDependencyModuleNames` 加模块 |
| `Unrecognized type 'UXXX'` | 缺 `UCLASS()` 或 `#include` | 补宏 / 补 include |
| `LNK2019: 无法解析的外部符号` | 声明了没实现 | `.cpp` 补实现 |
| `error : Unable to find 'XXX.generated.h'` | 文件名和类名不一致 | `#include "类名.generated.h"` 必须与文件名一致 |
| 编译成功但编辑器没变化 | 编辑器没重启 | 关掉重开 |
| 编译卡住不动 | 有残留进程 | 删 `Intermediate\` + `Binaries\` 重编 |
