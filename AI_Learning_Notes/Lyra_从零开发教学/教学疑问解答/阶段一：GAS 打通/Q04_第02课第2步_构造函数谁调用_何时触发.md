# Q04 — 第 02 课 · 第 2 步【基类】疑问：构造函数 `UTenkaichiAttributeSet::UTenkaichiAttributeSet()` 谁调用？哪里用到？

> **所属章节**：第 02 课 · 第 2 步【2/4】建基类 `TenkaichiAttributeSet.cpp`
>
> **对应 Lyra**：`LyraAttributeSet.cpp:12`（构造函数定义） + `LyraPlayerState.cpp:39` / `LyraAbilitySet.cpp:94`（创建点）
>
> **一句话**：构造函数**没有任何代码显式调用它**——它是 UE 在"创建属性集对象"那一刻**自动调用**的。你只管在构造函数里写"初值"，创建动作由引擎的对象系统触发。

---

## 一、你的疑问（原话）

```cpp
UTenkaichiAttributeSet::UTenkaichiAttributeSet()
{
}
```
这个构造函数，谁用到了？哪里用到？

**先给结论**：你在整个工程里**搜不到 `UTenkaichiAttributeSet::UTenkaichiAttributeSet()` 的调用**——这不是漏了，是**构造函数的本质就是这样**：它由引擎在"造对象"时自动调用，不需要（也不能）你手动调。

---

## 二、核心认知：构造函数是"造对象时自动触发"的，不是手动调的

普通函数你得写 `xxx->某函数()` 才能调用。但**构造函数不一样**：

> **只要引擎要"造一个属性集对象"，构造函数就自动执行一次**——你不用写任何调用代码。

那"什么时候会造属性集对象？"——见下面第三节，Lyra 里有**两种创建方式**，两种都会自动触发构造函数。

---

## 三、Lyra 里属性集在"哪里被创建"（= 构造函数在哪被触发）

### 创建方式 A：`CreateDefaultSubobject` —— 构造角色/记分牌时"顺带造好"（最常见）

**哪里用**：`LyraPlayerState.cpp` 第 39-40 行（记分牌的构造函数里）

```cpp
// LyraPlayerState.cpp 第 39-40 行
HealthSet = CreateDefaultSubobject<ULyraHealthSet>(TEXT("HealthSet"));   // ← 这里"造"了血量集
CombatSet = CreateDefaultSubobject<ULyraCombatSet>(TEXT("CombatSet"));
```

（另一处 `LyraCharacterWithAbilities.cpp:20` 也是同样写法，自带技能的角色用。）

**在干嘛**：记分牌（PlayerState）在**自己被构造**时，用 `CreateDefaultSubobject<ULyraHealthSet>` **顺手把血量集这个子对象也造出来**。**这一"造"，血量集的构造函数 `ULyraHealthSet()` 就自动执行了**（里面写 `Health(100.0f)`，把血量初值设成 100）。

> 剧场故事：记分牌（PlayerState）一"出生"，就**顺手把血型档案卡（血量集）印好、塞进自己怀里**。印这张卡的瞬间，卡上的"初始血量 100"就被写好了——这个"写初始值"的动作，就是构造函数干的。**不需要有人事后喊"请初始化血量"，印卡即初始化。**

---

### 创建方式 B：`NewObject` + `AddAttributeSetSubobject` —— 运行时"动态发"属性集

**哪里用**：`LyraAbilitySet.cpp` 第 94-95 行（授予技能/属性时）

```cpp
// LyraAbilitySet.cpp 第 94-95 行
UAttributeSet* NewSet = NewObject<UAttributeSet>(LyraASC->GetOwner(), SetToGrant.AttributeSet);  // ← 这里"造"
LyraASC->AddAttributeSetSubobject(NewSet);   // 挂到 ASC 上
```

（另一处 `GameFeatureAction_AddAbilities.cpp:200` 同理，GameFeature 动态加能力时用。）

**在干嘛**：有些属性集不是开局就有，而是**游戏过程中动态发**的（比如通过"技能集/装备"授予）。这时用 `NewObject` 现造一个，**构造函数同样自动执行**，再造完 `AddAttributeSetSubobject` 挂到 ASC 上。

> 剧场故事：有些档案卡不是演员一出生就有，而是**中途发了新装备才配发**（比如穿上"巨人铠甲"才发一张"护甲档案卡"）。发的时候用 `NewObject` 现印一张——印的瞬间，卡上的初始值也被写好了。

---

## 四、那"基类"的构造函数（你问的这个）什么时候跑？

你问的 `UTenkaichiAttributeSet::UTenkaichiAttributeSet()` 是**基类**构造函数。它比血量集（子类）的构造函数**更早**跑：

```
造一个血量集对象时，构造函数执行顺序：
  ① 先跑基类 UTenkaichiAttributeSet::UTenkaichiAttributeSet()   ← 你问的这个（基类，空的）
  ② 再跑子类 UTenkaichiHealthSet::UTenkaichiHealthSet()          ← 设 Health(100.0f)
```

这是 C++ 铁律：**构造派生对象，永远先构造基类，再构造子类**。所以基类构造函数虽然空，但**每次造血量集时它都会先跑一遍**（跑个空壳，啥也不做，但必须跑）。

> 类比：印一张血型档案卡（血量集）时——**先把"空白卡底座"做好**（基类构造函数，空的），**再往卡上填"初始血量 100"**（子类构造函数）。底座那步没填数据，但缺了它，卡根本不存在。

## 五、一张总表（构造函数在哪被"触发"）

| 创建方式 | 哪里用（Lyra 真实行号） | 谁创建 | 构造函数何时跑 |
|---------|------------------------|--------|--------------|
| `CreateDefaultSubobject<ULyraHealthSet>` | `LyraPlayerState.cpp:39`（记分牌构造时） | 记分牌/角色 | 记分牌被造时，自动造血量集 → 触发构造函数 |
| `NewObject<UAttributeSet>` + `AddAttributeSetSubobject` | `LyraAbilitySet.cpp:94`（动态授予时） | 技能集/装备系统 | 运行时动态发属性集 → 触发构造函数 |

> **注意**：两种方式的共同点是——**都没有一行代码写"调用构造函数"**。构造函数永远由引擎在"造对象"那一刻自动调用。你写构造函数，只是为了"告诉引擎：造这个对象时，把初值这么设"。

---

## 六、为什么"我们的工程搜不到调用"

因为**构造函数本来就不该被手动调用**。你现在的基类构造函数是空的（没属性要初始化，呼应 [Q01](./Q01_第02课第2步_基类cpp方法为何是空的_h与cpp关系.md)），等后面写了血量集 `TenkaichiHealthSet`，用 `CreateDefaultSubobject` 把它挂到 ASC 上时，**基类 + 子类的构造函数就会自动依次执行**。

> 一句话：**构造函数不用你调，引擎造对象时自动调。** 现在基类构造函数空着是对的，等血量集上场（第 3 步之后），创建它的那一刻，构造函数自然就跑起来了。

---

## 七、一句话结论

**构造函数没有任何代码显式调用它——UE 在"造属性集对象"时自动调用。Lyra 里两种创建方式：①`CreateDefaultSubobject`（记分牌构造时顺带造，`LyraPlayerState.cpp:39`）；②`NewObject`+`AddAttributeSetSubobject`（运行时动态发，`LyraAbilitySet.cpp:94`）。造对象时永远先跑基类构造函数（你问的这个，空的），再跑子类构造函数（设初值）。**
