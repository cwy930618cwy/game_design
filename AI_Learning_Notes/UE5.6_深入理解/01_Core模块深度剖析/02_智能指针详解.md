# 02 — 智能指针详解（TSharedPtr / TWeakPtr / TUniquePtr / TObjectPtr）

> **定位**：UE 里管理"对象生命周期"的指针工具。上一章（Core）里标了"可以延后学"，但当你要写**非 UObject 的 C++ 数据**、或者想在 UObject 之间安全持有时，它就必须懂了。
>
> **最重要的一句话**：UE 有**两套完全独立的"指针世界"**——
> - **UObject 世界**（Actor/Component）：生命周期由 **GC（垃圾回收）** 管，用 `UPROPERTY()` 裸指针 / `TObjectPtr` / `TWeakObjectPtr`
> - **普通 C++ 世界**（纯数据结构）：生命周期由你自己管，用 `TSharedPtr` / `TUniquePtr`
>
> **别把两套混在一起**，很多新手就在这里踩坑。

---

## 一、为什么需要智能指针（先搞懂动机）

C++ 里 `new` 出来的对象不会自己销毁，你必须手动 `delete`。漏了 → **内存泄漏**；删早了 → **悬垂指针**（访问已销毁的内存 → 崩溃）。

```cpp
// ❌ 传统裸指针：忘记 delete → 内存泄漏
MyObj* Obj = new MyObj();
// ... 忘了 delete Obj;
```

智能指针的核心思想：**让指针自己管自己的生命周期**，你只管用，不用管释放。

---

## 二、UE 的四大家族速览（先看这张表）

| 指针 | 属于哪套世界 | 生命周期 | 能否为空 | 用途 |
|------|:-----------:|:-------:|:-------:|------|
| **TSharedPtr** | 普通 C++ | 引用计数，最后一个释放 | 可空 | 跨系统共享非 UObject 对象 |
| **TWeakPtr** | 普通 C++ | 不拥有，只观察 | 可空 | 只引用不延长生命，防循环引用 |
| **TUniquePtr** | 普通 C++ | 独占，唯一所有者 | 可空 | 一个对象只属于一个系统 |
| **TObjectPtr** | UObject | **不决定**，由 GC 管 | 可空 | 替代 UObject 的裸指针（UE5 新推荐） |
| **TWeakObjectPtr** | UObject | 不决定，由 GC 管 | 可空 | 弱引用 UObject，销毁自动置空 |

> 前三个（`TSharedPtr`/`TWeakPtr`/`TUniquePtr`）对应的是 C++ 的 `shared_ptr`/`weak_ptr`/`unique_ptr`，是"手动管内存"的世界。
>
> 后两个（`TObjectPtr`/`TWeakObjectPtr`）对应的是 **UObject 世界**，内存由 GC 管，你只是"拿着一个引用"。

---

## 三、逐个讲（重点看两个 TWeak 的区别）

### 3.1 TSharedPtr — 共享所有权（普通 C++ 世界）

多个指针共享同一个对象，**引用计数归零时自动销毁**。

```cpp
// 创建（推荐用 MakeShared，一次分配）
TSharedPtr<FMyData> Data = MakeShared<FMyData>();
Data->Value = 42;                 // 用 -> 访问

// 复制一份，引用计数 +1
TSharedPtr<FMyData> Another = Data;   // 现在两个指针共享同一个对象

// 函数参数传递（按值传，自动管理计数）
void UseIt(TSharedPtr<FMyData> InData) { ... }

// 不想要了，置空即可，计数归零时对象自动 delete
Data.Reset();
```

**具体场景：技能系统的"共享战斗数据"**

一个 Buff 效果的数据（`FStatusEffect`）可能同时被"角色面板""HUD 图标""战斗日志"三个系统引用。这三个系统都想要这个数据、又都说不清谁该负责释放，就用 `TSharedPtr` 共享——谁都用完，最后一个销毁时自动释放，**谁都不用手动管**。

```cpp
class FStatusEffect {           // 非 UObject 的纯数据
public:
    FName Id;
    float Duration;
    int32 Stacks;
};

// 创建 Buff 时
TSharedPtr<FStatusEffect> Effect = MakeShared<FStatusEffect>();
Effect->Id = TEXT("Burning");

// 三处共享引用（角色、HUD、日志），引用计数到 0 自动释放
Character->ActiveEffects.Add(Effect);
Hud->ShowBuffIcon(Effect);
LogSystem->WriteLog(Effect);
```

**注意**：`FMyData` 不能是 UObject（UObject 用 GC，不该用 TSharedPtr 管）。

### 3.2 TWeakPtr — 弱引用（普通 C++ 世界）

**不拥有对象**，只"看着它"。对象还活着就 `Lock()` 拿一下，死了就返回空。**专门用来打破循环引用**。

```cpp
// A 持有 B 的共享指针，B 又持有 A 的共享指针 → 引用计数永远不为 0 → 内存泄漏
// 解决办法：让其中一方用 TWeakPtr，不参与计数

class A;
class B;
struct A { TSharedPtr<B> BPtr; };
struct B { TWeakPtr<A>   APtr; };   // B 用弱指针，不增加 A 的计数

// 使用时，弱指针要 Lock 一下才能拿
if (auto APtr = WeakA.Pin()) {      // Pin() 返回 TSharedPtr，为空说明已销毁
    APtr->DoSomething();
}
```

**具体场景：技能"持有者"和技能"实例"互相引用（防循环泄漏）**

技能系统里，一个 `FActiveAbility`（技能实例）需要知道"是哪个角色施放的"，角色又需要知道"当前激活了哪些技能"。如果**两边都用 TSharedPtr 强引用**，就互相咬死：谁都释放不掉，内存泄漏。

```cpp
class ACharacter_Internal;
struct FActiveAbility;
struct ACharacter_Internal {
    TSharedPtr<FActiveAbility> CurrentAbility;   // 角色强持有技能
};
struct FActiveAbility {
    TWeakPtr<ACharacter_Internal> Owner;         // 技能只"弱引用"角色，不增加计数
};

// 使用：技能想找施放者，先 Pin 再访问
if (auto Owner = Ability->Owner.Pin()) {
    Owner->DoCastFinish();   // 角色还活着才执行，死了就跳过
}
```

> 规则：**父子/主从关系里，子对象引用父对象用 TWeakPtr**，避免循环引用导致双方都释放不掉。

### 3.3 TUniquePtr — 独占所有权（普通 C++ 世界）

一个对象**只属于一个指针**，不能复制，只能移动。所有权转移后原来的就为空。

```cpp
TUniquePtr<FData> Owner = MakeUnique<FData>();
// TUniquePtr<FData> Copy = Owner;   // ❌ 编译错误，不能复制
TUniquePtr<FData> New = MoveTemp(Owner);  // ✅ 用 MoveTemp 转移所有权
// 此时 Owner 为空
```

**具体场景：AI 角色"独占"自己的寻路路径**

每个 AI 角色在移动时，需要一份"当前寻路路径数据"（`FPathData`：一串路点）。这份路径**只属于这个 AI**，其他系统不需要碰，AI 死亡时它就该跟着销毁。用 `TUniquePtr` 正好表达"这路径归这个 AI 独有"。

```cpp
class APatrolAI : public AActor {
    TUniquePtr<FPathData> CurrentPath;   // 独占一份路径

    void SetNewPath(TUniquePtr<FPathData> Path) {
        CurrentPath = MoveTemp(Path);    // 转移所有权，旧路径自动释放
    }

    void FollowPath() {
        if (CurrentPath) CurrentPath->Advance();
    }
};
```

**什么时候用**：某个系统**独占**一个非 UObject 对象，不共享。用它的语义是"这玩意儿归我一个人管"。

### 3.4 TObjectPtr — 新手问最多的 ★

**这是 UE5 推荐用来写 UObject 成员变量的指针**，替代以前直接用裸指针 `AActor*` 的写法。

```cpp
// ❌ 旧写法（UE4 时代）：裸指针
UPROPERTY()
AActor* MyTarget;

// ✅ UE5 推荐：TObjectPtr
UPROPERTY()
TObjectPtr<AActor> MyTarget;
```

**它是什么**：本质上**还是那个 UObject 指针**（指向的是同一个 Actor），生命周期**仍然由 GC 管理**。它只是包了一层，让编辑器知道"这个指针该做哪些特殊处理"（比如在编辑器里支持延迟加载资产、断链引用、更好的类型校验）。

**关键点（消除困惑）**：

- `TObjectPtr` 和裸指针 `AActor*` **指向的是同一个东西，都由 GC 管**，不是引用计数
- `TObjectPtr` 是 UE5 为了**编辑器扩展性**引入的，日常读代码你把它当裸指针用就行，访问同样用 `->`
- 成员变量用 `UPROPERTY()` + `TObjectPtr` 是**当前推荐的最佳实践**

```cpp
// 使用起来跟裸指针几乎一样
if (MyTarget.IsValid()) {
    MyTarget->TakeDamage(10.f);   // 用 -> 访问，和裸指针一样
}
```

**一句话**：看到 `TObjectPtr<AActor>`，就理解为"**一个受 GC 管理的 AActor 指针**"，比裸指针多了编辑器支持，用法几乎一样。

**具体场景：角色"长期锁定"一个攻击目标**

角色锁定敌人时，需要**一直引用这个目标**，绝不允许它被 GC 中途回收（否则打空气）。所以用 `TObjectPtr`（强引用），并加 `UPROPERTY()` 让引擎知道该管理它。

```cpp
UCLASS()
class APlayerCharacter : public ACharacter {
    GENERATED_BODY()
public:
    UPROPERTY()                                    // ← 必须加，GC 才知道要管理
    TObjectPtr<AActor> LockedTarget;               // 强引用：锁定目标，防 GC 误杀

    void SetTarget(AActor* NewTarget) {
        LockedTarget = NewTarget;
    }

    void Attack() {
        if (LockedTarget && LockedTarget->IsValidLowLevel()) {
            LockedTarget->TakeDamage(10.f);
        }
    }
};
```

> 只要这个角色存活，`LockedTarget` 指向的敌人就不会被 GC 回收，你可以放心在 Tick / 攻击里一直用它。

### 3.5 TWeakObjectPtr — UObject 世界的"弱引用"

作用类似 `TWeakPtr`，但属于 **UObject 世界**：持有一个 UObject 的引用，但**不阻止 GC**。被引用的对象销毁时，这个弱指针**自动变空**，不会悬垂崩溃。

```cpp
// 声明：UPROPERTY() 前缀可加可不加
TWeakObjectPtr<AActor> WeakTarget;

// 赋值
WeakTarget = SomeActor;      // 不增加引用计数，不阻止 GC

// 安全使用：先 Pin 或 IsValid
if (WeakTarget.IsValid()) {          // 对象还活着吗
    WeakTarget->DoSomething();
}
```

**和 TObjectPtr 的区别（最容易混的地方）**：

| | TObjectPtr | TWeakObjectPtr |
|---|:---:|:---:|
| 会阻止对象被 GC 吗 | **会**（强引用） | **不会**（弱引用） |
| 对象销毁后指针变空吗 | 需要 UPROPERTY 才能安全 | **自动变空** ✅ |
| 场景 | 我长期持有的目标 | 我临时看一眼、不想要的对象 |
| 能否存进容器 | 要 UPROPERTY | 可直接放 TArray |

**选型**：想**长期持有**一个 Actor → `TObjectPtr`（强引用，防 GC 误杀）；只是**临时记录**一下、不介意它被销毁 → `TWeakObjectPtr`（安全，自动失效）。

**具体场景：角色受伤时"记录凶手"，但不想保住他**

角色被打死时，要**记下最后伤害来源**（用于死亡结算、击杀回放）。但这个凶手可能已经被摧毁了，我们**不该为了记录就阻止它被 GC**——否则一堆死掉的小怪永远清不掉。用 `TWeakObjectPtr` 最合适：凶手活着就记着，被销毁就自动变空，不会悬垂崩溃。

```cpp
UCLASS()
class AMyCharacter : public ACharacter {
    GENERATED_BODY()
public:
    TWeakObjectPtr<AActor> LastDamageCauser;   // 弱引用：记录凶手，不阻止 GC

    void TakeDamage(float Amount, AActor* Causer) {
        LastDamageCauser = Causer;             // 只记录，不强持有
        // 结算时安全读取
        if (LastDamageCauser.IsValid()) {
            // 凶手还活着，算击杀归属
            AddKillTo(LastDamageCauser.Get());
        }
    }
};
```

> 对比：如果用 `TObjectPtr` 强持有"凶手"，那些已经死亡、本该被回收的小怪会因被你引用而**永远清不掉**，越打越卡。所以"只是记录、不该保住"的对象就用 `TWeakObjectPtr`。

## 四、生命周期对比总表（一张图记住两套世界）

```
┌─────────── UObject 世界（GC 管内存）───────────┐
│  持有(强)   TObjectPtr<AActor>    ← UPROPERTY，阻止 GC │
│  观察(弱)   TWeakObjectPtr<AActor> ← 自动失效，不阻止 GC │
└──────────────────────────────────────────────┘

┌──────── 普通 C++ 世界（你自己管内存）─────────┐
│  共享      TSharedPtr<T>   引用计数          │
│  观察      TWeakPtr<T>     不计数，防循环     │
│  独占      TUniquePtr<T>   唯一所有权        │
└──────────────────────────────────────────────┘
```

**判别的唯一关键**：你操作的对象是 **UObject（Actor/Component/资源）** 还是 **普通 C++ 类**？

- UObject → 用 `TObjectPtr` / `TWeakObjectPtr`（**大部分游戏代码都是这种**）
- 普通 C++ 类 → 用 `TSharedPtr` / `TWeakPtr` / `TUniquePtr`（插件、编辑器工具、纯数据）

## 五、使用速查（拿来即用）

### 成员变量（最常用场景）

```cpp
UCLASS()
class AMyCharacter : public ACharacter {
    GENERATED_BODY()
public:
    // ✅ UE5 推荐：长期持有的目标，由 GC 管
    UPROPERTY()
    TObjectPtr<AActor> CurrentTarget;

    // ✅ 弱引用：临时观察的对象，销毁自动失效
    TWeakObjectPtr<AActor> LastHitBy;

    // 普通 C++ 数据（非 UObject）用共享/独占
    TSharedPtr<FMyStats> Stats;
    TUniquePtr<FPathData> Path;
};
```

### 判断是否有效 / 访问

```cpp
// UObject 世界
if (MyTarget.IsValid())  MyTarget->DoIt();     // TObjectPtr 检查
if (Weak.IsValid())      Weak->DoIt();          // TWeakObjectPtr 检查

// 普通 C++ 世界
if (SharedPtr.IsValid()) SharedPtr->DoIt();     // TSharedPtr 检查
if (auto Ptr = WeakPtr.Pin()) Ptr->DoIt();      // TWeakPtr 要 Pin()
```

## 六、常见陷阱

**① 把 UObject 塞进 TSharedPtr → 错**
```cpp
// ❌ UObject 由 GC 管，不该用 TSharedPtr（会双管，容易崩）
TSharedPtr<AActor> Bad = MakeShared<AActor>();

// ✅ UObject 用 TObjectPtr / TWeakObjectPtr
TObjectPtr<AActor> Good;
```

**② 忘记 UPROPERTY 的 TObjectPtr 在重载时不更新 → 悬垂**
成员 `TObjectPtr` 一定要加 `UPROPERTY()`，否则引擎在"热重载/关卡重载"时不知道这是对象引用，可能导致引用失效。

**③ TWeakPtr 不 Pin 直接用 → 编译不过**
`TWeakPtr` 不能直接用 `->`，必须 `.Pin()` 拿回 `TSharedPtr` 才能访问。

**④ 把 TWeakObjectPtr 当强引用用 → 对象莫名被销毁**
`TWeakObjectPtr` **不阻止 GC**，如果你以为它保住了对象，结果对象被回收 → `IsValid()` 为 false。要强持有用 `TObjectPtr`。

## 七、TObjectPtr 到底是个啥（单独总结）

新手看到很多地方推荐 `TObjectPtr`，核心就三句话：

1. **它就是个 UObject 指针**，指向同一个 Actor/Component，生命周期**由 GC 管**，不是引用计数。
2. **它比裸指针 `AActor*` 好在哪**：给编辑器更多信息（延迟加载、类型校验、断链处理），是 UE5 的**最佳实践**。
3. **用法几乎和裸指针一样**：`->` 访问、`.IsValid()` 判断，只是声明时写 `TObjectPtr<AActor>`。

**看到它就当裸指针读，声明时用 `UPROPERTY()` + `TObjectPtr`**，就够了。

## 八、综合实战场景：把它们拼进一个真实的"角色战斗"模块

下面把**五种指针**放进同一个游戏模块里，看它们各自该待在哪、为什么。

```cpp
UCLASS()
class ABossFighter : public ACharacter {
    GENERATED_BODY()
public:
    // ---- UObject 世界（GC 管）----
    UPROPERTY()
    TObjectPtr<AActor> LockedTarget;          // ① 强持有：锁定目标，防 GC 误杀

    TWeakObjectPtr<AActor> LastHitBy;         // ② 弱引用：记录"谁打的我"，不阻止回收

    // ---- 普通 C++ 世界（自己管）----
    TSharedPtr<FStatSheet> Stats;             // ③ 共享：角色面板/HUD/日志都要读
    TUniquePtr<FComboData> Combo;             // ④ 独占：一套连击数据只属于这个角色
    TWeakPtr<FStatSheet> StatBackRef;         // ⑤ 弱引用：数据内部回指，防循环

    ABossFighter() {
        Stats = MakeShared<FStatSheet>();       // ③
        Combo  = MakeUnique<FComboData>();      // ④
        // ⑤ 让 FStatSheet 能弱引用回角色，且不增加计数 → 不泄漏
        Stats->Owner = this;                    // Owner 是 TWeakObjectPtr<ABossFighter>
    }
};
```

**每一处的判断逻辑（照这个思路选型）**：

| 指针 | 在这个场景 | 判断依据 |
|------|-----------|---------|
| ① `TObjectPtr` 锁定目标 | 长期持有敌人，打它 | 目标必须活着 → 强引用防 GC |
| ② `TWeakObjectPtr` 记录凶手 | 只记"谁打的"，可被销毁 | 不想保住它 → 弱引用，自动失效 |
| ③ `TSharedPtr` 战斗数据 | 面板/HUD/日志都要读 | 多处共享 → 引用计数 |
| ④ `TUniquePtr` 连击数据 | 只属于这个角色 | 独有 → 独占所有权 |
| ⑤ `TWeakPtr` 回指 | 数据回指角色，防循环 | 子引用父 → 弱引用不计数 |

> **核心心法**：先问"这对象是 UObject 吗"决定用哪套世界；再问"我要不要保住它 / 谁共享它 / 是不是独有"决定具体用哪个指针。

## 九、要不要现在学？

**可以延后**，但要分清楚：

- **TObjectPtr / TWeakObjectPtr**：写 UObject 代码时**迟早要遇到**，但现在只要知道"看到 TObjectPtr 就当裸指针"即可，先不深究。
- **TSharedPtr / TWeakPtr / TUniquePtr**：等你写**非 UObject 的 C++ 类**、或看插件源码时再系统学。
