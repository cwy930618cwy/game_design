# 08 — 异步与任务系统详解（Async/ + Tasks/）

> **定位**：Core 里让代码"不卡顿、能多线程干活"的两块——`Async/`（异步任务）和 `Tasks/`（新版任务系统）。
>
> **一句话**：**异步 = 把耗时操作放到后台做，主线程不卡**。`Future`/`Promise` 是"拿结果"，`ParallelFor` 是"并行循环"，`TaskGraph`/`Tasks` 是"任务调度"。日常最常用的是 `ParallelFor` 和 `AsyncTask`。
>
> **文件**：`Core/Public/Async/`、`Core/Public/Tasks/`

---

## 一、先搞懂：为什么要"异步"？（卡顿的来源）

游戏是**逐帧渲染**的，主线程（游戏线程）要做很多事。如果主线程卡在一个耗时操作上，**这一帧就慢了 → 掉帧/卡顿**。

```cpp
// ❌ 主线程做耗时操作 → 卡顿
void OnLoad() {
    LoadHugeAsset();   // 加载大资源，可能要几秒
    // 这几秒主线程卡住，游戏画面冻结
}
```

**异步解决**：把耗时活**扔到后台线程**做，主线程继续跑，等后台做完再拿结果。

```
❌ 同步（卡）：主线程 → [加载大资源 3 秒] → 继续
✅ 异步（不卡）：主线程 → [继续渲染...] 
                后台线程 → [加载大资源] → 好了通知主线程
```

```
Core/Public/Async/
├── Future.h              ← Future/Promise：拿异步结果

```

| 工具 | 干什么的 | 常用度 |
|------|---------|:---:|
| **`ParallelFor`** | 并行执行 for 循环 | ⭐⭐ |
| **`AsyncTask` / `Async()`** | 快速把任务扔后台 | ⭐⭐ |
| **`Future` / `Promise`** | 异步任务结束后拿返回值 | ⭐ |
| **`TaskGraph`** | 复杂的任务图调度（老派） | ⭐ |

## 三、重点讲解（配具体场景）

### 3.1 ParallelFor —— 并行循环（最常用）

把一个大 for 循环拆成多线程同时跑，大幅提速：

```cpp
// ❌ 普通 for：单线程，慢
for (int32 i = 0; i < 100000; i++) {
    ProcessItem(i);
}

// ✅ ParallelFor：多线程并行，快
ParallelFor(100000, [](int32 i) {
    ProcessItem(i);   // 每个 i 在不同的线程上跑
});
```

**具体场景**：批量处理大量网格顶点、大量单位寻路：

```cpp
// 1000 个敌人同时更新 AI，用并行
ParallelFor(Enemies.Num(), [&](int32 i) {
    Enemies[i]->UpdateAI();
});
```

> ⚠️ **注意**：`ParallelFor` 里**不能访问共享变量**（会数据竞争），只处理"每项独立"的数据。

### 3.2 AsyncTask / Async —— 快速扔后台

想快速把一段代码放到后台线程，用 `Async`：

```cpp
#include "Async/Async.h"

// 把加载扔到后台线程
Async(EAsyncExecution::ThreadPool, [this]() {
    LoadHugeAsset();          // 后台执行
});
```

**具体场景**：加载地图不卡主线程：

```cpp
void AMyGameMode::LoadLevel() {
    // 后台线程加载资源
    Async(EAsyncExecution::ThreadPool, []() {
        LoadHugeAsset();
    });
    // 主线程不卡，继续跑
}
```

> **EAsyncExecution 参数**：`ThreadPool`（后台线程池）、`TaskGraph`（任务图）、`Thread`（专用线程）。

### 3.3 Future / Promise —— 拿异步结果

`Future` 像"一个未来才有的值"。你发起异步任务，`Future` 会装"完成后的结果"，到时要 `Get()`：

```cpp
#include "Async/Future.h"

// 发起一个异步任务，返回 Future
TFuture<int32> Result = Async(EAsyncExecution::ThreadPool, []() {
    // 后台算一个值
    return 42;
});

// 等结果（会阻塞直到完成）
int32 Value = Result.Get();   // 拿到 42
```

**具体场景**：后台加载资源，加载完拿结果：

```cpp
// 后台读取配置，返回 Future
TFuture<FString> Config = Async(EAsyncExecution::ThreadPool, []() {
    return ReadConfigFile();   // 后台读文件
});

// 需要时再拿（此时可能已完成）
FString Content = Config.Get();
```

> **注意**：`Future::Get()` 会**等待**直到结果可用（阻塞）。如果不想阻塞，用 `IsReady()` 先检查。

### 3.4 TaskGraph / Tasks —— 任务系统

**老派（TaskGraph）**：复杂的多线程任务图，每个任务可依赖别的任务，按依赖关系调度。

**新版（Tasks/，UE5 推荐）**：更简单现代，用 `UE::Tasks`：

```cpp
#include "Tasks/Task.h"

// 创建一个任务
UE::Tasks::FTask MyTask = UE::Tasks::Launch(TEXT("MyTask"), []() {
    DoWork();
});

// 等它完成
MyTask.Wait();
```

**具体场景**：多个任务并行做，做完再统一收尾：

```cpp
using namespace UE::Tasks;
// 三个并行任务
FTask T1 = Launch(TEXT("LoadMesh"), [] { LoadMesh(); });
FTask T2 = Launch(TEXT("LoadTexture"), [] { LoadTexture(); });
FTask T3 = Launch(TEXT("LoadSound"), [] { LoadSound(); });
// 等全部完成
Wait(TArray{ T1, T2, T3 });
```

## 四、Async/ 和 Tasks/ 的区别（别搞混）

| | `Async/`（老派） | `Tasks/`（新版，UE5） |
|---|---|---|
| 代表 | TaskGraph、Future、ParallelFor | `UE::Tasks` 任务系统 |
| 风格 | 较老、功能多 | 更现代、更简单 |
| 常用 | `ParallelFor`、`Async()` | `UE::Tasks::Launch` |
| 推荐度 | 部分仍用 | **新版推荐** |

**给你的建议**：
- **`ParallelFor`**（并行循环）和 **`Async()`**（扔后台）是**最常用的**，先掌握这两个
- **`UE::Tasks`** 是未来的方向，进阶再学
- 复杂的 `TaskGraph` / `Future` **用到再看**

## 五、日常开发要学吗？—— 分轻重

| 工具 | 日常用得勤吗 | 建议 |
|------|:---:|------|
| `ParallelFor` | 处理大量数据用 | **必学**（提速神器） |
| `Async()` | 加载/耗时操作 | **常用**（不卡主线程） |
| `UE::Tasks` | 现代任务 | 进阶学 |
| `Future` / `Promise` | 拿结果 | 用到再看 |
| `TaskGraph` | 老派复杂 | 不用主动学 |

**结论**：
1. **先掌握 `ParallelFor`（并行循环）和 `Async()`（扔后台）**，这俩解决 90% 的卡顿问题
2. 复杂的（TaskGraph、Future）**用到再看**
3. 记住核心思想：**耗时操作放后台，主线程不卡**

## 六、常见陷阱

**① ParallelFor 里改共享变量 → 数据竞争/崩溃**
```cpp
// ❌ 并行里改共享数组，会冲突
int32 Sum = 0;
ParallelFor(N, [&](int32 i) { Sum += i; });   // 危险！
// ✅ 用原子操作或每个线程独立累加
```

**② 在后台线程访问 UObject → 崩溃**
```cpp
// ❌ 后台线程碰 UObject，UObject 不是线程安全的
Async(EAsyncExecution::ThreadPool, [this]() {
    Actor->DoSomething();   // 危险！UObject 要在游戏线程操作
});
// ✅ UObject 操作要回游戏线程
Async(EAsyncExecution::TaskGraphMainThread, [this]() {
    Actor->DoSomething();   // 回主线程再操作 UObject
});
```

**③ 主线程做大量计算（该用 ParallelFor 却没用）**
```cpp
// ❌ 大量计算单线程跑，慢
for (int i = 0; i < 100000; i++) Process(i);
// ✅ 用并行
ParallelFor(100000, [](int32 i) { Process(i); });
```

## 七、总结速查

```
Async/ = 异步任务
├── ParallelFor(n, lambda)   ← 并行循环（最常用，提速）
├── Async(ThreadPool, lambda) ← 扔后台线程（不卡主线程）
├── TFuture + Async(...)      ← 拿异步结果
└── TaskGraph                 ← 老派复杂调度

Tasks/ = 新版任务系统
└── UE::Tasks::Launch(name, lambda) + Wait()

核心思想：耗时操作放后台，主线程不卡
日常先用：ParallelFor（循环）+ Async()（扔后台）
```

**一句话**：异步 = "把耗时活放后台，主线程不卡"。你日常最常用 `ParallelFor`（并行循环提速）和 `Async()`（扔后台），这两个就够解决大部分卡顿。TaskGraph / Future / UE::Tasks 是进阶，用到再看。

---

## 八、什么时候深入？

- **现在**：掌握 `ParallelFor`（并行循环）和 `Async()`（扔后台）
- **处理大量数据**时：用 ParallelFor 提速
- **加载/读文件卡顿**时：用 Async 扔后台
- **做复杂异步依赖**时：再学 UE::Tasks / TaskGraph

> 和其他笔记一样：**先会用高频的（ParallelFor、Async），再深入复杂的（Tasks、TaskGraph）**。
