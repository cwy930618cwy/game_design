# 从打开游戏那一刻起，发生了什么？—— Lyra 启动全流程

> **定位**：跟着"玩家双击图标 → 进入一局游戏"这条线，把 Lyra 从进程启动到能玩的全过程串起来。**承接 [03_四大核心概念](./03_Lyra四大核心概念_ModularGameplay_GameMode_Experience_GameFeature.md)，把那四个概念在"启动时"怎么依次登场讲清楚。**
>
> **一句话**：打开游戏 = **引擎启动 → 创建 GameInstance → 加载 Experience（数据）→ 启用 GameFeature 插件 → 执行 Actions 注入功能 → GameMode 就位 → 生成玩家 → 能玩了**。其中"加载 Experience"这一步内部有个状态机：`Unloaded → Loading → LoadingGameFeatures → Loaded`。

---

## 一、先看全局时间线（鸟瞰）

```
【0. 进程启动】
  双击游戏图标 → 引擎(UE)启动 → 读 DefaultEngine.ini
        ↓
【1. 创建 GameInstance】
  引擎创建 ULyraGameInstance（全局单例，跨关卡不销毁）
        ↓
【2. 进入主菜单/大厅】
  加载前端地图(Frontend)，玩家在菜单选模式
        ↓
【3. 确定要玩什么 → 设置 Experience】
  选"射击模式" → 告诉系统要加载哪个 Experience
        ↓
【4. 加载 Experience（核心，有状态机）】★
  Unloaded → Loading → LoadingGameFeatures → Loaded
        ↓
【5. 启用 GameFeature 插件】
  按 Experience 里的 GameFeaturesToEnable 拉起插件
        ↓
【6. 执行 Actions 注入功能】
  GameFeature 通过 ModularGameplay Actions 把组件/能力/输入插进游戏
        ↓
【7. GameMode 就位 + 生成玩家】
  按 Experience 配置创建 GameMode、生成 Pawn、发装备
        ↓
【8. 能玩了 🎮】
```

> 下面逐段展开，重点讲【4】【5】【6】（Experience 加载 + GameFeature 启用，这是 Lyra 架构的精华）。

## 二、阶段 0-1：引擎启动 + 创建 GameInstance

### 0. 进程启动

```
双击图标
  → 引擎启动（UnrealEngine 那套：加载核心模块、初始化渲染/RHI/物理...）
  → 读 DefaultEngine.ini
     - 里面配了 AssetManagerClassName = LyraAssetManager（第 01 篇讲过）
     - 配了 GameInstance 类、默认地图等
```

### 1. 创建 GameInstance

```
引擎创建 ULyraGameInstance（全局单例）
  - GameInstance 是"跨关卡一直存在"的对象
  - 玩家从主菜单→游戏→回菜单，GameInstance 始终是同一个
  - Lyra 用它做全局管理（会话、前端状态等）
```

> **呼应前面**：`ULyraGameInstance` 就是之前看 `LyraGameInstance.cpp` 时那个类（有 `namespace Lyra` 和 DTLS 加密 CVar 的那个文件）。

## 四、阶段 4：加载 Experience（核心状态机）★

这是整个启动最关键的阶段。`ULyraExperienceManagerComponent`（挂在 GameState 上的组件）负责，内部有个**加载状态机**：

```cpp
enum class ELyraExperienceLoadState
{
    Unloaded,           // 未加载
    Loading,            // 正在加载资源
    LoadingGameFeatures,// 正在启用 GameFeature 插件
    Loaded,             // 加载完成
    // ...
};
```

### 加载的四个步骤（真实函数链）

```
SetCurrentExperience(ExperienceId)
        ↓
① StartExperienceLoad()         [状态: Loading]
   用 AssetManager 异步加载 Experience 资产本身
   （Experience 里引用的资源：Action、PawnData 等）
        ↓ 加载完成回调
② OnExperienceLoadComplete()
   读出 Experience 里的 GameFeaturesToEnable（要启用哪些插件）
   把插件名转成插件 URL
        ↓
③ 启用 GameFeature 插件          [状态: LoadingGameFeatures]
   对每个插件调 LoadAndActivateGameFeaturePlugin(...)
   每启用一个，回调 OnGameFeaturePluginLoadComplete()
   （NumGameFeaturePluginsLoading 计数，全部完成才往下）
        ↓ 所有插件启用完毕
④ OnExperienceFullLoadCompleted() [状态: Loaded]
   触发 OnExperienceLoaded 系列委托（高/中/低优先级）
   通知全系统："Experience 就绪，可以开始玩了"
```

### 看真实代码（关键片段）

```cpp
// ① 开始加载
void ULyraExperienceManagerComponent::StartExperienceLoad()
{
    LoadState = ELyraExperienceLoadState::Loading;
    // 用 AssetManager 异步加载 Experience 资产
    RawLoadHandle = AssetManager.LoadAssetList(..., &ThisClass::OnExperienceLoadComplete);
}

// ② 加载完 → 启用 GameFeature 插件
void ULyraExperienceManagerComponent::OnExperienceLoadComplete()
{
    // 收集 Experience 里 GameFeaturesToEnable 的插件 URL
    LoadState = ELyraExperienceLoadState::LoadingGameFeatures;
    for (const FString& PluginURL : GameFeaturePluginURLs)
    {
        // ③ 逐个启用插件
        UGameFeaturesSubsystem::Get().LoadAndActivateGameFeaturePlugin(
            PluginURL,
            FGameFeaturePluginLoadComplete::CreateUObject(this, &ThisClass::OnGameFeaturePluginLoadComplete));
    }
}

// ③ 每个插件启用完，计数 -1，全部完成则进入 ④
void ULyraExperienceManagerComponent::OnGameFeaturePluginLoadComplete(...)
{
    NumGameFeaturePluginsLoading--;
    if (NumGameFeaturePluginsLoading == 0)
        OnExperienceFullLoadCompleted();   // ④ 全部就绪
}
```

> **要点**：Experience 加载不是"一步到位"，而是"**加载资源 → 启用插件 → 全部就绪**"三段式，用状态机 + 计数管理多个插件的异步加载。

## 五、阶段 5-6：GameFeature 启用 + Actions 注入

### 5. 启用 GameFeature 插件

```
LoadAndActivateGameFeaturePlugin(插件URL)
  → 加载插件的代码 + 资源
  → 插件"激活"，它提供的 GameFeatureAction 准备就绪
```

### 6. 执行 Actions 注入功能（ModularGameplay 登场）

Experience 里有一组 `Actions`（`UGameFeatureAction`）：

```cpp
// LyraExperienceDefinition.h
// 加载/激活/停用/卸载时分别要执行的 Action 列表
UPROPERTY(EditDefaultsOnly, Instanced, Category="Actions")
TArray<TObjectPtr<UGameFeatureAction>> Actions;
```

**这些 Action 就是"注入"的具体动作**——通过 ModularGameplay 框架，往游戏各部位插东西：
- 给 Pawn 加组件（如血量、武器）
- 给角色加能力（GAS 的 GameplayAbility）
- 加输入映射（EnhancedInput）
- 加 UI、加 GameFeature 相关逻辑

```
Experience 加载完成
  → 遍历 Actions 列表
  → 每个 Action 通过 ModularGameplay 的接口
     把"射击组件/能力/输入"等插进 Pawn、控制器
  → 功能就位
```

> **这就是第 03 篇说的"GameFeature 通过 ModularGameplay 即插即用"**——具体发生就在这里：Experience 的 Actions 在加载完成时执行注入。

---

## 七、阶段 7-8：GameMode 就位 + 生成玩家

### 7. GameMode 就位

```
Experience 就绪后，进入对应地图
  → 地图指定了用哪个 GameMode（ALyraGameMode）
  → GameMode 读取 Experience 的配置（DefaultPawnData 等）
```

Experience 里配了默认 Pawn：
```cpp
// LyraExperienceDefinition.h
// 为玩家生成的默认 Pawn 数据
UPROPERTY(EditDefaultsOnly, Category=Gameplay)
TObjectPtr<const ULyraPawnData> DefaultPawnData;
```

### 8. 生成玩家

```
GameMode 按 Experience 配置：
  → 为每个玩家生成 PlayerController
  → 按 DefaultPawnData 生成 Pawn（角色）
  → 通过前面注入的能力/组件，装备武器、初始化血量
  → 玩家出生，可以操作了
        ↓
【能玩了 🎮】
```

## 九、四大概念在启动时怎么登场（呼应第 03 篇）

| 概念 | 启动时的角色 | 何时登场 |
|------|-------------|---------|
| **Experience** | 加载的"配方" | 阶段 4，整个加载流程围绕它 |
| **GameFeature** | 被启用的插件 | 阶段 5，`LoadingGameFeatures` 状态 |
| **ModularGameplay** | 注入功能的机制 | 阶段 6，Actions 执行时 |
| **GameMode** | 执行规则、生成玩家 | 阶段 7-8，最后登场 |

> **串起来**：**Experience 是启动的核心驱动**——它一加载，就拉起 GameFeature，GameFeature 借 ModularGameplay 注入功能，最后 GameMode 按它的配置生成玩家。**Experience 是开关，其余三者依次响应。**

## 十、几个关键设计点

### ① 为什么用状态机管理加载？
因为要**异步加载多个 GameFeature 插件**，每个耗时不定。用状态机 + 计数（`NumGameFeaturePluginsLoading`）能精确知道"全部插件都启用完了吗"，避免"玩家进游戏了插件还没加载完"的 bug。

### ② 为什么分高/中/低优先级委托？
Experience 加载完成后，不同系统要在"不同时机"响应（如先初始化核心系统，再初始化 UI）。`OnExperienceLoaded_HighPriority` / `_LowPriority` 让各系统按优先级排队，避免时序混乱。

### ③ 加载界面（Loading Screen）怎么来的？
`ULyraExperienceManagerComponent` 实现了 `ILoadingProcessInterface`——加载期间 `ShouldShowLoadingScreen` 返回 true，显示加载界面，直到 Experience 就绪。这就是 Lyra 那个加载进度条的来源。

### ④ 网络同步
`CurrentExperience` 是 `Replicated` 的（`OnRep_CurrentExperience`）——服务器上确定 Experience 后，同步给所有客户端，保证所有人玩的是同一个模式。

## 十二、总结速查

```
打开游戏的全流程：
  引擎启动 → 创建 GameInstance → 主菜单选模式
    → 加载 Experience（核心状态机）
        Unloaded → Loading → LoadingGameFeatures → Loaded
    → 启用 GameFeature 插件（按 GameFeaturesToEnable）
    → Actions 经 ModularGameplay 注入功能
    → GameMode 就位 → 生成玩家 → 能玩了

关键组件：
  ULyraExperienceManagerComponent（挂 GameState）驱动整个加载
  状态机 + 计数管理多插件异步加载
  高/中/低优先级委托协调各系统响应时机

四大概念登场顺序：
  Experience（驱动）→ GameFeature（被启用）
    → ModularGameplay（注入机制）→ GameMode（执行/生成玩家）
```

**一句话**：打开游戏 = 引擎启动 → 创建 `ULyraGameInstance` → 主菜单选模式 → **加载 Experience**（核心，状态机 `Unloaded→Loading→LoadingGameFeatures→Loaded`）→ 按 `GameFeaturesToEnable` 启用 **GameFeature** 插件 → 通过 **ModularGameplay** 执行 Actions 注入功能 → **GameMode** 按 Experience 配置生成玩家 → 能玩了。Experience 是整个启动的驱动核心，其余三者依次响应。
