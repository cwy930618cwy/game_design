# Lyra 启动流程人物谱 —— 用一座"游戏剧院"讲明白

> **定位**：为了让你轻松理解 [Lyra 启动全流程](../Lyra_5.6/04_从打开游戏那一刻_启动全流程.md)，把每个技术组件**拟人化**成一座"游戏剧院"里的角色。之后讲启动流程，就是讲"这些角色在一场演出前怎么依次登场、协作"。
>
> **一句话**：把 Lyra 想象成**一座大剧院**——每开一局游戏 = 上演一场演出。剧院里有一整套班子：总管、仓管、剧本、插座标准、外请节目、导演、场记。启动流程就是"开演前大家各就各位"的过程。

---

## 一、世界观：Lyra = 一座"游戏剧院"

```
整个 Lyra 游戏  =  一座大剧院
一局游戏        =  一场演出
玩家            =  观众
启动游戏        =  开演前的准备 + 正式开演
```

> 你要理解的所有技术组件，都是这座剧院里的**一个个人**。下面逐个认识他们。

---

## 二、人物名单（7 个核心角色）

### 👔 1. 葛总管 —— GameInstance（全局大管家）

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraGameInstance` |
| **职务** | 剧院总管 |
| **性格** | 沉稳、全局在握、从开馆就在、从不离场 |
| **口头禅** | "剧院里里外外，都归我管。" |

**他是干嘛的**：
- 剧院**一开门（游戏启动）他就上岗**，一直干到闭馆（游戏退出）。
- 员工（关卡、玩家）来来去去，演出（地图）一场换一场，**但葛总管始终在**。
- 管全局性的事：会话、登录、跨场次的状态。

> **记忆点**：`GameInstance` = 全局唯一、跨关卡不销毁的大管家。启动第一个登场的重量级角色。

---

### 📦 2. 仓管老李 —— AssetManager（资源管理员）

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraAssetManager` |
| **职务** | 剧院仓库管理员 |
| **性格** | 严谨、记性好、你要啥他都能从仓库翻出来 |
| **口头禅** | "要什么道具？报个名（路径），我去仓库给你取。" |

**他是干嘛的**：
- 剧院所有**道具/资源**（角色数据、技能、地图、音效...）都存在他的仓库里。
- 谁要用资源，找他。他负责"把东西从仓库搬出来、加载好"。
- **全剧院只有一个仓管**（单例），所以大家都认他。

> **记忆点**：`AssetManager` = 把"软引用（欠条）"兑现成"加载好的资源"的仓库总管。第 01 篇讲过他。

---

### 📜 3. 剧本小经 —— Experience（演出剧本）

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraExperienceDefinition`（数据资产） |
| **职务** | 演出剧本 / 流程策划 |
| **性格** | 死板但关键——今天演什么、怎么演，全看它 |
| **口头禅** | "别问我意见，按剧本走就对了。" |

**它是干嘛的**：
- 一本**写满流程的数据册**：今天演哪出戏（射击模式？竞技场？）、请哪些节目、用哪个导演、演员穿什么。
- **它不是人，是数据**——但它是整场演出的"最高指令"，所有人都照着它办。
- 换一本剧本，整场演出就变了（换玩法）。

> **记忆点**：`Experience` = 数据驱动的"演出配方"，启动流程的核心驱动。它一出场，后面所有人动起来。

---

### 🔌 4. 插座老王 —— ModularGameplay（接口标准制定者）

| 项 | 内容 |
|----|------|
| **技术对应** | `ModularGameplay` 框架 |
| **职务** | 舞台插座/接口标准的制定者 |
| **性格** | 低调、是"规矩"本身、不显眼但离不了 |
| **口头禅** | "只要符合我的接口，什么节目都能插上来用。" |

**他是干嘛的**：
- 制定舞台上**统一的插座规格**（标准接口）。
- 让外请节目（GameFeature）**插上就能用**，不用每次改舞台布线。
- 他本身不表演，是"让表演能即插即用"的底层机制。

> **记忆点**：`ModularGameplay` = 让 GameFeature 即插即用的"插座标准"。没有他，节目插不上舞台。

---

### 🎪 5. 外请节目团 —— GameFeature（可插拔插件）

| 项 | 内容 |
|----|------|
| **技术对应** | Game Feature Plugin（如 ShooterMaps、TopDownArena） |
| **职务** | 各路外请表演团队 |
| **性格** | 各显神通、独立成团、今天请哪团看剧本 |
| **代表** | 射击团（ShooterMaps）、竞技场团（TopDownArena）... |

**他们是干嘛的**：
- 一个个**独立的表演团队（插件）**，各有绝活（射击玩法、赛车玩法）。
- 剧院不养常驻节目，**需要哪团，今天才请（启用）**。
- 通过插座老王（ModularGameplay）的标准，把绝活插进舞台。

> **记忆点**：`GameFeature` = 即插即用的功能插件，按剧本（Experience）被启用。加新玩法 = 请个新团队。

---

### 🎬 6. 导演老规 —— GameMode（规则执行者）

| 项 | 内容 |
|----|------|
| **技术对应** | `ALyraGameMode` |
| **职务** | 整场演出的总导演 |
| **性格** | 讲规矩、铁面、输赢他说了算 |
| **口头禅** | "剧本怎么写，我就怎么导。谁赢谁输，我判。" |

**他是干嘛的**：
- 按**剧本（Experience）**执行整场演出的规则。
- 管演员（生成玩家/角色）、判胜负、管计分、管上下场（重生）。
- 他**不亲自表演**（那是节目团的活），他是**协调执行者**。

> **记忆点**：`GameMode` = 按 Experience 配置执行规则、生成玩家、判胜负的"导演大脑"。最后登场。

---

### 📋 7. 场记小流 —— ExperienceManagerComponent（加载协调员）

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraExperienceManagerComponent` |
| **职务** | 场记 / 开演流程协调员 |
| **性格** | 干练、管流程、记状态、催场一流 |
| **口头禅** | "剧本加载没？节目团到齐没？都好了才能开演！" |

**她是干嘛的**：
- 专门负责**"开演前的加载流程"**——拿着剧本（Experience）一项项落实。
- 管一个**状态清单**（状态机）：剧本拿没拿到 → 节目团到没到齐 → 可以开演没。
- 催齐所有人，确认就绪了，才通知"开演"。

> **记忆点**：`ExperienceManagerComponent` = 驱动 Experience 加载状态机（`Unloaded→Loading→LoadingGameFeatures→Loaded`）的催场员。

## 四、一场演出（启动）的登场顺序 ★

这就是启动流程，用"开演前各就各位"来讲：

```
【开演前，剧院开门】
  ① 👔 葛总管（GameInstance）第一个到岗，坐镇全局
        ↓
【观众（玩家）入场，要看今天演什么】
  ② 📜 剧本小经（Experience）拿出今天的演出剧本
        ↓
  ③ 📋 场记小流（ExperienceManager）开始催场：
        "剧本拿到了 → 去请节目团 → 都到齐 → 可以开演"
        （状态机：Unloaded → Loading → LoadingGameFeatures → Loaded）
        ↓
  ④ 🎪 外请节目团（GameFeature）被请进场
        （按剧本 GameFeaturesToEnable 启用插件）
        ↓
  ⑤ 🔌 插座老王（ModularGameplay）让节目团插上舞台
        （通过标准接口注入组件/能力/输入）
        ↓
  ⑥ 📦 仓管老李（AssetManager）把道具搬出来
        （加载角色数据、技能、武器...）
        ↓
  ⑦ 🎬 导演老规（GameMode）就位，按剧本开演
        （生成玩家、判胜负）
        ↓
【🎭 开演！观众（玩家）可以玩了】
```

> **一句话记住**：**葛总管坐镇 → 剧本定调 → 场记催场 → 请节目团 → 插座接入 → 仓管发道具 → 导演开演**。

## 五·补、幕后建造层 —— 比"开演"更早的一批人 ★

> 前面 7 个角色（葛总管、剧本小经...）都是**"游戏跑起来后才登台"的演员**。
> 但还有一批更底层的角色，他们在**"剧院还没开门营业前"**就忙活了——负责**立项、画图纸、施工、定运营手册**。没有他们，剧院根本盖不起来，更别说开演。
>
> **这一层回答一个问题**：`DefaultEngine.ini`、`.uproject`、`Target.cs`、`LyraEditor`、`LyraGame` 这些"文件/模块"到底是谁？

### 两个层次的分工

```
【幕后建造层】← 本节（游戏跑起来之前就存在，管"造剧院")
   🏛️ 立项书(.uproject) → 📐 施工总工(Target.cs) → 编译出 .dll → 📖 运营手册(ini)
        ↓ 造好、开门营业
【台上演出层】← 前面 7 人（游戏跑起来才登场，管"演好戏")
   👔 葛总管 → 📜 剧本小经 → 📋 场记 → 🎪 节目团 → 🔌 插座老王 → 📦 仓管 → 🎬 导演
```

---

### 🏛️ 8. 项目立项书 —— `LyraStarterGame.uproject`

| 项 | 内容 |
|----|------|
| **技术对应** | `LyraStarterGame.uproject`（项目文件） |
| **职务** | 剧院的"营业执照 + 组织架构总表" |
| **性格** | 是"总纲"本身、不干活、但所有人都由它定义 |
| **口头禅** | "我这剧院有哪些部门、请了哪些团，全在这张纸上。" |

**它是干嘛的**：
- 一张**总清单**，定义这座剧院的骨架：
  - **有哪些部门（模块）**：看真实内容——`LyraGame`（运行时主模块）、`LyraEditor`（编辑器模块）。
  - **请了哪些常驻团（插件）**：清单里那一长串 `Plugins`——GAS、ModularGameplay、CommonUI、ShooterMaps... 几十个。
- 它**不执行任何逻辑**，只是"声明"——告诉引擎"这个剧院由这些模块和插件组成"。
- 引擎/编辑器一打开项目，先读它，才知道要加载哪些模块、启用哪些插件。

> **记忆点**：`.uproject` = 项目总立项书。它说"有哪些模块+哪些插件"，是整栋剧院的**设计总图**。它不是人，是"名单"。

---

### 📐 9. 施工总工 —— `*.Target.cs`（如 `LyraClient.Target.cs`）

| 项 | 内容 |
|----|------|
| **技术对应** | `LyraClient.Target.cs` / `LyraServer.Target.cs` / `LyraEditor.Target.cs`... |
| **职务** | 打包施工总工 |
| **性格** | 务实、管"盖成什么用途"、一种目标一份图纸 |
| **口头禅** | "同样一堆砖，我能盖成客户端、服务器、编辑器——用途不同，方案不同。" |

**他是干嘛的**：
- 告诉编译工具（UBT）**"把这一堆模块，打包成什么用途的程序"**。
- 看真实内容——`LyraClient.Target.cs` 就三行核心：
  ```csharp
  Type = TargetType.Client;                          // 盖成"客户端"用途
  ExtraModuleNames.AddRange(new string[] { "LyraGame" });  // 把 LyraGame 这个主模块打进去
  LyraGameTarget.ApplySharedLyraTargetSettings(this);      // 套用共享配置
  ```
- **一个 Target 对应一种产物**：
  - `LyraClient.Target.cs` → 玩家玩的**客户端**
  - `LyraServer.Target.cs` → 专用的**服务器**
  - `LyraEditor.Target.cs` → 开发用的**编辑器**
- 同样一堆源码，施工总工用不同图纸，盖出**不同用途的楼**。

> **记忆点**：`Target.cs` = 打包施工图纸。它决定"哪些模块组成、盖成客户端还是服务器"。**编译时**起作用，运行时已经不在场了。

---

### 🔧 10. 装修彩排队 —— `LyraEditor`（编辑器模块）

| 项 | 内容 |
|----|------|
| **技术对应** | `Source/LyraEditor/`（含 Commandlets、Utilities、Validation 等） |
| **职务** | 装修 + 彩排团队 |
| **性格** | 只在"装修阶段"干活、正式开演就退场 |
| **口头禅** | "编辑器的活儿归我，游戏一跑起来就没我事了。" |

**他是干嘛的**：
- 一堆**只在编辑器里才需要**的工具代码：资源校验（Validation）、命令行工具（Commandlets）、编辑器辅助（Utilities）。
- 关键特性：**`.uproject` 里标了 `"Type": "Editor"`**——意味着它**只在编辑器环境加载**。
- 玩家双击游戏跑起来（正式演出）时，**装修队退场，`LyraEditor` 不参与运行**。

> **记忆点**：`LyraEditor` = 只活在编辑器里的装修队。`Type: Editor` 决定了它"运行时不登场"。你之前看的那个文件夹就是它。

---

### 🎭 11. 主演出团 —— `LyraGame`（运行时主模块）

| 项 | 内容 |
|----|------|
| **技术对应** | `Source/LyraGame/`（450+ 文件，游戏核心逻辑） |
| **职务** | 常驻主演出团（真正的游戏逻辑） |
| **性格** | 主力、最忙、前面所有演员都归它编制 |
| **口头禅** | "游戏真正跑起来的那套逻辑，全在我这儿。" |

**他是干嘛的**：
- **游戏运行时的核心模块**——前面讲的**所有台上演员都在这**：
  - 👔 葛总管（GameInstance）、🎬 导演老规（GameMode）、📜 剧本相关、📦 仓管老李（AssetManager）... 全在 `LyraGame` 里。
- `.uproject` 里标了 `"Type": "Runtime"`——**运行时主力**，客户端和服务器都要它。
- 施工总工打包时（`ExtraModuleNames = "LyraGame"`），第一个就把它打进去。

> **记忆点**：`LyraGame` = 运行时主模块，前面那批"台上演员"的**所属单位**。它是真正承载游戏逻辑的地方。

---

### 📖 12. 运营手册 —— `DefaultEngine.ini`

| 项 | 内容 |
|----|------|
| **技术对应** | `Config/DefaultEngine.ini`（引擎启动配置） |
| **职务** | 引擎启动时读的"员工名册 / 运营手册" |
| **性格** | 引擎的"最高指示"、引擎全靠它知道用谁 |
| **口头禅** | "店长是谁、用什么规则、默认进哪个厅——都写在我这儿，引擎照着我点名。" |

**它是干嘛的**：
- 引擎启动时**第一件事就是读它**，从中知道"这个游戏要用哪些自定义类"。看真实配置：
  ```ini
  [/Script/EngineSettings.GameMapsSettings]
  GameInstanceClass=/Game/B_LyraGameInstance...   ← 店长 = GameInstance
  GlobalDefaultGameMode=/Game/B_LyraGameMode...   ← 默认导演 = GameMode
  GameDefaultMap=/Game/System/FrontEnd/...        ← 默认进主菜单厅
  AssetManagerClassName=/Script/LyraGame.LyraAssetManager  ← 仓管 = AssetManager
  ```
- **引擎本身不知道 Lyra 用谁**——它靠这份手册"点名"：
  - 读到 `GameInstanceClass` → 知道"要请葛总管（GameInstance）上岗"。
  - 读到 `AssetManagerClassName` → 知道"仓管老李（AssetManager）是这位"。
- 这就是为什么 Lyra 能用自己的 GameInstance/GameMode/AssetManager **替换引擎默认的**——手册上改了名，引擎就换人。

> **记忆点**：`DefaultEngine.ini` = 引擎启动读的运营手册/名册。它把"抽象的类名"和"引擎要用的岗位"对应起来。**引擎是配置驱动的**，全靠它。

### 幕后层的协作时间线

```
【开发/编译期 —— 造剧院】
  🏛️ 立项书(.uproject)：声明"剧院由 LyraGame+LyraEditor 两个部门 + 几十个插件组成"
        ↓
  📐 施工总工(Target.cs)：按用途出图纸
        - LyraClient → 盖成客户端（打入 LyraGame）
        - LyraServer → 盖成服务器
        - LyraEditor → 盖成编辑器（只带 LyraEditor 部门）
        ↓
  🔨 编译 → 生成一堆 .dll（LyraGame.dll、LyraEditor.dll...）
        （🔧 装修彩排队 LyraEditor 只进编辑器版；🎭 主演出团 LyraGame 进客户端+服务器）

【运行期 —— 开门营业】
  双击图标 → 引擎启动
        ↓
  📖 运营手册(DefaultEngine.ini)：引擎读它，知道"店长=GameInstance、导演=GameMode、仓管=AssetManager"
        ↓
  🎭 主演出团(LyraGame.dll)里的角色开始登场...
        ↓
  👔 葛总管(GameInstance)第一个上台 → 后面接前面那 7 人演出流程
```

### 幕后层速查表

| 角色 | 技术对应 | 一句话 | 何时起作用 |
|------|---------|--------|-----------|
| 🏛️ 立项书 | `.uproject` | 声明有哪些模块+插件 | 打开项目/编译时 |
| 📐 施工总工 | `*.Target.cs` | 决定打包成客户端/服务器/编辑器 | 编译时 |
| 🔧 装修彩排队 | `LyraEditor` | 只在编辑器干活的模块 | 仅编辑器 |
| 🎭 主演出团 | `LyraGame` | 运行时核心逻辑模块 | 运行时 |
| 📖 运营手册 | `DefaultEngine.ini` | 引擎启动读的名册，决定用哪些类 | 引擎启动瞬间 |

> **回答你的问题"谁在管"**：
> - **模块/插件由谁管** → 🏛️ 立项书(`.uproject`)登记名单。
> - **打包成什么由谁管** → 📐 施工总工(`Target.cs`)出图纸。
> - **运行时用哪些类由谁管** → 📖 运营手册(`DefaultEngine.ini`)点名。
> - **谁真正干活** → 🎭 主演出团(`LyraGame`)承载所有运行时逻辑。

## 六、怎么用这套人物

之后再看启动流程、四大概念，都可以套用这套角色：

- 看到"加载 Experience" → 想"📜 剧本小经拿出剧本，📋 场记小流开始催场"
- 看到"启用 GameFeature" → 想"🎪 按剧本请节目团进场"
- 看到"ModularGameplay 注入" → 想"🔌 插座老王让节目插上舞台"
- 看到"GameMode 生成玩家" → 想"🎬 导演老规按剧本开演"

> **故事化记忆**：技术流程 = 一场演出的开演准备。每个组件是一个有性格的人，他们按顺序登场、各司其职，最终"开演"（玩家能玩）。
