# 开演后人物谱 —— 玩家怎么"附身"到角色上（Character / Player / System）

> **定位**：[01_启动流程人物谱](./01_Lyra启动流程人物谱.md) 讲到"⑦ 导演老规（GameMode）就位 → 🎭 开演"。本文接着讲**开演之后**：导演把玩家生成出来，玩家怎么操作到场上角色、角色的血量/生死/移动怎么管。
>
> **涉及目录**：`LyraGame/Character`（角色身体）、`LyraGame/Player`（玩家/控制器/状态）、`LyraGame/System`（支撑系统）。
>
> **一句话**：开演后，**真实的你（LocalPlayer）→ 通过遥控器（PlayerController）→ 附身到场上演员（Character）身上**；演员身上挂着一堆"功能零件"（移动、血量、输入、技能），由"装配组长"（PawnExtension）协调装配。

---

## 一、承接：导演开演后，发生什么？

```
【前情】🎬 导演老规（GameMode）就位，喊"开演"
        ↓
① 导演叫"上场口管理员"给玩家挑个上场点
② 导演"生成"出场上演员（Character）
③ 真实的你（LocalPlayer）通过遥控器（PlayerController）附身到演员身上
④ 演员身上的零件（移动/血量/输入/技能）逐个装配就绪
⑤ 你能操作了 —— 跑、跳、开枪、放技能
```

> **本文回答**：这 5 步里，每个"谁"是谁、管什么、互相怎么连。

---

## 二、两条核心链（先看懂这个，人物就通了）★

Lyra 里"玩家玩角色"靠**两条链**，别混：

### 链 A：操控链（谁在控制谁）

```
🎮 真实的你  ──▶  🎯 遥控器  ──▶  🎭 场上演员
(LocalPlayer)    (PlayerController)   (Character/Pawn)
 真人+键鼠手柄     你的"游戏内化身"      场上真正跑动的身体
```

- **你**（LocalPlayer）是真人，坐在设备前。
- **遥控器**（PlayerController）是你在游戏里的"化身/替身"——你按的键，先给它，它再转交给演员。
- **演员**（Character）是场上真正移动、开火的那个身体。

### 链 B：数据链（角色的"档案"和"技能库"放哪）

```
📊 记分牌(PlayerState) ──保管──▶ 🫀 技能库(ASC)
       │                            （技能/血量属性都在这）
       │
📋 角色设计稿(PawnData) ──定义──▶ 🎭 演员用什么身体、什么技能、什么操作
```

- **记分牌**（PlayerState）记录这个玩家的分数/队伍，还**保管技能库（ASC）**。
- **角色设计稿**（PawnData）是一张数据表，规定"这个演员该用什么身体、哪些技能、哪套操作"。

> **关键区分**：**控制器（PlayerController）管"操作"，状态（PlayerState）管"数据"**。一个像遥控器，一个像记分牌，别混。

## 三、人物名单（开演后的 9 个角色）

### 🎮 13. 观众本人 —— `ULyraLocalPlayer`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraLocalPlayer`（Player 目录） |
| **职务** | 坐在设备前的**真实玩家**（你） |
| **口头禅** | "我就是玩家本人，键盘手柄在我手里。" |

**他是干嘛的**：
- **代表"真人"**——一台机器上玩游戏的这个真实的人。
- 管本地的事：本地设置（画质/音量 `GetLocalSettings`）、存档设置（`GetSharedSettings`）、创建自己的控制器（`SpawnPlayActor`）。
- 是**操控链的源头**——你的操作，从这儿出发。

> **记忆点**：`LocalPlayer` = 真人玩家。一个本地玩家对应一个 PlayerController（遥控器）。

---

### 🎯 14. 遥控器 —— `ALyraPlayerController`

| 项 | 内容 |
|----|------|
| **技术对应** | `ALyraPlayerController`（Player 目录） |
| **职务** | 玩家在游戏中的**化身/遥控器** |
| **口头禅** | "玩家按的键先给我，我转交给场上演员。" |

**他是干嘛的**：
- **操控链的中间人**——接收你的输入，转交给控制的演员（Pawn）。
- 关键动作（看头文件重写）：
  - `OnPossess` / `OnUnPossess` → **附身/脱离**某个演员（"接管"某个角色）。
  - `InitPlayerState` → 初始化自己的记分牌。
  - `UpdateHiddenComponents` → 决定哪些东西该藏（比如自己角色的某些部件）。
- 还管：HUD（`GetLyraHUD`）、自动奔跑（`SetIsAutoRunning`）、录像回放（`TryToRecordClientReplay`）。

> **记忆点**：`PlayerController` = 你的游戏内化身/遥控器。它"附身(Possess)"到某个 Pawn 上，玩家就能操作那个 Pawn。**控制器 ≠ 角色**，控制器是"操作者"，角色是"被操作的"。

---

### 🎭 15. 场上演员 —— `ALyraPawn` → `ALyraCharacter` → `ALyraCharacterWithAbilities`

| 项 | 内容 |
|----|------|
| **技术对应** | `ALyraPawn` / `ALyraCharacter` / `ALyraCharacterWithAbilities`（Character 目录） |
| **职务** | 场上**真正跑动的身体**（演员） |
| **口头禅** | "我在台上跑、跳、开枪，玩家操作的就是我。" |

**他们是一条继承链**（越来越"完整"）：

```
ALyraPawn（最基础的身体）
   └─ ALyraCharacter（加了血量、镜头、移动、生死）
        └─ ALyraCharacterWithAbilities（自带一整套技能系统）
```

| 类 | 是什么 | 加了什么 |
|----|--------|---------|
| `ALyraPawn` | 最基础的"可被控制的身体" | 能附身、管队伍 |
| `ALyraCharacter` | 完整角色 | 血量组件、镜头、移动组件、**死亡流程**（`OnDeathStarted`/`OnDeathFinished`）、蹲跳 |
| `ALyraCharacterWithAbilities` | 自带技能的角色 | 自己身上挂一套**技能系统（ASC）**（多数玩家角色的技能其实在 PlayerState 上，这种是"自带干粮"的特例） |

> **记忆点**：`Pawn` = 可被控制的身体；`Character` = 加了血量/移动/生死的完整角色。Lyra 的设计原则写在头文件注释里：**"新行为尽量加在组件里，别塞进角色类"**——所以角色本身很薄，功能都在下面的零件。

---

### 🧩 16. 装配组长 —— `ULyraPawnExtensionComponent`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraPawnExtensionComponent`（Character 目录） |
| **职务** | 演员身上的**零件装配总协调** |
| **口头禅** | "别急，等技能库接好了、输入接好了，我喊'就绪'你才能动。" |

**他是干嘛的**：
- 头文件注释原话：**"协调其他组件的初始化"**（coordinates the initialization of other components）。
- 演员身上零件多（技能、输入、血量...），**它们有先后依赖**——技能库没接好，血量组件就没法初始化。装配组长就是**"总开关+协调员"**。
- 核心职责：
  - `InitializeAbilitySystem` → 把演员接到技能库上（成为技能库的"化身 avatar"）。
  - `SetupPlayerInputComponent` → 输入接好。
  - `HandleControllerChanged` / `HandlePlayerStateReplicated` → 控制器变了、记分牌同步了，它来通知相关零件。
- 它实现了 `IGameFrameworkInitStateInterface`——**参与之前葛总管注册的那套"四阶段初始化状态机"**，确保"零件都装好，演员才就绪"。

> **记忆点**：`PawnExtensionComponent` = 装配组长/总协调。它保证"技能、输入、血量都接好了，角色才允许动"，避免"还没装好就被操作"的 bug。

---

### 🎮 17. 操作台 —— `ULyraHeroComponent`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraHeroComponent`（Character 目录） |
| **职务** | 把**输入和镜头**接到演员身上的操作台 |
| **口头禅** | "键盘手柄的按键，我翻译成演员的动作；镜头怎么转，也归我。" |

**他是干嘛的**：
- 头文件注释：**"为玩家控制的演员设置输入和镜头处理"**。
- 具体管：
  - **输入**：`Input_Move`（移动）、`Input_LookMouse`/`Input_LookStick`（视角）、`Input_Crouch`（蹲）、`Input_AbilityInputTagPressed`（放技能）——你按的键，最终由它翻译成演员动作。
  - **镜头**：`SetAbilityCameraMode`（技能可以临时改镜头，比如开镜）。
- 依赖装配组长协调初始化（注释：**"depends on a PawnExtensionComponent"**）。
- `IsReadyToBindInputs` → 只有初始化到位了，才允许绑输入（再次体现"就绪才能动"）。

> **记忆点**：`HeroComponent` = 操作台。把"玩家的按键"变成"演员的动作和镜头"。它是"输入→动作"的翻译器。

---

### 🏃 18. 身法替身 —— `ULyraCharacterMovementComponent`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraCharacterMovementComponent`（Character 目录） |
| **职务** | 管演员**怎么跑、怎么跳**的身法组 |
| **口头禅** | "走位、跳跃、加速，身体的运动全归我算。" |

**他是干嘛的**：
- 继承引擎的 `UCharacterMovementComponent`，管角色的**移动物理**：走、跑、跳、蹲、加速。
- Lyra 加了：地面检测（`GetGroundInfo`）、跳跃判定（`CanAttemptJump`）、网络同步的加速度（`SetReplicatedAcceleration`）。
- 是"演员能动"的底层执行者——操作台发出"往前走"，最终由它算出"每秒移动多少"。

> **记忆点**：`CharacterMovementComponent` = 身法替身，管移动物理。操作台发指令，它执行位移。

---

### 🩺 19. 随队医生 —— `ULyraHealthComponent`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraHealthComponent`（Character 目录） |
| **职务** | 管演员**血量和生死**的随队医生 |
| **口头禅** | "血量掉到 0？准备收工（死亡流程）。" |

**他是干嘛的**：
- 头文件注释：**"处理一切和血量相关的事"**。
- 管：当前血量（`GetHealth`）、最大血量（`GetMaxHealth`）、归一化血量（`GetHealthNormalized`）。
- **管生死**——死亡状态机（`ELyraDeathState`）：
  ```
  NotDead（活着）→ DeathStarted（开始死）→ DeathFinished（死透）
  ```
  - `StartDeath` → 开始死亡流程（关碰撞、关移动，见 `LyraCharacter::OnDeathStarted`）。
  - `FinishDeath` → 结束（脱离控制器、销毁角色）。
- 依赖技能库（`InitializeWithAbilitySystem`）——血量本质是技能系统里的一个"属性"。

> **记忆点**：`HealthComponent` = 随队医生，管血量+生死。血量归 0 → 触发死亡流程 → 角色被销毁/重生。

---

### 📊 20. 记分牌 —— `ALyraPlayerState`

| 项 | 内容 |
|----|------|
| **技术对应** | `ALyraPlayerState`（Player 目录） |
| **职务** | 记录玩家**分数/队伍**的记分牌，**技能库的保管者** |
| **口头禅** | "你的击杀、分数、队伍，都记我这儿；技能库也放我这儿。" |

**他是干嘛的**：
- **记数据**：队伍（`GetTeamId`）、小队（`GetSquadId`）、连接类型（`ELyraPlayerConnectionType`：真人/观战/回放/掉线）、统计标签（`StatTags`）。
- **★ 保管技能库（ASC）**——看头文件：`AbilitySystemComponent` 这个成员在 **PlayerState** 里！
  - 这是 Lyra 的关键设计：**玩家角色的技能系统挂在 PlayerState 上，不是挂在 Character 上**。
  - 好处：角色死了重生，身体换了，但**技能/血量属性还在记分牌里**，不丢。
- 存 `PawnData`（角色设计稿）——知道这个玩家该用什么身体。
- `OnExperienceLoaded` → 剧本（Experience）加载好了，它跟着初始化。

> **记忆点**：`PlayerState` = 记分牌 + 技能库保管员。**ASC 挂在 PlayerState 上**是 Lyra 的核心设计——身体可以换，技能数据不丢。

---

### 📋 21. 角色设计稿 —— `ULyraPawnData`

| 项 | 内容 |
|----|------|
| **技术对应** | `ULyraPawnData`（Character 目录，数据资产） |
| **职务** | 定义"这个演员该长什么样"的**数据图纸** |
| **口头禅** | "用哪具身体、哪些技能、哪套操作、什么镜头——都写在我这张纸上。" |

**它是干嘛的**：
- 一张**纯数据表**（`UPrimaryDataAsset`，和之前的 `LyraGameData` 同类），规定一个角色的全部配置：
  - `PawnClass` → 用哪具身体（`ALyraPawn`/`ALyraCharacter` 的哪个类）。
  - `AbilitySets` → 给哪些技能。
  - `InputConfig` → 用哪套操作映射。
  - `DefaultCameraMode` → 默认镜头。
- 记分牌（PlayerState）和装配组长都读它——**"按这张图纸，装配出对应的角色"**。

> **记忆点**：`PawnData` = 角色设计图纸（数据资产）。它把"用什么身体+什么技能+什么操作"打包成一张表，供装配时读取。**数据驱动**——换张图纸就换个角色。

| 项 | 内容 |
|----|------|

## 七、三个最容易晕的点（重点澄清）

### ① 遥控器 vs 演员（PlayerController vs Character）
- **遥控器（PlayerController）** = 操作者，是"你"在游戏里的化身，不移动、不开火。
- **演员（Character）** = 被操作的身体，在场上跑动、开火。
- 通过 **附身（Possess）** 连起来。你操作的是演员，但"你"是遥控器。

### ② 技能库挂在哪？—— 在记分牌（PlayerState）上，不在演员身上
- 这是 Lyra 最反直觉的设计：**ASC 属于 PlayerState**。
- 好处：演员死了重生换身体，**技能/血量属性还在记分牌里，不丢**。
- （特例：`ALyraCharacterWithAbilities` 是"自带技能库"的变体，一般角色不走这个。）

### ③ 为什么角色类很"薄"？—— 功能都在组件里
- 头文件注释明确：**"新行为尽量加在组件里"**。
- 所以 `ALyraCharacter` 本身没多少逻辑，移动/血量/输入/技能全是**组件**，由**装配组长**协调。
- 这是 UE 组件化思想 + Lyra 的模块化设计。
