# 02-4-1 — 第 02 课 · 第 4 步【1/3】：为什么要有一个"自带 ASC 的角色类"

> **对应 Lyra**：`Source/LyraGame/Character/LyraCharacterWithAbilities.h`（第 17-41 行）+ `.cpp`（第 12-38 行）
>
> **一句话**：ASC 和属性集是**组件**，必须挂在某个 Actor 身上才有"宿主"。Lyra 用 `ALyraCharacterWithAbilities` 承载它们，我们对应建 `Character/TenkaichiCharacterWithAbilities`（一比一对应，只换前缀）。本小步只讲清"**为什么要这一层、挂在身上的是谁**"，**不写代码**。

## 一、这一小步要解决什么问题

前面三步我们做了：**GAS 依赖**（第 1 步）、**属性**（Health，第 2 步）、**自定义 ASC 类**（第 3 步）。

但此刻它们都还只是"**躺在代码里的三个类**"，**没有任何东西真的生成了它们的实例**——
要想让 Health 真的存在、真的能被改、能被读出来，必须满足一个硬条件：

> **ASC 必须挂在一个活着的 Actor（Member Object）上，属性集必须作为 ASC 的子对象存在。**

所以第 4 步的目标：
- 建一个角色类 `Character/TenkaichiCharacterWithAbilities`；
- 在它的**构造函数**里把 `UTenkaichiAbilitySystemComponent` 和 `UTenkaichiHealthSet` **创建出来并挂上**。

**验收**（第 4+5 步合起来）：PIE 里角色身上能看到 ASC 与 HealthSet 两个子对象，`GetHealth()` 返回 100。

## 二、先搞懂：Lyra 里"挂 ASC"其实有**两种**挂法（重点）

打开 Lyra 真实源码，这个类文件顶部有一段关键注释（`LyraCharacterWithAbilities.h` 第 15-16 行）：

```15:16:Source/LyraGame/Character/LyraCharacterWithAbilities.h
// ALyraCharacter typically gets the ability system component from the possessing player state
// This represents a character with a self-contained ability system component.
```

翻译成人话，就是 Lyra 的**两种挂法**：

| 挂法 | 类 | ASC 在哪 | 什么时候用 |
|------|----|---------|-----------|
| **① 从 PlayerState 取** | `ALyraCharacter`（基类） | ASC 挂在 **PlayerState** 上，角色只是一个"取用者" | 玩家角色，需要**跨 Pawn 存活**（死亡重生后属性/技能还在） |
| **② 自带（self-contained）** | `ALyraCharacterWithAbilities` | ASC 直接建在**角色自己身上**（第 33 行的成员 + cpp 第 15 行创建） | NPC / 丢枪即走的短期对象，谁都可以独立完成整套 GAS |

> 类比（**这是我的类比，非源码**）：①像"**档案放在局里**"——人换了（重生），档案还在；②像"**档案自己随身带**"——人没了档案跟着走。

**我们这个教学阶段（阶段一）走②**：因为要做成一个"ACharacter 上就有 ASC"的最小可跑骨架，PlayerState 那套还没建。
> ⚠️ 这是**应用层面的选择**，不是结构简化：**一样的成员、一样的创建方式、一样泳 Lyra 第 15-21 行的写法**，只"宿主"不同。

**源码依据**（都已实际打开核对）：
- ASC 成员声明：`LyraCharacterWithAbilities.h` **第 32-33 行** `UPROPERTY(VisibleAnywhere, Category = "Lyra|PlayerState") TObjectPtr<ULyraAbilitySystemComponent> AbilitySystemComponent;`
- 属性集成员：同文件 **第 36-37 行** `UPROPERTY() TObjectPtr<const class ULyraHealthSet> HealthSet;`（Lyra 还多一个 CombatSet，第 39-40 行）
- 真正的创建：`.cpp` **第 15-21 行**
- 网络复制设置：`.cpp` **第 16-17 行**（`SetIsReplicated(true)` + `SetReplicationMode(Mixed)`）与**第 24 行**（`SetNetUpdateFrequency(100.0f)`）
- 初始化调用点：`.cpp` **第 27-33 行** `PostInitializeComponents()` 里 `InitAbilityActorInfo(this, this)` ← 这一步是**第 5 步**的内容，本步先不动

## 三、Lyra 第 19 行注释的一个"隐藏知识"（提前说，免得后面踩坑）

`.cpp` 第 19 行写着：

```19:19:Source/LyraGame/Character/LyraCharacterWithAbilities.cpp
	// These attribute sets will be detected by AbilitySystemComponent::InitializeComponent. Keeping a reference so that the sets don't get garbage collected before that.
```

两个信息：
1. **属性集不需要手动"注册"给 ASC**——`CreateDefaultSubobject` 建出来后，ASC 自己会在 `InitializeComponent` 时把它们检测进来。
2. 之所以还留一个 `UPROPERTY()` 成员持有引用，是为了**防止被人 GC 掉**。

> 所以：`UPROPERTY()` 这两个成员**不是装饰**，是"持有引用保命"。后面第 4-3 小步写 `.h` 时别省。

## 四、明确标注：我们这版 vs Lyra 的差异

| 项 | Lyra | 我们 | 说明 |
|---|------|------|------|
| 角色继承自 | `ALyraCharacter`（→`AModularCharacter`, 并实现 `IAbilitySystemInterface`） | **直接 `ACharacter`** | 总纲定的：先不引入 Lyra 的角色继承链。**影响**：Lyra 能写 `virtual UAbilitySystemComponent* GetAbilitySystemComponent() const override;`（因为 `LyraCharacter.h` 第 98 行实现了 `IAbilitySystemInterface`、第 114 行 override） |
| `GetAbilitySystemComponent()` 怎么签 | `override` | **一比一还原：也实现 `IAbilitySystemInterface` + 写 `override`（甲方案，已在 4-2 拍板）** | 实现接口纯虚函数必须写 override；我们基类降到 `ACharacter` 但同样接接口，与 Lyra 一致 |
| 属性集数量 | `HealthSet` + `CombatSet` | **只有 `HealthSet`** | CombatSet 依赖战斗/伤害阶段，非遗漏，后续需要时再加 |
| `Category = "Lyra\|PlayerState"` | 有 | 对应写成 `"Tenkaichi\|Character"` 之类 | 仅是编辑器分类显示，无功能影响 |

## 五、一句话结论

**前面三步造好了"零件"（依赖 / 属性 / 自定义 ASC 类），第 4 步要给它们找一个"身体"——一个自带 ASC 的角色类 `TenkaichiCharacterWithAbilities`（一比一对应 Lyra 的 `LyraCharacterWithAbilities`），在构造函数里把 ASC 和 HealthSet 用 `CreateDefaultSubobject` 建出来挂上；这和 Lyra 的 `LyraCharacterWithAbilities`（self-contained 那一支）是同一个做法。**
