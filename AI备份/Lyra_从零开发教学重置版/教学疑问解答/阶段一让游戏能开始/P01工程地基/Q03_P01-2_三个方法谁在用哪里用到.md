# Q03 — 第 02 课 · 第 2 步【基类】疑问：这三个方法，谁在用？哪里用到了？

> **所属章节**：第 02 课 · 第 2 步【2/4】建基类 `TenkaichiAttributeSet.cpp`
>
> **对应 Lyra**：`LyraAttributeSet.cpp`（定义处） + `LyraHealthSet.cpp`（真实调用处）
>
> **一句话**：这三个方法**定义在基类**（`LyraAttributeSet`），但**真正用它们的是子类**（`LyraHealthSet` 血量集）。因为我们的血量集还没写，所以现在"看不到调用"是正常的——Lyra 里也是等血量集写好了才用。

---

## 一、你的疑问（原话）

`TenkaichiAttributeSet.cpp` 里这三个方法，谁在用、哪里用到？

```cpp
UWorld* UTenkaichiAttributeSet::GetWorld() const;
UTenkaichiAbilitySystemComponent* UTenkaichiAttributeSet::GetTenkaichiAbilitySystemComponent() const;
// 以及第二个内部调用的引擎方法：
GetOwningAbilitySystemComponent();
```

**关键前提**：我们的血量集（`TenkaichiHealthSet`）**还没写**，所以现在工程里**确实没有任何地方调用它们**——这不是漏了，是还没到用的时候。Lyra 里也一样：**定义在基类，等血量集写好了才调用**。下面直接看 Lyra 真实调用点。

---

## 二、三个方法各自的"谁在用 / 哪里用"

### 方法 ① `GetWorld()` —— 被 `LyraHealthSet` 用来"发伤害播报消息"

**谁在用**：子类 **血量集 `ULyraHealthSet`**
**哪里用**：`LyraHealthSet.cpp` 第 143 行，`PostGameplayEffectExecute`（GE 执行后回调）里

```cpp
// LyraHealthSet.cpp 第 143-144 行
UGameplayMessageSubsystem& MessageSystem = UGameplayMessageSubsystem::Get(GetWorld());
MessageSystem.BroadcastMessage(Message.Verb, Message);
```

**在干嘛**：血量被扣后，要**向全场广播一条"谁打了谁、扣了多少血"的消息**（击杀提示那种）。发这条消息需要拿到"消息子系统"，而消息子系统是**按 World（舞台）来取的**——血量集自己没 World，于是调 `GetWorld()` 顺藤摸瓜拿到舞台，再取消息子系统。

> 剧场故事（接 [Q02](./Q02_第02课第2步_基类两个工具函数_使用场景与故事.md)）：血型档案卡（血量集）扣了血，要**通过剧场的广播喇叭（消息子系统）喊一声"XX 被打掉了 40 血"**。但喇叭是按"剧场（World）"装的——档案卡得先问清楚"我在哪个剧场"（`GetWorld()`），才能找到那个剧场的喇叭。

---

### 方法 ② `GetTenkaichiAbilitySystemComponent()`（Lyra 叫 `GetLyraAbilitySystemComponent`）—— 被 `LyraHealthSet` 用来"改血量上限时同步当前血"

**谁在用**：子类 **血量集 `ULyraHealthSet`**
**哪里用**：`LyraHealthSet.cpp` 第 208-211 行，`PostAttributeChange`（属性变化后回调）里

```cpp
// LyraHealthSet.cpp 第 206-211 行
if (GetHealth() > NewValue)   // 如果"当前血"比"新的血量上限"还高
{
	ULyraAbilitySystemComponent* LyraASC = GetLyraAbilitySystemComponent();  // ← 拿到技能总管
	check(LyraASC);

	LyraASC->ApplyModToAttribute(GetHealthAttribute(), EGameplayModOp::Override, NewValue);  // 把当前血强制压到上限
}
```

**在干嘛**：当**最大血量（MaxHealth）被降低**（比如角色中了"血量上限减半"的 debuff），而当前血量还高于新上限时——必须**把当前血强制压到新上限**，否则会出现"血量 100/上限 50"的穿帮。这个"改当前血"的操作，得**通过技能总管（ASC）**来做（GAS 铁律：改属性必须走 ASC/GE，不能直接改），所以先调 `GetLyraAbilitySystemComponent()` 拿到自己的总管，再 `ApplyModToAttribute`。

> 剧场故事：档案卡的上限被人改了（上限从 100 降到 50），但卡上还记着 100 的血——这不行，得把当前血也压到 50。但档案卡**不能自己动手改血**（规矩：改血必须经技能总管）。于是它找自己的**技能总管**（`GetLyraAbilitySystemComponent()`），让总管帮它把当前血压到 50。

---

### 方法 ③ `GetOwningAbilitySystemComponent()` —— 引擎方法，是方法②的"内部原料"

**谁在用**：**只有方法②** 用它（在 `LyraAttributeSet.cpp` 第 26 行的定义里）

```cpp
// LyraAttributeSet.cpp 第 24-27 行（方法②的实现体）
ULyraAbilitySystemComponent* ULyraAttributeSet::GetLyraAbilitySystemComponent() const
{
	return Cast<ULyraAbilitySystemComponent>(GetOwningAbilitySystemComponent());  // ← 这里用到③
}
```

**在干嘛**：它**不是我们自己定义的方法，是引擎 `UAttributeSet` 基类自带的**——返回"拥有我这个属性集的那个 ASC"，但类型是**通用款** `UAbilitySystemComponent*`。方法② 就是拿它当原料，再 `Cast` 成我们项目自己的 ASC 类型。

> 所以调用链是：**血量集 → 调方法② `GetLyraAbilitySystemComponent()` → 方法②内部调方法③ `GetOwningAbilitySystemComponent()`（引擎）→ Cast 成项目 ASC**。方法③ 是"最底层那根线"，你几乎不会直接调它，都是通过方法② 包一层用。

## 四、为什么"现在我们的工程里搜不到调用"

因为这三个方法**是给血量集（子类）用的工具**，而我们的血量集 `TenkaichiHealthSet` **还没写**。

- Lyra 里：基类定义好工具 → 血量集写好后，在 `PostGameplayEffectExecute` / `PostAttributeChange` 里调用。
- 我们这里：基类工具已建好（✅）→ 血量集还没写（⏳ 后面第 3 步之后的课）→ 所以现在"没人用"是**正常的、符合预期的**。

> 一句话：**工具先备好（基类），等血量集上场了自然会用。** 你现在只要理解"这两个函数将来是血量集用来找舞台、找技能总管的"就够了，不用急着找调用点。

---

## 五、一句话结论

**三个方法都是"基类定义、子类（血量集）使用"：①`GetWorld` 在 `LyraHealthSet.cpp:143` 用来发伤害广播；②`GetLyraAbilitySystemComponent` 在 `LyraHealthSet.cpp:208` 用来在血量上限降低时同步当前血；③`GetOwningAbilitySystemComponent` 是引擎方法，只被②在内部当原料调用。我们的血量集还没写，所以现在搜不到调用是正常的。**
