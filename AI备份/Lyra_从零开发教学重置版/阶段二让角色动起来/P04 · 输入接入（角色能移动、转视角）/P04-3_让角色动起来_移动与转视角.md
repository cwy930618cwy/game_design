# P04-3 — 让角色动起来：把输入接到「移动 / 转视角」上

> **本步定位**：P04 第 3 步。前两步建好了「字典」（`TenkaichiInputConfig`）和「接线员」（`TenkaichiInputComponent`），但还没有任何代码去「调用接线员、把按键接到角色身上」。这一步就把这条链最后一段接通——让 WASD 能移动、鼠标能转视角。

>
> **本步拆法**：沿用 `.h`/`.cpp` 分开教、分开建 md：

## 一、这一步要解决什么问题（先讲为什么）

前两步做完，输入链还断在最后一环：

```
按键 → IA_Move → （第1步）字典查到 IA_Move  ← 有了
                （第2步）接线员能绑定回调   ← 有了
                （这一步）谁调用接线员？回调里写什么移动逻辑？  ← 还没有！
```

所以这一步做两件事：

1. **重写角色类的 `SetupPlayerInputComponent`**：在角色被 Possess（玩家接管）时，调用第 2 步的 `BindNativeAction`，把 `Input_Move` / `Input_LookMouse` 两个回调绑上。
2. **写这两个回调**：`Input_Move` 里调 `AddMovementInput`（真正移动），`Input_LookMouse` 里调 `AddControllerYawInput` / `AddControllerPitchInput`（转视角）。

> 做完这一步，角色就能动了。这是整个 P04 的「兑现时刻」。

---

## 二、关键：这一步为什么走「简化路线」（路线 B）

我查完 Lyra 源码发现，Lyra 的输入接入核心是 `ULyraHeroComponent`（输入大脑），但它是挂在 `ALyraCharacter`（角色类）上的，而且依赖一整套**很重**的架构：

| Lyra 依赖 | 是什么 | 阶段二现状 |
|-----------|--------|-----------|
| `IGameFrameworkInitStateInterface` | GameFramework 初始化状态机 | ❌ 没建 |
| `UGameFrameworkComponentManager` | 组件初始化协调器 | ❌ 没建 |
| `LyraPawnExtensionComponent` | Pawn 扩展组件 | ❌ 没建 |
| `LyraPawnData` | Pawn 数据资产 | ❌ 没建 |
| `LyraCameraMode` | 相机模式 | ❌ 没建 |
| `GameFeatureAction_AddInputContextMapping` | GameFeature 插件 | ❌ 没建（阶段七） |
| `ALyraPlayerController` / `ULyraLocalPlayer` | 玩家控制器/本地玩家 | ❌ 没建 |
| `LyraGameplayTags`（`InputTag_Move` 常量） | 全局 Tag 常量 | ❌ 没建 |

如果照搬 `ULyraHeroComponent`，会把上面一整串全拖进来——和「移动」无关，步子太大。

**所以这一步走「减法路线」**（和 P02 用引擎原生 `AGameMode` 而非 Lyra 的 `AModularGameModeBase` 是同一个思路）：

> **把「绑定 + 移动」的最小闭环，直接放进我们已有的 `ATenkaichiCharacterWithAbilities`（角色类）里**，暂时砍掉 GameFramework 状态机 / PawnExtension / HeroComponent / 相机 / GameFeature 那套。移动逻辑本身（`AddMovementInput` 等）**一比一照抄**，因为它不依赖那套重架构。

## 三、全景：这一步接完后的完整输入链

```
玩家按 W → MappingContext（步4才配）→ 触发 IA_Move
                                          │
              SetupPlayerInputComponent（这一步重写，角色被接管时引擎自动调）
                    │
                    ▼
        BindNativeAction(InputTag_Move, ..., &Input_Move)   ← 调用第2步的接线员
                    │
                    ▼
              Input_Move(回调)  ← 这一步写
                    │
                    ▼
        Pawn->AddMovementInput(方向, 值)  ← 引擎 Pawn 的方法，真正移动
```

转视角同理：`BindNativeAction(InputTag_Look_Mouse, ..., &Input_LookMouse)` → `Input_LookMouse` → `AddControllerYawInput/PitchInput`。

## 四、这一步的减法（相对 Lyra，我们砍掉什么、为什么）

按铁律「只做减法、说清删了什么」，对照 Lyra 的 `ULyraHeroComponent::InitializePlayerInput` 和两个回调：

| Lyra 有 | 我们这一步 | 为什么 |
|---------|-----------|--------|
| `IGameFrameworkInitStateInterface` 整套（初始化状态机、`NAME_BindInputsNow` 事件等） | **整个砍掉** | 阶段七做完整 Pawn 扩展时再回填，现在只为跑通移动 |
| `LyraPawnExtensionComponent` 查找（`FindPawnExtensionComponent` / `GetPawnData`） | **整个砍掉** | 同上，我们没建 PawnExtension，直接从角色类自己拿 InputConfig |
| `LyraPawnData` 资产 | **整个砍掉** | 用 `UPROPERTY(EditDefaultsOnly)` 直接在角色类上放一个 `InputConfig` 引用替代 |
| `ULyraLocalPlayer` / `GetSubsystem` 拿输入子系统 | **简化** | 用 `PC->GetLocalPlayer()` 直接拿（`GetSubsystem` 那层是拿映射上下文，步4才需要，这里先不写） |
| `ClearAllMappings` / `AddMappingContext`（映射上下文注册） | **暂时砍掉** | 这是「按键→IA」的配置，步4 专门讲（要配 MappingContext 资产） |
| `BindAbilityActions`（技能输入） | **砍掉** | 阶段三技能才用 |
| `Input_Crouch` / `Input_AutoRun` / `Input_LookStick`（蹲/自动跑/手柄视角） | **砍掉** | 只留「移动 + 鼠标转视角」两个最小闭环 |
| `SetIsAutoRunning(false)`（自动跑取消） | **砍掉** | 依赖 `ALyraPlayerController`，我们没建，自动跑功能也一并砍 |
| `LyraGameplayTags::InputTag_Move` 全局常量 | **改用 `FGameplayTag` 字面量或局部变量** | 全局 Tag 常量表是另一个独立主题，这里先用 `FGameplayTag::RequestGameplayTag("InputTag.Move")` 或直接本地定义 |

> **保留（一比一照抄，只换前缀）**：
> - `SetupPlayerInputComponent` 的调用链（重写到角色类里）
> - `BindNativeAction(InputConfig, Tag, ETriggerEvent::Triggered, this, &ThisClass::Input_Move, false)` 这行绑定
> - `Input_Move` 里 `AddMovementInput` 的移动逻辑（含 `GetControlRotation().Yaw` 转视角方向）
> - `Input_LookMouse` 里 `AddControllerYawInput` / `AddControllerPitchInput`

## 五、这一步会新出现、需要先教的方法（先预告，写代码前逐个讲）

1. **`SetupPlayerInputComponent(UInputComponent*)`** —— 引擎 `APawn` 的虚函数，角色被 Possess 时自动调用，是「接输入」的标准入口。
2. **`AddMovementInput(FVector, float)`** —— 引擎 `APawn` 方法（已核实 `Pawn.h:486`），给角色加一个世界方向上的移动输入。
3. **`AddControllerYawInput(float)` / `AddControllerPitchInput(float)`** —— 引擎 `APawn` 方法（`Pawn.h:535`/`526`），加偏航/俯仰旋转输入。
4. **`GetControlRotation()`** —— 引擎 `AController` 方法，拿当前视角朝向，用来把「前后左右」从「玩家视角」换算成「世界方向」。
5. **`FInputActionValue` / `.Get<FVector2D>()`** —— 输入动作的值，二维向量（X=左右，Y=前后；或鼠标 X/Y）。
6. **`GetPawn<APawn>()` / `GetController<APlayerController>()`** —— 组件模板方法，拿自己挂载的 Pawn / 控制器。
7. **`FGameplayTag::RequestGameplayTag("...")`** —— 运行时按名字请求一个 Tag（替代 Lyra 的全局常量）。

> 这些都会在写对应 `.h`/`.cpp` 时，先讲「干嘛 + 源码在哪 + 为什么」，再给代码。
