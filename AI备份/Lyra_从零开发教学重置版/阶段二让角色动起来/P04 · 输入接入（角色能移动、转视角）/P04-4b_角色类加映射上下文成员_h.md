## 一、这一步要解决什么问题（先讲为什么）

上一步说清楚了：要「注册 IMC」，代码里得先有一个 IMC 的引用，才能拿去 `AddMappingContext`。

所以这一步只做一件事：**在角色类上加一个 `UInputMappingContext` 成员**，供 `.cpp` 里的注册逻辑使用。

### 为什么这个成员这么设？

1. **为什么是 `UInputMappingContext*` 而不是别的？**
   因为 `AddMappingContext` 的第一个参数就是 `UInputMappingContext*`。我们要注册什么，就存什么。

2. **为什么用 `TObjectPtr`？**
   UE5 的智能指针，和 P04-1 的 `NativeInputActions`、P04-3b 的 `InputConfig` 一个待遇——编辑器里直指资产，自动管理生命周期。

3. **为什么 `EditDefaultsOnly`？**
   让这个 IMC 能在角色蓝图的**默认值**里指到 `IMC_Default` 资产（你后面绑资产时用）。运行时只读，不改。

4. **为什么 `Category = "Tenkaichi|Input"`？**
   和 P04-3b 的 `InputConfig` 保持同一个分类，编辑器里归类到一起，好找。

> **类比**：`DefaultInputMappingContext` 是角色身上留的一个「插口槽位」，告诉你「这个角色要用哪张接线图」。等你在编辑器里把 `IMC_Default` 资产指进去，`.cpp` 里的注册逻辑就会拿它去插进输入子系统。

## 二、Lyra 真实源码（先看它怎么写）

Lyra 里 IMC 不是直接放角色类成员，而是放在 `ULyraHeroComponent` 的 `DefaultInputMappings` 数组里。

`LyraHeroComponent.h` 第 106-115 行附近：

```cpp
// Input configuration used by player controlled pawns to create input mappings and bind input actions.
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Lyra|Input")
TArray<FInputMappingContextAndPriority> DefaultInputMappings;
```

其中 `FInputMappingContextAndPriority` 是一个结构体（`LyraHeroComponent.h` 顶部定义）：

```cpp
USTRUCT()
struct FInputMappingContextAndPriority
{
	GENERATED_BODY()

	UPROPERTY(EditAnywhere, Category = "Input", Meta = (ShowOnlyInnerProperties))
	TSoftObjectPtr<UInputMappingContext> InputMapping;

	UPROPERTY(EditAnywhere, Category = "Input")
	int32 Priority = 0;

	UPROPERTY(EditAnywhere, Category = "Input")
	bool bRegisterWithSettings = true;
};
```

> 注意三个点：
> 1. Lyra 用**数组**（支持多个 IMC），我们用**单个成员**（减法，只要一个默认 IMC）。
> 2. Lyra 用 `TSoftObjectPtr`（软引用，可延迟加载），我们用 `TObjectPtr`（硬引用，简化）。
> 3. Lyra 把「优先级」也塞进结构体里，我们把优先级直接写死在 `.cpp` 里（或用一个固定值）。

## 三、这一步的减法（相对 Lyra，我们砍掉什么、为什么）

| Lyra 有 | 我们这一步 | 为什么 |
|---------|-----------|--------|
| `TArray<FInputMappingContextAndPriority> DefaultInputMappings`（数组 + 结构体，含 `InputMapping`/`Priority`/`bRegisterWithSettings` 三字段） | **改成单个 `TObjectPtr<UInputMappingContext>` 成员** | 只要一个默认 IMC，不需要数组、不需要结构体、不需要「用户设置」开关 |
| 成员放在 `ULyraHeroComponent`（组件）里 | **搬进角色类** | 路线 B 没建 HeroComponent，直接放角色类 |
| `TSoftObjectPtr<UInputMappingContext>`（软引用） | **改成 `TObjectPtr<UInputMappingContext>`（硬引用）** | 简化，资产随角色加载，不搞延迟加载 |
| `Priority` 放结构体字段 | **砍掉，优先级写死在 `.cpp` 的 `AddMappingContext` 里** | 只有一个 IMC，优先级固定即可 |
| `bRegisterWithSettings` | **砍掉** | 不搞用户自定义按键设置 |

> **保留（一比一照抄）**：
> - 类型 `UInputMappingContext`（这是引擎 Enhanced Input 的核心类型）
> - `UPROPERTY(... Category = "...|Input")` 的「分类」思想（把输入相关归到 `Input` 分类）

## 五、逐段回扣「为什么这么写」

| 代码 | 为什么 |
|------|--------|
| `class UInputMappingContext;` | 前向声明，`.h` 只用指针，不必 include 完整定义（加快编译） |
| `UPROPERTY(EditDefaultsOnly, ...)` | 让成员能在蓝图默认值里指到 `IMC_Default` 资产；运行时只读 |
| `Category = "Tenkaichi\|Input"` | 和 `InputConfig` 同分类，编辑器里归类到一起 |
| `TObjectPtr<UInputMappingContext>` | UE5 智能指针，硬引用资产（对比 Lyra 的 `TSoftObjectPtr` 软引用，简化） |
| `DefaultInputMappingContext` | 名字前缀 `Default` 表示「默认映射上下文」，对应 Lyra 的 `DefaultInputMappings`（单数化） |

## 六、这一步没教过的新方法（先扫一遍）

- **`UInputMappingContext`**：Enhanced Input 的「映射上下文」类型，存「按键 → InputAction」的映射表。**重点新类型**。
- **`TObjectPtr<T>` vs `TSoftObjectPtr<T>`**：都是 UE5 智能指针；`TObjectPtr` 硬引用（加载就带），`TSoftObjectPtr` 软引用（可延迟加载）。本步选了前者做减法。

> 其余（前向声明、`UPROPERTY`、`TObjectPtr`、`EditDefaultsOnly`）都在 P04-1b / P04-2c / P04-3b 讲过了。
