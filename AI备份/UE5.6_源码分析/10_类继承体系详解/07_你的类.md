# 07 - 第 6 层：你的类

> 终于到你写的类了！
> 
> 这一层就是你项目里的具体实现。

---

## 一、例子 1：不用 GAS，纯存数据

```cpp
UCLASS()
class CODE_API UMyData : public UObject {   // ← 直接继承 UObject
    GENERATED_BODY()
    
public:
    UPROPERTY()
    int Health = 100;
};
```

**特点**：
- 不能放关卡（不是 Actor）
- 但能被 UE 管理（序列化、GC、蓝图访问）
- 适合做数据管理器、配置存储

---

## 二、例子 2：用 GAS（属性集）

```cpp
UCLASS()
class CODE_API UCodeAttributeSet : public UAttributeSet {   // ← 继承 GAS 插件类
    GENERATED_BODY()
    
public:
    UPROPERTY(BlueprintReadOnly, ReplicatedUsing=OnRep_Health)
    FGameplayAttributeData Health;
    
    ATTRIBUTE_ACCESSORS(UCodeAttributeSet, Health);
    
protected:
    UFUNCTION()
    void OnRep_Health(const FGameplayAttributeData& OldValue);
};
```

**特点**：
- 继承 GAS 插件的 `UAttributeSet`
- 用 `FGameplayAttributeData` 包装属性值
- 支持网络复制（`ReplicatedUsing`）

## 三、例子 3：角色类

```cpp
UCLASS()
class CODE_API ACodeCharacter : public ACharacter {   // ← 继承引擎基类
    GENERATED_BODY()
    
public:
    ACodeCharacter();   // 构造函数（UE 会自动处理签名）
    
    UPROPERTY()
    int Health = 100;
};
```

**特点**：
- 继承 `ACharacter`，自带移动组件和碰撞
- 能拖进关卡
- 能接收玩家输入

## 四、继承选择速查表

| 需求 | 继承 | 代码示例 |
|------|------|---------|
| 数据管理器 | `UObject` | `class UMyManager : public UObject` |
| 关卡里的物体 | `AActor` | `class AMyBox : public AActor` |
| 玩家角色 | `ACharacter` | `class AMyChar : public ACharacter` |
| 功能组件 | `UActorComponent` | `class UMyComp : public UActorComponent` |
| UI 控件 | `UUserWidget` | `class UMyWidget : public UUserWidget` |
| GAS 属性集 | `UAttributeSet` | `class UMyAttrSet : public UAttributeSet` |
| GAS 技能 | `UGameplayAbility` | `class UMyAbility : public UGameplayAbility` |

## 五、完整继承链示例

以 GAS 属性集为例：

```
C++ 语言（第 0 层）
    ↓
UObjectBase（第 1 层）— 内存管理、生命周期
    ↓
UObjectBaseUtility（第 2 层）— GetName、GetClass 等工具
    ↓
UObject（第 3 层）— 反射系统、序列化、GC
    ↓
UAttributeSet（第 5 层）— GAS 属性集基类
    ↓
UCodeAttributeSet（第 6 层）— 你写的类 ⭐
```

## 六、宏的作用总结

你写的每一行宏，都在告诉 UE "帮我生成哪些代码"：

| 宏 | 作用 | 生成的东西 |
|----|------|-----------|
| `UCLASS()` | 让 UE 认识这个类 | `StaticClass()` 声明、反射注册代码 |
| `GENERATED_BODY()` | 自动生成样板代码 | 构造函数、析构函数、拷贝构造、`StaticClass()` 实现 |
| `UPROPERTY()` | 让 UE 管理这个变量 | 反射信息（让变量能被序列化、蓝图访问） |
| `UFUNCTION()` | 让 UE 管理这个函数 | 反射信息（让函数能被蓝图调用、网络复制） |

### 它们的关系

```cpp
UCLASS()                    // 先说"这个类我要管"
class UMyClass : public UObject {
    GENERATED_BODY()        // 再说"帮我生成构造/析构/StaticClass"
    
    UPROPERTY()             // 再说"这个变量我要管"
    int Health;
    
    UFUNCTION()             // 再说"这个函数我要管"
    void TakeDamage();
};
```

## 七、常见问题 FAQ

### Q1：我写的类到底继承谁？

看需求：
- 不用 GAS → `UObject` 或其子类（AActor、UActorComponent...）
- 用 GAS → 从 GAS 插件提供的基类继承（UAttributeSet、UGameplayAbility...）

### Q2：为什么构造函数要传 `FObjectInitializer`？

因为 UE 规定 UObject 子类的构造函数必须匹配这个签名，用来注入初始化信息。`GENERATED_BODY()` 帮你处理了。

### Q3：`StaticClass()` 在哪定义的？

- **声明**：由 `UCLASS()` 宏生成
- **实现**：由 `GENERATED_BODY()` 宏生成
- **位置**：编译时写入 `Intermediate/Build/.../*.generated.h`

### Q4：反射信息一直存在，会不会占内存？

不会。反射信息是"类的说明书"，每个类只有一份，不随实例数量增加。一个类的反射信息大约几百字节，对现代电脑来说微乎其微。

### Q5：UCLASS() 和 GENERATED_BODY() 有什么区别？

- `UCLASS()` = 告诉 UE "这个类需要被管理"（声明）
- `GENERATED_BODY()` = 告诉 UE "帮我生成构造/析构/StaticClass 等代码"（实现）
- 两者永远一起出现

## 八、一句话总结

> **你的类 = 最终用户**
> 
> - 根据需求选择合适的基类
> - 加上 UCLASS() + GENERATED_BODY()
> - 用 UPROPERTY/UFUNCTION 标记需要 UE 管理的东西
> 
> 剩下的交给 UE 自动处理！
