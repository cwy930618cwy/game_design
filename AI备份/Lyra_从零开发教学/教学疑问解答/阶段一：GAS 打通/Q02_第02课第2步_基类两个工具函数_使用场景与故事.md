# Q02 — 第 02 课 · 第 2 步【基类】疑问：`GetWorld` / `GetTenkaichiAbilitySystemComponent` 是干嘛的？使用场景是什么？

> **所属章节**：第 02 课 · 第 2 步【2/4】建基类 `TenkaichiAttributeSet.cpp`
>
> **对应 Lyra**：`AbilitySystem/Attributes/LyraAttributeSet.cpp` 第 16-27 行
>
> **一句话**：属性集（血量表）自己是个"死物件"，不知道自己在哪个世界、挂在哪个技能库身上。这两个函数就是**帮属性集"顺藤摸瓜"找回自己所在的舞台（World）和所归属的技能总管（ASC）**。

---

## 一、你的疑问（原话）

`TenkaichiAttributeSet.cpp` 里这两个函数：
```cpp
UWorld* UTenkaichiAttributeSet::GetWorld() const
{
	const UObject* Outer = GetOuter();
	check(Outer);
	return Outer->GetWorld();
}

UTenkaichiAbilitySystemComponent* UTenkaichiAttributeSet::GetTenkaichiAbilitySystemComponent() const
{
	return Cast<UTenkaichiAbilitySystemComponent>(GetOwningAbilitySystemComponent());
}
```
- 这俩是干嘛的？
- 什么时候会用到？
- 第二个里的 `Cast<UTenkaichiAbilitySystemComponent>(...)` 完全没看懂。

---

## 二、先记住一个大前提：属性集是"死物件"，没有自己的感知

在讲这两个函数前，必须先懂一件事——**属性集（AttributeSet）本身是个"哑巴物件"**：

- 它**不是 Actor**，不能自己满世界跑、不能自己找世界、不能自己找技能库。
- 它只是一张**数据表**（存血量、蓝量这些数值），被动地**挂**在 ASC（技能总管）身上。

> 用你人物谱里的话说（[03_运行时链路人物谱](../../人物介绍/03_动起来后_运行时链路人物谱.md)）：
> - 📉 **血量属性（HealthSet）** = 属性集，就是那张"血量表"。
> - 🧠 **技能总管（ASC）** = 挂在记分牌上的技能中枢，**属性集就挂在他身上**。

**问题来了**：血量表自己不知道自己"在哪个舞台上演（哪个 World）"，也不知道"我归哪个技能总管管（哪个 ASC）"。这两个函数，就是**让血量表能反过来找到自己所在的舞台、和所归属的技能总管**。

---

## 三、剧场故事：一张"演员血型档案卡"的自白

> 下面用你人物谱的剧场世界观，把这两个函数编成一段故事。

### 故事背景

在"开演"之后，场上每个演员（角色）都配了一张 **血型档案卡**（= 属性集 `UTenkaichiAttributeSet`），上面记着这个演员的血量。

这张档案卡有个特点：**它被塞进演员随身的一个"技能背包"里（= ASC 技能总管）**。档案卡自己不能动，它只能**通过"技能背包"去接触外面的世界**。

---

### 🎬 场景一：档案卡想知道"我现在在哪个舞台？" → `GetWorld()`

档案卡被塞进技能背包后，它懵了："我在哪张桌子上？这个剧场叫什么？"

它怎么找？——**它不直接知道，但它知道自己被谁装着（技能背包）**。于是：

```cpp
UWorld* UTenkaichiAttributeSet::GetWorld() const
{
	const UObject* Outer = GetOuter();   // ① 先问："我被谁装着？" → 拿到技能背包（Outer）
	check(Outer);                          // ② 确认：技能背包确实在（不在就报错）
	return Outer->GetWorld();              // ③ 再问背包："你在哪个舞台？" → 返回舞台（World）
}
```

**翻译成故事**：
- `GetOuter()` = 档案卡**顺着"我被塞进谁里面"这根线**，摸到"技能背包"。
- `Outer->GetWorld()` = 再**问技能背包**："你在哪个舞台（World）上演？" 背包知道自己在哪个剧场，就告诉它。

> **类比**：你（档案卡）被塞进一个旅行箱（技能背包）。你想知道自己在哪个城市（World）？——你问旅行箱："你在哪？" 旅行箱回答："我在东京巨蛋剧场。" 这就是 `Outer->GetWorld()`。

**使用场景**：属性集里的逻辑需要拿 World 时——比如**发一条全局消息、查游戏状态、生成一个特效**。属性集自己没 World，就用这个函数顺藤摸瓜拿到。

---

### 🎬 场景二：档案卡想直接找"我的技能总管" → `GetTenkaichiAbilitySystemComponent()`

档案卡还想找那个**专门管它的技能总管（ASC）**——因为改血量、查拥有者，都得找技能总管。

```cpp
UTenkaichiAbilitySystemComponent* UTenkaichiAttributeSet::GetTenkaichiAbilitySystemComponent() const
{
	return Cast<UTenkaichiAbilitySystemComponent>(GetOwningAbilitySystemComponent());
}
```

**拆解这两行**：

**第 1 步：`GetOwningAbilitySystemComponent()`**
- 这是**引擎 `UAttributeSet` 基类自带**的方法，意思是"拿到拥有我的那个 ASC"。
- 但引擎返回的是**"通用款"技能总管指针**（类型是基类 `UAbilitySystemComponent*`）——它只说"这是个技能背包"，**没说"这是我们项目自己定制的那个技能背包"**。

**第 2 步：`Cast<UTenkaichiAbilitySystemComponent>(...)`**
- `Cast` 是 UE 的**安全类型转换**：把"通用款技能背包指针" → 转成"我们 Tenkaichi 项目自己的技能背包类型 `UTenkaichiAbilitySystemComponent`"。
- 转完，档案卡手里拿的就是**"我专属的技能总管"**，可以调用我们项目给 ASC 加的那些定制功能了。

**翻译成故事**：
- 档案卡喊一声"我的技能总管在哪？"（`GetOwningAbilitySystemComponent`），引擎回它一个"通用款背包管理员"。
- 但档案卡要的是**"我们剧团自己培养的那个管理员"**（`UTenkaichiAbilitySystemComponent`），不是随便一个路人管理员。于是它用 `Cast` **确认并转换**："你就是我们剧团的管理员，对吧？是 → 拿到手。"

> **类比**：你问前台"我的专属管家在哪？"，前台带来一个人（`GetOwningAbilitySystemComponent` 返回的通用指针）。但你要确认这人**真是你那位管家**（`Cast` 转换），而不是别人——确认无误，你才认他当管家，才能让他帮你办事。

**使用场景**：属性集里需要**反过来操作技能总管**时——比如查属性的拥有者是谁、给 ASC 上查别的东西。子类（血量集）经常用这个拿到"自己的总管"。

---

## 四、两个函数对比（一张表看懂）

| 函数 | 找的是什么 | 怎么找的 | 使用场景 |
|------|-----------|---------|---------|
| `GetWorld()` | 所在的**世界/舞台**（`UWorld`） | 先 `GetOuter()` 摸到技能背包，再 `Outer->GetWorld()` 问背包 | 发消息、查游戏状态、生成特效 |
| `GetTenkaichiAbilitySystemComponent()` | 归属的**技能总管**（我们项目的 ASC） | `GetOwningAbilitySystemComponent()` 拿到通用 ASC，再 `Cast` 转成我们的类型 | 查拥有者、操作 ASC 的定制功能 |

---

## 五、为什么这两个函数要放在"基类"里（而不是血量集里）

因为**所有属性集（血量表、蓝量表、体力表……）都需要这两个功能**——都要找世界、都要找技能总管。

放在基类 `UTenkaichiAttributeSet` 里，**所有子类自动继承**，不用每个子类重写一遍。这正是 Lyra 的设计（`LyraAttributeSet` 基类里就有这两个函数，`LyraHealthSet` 等子类直接用）。

> 呼应 [Q01](./Q01_第02课第2步_基类cpp方法为何是空的_h与cpp关系.md)：基类构造函数是空的（没属性要初始化），但基类**提供了这两个工具函数**给子类用——"空底座"不等于"没用"，它把"通用工具"备好了。

---

## 六、一句话结论

**属性集是"死数据表"，不知道自己在哪、归谁管。`GetWorld()` 顺着 Outer 摸到自己所在的舞台（World）；`GetTenkaichiAbilitySystemComponent()` 用 `GetOwningAbilitySystemComponent` 拿到通用 ASC 再 `Cast` 成我们项目自己的技能总管。两个都是给所有子类复用的"顺藤摸瓜"工具。**
