# 12 — 本地化（Internationalization/）与模块系统（Modules/）

> **定位**：Core 里 `Internationalization/`（本地化/多语言）和 `Modules/`（模块系统）。
>
> **一句话**：本地化 = **让游戏支持多语言**（核心是 FText）；模块系统 = **UE 代码的组织和加载方式**（FModuleManager 加载 .dll/.so）。
>
> **文件**：`Core/Public/Internationalization/`、`Core/Public/Modules/`

---

## 一、Internationalization/ —— 本地化（多语言）

### 1.1 什么是本地化（i18n）

**本地化** = 让游戏能显示多种语言。玩家是中文就显示中文，是英文就显示英文，切换语言不用改代码。

```
i18n = Internationalization（国际化，18 是中间字母数）
   让游戏"准备支持多语言"
L10n = Localization（本地化）
   具体翻译成某一种语言
```

### 1.2 核心：FText（可翻译的文本）

你之前学过 FName（标识符）、FString（操作），现在 `FText` 是**"要翻译的文本"**——显示给玩家看、需要多语言的文本，必须用 FText。

```cpp
// 显示给玩家的文字，用 FText
FText  DisplayName = NSLOCTEXT("MyGame", "PlayButton", "Play");
//                                            ↑key    ↑默认英文
```

**为什么用 FText 而不用 FString**：FString 不能翻译，FText 能根据语言自动显示对应翻译。

### 1.3 具体场景：按钮文字多语言

```cpp
// 用 NSLOCTEXT 定义可翻译文本
FText StartText = NSLOCTEXT("MyGame", "Start", "Start");
// 英文显示 "Start"，中文玩家显示 "开始"（在翻译表里配）

// 常见写法
FText::FromString(TEXT("..."))  // 一般别用，不能翻译
LOCTEXT("Key", "English")        // 局部文本
NSLOCTEXT("Category", "Key", "English")  // 带分类的文本
```

### 1.4 FText / FString / FName 对比（回忆）

| 类型 | 用途 | 能翻译吗 |
|------|------|:---:|
| FName | 标识符（Tag、资源名） | ❌ |
| FString | 通用字符串操作 | ❌ |
| **FText** | **显示给玩家的文本** | ✅ |

**具体场景：HUD 上显示血量文字**

```cpp
// 血量数字是玩家看的，用 FText
FText HpText = FText::Format(
    NSLOCTEXT("MyGame", "Hp", "HP: {0}"),   // 可翻译
    FText::AsNumber(CurrentHp));            // 数字格式化
```

### 1.5 什么时候必须用 FText？

- **UI 上显示的、要给玩家看的文字** → 必须 FText（能翻译）
- 内部变量名、日志、Key → 不用 FText（用 FName/FString）

> **新手常犯**：UI 上直接用 `FString` 显示文字，导致无法翻译。**给玩家看的文字一律用 FText。**

## 二、Modules/ —— 模块系统

### 2.1 什么是模块（Module）

**模块** = UE 里"一块独立的代码 + 它编译成的 .dll/.so"。整个引擎被拆成很多模块（Core、Engine、Renderer、AIModule……），每个模块是一坨相关的类。

```
模块 = 一堆相关代码打包
Core      → 基础（容器、字符串）
Engine    → 游戏框架（Actor）
Renderer  → 渲染
```

### 2.2 FModuleManager —— 加载/卸载模块的"总管"

`FModuleManager` 负责：加载模块、卸载模块、查找模块。是模块系统的核心。

```cpp
#include "Modules/ModuleManager.h"

// 检查模块是否已加载
bool bLoaded = FModuleManager::Get().IsModuleLoaded("MyModule");

// 加载模块（返回模块实例）
IModuleInterface* Mod = FModuleManager::Get().LoadModule("MyModule");
```

**具体场景：插件模块在启动时加载**

```cpp
// 游戏启动时确保某个插件模块被加载
FModuleManager::LoadModuleChecked("GameplayAbilities");  // GAS 插件
```

### 2.3 模块的两个"入口"（IModuleInterface）

每个模块类继承 `IModuleInterface`，重写启动/关闭函数：

```cpp
#include "Modules/ModuleInterface.h"

class FMyGameModule : public IModuleInterface {
public:
    virtual void StartupModule() override {
        // 模块加载时执行（注册类、初始化）
    }
    virtual void ShutdownModule() override {
        // 模块卸载时执行（清理）
    }
};
```

### 2.4 模块的 .Build.cs（你之前见过）

每个模块有个 `.Build.cs` 文件（如 `Core.Build.cs`），声明它依赖哪些其他模块：

```csharp
// Core.Build.cs 的一部分
PublicDependencyModuleNames.AddRange(new string[] {
    "Core",
    "CoreUObject",
    "Engine",
});
```

**具体场景**：你的游戏模块要用渲染功能，就在 .Build.cs 里加依赖：

```csharp
PublicDependencyModuleNames.AddRange(new string[] {
    "Core", "CoreUObject", "Engine", "Renderer"
});
```

## 三、两者关系：模块是"骨架"，本地化是"功能"

```
Modules/ = UE 代码怎么组织（骨架）
Internationalization/ = 一个具体功能（多语言）
```

- **Modules/ 决定了"哪些代码一起编译、互相依赖"**
- **Internationalization/ 是其中一个"功能模块"内部的能力**

## 四、日常开发要学吗？—— 分轻重

| 主题 | 日常用得勤吗 | 建议 |
|------|:---:|------|
| `FText`（本地化） | **UI 显示文字常用** | **必学**（给玩家看的文字用它） |
| `NSLOCTEXT` / `LOCTEXT` | 定义可翻译文本 | 常用 |
| `FModuleManager` | 看插件代码时 | 了解 |
| `IModuleInterface` | 写插件/模块时 | 遇到再做 |
| `.Build.cs` | 加模块依赖 | 了解 |

**结论**：
1. **`FText` 必学**——UI 上给玩家看的文字必须用它（能翻译）
2. `NSLOCTEXT`/`LOCTEXT` 定义可翻译文本，常用
3. `Modules/`（FModuleManager、IModuleInterface）**了解即可**，写插件/模块时才深入

## 五、常见误区

**① UI 文字用 FString（无法翻译）**
```cpp
// ❌ 给玩家看的文字用 FString，不能翻译
FString Name = TEXT("Play");
// ✅ 用 FText，能多语言
FText Name = LOCTEXT("Play", "Play");
```

**② 忘了 FText 是"要显示才用"**
```cpp
// ❌ 内部 Key、日志别用 FText（没意义）
FText Category = ...   // 内部标识不该用 FText
// ✅ FText 只用于"显示给玩家"的文本
```

**③ 手写模块加载（该用 FModuleManager）**
```cpp
// ❌ 手动处理 dll 加载，麻烦且危险
// ✅ 用 FModuleManager::LoadModuleChecked
FModuleManager::LoadModuleChecked("MyModule");
```

## 六、总结速查

```
Internationalization/ = 本地化（多语言）
├── FText：可翻译文本（给玩家看）← 必学
├── NSLOCTEXT("分类","key","英文")：定义可翻译文本
└── FText::Format：格式化可翻译文本

Modules/ = 模块系统
├── FModuleManager：加载/卸载模块
├── IModuleInterface：模块入口（Startup/Shutdown）
└── .Build.cs：声明模块依赖

日常重点：FText（UI 文字必用）
Modules/：了解即可，写插件再深入
```

**一句话**：本地化 = 用 `FText` 让"给玩家看的文字"支持多语言（必学）；模块系统 = UE 代码怎么组织和加载（了解即可）。**记住：UI 上显示给玩家的文字，一律用 FText。**

---

## 七、什么时候深入？

- **现在**：掌握 `FText`（给玩家看的文字用它），了解 Modules/ 是"代码组织骨架"
- **做多语言游戏**时：深入 Internationalization、翻译表
- **写插件/模块**时：学 FModuleManager、IModuleInterface、.Build.cs

> 和其他笔记一样：**先会用高频的（FText），再深入冷门的（Modules/）**。
