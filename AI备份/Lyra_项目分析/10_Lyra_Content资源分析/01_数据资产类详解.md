# 01 — 数据资产类（Experience / PawnData / AbilitySet / InputConfig）

> **定位**：讲 Lyra Content 里**最重要的一类资源——数据资产（DataAsset）**。这些是 Lyra "数据驱动"哲学的落地，也是策划配置的真正入口。
>
> **关联**：[04_UPrimaryDataAsset详解](../04_UPrimaryDataAsset详解.md) 讲这个类的技术细节，本篇讲**它们在 Content 里长什么样、怎么组织、怎么被引用**。
>
> **一句话**：Lyra 的"玩法/角色/技能/输入"全靠这几份 DataAsset 配置，**改它们就是改游戏，不用动代码**。

---

## 一、这类资源是什么

在 Content 里，它们是 `.uasset` 文件（蓝图编辑器里显示为"数据资产"图标）。双击打开是一个**填表界面**，没有逻辑，只有配置项。

```
Content/Data/（或类似目录）
├── DA_Experience_TeamDeathmatch    ← Experience 规则
├── DA_PawnData_Hero                ← 角色配置
├── DA_AbilitySet_Rifle             ← 技能集
└── DA_InputConfig_Default          ← 输入配置
```

| 资源类型 | C++ 基类 | 作用 |
|---------|---------|------|
| **Experience** | `ULyraExperienceDefinition` | 一局游戏的玩法规则（用哪些 GameFeature、什么模式） |
| **PawnData** | `ULyraPawnData` | 一个角色的装配清单（用哪些组件、技能、输入） |
| **AbilitySet** | `ULyraAbilitySet` | 一组要授予的技能/效果/属性 |
| **InputConfig** | `ULyraInputConfig` | 输入按键到 GameplayTag 的映射 |

> 共同点：**都继承 `UPrimaryDataAsset`**，都有 PrimaryAssetId，都能被异步加载、被切换。

---

## 二、Experience（体验/玩法定义）★最顶层

### 是什么
Experience 是"**这一局怎么玩**"的总配置。它是 Lyra 切换玩法的核心。

### Content 里长这样
双击 `DA_Experience_xxx`，能看到：
```
Game Features to Load:        ← 要加载哪些玩法插件
  └─ [ ] ShooterCore
  └─ [ ] ShooterMaps
Actions:                      ← 要执行的动作
  └─ [+ Add] 各种 Action
```

### 怎么被引用
通过 **PrimaryAssetId** 被 ExperienceManagerComponent（在 GameState 上）异步加载：

```cpp
// 切换玩法时，按 ID 加载对应的 Experience
FPrimaryAssetId ExpId(TEXT("LyraExperienceDefinition"), TEXT("TeamDeathmatch"));
ExperienceManager->LoadExperience(ExpId);
```

### 策划在哪配
- 新增一种玩法 → 复制一份 Experience 资产，改名，勾选不同的 GameFeature/Action
- **完全不用动代码**

> 详见 [03_Experience详解](../03_Experience详解.md)

---

## 三、PawnData（角色配置）★最常接触

### 是什么
PawnData 是"**这个角色怎么装配**"的清单——它把组件、技能、输入串起来。

### Content 里长这样
双击 `DA_PawnData_xxx`：
```
Ability Sets:                 ← 授予哪些技能集
  └─ [ ] DA_AbilitySet_Rifle
Input Config:                 ← 用什么输入配置
  └─ DA_InputConfig_Default
Tag Relationship Mapping:     ← 技能互斥关系
  └─ DA_TagRelationshipMapping
Components:                   ← 要挂载哪些组件（Modular 拼装）
  └─ [+ Add] 各业务组件
```

### 怎么被引用
由 GameMode 在 Spawn 角色时指定，通过 `PawnExtensionComponent::SetPawnData()` 传给角色：

```cpp
// GameMode 生成角色时（真实源码简化）
if (ULyraPawnExtensionComponent* PawnExt = FindPawnExtensionComponent(SpawnedPawn))
{
    PawnExt->SetPawnData(PawnData);   // 把 Content 里的 DataAsset 喂给角色
}
```

### 策划在哪配
- 做一个新角色 → 新建一份 PawnData，勾不同的 AbilitySet/InputConfig
- 同一份 C++ 角色类，配不同 PawnData = 不同角色（见 [09_组件化加DataAsset开发范式](../09_组件化加DataAsset开发范式.md)）

## 四、AbilitySet（技能集）

### 是什么
"**一组要授予的能力打包**"——包含 GA（技能）、GE（效果）、AttributeSet（属性集）。

### Content 里长这样
```
Ability Set: DA_AbilitySet_Rifle
├── Abilities:                ← 授予哪些 GameplayAbility
│     └─ [ ] GA_Rifle_Shoot
├── Effects:                  ← 授予哪些 GameplayEffect
│     └─ [ ] GE_Health_Max
└── Attribute Sets:           ← 注册哪些属性集
      └─ [ ] LyraHealthSet
```

### 怎么被引用
角色初始化时（InitState 推进到 DataInitialized），ASC 读取 PawnData.AbilitySets，批量授予：

```cpp
// 遍历 AbilitySet，一次性授予所有能力（真实逻辑简化）
for (UAbilitySet* AbilitySet : PawnData->AbilitySets)
{
    AbilitySet->GiveToAbilitySystem(AbilitySystemComponent, ...);
}
```

> **好处**：策划配技能就像"打勾清单"，勾哪些就授予哪些，不用程序写死。

---

## 五、InputConfig（输入配置）

### 是什么
把 **Enhanced Input 的 InputAction** 映射到 **GameplayTag**，让"按键"和"技能"通过 Tag 解耦连接。

### Content 里长这样
```
Input Config: DA_InputConfig_Default
├── Native Input Actions:     ← 原生输入（移动/视角）
│     └─ IA_Move → Movement.InputTag
├── Ability Input Actions:    ← 技能输入（开火/跳跃）
│     └─ IA_Fire → Ability.InputTag.Rifle.Shoot
```

### 怎么被引用
HeroComponent 读取 InputConfig，用模板方法批量绑定：

```cpp
// 绑定原生输入 + 技能输入（真实逻辑简化）
InputConfig->NativeInputActions.ForEach(...);      // 绑移动等
InputConfig->AbilityInputActions.ForEach(...);     // 绑技能到 ASC
```

> 详见输入系统相关篇章。

## 六、它们之间的关系图

```
Experience（这一局怎么玩）
   │  引用
   ▼
PawnData（这个角色怎么装配）
   │
   ├──► AbilitySet（授予哪些技能）──► GA / GE / AttributeSet
   │
   ├──► InputConfig（按键映射到哪个 Tag）──► InputAction
   │
   └──► Components（挂哪些组件）──► Modular 拼装角色
```

**一条链**：Experience → PawnData → AbilitySet/InputConfig/Components → 最终组成一个能玩的角色。

---

## 七、策划配置入口速查

| 想改什么 | 去 Content 里找 |
|---------|----------------|
| 改玩法规则 | `DA_Experience_xxx` |
| 改角色配置（技能/输入） | `DA_PawnData_xxx` |
| 增减技能 | `DA_AbilitySet_xxx` |
| 改按键映射 | `DA_InputConfig_xxx` |
| 技能互斥关系 | `DA_TagRelationshipMapping` |

> ⚠️ 这些都是**双击打开填表**，不用写代码、不用编译（大部分情况）。

---

## 八、常见误区

| 误区 | 正确理解 |
|------|---------|
| "DataAsset 里有逻辑" | 纯数据，逻辑在 C++ 组件里 |
| "改了要重启引擎" | 多数配置运行时会重新读取 |
| "蓝图和数据资产是一回事" | 蓝图能跑逻辑，DataAsset 只存数据 |
| "直接改引擎自带的别复制" | 建议复制一份改名，保留官方原版方便升级 |

---

## 九、总结速查

```
Lyra Content 数据资产 = 策划的配置入口

Experience   → 这一局怎么玩（最顶层，切玩法靠它）
PawnData     → 角色怎么装配（串起组件/技能/输入）
AbilitySet   → 一组技能打包（打勾授予）
InputConfig  → 按键 → Tag 映射

共同点：
  ├─ 都继承 UPrimaryDataAsset
  ├─ 都有 PrimaryAssetId（能被异步加载/切换）
  └─ 双击填表，改它们即改游戏，不用动代码

关系链：Experience → PawnData → AbilitySet/InputConfig/Components → 角色
```

**一句话**：这四类 DataAsset 是 Lyra 的"配置中枢"——从玩法（Experience）到角色（PawnData）到技能（AbilitySet）到输入（InputConfig），层层引用，全在 Content 里可视化配置。**这就是 Lyra "数据驱动"的真正含义。**
