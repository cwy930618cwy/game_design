# 04 — 动画资源概念详解（蒙太奇/骨骼/骨骼体/动画序列/动画蓝图）

> **定位**：讲清 Lyra Content 里 `Characters/` 等目录下常见的**动画相关资源概念**——蒙太奇（Montage）、骨骼（Bone）、骨骼体（Skeleton）、骨骼网格（SkeletalMesh）、动画序列（AnimSequence）、动画蓝图（AnimBlueprint）。这些是新手最容易搞混的一堆名词。
>
> **一句话**：一个角色要"动起来"，需要 **骨架（Skeleton）+ 皮（SkeletalMesh）+ 动作（AnimSequence/Montage）+ 控制器（AnimBlueprint）** 四样配合。搞清楚每样管什么，就不会晕。

---

## 一、先看全貌：一个角色怎么"动"起来

在 UE 里，一个能动的角色 = **4 样东西组合**：

```
能动的角色
├── 1. Skeleton（骨骼/骨架）   ← "内部骨架"，定义有哪些骨头、怎么连接
├── 2. SkeletalMesh（骨骼网格）← "外表皮肤"，角色的3D模型，绑在骨架上
├── 3. Animation（动画）       ← "动作"，让骨头怎么动
│        ├─ AnimSequence（动画序列）= 一段预设动作（如跑步、跳跃）
│        └─ Montage（蒙太奇）    = 可打断、可混合的动画（技能动作常用）
└── 4. AnimBlueprint（动画蓝图）← "大脑控制器"，决定什么时候播哪个动作
```

### 用一个比喻建立全局印象

| 概念 | 比喻 | 本质 |
|------|------|------|
| **Skeleton（骨骼）** | 人体的**骨架**（头骨、脊椎、四肢骨） | 定义"有哪些骨头、骨头怎么连接" |
| **SkeletalMesh（骨骼网格）** | 穿在骨架上的**皮肤和衣服** | 角色的 3D 外观模型 |
| **AnimSequence（动画序列）** | 一段**录好的舞蹈视频** | 预先做好的单个动作 |
| **Montage（蒙太奇）** | 可以**随时插播/打断**的动作片段 | 技能、攻击等可打断动画 |
| **AnimBlueprint（动画蓝图）** | 指挥放哪段视频的**导演** | 控制"何时播何动作"的逻辑 |

---

## 二、Skeleton（骨骼 / 骨架）

### 是什么
**Skeleton = 角色的骨架结构**。它定义了"这个角色有哪些骨头、骨头之间怎么连接（父子关系）"。

```
Skeleton（骨架）
├── Root（根，通常在脚底/世界原点）
│   └── Pelvis（骨盆）
│       ├── Spine（脊椎）→ Chest（胸口）→ Neck（脖子）→ Head（头）
│       ├── LeftUpperArm（左上臂）→ LeftForearm（左前臂）→ LeftHand（左手）
│       └── RightUpperArm ... → RightHand ...
│       ├── LeftThigh（左大腿）→ LeftCalf（左小腿）→ LeftFoot（左脚）
│       └── RightThigh ... → RightFoot ...
```

### 关键点
- **Skeleton 是"共享"的**：同一个骨架可以被多个不同的 SkeletalMesh 复用。
  - 比如"男英雄骨架"可以让 A、B、C 三个角色共用——只要骨架一样，动画就能通用。
- **Skeleton 里没有外观**：它只是抽象的骨头结构，看不见摸不着（编辑器里能看到线框骨架）。
- **动画数据存在相对变化**：记录的是"每根骨头相对于父骨头怎么转动"，所以一套动画能套用到同骨架的所有模型上。

> ⚠️ 记忆：**Skeleton 决定"能不能用同一套动画"**。两个角色要共享动画，必须用同一个 Skeleton。

---

## 三、SkeletalMesh（骨骼网格 / 蒙皮网格）

### 是什么
**SkeletalMesh = 角色的 3D 外观模型**，并且"绑定（蒙皮）"到了某个 Skeleton 上。你看到的角色外形、贴图、材质，都在 SkeletalMesh 里。

### 它和 Skeleton 的关系

```
Skeleton（骨架，看不见）
    │  绑定（蒙皮）
    ▼
SkeletalMesh（皮肤+衣服，看得见）
    └── 包含：网格顶点 + 贴图材质 + 绑定的骨架引用
```

### 关键点
- **SkeletalMesh 引用一个 Skeleton**：一个模型必须绑到某个骨架上才能动。
- **换装靠 SkeletalMesh / Mesh Section**：换武器、换皮肤，本质是换 SkeletalMesh 或它的材质。
- **同一个 Skeleton 可以有多个 SkeletalMesh**：同骨架的不同外观（不同皮肤）。

| | Skeleton | SkeletalMesh |
|---|---|---|
| 看得见吗 | ❌ 抽象骨架 | ✅ 角色外观 |
| 存什么 | 骨头结构 | 网格+贴图+材质+骨架引用 |
| 能否复用动画 | 是（同骨架共享） | 否（外观不同） |
| 换装换的是 | 不换 | 换这个 |

---

## 四、AnimSequence（动画序列）

### 是什么
**AnimSequence = 一段预先制作好的单一动作**。比如"跑步""跳跃""待机""死亡"各是一个 AnimSequence。

```
Animations/
├── AS_Idle          ← 待机（站着不动）
├── AS_Run           ← 跑步
├── AS_Jump          ← 跳跃
├── AS_Death         ← 死亡倒地
└── AS_Rifle_Shoot   ← 步枪射击
```

### 关键点
- **它是"一整段完整的动画"**，从头到尾固定播放。
- **不能被打断**（这是和 Montage 最大的区别）。
- 通常由美术在 DCC 软件（Maya/Blender）做好，导入 UE。
- 播放方式：循环（Loop，如跑步）或不循环（如跳跃播一次就停）。

> ⚠️ AnimSequence 是**最基础的动画单位**。Montage、动画蓝图都是建立在它之上的。

---

## 五、Montage（蒙太奇）★重点

### 是什么
**Montage = 一种"可以被主动控制、打断、混合"的动画**，底层基于 AnimSequence，但加了"调度能力"。

### 为什么需要蒙太奇

普通 AnimSequence 是"播完一整段"，但游戏里经常需要：
- 角色正在跑步，突然要**开枪**（临时插一个射击动作）
- 开枪打到一半，玩家又去**翻滚**（要能打断射击）
- 上半身射击、下半身继续跑步（**分层混合**）

这些需求 AnimSequence 做不到，所以要靠 **Montage**。

### Montage 的结构

```
AM_Rifle_Shoot（步枪射击蒙太奇）
├── Slot: DefaultSlot        ← 插槽（用于分层混合）
├── Blend In: 0.1s           ← 切入混合时间（多快进入这个动作）
├── Sections（段落）:
│     ├── Start              ← 起手
│     ├── Loop               ← 循环（可重复）
│     └── End                ← 收尾
├── 引用的 AnimSequence      ← 实际的动作数据
└── Notify（通知）           ← 播放到某帧触发事件（如"这帧开火""这帧播音效"）
```

### 关键特性（和 AnimSequence 的区别）

| 特性 | AnimSequence | Montage |
|------|-------------|---------|
| 打断 | ❌ 播完一整段 | ✅ 可被其他 Montage 打断 |
| 混合切入 | 弱 | ✅ Blend In/Out 平滑过渡 |
| 分段控制 | 无 | ✅ Section（可跳到某段/循环某段） |
| 分层播放 | 难 | ✅ Slot 插槽支持上下半身分离 |
| 触发事件 | 无 | ✅ Notify（开火/音效/特效时机） |
| 典型用途 | 待机/跑步/死亡等基础动画 | **技能/攻击/交互等复杂动作** |

### 怎么用（代码层面）

蒙太奇通常由 **AnimInstance（动画实例）** 通过 `PlaySlotAnimationAsDynamicMontage` 或 `Montage_Play` 播放，并由 GAS 的 `UAbilityTask_PlayMontageAndWait` 驱动：

```cpp
// GA 里播放攻击蒙太奇（真实模式，常配 GAS）
UAbilityTask_PlayMontageAndWait* Task =
    UAbilityTask_PlayMontageAndWait::CreatePlayMontageAndWaitProxy(
        this, NAME_None, AttackMontage);   // 播放攻击蒙太奇
Task->OnBlendOut.AddDynamic(this, &ThisClass::OnMontageFinished);
Task->Activate();
```

> **Lyra 里几乎所有技能动作都用 Montage**——因为技能要能被取消、要和其他动作混合、要在特定帧触发伤害判定。

### Montage Notify（蒙太奇通知）

Montage 能在"特定时间点"触发事件，叫 **Notify**：
- `AnimNotifyState_Trail`：拖尾特效开始/结束
- `AnimNotify_AkEvent`：播放音效
- `AnimNotify_ApplyDamage`：这一帧计算伤害（配合 GAS）

> 这就是"动作和逻辑/表现对齐"的机制——美术在动画里标好"第几帧开火"，程序在那帧触发逻辑。

## 六、AnimBlueprint（动画蓝图）

### 是什么
**AnimBlueprint（ABP）= 动画的"控制大脑"**。它是一个蓝图，负责决定"角色当前应该播哪个动画、怎么混合"。

### 它干什么

```
AnimBlueprint（动画蓝图）
├── EventGraph（事件图）     ← 逻辑：读取速度/状态，决定播什么
├── State Machine（状态机）  ← 核心：Idle→Run→Jump→Death 状态切换
├── Blend Space（混合空间）  ← 根据速度/方向混合动画（如跑得快慢）
└── 输出姿势（Pose）         ← 最终拼出来的骨骼姿势 → 给 SkeletalMesh 显示
```

### 关键概念

| 概念 | 作用 |
|------|------|
| **State Machine（状态机）** | 管理状态切换：待机→跑步→跳跃→落地→死亡 |
| **Blend Space（混合空间）** | 根据一个数值（如速度）在多个动画间平滑混合（走路↔跑步） |
| **Layered Blend per Bone（按骨骼分层）** | 上下半身播不同动画（如边走边挥手） |
| **Slot（插槽）** | 给 Montage 留"插播位" |

### 它和其他三者的关系

```
AnimSequence/Montage（动作素材）
        │  被引用
        ▼
AnimBlueprint（大脑：决定播哪个、怎么混合）
        │  输出 Pose
        ▼
SkeletalMesh（外观：按 Pose 摆出造型显示出来）
        ↑
Skeleton（骨架：Pose 依据的结构）
```

> ⚠️ **每个 SkeletalMesh 对应一个 AnimBlueprint**（也可以没有，用默认姿势）。AnimBlueprint 是"逻辑"，SkeletalMesh 是"皮囊"，Skeleton 是"骨架"。

## 七、完整协作流程图（串起来）

```
1. 美术做好 Skeleton（骨架）+ SkeletalMesh（皮肤）
        │
2. 美术做 AnimSequence（一个个基础动作）
        │
3. 需要可打断的动作 → 做成 Montage（蒙太奇）
        │
4. 程序写 AnimBlueprint（动画蓝图）
        │     ├─ 状态机：根据输入/速度决定播哪个 AnimSequence
        │     └─ 预留 Slot 给 Montage 插播
        │
5. 运行时：
        ├─ 玩家移动 → AnimBlueprint 切到"跑步"AnimSequence
        ├─ 玩家开枪 → GAS 播放"射击"Montage（打断跑步）
        └─ Montage 的 Notify 在特定帧触发伤害/音效
        │
6. 最终：Skeleton 提供结构 → Pose 驱动 → SkeletalMesh 显示出来
```

## 八、Lyra 里的实际情况

| 资源 | Lyra 里在哪 | 说明 |
|------|------------|------|
| Skeleton | `Characters/` | 每种体型一个骨架（如 Mannequin） |
| SkeletalMesh | `Characters/` | 角色外观模型 |
| AnimSequence | `Characters/.../Animations/` | 走/跑/跳/死等基础动作 |
| Montage | `Characters/.../Animations/` 或 Weapons | 技能/攻击动作 |
| AnimBlueprint | `Characters/`（ABP_Mannequin 等） | 动画控制蓝图 |

> Lyra 的角色动画资源大多在 `Content/Characters/` 下，按"骨架 → 网格 → 动画 → 蓝图"组织。

## 九、常见误区

| 误区 | 正确理解 |
|------|---------|
| "Skeleton 和 SkeletalMesh 是一个东西" | Skeleton 是看不见的骨架；SkeletalMesh 是看得见的外观 |
| "Montage 就是 AnimSequence" | Montage 基于 AnimSequence，但可打断/混合/分段/触发事件 |
| "动画蓝图是动画本身" | 动画蓝图是"控制器"，决定播哪个动画，不是动画素材 |
| "换个皮肤要重做所有动画" | 同 Skeleton 的皮肤共享动画，不用重做 |
| "所有动作都用 Montage" | 基础循环动作（走跑跳）用 AnimSequence+状态机；技能才用 Montage |

## 十、总结速查

```
一个能动的角色 = 骨架 + 皮肤 + 动作 + 大脑

Skeleton（骨骼/骨架）     = 内部骨头结构（共享，决定能否共用动画）
SkeletalMesh（骨骼网格）  = 3D 外观模型（绑在骨架上，换装换这个）
AnimSequence（动画序列）  = 一段预设基础动作（不可打断，如走跑跳）
Montage（蒙太奇）         = 可打断/混合/分段的动画（技能/攻击用）★
AnimBlueprint（动画蓝图） = 控制大脑（状态机决定播哪个、怎么混合）

关系链：
  Skeleton 提供结构
    → AnimSequence/Montage 提供动作
      → AnimBlueprint 控制何时播何动作，输出 Pose
        → SkeletalMesh 按 Pose 显示出来

关键区分：
  基础循环动作 → AnimSequence + 状态机
  技能/攻击   → Montage（可打断、带 Notify）
```

**一句话**：**Skeleton 是骨架，SkeletalMesh 是皮肤，AnimSequence 是基础动作，Montage 是可打断的技能动作，AnimBlueprint 是控制一切的大脑**。Lyra 里基础动画走 AnimSequence+状态机，技能攻击走 Montage（配合 GAS），换皮肤靠共享 Skeleton。
