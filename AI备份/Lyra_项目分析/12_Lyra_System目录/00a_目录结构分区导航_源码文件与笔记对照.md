## 二、按职责分 5 个区（每个区的文件 + 一句话职责）

### 区 A：引擎与生命周期入口（6 个文件）

游戏从"进程启动"到"一局结束"的骨架，全部是引擎原生类的子类。

| 文件 | 是什么 | 一句话 |
|---|---|---|
| `LyraGameEngine.h/.cpp` | `UGameEngine` 子类 | 进程启动最早期的引擎对象（总闸） |
| `LyraGameInstance.h/.cpp` | `UCommonGameInstance` 子类 | 跨关卡存在的全局单例（登录、加密、会话请求） |
| `LyraGameSession.h/.cpp` | `AGameSession` 子类 | 一局比赛在服务器侧的会话状态（禁自动登录、开局/结束回调） |

**关系**：进程 → GameEngine 创建 GameInstance（跨关卡）→ 每局生成 GameSession（单局）。

### 区 B：资源与全局数据（6 个文件）★重点

Lyra 大量使用 `UPrimaryDataAsset`，这一区负责"加载它们 + 存全局配置"。

| 文件 | 是什么 | 一句话 |
|---|---|---|
| `LyraAssetManager.h/.cpp` | `UAssetManager` 子类 | 资源加载总枢纽：`GetAsset<T>`、启动任务、Cue 管理器初始化 ★ |
| `LyraAssetManagerStartupJob.h/.cpp` | 普通 `struct` | 一张"启动任务卡"：名字 + 权重 + 进度上报 |
| `LyraGameData.h/.cpp` | `UPrimaryDataAsset` 子类 | 全局数据资产：伤害/治疗 GE、动态 Tag GE |

**关系**：AssetManager 启动时跑一串 StartupJob；`GetGameData()` 就是其中一个（权重 25）。

### 区 C：网络同步（7 个文件）★最难、**目前笔记完全空白**

多人游戏"谁同步给谁、多久同步一次"的优化层。

| 文件 | 是什么 | 一句话 |
|---|---|---|
| `LyraReplicationGraph.h/.cpp` | `UReplicationGraph` 子类 | 复制图总调度：给每个 Actor 类定复制策略 ★；同文件还定义了两个自定义节点（`..._AlwaysRelevant_ForConnection`、`..._PlayerStateFrequencyLimiter`） |
| `LyraReplicationGraphSettings.h/.cpp` | `UDeveloperSettingsBackedByCVars` 子类 | 复制图参数面板：开关、网格大小、分桶频率 |
| `LyraReplicationGraphTypes.h` | 只有头 | 路由策略枚举 `EClassRepNodeMapping` + 配置结构 `FRepGraphActorClassSettings` |
| `LyraSignificanceManager.h/.cpp` | `USignificanceManager` 子类 | **空占位**，预留给"按重要性降频"的扩展点 |

### 区 D：蓝图工具库（6 个文件）

三个 `UBlueprintFunctionLibrary`，纯静态函数，给蓝图用。

| 文件 | 是什么 | 一句话 |
|---|---|---|
| `LyraSystemStatics.h/.cpp` | 蓝图函数库 | 运行时通用工具：按 PrimaryAssetId 取软引用、玩下一局、批量设网格材质参数、按类找组件 |
| `LyraDevelopmentStatics.h/.cpp` | 蓝图函数库 | 开发期专用：PIE 跳过流程开关、找 PIE 服务器世界、按短名找类 |
| `LyraActorUtilities.h/.cpp` | 蓝图函数库 | 只干一件事：`SwitchOnNetMode` 让蓝图能判断服务器/客户端 |

### 区 E：数据结构（2 个文件）

| 文件 | 是什么 | 一句话 |
|---|---|---|
| `GameplayTagStack.h/.cpp` | 两个 `USTRUCT` | `FGameplayTagStack`（Tag+层数）+ `FGameplayTagStackContainer`（可增量网络同步的容器） |

> 注意：它的"邻居概念" `FGameplayTagContainer`（一个 Tag 袋）**不是 Lyra 写的**，在引擎 `Runtime/GameplayTags` 里，笔记放在 `05_GameplayTagContainer/` 属于**概念补充**，不算 System 源码的拆解。

## 七、一句话总结

`System` 目录是**平铺的 27 个文件**，按职责可切成 5 个区：

```
 A 引擎入口（Engine/Instance/Session）      → 生命线
 B 资源与数据（AssetManager/StartupJob/GameData）→ Lyra 的重点
 C 网络同步（ReplicationGraph × 3 + Significance）→ 最难，笔记还空着
 D 蓝图工具库（SystemStatics/DevelopmentStatics/ActorUtilities）→ 小工具
 E 数据结构（GameplayTagStack）             → 基础零件
```

看文件先定位区：**区 B 和区 C 是"技术含量"所在**，区 A/D/E 基本是骨架和零件。
