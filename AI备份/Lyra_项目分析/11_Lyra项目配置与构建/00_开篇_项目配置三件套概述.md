# 00 — 开篇：`.uproject`、`Target.cs`、`Build.cs` —— Lyra 工程配置"三件套"

> **定位**：开始深入 Lyra 工程最底层的"项目配置文件"——`.uproject`（项目清单）、`Target.cs`（构建目标）、`Build.cs`（模块依赖）。这一篇先给全局地图，搞清楚每个文件管什么、谁先谁后。

---

## 一、一句话：三个文件管三件事

| 文件 | 管什么 | 类比 |
|---|---|---|
| `LyraStarterGame.uproject` | **项目清单**：这是不是一个 UE 项目、用哪个引擎版本、启用哪些插件/模块 | 楼盘的"立项书" |
| `Source/*.Target.cs` | **构建目标**：要"构建出哪几种可运行程序"（客户端/服务器/游戏…），各用什么配置 | 施工队要建"哪几栋楼" |
| `Source/*Module.Build.cs` | **模块依赖**：某个代码模块能 include 哪些其他模块 | 每栋楼"能接哪几条市政管线" |

> **大白话流程**：`uproject` 说"我要建一个小区" → `Target.cs` 说"小区要建 A 栋（客户端）、B 栋（服务器）" → `Build.cs` 说"A 栋里每户（模块）能接什么水电"。

---

## 二、逐个初识

### ① `LyraStarterGame.uproject`（项目清单）

`FileVersion` / `EngineAssociation: "5.6"`（用 UE 5.6） / `Modules: [LyraGame, LyraEditor]` / 一长串 `Plugins`（启用了哪些插件：GameplayAbilities、GameFeatures、ModularGameplay…）。

### ② `Target.cs`（构建目标）

例 `LyraClient.Target.cs`：
```csharp
public class LyraClientTarget : TargetRules
{
	public LyraClientTarget(TargetInfo Target) : base(Target)
	{
		Type = TargetType.Client;                      // 这是"客户端"目标
		ExtraModuleNames.AddRange(new string[] { "LyraGame" });   // 要编 LyraGame 模块
		LyraGameTarget.ApplySharedLyraTargetSettings(this);       // 用共享配置
	}
}
```

例 `LyraGameSteamEOS.Target.cs`：
```csharp
public class LyraGameSteamEOSTarget : LyraGameTarget   // 继承"游戏"目标
{
	public LyraGameSteamEOSTarget(TargetInfo Target) : base(Target)
	{
		CustomConfig = "SteamEOS";   // 加一套自定义配置名（Steam+EOS 联机）
	}
}
```

### ③ `Build.cs`（模块依赖）

例 `LyraGame.Build.cs`：`PublicDependencyModuleNames` 里一长串模块名（GameplayTags、GameplayAbilities、ModularGameplay…），决定 LyraGame 模块能 include 什么。

## 三、本文件夹学习计划（预览）

- `01_uproject详解_项目清单与插件`：FileVersion、EngineAssociation、Modules、Plugins 每个字段。
- `02_TargetType详解_Client_Server_Game`：TargetType 有几种、怎么选。
- `03_Target链_LyraGameTarget与共享设置`：为什么 Target 能继承、共享设置放哪。
- `04_CustomConfig详解_SteamEOS`：一套代码多套配置是怎么来的。
- `05_Build.cs详解_模块依赖与Public/Private`：DependencyModuleNames 的机制。

---

**一句话**：`.uproject` 立项、`Target.cs` 定目标、`Build.cs` 管依赖——三件套决定了"这个项目能被编译成什么、能链接什么"，是一切 Lyra 代码能跑起来的"地基"。
