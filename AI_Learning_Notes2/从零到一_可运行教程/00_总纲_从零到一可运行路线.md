## 一、这条路线和旧路线有什么不同

| 维度 | 旧路线（Lyra 复刻） | 本路线（从零到一） |
|---|---|---|
| 目标 | 一比一还原 Lyra 源码 | **自己写**，每步都能跑 |
| 顺序 | 按 Lyra 目录自上而下 | 按**能力递进**：能编译 → 能动 → 能操作 → 有玩法 |
| 依赖 | 大量前置依赖，常需注释挂起 | **零挂起**，每课自洽 |
| 验收 | 代码行 diff = 0 | **编译通过 + 编辑器可见效果** |
| 讲义 | 总 md + 逐行注释版 + 还原文件 | **一课一 md，代码你自己敲** |
| 谁写代码 | AI 生成还原文件 | **你写，我讲** |

> 🔑 一句话：旧路线是「抄一遍 Lyra」，本路线是「自己长出来」。

## 二、每课的固定结构（6 段，不许省）

```markdown
# NN — <课名>

> 本课目标：<一句话>
> 改动文件：<列表>
> 前置：<上一课>
> ✅ 本课结束可编译、可运行

## 一、为什么需要它（场景 + 类比）
## 二、完整代码（整份贴完，可直接抄）
## 三、逐段拆解（小代码块 + 小表格 + 一句类比）
## 四、怎么验证（编译命令 + 编辑器操作 + 预期现象）
## 五、常见报错（症状 → 原因 → 改法）
## 六、本课新元素（一行一个，只列首次出现的）
```

**硬规则**：
1. 每课结束**必须**给出可执行的编译命令 + 编辑器里能看到的现象。
2. 代码**整份贴完**，不切片、不省略 —— **但由你自己敲进工程**，我不代写。
3. 新元素**就地教**（每段代码后立刻列），不攒到末尾。
4. 报错章节必须写真实会遇到的（UHT 报错、链接错误、模块找不到）。
5. 每课开头写清「**你要新建/修改哪几个文件**」，路径给全。

## 五、验收方式（每课必做）

```powershell
# 1. 编译（每课结束必跑）
& "D:\ue5\Epic Games\UE_5.4\Engine\Build\BatchFiles\Build.bat" texiaoue54Editor Win64 Development -Project="E:\ue5\game_design\code\texiaoue54\texiaoue54.uproject" -WaitMutex

# 2. 启动编辑器
& "D:\ue5\Epic Games\UE_5.4\Engine\Binaries\Win64\UnrealEditor.exe" "E:\ue5\game_design\code\texiaoue54\texiaoue54.uproject"
```

> ⚠️ **编译前必须先关掉编辑器**。编辑器会占用 `UnrealEditor-texiaoue54.dll`，导致链接报 `LNK1104: cannot open file`。

**通过标准**：
- 编译输出 `Build succeeded` / `Total execution time`，无 `error`。
- 编辑器里能看到本课「预期现象」。
- Output Log 无红色 Error。
