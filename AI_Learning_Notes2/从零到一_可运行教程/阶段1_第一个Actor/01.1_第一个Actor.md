## 一、为什么从 Actor 开始（场景 + 类比）

UE 世界里**所有能放进关卡的东西都是 Actor**：

| 东西 | 是不是 Actor |
|---|---|
| 一盏灯 | ✅ `ALight` |
| 一个方块 | ✅ `AStaticMeshActor` |
| 玩家角色 | ✅ `ACharacter`（继承自 `APawn`，`APawn` 继承自 `AActor`） |
| 摄像机 | ✅ `ACameraActor` |
| 一个纯数据配置 | ❌ 那是 `UDataAsset` |

所以「第一个 C++ 类」选 Actor 最合适 —— 它**能被拖进关卡、能被看见、能跑起来**，闭环最短。

> 🔑 **类比**：`AActor` 是「**能站在场景里的实体**」的通用底座。
> 就像乐高积木的**底板**：底板本身没什么用，但所有积木都得插在底板上。
> 本课的 `AMyFirstActor` 就是一块**光秃秃的底板** —— 它什么都不做，只在被创建时喊一声「我来了」。

### 1.1 UE 的类名前缀规则（先记住，后面天天见）

| 前缀 | 含义 | 例子 |
|---|---|---|
| `A` | Actor —— 能放进关卡的实体 | `AActor` / `AMyFirstActor` / `ACharacter` |
| `U` | UObject —— 不能放进关卡，但能被引擎管理（GC、反射、序列化） | `UObject` / `UStaticMeshComponent` / `UDataAsset` |
| `F` | 纯 C++ 结构体 / 类 —— 不参与反射，没有 GC | `FString` / `FVector` / `FActorTickFunction` |
| `T` | 模板类 | `TArray` / `TMap` / `TSharedPtr` |
| `I` | 接口 | `IInterface` |

> 💡 为什么本课类名是 `AMyFirstActor` 而不是 `MyFirstActor`：因为它是 Actor，必须带 `A`。
> 少了 `A` → UHT 会报错，或者它变成一个普通 C++ 类，引擎完全不认。

### 2.1 `Source\texiaoue54\01_Actor\MyFirstActor.h`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.
// 版权声明：UE 模板文件的固定首行。纯注释，删掉也能编译，但保留是引擎惯例

#pragma once
// 头文件保护：保证本文件在一次编译单元里只被展开一次
// 等价于老式 #ifndef MYFIRSTACTOR_H / #define MYFIRSTACTOR_H / #endif 三件套，但只需一行
// 不写 → 同一个 .h 被两处 include 时，类被重复定义 → 报 C2011: 'AMyFirstActor': class type redefinition

#include "CoreMinimal.h"
// 引擎核心基础头（引擎路径：Engine\Source\Runtime\Core\Public\CoreMinimal.h）
// 它一次性带进 UE 最常用的基础设施：
//   · 定宽整型：int32 / uint8 / int64（UE 不用裸 int，因为各平台 int 宽度不保证一致）
//   · 字符串：FString / FName / FText
//   · 容器：TArray / TMap / TSet
//   · 日志：UE_LOG 宏、TEXT() 宏
//   · 智能指针：TSharedPtr / TUniquePtr
// 几乎所有 UE 的 .h 第一件事就是 include 它

#include "GameFramework/Actor.h"
// AActor 基类的定义所在（引擎路径：Engine\Source\Runtime\Engine\Classes\GameFramework\Actor.h）
// 下面第 20 行写了 "public AActor"，编译器必须先知道 AActor 长什么样
// 不 include → 报 C2504: 'AActor': 未定义基类

#include "MyFirstActor.generated.h"
// UHT（Unreal Header Tool）在编译前自动生成的反射代码
// 它不在你的源码目录里，编译时才生成到：
//   Intermediate\Build\Win64\x64\UnrealEditor\Development\texiaoue54\MyFirstActor.generated.h
// 内容：类的反射信息、GENERATED_BODY() 展开体、序列化函数等
// ⚠️ 三条铁律：
//   1. 文件名必须与 .h 完全一致（MyFirstActor.h → MyFirstActor.generated.h），大小写也要一致
//   2. 必须是本文件最后一个 #include，后面不能再 include 任何东西
//   3. 只有标了 UCLASS() 的类才需要它

UCLASS()
// UCLASS()：告诉 UHT「这是一个 UE 反射类，请为它生成反射代码」
// 必须紧贴在 class 声明的正上方，中间不能插别的语句
// 括号里可以填说明符，比如 UCLASS(Blueprintable) 让蓝图能继承它
// 本课留空 = 用默认设置
// 不写 → UHT 完全忽略这个类 → 编辑器里看不到、蓝图里找不到、无法被引擎管理

class TEXIAOUE54_API AMyFirstActor : public AActor
// class            ：C++ 类声明关键字
// TEXIAOUE54_API   ：模块导出宏，由 UBT 自动定义
//                    规则 = 模块名全大写 + _API（模块名见 texiaoue54.Build.cs:5）
//                    作用 = 让这个类的符号从 DLL 里导出，别的模块才能链接到它
//                    不写 → 跨模块使用时链接报 LNK2019 找不到符号
// AMyFirstActor    ：类名。UE 的 Actor 类必须以 A 开头（A = Actor，U = UObject，F = 纯结构体）
// : public AActor  ：公有继承 AActor —— 这是「能放进关卡」的唯一前提
//                    继承链：AMyFirstActor → AActor → UObject
{
	GENERATED_BODY()
	// GENERATED_BODY()：UHT 必需宏，必须放在类体的第一行（在第一个 { 之后）
	// 它会被展开成一大坨代码，包括：
	//   · 构造函数声明
	//   · 静态类信息函数 StaticClass()
	//   · 反射注册、序列化、GC 相关函数
	//   · 友元声明（让 UHT 生成的代码能访问私有成员）
	// 不写 → 编译报 GENERATED_BODY 相关错误，或类没有构造函数

public:
	// public 区：外部（引擎、蓝图、其他类）可以直接访问

	// 构造函数：创建对象时调用，用来设置默认值
	// 注意：UE 的构造函数可能被调用多次（编辑器加载、蓝图编译、CDO 创建等），
	//       所以里面只做「设默认值」，不要做「依赖运行时的逻辑」
	AMyFirstActor();

protected:
	// protected 区：只有自己和子类能访问，外部不能直接调
	// UE 惯例：生命周期函数（BeginPlay / EndPlay 等）都放 protected

	// BeginPlay：游戏开始（PIE 点 Play）或 Actor 运行时被生成时，调用一次
	// virtual  ：父类 AActor 里已经是虚函数，这里重写
	// override ：C++11 关键字，让编译器帮你检查「确实重写了父类虚函数」
	//            签名写错（比如参数类型不对）会直接编译报错，而不是悄悄变成一个新函数
	virtual void BeginPlay() override;

public:
	// Tick：每帧调用一次，参数 DeltaSeconds = 距上一帧经过的秒数
	// 本课在构造函数里把 Tick 关掉了，所以这个函数实际不会被调用
	// 保留它只是为了保持「标准 Actor 骨架」，01.4 会启用它做旋转
	virtual void Tick(float DeltaSeconds) override;
};
```

### 2.2 `Source\texiaoue54\01_Actor\MyFirstActor.cpp`

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.
// 版权声明，同 .h

#include "MyFirstActor.h"
// IWYU 规则（Include What You Use）：.cpp 的第一个 include 必须是自己的 .h
// 原因：
//   1. 保证 .h 自身是「自包含」的 —— 如果 .h 漏了某个 include，这里会立刻暴露
//   2. UE 的 Unity Build 会把多个 .cpp 拼在一起编译，先包含自己的 .h 能避免符号冲突
// 不写 → 报 C2039 / C2065：AMyFirstActor 未定义

AMyFirstActor::AMyFirstActor()
// 类外定义构造函数：格式是「类名::类名()」
// 这里没有初始化列表，因为 UE 的成员默认值都在 .h 里用 UPROPERTY 或直接赋值设好了
{
	// PrimaryActorTick 是 AActor 的成员（类型 FActorTickFunction），控制「这个 Actor 要不要 Tick」
	// bCanEverTick = false → 引擎永远不会为这个 Actor 调用 Tick()
	// 好处：省掉每帧的函数调用开销。关卡里几百个 Actor 都开 Tick 会明显掉帧
	// 注意：这是「能不能 Tick」的总开关；另有 bStartWithTickEnabled 控制「初始是否启用」
	PrimaryActorTick.bCanEverTick = false;
}

void AMyFirstActor::BeginPlay()
{
	// Super = 父类 AActor 的指针别名（由 UHT 的 GENERATED_BODY() 生成）
	// Super::BeginPlay() 必须第一个调用，原因：
	//   AActor::BeginPlay() 里做了很多内部初始化：
	//     · 设置 bHasBegunPlay = true
	//     · 通知所有组件「游戏开始了」（UActorComponent::BeginPlay）
	//     · 触发蓝图里的 BeginPlay 事件
	//   漏掉 → 组件不初始化、蓝图事件不触发、后续出现各种诡异 bug
	Super::BeginPlay();

	// UE_LOG(日志分类, 级别, 格式串, 参数...)
	//   LogTemp  ：临时日志分类。引擎内置，不用自己声明。正式项目应该用自定义分类
	//   Warning  ：级别。可选 Log / Warning / Error / Fatal
	//              · Log     —— 白色，可能被 Output Log 的过滤器隐藏
	//              · Warning —— 黄色，默认显示，最适合调试
	//              · Error   —— 红色
	//              · Fatal   —— 红色 + 直接崩溃
	//   TEXT("...")：把普通字符串字面量转成 UE 的宽字符 TCHAR
	//              UE 内部字符串是 TCHAR（Windows 上是 wchar_t），
	//              直接写 "..." 是 char，类型不匹配会报错
	//   %s       ：格式化占位符，对应一个 const TCHAR* 参数
	//   *GetName()：GetName() 返回 FString，前面加 * 取出内部的 const TCHAR*
	//              （FString 重载了 operator* 来做这个转换）
	//              不加 * → 传进去的是 FString 对象，%s 会读到垃圾数据甚至崩溃
	UE_LOG(LogTemp, Warning, TEXT("AMyFirstActor::BeginPlay 已执行，Actor 名称：%s"), *GetName());
}

void AMyFirstActor::Tick(float DeltaSeconds)
{
	// 调父类 Tick。AActor::Tick 目前是空实现，但保持这个惯例：
	// 万一以后父类加了逻辑，你不会漏掉
	// DeltaSeconds 本课没用到，01.4 会用它做「每秒转 90 度」这类与帧率无关的旋转
	Super::Tick(DeltaSeconds);
}
```

> ⚠️ **两个文件都必须建**。只建 `.h` 会链接报错（`LNK2019`），因为构造函数和 `BeginPlay` 只有声明没有实现。

## 三、逐段拆解

### 3.1 `.h` 的 include 区

```cpp
#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "MyFirstActor.generated.h"
```

| 行 | 干什么 |
|---|---|
| `#pragma once` | 防止同一个头文件被重复包含（C++ 标准写法） |
| `#include "CoreMinimal.h"` | 引擎核心基础头：`FString` / `TEXT()` / `UE_LOG` / `int32` 都在这里 |
| `#include "GameFramework/Actor.h"` | `AActor` 基类定义 —— 不 include 它，`public AActor` 直接报「未定义」 |
| `#include "MyFirstActor.generated.h"` | UHT 自动生成的反射代码。**必须是最后一个 include**，且文件名与 `.h` 完全一致 |

**本段新元素**
- `#pragma once` —— 防重复包含，每个 `.h` 第一行（版权注释之后） —— `MyFirstActor.h:3`
- `CoreMinimal.h` —— 引擎核心头，几乎所有 `.h` 都要 include —— `MyFirstActor.h:5`
- `GameFramework/Actor.h` —— `AActor` 的定义所在 —— `MyFirstActor.h:6`
- `MyFirstActor.generated.h` —— UHT 生成，文件名必须与 `.h` 同名 —— `MyFirstActor.h:7`

**这段在干什么**

| include | 少了会怎样 |
|---|---|
| `CoreMinimal.h` | `FString` / `TEXT` / `UE_LOG` 全部未定义 |
| `GameFramework/Actor.h` | `AActor` 未定义，`public AActor` 报错 |
| `MyFirstActor.generated.h` | UHT 报错：`Unable to find 'MyFirstActor.generated.h'` |

> 类比：`CoreMinimal.h` = 工具箱，`Actor.h` = 底板图纸，`generated.h` = 引擎给你自动生成的「身份证」。

> ⚠️ **顺序不能乱**：`generated.h` 必须在**所有** include 之后。放前面会报 `generated.h must be the last include`。

> 💡 **为什么 `CoreMinimal.h` 在 VS 里可能报红**：这是 IntelliSense 的显示问题，不是真错误。
> 原因：`MyFirstActor.cpp` 还没建 → 这个 `.h` 没有所属的翻译单元 → VS 只能用项目级 `IncludePath`，
> 而 UBT 生成的 `IncludePath` 有 24KB 上限（`VCProjectFileGenerator.cs:38` 的 `MaxSharedIncludePaths`），
> 超限后 `Engine\Source\Runtime\Core\Public` 被挤掉了。
> **解决**：建好 `.cpp` 并 include 自己的 `.h`，编译一次（或右键 `.uproject` → Generate Visual Studio project files），报红自动消失。

### 3.2 `UCLASS()` + 类声明

```cpp
UCLASS()
class TEXIAOUE54_API AMyFirstActor : public AActor
{
	GENERATED_BODY()
```

| 行 | 干什么 |
|---|---|
| `UCLASS()` | 告诉 UHT「这是一个 UE 反射类」，必须写在类声明**正上方** |
| `class TEXIAOUE54_API AMyFirstActor` | `TEXIAOUE54_API` = 模块导出宏，让引擎能加载这个类 |
| `: public AActor` | 继承 `AActor` —— 这是「能放进关卡」的前提 |
| `GENERATED_BODY()` | UHT 必需宏，展开成构造函数声明、反射注册等一大堆代码 |

**本段新元素**
- `UCLASS()` —— 标记 UE 反射类，UHT 靠它生成代码 —— `MyFirstActor.h:12`
- `TEXIAOUE54_API` —— 模块导出宏（模块名全大写 + `_API`） —— `MyFirstActor.h:13`
- `GENERATED_BODY()` —— UHT 必需宏，必须放在类体第一行 —— `MyFirstActor.h:15`

**这段在干什么**

| 宏 | 不写会怎样 |
|---|---|
| `UCLASS()` | UHT 不生成反射代码 → 类无法被引擎识别 → 编辑器里看不到 |
| `TEXIAOUE54_API` | 链接时找不到符号（跨模块调用失败） |
| `GENERATED_BODY()` | 编译报 `GENERATED_BODY` 相关错误，或类没有构造函数 |

> 类比：`UCLASS()` = 给这个类**上户口**；`GENERATED_BODY()` = 户口本上的**必填页**；`TEXIAOUE54_API` = **门禁卡**（别的模块能进来）。

> 💡 **为什么是 `TEXIAOUE54_API` 而不是 `TEXIAOUE54GAME_API`**：因为你的模块名就叫 `texiaoue54`（见 `texiaoue54.Build.cs:5`），全大写就是 `TEXIAOUE54`。

> 💡 **`UCLASS()` 括号里能填什么**（本课不用，但先知道有这些）：
> - `UCLASS(Blueprintable)` —— 允许蓝图继承这个类
> - `UCLASS(BlueprintType)` —— 允许作为蓝图变量类型
> - `UCLASS(Abstract)` —— 抽象类，不能直接实例化
> - `UCLASS(ClassGroup=(Custom), meta=(BlueprintSpawnableComponent))` —— 组件类常用
> - 留空 `UCLASS()` = 全部用默认值

### 3.3 三个函数声明

```cpp
public:
	// 构造函数：设置 Tick 开关等默认值
	AMyFirstActor();

protected:
	// 游戏开始（或 Actor 被生成）时调用一次
	virtual void BeginPlay() override;

public:
	// 每帧调用（本课暂不使用，但保留标准骨架）
	virtual void Tick(float DeltaSeconds) override;
```

| 行 | 干什么 |
|---|---|
| `AMyFirstActor();` | 构造函数 —— 创建对象时调用，用来设默认值 |
| `virtual void BeginPlay() override;` | 重写父类的 `BeginPlay` —— 游戏开始 / Actor 生成时调用一次 |
| `virtual void Tick(float DeltaSeconds) override;` | 重写父类的 `Tick` —— 每帧调用，`DeltaSeconds` = 距上一帧的秒数 |

**本段新元素**
- `AMyFirstActor()` —— 构造函数，与类同名，无返回值 —— `MyFirstActor.h:18`
- `BeginPlay()` —— `AActor` 的生命周期函数，游戏开始/生成时调用一次 —— `MyFirstActor.h:22`
- `Tick(float DeltaSeconds)` —— 每帧调用，参数是帧间隔秒数 —— `MyFirstActor.h:26`
- `override` —— C++11 关键字，表示「我确实在重写父类的虚函数」，写错签名会编译报错 —— `MyFirstActor.h:22`

**这段在干什么**

| 函数 | 什么时候调用 | 本课用途 |
|---|---|---|
| 构造函数 | `NewObject` / 拖进关卡时 | 设 `bCanEverTick = false` |
| `BeginPlay` | 游戏开始（PIE 点 Play）时 | 打一行日志 |
| `Tick` | 每帧（如果启用） | 本课不启用，空实现 |

> 类比：构造函数 = **出生**，`BeginPlay` = **上学第一天**，`Tick` = **每天的心跳**。

> 💡 `protected` vs `public`：`BeginPlay` 放 `protected` 是 UE 惯例（外部不该直接调它，引擎自己会调）；构造函数和 `Tick` 放 `public` 也是惯例。

> 💡 **`virtual` + `override` 为什么两个都要写**：
> - `virtual` 是「我允许子类重写我」—— 父类 `AActor` 已经写了，子类重写时**可写可不写**，但写上更清晰
> - `override` 是「我确实在重写父类」—— 编译器会检查父类有没有同名同签名的虚函数
> - 只写 `virtual` 不写 `override`：签名写错时，编译器会当成「新函数」，不报错 → 你的 `BeginPlay` 永远不被调用（超难查的 bug）
> - 两个都写：签名写错立刻报 `C3668: 未重写任何基类方法`

### 3.4 `.cpp` 的 include

```cpp
#include "MyFirstActor.h"
```

| 行 | 干什么 |
|---|---|
| `#include "MyFirstActor.h"` | **必须是第一行 include**（UE 的 IWYU 规则：`.cpp` 先包含自己的头） |

**本段新元素**
- IWYU（Include What You Use）—— UE 的包含规范：`.cpp` 第一行必须是自己的 `.h` —— `MyFirstActor.cpp:3`

**这段在干什么**

| 写法 | 结果 |
|---|---|
| `#include "MyFirstActor.h"` 第一行 | ✅ 正确 |
| 先 include 别的，再 include 自己的 | ⚠️ 可能触发编译警告 / 隐藏依赖问题 |

> 类比：先照镜子（自己的 `.h`），再看别人。

> 💡 **为什么 UE 这么在意顺序**：UE 用 Unity Build（把多个 `.cpp` 拼成一个大的 `.cpp` 编译，加快速度）。
> 如果每个 `.cpp` 不先包含自己的 `.h`，前一个 `.cpp` 的 include 会「污染」后一个，
> 导致「单独编译能过、整体编译报错」这种最难查的问题。

### 3.5 构造函数

```cpp
AMyFirstActor::AMyFirstActor()
{
	// 本课不需要每帧更新，关掉 Tick 省性能
	PrimaryActorTick.bCanEverTick = false;
}
```

| 行 | 干什么 |
|---|---|
| `AMyFirstActor::AMyFirstActor()` | 类外定义构造函数，`类名::类名()` |
| `PrimaryActorTick.bCanEverTick = false;` | 关掉 Tick —— 不关的话每帧都会调 `Tick()`，浪费性能 |

**本段新元素**
- `PrimaryActorTick` —— `AActor` 的成员，控制 Tick 行为 —— `AActor` 成员
- `bCanEverTick` —— `PrimaryActorTick` 的子字段，`false` = 永不 Tick —— `AActor` 成员

**这段在干什么**

| 值 | 效果 |
|---|---|
| `bCanEverTick = true` | 每帧调 `Tick()` |
| `bCanEverTick = false` | 永不调 `Tick()`（本课用这个） |

> 类比：`bCanEverTick` = **心跳开关**。关掉就不跳了。

> ⚠️ **构造函数里不要写 `UE_LOG`**：构造函数可能在编辑器加载资源时被调用（比如打开蓝图编辑器），日志会刷屏。日志放 `BeginPlay`。

> 💡 **`PrimaryActorTick` 里还有哪些字段**（本课不用，先知道）：
> - `bCanEverTick` —— 总开关，能不能 Tick
> - `bStartWithTickEnabled` —— 初始是否启用（默认 true）
> - `TickInterval` —— Tick 间隔秒数，`0` = 每帧；设 `0.1` = 每秒 10 次
> - `TickGroup` —— 在哪个阶段 Tick（`TG_PrePhysics` / `TG_DuringPhysics` / `TG_PostPhysics` 等）
> - `bTickEvenWhenPaused` —— 暂停时是否继续 Tick

### 3.6 `BeginPlay`

```cpp
void AMyFirstActor::BeginPlay()
{
	// 必须先调用父类实现，否则 AActor 的内部初始化会缺失
	Super::BeginPlay();

	// 在输出日志里打印一行，用来确认这个 Actor 真的被创建并运行了
	UE_LOG(LogTemp, Warning, TEXT("AMyFirstActor::BeginPlay 已执行，Actor 名称：%s"), *GetName());
}
```

| 行 | 干什么 |
|---|---|
| `Super::BeginPlay();` | 调父类 `AActor::BeginPlay()` —— **必须调**，否则父类的初始化逻辑被跳过 |
| `UE_LOG(LogTemp, Warning, TEXT("..."))` | 往 Output Log 打一行黄色警告级日志 |
| `%s` + `*GetName()` | `GetName()` 返回 `FString`，`*` 取出 `TCHAR*` 给 `%s` 用 |

**本段新元素**
- `Super::` —— 调用父类同名函数 —— `MyFirstActor.cpp:14`
- `UE_LOG(分类, 级别, 格式串, 参数...)` —— 引擎日志宏 —— `MyFirstActor.cpp:17`
- `LogTemp` —— 临时日志分类（引擎内置，不用自己声明） —— `MyFirstActor.cpp:17`
- `Warning` —— 日志级别（`Log` / `Warning` / `Error` / `Fatal`） —— `MyFirstActor.cpp:17`
- `TEXT("...")` —— 把字符串字面量转成 UE 的宽字符格式 —— `MyFirstActor.cpp:17`
- `GetName()` —— `UObject` 成员，返回对象名 —— `MyFirstActor.cpp:17`

**这段在干什么**

| 部分 | 说明 |
|---|---|
| `LogTemp` | 日志分类。本教程统一用它，方便在 Output Log 里过滤 |
| `Warning` | 级别。用 `Warning` 是因为它**默认显示**（`Log` 级别可能被过滤掉） |
| `TEXT("...")` | UE 内部用 `TCHAR`（宽字符），普通 `"..."` 是 `char`，必须包一层 |
| `*GetName()` | `FString` → `const TCHAR*`，`%s` 需要指针 |

> 类比：`UE_LOG` = **往公告栏贴通知**。`LogTemp` = 公告栏编号，`Warning` = 黄色便签（显眼），`TEXT()` = 用中文写（引擎只认中文）。

> ⚠️ **`Super::BeginPlay()` 忘了调会怎样**：`AActor` 内部的一些初始化（比如组件注册、`bHasBegunPlay` 标记）不会执行，后续可能出现诡异 bug。**永远先调 Super**。

> 💡 **`UE_LOG` 的格式化占位符**（和 `printf` 基本一样，但字符串要用 `%s` + `*`）：
> | 占位符 | 类型 | 例子 |
> |---|---|---|
> | `%d` | `int32` | `UE_LOG(LogTemp, Warning, TEXT("HP=%d"), 100);` |
> | `%f` | `float` / `double` | `UE_LOG(LogTemp, Warning, TEXT("Speed=%f"), 3.5f);` |
> | `%s` | `const TCHAR*` | `UE_LOG(LogTemp, Warning, TEXT("Name=%s"), *GetName());` |
> | `%p` | 指针 | `UE_LOG(LogTemp, Warning, TEXT("Ptr=%p"), this);` |
>
> ⚠️ `%s` 传 `FString` 必须加 `*`，传 `FName` 必须调 `.ToString()`，否则崩溃。

> 💡 **`GetName()` 返回什么**：`FString`，内容是「关卡里的对象名」，比如 `MyFirstActor_1`。
> 后面的 `_1` / `_2` 是引擎自动加的序号（关卡里有多个同名对象时用来区分）。

### 3.7 `Tick`

```cpp
void AMyFirstActor::Tick(float DeltaSeconds)
{
	Super::Tick(DeltaSeconds);
}
```

| 行 | 干什么 |
|---|---|
| `Super::Tick(DeltaSeconds);` | 调父类 Tick（`AActor::Tick` 目前是空的，但保持惯例） |

**本段新元素**
- `DeltaSeconds` —— 距上一帧的秒数（60fps 时约 0.0167） —— `MyFirstActor.cpp:23`

**这段在干什么**

| 情况 | 说明 |
|---|---|
| `bCanEverTick = false` | 这个函数**永远不会被调用**，写了也没用 |
| 为什么还写 | 保持标准骨架，01.4 要启用 Tick 做旋转 |

> 类比：这是**预留的心跳接口**，本课先关掉，01.4 再打开。

> 💡 **`DeltaSeconds` 为什么重要**：它让「速度」与帧率无关。
> 错误写法：`Rotation += 1.0f;` —— 60fps 时每秒转 60 度，144fps 时每秒转 144 度
> 正确写法：`Rotation += 90.0f * DeltaSeconds;` —— 不管多少帧，每秒都转 90 度

## 七、本课你学到了什么（复盘）

1. **一个 C++ Actor 的最小构成**：`.h`（声明）+ `.cpp`（实现），缺一不可。
2. **UHT 的三个必需件**：`UCLASS()` / `GENERATED_BODY()` / `XXX.generated.h`。
3. **生命周期**：构造函数（出生）→ `BeginPlay`（上学第一天）→ `Tick`（心跳）。
4. **日志**：`UE_LOG(LogTemp, Warning, TEXT("..."))`，在 Output Log 里看。
5. **完整闭环**：写代码 → 编译 → 开编辑器 → 拖进关卡 → Play → 看日志。
6. **UE 命名前缀**：`A` = Actor，`U` = UObject，`F` = 纯结构体，`T` = 模板。
