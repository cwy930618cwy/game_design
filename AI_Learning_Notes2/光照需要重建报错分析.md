# UE5「光照需要重建（1 未构建对象）」报错分析与解决

## 一、报错现象

编辑器视口左上角红色提示：

> 光照需要重建（1 未构建对象）
> 运行控制台命令 `DumpUnbuiltLightInteractions` 来查看未构建内容
> `DisableAllScreenMessages` 进行抑制

## 二、报错本质（先定性，别慌）

这不是崩溃，也不是编译错误，而是 UE5 的一条**屏幕消息（Screen Message）**。

含义：当前关卡里有 **1 个对象**依赖「预计算光照数据」（Lightmap / 静态光照缓存），但这份数据已经过期或根本没生成。编辑器在提醒你：光照数据与实际场景不一致，需要重新构建（Build Lighting）。

- 数字「1」= 有 1 个这样的未构建对象。
- 只要场景里有 **Static（静态）或 Stationary（固定）** 的光源 / 需要烘焙光照的几何体，就会触发。
- 它**不影响编辑器正常运行**，但画面里这部分光照是错的（偏黑、阴影不对、间接光缺失）。

## 三、结合本项目为什么会触发

排查到的项目实际配置：

| 项目 | 当前值 | 来源 |
| --- | --- | --- |
| 动态全局光照 | Lumen（`r.DynamicGlobalIlluminationMethod=1`） | `Config/DefaultEngine.ini` |
| 反射 | Lumen（`r.ReflectionMethod=1`） | 同上 |
| 阴影 | 虚拟阴影贴图（`r.Shadow.Virtual.Enable=1`） | 同上 |
| 光栅/RHI | DX12 + SM6 | 同上 |
| 当前关卡 | `/Game/zixue/MainMap` | `Content/zixue/MainMap.umap` |
| 关卡特性 | World Partition + HLOD | `__ExternalActors__/zixue/MainMap/...`、`MainMap_HLOD0_Instancing.uasset` |

**关键点：Lumen 项目理论上不需要烘焙静态光照。** 但只要有任何一个对象仍是 Static/Stationary 光照模式，UE 就仍会要求构建。常见触发动作：

1. 新建 / 移动 / 删除 / 复制了 **Static 或 Stationary 光源**，没重新 Build Lighting。
2. 从别的关卡或外部**导入、复制了带静态光照的对象**。
3. 把某个光源的 Mobility 从 Movable 改成了 Static / Stationary。
4. World Partition 下构建了 HLOD / 实例化静态网格，引入需要光照数据的对象。
5. 拉取或还原了关卡文件，光照缓存与场景版本对不上。

## 四、先定位：到底是哪 1 个对象

按提示操作，别猜：

1. 打开 **Output Log**（窗口 → 开发人员工具 → 输出日志）。
2. 在控制台输入命令并回车：

   ```
   DumpUnbuiltLightInteractions
   ```

3. 日志里会打印出未构建对象的名称 / 路径。记下来，后面针对性处理。

> 补充：也可以在工具栏 **Build → Lighting Build**（构建 → 光照构建）面板里查看/管理光照构建状态。

## 五、解决方案（按推荐程度排序）

### 方案 A：直接构建光照（最稳妥，保留静态光照）

适用：你想保留 Static/Stationary 光源。

1. 先保存关卡（Ctrl+S）。
2. 工具栏 **Build（构建）→ Build Lighting Only（仅构建光照）**。
3. 等 Lightmass / 光照构建跑完（World Partition + HLOD 关卡会明显慢一些）。
4. 构建完成，红色提示消失，画面光照恢复正常。

> 若构建后仍提示，用 **Build Lighting → 勾选 Force rebuild / 重建已修改** 强制全量重建。

### 方案 B：改成纯动态光照（Lumen 项目一劳永逸，推荐）

适用：本项目已经用 Lumen（`DynamicGlobalIlluminationMethod=1`），本就不需要烘焙。

做法二选一：

- **关卡层面**：把关卡里所有光源的 **Mobility 改为 Movable（可移动）**。全动态后不再依赖 Lightmap，提示消失。
- **项目层面**（更彻底）：项目设置 → Engine → Rendering → Lighting，关闭 **Allow Static Lighting（允许静态光照）**。关闭后引擎会把光源强制当动态处理，从此不再需要构建光照。

这是使用 Lumen 的官方推荐做法，能从根本上杜绝此类提示。

### 方案 C：定位后针对性修正

用第四步的命令找到那 1 个对象后：

- 若是**误设的静态光源** → 改回 Movable，或删除。
- 若是**不需要的对象** → 直接删除。
- 若是**确实要保留的静态光照** → 回到方案 A 重新构建。

### 方案 D：只抑制提示（治标不治本，不推荐）

控制台输入：

```
DisableAllScreenMessages
```

作用：仅仅隐藏这条红色消息，**问题依然存在**，光照数据仍不一致。仅在你明确知道后果、且暂时不想处理时使用。

## 六、操作建议（本项目）

1. 优先走**方案 B**：项目已启用 Lumen，直接关闭静态光照或把光源改 Movable，一次性解决。
2. 若你必须保留某个静态光源的效果，走**方案 A**：先 `DumpUnbuiltLightInteractions` 定位对象，再 Build Lighting Only。
3. 构建 / 修改前**先保存关卡**，避免 World Partition 关卡状态混乱。
4. 处理完重启一次编辑器或重新加载关卡，确认提示不再出现。

## 八、一句话总结

**这是「光照数据过期」提醒，不是真错误。** 定位用 `DumpUnbuiltLightInteractions`；要根治就在 Lumen 项目里关掉静态光照 / 把光源全改 Movable（方案 B），或老老实实 Build Lighting Only（方案 A）；`DisableAllScreenMessages` 只是把提示藏起来。
